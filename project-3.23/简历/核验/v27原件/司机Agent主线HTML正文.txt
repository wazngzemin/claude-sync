产品概述
1.1 产品定位与愿景
豆包汽车1.0 完成数字世界的Agent上车，让座舱具备了更加拟人、丝滑的交互体验，并能接管用户车控、导航、娱乐、生活服务等。
舱驾融合重新思考和定义AI汽车的体验，让汽车成为像人一样思考&行动的物理世界的具身智能体。
1.2 用户研究
与11位网约车/专车司乘用户进行workshop，并与1位私家司机、2位Robotaxi深度用户进行1V1深度访谈；
识别到从快车司机、专车司机、私人司机、Robotaxi出行服务中的痛点和诉求，几种不同类型的出行方式带来不同的出行体验，有巨大体验断层，这给司机Agent带来了差异化的机会点。

3.3 主链路
主线（赛力斯）：
User Case：「开智驾去公司，把车停到负二层充电车位」。
整体说明：拆解以下3大任务。
调用导航工具
动作：发起导航路线规划
起点 POI：当前位置
终点 POI：公司
联动逻辑：导航下发目的地给智驾 ADC，作为 NOA 行驶终点
开启辅助智驾（VLA 行车意图 VLA_driving_setting = 1）（以实际为准）
对应 Function：driving_setting （以实际为准）
槽位参数：adas_status = ADASStatus_open(1) （以实际为准）
开启通用辅助智驾 其余行车槽位无识别，全部填默认值（-10000 / 10000 / ""）（以实际为准）
抵达后泊入负二层充电车位（VLA 泊车意图 VLA_INTENT_PARK_IN = 202）（以实际为准）
对应 Function：park_in （以实际为准）
泊车槽位：
parking_floor = -2（负二层，默认 - 10000，这里填充 - 2）（以实际为准）
parking_position = PARKING_POSITION_CHARGE (3) 充电车位（以实际为准）
parking_area = "NA"（未指定区域，按协议默认值）（以实际为准）

激活智驾，沿导航自动驾驶

4.1 行车场景_无参照物临停
注：
用户下发没有任何参照物的靠边临停指令，无需输入目的地，仅需就近 / 按参照物停靠，如「前面靠边停」。智驾系统执行靠边临停动作，整个靠边动作、寻找安全停靠点、安全兜底由智驾保证。

典型场景：
场景01-用户即时任务query「前面/对面的公交站靠边停、前面的全家停一停」，智驾行车模式下，执行即时性临停任务。
场景02-用户计划型任务query「激活智驾去公司，中间经过本溪路幼儿园靠边停下接小宝」，「去公司，到了停到楼下那个星巴克旁边」。
4.3.1 需求说明
场景01-即时性POI参照临停
需求描述：「对面的公交站靠边停」、「前面的全家停一停」。
最开始实现方案是基于VLM看「前面公交站」，但VLM有难度，经内外部讨论，现阶段采用POI搜索的方式，类似人查地图。但有可能存在一些性能、体验问题，需要达到发布标准才上线。
|
需求描述
|
场景定义
|
用户以地图兴趣点（POI） 为停靠目标，如「在前面的星巴克那停下」。
POI参照的主要特征：
包含POI类型，如公交站、便利店、药店、地铁站、小区、加油站等
包含品牌词：全家、蜜雪冰城、中石化、大参林等
包含具体地名 / 设施名：XX 小区、XX 大厦、公交站、地铁站
方位：前面、对面，导航需支持搜道路同向和对面的POI；
ODD使用范围：
仅限低速场景下使用（＜30kph），如即将到目的地或途经点后，找寻一个参照物进行靠边停车（待后续实车评估可拓展的最大车速）

4.4.2 场景02-用户长时任务-P1
指用户发起的并非即时性的任务，而是有一定计划性、长时的任务，例如，在上车后提前规划并query「智驾去幼儿园接小宝，到时候找个阴凉的地方停靠」。参照物「阴凉的地方」在发起query时不在视野内，系统需要在导航行驶过程中挂起临停子任务，待车辆到达目的地附近后，开始通过VLM寻找参照物，智驾执行靠边停车。

泊车场景
5.1 泊车类-停车场静态参照物临停/ 泊入
静态参照物指，静态、固定、可智驾泊车地图标注的参照物，如电梯口、门店、充电桩、导视牌，具体视智驾方案商而定。静态参照物当前方案依赖智驾去识别、实现，基于有图或无图智驾VLA能力。
动态参照物指，位置可变、临时存在的物品，人车、锥桶、水马、手推车、施工工具等，具体视智驾方案商而定。
