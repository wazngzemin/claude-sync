# 系统预设任务整体配置框架：配置项与原子能力范围

### 3.1 本次专项要定什么

本次要定两件事：①配置逻辑——平台提供哪些填写项，怎样表达“条件满足后先询问、确认后再执行”；②原子能力范围——这些填写项里，具体能选哪些信号、事件、交互和动作。原子能力是可以被不同任务重复使用的一项能力，例如读取档位、播报一句话、打开后雾灯。

会议依据：02:09:41—02:10:22明确指出原子能力需要分批补齐，TTS和二次确认尚未加入；02:10:31—02:11:29要求先定义完整配置能力，再用任务案例验证。目标不是每新增一个场景就开发一条专用链路，而是：能力已接入、组合方式已支持时，修改条件、文案和动作即可复用。

以下分开标注“页面已见”“本次拟补”“待能力接入”。页面核验范围为当前账号、赛力斯渠道的新建场景页；未看到选项不等于车辆或模型本身没有该能力。

### 3.2 当前平台有哪些配置项

|现有页面区域|实际配置项|使用方式及边界|
|---|---|---|
|基础信息|场景名称；优先级|名称区分测试/正式、使用方与场景。优先级可填写；与卡片展示仲裁的映射需确认，不能当作已打通。|
|发布范围|渠道；指定车辆；适用车型；软件版本及运算符|先选择渠道，再选择该渠道的能力。指定车辆支持多选；车型、版本不填时页面提示默认全部生效。|
|触发条件|动态条件；静态条件；新增条件组。每条填写：条件类型→信号→字段→运算符→值|动态条件表达状态变化。本次实见：车状态信号→车辆行进状态→状态→变更为→P（可选D/N/P/R）。静态条件用于补充当前状态判断；具体运算符以所选信号支持范围为准。|

|执行策略设置|执行总次数；单次上电周期内次数；自然日内总次数；执行最小间隔（分、秒）|前三项不填写时页面提示不限次数。页面显示的默认间隔不是四项任务已确认的频控值；本次须明确按触发、展示还是执行计数。|

### 3.3 本次需要补齐哪些配置逻辑

以下是将会议要求落到表单的产品方案，不是已经上线的功能，也不是会议逐字段定稿。平台应支持配置一条完整规则：何时检查→还需满足什么→命中后做什么→是否询问→收到结果后做什么。

|配置项|产品需填写或选择什么|联动规则与预期结果|
|---|---|---|
|任务关联与运行位置|关联哪项系统预设任务；任务有效状态来源；端侧/云端运行|任务关闭时不产生新触发，未完成询问按失效规则撤销。仅可选择该渠道、车型、版本实际支持的能力；不按有网/无网自动切换链路。端云统一配置与下发属于目标能力。|
|事件与条件组合|触发事件；当前状态条件；比较方式与值；全部满足/任一满足|能明确表达“（下雨或湿滑）且车速>30且当前不是目标模式”。界面展示完整规则摘要，避免把任一满足配置成全部满足。比较符、值域和单位随能力限定，不能任意填。|
|稳定判断与退出|持续时间或连续次数；时间窗；何时认定场景结束；退出后做什么|例如连续识别后才提醒，或在约定时间窗计算温差；具体数值按场景会签。防抖不等于执行最小间隔。退出可选结束本次、再次询问或调用已批准的恢复动作，不能默认自动反向车控。|
|命中后的处理|直接执行已接入动作／仅告知／先询问／发起主动推荐；目标动作及参数|选择主动推荐时填写建议信息，并约定由谁生成和承接Query。选择直接执行车控时，必须有明确允许静默执行的任务方案，不能因省略卡片配置就自动执行。|
|即时交互卡|卡片模板；标题/正文；按钮文案；每个按钮的业务含义；有效时长|例如确认按钮对应“同意切换湿滑模式”，取消对应“不处理本次”。引用已支持的卡片模板，不让每个场景重做卡片。是否真正展示由卡片返回，提交请求不等于已展示。|
|TTS（语音播报）|是否播报；固定文案/下游生成；播报内容；与卡片展示的时机关系|本地固定任务可配询问文案；云端可选择由下游生成，不必两处重复维护。需要询问的卡片尚未展示时，不先播出并等待答复。语音禁用时按会议意见保留卡片、不播TTS。|
|二次确认|无需确认/需要确认；点击与语音承接方式；等待时长；确认/拒绝/关闭/超时后的处理|本地可见即可说把支持的表达对应到当前按钮，由原业务处理；云端走已选定的Advisor/Planner链路。只有明确、仍有效的同意才进入动作。配置取消、关闭、超时为结束本次，不能默认同意。|
|动作顺序与结果分支|先做哪一步；需等待哪类结果；成功、失败、未知分别走哪一步；动作完成的真实状态|必须能表达“出卡→等确认→复核→执行”，以及“调用识别→有设备才继续”。不可把出卡与车控配置成同时执行。车控请求返回成功不等于目标状态已达到；业务回读后再更新结果。|
|重复处理与频控|沿用次数/间隔；同一次事件去重；拒绝后的再次提醒规则|本次补清计数口径与重试规则；同一次确认不能重复执行，旧卡片不能触发新一轮动作。连续拒绝后是否降频或停用仍需专项确认，不写死次数。|

### 3.4 原子能力范围：哪些是可选项，哪些需要接入

① 当前页面可见：车状态信号列表包括上下电状态、当前播放音频、ASR识别状态、车门锁状态、导航状态、除霜除雾开关状态、座位占座信息、收藏地址位置、车辆行进状态、目的地位置、途经点位置、车门状态、TTS播报状态。已核验车辆行进状态的枚举为D/N/P/R；其余条目不在本次逐字段验收范围。

动作列表可见：舒适Advisor、情感Advisor、出行Advisor、内容Advisor、主动推荐、延时执行、自定义回调。赛力斯渠道选择“vlm信号”后，本次信号下拉显示“暂无数据”。因此，有VLM类型入口不代表天气、路面等视觉能力已经能配置。

② 本期按四项任务补齐以下输入能力。表中列的是业务所需能力，不是承诺全部已接入；同一信号能否同时用作变化事件和当前条件，需分别确认。

|输入能力|在平台中怎样使用|对应任务及接入核验|
|---|---|---|
|任务有效状态；AI主动服务总开关|作为是否允许触发的当前条件；关闭变化使未完成处理失效|任务有效状态用于全部任务；AI总开关按任务约定使用。需确认真实状态提供方、更新方式及端/云可读范围。|
|档位|变化事件：变为P或D；当前条件：是否P、是否非P|当前页面已见动态档位变化。充电、儿童锁、加热还需核对静态档位判断及上行范围。|
|车速|当前值与阈值比较；需要时支持跨越阈值事件|天气与加热复用，单位km/h。现稿有>30、<70示例；需确认平台目录与事件能力，不能仅凭文档ID判定可配。|
|天气识别；路面识别；雨量状态|天气/路面变化用于触发，当前值用于条件；雨量状态独立引用|天气保护、后视镜加热。VLM天气与车辆雨量传感器不是同一来源；小/中/大雨能否区分需按能力实际输出，不能自行补枚举。|
|驾驶模式；后雾灯状态|判断是否已经处于目标状态；执行后再次读取|天气保护。模式需包含任务要求的湿滑/雪地目标；真实枚举、可读端云范围待核对。|
|儿童识别；猫/狗识别；儿童锁状态|识别目标出现作为事件或条件；读取对应侧儿童锁是否开启|儿童锁。区分儿童与宠物能力来源、座位/左右侧及未知结果；占座信息不能替代儿童或宠物识别。|
|电量；充电口盖状态；充电设备识别结果|电量与口盖作前置条件；识别结果区分有设备、无设备、无法判断、失败|充电口盖。SOC单位%；识别通过既有主动推荐/DT链路接入，需回到本次停车处理，不能另做一个无关联的状态条件。|
|传送带洗车退出；环境湿度；温度/温差；后视镜加热状态|洗车退出作为事件；湿度和指定时间窗内温差作为条件；加热状态用于去重与回读|后视镜加热。温差时间窗、数据来源及加热结束策略需确认；不能只增加一个“温差>5”的输入框就认为已支持。|

③ 本期需要的动作与反馈能力如下。当前菜单中的“自定义回调”不能直接算作所有车控、卡片和确认能力都已具备；需要证明它能接收参数、执行并返回对应业务结果。

|动作或反馈能力|需要开放的参数或结果|适用范围及边界|
|---|---|---|
|发起主动推荐|推荐原因、建议内容、当前场景及后续承接业务|现有菜单入口已见；充电Query和DT结果如何衔接仍需按既有链路联调。|
|展示/更新/结束即时交互卡|模板、文案、按钮、当前询问关联；实际展示、失败、关闭等反馈|天气及需询问的云端任务。本次待补配置及对接，不是Trigger自己渲染UI。|
|播报TTS；结束本次播报/交互|是否播、文案或内容来源、播报时机；取消时结束哪次交互|本次待补。“TTS播报状态”是可读取的输入，不是“播报一句话”的动作；“关闭语音”不应含糊写成关闭系统语音总开关。|
|接收用户选择|确认、拒绝、关闭、超时；关联当前有效询问|本地按钮/可见即可说与云端回答分别接入。反馈是一次业务事件，不是永久车辆状态。|
|切换驾驶模式；设置后雾灯|目标模式；后雾灯开/关；对应真实状态回读|天气保护。每个子场景绑定自己的动作，不能把雨、雪、雾都配置为同时切模式并开雾灯。|
|开启儿童锁；控制后视镜加热；打开充电口盖|目标部位、目标状态及车辆允许条件；对应真实状态回读|三个任务分别使用。每项车控单独核验车型支持、参数和执行结果；是否恢复或关闭按各自任务方案。|
|接收识别与执行结果|本次识别结果、执行失败/未知原因、目标是否真正达到|用于结果分支、复核与结果卡更新；不能把“请求已受理”配置成“任务已完成”。|

能力接入的最低交付：每项都说明名称及用途、可作事件/条件/动作中的哪一种、字段和值域/单位、适用渠道/车型/端云位置、异常或未知结果、提供团队及验证状态。只有已接入且可验证的能力才进入正式可选列表；其余标为待接入，不能保存成可发布任务。

### 3.5 用一个案例验证能否完整配置

以“雨天建议切换湿滑模式”为例，以下为目标配置，不代表今天能在赛力斯平台一键完成。阈值沿用现稿演示，防抖和频控不在此处重新定值。

1. 任务与范围：关联天气路况保护，运行在端侧；选择适用车型及软件版本。任务关闭时，不产生本次建议。
2. 事件与条件：天气变为下雨或路面变为湿滑时开始检查；当前任务有效，车速>30km/h，驾驶模式不是湿滑。平台需能展示完整与/或关系。速度后来达标是否补触发，作为规则唤醒范围一并确认，不能只监听天气变化造成漏触发。
3. 命中后：选择“先询问”，引用即时交互卡模板。正文与TTS为“检测到路面湿滑，要切换到湿滑模式吗？”，按钮为“确认”“取消”。
4. 确认后：绑定“重新检查任务及当前车况→切换湿滑模式”。本地语音命中确认按钮时，与手动点击走同一处理；不是TTS播完就执行。
5. 取消、关闭或超时：结束本次卡片与交互，不切换模式。询问排队期间已过时、任务被关闭，也不继续执行。
6. 执行后：读取驾驶模式。确为湿滑才反馈成功；失败或暂无法确认时如实反馈，再按约定结束本次并进入频控。
7. 用例复用：将雨/湿滑条件换成浓雾，目标动作换成开启后雾灯，文案对应修改；如果仍需重写“出卡—确认—执行”代码，说明公共配置逻辑还没补齐。

覆盖检查：儿童锁用于验证成员识别、档位和静默/询问分支，但当前稿两种方案需先会签；后视镜用于验证复合条件、时间窗和退出动作；充电用于验证“主动推荐→DT结果→后续处理”的异步分支。三者用于检验框架缺口，不在本章替代场景评审。

### 3.6 专项评审必须形成的结论

1. 配置平台/触发器产品与研发：逐项确认3.3哪些沿用、哪些新增，尤其与/或表达、TTS、二次确认、动作等待与结果分支；明确端侧当前按需求开发，云端已有部分配置，端云统一配置和同步如何分期。
2. 任务、感知、VUI/即时交互卡、主动推荐/DT及车控团队：逐项认领3.4能力提供方，给出已接入/可复用但未接入/需新增的结论。不要只回复“支持卡片”或“有车控”，需要对上具体参数、返回结果与适用范围。
3. 王泽民与赛力斯需求方：确认四个案例能否由上述公共能力组合完成；带回儿童锁交互方案、后视镜P/非P与雨量限制、充电确认时机及双方实现边界。会上未定的内容单列，不写成已确认配置。

评审产出：一份配置项清单、一份带接入状态和责任团队的原子能力清单、一份缺口与分期结论。验收标准是同一套已支持能力能组合出不同任务，并能正确处理确认、拒绝、失败与退出，不是页面能保存就算完成。
