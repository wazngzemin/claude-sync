# 【内部】AI汽车技术架构

# AIDV

要素：

1. 端侧推理引擎（支持量化后的语言模型、多模态模型混合推理）

2. 豆包链路的融合（复用其理想架构，重点是支持多协议的链路）

3. 运营平台：模型管理、数据闭环、服务/Agent管理

**创新点：**

1. **深度融合AI技术**：集成端侧大模型、AIGC、Multi\-Agent等前沿技术，打造智能化程度更高的座舱体验

2. **端云协同架构**：兼顾离线可用性和在线强大能力，在保证用户隐私和快速响应的同时，提供高质量的智能服务

3. **多模态感知与交互**：整合语音、视觉、触控等多种交互方式，使人机交互更加自然、直观

4. **个性化与情感化**：根据用户特点提供差异化服务，使智能座舱具备情感理解和表达能力

5. **全面环境感知**：360°感知舱内外环境，为安全驾驶和个性化服务提供数据基础

6. **主动式服务**：基于对用户状态的理解，主动提供服务，从\&\#34;被动响应\&\#34;转向\&\#34;主动关怀\&\#34;

7. **可扩展的Multi\-Agent架构**：支持灵活添加新功能和服务，使系统能够持续进化和完善

# 端云链路

## 202607版本

**云端各模块职责介绍**

- 豆包云：与客户端直接交互，负责链路中的环境风控、内容安审、地理位置获取、打断判定等功能。

- Speech云：语音能力模块，负责链路中的ASR、TTS、S2S功能。

    - ASR功能当前采用端侧SDK直接对接Speech云方案。

    - TTS功能由座舱云调用生成音频并缓存，端侧通过接口拉取。

    - S2S功能当前采用纯文本形式对接。

- 座舱云

    - Gateway模块：负责豆包协议与座舱协议的转换。

    - 句法RAG：对query进行规则匹配，命中的query会跳过Planner推理，直接由Agent进行处理。

    - 分类拒识：对query进行拒识判定，与简单、复杂分类，简单case跳过Planner推理，直接由Agent进行处理。

    - **Planner模块**：结合Context模块的记忆、端状态等上下文信息，对query进行推理，拆分任务给到Agent模块。

    - **Agents Server模块**：负责各方Agent的注册管理、调用、协议转换。当前支持自建、ToB、豆包/一方、三方四种Agent类型。

    - **Context模块**：负责端侧上报的数据、事件等信息的存储与检索；主链路中构建query相关的上下文信息，包括长短期记忆检索、端状态筛选等功能。

    - TTS模块：负责响应TTS音频的生成与缓存。

    - 触发器模块：负责主动推荐链路中规则的配置与检测，命中则触发相应的主动推荐功能。

    - Frontier模块：云端向端侧主动推送数据的通道，当前主要负责下发车控指令、主动推荐的id与建议文本。

- Advisor云：负责状态感知类主动推荐的建议文本的生成，长时任务的目标管理。

**当前链路存在的问题**

1. 当前链路下视频通话能力无法与Planner\-MutiAgent架构融合。

2. S2S采用文本方案接入，存在联网类badcase，Speech侧新迭代的功能不支持文本接入。

3. RTC通道建联慢、成本高、不支持音区，不适合车机场景。
