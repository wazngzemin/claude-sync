司机Agent的定位是舱驾一体中行程和泊车场景的主控Agent，主要负责导航\&amp;停泊车相关的场景，同时单独的导航、路线规划、智驾指令也由司机Agent负责。对DT而言单独和复杂的导航、路线规划、智驾等指令由现状DT拆分改成统一交给司机Agent，由司机Agent内部具体分析和拆分工具调用。

此方案的好处：1、司机Agent主要针对导航、路线规划、停泊车等垂类场景，能自行管理Context相关信息，对复杂场景能提供更做到更好的任务解析、编排和执行；2、可减轻DT架构复杂度，DT无需细化区分AiNavi和智驾工具的组合调用方式

### 目标

- 司机 Agent 支持DT中原AiNavi、智驾工具的相关场景

- 司机 Agent 支持涉及AiNavi和智驾的复杂场景

智能辅助驾驶工具

</td>
<td>

auto\_drive

</td>
<td>

【工具描述】智能驾驶综合控制工具，涵盖行车漫游、智慧寻车（沿途/就近/指定车位泊入）、路口转向控制、停车场出口寻找、巡航车速调节、跟车时距调节、变道控制、NOA领航辅助开关、计划型智驾行程（含目的地/途经点及动作）等所有智驾相关功能。凡是用户需求涉及智驾（query 中含\&\#34;智驾\&\#34;关键字，或语义上需要激活/使用智能驾驶），无论计划型还是即时型，均由本工具统一承接。计划型指令（如\&\#34;激活智驾去公司，中途经幼儿园靠边接小宝\&\#34;）本工具会与导航协同规划路线并记录途经点动作，在接近时自动触发相应操作；即时型指令一旦发出立即执行。

【具体能力】

1. 计划型智驾行程：含目的地、途经点及动作，如「激活智驾去公司，中途经幼儿园靠边接小宝」「开启智驾去超市买水再回家」「用智驾导航去机场，途中加油站停一下」。

2. 行车漫游：开启/关闭漫游模式（无目的巡航驾驶），如「激活漫游」「开启行车漫游」「开车随便逛逛」「关闭漫游模式」。

3. 智慧寻车与泊车：沿途或就近寻找车位并泊入，支持指定楼层/区域/充电类型，如「沿途找个车位停进去」「停在负二层充电车位」「找个离电梯近的车位」「别停充电车位找普通车位」。

4. 路口转向控制：在导航中或自由驾驶时控制车辆转向，如「前面路口右转」「第二个路口掉头」「前面直行不要拐」「连续直行三个路口后右拐」「前面不要右转改成左转」。

5. 停车场出口寻找：从停车场内导航至出口，如「智驾帮我找出口」「开去出口」「从停车场出去」「带我开去最近的出口」。

6. 车速与跟车控制：巡航速度调节、跟车时距调节、加速/减速，如「速度调高」「降速」「目标车速加8」「跟车时距调大1档」。

7. 变道与辅助驾驶控制：语音控制变道、NOA/领航辅助开关、驾驶风格切换，如「帮我向右变道」「打开导航辅助」「退出NOA」「开稳当一些」。

8. 即时靠边停车：路边临时停靠，如「找个地方靠边停」「我要下车」「把我放这儿」。

【入参要求】\&\#34;params\&\#34;:\{\&\#34;query\&\#34;:\&\#34;智驾操作指令，如\&\#39;激活智驾去公司，中途经幼儿园靠边接小宝\&\#39;、\&\#39;激活漫游\&\#39;、\&\#39;开启行车漫游\&\#39;、\&\#39;关闭漫游模式\&\#39;、\&\#39;沿途找个车位停进去\&\#39;、\&\#39;停到负二层充电车位\&\#39;、\&\#39;找个离电梯近的车位\&\#39;、\&\#39;前面路口右转\&\#39;、\&\#39;第二个路口掉头\&\#39;、\&\#39;前面直行不要拐\&\#39;、\&\#39;智驾帮我找出口\&\#39;、\&\#39;开去出口\&\#39;、\&\#39;帮我找最近的出口\&\#39;、\&\#39;加速\&\#39;、\&\#39;减速\&\#39;、\&\#39;速度调高\&\#39;、\&\#39;目标车速加8\&\#39;、\&\#39;跟车时距调大1档\&\#39;、\&\#39;帮我向右变道\&\#39;、\&\#39;打开导航辅助\&\#39;、\&\#39;退出NOA\&\#39;、\&\#39;找个地方靠边停\&\#39;、\&\#39;我要下车\&\#39;等。\&\#34;\}

【注意事项】

- 凡是需求涉及智驾（query 含\&\#34;智驾\&\#34;关键字，或语义上需激活/使用智驾），无论计划型还是即时型，都直接使用本工具

- 仅纯导航需求（不含智驾语义，如\&\#34;导航去公司\&\#34;\&\#34;先去A再去B\&\#34;）才使用 route\_planning。

- 寻找充电站/停车场（非泊入动作）请使用 poi\_search。

- 本工具与 route\_planning、poi\_search、navi\_basic\_control 不要并行调用。

- 当 query 中同时包含“导航去某地”和“停在某层/某区域/某类车位”时，属于“路线规划/导航\+指定车位泊入”的复合智驾需求，就应整体交给本工具处理

【工具tips】用户说「停到负二层」「找个有充电的车位」「停到电梯口」等涉及具体车位时，直接使用本工具，不要调用 POI 或路线规划。转向、掉头、直行等指令无论是否在导航中，均由本工具承接。车速控制仅支持5的整数倍调节（如110、115）。

</td>
<td>

trip\_planning

</td>
<td>

【工具描述】行程规划工具，支持自驾游及旅行场景下的多日行程规划，可根据用户明确提出的目的地、出行天数、出发地、偏好、同行人、预算等信息，生成完整的多日行程方案。支持规划每天的游玩安排、路线节奏、景点、美食、住宿建议和注意事项，并可在多轮对话中根据用户要求进行灵活修改。支持保存已确认的行程方案，也支持查看已保存的行程内容，帮助用户持续管理出行安排。

【入参要求】\&\#34;params\&\#34;:\{\&\#34;query\&\#34;:\&\#34;行程规划相关指令（如\&\#39;我要去重庆玩两天，你帮我规划一下怎么玩比较好？\&\#39;、\&\#39;带我去兜兜风\&\#39;、\&\#39;规划一下三天去川西的自驾游行程\&\#39;、\&\#39;帮我安排一个上海出发去黄山两天一晚的自驾行程\&\#39;、\&\#39;把第二天的行程改轻松一点\&\#39;、\&\#39;保存这个行程\&\#39;、\&\#39;查看我之前保存的川西行程\&\#39;等）。query 应尽量保留用户原始表达和已明确给出的关键信息，可结合用户历史习惯或上下文做轻度改写，但不要额外补充用户未明确提出的目的地细节、景点清单、出发地、住宿位置、节奏偏好、预算等信息。例如用户说\&\#39;我要去重庆玩两天，你帮我规划一下怎么玩比较好？\&\#39;，可改写为\&\#39;规划两天重庆游玩行程\&\#39;，不应主动补充\&\#39;洪崖洞、解放碑、山城步道、磁器口、长江索道\&\#39;或\&\#39;出发地默认为重庆主城区酒店\&\#39;等用户未提供的信息。当前支持多日行程规划、行程修改、行程保存和行程查看。不支持当天多段目的地导航，如\&\#39;先去徐汇滨江吃饭，再去滴水湖逛一逛\&\#39;，此类需求应使用多目的地导航或路线规划能力。\&\#34;\}

# 详细方案

## 领域边界与路由

### 准入规则

【待讨论】司机 Agent 是否需要接管用户的简单导航、简单路线规划等诉求



## 泊车、临停FC下发时机

SLS上目的地泊车、途径点临停属性强依赖地图处于导航中，由于长期方案中司机Agent来管理与导航、路线规划相关的泊车、临停FC，下发时需要等地图处于导航中时才能下发给车控APP执行。 有两条可选链路能实现：

1. AINavi成功发起导航\-\&gt;**端状态上报导航信号\-\&gt;导航从没有变为有发生状态变化\-\&gt;触发器感知调用司机Agent Callback**\-\&gt;司机Agent检查任务\-\&gt;司机Agent下发FC\-\&gt;车控APP执行FC\-\&gt;智驾执行

2. AINavi成功发起导航\-\&gt;**AINavi云端返回“导航成功”结果时，在Ext中增加标识**\-\&gt;司机Agent感知导航成功\-\&gt;司机Agent检查任务\-\&gt;司机Agent下发FC\-\&gt;车控APP执行FC\-\&gt;智驾执行

## 端到端执行链路

<div class="callout">

**核心链路**：Director（DT）只负责驾驶领域路由、跨域协调和最终用户表达；Driver Agent 负责目标拆解、领域工具选择及需要语义理解的再规划；Driver Runtime 负责任务生命周期、流式调度、版本控制、事件恢复和结果路由。

</div>

### 主执行流程

1. **领域路由与任务创建**：Director 判断请求属于导航/智驾领域后，将原始 Query 和必要上下文交给 Driver Agent，不再选择驾驶域内部工具。Driver Runtime 在请求进入时创建 `DriverTask`，记录当前目标、任务状态、等待项以及 `task\_id \+ version`；简单请求仍只生成一条 Action，不进入复杂拆解。

2. **目标拆解与动作生成**：Driver Agent 根据当前 Query 和按需提供的最小 `task\_context`，以 DSP/1 流式输出 Action 和 Terminal，选择 `route\_planning plan/execute`、`poi\_search query`、`auto\_drive generate\_fc/execute`，或输出澄清、兜底与取消语义。

3. **流式解析与安全调度**：Driver Runtime 只在收到完整行时提交 Action。无副作用的 `generate\_fc`、`poi\_search query` 可在完整行且依赖满足后提前执行；会修改导航任务或触发车辆动作的写操作必须等待完整 `\!dispatch`，并在执行前校验当前任务版本。

4. **FC 生成与请求适配**：`auto\_drive generate\_fc` 仅生成自然语言语义 FC，不直接触发 ADC。存在 FC 依赖时，Runtime 等待 FC 返回，Adapter 再将其紧凑序列化到 AiNavi `Request\.ext\[\&\#34;intelligent\_driving\_fc\&\#34;\]`；无 FC 时不传该字段。

5. **导航、智驾执行与任务绑定**：Adapter 将规划或执行 Query 交给 AiNavi，并完成下游协议适配。终点泊车 FC 必须绑定当前导航任务和唯一确认终点；POI 途经点临停通过 Navi Query 或地图临停属性表达，不进入终点泊车 FC；即时智驾则按独立动作执行。

6. **结果统一回流**：工具结果、UI 交互和车端事件统一返回 Driver Runtime。Runtime 首先校验 `task\_id \+ version \+ action\_id`，再更新 `DriverTask`；旧版本或已关闭任务的迟到结果只记录，不再推进任务。

7. **自动推进、再规划与用户反馈**：确定性中间结果由 Runtime 自动满足依赖并继续执行；只有结果改变后续决策、用户回答需要语义理解或存在多个降级方案时，才再次调用 Driver Agent 模型；只有用户可见结果或结构化交互才交给 Director 生成最终表达。

8. **版本更新与任务结束**：用户修改目的地、途经点或终点动作时，Runtime 递增版本并立即使旧版本待执行动作和 FC 失效；取消时关闭任务。单个 `action\_status=completed` 不等于目标完成，只有收到真实用户目标完成事件后，才将 `task\_status` 置为 `completed`。
