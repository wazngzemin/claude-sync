# 总结

本次会议主要围绕《基础评测集（basic\_vehicle）》展开讨论，参会人员就评测集的搭建思路、数据选取、场景分类等方面进行了深入交流，明确了评测集的调整方向和构建步骤，并确定了时间节点，内容如下：

- **基础评测集的目的与现状**

    - **评测集目的**

        - 满足高频问题回复：陈芮婷提出基础评测集相当于 AI 豆包汽车的必过级，目标是在 Q1 对用户常见高频问题有较好回复，为此准备了评测集并介绍搭建思路和数据情况。

        - 衡量基础用车场景：张航认为基础评测集应衡量用户基本一定会用到的、能代表日常最基础用车场景的情况，项目在此评测集上应拿满分。

    - **数据选取与分析**

        - 车企线上数据选取：陈芮婷选取吉利、沃尔沃、特斯拉、极氪、奥迪等车企的线上生产数据，因数据量大，让研发人员拉取，选择冬天和夏天各一段时间的数据，约每周 50 万条。

        - 场景分类与分析：对线上数据进行分析，选取三类场景，包括高频场景和问题、与用车场景高度相关场景、与安全或用户关心话题相关场景，并发现不同车企用户高频场景分布有区别。

        - 数据比例与问题：张航指出部分分析因数据范围问题可能不准确，如特斯拉只接车控，极氪只接闲聊等，陈芮婷表示需重新考虑数据比例。

        - 高频场景选取：陈芮婷按 TOP30 个场景取比例，在 DOMAIN 下增加子话题概念，以保证数据分布均匀。

        - 代表性问题选取：与车场景相关但非高频的问题，如车书相关问题，也会被纳入评测集，但比例较低。

        - 重要问题选取：陈芮婷认为与用户身体、心理、家人、职业等相关的问题能提升用户好感，纳入评测集；张航认为此类问题不属于基础评测集范畴，陈芮婷表示可将其筛出，除非本身高频。

    - **多轮对话分析**

        - 多轮对话数据少：陈芮婷从 2 万组数据中人工筛选，认为能被认定为多轮对话的只有二三十组，量级较少，在数据集 A 中用典型单轮 query 续写多轮话术用于评测。

        - 多轮对话场景：多轮对话主要分布在 POI 搜索、车控、科普类、导航、讲故事讲笑话、拟人对话等领域，选取 30 多组有代表性且话术不重复的作为多轮 case。

- **评测集的讨论与优化方向**

    - **数据选取比例**

        - 按比例抽取：张航认为应按线上使用频率比例抽取数据，导航高频则样本中应占比高，以证明在高占比情况下的准确率。

        - 补充缺失数据：张航和韩杰提出要分析高频场景是否真正闭环，补充因功能缺失导致线上数据未体现的用户需求，如 POI 搜索中顺路、红绿灯少等条件。

    - **多轮数据补充**

        - 借助系统采集：张嘉锋提出线上系统无法采集某些多轮数据，需借助现有更智能系统（如 planner 的回复）采集，模拟真实用户解决需求闭环的 query。

        - 区分基础与高阶：陈芮婷认为部分非高频场景的多轮数据不应放在基础评测集，张嘉锋认为从 Alex 的基础标准看，应考虑用户自然完成基本需求的各种表达。

    - **测试集构建思路**

        - 以线上比例为基础：韩杰提出以线上用户交互的 query 或领域比例构建测试集，在比例范围内有限调整小意图范围，先构建基础测试集，再补充未覆盖内容。

        - 考虑用户真实需求：张航和韩杰强调要从用户高频需求出发，确保需求得到闭环满足，而不仅仅是回答 query。

    - **衡量指标**：张航提出考虑将从唤醒到识别这一段作为衡量指标，韩杰认为端到端的满足度测试应包括识别准确性、速度、时延等方面。

- **后续工作计划**

    - **调整评测集**：陈芮婷按照会议讨论的调整方向，先打几个样，再拉大家讨论。

    - **分工完成第一版**：明天参会人员在漕溪北路进一步沟通分工，下周完成第一版评测集。

    - **与 Alex review**：4 月份清明之前与 Alex 进行 review，展示评测集成果。
