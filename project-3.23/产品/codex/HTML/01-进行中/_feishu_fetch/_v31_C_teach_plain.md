# C Context 上下文

summary: 在正式推理前，把与当前决定有关的人、车、历史和能力组织好；缺失的事实留给后续显式查询。

## INTRO

用户说“我有点冷”，光看这几个字，模型能想到开暖风，却不知道说话的人坐在哪、空调已经开到多少度、车窗是否敞着，也不知道用户是否不喜欢风直吹。Context 就在正式推理之前，把这些与当前决定有关的信息组织好。

换成“带我去昨天那家游泳馆附近的餐厅”，需要的背景又变了：先弄清昨天去过哪家、地址在哪，才能找附近餐厅。当前车况不能回答昨天的行程，用户偏好也不能凭空补出地点。

Context 负责组装和供给，不包办原始长期存储，也不直接发导航。V2 现行是预注入加动态检索；各来源各自过滤，保留未知。性能数字（如历史上的 P90 目标）写不清现行值就不写死。

## c-parallel 先把当前人、当前车和情景分清楚

C1 按当前问题并行取背景。C2 确认说话人与操作对象：音区≠操控座位；同名未知不能猜；读私人记忆要授权。

C3 取车辆此刻值与时间：最新车况优先于历史描述；缺值不填成关闭或零。C4 取舱内外情景，视觉人物要落到可信身份，不把画面当账号。

三条并行路回答不同问题，不能揉成一段看似顺畅却无法核对的描述。

## c-history 最新车况放在本次请求旁，历史里接住工具事实

上下文调整把 goal_list 与最新 env_info 放在这一次输入旁，并明确最新车况优先于对话历史。

C5 承接最近对话、工具返回后的播报与执行；区分已播未播。C6 带上仍在跟进的任务视图，修改取消要定位真实任务。

成为历史后不再无变量形式重复堆叠全部 context，以节省窗口——但关键事实与对象边界不能丢。

## c-memory 常用背景先准备；画像已注入，情景画像待核

预注入覆盖大多数常规请求需要的常用数据；复杂缺项由 Director 动态检索兜底。不能宣称预请求已查完所有背景。

显式语义画像已固定注入；行为推导的情景画像宣讲口径是当时未用于推理——并列待核，不写成每轮必然可用。

C8/C9 注入本车型能力与适用示例，示例不覆盖真实约束。记忆体系细节归身份与记忆章，本章只讲本轮取用。

## c-assemble 各源过滤后组装给 Director；缺事实走显式查

C10 各来源各自核权限、相关性与时效，冲突保留来处，缺失不擅自补齐。V2 取消统一精筛，避免跨源挤压与位置偏好。

C11 组装本轮背景给同一个 Director；信息够就进入动作判断，不够就留查询出口。

C12 是第二路：Director 缺记忆才显式查人物、日期与事件；本例先补游泳馆位置，再找附近餐厅。反馈仍回原目标，不另建大脑。

## CLOSING

到这里，Director 拿到的是带来处的当前背景，而不是猜补完整的故事。下一章（Director）在事实够时规划动作，不够时先查；不要在 Context 章把“预注入完成”写成“昨天那家地址已经确定”。
