场景二 · 兜风推荐（复杂场景：多条件 + AND/NOT 组合）
益红的需求："周末、未发起导航、连续驾驶超过 6 分钟、不在高速公路上 → 推荐周边景点/美食。"
频次：每次导航只推荐一次（但这里"未发起导航"意味着不能按导航频次算，要按上电周期）。

以前怎么做

  1. 1 益红给你需求。你判断：触发条件是"导航状态 = 未发起 + 日期 = 周末 + 连续驾驶时长达 6 分钟 + 道路类型 ≠ 高速"。
  2. 2 你在触发器平台上一条条配。问题是：你现在的触发器平台只支持"并行条件"（所有条件同时满足），不支持"先等 6 分钟再判断一次"这种串行逻辑。怎么办？你只能：先配一条触发器监听"导航状态 = 未发起 + 周末 + 非高速"，然后在条件里加一个"连续驾驶时长 ≥ 6 分钟"——但这个"连续"判断其实不准，因为触发器每次轮询状态，不知道"连续"了多久。
  3. 3 你去找刘杨："这个'连续驾驶 6 分钟'的判断，靠轮询不准，能不能在端上做个计时器？" 刘杨说可以，给你单独加了一段端侧代码。
  4. 4 下次赛力斯也要"连续驾驶 XX 分钟"的判断 → 你又要找赵衍再写一遍。

以后怎么做

  1. 1 你去韩杰大表找积木：
       导航状态判断 → con_navState（条件表第 8 行）✓
       日期判断 → 表里没有"周末"条件 ✗
       道路类型判断 → 表里没有"高速/非高速"条件 ✗
       连续驾驶时长 → 表里没有这个条件 ✗
  2. 2 你画流程图：
    tri_navState
    导航变未发起
    →
    等 6 分钟
    （韩杰说的延时器）
    →
    再查：
    还在未导航？
    →
    周末 + 非高速
    →
    调 Advisor
    注意这个流程有串行：先触发 → 等 6 分钟 → 再检查一遍状态 → 才判断条件。你现在的触发器做不了串行，韩杰的编排引擎能做。
  3. 3 标缺口：日期条件、道路类型条件、连续驾驶时长条件 → 提交韩杰。韩杰评估是否加进大表。一次加进去以后，之后所有需要"连续驾驶时长"的场景（不止兜风，疲劳驾驶提醒也要用）——直接勾选这个积木就行，不用再找研发。
这个场景暴露了韩杰方案的两个核心优势（你要承认的）：
① 串行编排：你现在的触发器只能"所有条件同时满足"，韩杰能做"先等 6 分钟 → 再判断"。这是你触发器确实做不到的。
② 一次开发复用："连续驾驶时长"这个积木做一次，兜风推荐用、疲劳提醒用、长途驾驶关怀也用——不用每个场景都找研发写一遍。
场景三 · 充电口盖提示（最复杂：两段式，有缺口需新增）
益红的需求："档位变 P 档（切入）+ 电量 19% + 充电口盖关闭 + AI 主动服务已开启 → 触发 VLM 看后视有没有充电桩 → 有的话弹卡片'检测到充电桩，要打开充电口盖吗？'"
频次：一次上电周期一次。

以前怎么做

  1. 1 这个场景是两段式的：第一段是信号侧（档位 P + 电量低 + 口盖关 + AI 主动服务开），纯静态信号判断。第二段是视觉侧（VLM 识别后视摄像头有没有充电桩），走你的 VLM 条件任务。
  2. 2 你现在做：在触发器平台配第一段条件（档位、电量、口盖、AI 开关），命中后 → 调到你的 VLM 条件任务 → VLM 识别 → 命中 → 弹主动服务卡片。
  3. 3 问题是：充电口盖状态这个信号，在仁杰的端状态清单里有（vehiclePowerStatus 的 sls 里写着"车身_充电口盖状态"），但没暴露成独立状态参数。你要找仁杰把它提出来。
  4. 4 AI 主动服务开关——也不是车端信号，是车机设置里的。你也得确认数据源在哪。

以后怎么做

  1. 1 去韩杰大表找：
    · tri_gear（档位变化）→ 触发事件表第 2 行 ✓
    · con_gear（档位判断）→ 条件表第 2 行 ✓
    · 电量值判断 → 条件表第 30 行 ⚠ 缺唯一 con_ID
    · 充电口盖状态 → ✗ 没有这个积木（原料在，没上架）
    · AI 主动服务开关 → ✗ 不在他表里（不是端信号）
    · 弹主动服务卡片 → 动作表第 8 行 ✓
  2. 2 画流程图：
    tri_gear
    切到 P
    →
    电量<19%
    →
    口盖=关
    →
    AI开关=开
    →
    【交给 VLM】
    识别后视
    有无充电桩
    →
    弹卡片
  3. 3 标缺口：充电口盖状态（新增状态+条件）、电量 con_ID（补唯一标识）、AI 主动服务开关（确认数据源）。发给韩杰。
这个场景最关键的地方：第一段（信号判断）可以进韩杰的编排引擎。第二段（VLM 视觉识别）是 AI 判断——韩杰自己说了，AI 判断走云端模型，和他的编排引擎是两套东西。

你的 VLM 条件任务链路，不在他的编排引擎范围内。这就是你的三块骨头之一（AI 判断的判断逻辑）。他管"档位是不是 P、口盖是不是关"，但"后视摄像头里有没有充电桩"这个判断——归你。
第四幕 · 汇总：韩杰具体在干什么？（三件事）

他本周要交付的三件东西（P0）

① 端云协议打通

  • 他要干什么：定义一份统一的数据格式。让"画出来的流程图"在端侧和云端都能解析、都能执行。不管这个场景是端侧跑还是云端跑——研发拿到的都是同一份流程图。
  • 以前什么样：云端触发器是刘杨写的代码，端侧触发器是赵衍写的代码——两套代码，格式不同。同一个"档位变 P"这个条件，刘杨的代码里叫 gear == P，赵衍的代码里叫 driveMode:PARK。容易不一致、容易出 bug。
  • 以后什么样：流程图里写的是标准格式（比如 con_gear = P），刘杨和赵衍各自实现解析器去读同一份流程图。标准统一了，不会出现"云端触发了但端侧没反应"的 bug。

② 事件日志上报

  • 他要干什么：你（产品）告诉他"哪些触发事件需要记录成事件日志"，他列成清单。研发在端侧监听这些事件，触发后就生成一条文本日志，发给仁杰的 Context。
  • 以前什么样：事件日志还没有。仁杰的 Context 只能看到端状态（车速多少、档位是什么、空调几度）——是"快照数据"，不是"事件记录"。比如 Context 能看到"当前档位 = D"，但不知道"2 分钟前档位从 P 变成了 D"。
  • 以后什么样：当档位从 P 变成 D 时，一条事件日志生成："2026-07-24 18:30:15，档位由 P 变为 D，当前车速 0，主驾已占用。" 这条日志发给 Context → Context 喂给 AI → AI 知道了"用户刚上车、刚挂挡、准备出发"——这个上下文让它后面的推荐更准。
  • 他的交付物：一个表——勾选哪些触发事件要生成事件日志 + 每条日志的文本格式模板。你（产品）填触发事件和拼接规则，他自己也填了一版。

③ 端侧自闭环主动服务（两个 demo 场景）

  • 他要干什么：在赛力斯车上跑通两个端侧场景，验证"端侧原子能力 + 编排引擎"整条链路能通。
  • 两个场景：① D 档检测到儿童 → 弹儿童锁主动服务卡片 ② 雨雪天气/湿滑路面 → 开雾灯/调驾驶模式。
  • 以前什么样：端侧触发器只有你的 PRD，没有代码实现。你的 PRD 里写了端侧场景（如充电口盖提示），但端侧还没接入信号。
  • 以后什么样：韩杰拿这两个 demo 场景去验证——如果跑通了，说明"端侧原子能力 + 编排引擎"这条路可行。然后益红的 8 条场景就可以按同样的方式在端侧/云端实现。
  • 他自己承认的问题：这两个场景他说是"鸡肋"、"伪需求"。他是为了验证架构——不是为了做产品。

远期他要做的（平台）

可视化配置平台（优先级 P0-P1，不急）

  • 一个 Web 页面，产品（你/益红/韩杰）可以在上面拖拽配置场景：从原子能力库里拖触发事件、条件、动作 → 连线 → 保存 → 点发布 → 车端 5 分钟内生效。
  • 新建的"剧本"（场景）类型分四种：事件日志、静态 Advisor、动态 Advisor、预置场景。注意：没有"触发器"这个类型。
  • 韩杰说这个平台就是"现在云端触发器平台的一个升级版"。他管平台改造，优先级不高，画布改造（支持串行并行嵌套）刘杨说了要 2 周，还没选型。
第五幕 · 总结：以前你的位置 vs 以后你的位置
维度以前（现在）以后（韩杰方案）
你是谁 触发器模块的 owner。从需求到实现你一个人串。
需求来了怎么走 益红 → 你（翻译+配规则+找研发） → 刘杨/赵衍 益红 → 你（画流程图+标缺口） → 韩杰（审核+派活） → 刘杨/赵衍
规则谁定义 你。什么场景用什么条件、什么运算符、什么频次——你说了算。 积木（有什么）归韩杰。积木怎么拼——流程图上画——还可能是你（如果你抢住）。
研发对接 你直接对话刘杨和赵衍。需求不失真，变更快。 韩杰统一对接。你的需求经过他转述 → 可能失真 → 变更要经过他。
平台归属 "触发器平台"，你和仁杰在用。 "可视化配置平台"= "触发器平台升级版"，剧本类型没有"触发器"。
频次策略 你定义。 韩杰四张表没有这列。空白 = 你的机会。
条件组合逻辑 你在触发器平台里配 AND/OR。 流程图上画串行/并行/AND/OR/NOT。画布改造要 2 周未选型 = 规则可以先定义。
最后的最后：韩杰在做什么？用一句话——

他在把车上所有"主动能力"（触发+条件+动作）收进一张表、一套引擎、一个平台。
你的触发器是最早实现这套模式的东西——所以你的成果会被他收进去。
但他不知道你的场景。他不知道缺什么、不知道频次怎么定、不知道条件怎么组合。

你的位置 = "韩杰管积木仓库，我管积木怎么拼成场景"。这个位置你要守住，靠的不是在会上宣布，是靠把益红 8 条场景的规则表做出来、发出去。
