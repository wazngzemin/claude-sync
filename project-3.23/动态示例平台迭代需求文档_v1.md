# 动态示例平台迭代需求文档

- **版本**：v1.0
- **日期**：2026-08-12
- **撰写人**：王泽民
- **对接开发**：王梦尧
- **相关方**：李浩然（项目）、赵晓朝（算法）、高红涛/罗丽（测试）、郝晓伟（DT）
- **需求来源**：2026-08-05「DT复测结果分析（动态示例质量问题）」会议

---

## 一、背景

动态示例（检索注入 Planner SP 的 query→决策分析对）已成为 badcase 修复的主要手段。8 月 5 日复测分析会发现：动态示例加了之后测试结果改善不及预期（原预期约 80% 可解），核心原因不是示例思路不对，而是**平台能力撑不住当前的使用方式**：

1. **重复冲突无人拦**：多人分散添加，同一功能点（如天窗类）重复添加多条相似 query，互相稀释召回，目标示例进不了召回 top3；
2. **批量能力半残**：现有批量接口只能新增，不能批量修改、不能批量删除；query 重复也不校验直接落库；批量导入的条目添加人全部记为 system，无法追溯；
3. **数据导不出来**：线上平台是唯一全量数据源，但不支持导出。导致：无法全量 review 冲突、测试无法对全部示例做回归验证、Excel 台账与线上版本脱节（Excel 已断档无人维护）；
4. **发布无审核**：任何人添加即生效，没有草稿态和审核环节，错误示例直接污染线上。

## 二、目标

| 目标 | 衡量标准 |
|------|---------|
| 新增示例不再产生重复/冲突 | 添加时重复检出率 100%，重复示例零新增（除非人工确认） |
| 批量修复模式可闭环 | Excel 维护 → 审核 → 批量导入 → 可回滚，全链路可走通 |
| 全量数据可导出 | 支持一键导出全量示例，供全量 review 和测试回归使用 |
| 批量导入有审核 | 批量导入的条目必须经审核人通过后生效 |

## 三、使用角色与场景

| 角色 | 场景 | 频率 |
|------|------|------|
| 产品/算法（泽民、晓朝等 4-6 人） | 单条 Meego bug 修复，直接在平台添加 | 日常，每天几条 |
| 产品/算法（同上） | 大测试后发现批量 badcase（一次 200-300 条），Excel 集中维护后批量导入 | 每次大测试后，约月度级 |
| 审核人（泽民、晓朝） | 审核批量导入的示例 | 随批量导入发生 |
| 测试（红涛、罗丽） | 全量导出做回归验证；复测关单前核查自测凭证 | 每次大测试后 |

## 四、功能需求

### P0-1 添加查重拦截

**现状**：添加时不做任何查重，query 完全重复也直接落库。

**需求**：
1. 单条添加和批量导入时，均对新 query 与库内已有 query 做相似度匹配（语义相似，不只是字符串完全相同）；
2. 检出相似条目时，展示已有条目信息（ID、query、决策分析摘要、添加人、添加时间），操作者三选一：
   - **取消添加**（确认重复）；
   - **覆盖更新**（用新内容替换旧条目，保留原 ID）；
   - **仍要新增**（确认两条确实不同，强制添加）；
3. 批量导入时逐条执行同样校验，导入完成后输出报告：新增 X 条、覆盖 Y 条、拦截 Z 条、强制新增 W 条，报告可下载；
4. 相似度阈值先给默认值，支持后台配置调整。

**验收标准**：构造一条与库内已有 query 语义相近的示例添加，系统能检出并给出三选一；批量导入 10 条含 3 条重复，报告中准确标出 3 条。

### P0-2 全量批量导出

**现状**：不支持导出；从数据库直接导需 leader 审批人肉提数。

**需求**：
1. 平台支持一键导出当前环境全量示例为 Excel/CSV；
2. 导出字段：ID、query、决策分析、其他说明、添加人、添加时间、最后修改时间、环境（DEV/PRD）、状态（草稿/已上线）；
3. 导出动作记录操作日志（谁、什么时间、导出了哪个环境）；
4. 如需审批，审批链路线上化（导出申请→leader 线上批准→下载），不要人肉提数。

**验收标准**：导出文件条数与平台列表条数一致，字段完整无乱码，含合并单元格之外的纯平铺格式（不要求兼容旧 Excel 台账格式）。

### P0-3 批量修改 + 批量删除

**现状**：批量接口只支持新增；修改和删除只能逐条手动。

**需求**：
1. **批量更新**：按 ID 匹配，批量覆盖更新条目内容（决策分析、其他说明等字段）；ID 不存在的行报错跳过并列入报告；
2. **批量删除**：按 ID 列表批量删除；增加二次确认（展示将删除的条数和内容摘要）；
3. 定义**标准导入/更新模板**（平台提供下载）：列固定为 ID（更新/删除时必填）、query、决策分析、其他说明、环境，不允许合并单元格；
4. 批量操作同样生成批次号和操作报告。

**验收标准**：用模板批量更新 5 条、删除 5 条，结果与预期一致；ID 填错的行有明确报错。

### P1-4 草稿态 + 审核上线

**需求**：
1. 示例增加状态字段：草稿（不生效）/已上线（生效）；
2. **单条添加**：默认直接上线（保持分散添加的效率，会上已对齐），但操作者可选择存为草稿；
3. **批量导入**：一律进草稿区，必须经审核人通过后才生效；
4. 审核人可配置（1-N 人，当前配置为王泽民、赵晓朝）；
5. 审核界面：逐条展示内容，自动附带库内相似条目（复用 P0-1 的相似度能力），支持单条通过/驳回、批量通过；
6. 驳回时可填驳回理由，导入人可见。

**验收标准**：批量导入 10 条后线上未生效；审核通过后生效；驳回的条目有理由记录。

### P1-5 自测凭证 + bug 关联

**需求**：
1. 每条示例增加两个选填字段：
   - **关联 bug ID**：Meego 单号，支持一对多（一个 bug 可能对应多条示例）；
   - **自测凭证**：文本或附件（召回测试截图/fornax 验证结论）；
2. 列表页支持按"无关联 bug""无自测凭证"筛选，供测试关单前核查；
3. 这两个字段不为必填，但添加/编辑页有醒目提示引导填写。

**验收标准**：字段可填可改可查；筛选可用。

### P1-6 添加人与批次追溯

**现状**：批量导入的条目添加人全为 system。

**需求**：
1. 批量导入必须记录真实操作人（接口增加操作人参数，或登录态导入）；
2. 每次批量导入生成批次号，支持按批次查看全部条目；
3. 支持按批次整体回滚（该批次新增的全部删除、覆盖的全部恢复原值）。

**验收标准**：导入后条目添加人显示真实姓名；可按批次号查出全部条目并一键回滚。

### P2-7 召回测试嵌入编辑页

**现状**：验证召回需芭比登录→跳转 Waking 数据库管理页→手动输入 query 测试，链条长，多数人不会用。

**需求**：添加/编辑页内嵌"召回测试"按钮，输入 query 实时返回召回 top3 及相似度分值，添加前即可验证目标 query 能否召回本条。

### P2-8 环境标识与同步

**现状**：大家添加在 PRD，车端多为 DEV，存在环境错配。

**需求**：条目带环境标识；列表按环境筛选；支持 DEV↔PRD 批量同步（复制）和差异对比视图。

### P2-9 变更历史与回滚

**需求**：每条示例记录修改历史（谁、何时、改了什么前后的值），支持单条回滚到任一历史版本。解决老旧示例（工具名变更等）长期无人修的追溯问题。

## 五、配合流程（非平台需求，会上已定的 SOP）

1. **单条 Meego bug**：修复人在平台直接添加，在 Meego 单上贴动态示例 ID（列表最左列主键）+ 自测结果；测试复测关单前检查，缺信息打回；
2. **批量修复**：统一在 Excel 模板维护 → 群内过一遍 → 审核人审查 → 批量导入；
3. **分工原则**：按问题分类/功能模块认领（不按 query 均分），避免同类问题多人重复添加。

## 六、范围框定

**本期（P0）**：查重拦截、全量导出、批量修改+删除。这三项不做，批量修复和全量测试两条路都走不通。

**二期（P1）**：审核上线流程、自测凭证、批次追溯。

**三期（P2）**：召回测试嵌入、环境管理、变更历史。

**明确不做**：不兼容旧 Excel 台账的合并单元格等乱格式（以平台标准模板为准）；不做复杂的权限体系（现阶段就 4-6 个内部用户）。

## 七、开放问题

1. 相似度匹配的阈值默认值和可调范围，需梦尧评估检索侧现有能力（会上泽民提到"之前有检索策略后来没加"，确认能否复用）；
2. 导出的审批链挂哪位 leader（正伟/晓杰，浩然会上说可群内 push）；
3. 批次回滚对"已被后续人工修改过的条目"的处理策略（跳过 or 强制回滚）。
