# L 章新增部件与概念候选

按全站部件卡片 1～98 去重。沿用既有名称的部件包括车上的 30B 视觉模型（6）、上下文服务（27）、车况与情景（28）、车上回执（40）、长时观察任务的任务侧（74）、Planner 的 event（76）、云端触发器（83）和事件日志生产（96）。下面补的是车端侧的运行与交接，按 7 月、8 月、9 月和 10 月各阶段注明范围。

## C01 端侧触发器

- **是什么｜**车上监听本地事实、核验规则成立后交给任务业务的模块。
- **运行位置与输入｜**车机，收电源、车况、视觉结果、任务开关、时间或事件；旧方案也让它发 VLM 启停指令。
- **输出｜**命中或跳过的结论，命中时附任务、子场景、时间和依据；10 月天气链路发本地业务事件。
- **关键数字与边界｜**804 删通用触发器 P0，10 月本期纯端主例 1 项；判断与拉卡、用户确认和控车分别验收。
- **来源｜**[7-08 第三轮逐字稿](feishu/文字记录：804：端侧触发至VLM数据上报context评审（第三轮）_2026年7月8日.md) L416–444、L568–580，[10-20 框架](feishu/PRD｜系统预设任务配置平台与端云交互框架.md) L87–145、L246–254。

## C02 AI Box 与 VLM SDK

- **是什么｜**AI Box 是车上的视觉计算设备，VLM SDK 是让应用发起或停止视觉任务、管理运行资源的接口层。车上的 30B 视觉模型沿用卡片 6。
- **运行位置与输入｜**车载计算设备，收相机画面、模型任务和启停条件；804 的舱外自启由 VLM Agent 承接。
- **输出｜**模型原始结果及运行状态，分给端侧订阅者；周期及摄像头调度由 SDK 或其所在运行层负责。
- **关键数字与边界｜**11 月舱外模型表写 3 秒轮询、1920×1080，采集视频、模型帧和轮询间隔分别核对。
- **来源｜**[7-06 VLM 链路](feishu/文字记录：端侧触发器：端侧预置任务-VLM相关链路讨论_2026年7月6日.md) L1276–1324，[7-08 第三轮逐字稿](feishu/文字记录：804：端侧触发至VLM数据上报context评审（第三轮）_2026年7月8日.md) L416–444，[11-11 模型汇总](feishu/【AICar】主线端侧VLM需求汇总_V1.0.md) L1355–1389、L1565–1643。

## C03 常驻观察任务（AlwaysOn）

- **是什么｜**系统预设的周期感知，用多次刷新让业务随时读到当前观察。
- **运行位置与输入｜**车上 VLM SDK 或 Agent；按 804 评审及后续上传稿，舱外随 AI Box，舱内动态及静态还看持续观察开关，关机或关相应开关停。
- **输出｜**舱外天气、路面等描述，舱内动态动作与神情，及舱内低频静态信息；有效输出发布到订阅主题。
- **关键数字与边界｜**7 月讨论节律依次为舱外 3 秒、舱内动态 5 秒、舱内静态 5 分钟，赛力斯 11-03 V1.3 沿用。采集时窗、执行用时与 T 章用户长时任务的实际回包分开。
- **来源｜**[7-06 动态 Advisor 逐字稿](feishu/文字记录：聊下动态adviser触发条件判断承接方_2026年7月6日.md) L92–144、L256–272，[视觉上传规范 A46](../lecture-rewrite-20261029/async-source-compact/A46.md) L52–66，[赛力斯 V1.3 模型规格](../../../HTML/01-进行中/_v32/artifacts/vlm_verified_source.md) L28 第 11–13 行。

## C04 单次观察（视觉 OneShot）

- **是什么｜**有一次明确触发或观察请求才取画面，完结后释放资源。
- **运行位置与输入｜**车上 VLM SDK；输入如切 P 后观察充电设备的指令，或已有模型任务编号和目标。
- **输出｜**本次任务终态及有时效的结果，可走本地业务或后续数据回传，订阅者和 response 路径按项目核。
- **关键数字与边界｜**7 月通用触发器设计超时或失败后重试 1 次，数据漏传补 1 次是另一个计数；SOP 同名 OneShot 是语音形态。
- **来源｜**[端侧触发器 PRD](feishu/端侧触发器_-_PRD.md) L231–244、L316–333，[7-06 VLM 链路](feishu/文字记录：端侧触发器：端侧预置任务-VLM相关链路讨论_2026年7月6日.md) L1480–1748，[SOP 对照](sop-items.md) S01–S06 及同名说明。

## C05 视觉运行指令

- **是什么｜**让调度与模型运行层知道“跑哪次、看什么、排多前、等多久”的调用约定。
- **运行位置与输入｜**任务发起方在车上组装并交 VLM SDK，调用时带本次任务参数。
- **输出｜**同步送达结果，其后以同一次任务身份关联工作状态和数据。
- **关键数字与边界｜**5 月对齐标识、目标、优先级、超时 4 类，7 月九项示例中的相机、互斥组、来源、有效期、执行类型及 P3/3 秒都带删除线，保留作候选字段。
- **来源｜**[5-09 排期逐字稿](feishu/文字记录：端侧触发器项目讨论与排期_2026年5月9日.md)  00:05:41–00:06:35，[端侧触发器 PRD](feishu/端侧触发器_-_PRD.md) L323–329。

## C06 摄像头互斥、抢占与恢复

- **是什么｜**同一时间同一受限资源只由可运行任务占用；高优来时暂停低优或让它排队，释放后按上下文恢复。
- **运行位置与输入｜**车端视觉运行层；收任务优先级、正在占用的相机及任务完成或失败状态。
- **输出｜**启动、暂候或抢占，任务超时或结束时释放；低优还有运行资格时恢复。
- **关键数字与边界｜**4 月有 P0～P3 设想；运行资源优先级、同一次规则候选优先级和天气雪雨雾顺序是三套判断；同相机测试须含抢占后恢复。
- **来源｜**[5-09 排期逐字稿](feishu/文字记录：端侧触发器项目讨论与排期_2026年5月9日.md)  00:15:22–00:21:23，[7-06 VLM 链路](feishu/文字记录：端侧触发器：端侧预置任务-VLM相关链路讨论_2026年7月6日.md) L1276–1324，[端侧触发器 PRD](feishu/端侧触发器_-_PRD.md) L223–248。

## C07 控制通道

- **是什么｜**调用方看工作是否真的启动、跑完或停止的状态回路。
- **运行位置与输入｜**车上 VLM SDK 到调用方，关联原指令和任务身份。
- **输出｜**同步送达成功或失败；异步已启动、成功、空结果、超时、失败、已停止，供续跑、释放和告警。
- **关键数字与边界｜**2 层反馈，设计举例为 1～2 秒后异步回调；实际时限按任务与项目决定，空识别不是超时。
- **来源｜**[端侧触发器 PRD](feishu/端侧触发器_-_PRD.md) L130–209、L223–264、L325–329。

## C08 数据通道

- **是什么｜**把实际视觉输出分发给本地消费者及有资格的云端消费者的路径。
- **运行位置与输入｜**车上 SDK 发布结果主题，得到许可的订阅者收原始 JSON；历史资料写数据中心，9 月上传规范写 AI Service 订阅后转云端端状态。
- **输出｜**整包结果和用于关联的类型及时间，云端在接收后才解析；本地天气可直接消费本地结果。
- **关键数字与边界｜**周期只发最新，OneShot 漏传补 1 次；上传临时暂存与长期持久化分开，过期销毁；发布成功和云端读到分别验证。
- **来源｜**[端侧触发器 PRD](feishu/端侧触发器_-_PRD.md) L136–147、L323–333，[视觉上传规范 A46](../lecture-rewrite-20261029/async-source-compact/A46.md) L45–75。

## C09 车端数据中心

- **是什么｜**车上的运行时信息分发点，支持订阅信号变化并按需要读有关当前值。
- **运行位置与输入｜**车机，收端状态和业务变化，数据版本各定义具体来源；9 月天气开关例收同一任务 ID 的新旧值。
- **输出｜**通知 Trigger 或其他订阅者，按协议转发；天气开关真值由车控 APP 持久化，重启后由车控同步。
- **关键数字与边界｜**无统一频率；9 月方案举键值对中的 1 个任务 ID 如 weather，值 on/off 属示意。
- **来源｜**[8-11 技术评审](feishu/文字记录：触发器端侧自闭环任务技术方案评审_2026年8月11日.md) L168–192，[9-22 任务中心续会](feishu/文字记录：小范围聊一下任务中心和端侧触发器的链路实现_2026年9月22日.md) 00:33:48–00:40:39、00:42:13–00:43:22。

## C10 端侧规则协议

- **是什么｜**把“听哪种变化、查哪些条件、合格后交什么动作”交给车机运行的 JSON 约定。
- **运行位置与输入｜**规则配置和车端加载时使用；顶层 version、content，每条含 id、name、description、trigger、conditions、actions、priority。
- **输出｜**事件对规则的订阅关系、要算的条件和可交给执行方的动作树。
- **关键数字与边界｜**8 月提议 version 为整数加 1；一条可关心多个事件，一个事件可叫醒多条，订阅唤起与条件成立各有日志。
- **来源｜**[8-11 技术评审](feishu/文字记录：触发器端侧自闭环任务技术方案评审_2026年8月11日.md) L32–44、L100–116、L160–192。

## C11 规则脚本引擎（QuickJS）

- **是什么｜**8 月方案选用的 JavaScript 执行器，按可枚举字段、当前值、旧值和时间执行确定判断。
- **运行位置与输入｜**车端沙盒，只有当前规则所需数据中心上下文。比较过自研、Rhino、AviatorScript 和 QLExpress。
- **输出｜**true 或 false，候选和动作交执行管理层。
- **关键数字与边界｜**技术评审给出 5 类条件例；标准 JavaScript 支持复杂 JSON、数组、正则、嵌套和日期，选型也考虑 Go 适配及隔离，云端当时仍用自定义协议。
- **来源｜**[8-11 技术评审](feishu/文字记录：触发器端侧自闭环任务技术方案评审_2026年8月11日.md) L44–100、L120–192、L196–224、L744–764。

## C12 规则命中仲裁

- **是什么｜**一条变化叫醒多条规则后，从同时满足的候选里决定谁先派发。
- **运行位置与输入｜**端侧触发器，收各条件结果、候选优先级及适用的业务限制。
- **输出｜**仲裁后的候选交任务管理再执行或交具体业务处理。
- **关键数字与边界｜**priority 为一期预留；同优先级时的通用策略、复杂仲裁和是否并行待按业务单独明确。天气同刻命中用雪、雨、雾顺序。
- **来源｜**[8-11 技术评审](feishu/文字记录：触发器端侧自闭环任务技术方案评审_2026年8月11日.md) L36–44、L168–192，[天气专项 V1.2](feishu/【机密】天气路况保护_PRD_V1.2_20261009_副本.md) L367–387。

## C13 规则版本同步和本地配置仓库

- **是什么｜**后续方向，由车端检查规则版本、下载并保存新规则，加载到当次本地引擎。
- **运行位置与输入｜**配置服务在云端，配置同步、加载和文件仓库在车上，输入本地已有版本和可用的车型规则。
- **输出｜**版本没变化时继续当前规则，有更新时下载、替换和加载后按新规则监听。
- **关键数字与边界｜**8 月举启动或每 10 分钟轮询为例，周期未定；10 月当期仍按任务开发，回滚、失败原子性和验收需单核。
- **来源｜**[8-11 技术评审](feishu/文字记录：触发器端侧自闭环任务技术方案评审_2026年8月11日.md) L160–176、L744–780，[10-20 框架](feishu/PRD｜系统预设任务配置平台与端云交互框架.md) L9–13、L396–408。

## C14 端侧动作与执行管理

- **是什么｜**条件成立后可指定的车控函数、即时卡、语音播报等车端能力。
- **运行位置与输入｜**8 月协议把动作交给端侧任务管理，输入 type 与其参数；10 月天气由原任务业务接收命中后承接拉卡和确认后动作。
- **输出｜**车控提交、卡片实际显示或播报结果，卡片的按钮可带下一组动作。
- **关键数字与边界｜**3 大类；技术评审的 function call 是使用已定的车控能力，别与 Planner 选择工具 vehicle_basic_control 或确认后的实车结果混用。

## C15 端侧业务事件与记录

- **是什么｜**本地条件命中后交给具体业务的一份结果，保留这次和后续确认、动作及回读的对应关系。
- **运行位置与输入｜**Trigger 和端侧业务之间，输入任务、命中子场景、时间、车况、识别依据。
- **输出｜**本次注册拉卡或其他固定动作及本地追踪数据；要参与云端跨模块消费、历史或监控时另走获准的出口及事件生产配置。
- **关键数字与边界｜**同类云端事件只定 1 个生产方；同一行为有两个明确用途时分 ID；Planner 本轮 event 为自然语言和时间戳 2 字段。
- **来源｜**[10-20 框架](feishu/PRD｜系统预设任务配置平台与端云交互框架.md) L248–254、L278–329，[G 章事件事实](../G-v2/facts.md) EVT-F025，[现行 Planner SP](../planner-sp-20261117/planner-sp.md) L24–31。

## C16 端侧即时交互卡的业务回调

- **是什么｜**已有卡片能力的本地确认接口，业务注册当前任务的按钮词、卡片有效期和回调含义。
- **运行位置与输入｜**车机，由天气等业务填文案、TTS、按钮、本地词条以及本次关联；读卡片真正展示、关闭、过期及用户操作。
- **输出｜**点击或本地语音命中同一按钮回调，交原业务处理；过期或模糊表达不产生同意。
- **关键数字与边界｜**湿滑的卡片例是确认/取消 2 个按钮；语音只有支持的本地词才走该路径，云端 current_page_specific 另见 W/SP。
- **来源｜**[10-20 框架](feishu/PRD｜系统预设任务配置平台与端云交互框架.md) L252–254、L292–391，[现行 Planner SP](../planner-sp-20261117/planner-sp.md) L2912–2922。

## C17 本地闭环

- **是什么｜**在本车把一次识别和判断推进到用户选择、车辆动作、读回结果。
- **运行位置与输入｜**车端 Trigger、业务、卡片、车控协作，读观察、本车状态、任务开关和有时效的同意。
- **输出｜**完成、失败、未知、拒绝或失效，仍开启的长期预设回到等待；根据合规需求另发埋点或获准的记录。
- **关键数字与边界｜**天气一张卡的一次确认对应这一项动作；DT/Planner 不参与本地拉卡和本地确认。
- **来源｜**[10-20 框架](feishu/PRD｜系统预设任务配置平台与端云交互框架.md) L246–329，[天气专项 V1.2](feishu/【机密】天气路况保护_PRD_V1.2_20261009_副本.md) L375–387、L766–925。

## C18 系统预设任务

- **是什么｜**产品预先定义，用户只需开关即可长期等待条件的任务。
- **运行位置与输入｜**各任务按设计在端或云运行，由任务中心展示和接收开关；输入本车真状态、场景参数和启用状态。
- **输出｜**每次提醒或处理结果，完成后可回到等待，关闭拦截新的触发。
- **关键数字与边界｜**10 月本期 4 项，1 项天气端侧、3 项云端；项目资料中的“本期”不是全站通用数量。
- **来源｜**[9-22 任务中心续会](feishu/文字记录：小范围聊一下任务中心和端侧触发器的链路实现_2026年9月22日.md) 00:05:01–00:08:47，[10-20 框架](feishu/PRD｜系统预设任务配置平台与端云交互框架.md) L5–13、L87–145。

## C19 任务开关的端云归属

- **是什么｜**任务中心单个任务的启用状态应由执行该任务的一侧维护。
- **运行位置与输入｜**端侧天气由车控 APP 保存，重启回读并经数据中心通知 Trigger；云端条目由云端保真并给任务中心回包。
- **输出｜**真实开关回显及各侧触发门禁更新，断网时本地条目仍可在，本期云端列表可能拉取失败。
