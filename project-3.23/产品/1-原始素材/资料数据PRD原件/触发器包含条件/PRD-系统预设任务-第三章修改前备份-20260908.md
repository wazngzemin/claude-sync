# 系统预设任务PRD

## 需求背景

系统预设任务，是产品提前定义好、用户不用每次重新创建的服务。用户在任务中心启用后，系统在条件满足时，按约定直接处理或先询问，再完成任务执行并反馈结果。本次要把“任务怎么配置和启停、何时触发、如何交互、谁执行、如何结束”接成完整链路，而不是只定义触发条件。

### 3\.1 当前平台的定位与现有能力

当前入口是“AI汽车管理平台 \&gt; 触发器 \&gt; 场景管理”。它已经能配置一条 Trigger 场景的适用范围、触发条件、后续动作、触发频率和触发记录。因此，它解决的是“什么情况下产生一次场景事件、把事件交给谁”，还没有覆盖“用户如何管理任务、任务在哪运行、如何询问用户、车辆是否真正执行成功”的完整预设任务闭环。

当前已核实能力：
• 场景与发布范围：可配场景名称、优先级、渠道、指定车辆、车型、软件版本，并支持新建、编辑、复制、启停。结论：可以继续作为预设任务的触发规则配置入口。
• 触发条件：区分动态条件和静态条件；可选车状态信号或VLM信号；支持组内AND、组间OR，以及“等于”“变更为”等判断。结论：规则框架可复用，但每个渠道实际有哪些信号可选，需要按能力清单确认。
• 后续动作：可选择舒适、情感、出行、内容Advisor，也可选择主动推荐、延时执行或自定义回调，并填写参数。结论：只能证明事件可以交给下游，不能把“动作调用成功”写成“整项任务已经执行成功”。
• 频控与记录：可配置执行总次数、单次上电次数、自然日次数和最小间隔；触发记录包含场景、车辆、触发条件、执行结果和Log ID。结论：可以追查是否触发，但页面里的“执行结果”是否等于车辆真实状态回读，仍需研发确认。
• 赛力斯VLM：【待确认】本次实查选择“赛力斯 \+ VLM信号”时，下拉框显示“暂无数据”。需要确认是能力尚未注册、渠道或权限问题，还是还有其他前置条件；确认前不能承诺相关任务可直接在平台配置上线。

3\.2 完整任务需要补齐三层能力

第一层，任务管理层：配置任务中心展示的任务名称、说明和开关，并明确谁真正保存启停结果。任务中心只转发用户操作，不能把“用户点击开启”直接当成“任务已经生效”。

第二层，运行规则层：为每项任务固定选择端侧或云端作为唯一运行方；复用当前页面配置适用范围、动态/静态条件、后续动作和频控。端云不是根据有没有网络临时切换，也不能同时各触发一次。

第三层，交互与结果层：配置本任务是静默执行、仅告知还是需要确认；需要确认时，明确卡片、TTS以及端侧“可见即可说”或云端Planner的承接方式；用户确认后还要重新检查最新车况，最后以车辆真实状态判断成功或失败。

完整产品链路：产品一次定义完整任务 → 平台校验所需能力是否齐全 → 展示信息发给任务中心、运行规则发给指定端侧或云端 → 用户开启并得到真实生效结果 → 唯一运行方判断条件 → 按任务约定交互 → 端侧执行前复核并车控 → 读取真实车辆状态并回传结果。
