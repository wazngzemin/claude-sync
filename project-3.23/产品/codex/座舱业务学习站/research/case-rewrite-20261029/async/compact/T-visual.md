### 动态感知任务定义
以舱内高频AlwaysOn任务为载体（预计上报周期6\-7s），针对用户发起的特定感知目标持续推理并返回实时结果。每个动态感知任务包含**任务编号**和**感知目标**（user\_query 经 TaskService 改写后），VLM 在每次推理时同时输出默认感知结果和各动态任务的识别结果。
**感知目标可覆盖的动态感知维度：**
1. **乘客状态变化**：睡醒/入睡、哭闹/情绪变化、体位移动等
2. **行为事件**：是否系安全带、是否玩手机、是否有危险动作等
3. **物品状态**：物品遗留/移动/取放、宠物状态变化等
4. **不安全因素**：儿童独处、车门/车窗未关、危险物品等
5. **上下车事件**：乘客上车/下车、人员变化等
**任务约束：**同一时间最多支持 3 个动态感知任务并发，且任务编号不能重复；通过全量替换机制实现任务的增、删、改；AlwaysOn 开关关闭时下发空列表清除所有任务。
### **AlwaysOn 开关控制**
AlwaysOn 开关是舱内感知功能的总开关，决定系统是否允许响应并执行用户发起的舱内动态感知需求，该开关是**动态感知任务（dynamic\_watch\_tasks）**下发的前置条件。
1. **开关状态与系统行为**
    1. **开关开启（ON）**：系统正常响应用户的舱内动态感知需求，TaskService 可向 VLM 下发**动态感知任务（dynamic\_watch\_tasks）**
    2. **开关关闭（OFF）**：系统不响应用户的舱内动态感知需求，TaskService 禁止向 VLM 下发任何**动态感知任务（dynamic\_watch\_tasks）**；已下发的任务需通过全量替换为空列表进行清除。
2. **开关关闭时的用户答话策略**
    当用户在 AlwaysOn 开关关闭状态下发起动态长时感知需求时，系统必须给予明确、友好的答话反馈，避免用户产生\&\#34;系统无响应\&\#34;或\&\#34;功能故障\&\#34;的困惑。
    1. 答话原则：
        1. **明确告知**：直接说明舱内动态感知功能当前未开启，不回避、不模糊。
        2. **引导开启**：告知用户开启 AlwaysOn 开关的路径或方式，降低用户操作成本。
        3. **语气自然**：以对话感表达，避免生硬的系统提示语气。
    2. 答话示例：
        1. \&\#34;当前舱内感知功能还没开启哦，你可以在设置里打开 AlwaysOn 开关，之后我就能帮你持续关注啦～\&\#34;
        2. \&\#34;这个需要先开启舱内感知开关才行，开启后我就可以帮你盯着了，需要我引导你去设置吗？\&\#34;
3. **开关状态变更处理**
    1. **OFF → ON**：系统恢复舱内动态感知能力，用户可正常发起需求，TaskService 恢复任务下发权限。
    2. **ON → OFF**：TaskService 立即向 VLM 下发空任务列表（全量替换），清除所有正在执行的长时感知任务；若存在进行中的用户需求，应同步告知用户功能已关闭、任务已终止。
### **TaskService** 将**动态感知任务（dynamic\_watch\_tasks）**下发VLM
1. **VLM** 目前可以支持插入**动态感知任务（dynamic\_watch\_tasks）**的原始任务为**舱内高频AlwaysOn任务**
2. **舱内高频AlwaysOn任务**会在上电后自动开启，以一定的（预计上报周期为6\-7s，可能会有一定的小范围波动，也可能会出现其他高优任务抢占而导致任务无法进行推理从而无法上报的情况）周期上报感知结果：
    1. 在没有插入**动态感知任务（dynamic\_watch\_tasks）**时，输出默认感知结果
    2. 在插入**动态感知任务（dynamic\_watch\_tasks）**时，同时输出默认感知结果 \+ 动态感知任务的结果
3. **舱内高频AlwaysOn任务** 接收 **动态感知任务UP **的格式为：
```JSON
dynamic_watch_tasks:
[
    {
        "任务编号": "",
        "user_query": ""
    }
]
```

### 感知目标的改写
1. **VLM**将承担感知的角色，而用户的query可能是感知\+推理，所以再给VLM下发动态感知任务时需要**TaskService** 将用户的query进行改写，改写后的内容填入上述UP的感知目标里
2. 由于用户的query里可能有位置信息，该位置信息也需要进行指代消解
3. 改写的种子数据：[Director种子数据](https://bytedance.larkoffice.com/wiki/WTPIwriowis0vNkETBfcpyTLnob?sheet=9A01cq&rangeId=9A01cq_vDUNSiOiBW&rangeVer=1)
4. 需要注意：考虑到底层vlm任务的周期不定，而用户的query可能要求处理时间周期是每1分钟，这个每1min需要由**TaskService**  来进行处理。例如用户query：每分钟告诉我宝宝在干啥，VLM会不定周期返回宝宝在干啥，需要**TaskService**  自己设定定时器并在每分钟结合VLM的输出向用户进行反馈。

### **动态感知任务（dynamic\_watch\_tasks）**的增删改（全量替换机制）
1. 核心机制：
    VLM 没有提供单独的 \&\#34;新增 / 删除 / 修改\&\#34; 接口。每次 TaskService 下发**动态感知任务**时，VLM 都会用新列表完整覆盖旧列表。因此，任务的增、删、改全部由 TaskService 通过 \&\#34;下发新的全量任务列表\&\#34; 来实现。
2. 增删改与全量替换的对应关系
    
    
    操作
     | 
    实现方式
     | 
    典型场景
     | 
    
    新增任务
     | 
    在现有列表基础上追加新任务，全量下发
     | 
    用户发起新的感知需求
     | 
    
    删除任务
     | 
    从列表中移除该任务，全量下发（VLM 侧会自动清除）
     | 
    VLM 上报结果已满足用户需求
     | 
    
    修改任务
     | 
    保持任务编号不变，修改感知目标后全量下发
     | 
    用户调整感知目标
     | 
    
    清空所有任务
     | 
    下发空列表
     | 
    AlwaysOn 开关关闭
     | 
    
3. 示例
    1. 新增任务
    ```Plain Text
    // 当前已有任务：
    dynamic_watch_tasks:
    [
        { "任务编号": "8", "感知目标": "二排右侧的宝宝醒了吗？" }
    ]
    // 用户新增需求后，下发（追加任务7）：
    dynamic_watch_tasks:
    [
        { "任务编号": "8", "感知目标": "二排右侧的宝宝醒了吗？" },
        { "任务编号": "7", "感知目标": "副驾睡着了吗" }
    ]
    // 结果：任务8保留，任务7新增
    ```
    2. 删除任务
    ```Plain Text
    // 当前已有任务：
    dynamic_watch_tasks:
    [
        { "任务编号": "8", "感知目标": "二排右侧的宝宝醒了吗？" },
        { "任务编号": "7", "感知目标": "副驾睡着了吗" }
    ]
    // 任务8结果已满足需求，下发（移除任务8）：
    dynamic_watch_tasks:
    [
        { "任务编号": "7", "感知目标": "副驾睡着了吗" }
    ]
    // 结果：任务8被清除，任务7保留
    ```
    3. 修改任务
    ```Plain Text
    // 当前已有任务：
    dynamic_watch_tasks:
    [
        { "任务编号": "8", "感知目标": "二排右侧的宝宝醒了吗？" }
    ]
    // 用户调整感知目标，下发（编号不变，目标改变）：
    dynamic_watch_tasks:
    [
        { "任务编号": "8", "感知目标": "二排右侧的宝宝哭了吗？" }
    ]
    // 结果：任务8的感知目标被更新
    ```
    4. 清空所有任务
    ```Plain Text
    // 当前已有任务：
    dynamic_watch_tasks:
    [
        { "任务编号": "8", "感知目标": "二排右侧的宝宝醒了吗？" },
        { "任务编号": "7", "感知目标": "副驾睡着了吗" }
    ]
    // AlwaysOn开关关闭，下发空列表：
    dynamic_watch_tasks:
    []
    // 结果：所有任务被清除
    ```
