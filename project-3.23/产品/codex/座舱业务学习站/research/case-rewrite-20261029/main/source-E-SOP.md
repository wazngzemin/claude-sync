# Agent 管理平台使用 SOP

## 概述

Agent 管理平台是 AI 汽车管理平台的核心模块，用于管理智能座舱中各类 Agent 工具的**业务定义**与**技术实现**。平台采用\&\#34;定义—实现\&\#34;两层架构：先通过定义列表明确 Agent 的业务能力边界，再通过实现列表配置具体的技术实现和租户隔离。

新Agent体系的收益：

- 定义与实现解耦，可以实现一对多场景

- 租户维度隔离，互相不影响

- 同一个定义支持多个草稿版本实现，可快速切换进行实验对比

- Director sp中的工具信息改为动态加载，规避一些格式问题

### 新建 Agent 定义

**操作步骤：**

1. 点击页面右上角 **「新建 Agent 定义」** 按钮

2. 填写以下必要信息：

    - **英文名称：** Agent 的唯一英文标识，如 `vehicle\_basic\_control`，**供director使用**

    - **中文名称：** Agent 的中文标识，如\&\#34;车控控制工具\&\#34;，**供director使用**

    - **UI 展示名称：** 展示在UI上给用户看的简短名称，如\&\#34;车辆控制\&\#34;

    - **描述：** Agent 功能的详细描述，**供director使用**

3. 点击提交完成创建

<div class="callout">

**命名规范建议：**

- 英文名称采用 snake\_case 格式命名（如 vehicle\_basic\_control、weather\_search）

- 描述字段应尽可能详细，列举工具可控制/查询的具体功能点，方便大模型理解调用时机

</div>

### 1\.3 编辑 Agent 定义

在定义列表的操作列点击 **「编辑」**，可修改中文名称、UI 展示名称和描述等字段。

### 1\.4 删除 Agent 定义

在操作列点击 **「删除」** 可移除不再使用的Agent定义。

**删除前必须确认：**

1. 点击 **「查看实现」** 检查该Agent定义下是否存在关联的实现

2. 如有关联实现，需先逐一禁用对应的实现，再删除定义，直接删除定义会报错：系统还存在激活状态的Agent，请禁用后再进行删除操作。

### 2\.2 新建 Agent 实现

可通过三个入口发起：

1. 定义列表 → 操作列 → 「新建实现」

2. 实现列表 → 对已有实现点击 → 「新建实现」

3. 实现列表 → 复制按钮 → 「新建实现」

<div class="callout">

**新建实现表单字段详解：**

**实现信息模块：**

- **Channel**（必填）：选择渠道，如\&\#34;AIDV主线\&\#34;

- **Channel App ID**（必填）：渠道对应的 App ID

- **是否参与Director推理**（必填）：选择\&\#34;是\&\#34;或\&\#34;否\&\#34;

- **集成类型**（必填）：选择\&\#34;云端\&\#34;或\&\#34;车端\&\#34;

- **Agent 类型**（必填）：选择 Agent 类型（提供方），如 `aidv`、`dpfm`、`doubao（豆包提供）`、`ecology（三方提供）`

- **生效环境**：输入环境标识后回车添加

- **Notice**：Agent 的限制说明，如\&\#34;不支持开关车门\&\#34;，**供director使用**

- **重写描述**：可覆盖定义中的描述，**供director使用**

- **参数描述**：Agent 的输入参数说明，**供director使用**

- **Tips**：Agent 使用提示信息，**供director使用**

**接入点信息模块：**

- **接入类型**：支持 `http`、`kitex`、`mcp`、`frontier` 四种方式

- **认证类型**：支持 `APIKey`、`X\-Signature`、`VAuth\-V1`、`SAIC\-OpenAPI`

- **认证信息 AK/SK**（必填）：接口的 Access Key 和 Secret Key

- **Method**（必填）：HTTP 请求方法，如 POST

- **Host**（必填）：接口域名

- **Path**（必填）：接口路径

- **Port**：端口号（可选）

</div>

### 2\.3 查看实现详情

在操作列点击 **「查看」**，可查看该实现的完整配置信息，包括参数信息和接入点信息的 JSON 全文。

### 2\.4 复制实现

在操作列点击 **「复制」**，基于已有实现信息做针对性修改，快速创建一份新实现。

### 2\.5 启用 / 禁用实现

在操作列点击 **「禁用」** 或 **「启用」**：

- **禁用：** 该实现临时下线，不会被使用，但配置保留，可随时重新启用

- **启用：** 恢复该实现的在线状态

<div class="callout">

**注意：** 禁用操作仅影响当前实现，不影响同一定义下其他渠道的实现。上线前请确保至少有一个对应渠道的实现处于启用 \+ 已发布状态。

</div>

### 2\.7 快速测试

点击页面右上角 **「快速测试」** 按钮，可立即发起一次临时对话测试，验证 Agent 实现的连通性和执行效果。

不指定Agent时，系统流程与车端流程类似，会由Planner进行工具选择，以及对响应内容进行总结。指定Agent时，系统会跳过director模块，直接请求Agent，并展示Agent的响应内容。

<div class="callout">

**注意：** 暂时只能支持一些纯文本类交互的Agent的测试，例如：闲聊、天气、车书等。

</div>

## 标准工作流程

### 研发

1. **创建定义** → 在定义列表新建 Agent，填写名称和能力描述

2. **创建实现** → 为Agent创建实现，配置接入点和参数。如果是aidv自建Agent或未按照座舱Agent标准协议实现的Agent，则需要从Agent定义中拿到AgentID后进行代码开发。

3. **调通验证** → 通过「快速测试」验证 Agent 的对话效果和工具调用

4. **测试验证** → 在测试环境部署系统，并把Agent应用到指定的环境。

5. **代码上线（按需）** → 如有代码变更，则正常进行代码Review、发版流程。

6. **发布版本** → 确认测试通过后将Agent版本状态从\&\#34;草稿\&\#34;变为\&\#34;已发布\&\#34;

### 产品

Director SP中的工具模块由固定值转变为动态加载，但fornax上无法获取具体内容，因此产品同学在调优Director时的工作流程有变化。这里提供两种方案：

**方案一：**在fornax的变量中填写工具信息，调试没问题后在Agent管理平台做变更。prompt的其他模块与当前流程保持一致。

**方案二**：新建一个Prompt副本，调试没问题后在Agent管理平台做变更。调优后的prompt内容覆盖正式Prompt，工具模块使用占位符`\{\{tool\_info\}\}`替换。优势：测试Prompt和正式Prompt隔离，正式Prompt的版本数量和变更频率都能降低，与发布窗口对齐。

## 注意事项

<div class="callout">

**操作规范：**

- 操作前确认当前所选 **渠道（Channel）** 正确，避免误操作其他渠道的数据

- 英文名称创建后不建议修改，会影响下游实现的关联关系

- 删除操作不可恢复，删除定义前务必确认无关联实现

- 修改参数信息中的 param\_desc、notice、tips 会直接影响大模型的调用行为

</div>

<div class="callout">

**最佳实践：**

- **先测后发：** 每次配置变更后必须通过快速测试验证，再发布正式版本

- **善用复制：** 多渠道场景下用「复制」快速创建实现，仅修改差异部分

</div>
