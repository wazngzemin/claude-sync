# 豆包上车 表情与卡片提取

### 需求

PRD：[【路特斯项目】豆包车载版\-产品需求文档 V3\.0版本 ](https://bytedance.larkoffice.com/docx/N1D2dPRYmoAJzgxtLXpcwePfnnd) **2\.5\.9 人设对话\+联网检索 3）结果输出**

需求评审：[智能纪要：豆包上车【闲聊\&amp;联网】【天气】场景需求评审 2025年5月14日](https://bytedance.larkoffice.com/docx/ASo5dLsa1oWxA8xm995cxQgNntb?dcuId=6834386903116300290)

**需求1：闲聊表情提取（流式）**

在用户和AI助手（豆包）的对话中，提取助手回复内容的表情（情绪）。

表情类别（闭集）：

```Markdown
认可
祝贺
否定
快乐
悲伤
愤怒
惊讶
厌恶
恐惧
轻蔑
羞耻
困惑
安慰
担心
```

<div class="callout">

注意：将正反馈、负反馈映射为了表情，分别为认可、祝贺、否定，删去了正反馈、负反馈。

</div>

没有表情输出无。

**需求2：联网卡片关键信息提取（流式）**

联网结果中的关键信息、重点信息需要被提槽出，并于卡片渲染。

可提取单个信息或多个信息。所提取信息为开放域，以AI助手实际回复中包含的内容信息为准。

### 算法输出格式

（1）闲聊

单个表情结果，流式提取过程中可能会有跳变。

```Markdown
表情
```

（2）联网

单个关键信息，或多个关键信息。流式提取过程中，可能会从单个转为多个。

多个关键信息用换行符分隔。

只含纯文本。图片、视频、图表等需要前后端处理。

```markdown
单关键信息：
key

多关键信息：
key1
key2
key3
```



### 流式切分逻辑@吕鹏浩

切分逻辑

1\. 每满20、50、100、250、500、1000 token时各请求（提槽）一次。期间如果模型finish，则直接请求。

2\. \&gt;1000，直到结束后再请求最后一次，1000\~end期间不再流式请求。

即，每个query对应的回复，请求卡片提槽最多**7次**。

用字符模拟token的伪代码和例子如下。

```Python
def split_text_flow(text):
    """
    流式切分文本，模拟流式返回效果
    """
    split_num = [20, 50, 100, 250, 500, 1000]
    texts = []
    length = len(text)
    for num in split_num:
        if len(text) < num:
            texts.append(text)
            break
        texts.append(text[:num])
    if len(text) > split_num[-1]:
        texts.append(text)
    return texts
```

### 历史对话@吕鹏浩

在闲聊表情和联网提取时，需要传入历史对话。

内容为当前query下，流式提取过程中，前面轮次的请求和提槽结果。

user：提槽请求内容\(user prompt\)

assistant：提槽结果

卡片信息提槽举例：在“最近有什么热销的豪华车？”query下，第四次流式请求提槽模型时，历史记录如下：

### user prompt

user prompt是请求提槽时，发送给模型的请求内容，在结构体中用\{\&\#39;role\&\#39;: \&\#39;user\&\#39;, \&\#39;content\&\#39;: \&\#39;\&\#39;\}包装，常规的模型请求up内容，为用户请求的query本身。但提槽任务并不是问答\(QA\)，因此直接将query作为内容请求是不恰当的。

**闲聊up：**

```Markdown
以下是对话内容：
user：{query}
AI assistant：{text}
请提取AI助手回复的表情：
```

**联网up：**

```Markdown
以下是对话内容：
user：{query}
AI assistant：{text}
请提取AI助手回复的关键信息：
```

其中query是用户的问题，text是模型流式返回的文本结果。
