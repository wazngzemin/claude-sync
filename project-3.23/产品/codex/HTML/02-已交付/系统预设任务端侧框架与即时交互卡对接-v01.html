00 · READ THIS FIRST

你只需要交付两次“交接”

你不是卡片产品，也不需要替VUI写底层代码。你的PRD必须把Trigger与卡片之间的请求、回调讲清楚。

你本人职责
① 何时出卡

任务有效、信号可用、规则命中、防抖和去重通过后，才创建一次运行事件。

② 给卡片什么

事件标识、来源、文案、按钮、TTS、本地语音路由、有效期、回调对象。

③ 卡片回什么

展示结果；确认/拒绝/关闭/超时；卡片隐藏、过期、打断等生命周期事件。

④ 回来后做什么

再次读最新状态；通过才车控；读取真实车辆状态；把结果更新回卡片。

不要这样提需求：“天气满足就弹卡，用户点确定就开灯。”它缺少任务门禁、数据时效、事件ID、展示ACK、语音路由、卡片过期、执行前复核和真实状态回读。
应该这样提：“Trigger为本次命中创建run_event，调用标准卡片能力；卡片带同一run_event返回标准选择；Trigger复核后执行，最终用真实车况更新卡片。”
01 · BACKGROUND / OBJECTIVE

为什么需要独立的端侧框架

天气Trigger前半段已进入开发，但“条件命中之后如何问用户、用户回答如何回来、车控怎么收口”仍未形成一份可对接合同。

天气链路明确

问题

任务中心、Trigger、VUI、可见即可说和车控各自有能力，但资料把“弹卡”写成一个动作，研发无法据此联调。

目标

让每个团队都能回答：谁发什么、谁判断、谁返回什么、事件何时失效、哪一种状态才算成功。

用户价值

危险天气下弱网仍能及时询问；用户拒绝或场景变化不误执行；页面展示和车辆真实状态一致。

受众看完后必须知道不要求本次完成
端侧Trigger研发规则命中后如何创建事件、调用卡片、消费反馈、复核和收口本次不要求给出排期
VUI/即时交互卡研发端侧Trigger拉卡需要什么协议、如何返回ACK/交互/生命周期不替Trigger判断天气规则
可见即可说研发卡片有效期内如何注册按钮语义、如何注销、如何形成标准结果不做开放域Planner理解
赛力斯信号/车控提供什么状态、执行什么动作、如何回读真实结果不决定主动服务策略
测试按事件ID还原整条链，验证弱网、超时、重复、状态变化和假成功不替产品决定规则冲突

时序图：Trigger和卡片具体怎么“握手”

不是一次调用，而是四次交接：创建卡片、展示ACK、用户结果、执行结果更新。

产品合同

sequenceDiagram
  participant D as 任务状态/数据中心
  participant T as 端侧Trigger
  participant C as 即时交互卡
  participant U as 用户/可见即可说
  participant V as 赛力斯车控
  D->>T: ENABLED + 信号变化 + 最新快照
  T->>C: InteractionRequest(run_event/文案/按钮/TTS/路由/有效期)
  C-->>T: CardAdmissionAck(展示/排队/失败, card_id)
  C->>U: 展示卡片 + TTS + 注册本地词条
  U-->>C: 点击或语音选择
  C-->>T: InteractionResult/Lifecycle + run_event_id
  T->>D: 执行前读取最新状态
  D-->>T: 最新快照
  T->>V: 复核通过后调用车控

时序底线：卡片显示成功不等于用户确认；用户确认不等于车控成功；RPC成功不等于目标状态达到。三个“成功”必须分别记录。

05 · DATA CONTRACT

你给卡片什么，卡片必须回什么

以下是产品合同，不是已经签字的IDL。研发可以改字段名，但不能丢失业务语义。

字段名建议

A. Trigger → 即时交互卡：InteractionRequest

字段/信息为什么必须有天气示例缺失后果状态
task_definition_id区分长期任务模板weather_protection无法按任务做频控和追踪建议
task_instance_id区分车辆/账号的启用实例vehicle_A_weather可能串车或读取错开关建议
run_event_id唯一关联本次触发、卡片和车控weather_fog_1001旧确认可能执行新事件P0必须有
source_type告诉客户端使用哪条语音回路EDGE_TRIGGER可能错误进入Planner业务语义明确
interaction_mode确认、告知、静默结果不能混用CONFIRM_LOCAL按钮/TTS/收音行为不确定建议
文本/按钮定义用户看到的问题和标准选择“是否打开后雾灯” + 打开/暂不处理卡片无可执行内容需业务提供
TTS策略定义是否播报、播什么、禁语音如何降级询问TTS；禁语音时card-only方向待确认可能误播或无法确认降级待定
voice_route端侧任务必须走本地可见即可说VISIBLE_SAY离线失效或语义链路错误端侧方向明确
click_route点击应返回原业务事件ORIGIN_CALLBACK点击后无人消费正式协议待定
有效期/优先级/回调控制过期、仲裁和结果归属具体值待VUI专项确认旧卡执行、打断错乱P0待定

B. 即时交互卡 → Trigger：三类返回

返回对象建议枚举必须携带Trigger怎么处理
CardAdmissionAckDISPLAYED / QUEUED / REJECTED / FAILEDcard_id、run_event_id、错误原因、时间只有进入有效展示态才等待用户；失败结束或按策略处理
InteractionResultCONFIRM / REJECTcard_id、run_event_id、option_id、输入渠道、时间确认进入复核；拒绝不执行并冷却
CardLifecycleEventCLOSE / TIMEOUT / INTERRUPTED / EXPIRED / RESUMEDcard_id、run_event_id、原因、时间卡片无效即注销词条；旧结果不得继续执行

C. Trigger/车控 → 即时交互卡：ActionUpdate

状态卡片展示判断依据禁止做法
EXECUTING执行中复核通过且动作已发出用户刚确认就直接显示成功
SUCCESS后雾灯已开启/模式已切换车辆真实状态达到目标仅看RPC返回SUCCESS
FAILED操作未完成及可理解原因真实状态未达成或明确错误无限重试或展示假成功
CANCELLED场景已变化，本次不再处理执行前复核失败使用过期授权继续执行

07 · EXCEPTIONS / ACCEPTANCE

异常与验收：研发拿到就知道怎么证明

框架宣讲不承诺排期，但必须说明每个失败分支的安全结果。

误执行必须为0
编号场景预期结果主要责任必须观察的证据
EA-01任务关闭，天气条件全部满足不创建run_event、不出卡、不TTS、不车控状态适配+Trigger门禁日志
EA-02无网，浓雾条件满足本地出卡、TTS、本地语音确认、车控闭环可用Trigger+VUI+可见即可说断网实车录屏与事件日志
EA-03卡片展示失败Trigger不进入已授权，不车控；记录失败原因VUI+TriggerCardAdmissionAck
EA-04用户拒绝/关闭/超时不执行、注销词条、进入冷却VUI+TriggerInteractionResult/Lifecycle
EA-05卡片过期后用户说“好的”旧run_event不得被消费可见即可说+VUI词条已注销、无车控调用
EA-06用户确认后天气消失或任务关闭执行前复核失败，本次取消Trigger/执行层PRECHECK_FAILED原因
EA-07同一信号重复上报同一事件只出一张卡、只执行一次Triggerdedupe_key/run_event
EA-08RPC成功但后雾灯仍OFF最终判失败，不展示“已开启”车控+状态回读+VUIRPC与真实状态对照
EA-09用户确认前已手动开启后雾灯不重复车控；可按已达成收口执行前复核最新状态时间戳
EA-10用户Query打断主动卡按VUI仲裁结论挂起/关闭；恢复前重新验证事件VUI/仲裁+TriggerINTERRUPTED/RESUMED事件

通过标准

每次事件可由task、run_event、card和action关联；任何失败都能定位在哪一段。

专项待定

卡片有效期、主动服务优先级、打断恢复、TTS禁用降级、防抖和冷却值。

禁止上线

无事件ID、无展示ACK、卡片消失仍可确认、车控无真实状态回读。

08 · REVIEW SCRIPT

你在会上从哪里开始，怎么说

先讲边界，再讲四次交接，最后用浓雾走一遍。不要先念字段表。

可直接照读
开场：
“今天只讲端侧系统预设任务框架，不评具体排期。我的Trigger负责判断任务是否有效、天气和车辆条件是否命中；即时交互卡不判断天气，也不直接车控，它只负责展示问题和返回用户选择。两边需要对齐的是一份交互合同。”

讲合同：
“Trigger命中后创建一次run_event，把来源、文案、按钮、TTS、本地语音路由、有效期和回调信息给卡片。卡片要返回展示ACK、用户选择和卡片生命周期。只有同一run_event返回有效确认后，Trigger才重新读取最新车况、调用车控，并用真实车辆状态更新卡片。”

讲天气：
“例如浓雾：任务已开启、车速大于30、浓雾成立、后雾灯关闭，Trigger才出卡。用户说‘打开吧’由本地可见即可说映射成CONFIRM；如果卡片已过期、天气消失或后雾灯已开，就不再执行。真实状态变为ON才展示成功。”

现场只问这8个问题

  1. 即时卡是否已有统一创建、更新、关闭接口？正式Owner和IDL在哪里？
  2. 拉卡时如何显式携带端侧来源和本地语音路由？
  3. 展示成功、排队、拒绝、失败分别如何ACK？
  4. 可见即可说的按钮词条由业务注册还是卡片自动注册？卡消失如何注销？
