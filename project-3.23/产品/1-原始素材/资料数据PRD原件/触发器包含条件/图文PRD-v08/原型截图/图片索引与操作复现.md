# PRD v08 原型截图索引与操作复现

截图来源为本机已交付的《触发器配置平台-交互原型-v08.html》。本次没有改 HTML，没有补画不存在的控件，没有调用线上接口。画面中的车辆、输入和运行结果都是明确标注的演示数据。

## 1. 正文如何摆放这些图片

每张图放在它对应的需求段落旁边，不把所有截图集中堆在附录。先用一段话说明这个页面解决什么问题，再展示区域截图，再用字段表说明填写规则、修改后的影响和保存校验。截图本身不能代替字段说明。

整体画布和节点属性分开讲。S05 展示节点关系；S06 至 S08 是属性特写，避免把右侧窄面板缩在一张大图里。S06、S07 分上下截图，是因为实际属性区有滚动，不能把没拍到的字段当作读者已经看过。

建议统一使用正文自然宽度。图片的逻辑宽度为 916 至 1136 像素，输出使用 1.5 倍像素密度；不要把属性图强行放大成模糊的整屏图。无需在截图上额外叠一层密集文字，解释写在图下。

## 3. 手动复现步骤

打开原型时先使用独立演示环境，避免把截图中的虚拟场景与自己已保存的本地草稿混淆。复现脚本使用独立 headless 浏览器上下文，只清空该上下文的本地数据，不清空用户浏览器中的数据。

### 3.1 基础、简单条件与视觉目标

1. 在页面顶部“业务示例”选择“简单：车速条件示例”，如出现“替换未保存内容”弹窗，确认载入。
2. 分别定位“基础信息”和“发布范围”，得到 S02 与 S02b。定位“触发条件”，得到 S03。
3. 在同一业务示例中选择“闪念（简单）：单视觉目标 + 固定通知”，定位判断区域，得到 S04。
4. 向下定位“执行动作设置”，得到 S09；定位“执行策略设置”，得到 S09b。
5. 点底部“新建场景”，校验通过后的保存摘要为 S11。选择“返回继续编辑”，不立即保存。

### 3.2 Workflow 和 VLM 节点

1. 在场景列表点“新建场景”，选择“Workflow：条件 / 模型推理判断图”。在业务示例中载入“儿童 / 宠物 OR 判断”。
2. 点“适应画布”，得到 S05。点公共前置节点，看属性区上部得到 S06；滚动属性区到下部得到 S06b。
3. 点“后排儿童结构化判断”，拍属性上部 S06c 和下部 S06d。位置和年龄是同一个节点里的同一对象约束。
4. 点“后排宠物描述判断”，得到 S07a；滚动到属性下部得到 S07b。
5. 点“OR 汇合后复核任务有效”，得到 S08。回到页面“执行动作设置”，得到 S10。
6. 另外载入“闪念：视觉目标 + 固定通知”这一 Workflow 示例，查看单个视觉节点，得到 S07c。

图 S06 至 S08 使用原型已有的响应式布局：浏览器宽度设为 1180 像素后，属性区移动到画布下方，成为可读的宽面板。没有改页面 CSS 或伪造字段。

### 3.3 试跑、列表和历史

1. 载入简单闪念示例，点“本地试跑”。填“后排乘客闭着眼，但画面被遮挡，无法确定是否正在睡觉”，手动选择 UNKNOWN 和频控允许，计算后得到 S12a。
2. 改输入为“已有舱内视觉描述：后排乘客闭着眼，靠在座椅上睡觉”，手动选择 PASS 和频控拦截，得到 S12b。
3. 改频控为允许，计算后依次点“模拟 Action 发出成功”“模拟下游已接收”“模拟卡片真正展示”，得到 S12c。
4. 关闭试跑弹窗。保存简单闪念场景，再新建并保存儿童 / 宠物 Workflow 场景。回到列表，渠道选全部，展开高级筛选，得到 S01a；水平右滚表格，得到 S01b。
5. 左侧进入“触发记录”，选赛力斯与 DEMO-VEHICLE，刷新，点最新“查看简单判断”，得到 S13a 与 S13b。展开“查看当次操作时间线”，得到 S13c。

## 4. 原型缺口，不能在正式 PRD 中照图承诺

| 原型展示 | 实際边界 | 正式 PRD 需要怎样说明 |
| --- | --- | --- |
| 带卡动作中的 buttons 可手工编辑 | 演示 JSON 结构，不是正式自由配置按钮 | 当前正式需求固定确认 / 取消并由系统补齐，后续原型应改为只读展示 |
| 场景来源保留两种来源，当前手工页面只读 | 后台手工配置由系统标记，不代表操作员能冒充动态注册来源 | 保持来源只读；其他接入链路创建的场景按实际来源展示 |
| VLM 来源可选择 | 示例字典与技术方案字段，不证明该渠道的预设入口已接通 | 分别列清结构化字段、已有描述、待接入 Caption，保存与可发布能力核验分开 |
| 页面启动依赖清单 | 依赖推导展示，不是已注册真实唤醒订阅 | Workflow 多分支如何汇总启动输入、订阅来源和新鲜度策略需要研发收口 |
| 儿童节点 Position 与 AgeRange | 原型显示同一节点内条件，不证明后端已完成同一对象关联校验 | 保存和实际判断必须保证同一乘客对象，不做跨对象拼接 |
| 默认 0 分 30 秒 | 现有页面默认，不是会议确认的闪念产品策略 | 最终频控值、计数时点、重试和仲裁应单独确认 |
| 未接入 Caption 仍能本地保存 | 本机演示容许草稿，不等于正式可发布 | 未接入能力可保存草稿，但发布校验必须阻断或明确范围 |
| 本地列表“启用” | 只改本地演示标记 | 区分保存、发布、生效、任务中心用户开关；不要写成本次实现了真实开关持久化 |
| 本地人工试跑 | 不运行模型、不测试异步等待 / 并发，不发真实下游消息 | 正式验收必须拿实际输入、真实节点结果与下游接收和展示证据 |
| 闪念已展示 | 只是人工按钮推进的演示结果 | 当前客户端直接覆盖与后续排队规划仍需产品确认，不宣称队列已完成 |

## 5. 自动复现和检查

运行 `node capture.mjs` 即可使用当前机器已安装的 Playwright 和 Chrome，在独立 headless 上下文重新截图。生成目录只包含本任务新资产；脚本不改旧 HTML，不连接真实配置平台，不触达车辆。源码中的 `source` 是本机已交付原型路径。

检查数据保存到 `截图检查结果.json`，记录每张截图的选择区域、逻辑宽高、演示场景、解释重点与浏览器错误。截图清晰度和业务能力要分开验收：截到控件只代表原型真实有这个控件，不代表后端已经支持。
