# 一、需求概述

## 需求背景：

当前主流手车互联体验痛点\&amp;我们优势：

1. 【P0】体验不丝滑（操作路径长/繁琐）**→ 优势：预判需求缩短路径\&amp;支持模糊控制**

    - 利用豆包 C 端用户偏好数据，记住 “降温” 习惯，无需反复选参数

    - 支持模糊车控能力。如说 “凉快些” 自动调 25℃，不用选具体温度

2. 【P1】服务被动（需用户主动触发）**→ 优势：主动推送服务**

    - 利用用户行为数据，做精准服务推送/预约。如根据行程推 “提前开空调”，不用用户手动操作

3. 【P2】车端服务无法在座舱外延伸 **→ 优势：豆包跨设备同步**

    - 车端指令同步至多端。如车上聊的文章，可生成博客后在手机端/耳机续听

## 目标概述：

“极致可靠的连接 \+ 主动智能”

- **极致可靠：**我们要把基础体验做到最好，实现稳定的“无感”连接。

- **数据智能：**依托豆包强大的数据和AI能力，我们的产品将从“被动控制”进化为“主动式智能陪伴”。我们不仅提供功能，更提供闭环的智能服务——在用户需要之前，就预判并满足其需求并主动提供服务。

## 场景举例

#### **丝滑车控（P0**）

背景：周五傍晚6点，夏季炎热的下班高峰期。王先生即将结束了一周的工作后回家

体验流程：

- 用户表达：**“又热又烦，出发前车给我弄好”**

- 豆包回复：**“没问题，安排好啦，我在车上等你～”**

智能预约控车：基于时间（周五傍晚）、地理位置（公司停车场）、车外高达35℃的气温以及车内密闭的闷热环境，系统AI预判出王先生的核心需求是“降温、回家、放松”。

\- 空调：自动开启，并设置为王先生常用的24℃，风速3档。

\- 导航：目的地已设为“家”，并根据实时路况规划出一条最优路线。

\- 音乐：准备播放王先生最常在下班路上听的“舒缓驾驶”歌单。

上车后AI主动问候：**“晚上好！车内环境已经准备好，希望你可以觉得凉爽舒服呢～ 导航目的地还是回家对吧，今天虹梅路拥堵，给你选了高架有限的路，希望路上也顺顺利利！”**





#### 主动服务**（P2**）

背景：李女士的智能汽车当前剩余续航为100公里。她已经在手机日历中设置了明天上午9点要去邻市的“科创中心”参加一个重要会议。

体验流程：

1. 后台静默分析：周日晚上8点，李女士在家休息。车载系统的后台服务在例行数据同步时，发现了以下信息：

    - 车况：剩余续航 = 100公里。

    - 日程：明天上午9点，会议地点“科创中心”。

    - 地理位置：系统通过地图服务计算出，从李女士家到“科创中心”单程距离为80公里。

2. 智能逻辑触发：系统AI触发了预设的“行程续航预警”逻辑：

    - `判断条件1`：往返距离（80km \* 2 = 160km）远大于当前续航（100km）。

    - `判断条件2`：出发时间（明天上午）临近，当前是最佳的准备时间（今晚）。

    - `结论`：存在显著的续航风险，需要立即主动提醒用户。

3. 主动服务推送：李女士的手机上收到一条来自汽车App的推送通知，标题为“出行助手提醒”。点开后内容为：

“**您好，李女士。检测到您明天上午要去‘科创中心’参会，当前车辆续航可能不足以支持往返。建议您今晚或明早出发前及时充电。需要我为您查找回家途中或公司附近方便的充电站吗**？”

4. 提供解决方案：通知下方直接提供了三个可点击的按钮：“查找沿途充电站”、“查找家附近充电站”、“忽略”。

5. 无缝导航：李女士点击了“查找家附近充电站”，App立即在地图上展示了周边几个评分高且显示有空闲桩位的充电站。她选择了一个最近的，点击“发送到车机”。当她稍后进入车库准备去充电时，车机屏幕已自动设定好了前往该充电站的导航路线，实现了手机与车机的无缝衔接。



#### **多端互通\_基本场景（TBD）**

背景：张先生是一位播客爱好者，他习惯在通勤路上收听科技类播客。他的手机、智能汽车和蓝牙耳机都登录了同一个“豆包”账户。

体验流程：

1. 步行 \-\&gt; 驾车（手机 \-\&gt; 汽车）：

    - 张先生在下楼走向停车场的路上，正用手机和蓝牙耳机收听一档名为《科技早知道》的播客，进度在15分30秒。

    - 当他进入汽车并启动车辆后，车载蓝牙自动连接上他的手机。

    - 车机系统通过连接感知到手机，并立即通过“豆包”云服务查询到手机App的当前状态——正在播放《科技早知道》，进度15分30秒。

    - 中控屏上立即浮现一个提示卡片：**“检测到您正在收听《科技早知道》，是否在车上继续播放？”**

    - 张先生点击“是”，车机的音响立刻从15分30秒处开始播放该播客，同时，手机上的播放自动暂停，耳机中断开音频流。

2. 驾车 \-\&gt; 步行（汽车 \-\&gt; 手机）：

    - 到达公司停车场后，张先生停好车并熄火。此时，车机上播客的进度已经到了35分10秒。系统自动将这个最新的播放进度同步到“豆包”云端。

    - 张先生拔下安全带，推开车门下车。

    - 当他带上蓝牙耳机并走出几步后，耳机会自动重新连接到手机。手机App在检测到耳机连接后，立刻从云端获取最新的播放记录。

    - 手机屏幕上出现一条锁屏通知：**“继续收听《科技早知道》？**”

    - 张先生轻点通知，或直接按了一下耳机上的播放键，播客便从35分10秒处无缝地在他耳边继续响起，他可以一边听着播客，一边从容地走进办公楼，整个收听体验未曾有过一秒的断裂。
