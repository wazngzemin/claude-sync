# AI 汽车与豆包共仓场景下的 Bits Pipeline 差异化配置方案

## 背景

当前，AI汽车（AICar） 与 豆包 共用同一个代码仓库进行研发协作，以便在代码复用、版本管理和统一维护上保持一致性。AICar 与豆包虽然共仓，但在实际研发流程、触发逻辑、执行内容以及交付目标上存在差异，如果继续沿用统一的 Bits Pipeline 流程，可能会带来以下问题：

- **流水线触发边界不清晰**：不同业务的 MR / 分支触发到相同流程，容易出现误触发或漏触发；

- **执行流程相互耦合：**AICar 的流程改动可能影响豆包现有流水线稳定性，反之亦然；

- **无法满足差异化诉求**：AICar 与豆包在校验、构建、发布等环节可能需要不同的处理策略，统一流程难以兼顾。

因此，需要在保持 AICar 与豆包共仓模式不变的前提下，对 Bits 上的 Pipeline 流程进行合理区分，建立一套能够兼容共仓开发、同时支持不同业务独立触发与执行的方案。

## 问题一：MR Review 人差异

Bits可以根据项目配置的config\.yml文件，通过分支来拉不同的reviewers。

```YAML
code_review:
  mode: strict
  pick_strategy: pick_first
  reviewers_required_amount: 1
  maintainers:
    - jiangfeng.jiang
    - guojinlong.123
    - wangshuai.ai
  independent_target_branches:
    - pattern: vehicle/*
      reviewers:
        - jiangfeng.jiang
        - guojinlong.123
        - lixin.milo
        - liangyu.03
        - wangshuai.ai
      required_approvals: 2
```

## 问题二：MR Pipeline 流水线差异化配置

https://bits\.bytedance\.net/devops/5140685058/code/detail/8126229?tab=changes\&amp;devops\_space\_type=client\&amp;devops\_space\_old\_id=2020094588\&amp;cr\_tab=eyJpIjo2MDY1ODYsIm4iOiJmbG93L2Zsb3dfYW5kcm9pZCJ9

经过和豆包主端@王立新 的沟通、支持，目前采用的方案如下：

1. bits流水线编排（流程不能动），采用的方案为：通过给豆包的job增加过滤条件（根据target分支）来决定是否参与 bits pipeline流程。

    1. 废弃方案：新建bits空间（座舱有自己的appid）用来隔离不生效（同一个仓库只能对应一个流水线编排）

    2. 废弃方案：座舱分支创建独特的bits 流水线yaml文件，不生效。（bits 在远端 、 本地同时存在流水线编排的情况下，会优先采用远端配置。豆包主端在远端已经配置过pipeline 流程，会覆盖掉本地配置）。
