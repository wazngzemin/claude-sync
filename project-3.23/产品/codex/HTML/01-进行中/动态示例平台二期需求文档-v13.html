文档口径#

本文用四种标签区分结论，研发、设计和测试不能把“待确认”直接实现为正式规则。

标签 含义
已确认 评审会议形成一致意见，或后续补充已明确结论
后续新增 评审后由新问题或新业务范围带入，需求真实存在
建议方案 为了让评审可继续而给出的产品方案，尚需拍板
待确认 问题存在，但规则、数据或依赖没有形成唯一结论

一期能力保持不变。本文只描述二期改造与相关待确认项。

1. Summary｜需求摘要#

动态示例正在从少数人维护变成算法、产品等多人共同维护。现有平台缺少录入查重、批量维护和正式审批；同时，动态示例开始服务不同渠道、环境以及赛力斯舱内/舱外两套数据，存在重复内容和跨范围误用风险。

二期要完成两类工作：

  1. 管理质量：新增时主动查重，提交时二次查重，支持批量导入、导出、审批和结果追溯。
  2. 生效隔离：按渠道、环境和赛力斯舱域维护及召回，避免不同数据集互相污染。

2026-09-02 的排查会进一步确认了车系、车型或配置款差异可能导致动态示例与车书 QA 冲突。这个问题必须进入 PRD，但最终按哪一级隔离、如何继承和如何运行时命中仍需专项评审，因此本稿不把车型选择器画成已经确定的功能。

3. Background｜背景与问题#

3.1 现网基线#

本稿已按现网 PROD 页面核对，二期只能在现有页面上增量修改。

区域 现网真实内容
页面入口 AI 汽车管理平台 → Planner 管理 → 动态示例管理
页面标题 动态示例管理
筛选字段 渠道、环境、Query、重置
渠道选项 AIDV主线、上汽DNA、赛力斯
AIDV主线环境 prod
上汽DNA环境 prod
赛力斯环境 ppe_aidv_seres_dev、ppe_aidv_seres_test、prod
列表字段 ID、Query、决策分析、环境、创建人、更新时间、操作
现网操作 新增示例、编辑、删除
新增/编辑弹窗 Query、决策分析、渠道、环境；取消、提交

二期原型保留火山引擎顶栏、浅色左侧导航、现有筛选布局和约 600px 居中弹窗。不得替换为深色侧栏、规则编排台或研发数据模型页。

3.2 为什么现在要做#

  1. 多人新增动态示例时，需要逐条手工搜索，重复或相反内容往往到二次测试才被发现。
  2. 一次批量测试可能产生上百条候选示例，逐条录入成本高。
  3. 新增后直接进入可用列表，缺少审批结果和驳回原因记录。
  4. 上汽与赛力斯需要独立维护；赛力斯进一步要求舱内和舱外分别维护两套动态示例。
  5. 同一车企下不同车型或配置款可能存在能力差异。车书 QA 已有差异化数据，而动态示例尚未具备对应范围。

3.3 典型风险#

风险 直接影响
相似 Query 重复新增 同一用户问题可能召回多条相似或相反决策
只在提交后发现重复 用户已经填写完整内容，返工和沟通成本高
页面加渠道字段但运行时不过滤 管理侧看似隔离，实际仍会串池
舱内与舱外共用同一数据池 舱外感知示例可能进入舱内决策，反之亦然
车型能力不同但示例通用 可能给不具备该能力的车辆回答错误事实
Excel 上传后直接写库 用户来不及确认错误、相似内容和影响范围
审批无个人结果视图 提交人不知道是否通过，也不知道如何修改

3.4 证据边界#

“D6X 某低配车型没有座椅按摩”在会上没有核实，可能只是配置表未说明语音控制能力。该案例只能证明“车型或配置差异可能引发冲突”，不能直接作为车型隔离的验收样例。专项评审必须补充一个已经确认能力差异的正反车型组合。

4. Objective｜目标与衡量#

4.1 产品目标#

目标 验收口径
重复录入前可发现 新增/编辑弹窗提供主动检索；每次正式提交都使用最新 Query 再查一次
相似结果可判断 展示相似示例 ID、Query、决策摘要、渠道、环境及赛力斯舱域
批量维护可闭环 下载模板 → 上传 → 校验 → 查看/下载报告 → 线下修改 → 重传 → 确认
上线前有人审核 新增提交进入待审批；审批白名单可通过或填写原因驳回
导出受控 只有白名单可直接导出当前范围数据，不再增加导出申请审批
已确认范围不串用 AIDV主线、上汽DNA、赛力斯及赛力斯舱内/舱外按目标环境隔离
车型问题不再遗漏 页面、PRD和验收计划持续展示待专项评审状态，不伪装成已实现
操作可追溯 记录提交、审批、导入和导出的操作者、时间及结果

4.2 本期不以这些作为成功#

  • 不承诺库内完全没有相似示例，因为查重是提醒，不是硬拦截。
  • 不以页面出现“渠道”或“舱内/舱外”字样代表隔离完成，必须验证运行时召回。
  • 不以普通 Query 回归通过代表跨渠道或跨舱域隔离通过。
  • 不以放置一个“车型”下拉框代表车型问题解决。车型主数据、请求信号和唯一命中规则缺一不可。

5. Market Segments｜内部用户与任务#

用户 主要任务 需要解决的问题
示例提交人 新增、编辑并查看自己的审批结果 在录入过程中发现相似内容，避免重复劳动
审核人 查看待审内容并通过或驳回 看清内容和生效数据集，避免错误上线
批量管理员 批量导入、导出、下载校验报告 写库前集中定位错误和重复项
测试人员 按渠道、环境、舱域验证 明确一条示例应该在哪个数据集命中
运行时检索服务 根据当前请求选择候选示例 不跨渠道、环境或舱域召回
车型专项参与人 确认车辆差异的表达和命中规则 在维护成本和精确隔离之间形成唯一方案

6. Value Propositions｜产品价值#

  1. 提交人少返工：输入 Query 后即可查找相似内容，优先复用或编辑旧示例。
  2. 审核人有依据：审批中同时看到内容、渠道、环境和舱域，不再只看一句 Query。
  3. 批量管理员可控：上传阶段只校验，阻断项修好后才允许确认。
  4. 测试边界清楚：隔离验收有目标池和对照池，不能用普通成功案例代替。
  5. 产品结论可信：已确认能力可以直接开发，未拍板车型方案只作为待确认项，不误导研发。

7.4 新增/编辑动态示例#

7.4.1 字段顺序#

顺序 字段/区域 必填 说明
1 Query 是 保留现网 textarea；下方新增主动查重
2 相似示例检索区 否 手动触发，展示状态和结果
3 决策分析 是 保留现网 textarea
4 渠道 是 沿用现网单选

7.4.2 新增时主动查重#

触发与检索规则：

  1. Query 下固定提供“检索相似示例”。
  2. Query 为空时不可检索，提示“请先填写 Query”。
  3. 用户点击后发起，不在每输入一个字符时请求。
  4. 管理侧查重只使用 Query 做语义检索。
  5. 检索用户有权限查看的全部动态示例，不先按渠道、环境、舱域或待定车型范围过滤。
  6. 编辑已有示例时排除当前 ID，避免把自身作为重复项。
  7. 结果不展示相似度百分比，也不提供阈值配置。
  8. 返回数量由服务端控制；最终 Top 3 还是 Top 5 待评审。

每条相似结果最少展示：

  • 示例 ID；
  • Query；
  • 决策分析摘要；
  • 渠道；
  • 环境；
  • 舱内/舱外，仅赛力斯结果展示；
  • 查看示例。

主动查重状态：

状态 页面表现 下一步
未检索 不展示结果区 可以点击检索
检索中 显示加载状态 防止重复请求
有相似结果 展示结果和“仅提醒，不阻断” 用户判断复用、编辑旧示例或继续新增
无相似结果 提示“未发现相似示例” 继续填写
Query 已修改 原结果标记失效 必须重新检索
检索失败 展示失败和重试 不能当作“无结果”

请求进行中若 Query 再次修改，旧请求结果不得覆盖新状态。

7.4.3 提交时二次查重#

完整流程：

填写 Query 和决策分析 → 可主动查重 → 选择渠道和环境 → 检查并提交 → 必填校验 → 使用最新 Query 二次查重 → 返回修改或仍要提交 → 进入待审批

  1. 二次查重必须使用点击提交时的最新 Query，不能复用页面上的旧结果。
  2. 无相似结果：生成待审批记录。
  3. 有相似结果：再次展示相似列表，只提供“返回修改”和“仍要提交”。
  4. 用户选择“返回修改”：回到原弹窗，已填内容不丢失。
  5. 用户选择“仍要提交”：生成待审批记录，不覆盖、不删除任何旧示例。
  6. 二次查重失败：保留表单并提供重试，不生成审批记录。

7.5 渠道、环境与赛力斯舱内/舱外#

7.5.1 已确认的数据层级#

当前本期已确认层级为：

渠道 → 条件舱域 → 环境 → 动态示例

  • AIDV主线和上汽DNA当前不展示舱域。
  • 赛力斯显示“舱内动态示例 / 舱外动态示例”两个页签。
  • 舱内和舱外是两套独立数据，不是一条示例上的多选标签。
  • 进入新增/编辑时，弹窗只读展示当前数据集，例如“赛力斯 · 舱内”。用户不在单条记录里再次自由选择舱域。
  • 批量导入、导出和审批都必须带出当前数据集。

7.5.2 管理与运行时必须一致#

链路 规则 原因
管理侧列表 按当前渠道、舱域和环境展示 避免编辑错数据集
新增/编辑查重 全库查重，不按范围预过滤 发现其他范围内可复用的内容
运行时召回 先按渠道、环境和条件舱域过滤，再做语义召回 防止跨池污染

运行时关键边界：

  • 测试环境示例只在对应测试环境生效。
  • prod 的含义只能在当前渠道/数据集内解释，不得理解为跨渠道全局生效。
  • 目标池为空时不得自动跨渠道或跨舱域兜底；是否允许其他兜底策略需另行评审。
  • 页面字段和运行时过滤必须一起发布，不能只完成页面。

7.6 车系、车型、配置款范围#

7.6.1 已确认的是问题，不是最终方案#

已确认：同一车企内部可能存在车系、车型或配置款能力差异，动态示例缺少车辆范围时可能与车书 QA 的车型答案冲突。

尚未确认：

  • 最终按车系、车型还是配置款维护；
  • 车辆主数据从哪里来，是否有稳定 ID；
  • 请求链路能稳定携带到哪一级车辆标识；
  • 通用示例与车型专属示例同时存在时如何唯一命中；
  • 通用修改如何同步到各车型；
  • 与赛力斯舱内/舱外如何组合；
  • 是否允许一条内容跨多个渠道复用。

因此本期页面只展示待评审提示和决策清单，不提供虚构的车系、车型或配置款下拉框，也不提供 BASE、OVERRIDE、EXCLUDE 等研发关系模型。

7.6.2 专项评审必须产出#

决策 必须得到的唯一结论 影响页面
隔离粒度 车系、车型或配置款中的正式最细粒度 筛选、列表、新增/编辑、模板
主数据 展示名称、稳定 ID、父子关系和负责人 选项加载与合法性校验
请求信号 运行时一定能拿到的车辆标识 是否具备真正隔离条件
优先级 通用与专属内容如何保证一辆车只命中一条 运行时召回与冲突校验
继承策略 未来新车型是否自动继承，通用修改如何同步 维护成本和风险提示
舱域组合 赛力斯舱内/舱外与车辆范围的组合方式 数据模型和批量模板

专项结论形成后，预留字段位置为：渠道之后、环境之前。车型能力必须由“管理配置 + 存储 + 请求信号 + 运行时过滤 + 日志”一起交付。

7.7.1 权限与视图#

  • 普通用户：只看自己提交的记录及结果。
  • 审批白名单：看全量待审批及历史记录。
  • 首批审批白名单：王泽民、赵晓朝。
  • 首版只做服务端白名单，不建设完整角色体系。
  • 本期不做飞书通知，提交人从审批中心查看结果。

7.7.2 字段与动作#

字段 说明
Query、决策分析 查看完整提交内容
渠道、环境、舱域 判断内容应该在哪个数据集生效
提交人、提交时间 追溯来源
状态 待审批、已通过、已驳回
驳回原因 审核人填写，提交人可见
操作 查看、通过、驳回

新增提交的状态变化：

编辑中 → 待审批 → 已通过并上线 / 已驳回 → 修改后重新提交

编辑已上线示例是否必须重新审批，会议没有形成最终结论。开发开始前必须拍板旧版本是否继续生效、审批通过后如何切换，原型不把某一种方案写成既定事实。

7.8.2 当前可确认模板字段#

字段 规则
ID 修改或待确认删除语义时使用；新增可为空
Query 新增/修改必填
决策分析 新增/修改必填

7.8.3 上传和校验#

上传阶段只解析和校验，不写入正式库。结果分三类：

结果 示例 是否可确认
阻断 缺 Query、缺决策分析、非法渠道/环境/舱域 存在任一阻断时不可确认
提醒 Query 与已有示例相似 不阻断，备注展示相似 ID 和范围
通过 字段完整且无阻断 可以进入确认

校验报告必须包含：

  • Excel 行号；
  • Query；
  • 校验结果；
  • 原因/备注；
  • 相似示例 ID、Query、渠道、环境和舱域；
  • 总行数、通过数、提醒数、阻断数；
  • 只看问题；
  • 下载校验报告；
  • 重新上传。

页面不支持直接修改 Excel。用户下载报告，在线下修改源文件后重新上传。确认前若源数据或目标记录发生变化，服务端应要求重新校验。

以下三点仍待评审，不能由研发自行默认：

  1. 删除用“ID 非空且 Query 为空”表示，还是增加显式操作类型；
  2. 校验通过后直接生效，还是统一进入审批；
  3. 批量写入部分失败时整批回滚，还是允许部分成功。

7.12 异常与边界#

场景 页面处理 是否继续
Query 为空 提示先填写 Query 不能查重或提交

查重中修改 Query 丢弃旧请求结果 重新检索
修改 Query 后看旧结果 标记结果失效 重新检索
编辑时命中自身 服务端排除当前 ID 不展示自身
提交二次查重发现相似 显示相似列表 可返回修改或仍要提交
提交二次查重失败 保留表单并重试 不生成审批

目标运行池为空 不跨渠道/舱域兜底 返回无候选或按后续兜底结论处理
批量模板缺列 文件级阻断 重新上传
批量某行缺字段 行级阻断 修复后重传
批量 Query 相似 黄色提醒 不作为阻断

7.13 明确不做#

  • 不做批量校验页内直接编辑。
  • 不做导出申请和导出审批。

  • 不做审批飞书通知。

8. Release｜拆分、验收与待拍板#

8.1 建议拆分#

会议没有锁定 P0/P1。以下只按依赖关系建议拆分。

第一批：新增质量与已确认隔离#

  • 在现网新增/编辑弹窗加入主动查重和提交二次查重；
  • 增加审批最小链路；
  • 补充渠道列和状态列；
  • 完成渠道 × 环境的管理和运行时过滤；
  • 拆分赛力斯舱内/舱外两套数据并完成隔离验收；
  • 关键操作留痕。

第二批：规模化维护#

  • 批量导入、校验报告和报告下载；
  • 批量导出；
  • 审批历史和批次追溯；
  • 处理批量并发与报告过期。

车型专项评审后#

  • 接入正式车辆主数据；
  • 增加已拍板的车辆范围字段；
  • 完成存量范围迁移；
  • 完成运行时唯一命中和跨车型验收。

8.2 发布依赖#

  • 查重服务支持 Query 语义检索和编辑自排除。
  • 请求链路能稳定携带渠道、环境和条件舱域。
  • 管理字段、存储字段和运行时过滤同时发布。
  • 审批、导入和导出白名单完成服务端配置。
  • 存量数据完成渠道、环境及赛力斯舱域确认。
  • 测试准备跨渠道、跨环境、跨舱域冲突用例。
  • 车型能力等待主数据、请求信号和唯一命中规则专项结论。
