2026-07-23 泽民给了《离线指令FC协议.xlsx》(582行,New版51函数) +《离线LLM指令解析PRD》，产物 `planner 架构/车控SFT-FC模型详解_v1.html`。要点：

- **SFT FC 模型 = 端侧小LLM，按FC协议监督微调，把语音指令离线翻译成函数调用JSON**；三层漏斗第1层（缓存50ms→FC 200ms→云端Director）。指标：≤200ms、准确率≥95%、输出「其他」=不属离线范围交回云端。
- **仲裁条文（Director PRD）**：命中白名单→端侧直接执行；未命中→云端优先；云端超时→端上结果兜底。
- **FC协议51函数**：车控25(白名单20是，危险警示灯+雨刮4个否)/导航13全否/系统6(5是)/媒体4全否/电话2(拨打是)/应用1。白名单"否"的道理：导航媒体依赖在线数据；危险/紧急=安全敏感；雨刮=v0.3对齐赛力斯可控范围。**模型共享协议、白名单按车型定制**。
- **槽位设计**：value带+/-前缀分相对绝对量（"调高15度"=+15 vs "调高到15度"=15）；unit独立槽；position有"音区"值=说话人位置。
- **缓存层30条**（导航回家/上一首/空调调到23度…）三原则：单轮/上下文无关/结果唯一——缓存是绕过FC+白名单的第三通道。
- **拒识模块**：单轮/多轮；过拒vs漏拒是产品阈值决策。
- **协议三大坑（可提owner）**：①车窗action标注自相矛盾（"开50%"→关闭 vs "开到一半"→打开；"下降20%"→关闭+20%）SFT脏数据硬伤 ②FC mode枚举有"强力制冷"但荣威家越07边界说没有=车型错配 ③多轮对话样本混进单轮协议，FC吃不吃上下文没表态。
- 对泽民：FC召回边界=体验快慢边界；触发器叫醒的是Director不是FC（纯车控条件动作走FC是时延优化空间）；FC与Director分开考核（95% vs 90% ACC）。
