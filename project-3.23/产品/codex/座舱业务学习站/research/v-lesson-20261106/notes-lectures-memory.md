## A. 讲法指南（基于【DT宣讲】【记忆宣讲】，两场均为郝晓伟主讲）

### A1. 一个模块的固定讲述顺序

两场宣讲结构高度一致，可以归纳成 9 步。V 章每个小节建议按这个顺序写。

| 步骤 | 做什么 | 原话为证（≤30 字） |
|---|---|---|
| 1. 先澄清名字 | 开场先统一叫法，说清"几个名字指同一个东西" | "其实指的都是同一个模块。"（DT宣讲 00:01:15） |
| 2. 为什么要做 | 先列旧方案的痛点，每个痛点配一个用户能感知的场景（找电影费劲、多人找餐厅） | "用户的需求被处理成了这种一锤子的买卖"（DT宣讲 00:01:15） |
| 3. 在链路里的位置 | 用链路图讲上游谁送进来、下游交给谁；前一场已讲过的环节一句带过 | "它在整体的链路里面的一个算是生态位吧。"（DT宣讲 00:13:15） |
| 4. 职责 → 输入 → 输出 | 输入按类型逐个列，每类配一个触发场景；输出配一个具体工具调用 | "模块输入的话，基本上分，这几类"（DT宣讲 00:11:16） |
| 5. 规则逐条 + 具体 query | 每条规则都配"用户说了什么 + 当时状态 + 应该/不应该怎么做" | "用户说车里好热，那这时候空调已经开了"（DT宣讲 00:27:38） |
| 6. 原方案 → 问题 → 改造 | 讲迭代时先讲旧方案，再讲旧方案的问题，最后讲改了哪里 | "可以简单看一下原方案"（记忆宣讲 00:06:33） |
| 7. 边界与异常 | 正例 + 反例（"清"与"不清"两组），并说明做不到的场景和为什么可接受 | "下面是一些不清的场景举例"（记忆宣讲 00:46:28） |
| 8. 标注是否已实现 | 讲到未上线内容就明说"没做/没接入/还在评估"，并说后面谁负责 | "人人对话这一块其实是目前没有接入的一块。"（DT宣讲 00:28:59） |
| 9. 评测/性能收尾 + 答疑 | 最后讲性能目标与评测维度，再开放提问；答疑时沿真实链路一步步讲 | "下面是一些关于 director 的评测方面的一些事情"（DT宣讲 00:37:40） |

记忆宣讲的具体顺序（可直接用作 V 章"记忆进入 DT"一节的模板）：
数据底座（事件日志）→ 记忆分类定义（瞬时/短期/长期情景/长期语义）→ 两类记忆对比 → 最近的迭代（原方案→问题→改造）→ 补空白的模块（对话摘要）→ 用户画像 → 标签与召回 → 交互（开关、记忆空间）→ 管理接口 → 隐私策略 → 后续规划 → 答疑。

### A2. 常用句式与过渡方式

| 句式 | 用途 | 原话为证 |
|---|---|---|
| "简单区分一下 X 跟 Y 吧" | 两个易混概念并排对比 | "这边就简单区分一下情景记忆跟语义记忆吧"（记忆宣讲 00:04:22） |
| "就比如说……" | 每个抽象定义后立刻跟例子，几乎每段都用 | "就比如说用户他很喜欢听周杰伦、林俊杰。"（记忆宣讲 00:04:22） |
| "中间那一段……得有一个角色来承接" | 用"时间/信息空白"引出新模块 | "所以就得有一个角色来承接起来。"（记忆宣讲 00:09:12） |
| "这也是考虑到……得不偿失" | 解释取舍：为什么不做、为什么例外 | "让基础体验里面的多轮推理能力都直接丧失了"（记忆宣讲 00:21:30） |
| "OK，这是 X……然后接下来……" | 小节过渡：先收束再起头 | "OK， 这是一个情景记忆生成这一块的一个……迭代"（记忆宣讲 00:08:21） |
| "第一块……第二块……" | 讲"为什么"时分块编号 | "这是第一块，就我们期望是能够解决传统语音"（DT宣讲 00:05:03） |
| "总之就是……" | 一段讲完后用一句话下结论 | "总之就是我们会把豆包的他内心的一些想法"（记忆宣讲 00:29:08） |
| "大概就是这样" | 一段结束时收口 | "大概就是这样，这些是基础记忆的一些定义内容。"（记忆宣讲 00:05:09） |
| "下游是不知道……所以要改写成……" | 从下游视角解释上游为什么要这样做 | "下游的工具其实是不知道这个人他坐在什么位置的"（DT宣讲 00:28:18） |

### A3. 怎样处理"还没上线"的内容

1. 明说没上线，并给出原因："因为一些人力以及前置依赖的原因。还没有实现"（记忆宣讲 00:10:23）。
2. "已实现但未使用"单独算一档："是已实现，但是当前实际没有使用。"（记忆宣讲 00:15:52）
3. 在文档里当场划掉或标注："这一块其实现在我先把它划掉吧"（记忆宣讲 00:24:11）。
4. 未定的内容不展开，等做完再同步："后面可能也会存在一些变化。"（记忆宣讲 00:11:58）
5. 评估中的内容要加一句"不是已上线"："总之，这个不是一个已经上线的东西。"（DT宣讲 00:49:27）
6. 说清负责人："这一部分最近是仁杰在做这一块的产品的规划"（记忆宣讲 00:11:58）。
7. 对外口径和内部口径分开："对外的记忆的 PRD 里面。我也只放了上面这一部分。"（记忆宣讲 00:10:23）

### A4. 哪些讲重点，哪些一笔带过

重点展开（花时间、给多个例子）：
- 为什么要做（痛点）：DT 宣讲用了约 8 分钟（00:01–00:09）。
- 会改变推理结果的规则：结合情境、端状态、记忆、人名、方位的拆解规则，每条都给 query。
- 隐私与身份边界：白名单/非白名单、交集记忆、新的人上车清摘要，都给了"清/不清"正反例（记忆宣讲 00:41–00:48）。
- 与客户的分工边界：哪些只提供接口、哪些页面由客户开发（记忆宣讲 00:29–00:41）。

一笔带过（明说"不赘述/快速过/感兴趣自己看"）：
- 其他宣讲讲过的环节："应该左晨也已经介绍过，我就不赘述了。"（DT宣讲 00:14:14）
- 枚举清单（表情列表、标签全表、评测指标说明）："这一块我们的就快速地去过吧"（DT宣讲 00:24:00）。
- 技术方案细节与打分公式："大家有兴趣的话可以了解。"（记忆宣讲 00:19:56）
- 未实现的长期方案和 TBD 能力："因为本身还是一个 TBD 的状态，我们就跳过了。"（DT宣讲 00:24:24）

### A5. 写 V 章时必须遵守的 10 条讲法规则

1. 每节开头先统一名字：Planner = Director = DT = 对话推理引擎；"历史对话/历史输入""对话摘要/摘要记忆"这类改名要先交代新旧叫法。
2. 先讲"没有这个模块用户会遇到什么问题"，再讲模块是什么；痛点必须是车上能感知的场景。
3. 每个模块固定写：上游是谁 → 输入是什么（字段 + 示例 JSON）→ 输出给谁 → 输出长什么样。
4. 每条规则都配一条真实 query，写清当时的车况/记忆/在场人，以及应该或不应该拆出的动作。
5. 讲迭代按"原方案 → 原方案的问题 → 改了哪里"三段写，不要只写现状。
6. 边界给正反两组例子（如"新的人上车：清/不清"），并说明做不到的场景和为什么可以接受。
7. 每条事实都标状态（已上线 / 已实现但未使用 / 开发中 / 讨论中 / 未实现），PRD 里的设想不能写成现状。
8. 数字带单位和来源（20 分钟/20 条、第 3 轮起、最多 28 轮、500 token、P50 500ms）；口径冲突时并列写出处。
9. 写清与客户/下游的分工（如"仅接口能力，页面由客户开发"），避免读者以为全是主线做的。
10. 其他章节讲过的环节一句带过并写"见 X 章"；枚举清单放表格或折叠，不在正文展开。

### A6. 必须避免的废话类型

1. 空泛价值句："提升用户体验""更智能""更懂你"，后面没有具体场景。
2. 不解释的缩写和代号：VAD、FC、SP、KV、S0/A1 等首次出现不解释。
3. 把讨论中的设想写成已上线，例如人人对话进入推理、情境感知、用户形象画报、豆包日记。
4. 只列字段名不给示例值，或只给示例不说字段从哪来。
5. 用通用类比开头（"就像人的大脑"），而不是从车上的真实链路讲起。记忆 PRD 里有人类记忆的科学分类，宣讲完全没讲，说明这部分不是重点。
6. 堆公式：记忆打分的 α/β/γ/δ/ε 公式只是未来迭代，不进正文。
7. 首轮话术式的过度承诺（"已经帮你做好了"），DT 宣讲明确反对。
8. 同一个意思多处重复，首段和末段互相复述。
9. 只讲做了什么，不讲为什么这样取舍（例如为什么关闭记忆开关也不影响 5 轮历史对话）。
10. 把逐字稿里的口误当事实（见 B8 对"非白名单最小集"的标注）。
