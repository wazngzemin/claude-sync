# 豆包汽车语音用户请求到真实结果：单一连通业务架构图布局草案

> 本文件只定义一张连续画板的布局、节点、边和泳道，供后续生成原生可编辑 SVG；不直接写入飞书。

## 1. 画布与阅读规则

- 逻辑画布：`2200 × 13000`，内容决定边界，不裁成 16:9。
- 阅读顺序：从上到下分 9 个业务阶段；同一阶段从左到右跨泳道阅读。
- 主轴：一条 `4px` 深钴蓝实线贯穿 `用户发声 → 语音识别 → 接入分流 → 上下文快照 → Planner/Director → 动作校验 → 工具/任务执行 → tool_feedback → 下一轮判断 → 四路输出 → 用户真实感知`。
- 回流：`3px` 钴蓝回路线，统一从右侧反馈总线返回“本轮输入治理”，不能让反馈悬在工具旁边。
- 条件、异常、待确认：`2px` 深钴蓝虚线；不另开“附录孤岛”，必须用连线挂回对应主轴节点。
- 证据/追踪：最右侧一条纵向追踪总线，从统一请求开始到用户结果结束；每个阶段向它写事件，底部指标从这条总线聚合。
- 颜色严格采用 Cobalt Glaze：画布 `#ECECEC`；卡片 `#F4F2EE`；主色 `#185DB7`；结构/文字 `#0D4FA8`；预生产或待验真用 `#8E9179`。不使用渐变、阴影、透明度。
- 所有最终图中文字不小于 `16px`：标题 34；泳道名 20；阶段名 24；节点标题 18；正文 16；边标签 16。
- 所有卡片仅用矩形/圆角矩形/圆形；连接线只用直线或直角折线；箭头由 `marker-end` 生成。
