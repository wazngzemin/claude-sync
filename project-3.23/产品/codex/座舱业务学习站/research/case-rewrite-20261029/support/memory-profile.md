# 语义记忆画像算法方案

# 背景

## 业务背景

在 AI 汽车场景中，用户画像（User Profile）是实现个性化服务体验的核心基础。当前系统通过**预注入机制**，在会话发起前将用户的结构化记忆画像注入上下文，使 AI 助手能够感知用户的偏好、行为习惯与历史交互特征，从而提供更精准的响应。

针对预注入的用户记忆画像部分，需要细化的槽位，参考：[记忆标签化](https://bytedance.larkoffice.com/wiki/GJbFwqP3oi8dd6kVw8PcJSdHnze)

## 现状分析

**当前 toB 侧画像生成方案**：使用全量长期记忆，通过单一 System Prompt（SP）将上述槽位内容提取为键值对，输出 JSON 供工程侧解析与下发。

该方案在规模化场景下存在以下两个瓶颈：

1. **P1 覆盖式更新**：新记忆写入时直接替换槽位旧值，缺乏合并逻辑，导致历史画像信息永久丢失，画像完整性下降

2. **P2 上下文膨胀**：随长期记忆积累，SP 输入量持续增长，超出模型有效注意力窗口，导致抽取质量下降、推理成本上升

```Markdown
profile_extraction_base_prompt: |
  你是一个专业的用户画像分析与信息提取助手。你的任务是根据提供的用户历史记忆片段，为指定的画像标签（子类）提取、总结并输出结构化的用户信息。

  【核心规则与约束】
  1. **严格 JSON 输出**：你必须严格按照提供的大类-小类-子类结构输出 JSON 格式的结果，不要包含任何其他多余的解释文本。
  2. **过滤不相关内容**：你具备严格的判别能力。如果召回的记忆片段与当前需要填写的标签完全无关，必须予以过滤，不可强行提取、推断或编造。
  3. **主体约束（关键）**：你只负责提取当前主用户（车主或主要交互者）自身的信息和偏好。如果记忆片段中明确指出是其他乘客（如家人、配偶、孩子、朋友等）的偏好或行为（例如：“女儿喜欢粉色氛围灯”），必须予以排除，绝不能总结进当前用户的偏好中。
  4. **输出格式规定 (List)**：为了无损保留用户的多样化偏好和可能的时效性变化，提取的有效信息必须以 `List` 格式存储（例如：`["喜欢吃辣", "最近偏好川菜"]` 或 `["王力宏"]`）。
  5. **语义去重与合并**：识别并合并语义重复的记忆，剔除无用信息。对于存在互补或一定时效性变化的信息，作为多个条目保留在 List 中。
  6. **空值处理**：如果对于某个子类，没有任何相关的有效记忆，请在该子类的值中输出空列表 `[]`。

  【当前处理的大类与子类结构】
  {target_json_structure}

  【该大类特定业务规则与示例】
  {category_specific_rules}

  【相关的用户历史记忆片段】
  {retrieved_memories}

*# 各大类的特定业务规则与示例 (Category Specific Rules)*
profile_specific_rules:
  基础画像: |
    - 业务特性：基础身份和社会属性通常是唯一且客观的事实（如姓名、性别、出生年月）。
    - 冲突处理：如果记忆中存在明显矛盾（如之前说自己30岁，后来又说自己32岁），请以能推断出的最新状态或最确定的表达为准，List 中只保留一项。
  内容偏好: |
    - 业务特性：用户的偏好往往是多样化的（如喜欢多个歌手、多种影视类型）。
    - 冲突处理：不要随意覆盖。如果用户提到喜欢周杰伦，后来又提到喜欢陈奕迅，两者应同时保留在 List 中。
  服务偏好: |
    - 业务特性：餐饮等服务偏好可能具有多样性。
    - 冲突处理：如果用户口味有变化（如“以前无辣不欢，现在为了养生开始吃清淡的”），需在 List 中体现这种变化或保留最新的偏好。
  出行偏好: |
    - 业务特性：涉及具体数值或目的地（如补能焦虑阈值、高频目的地），可能会有多个常用地点。同时涉及时间偏好时，必须严格区分“出行时段”和“出行日”。
    - 冲突处理：对于目的地，可保留多个。对于数值型偏好（如电量低于20%），合并为一个合理范围或取最新值。
    - 时间提取规则：“偏好的出行日”仅提取表示日期或周几的概念（如工作日、周末、周一等）；“偏好的出行时段”仅提取具体的时间点或时间段（如早上8点、晚上19点、午休时间）。若记忆中同时包含两者（如“周末上午10点”），必须拆分填入对应的标签中，严禁合并填入同一个标签。
  用车偏好: |
    - 业务特性：涉及车辆的具体设置（如空调温度、座椅档位），通常只有唯一生效的状态。
    - 冲突处理：如果是具体设置档位（如“空调2档”变成“空调3档”），请以最新记忆中的设置为准，List 中保留一项。
```
