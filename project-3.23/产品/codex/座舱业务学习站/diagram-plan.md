# 业务导航与模块机制图计划

用户明确要求每个模块都有流程和详细解释，因此采用按模块展开，不再请求用户挑少量主题。总入口连接 24 个业务模块，沿语音→采信→输入→上下文→Director→工具/输出的主线，并连接司机 Agent 专项业务、事件→日志→记忆与受控迭代。旧版 291 节点完整图保留为精细参考层，不将配套能力画成每轮必经步骤。

各章节画流程图：读者需要知道谁在什么条件下先做什么、何时交给下一方。常规模块采用 5 阶段总机制；Memory、事件、日志和自进化使用各自详细业务流程。正文逐节点解释、案例和异常补充图内短标签。

新图使用 baoyu-diagram 模板完整样式，680 宽，中文 14/12 px，灰色中性步骤与青色核心过程，规划连接为虚线并明确标注。纵向节点宽 340，标题与正文按字宽计算高度；跨阶段线走左侧通道。每条边保留完整关系文字，不能因视觉简化丢失条件。原 v15 图不改样式、不删节点。

总入口专用于阅读导航：带箭头实线保留主链、工具反馈及事件日志/记忆关联，带箭头虚线表示受控改进方向。无箭头点线是同阶段相关模块的阅读入口，不伪装为每轮固定调用。全部真实业务交接另在原始 291 节点图与各模块细节视窗保留；不为了首页一屏展示把完整业务链裁掉。

每个输出 SVG 将附内容计划、结构元数据及渲染预览。图与文章链接使用 data-page、data-flow、data-step；原节点使用 data-node。几何检查覆盖节点重叠、连线穿越无关节点；保留每条非线性分支的 E 编号与完整条件表。只要任意模块仍为空、来源引用失效、流程分支错误或浏览器行为未验证，目标不能标已完成。

## v07 补充：司机 Agent 与场景贯通

新增 DR 是原始 PRD 明确的独立业务模块，不合并进 auto_drive，也不把 Director 再画成一个串行 Planner。来源区分 3 月澄清、旧版需求、8 月 31 日 v1.5.2 与 G9m 专项 POI/泊车链；“以下忽略”的旧章节不用于定义新版执行顺序。

DR 按业务场景作有界纵向流程：Director 交办→专项判断→下游提槽/导航/视觉→用户确认或补齐→真实车辆/服务结果→回流。POI/泊车细节明确导航成功、泊车属性设置和智驾执行是不同状态。每图不超过 12 节点；决定和回退按单独端口、左侧分支通道连接，不穿无关节点。图外保留完整交接说明和失败条件，不把长段落挤在箭头上。

总导航在“执行工具并回流”附近增加 DR 入口；此线作为专题关联，不声称每次查询都会调用司机 Agent。所有实际条件调用在 DR 专题流程与原始来源逐项说明。生成前自动备份原 SVG 至 diagram-history/<旧版本>/，原详细图和旧 HTML 不改。

四条完整教学走查提供前后连续的 48 步交接：每步都写已知/未知、判断、交接对象、完成证据、失败去向；它们不是伪造的运行日志。章节搜索包含事件 ID 和表格字段，避免有细节但读者找不到。

端云 One Page 增加两张 8 节点流程：R-endcloud-input 解释音频→转写→ASR 回端→正式文字经豆包上行→汽车业务；O-endcloud-speech 保留文字与语音合成并行、按 tts_audio_id 取流、接收与实际播放的区别。三阶段说明放右侧 x=540–640 注释栏，主节点 x=180–520，跨阶段分支放左侧，避免阶段名压住连线。依据原始画板检查的结果重绘，不合并成单条音频管道。

v07 图像审查发现跨节点分支只有 E 编号会增加读者查表负担。v08 在 DR 三图与文字/音频并行图中，将每条跨节点分支的完整条件同步放到发起节点右侧注释栏；E 编号在源/目标端口及底部条件表保留。节点高度同时纳入注释文本高度，避免条件与下一阶段堆叠。v07 及其 SVG 备份保留，不覆盖 HTML。
