# 09 可见即可说｜v14 全景图 SVG 中的 W 模块（节点 12 个）

框标题：W · 可见即可说：从页面注册到真实点击，再回到对话历史
框说明：页面词表与当前界面绑定，命中后执行对应操作，失效词不能继续接管请求。

## 节点（编号与文档画板一致；措辞为 10/26 最新版，含每个节点两段讲解）
### W01｜由页面业务整理当前可以操作的控件（蓝底）
- 要点：读取当前最上层可交互界面提取按钮文字与对应控件只注册实际允许操作的对象
- 讲解①：可见即可说从页面准备开始。车企或所属业务读取当前界面，把真正能够操作的控件及显示文字整理出来，例如设置页的座椅加热按钮。装饰说明文字不能因为看得见就全部变成可点击目标。
- 讲解②：随后这些控件交给注册与匹配能力，用户说出名称时才能找到具体对象。此路径使用业务提供的控件信息，没有要求视觉模型先看截图再猜按钮。最终实际点击也仍由控件所属业务完成。

### W02｜把可说名称与唯一控件标识绑定（蓝底）
- 要点：绑定显示文字、泛化词和控件 ID注册范围对应当前页面或卡片本框架每页上限为 500 个词同名按钮也要保留不同身份
- 讲解①：业务把显示文字、允许的说法和唯一控件 ID 交给框架，形成可说名称与实际对象的对应表。同一页面有两个“播放”按钮时，也必须保留各自身份，后面才有条件消歧。
- 讲解②：本框架采用每页最多 500 个词的上限，统计的是词条而非工具数量。注册成功还需继续检查词表进入识别、页面仍有效和操作能否执行。仅有一份注册记录，不能保证用户已经点到了正确按钮。

### W03｜把当前有效按钮词送入语音识别（蓝底）
- 要点：有效注册词进入识别热词随页面和卡片变化更新范围热词帮助听清而不直接点击
- 讲解①：注册好的按钮名称可以加入在线和离线识别热词，帮助 ASR 听清当前页面中的特殊名称。比如歌曲卡片上有一个生僻曲名，这份词表能提供识别线索，但必须实际进入当前请求才发挥作用。
- 讲解②：识别听对之后还要匹配控件并执行，不能让热词自己产生点击。页面切换时要同步维护有效词范围，避免旧按钮继续干扰新页面；失效处理应与控件注册生命周期一致，而不能只更新画面不更新语音侧对象。

### W04｜最终文字到来后匹配本次有效界面（蓝底）
- 要点：接收 final 及请求与音区信息使用当前页面和卡片上下文过程文字不提前模拟点击序号选择必须对应真实当前列表
- 讲解①：用户说按钮名称时，先经过正常语音识别，最终文字到来后才与本次有效界面注册内容匹配。过程文字仍可能改字，因此不能只听到半个按钮名就提前点击。
- 讲解②：支持动态选项的卡片可以注册当前候选，让“第二个”等表达找到真实对象。它依赖卡片与前文，不能当成无上下文缓存。请求编号、音区和页面关系一同保留，后续才能检查用户说话期间卡片是否已经变化。

### W05｜按约定文字规则找候选控件（金底）
- 要点：进行全文、局部或模糊匹配结果可能零个、一个或多个无匹配回普通请求入口候选仍需核对对象有效性
- 讲解①：匹配服务拿最终文字与注册词比较，按框架配置的全文、局部或模糊规则产生候选控件 ID。模糊匹配也有明确边界，不能扩大为任意语义相似都算同一个按钮。
- 讲解②：没有候选时，用户仍可能在问问题或提出车控需求，应回普通入口继续处理。一个候选还要确认控件有效，多个候选则交注册业务选择或消歧。这里产出的是候选关系，尚未证明任何按钮已经被执行。

### W06｜多个控件命中时交注册业务消歧（金底）
- 要点：保留全部候选控件 ID注册业务结合界面处理选择不默认点击第一个候选目标未明确前不报操作成功
- 讲解①：页面上有两个同名播放按钮时，识别与文字匹配可能都正确，却仍无法知道用户要哪个。框架把全部候选 ID 交还注册业务，由它结合当前界面关系处理选择或必要消歧。
- 讲解②：具体怎样询问或展示选择，应采用当前业务已定义的交互，不能默认随机点击或总选第一个。消歧后得到确定目标，才继续交执行入口。候选列表返回成功只完成了找对象这一步，不能直接告诉用户音乐已播放。

### W07｜把确定目标交回所属业务执行入口（蓝底）
- 要点：交付已确定的控件 ID映射当前页面的实际对象再次核卡片和控件是否有效确定对象之后才开始操作
- 讲解①：匹配或消歧得到确定控件后，服务把 ID 交回当初注册它的业务，由业务映射到实际交互对象。例如音乐卡片的播放按钮，应回到对应音乐业务处理。
- 讲解②：用户说话期间可能已经切页，卡片也可能超时退场，因此交付时必须核当前对象仍有效。这里明确了执行目标，下一步才会模拟点击。不能把注册、匹配或收到 ID 这些中间成功，提前算成用户要求已经完成。

### W08｜由控件所属业务完成实际点击（蓝底）
- 要点：使用页面已有交互能力操作触发真实界面变化或业务请求异常由执行方返回具体原因点击动画不替代业务结果
- 讲解①：业务方收到有效控件 ID 后，使用页面已有的点击能力执行操作。点击音乐卡片播放按钮，应真正触发播放器或后续业务请求，不能只在语音层显示一个已点击标记。
- 讲解②：执行还可能遇到页面过期、权限不足或服务失败，需要由这一层返回真实原因。点击动画能帮助用户知道系统在响应，但音乐有没有播出仍要看业务状态。操作完成到什么程度，继续通过 W09 回传。

### W09｜把实际操作结果和可播内容交回（绿底）
- 要点：返回点击及业务真实状态成功、失败与未完成分开附上适合统一播报的内容多项操作保留各自结果
- 讲解①：页面业务执行后，把实际结果和需要播报的内容交回助手。前面的识别、匹配、控件接收即使都成功，服务不可用或目标过期也可能导致最终操作失败，因此需要等这一层的事实。
- 讲解②：如果一次操作涉及多项结果，应保留各自完成与失败，不能用一句成功覆盖全部。回执采用对应业务接口，但表达必须忠实反映状态。接下来由统一输出链处理声音和界面，让用户知道究竟做到了哪里。

### W10｜统一播报并呈现相应界面反馈（绿底）
- 要点：可播内容交统一声音服务界面呈现点击或业务结果失败提示不必逐字念出实际听见与界面显示分别确认
- 讲解①：业务返回的可播内容交给豆包统一合成与播放，避免每个页面各自抢麦。界面可以显示点击动画、成功结果或失败提示，但失败提示中的生硬文字不必逐字念给用户。
- 讲解②：最后仍要分别看真实操作、画面反馈和声音是否到达。TTS 生成了音频，可能还因焦点抢占而没有播出；屏幕显示成功，也不能覆盖业务实际失败。几条结果对应同一操作，才便于下一轮继续承接。

### W11｜记录这次模拟点击供下一轮承接（绿底）
- 要点：历史注明来自模拟点击保留原话、目标与真实结果成功和失败都按事实同步后续引用才能对应实际选择
- 讲解①：可见即可说完成后，需要把交互写进历史，注明来自模拟点击，并保留用户原话、目标对象和真实结果。这样云端后续不会误以为它是自己生成的一次普通问答或车控。
- 讲解②：例如用户选了卡片第二家餐厅，下一句“就去这里”需要对应刚才真正选中的地点。若点击失败，也必须保存失败，不能只记录拟选对象。历史已接收与实际点击成功仍是两个结果，都应对回原请求。

### W12｜卡片退场和页面切换时更新可说范围（蓝底）
- 要点：卡片出现时注册动态选项卡片消失时删除对应选择器页面更新有效控件及热词旧 ID 不得跨界面继续执行
- 讲解①：动态卡片出现时注册选择器，让用户可以说当前选项；卡片消失时需要删除对应选择器。否则用户早已离开旧卡片，一句“第二个”仍可能误点以前的内容。
- 讲解②：普通页面也要维护当前可操作范围，切页、手动关闭、超时和新卡替换都可能改变有效对象。控件更新还要带动相关热词范围变化。具体注销接口按框架执行，但最终应保证旧 ID 无法在无关新页面上继续操作。
