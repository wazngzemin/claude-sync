# 需求简介

停车大师是 GUI Agent 在虚拟屏上的通用停车能力。本方案只覆盖两个场景：入场探测和离场缴费。调用方/客户端在合适时机把页面打开到虚拟屏，并触发对应 GUI 能力；GUI 负责基于当前页面生成操作、提取页面可观测信息、返回确认态或结束态。

# 入场流程

入场阶段目标是：车辆拿到候选 URL 后，GUI 判断该页面是否为停车缴费页，并在确认后提取页面可观测到的停车基础信息。

入场链路的关键点：

1. 只考虑建立码库。车辆本身收集外部信息，拿到候选 URL。

2. 车辆将候选 URL 下发给 GUI 客户端，GUI 客户端打开到虚拟屏。

3. GUI 客户端触发入场探测，GUI 服务端只处理当前虚拟屏页面，不判断车辆是否真的入场，也不判断候选 URL 是否来自有效二维码。

4. 如果不是停车缴费页，结果返回 GUI 客户端，由车辆或 GUI 客户端继续尝试下一个候选入口。

5. 如果是停车缴费页，GUI 继续提取页面上可见的停车基础信息。

## 停车场信息交付

当前期望是 GUI 服务端只与 GUI 客户端通信，停车基础信息由 GUI 客户端再同步给车企服务端；但如果 GUI 探测耗时较长，执行过程中车辆已经下电，GUI 客户端可能无法再把最终结果送达车企服务端，导致码库信息传递失败。

# 离场流程

离场阶段目标是：车辆拿到缴费 URL 后，GUI 客户端打开页面，GUI 服务端完成查费、优惠处理和跳转支付页；涉及真实支付时，必须让用户确认或接管。

## 离场缴费

离场链路沿用既有 GUI 长程任务逻辑，本方案重点补充停车缴费场景下的触发参数、页面目标和支付确认态。

# 关键边界

1. GUI 不决定业务触发时机，也不负责检索码库；触发由车辆、GUI 客户端或调用方完成。

2. GUI 每次只处理当前虚拟屏页面；多个候选 URL 由车辆或 GUI 客户端排队处理，用 `request\_id` 关联结果。

3. 入场阶段只返回页面可观测信息，页面上没有的信息不构造。

4. 离场阶段涉及真实支付时，必须返回确认态；用户手动支付、密码输入或扫码支付时，由前台和 GUI 客户端接管。
