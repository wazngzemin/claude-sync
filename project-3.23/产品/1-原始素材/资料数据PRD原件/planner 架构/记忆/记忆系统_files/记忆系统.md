1.  短期记忆&长期记忆的更新存在空白期（更新有延迟）。

1.  对当前的情境没有追踪，没眼力见

## 人类记忆系统

### 人类记忆的科学分类

人类记忆并非单一的存储单元，而是一个由多个子系统协同工作的复杂结构。

从信息处理的流程来看，记忆被经典地分为三个阶段：

-   **感官记忆 (Sensory Memory)**：这是记忆的入口，信息在这里仅被短暂保留（通常少于1秒），如视觉的“图像记忆”和听觉的“声像记忆”。它为大脑提供了极短的时间窗口来决定哪些信息值得被进一步处理。
    
    **\---> 对应我们的数据流**；
    

-   **短时/工作记忆 (Short-Term / Working Memory)**：经过“注意”筛选的信息进入此阶段。**短时记忆**容量有限（乔治·米勒提出的“7±2”魔法数字），信息若不经复述，会在15-30秒内消失。而**工作记忆**是其动态升级版，不仅临时存储信息，更对其进行主动加工、操控和整合，是推理、理解和决策的核心中枢。
    
    **\---> 对应我们的短期记忆**；
    

-   **长时记忆 (Long-Term Memory)**：信息通过深度加工（如精细化复述、构建联系、赋予意义）从短时记忆转入长时记忆，其容量和保存时间几乎是无限的。
    
    长时记忆内部也存在精细分工，主要分为两大类：
    
    |     |     |     |
    | --- | --- | --- |
    | **记忆类型** | **核心特征** | **大脑关联区域** |
    | **陈述性记忆** **(Declarative / Explicit)**  <br>**“知道是什么”**<br><br>**\--****\-****\> 对应我们的长期情景记忆和长期语义记忆** | -   **可被有意识回忆和言语表达**<br><br>-   **语义记忆 (Semantic)**：关于世界的事实、概念和常识。例如，“特斯拉是一家电动汽车公司”。<br><br>-   **情景记忆 (Episodic)**：关于个人亲身经历的事件，包含时间、地点、情感等上下文。例如，“上周日，我和家人开车去了海边，路上听了周杰伦的歌”。 | 主要依赖**海马体 (Hippocampus)** 和内侧颞叶进行编码和巩固。 |
    | **非陈述性记忆** **(Non-Declarative / Implicit)**  <br>**“知道怎么做”**<br><br>**\--****\-****\> 一些肌肉记忆、“思想钢印”** | -   **无意识形成，难以言表，通过行为展现**<br><br>-   **程序性记忆 (Procedural)**：技能、习惯和运动学习。例如，熟练地调节空调温度、驾驶时的肌肉记忆（老司机可以快速精准地驾车转过每一个不同的弯，但你要问他具体要怎么打方向盘，他也答不上来）。<br><br>-   **启动效应 (Priming)**：先前接触的刺激会无意识地影响后续反应。<br><br>-   **经典条件反射 (Classical Conditioning)**：学习到的情绪或生理反应。 | 主要与**基底神经节 (Basal Ganglia)、小脑 (Cerebellum)** 等区域相关。 |
    
    **\---> 对应我们的长期记忆。**
    

### **人的记忆有哪些特征**

1.  人的视觉、听觉、触觉、味觉、嗅觉……都在为大脑的记忆系统提供素材，人脑对这些内容加工后，形成记忆，**记忆产生于感知**；

2.  一件令人开心、悲伤、心跳加速、意义重大的事情，会被打上“高亮标签”，从而强化这部分的记忆，在后续的场景中更容易被回忆起，影响用户的行为表现，**人的记忆被****情绪****强化**；
    
    > 情绪会强化人类记忆的存储。情绪并非记忆的干扰项，而是其编码和提取的“强化剂”。高唤醒度的情绪事件（如一次惊喜的旅程、一次烦躁的堵车）会被打上“高亮标签”，形成类似“闪光灯记忆”的深刻印象。这主要源于**杏仁核 (Amygdala)** 的激活，它会调节**海马体 (Hippocampus)** 的功能，增强记忆巩固。
    

3.  最近发生的事情，记忆会比较清晰，很早前发生的事情，记忆会比较模糊，**记忆会随着时间衰减**。
    
    > 人类的遗忘并非缺陷，而是一种重要的自适应机制，防止大脑被海量无用信息淹没。艾宾浩斯遗忘曲线揭示了“先快后慢”的遗忘规律，而记忆间的相互干扰（前摄/后摄）也是导致回忆失败的重要原因。
    

4.  人的记忆是**连续**的，包括：
    
    1.  人对于人的记忆是连续的：
        -   比如对于一个朋友的记忆，这些内容不是碎片化的，而是从过去到现在**一连串共同经历**串起来的：一起吃饭、上学、出游、吵架、和好……经历过的点点滴滴，最终形成一个完整连续的形象，下次跟他对话的时候你带着对他的整体认知，而不是只带着他的一些属性片段（常见的一些AI记忆召回策略）；
    
    2.  人对于情境的记忆是连续的：
        
        -   比如老师教学生一个知识点，第一次教的时候会比较有耐心，第二次的时候可能略微有点不耐烦，第三次的时候老师开始破口大骂你怎么这么不用心……这才是一个真实的人，而不是每次对话时，都只有当前时刻的情境感知。
        
        -   再比如一个开场就非常严肃的会议，严肃的环境会影响会议始终。

### **人的记忆被怎样使用以及对AI记忆系统的启发**

基于几个情境分析：

1.  你叫什么：**脱口而出，肌肉记忆、思想钢印** \---> 对应固定给AI的那些内容；

2.  你过去最难忘的一件事情是什么：**情绪增强，高优召回** \---> 对应情绪强化的记忆内容；

3.  双周会要到了，写一下你的周报吧：**回忆事件，提炼总结** \---> 对应从常规记忆/事件日志中总结出的记忆内容。

### 增加用户画像（P1）

用户画像为一段概括用户核心且实时信息的自然语言。包括下面几部分信息：

1.  基础设定与性格底色

格式示例： “\[用户名\]是一位\[职业/身份\]，\[性别\]，\[年龄\]，\[家庭及社会关系\]，性格偏向\[冷静/热情\]，喜欢\[直接/委婉\]的沟通方式。他非常看重\[计划/效率/情感连接\]，对\[某领域\]有专业见解。”

#### mem0的记忆管理机制

mem0通过一套基于重要性、时间、访问频率与语义相关性的动态记忆权重管理与生命周期控制系统，降低低价值、过时记忆的可访问性，让记忆随时间 “变模糊、变不重要、更容易检索不到”，模拟人脑的遗忘曲线。

其遗忘机制主要分为 隐式遗忘（检索衰减） 和 显式遗忘（清理删除） 两大类，并配合分层记忆结构协同工作。

1.  核心基础：记忆元数据与评分体系

每条记忆（Memory Unit）都附带关键元数据，作为遗忘判断的依据：

-   创建时间戳 (created\_at)：计算时间间隔

-   最后访问时间 (last\_accessed)：判断新鲜度

-   访问计数 (access\_count)：统计使用频率

-   重要性评分 (importance\_score)：0~1 分，LLM 自动评估或人工设定

-   语义向量 (embedding)：用于相似度与冲突检测

Mem0 会为每条记忆计算综合检索分数 (Total Score)，决定其被召回的概率，分数越低越容易被 “遗忘”：

```Plain
总分数 = 语义相似度 × 时间衰减系数 × 重要性 × 访问频率权重
```

-   语义相似度：与当前查询的向量匹配度

-   时间衰减系数：随时间推移降低（核心遗忘算法）

-   重要性：预设或动态评估的价值分

-   访问频率：min(access\_count / 100, 1.0)，越常用权重越高

2.  隐式遗忘：时间衰减机制（核心）

Mem0 模仿人类艾宾浩斯遗忘曲线，通过指数衰减公式让旧记忆的权重自然下降，不立即删除但降低检索优先级。

1.  标准衰减算法

```Python
def calculate_decay(self, current_time: datetime) -> float:
    # 计算自上次访问的小时数
    hours_since_access = (current_time - self.last_accessed).total_seconds() / 3600
    # 重要性越高，衰减越慢
    decay_rate = 0.1 * (1 - self.importance_score)
    # 衰减值（越新、越重要，值越接近1）
    decay = 1.0 - decay_rate * hours_since_access
    # 下限钳位，防止变为负数
    return max(decay, 0.0)
```

2.  简化版时效权重（常用实现）

```Plain
最终权重 = 重要性评分 × (0.95 ^ 未访问天数)
```

示例：

-   重要性 0.7 的记忆，30 天未访问：`0.7 × (0.95^30) ≈ 0.7 × 0.21 ≈ 0.15`

-   重要性 1.0 的记忆，1 天未访问：`1.0 × 0.95 = 0.95`

效果：不重要的旧记忆分数快速跌破检索阈值（通常 0.3），在检索时被过滤，实现 “想不起来” 的效果。

3.  显式遗忘：主动清理与删除机制

当记忆分数长期极低、完全过时或冲突时，Mem0 会物理删除，释放存储。

1.  异步定期清理（后台任务）
    
    默认每小时执行，删除两类条目：
    
    -   低价值过期记忆：分数 < 阈值（如 0.3）且 超过 30/90 天未访问
    
    -   高度重复记忆：语义相似度 > 90%，只保留最新 / 最完整的一条

2.  冲突更新与覆盖（UPDATE/DELETE）
    
    新记忆与旧记忆语义冲突时（如 “喜欢咖啡”→“只喝茶”）：
    
    1.  检索相似旧记忆
    
    2.  LLM 判断为矛盾 → 执行 DELETE 旧记忆 / UPDATE 为新内容
    
    3.  旧记忆被直接移除，强制 “遗忘” 过时信息

3.  分层记忆的天然遗忘

Mem0 采用工作记忆 / 短期 / 长期三层结构：

-   工作记忆（Working Memory）：缓存最近 N 条交互，会话结束 / 超时空自动删除

-   短期记忆：保留数天～数周，按强衰减快速清理

-   长期记忆：低衰减、高保留，但仍受重要性与访问频率约束

4.  辅助遗忘机制
    
    1.  访问频率压制：长期不访问的记忆，`access_count` 停滞 → 频率权重趋近 0 → 总分下降 → 难以被检索。
    
    2.  语义相关性过滤：检索时只返回与当前查询语义相关的高分记忆，无关旧记忆即使分数尚可也被排除。
    
    3.  用户显式遗忘：提供 API / 接口让用户手动删除某条记忆，强制 “主动遗忘”。

**综上，mem0遗忘机制考虑了记忆的初始重要性、语义向量相关性、时间衰减和访问频率。**

#### 优化方案

mem0重要性评分主要考虑记忆的信息有用性，缺乏对于情感的关注，无法做到像人。

信息的有用性固然重要，比如用户家的地址、上周去过的地方、美食偏好等等。但情感才是构建更好用的记忆系统乃至AI人格的关键（为gpt-4o献一束电子鲜花），下面这些都是记忆有用性不高，但重要性高的例子：

-   很多年前的一个下午，你和儿时伙伴一起，在门口的那堆沙子当中打滚、挖洞，从下午到天黑，脏到都快认不出来，最后依依不舍地互相道别各回各家，当时只道是寻常，如今忆起只剩恍惚；

-   去年3月8号那天，你开着自己的车，缓缓打开敞篷，晚风轻轻吹进来，小美头发飘在脸上，一边害羞挡着，一边偷偷看着你笑，你们沿着江边慢慢地兜风，这一刻你觉得甜甜的恋爱或许就是这样吧；

-   今年1月23日那天，你开车去了一趟安吉，其实路上的风景平平无常，但因为此行的目的是去策划自己的求婚仪式，所以至今都对路上的花草树木记忆尤深；

-   今年8月19日那天下午，你没有去上班，自己一个人独自驾车在日落大道浪漫出逃，除了风没有别人知道，逃离社会的框架，那天下午你找回了最真实的自己。

-   ……

如果将mem0记忆遗忘机制抽象成简单的公式：

```Plain
最终得分 = α*语义相似度 + β*信息重要性 + γ*时效性
```

新方案期望在此基础上能够更多的考虑情感因素（即上面提到的情感显著性），在检索时，将情感显著性作为检索后的rerank因子：

```Plain
最终得分 = α*语义相似度 + β*信息重要性 + γ*时效性 + δ*情感显著性
```

情感显著性的定义和计算逻辑：

-   定义：记忆存入时，对记忆进行的情感评估并打上的分值

-   计算逻辑：
    
    -   情绪强度：强烈的快乐、愤怒、悲伤、恐惧（如：用户失业、亲人过世、获得大奖）；
    
    -   冲突/独特性：与常态不符的事情（如：平时打车下班，今天北京下雪了，选择步行5公里，边回家边感受自然）。
    
    -   核心用户画像：涉及用户核心偏好或价值观的事情（如用户偏爱二次元、用户提到自己坚决不吃香菜）

-   效果：即使这个记忆是半年前的，且语义匹配度和信息重要性都不是很高，但因为情感显著性比较高，它依然会被顶到模型前面。

上面几个参数决定了AI的性格：

-   工具人模式：α和β比较大，更偏理智，只回答你问的问题，不翻旧账；

-   感性模式：δ比较大，会记着那些让你情绪深刻的事，能更好地照顾用户的情绪；

-   活在当下模式：γ比较大，更关注近期发生的事情。

但只靠上面的公式还是不能全面的评估记忆是否应该被召回。情感包括正向情感和负向情感，二者在召回中不能仅通过显著性来一概而论，应该由时下的情感共鸣决定。

```Plain
最终得分 = α*语义相似度 + β*信息重要性 + γ*时效性 + δ*情感显著性 + ε*情感共鸣
```

参考心理学对于情感维度的定义，情感共鸣由记忆的极性以及当前对话的情绪极性决定：

```Plain
最终得分 = α*语义相似度 + β*信息重要性 + γ*时效性 + δ*情感显著性 + ε*（Pmem*Pnow）
* 第一阶段可以先保留情感显著性，不增加情感共鸣
```

其中Pmem为记忆的极性，\[-1,1\]；Pnow为当前对话的情绪极性，\[-1,1\]。新增项提供了同频共振的能力：

-   当 Pmem和Pnow 同号（同为正或同为负）：乘积为正，得分增加。
    
    -   场景：用户现在很高兴（Pnow＞0)，模型更容易检索出以前开心的记忆（Pmem>0）来助兴，“锦上添花”。
    
    -   场景：用户现在很沮丧（Pnow<0），模型更容易检索出以前悲伤的经历（Pmem<0）来共情，“感同身受”，同时做到不戳伤疤。

-   当二者异号：乘积为负，得分减少。这可以防止在用户难过时，模型提起一件大喜事，显得缺乏情商（除非你的策略是“转化”情绪）。

实际使用时：

-   如果Pnom（当前情绪）判断不准，情感共鸣项可能会起反作用。可以给Pnow设定一个置信度阈值。如果模型不确定用户现在是什么心情，就把ε设为0，退回到不带情感共鸣的检索；

-   解决“情感显著性”与“情感共鸣因子”的冗余：在数学建模上，通常会有“情感显著性”≈|“情感共鸣因子”|的倾向。
    
    -   如果一个记忆的极性是0.9（大喜）或-0.9（大悲），它的显著性一定很高。
    
    -   如果极性是0.1（平淡），显著性通常很低。
    
    -   因此，在存储时，可以只计算一个极性值\[-1,1\]，“情感显著性”自动定义为情感共鸣因子的绝对值，这样可以简化标注工作。

-   在有些情况下，比如悲伤的时刻，模型做不好在检索出悲伤经历时感同身受、不戳伤疤（表现为哪壶不开提哪壶），或者希望能够检索出一些开心的时刻来激励用户，可以动态调整ε，直接将ε置为负，检索出想要的记忆，情绪策略可以是模型来决定的：
    
    -   模式A：共情验证(Validation Mode)---“我懂你”
        
        -   适用场景：用户刚开始表达负面情绪，需要被听见和理解。
        
        -   逻辑：ε为正，检索相似的负面记忆，但侧重于“感受”而非“事件”。
        
        -   效果：“我记得上次你加班到深夜时也是这种感觉，那种努力没被看到到的心情真的很糟糕。”（这能建立深度的信任感）。
    
    -   模式B：情绪修复(Mood Repair Mode)---“拉你一把”
        
        -   适用场景：用户深陷负面情绪一段时间，或者明确表现出想要摆脱现状
        
        -   逻辑：强制将ε设为负值，专门检索Pmem>0的记忆
        
        -   效果：“我知道你现在很累。但你还记得去年那个夏天，你最后通过难关时的兴奋劲吗，我们要不要换个思路，找找那次解决问题的感觉?”

-   并不是所有的负面记忆都能拿出来聊。针对一些特殊的记忆，可以在记忆库中增加\*\*敏感\*\*标签，来在检索或使用时区分轻度负面或重度负面（如“亲人离去”、“重大的失败”等），作为一种安全过滤措施。

综上，希望在记忆的rerank机制中，除了考虑语义相似度、信息重要性以及时效性，能够**考虑记忆的情感显著性以及和当前情绪的情感共鸣**，提升结果质量。

### 记忆召回优化（P0）

【P0】部分包含基于标签的召回，结合情感rerank属于【P1】

![](记忆系统_files/0EIA9hJ20Hn8KmiepyyaipkdCUHYUZzg.png)

1.  第一步：先用LLM进行标签化提取
    -   人类在回忆时，大脑首先会进行一个“剪枝”过程。比如提到“充电”，大脑会自动关闭关于“社会关系”的搜索域。好处是：
        
        -   减少干扰：向量检索容易产生“语义漂移”。通过LLM先进行标签匹配（#出行偏好、#补能偏好、#美食偏好），可以将检索范围限制在相关领域。
        
        -   可以改善用户记忆模糊的场景：上次吃过的那个，什么什么酸酸辣辣的特色菜那家
        
        -   性能优化：在数万条记忆日志中做全量向量匹配比较慢。通过标签做元数据过滤，可以将检索范围瞬间缩小到几百条，提升响应速度。

2.  第二步：向量+关键词混合检索（是否基于第二步缩小范围，可以根据第一步召回的数量来定，第二步当前可以先不做，把第一步的标签定义的更细一点）
    -   在过滤后的子集中，进行向量相似度匹配，取TOPxxx。

3.  第三步：结合情感因素Rerank
    -   对检索出的记忆，结合情感因素进行精排。结合情感因素rerank时，不同标签单独rerank

**核心收益：**

优化了向量检索的过召和漏召问题。

-   过召：标签提取会更加贴合场景

-   漏召：标签提取能够在记忆召回时就融入场景知识，比如长途出行场景把补能相关的内容也召回，让整个场景不单薄；结合情绪等因子排序，也可以优化漏召问题。

**应用示例一：**

> **用户**：“又得去充电了，上次那地方排队太久，烦死了。”
> 
> **第一步**：先用LLM进行标签化提取：
> 
> -   召回语义标签：#补能偏好 #出行及导航偏好
> 
> -   召回情景标签：#补能
> 
> **第二步**：向量+关键词混合检索：寻找语义上与“排队、充电、体验差”相似的片段
> 
> **第三步**：结合情感因素Rerank：
> 
> -   有一条记忆是“一年前在某地充电很快”，虽然相似度比较高，但时效性和情感共鸣都比较低
> 
> -   另一条记忆是“上周在A站排队50多分钟”，相似度高、时效性高、情感显著和情感共鸣都比较高
> 
> **最终表现**：豆包：“是啊，上次在A站等了快一个小时，确实糟心，我来帮你找个附近更快、空闲桩更多的。”

**应用示例二：**

### 历史对话清空需求（P0）

**需求背景**：客户【一键除痕】模式，需要清空当前的模型历史对话。

**需求内容**：提供接口支持清空Director的全部历史对话（通过新起chat\_id的方式）。

### 对话摘要清空需求（P0）

**需求背景**：客户【一键除痕】模式，需要清空当前的对话摘要内容。

**需求内容**：提供接口支持清空对话摘要（通过新起chat\_id的方式，逻辑上和3.10.1一致）。

### 记忆删除需求（P0）

#### 语义记忆删除需求

语义记忆支持的删除方式：

-   单条删除：新增接口支持

-   按标签筛选删除：新增接口支持

-   按人筛选删除：新增接口支持

-   一键清空：新增接口支持

#### 情景记忆删除需求

情景记忆（包含所有类型）支持的删除方式：

-   按时间筛选删除：新增接口支持，支持以日为颗粒度，接口返回删除条数

-   按标签筛选删除：新增接口支持

-   按人筛选删除：新增接口支持

-   一键清空：新增接口支持

#### 语义记忆删除时对用户画像的影响

模拟query更新用户画像，比如：

-   用户删除了记忆【xxx】

-   用户删除了【内容及车上娱乐偏好】的所有记忆

-   用户删除了【小明】的所有记忆

-   用户清空了所有记忆

用户画像模块接收到记忆操作query后，更新用户画像内容。
