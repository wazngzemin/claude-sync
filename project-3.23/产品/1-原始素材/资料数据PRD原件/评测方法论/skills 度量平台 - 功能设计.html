背景与目标

当前问题

团队在 AI Agent 方向已有大量实践积累，但随着 Skill 数量快速增长，逐渐暴露出系统性问题：

  • 不同开发者对 Skill 质量理解不一致，缺乏统一认知
  • 缺少性能数据参考，导致类似问题反复出现
  • 难以评估开发投入的实际价值，资源分配不够精准
  • 没有明确的质量准入标准，Skill 水平波动较大

建设目标

通过建立全面的度量指标和可执行的工程规范，让团队成员能够基于数据做决策，而非依赖经验和直觉。

  • 建立性能指标体系（执行耗时、Token 消耗、成功率等）
  • 通过数据对比，总结高效 Skill 的共性特征
  • 提供实时反馈，帮助开发者快速定位优化方向
  • 沉淀团队认可的工程标准，降低新人接入成本

整体架构流程

数据收集方案

提供轻量级 SDK，支持本地 UI（JavaScript）、自建云端（Node/Python/Go）、基建云端（侵入式埋点）等多种形态。通过 hook 机制自动采集 Skill 执行日志，无需手动调用，本地仅负责上报，服务端负责处理和分析。

功能需求

一、数据收集

系统提供轻量级的 SDK，自动收集 Skill 执行日志

  • 支持一键安装到项目 hooks 文件夹（npm install 或复制脚本）
  • 在 Claude hook 完成时自动触发，无需手动调用
  • 支持本地 UI（JS SDK）、自建云端（Node/Python/Go）、基建云端（侵入式埋点）
  • 本地仅负责采集和上报，不做复杂处理

二、日志分析

服务端需将原始日志组织为树形结构，支持完整链路追踪

  • 以 Skill 为中心，按触发链形成树状数据
  • 通过 [START]/[END] 标记计算每个 Skill 的执行时间
  • 嵌套关系反映工具调用链（Skill → Tool → Sub-Skill）

示例：

Task: 登录功能实现
├─ skill: code-search [START]
│  ├─ tool: Grep (20ms)
│  └─ [END] ✓ success
└─ skill: code-write [START]
   ├─ tool: Edit (600ms)
   └─ [END] ✓ success

系统支持通用指标（平台统一）+ 特殊指标（Creator 自定义）

特殊指标（示例）：

  • code-search: 搜索精度（hit-rate）、误触发率
  • code-write: 生成代码质量（编译通过率）、代码风格一致性
  • test-runner: 覆盖率提升、新增缺陷数

验收标准： 通用指标自动计算，特殊指标可由 Creator 配置并执行

四、单测卡点

Skill Creator 必须提供单测用例，达标后方可上线

  • 每个 Skill 至少提供 3-5 个测试用例
  • 覆盖正常、异常、边界情况
  • 单测通过率 ≥ 95% 才允许上线
  • 测试用例需包含输入、预期输出、实际通过率
test_case_1:
  input: {files: ["main.js"], pattern: "function"}
  expected: {results: [...], count: 5}
  pass_rate: 100%

五、可视化展示

提供 Dashboard 支持任务维度和 Skill 维度查看

任务维度：

  • 表格展示所有任务
  • 点击任务查看 Skills 树
  • 显示执行时长、Token、状态

Skill 维度：

  • 统计历史执行次数
  • 展示平均执行时长
  • 查看执行历史记录

六、评估优化

需求描述： 建立评估 → 反馈 → 优化 的循环

  • ① 评估： 实时对 skill 进行评分，评估
  • ② 反馈： 将评估结果反馈给 Creator
  • ③ 迭代： Creator 根据反馈优化 Skill

预期效果： 持续推高 Skill 质量和标准化程度
