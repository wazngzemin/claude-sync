动态示例平台迭代需求文档

版本：v2.0 ｜ 日期：2026-08-12 ｜ 撰写人：王泽民 ｜ 对接开发：王梦尧

评审方：李浩然（项目）、赵晓朝（算法）、高红涛/罗丽（测试）、郝晓伟（DT）

需求来源：2026-08-05「DT复测结果分析——动态示例质量问题」会议纪要

文档约定：P0=本期必须做，不做则批量修复链路走不通；P1=二期；P2=三期。"示例"均指动态示例。

一、背景与问题定义

1.1 动态示例是什么、现在怎么用的

动态示例是"query→决策分析"的知识对，按语义检索注入 Planner 的 System Prompt（{{场景示例}}槽位），用于修复线上 badcase。当前两种使用方式：

  • 单条修复：Meego 上单个 bug，修复人分析后直接上平台添加，每天几条，分散在产品和算法 4-6 个人手里；
  • 批量修复：每轮大测试（约月度级）产出几百条 badcase（如本轮 187 条用例、功能安全集 600+ 条），集中在 Excel 里写好后批量导入。

1.2 出了什么问题

8 月 5 日复测：动态示例大量添加后，测试通过率改善远低于预期（会上对齐的预期约 80%）。会上定位到四类平台侧根因：

#问题会议证据（原话）后果
1 添加无查重，重复/相似 query 直接落库 晓朝："很多动态示例加得比较重复，比如天窗的可能重复在加，导致目标示例不在召回 top3 里"；罗丽："每个人都可能在修天窗问题" 相似示例互相稀释召回排序，该召回的召不回，示例加了等于没加
2 批量接口只增不改不删，重复也不拦 梦尧："只能在上面追加……query 完全一样它也不关心，直接往上添加" Excel 维护→批量导入的模式不成立：改不了旧数据，错数据越积越多
3 全量数据导不出来 红涛："我们现在有全量的动态示例内容吗？想跑一下所有动态示例评个结果"；梦尧："不支持（导出），数据库导出需要 leader 审批" 无法全量 review 冲突；无法全量回归测试；Excel 台账与线上脱节断档
4 发布即生效，无审核 浩然："加一个审批机制，或强制要求自测结果"；晓朝："长远看需要平台加评审上线流程，归口到一两个人审核" 低质量/写错的示例直接污染线上，影响面放大
5 批量导入全部记为 system 梦尧："批量导入默认通过系统添加，名字都是 system" 出问题找不到责任人，无法追溯谁导的、导了什么
6 环境错配不可见 会上对不齐："你们用的是 DEV 还是 prod？""都加在 PRD，车端 DEV 居多" 示例加在 PRD 但车在 DEV，测试复测时示例根本没生效

1.3 为什么现在要解

每轮大测试后都有 200-300 条级别的批量修复需求，当前平台能力下，批量修复=批量制造新冲突。本轮 187 条用例的修复已经实际发生重复添加（天窗类）。下一轮测试前平台必须具备最小闭环能力。

六、功能需求详述

P0-1 添加查重拦截

现状：添加时不做任何查重，query 完全重复也直接落库。

需求描述

  1. 单条添加、批量导入时，均对新 query 与库内已有 query 做语义级相似度匹配（非字符串完全相等——"打开天窗"和"帮我开一下天窗"应判为相似）；
  2. 检出相似条目时，展示已有条目：ID、query、决策分析摘要（前 100 字）、添加人、添加时间；操作者三选一：
    • 取消添加——确认重复，放弃；
    • 覆盖更新——新内容替换旧条目，保留原 ID（外部 Meego 单上贴的 ID 不失效）；
    • 仍要新增——确认两条确实不同（如 query 相似但适用分支不同），强制添加；
  3. 批量导入逐条执行同样校验，导入完成输出报告：新增 X 条、覆盖 Y 条、拦截 Z 条、强制新增 W 条，报告可下载；
  4. 相似度阈值给默认值，后台可配置。
边界场景：①一条新 query 同时相似多条旧条目→全部列出，操作者逐条判断；②批量导入含相似条目时默认拦截进报告，不阻塞其余条目导入；③查重范围含草稿区条目（防止草稿和线上也打架）。
验收标准：①构造与库内 query 语义相近的示例添加，能检出并三选一；②批量导入 10 条含 3 条重复，报告准确标出 3 条且其余 7 条正常进草稿；③"打开天窗" vs "帮我开一下天窗"判为相似。

P0-2 全量批量导出

现状：不支持导出；数据库直接导需 leader 审批人肉提数。

需求描述

  1. 平台提供"导出全部"按钮，导出当前环境（可选 DEV/PRD/全部）全量示例为 Excel 或 CSV；
  2. 导出字段=第五节全部字段，纯平铺，无合并单元格；
  3. 导出动作记操作日志：谁、何时、导出了哪个环境、多少条；
  4. 如需审批，审批线上化：导出申请→leader 线上批准→生成下载链接（有效期 24 小时），不要人肉提数。
边界场景：①数据量大（数千条）时异步生成+完成通知，不卡页面；②导出含草稿区条目并标注状态，供全量 review。
验收标准：导出条数与平台列表一致，字段完整无乱码；Excel 可直接打开筛选。

P0-3 批量修改 + 批量删除

现状：批量接口只支持新增；修改、删除只能逐条手动。

需求描述

  1. 标准模板：平台提供模板下载，列固定为：ID、query、决策分析、其他说明、环境、操作类型（新增/更新/删除）。新增行 ID 留空；更新/删除行必填 ID；
  2. 批量更新：按 ID 匹配覆盖更新内容字段；ID 不存在的行报错跳过，列入报告；
  3. 批量删除：按 ID 删除，执行前二次确认（展示将删除条数+内容摘要）；
  4. 批量更新/删除同样走草稿区+审核（同 4.2 流程），同样生成批次号，支持按批次回滚。
边界场景：①更新操作同样触发查重校验（改完的 query 可能和别的条目撞了）；②删除已上线条目需在报告中标红提示"该条目线上生效中"；③模板列顺序错、列缺失时给明确报错，不做静默容错。
验收标准：模板批量更新 5 条、删除 5 条结果正确；ID 填错的行有明确报错；删除已上线条目有标红提示。

P1-4 草稿态 + 审核上线

需求描述

  1. 状态机：草稿 →（审核通过）→ 已上线；草稿 →（审核驳回）→ 已驳回；
  2. 单条添加默认直接上线，操作者可手动选"存为草稿"；
  3. 批量导入一律进草稿区，审核人通过后才生效；
  4. 审核人可配置（1-N 人，当前：王泽民、赵晓朝），审核界面逐条展示内容并自动附带库内相似条目参考（复用 P0-1 能力）；
  5. 支持单条通过/驳回、批量通过；驳回必填理由，导入人可见可修改后重新提交。
边界场景：①审核期间原条目被他人修改→提示审核人"内容已变更"；②草稿区条目长期未审（>7 天）→列表标黄提醒。
验收标准：批量导入 10 条未生效；审核通过后生效；驳回条目带理由且导入人可见。

P1-5 自测凭证 + bug 关联

需求描述

  1. 新增"关联 bug ID"（Meego 单号，可多个）和"自测凭证"（文本/附件）两个选填字段；
  2. 列表页支持筛选"无关联 bug""无自测凭证"的条目，供测试关单前核查；
  3. 添加/编辑页面对两字段给醒目提示："建议关联 Meego 单号并附自测结果，测试关单前将核查"。
验收标准：字段可填可改可查；筛选可用；提示文案展示正常。

P1-6 添加人与批次追溯

现状：批量导入的条目添加人全为 system。

需求描述

  1. 批量导入记录真实操作人（登录态导入或接口强制传操作人参数）；
  2. 每次批量操作生成批次号，支持按批次号查看全部条目；
  3. 支持按批次整体回滚：该批次新增的删除、覆盖的恢复原值。
边界场景：批次内条目在导入后被人工单独修改过→回滚时跳过该条目并在结果中提示（防止回滚吃掉人工修复）。
验收标准：导入后添加人显示真实姓名；按批次号可查出全部条目；一键回滚结果正确。

P2-7 召回测试嵌入编辑页

现状：验证召回需芭比登录→跳转 Waking 数据库管理页→手动输 query 测试，链条长，多数人不会用。

需求：添加/编辑页内嵌"召回测试"按钮，输入 query 实时返回召回 top3 及相似度分值，让"加之前先验证能召回"成为顺手动作。

P2-8 环境标识与同步

需求：条目带环境标识；列表按环境筛选；支持 DEV↔PRD 批量同步（复制）与差异对比视图。解决"加在 PRD、车在 DEV"的错配。

P2-9 变更历史与回滚

需求：每条示例记录修改历史（谁、何时、前后值），支持单条回滚到任一历史版本。解决老旧示例（工具名变更等）的追溯问题。

七、非功能需求

项要求
量级单次批量操作 300 条内正常完成；全库万级条目不卡顿
操作日志所有增删改、导入导出、审核动作留痕，可追溯
权限现阶段仅 4-6 名内部用户，不做复杂权限；审核人名单可配置即可
兼容性新字段对存量数据置空即可，不要求历史数据补录

八、配合流程（非平台需求，8.5 会上已定的 SOP）

  1. 单条 Meego bug：平台直接添加，Meego 单上贴动态示例 ID + 自测结果；测试复测关单前核查，缺信息打回；
  2. 批量修复：Excel 标准模板集中维护 → 群内过一遍 → 审核人审查 → 批量导入；
  3. 分工原则：按问题分类/功能模块认领（不按 query 均分），避免同类问题多人重复添加。

九、范围框定与分期

期内容理由
本期 P0查重拦截、全量导出、批量修改+删除不做则批量修复和全量测试两条路都走不通
二期 P1草稿态审核、自测凭证、批次追溯质量管控闭环
三期 P2召回测试嵌入、环境管理、变更历史体验优化

明确不做：①不兼容旧 Excel 台账的合并单元格等乱格式，以平台标准模板为准；②不做复杂权限体系。

十、开放问题

  1. 相似度匹配能否复用检索侧现有能力？阈值默认值与可调范围？（会上泽民提到"之前有检索策略后来没加"，请梦尧确认）；
  2. 导出审批链挂哪位 leader（正伟/晓杰，浩然说可群内 push）；
  3. 批次回滚遇"后续被人工修改过的条目"：本期按"跳过并提示"写，确认是否接受；
  4. 草稿区超 7 天未审标黄提醒，是否要做成消息推送。
