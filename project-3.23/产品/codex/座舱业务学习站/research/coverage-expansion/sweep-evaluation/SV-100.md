    - **理解层问题**

        - 缺乏内化记忆：大模型在处理多轮对话时，每一轮任务都是切片式的，缺乏内化的记忆，导致在上下文出现冲突时无法取舍。例如，当记忆中副驾是妈妈，而视觉感知显示副驾是小女孩时，模型会混淆。建议建立连续的记忆和用户画像，为模型提供全局推理的依据。

        - 缺乏幽默和轻重缓急判断：豆包汽车像《生活大爆炸》里的谢尔顿，听不懂幽默，无法区分不同任务的轻重缓急。例如，在用户询问车上电量时，仍强调背单词任务。同时，缺乏主动澄清和追问的理解驱动，对于用户模糊的需求，往往直接执行预设策略。

    - **表达执行层问题**

        - 缺乏生活化经验：大模型的知识来源于文档文字内容，缺乏生活化的经验，导致在执行任务时出现逻辑错误。例如，在与副驾小女孩背单词时，给出的例子不合理。

        - 缺乏态度表达：豆包汽车在表达和执行时缺乏态度，过度讨好用户，语言风格单一，回答冗长，语速同质化。建议在闲聊场景中增加情感陪伴，使表达更真实。

        - 缺乏主动追问和确认：对于用户的需求，豆包汽车缺乏主动追问和确认的意识，直接执行自认为的最佳方案，可能无法满足用户的真实需求。

    - **其他方面**

        - 反思和学习能力：豆包汽车在收到负面反馈时，只是单纯道歉，下次遇到类似情况仍会犯错，缺乏反思和学习能力。建议通过重复测试场景，观察数值提升情况来评估其学习能力。

        - 个人喜好和审美：认为豆包汽车应具有独立人格，有自己的喜好和审美偏向，并持续迭代。例如，在与用户交流过程中，逐渐发现自己喜欢的电视剧、游戏等。

- **车载智能助手评测体系 2\.0**

    - **评测流程**

        - 选择场景：根据评测目的选择对应的场景，补齐出行目的和角色等相关信息。例如，如果 planner 或 Advisor 等有优化点，评测场景应与之强相关。

        - 角色扮演：让测试者或大模型根据场景剧本与豆包汽车进行真实交互和对话体验。

        - 检查点分析：根据对话内容进行检查点分析，包括数据报表和打分情况。检查点分为基础和惊喜两个等级，未来考虑增加权重。

        - 问题汇总：对评测得来的信息和数据分析进行问题汇总，找出共性问题并进行归因，如 context 信息缺失、planner 理解问题等。

        - 输出报表：根据体验目的输出报表，展示豆包汽车的能力分布、问题集中点和场景完成度。

    - **控制变量与稳定性评估**

        - 控制变量方式：在大模型评测中，控制变量有多种层级。最严格的方式是按照评测 log 再次评测；其次是保持需求和 context 相同，但自由发挥话术；还可以适当改变 context 进行评测。

        - 稳定性指标：引入 “PASSAT3” 指标，即三次评测中完成一次可得一分，乘以 3 表示三次全部完成，用于评估稳定性。

    - **场景评测数据**

        - 场景设定：以本人画像为基础，设定了通勤感冒、上车放松和带女儿回父母家三个场景，在每个场景中与豆包汽车进行对话。

        - 检查点设置：根据不同任务生成针对性的检查点，分为过程分和结果分，大部分由 AI 生成，人工进行调整。检查点与 case 强相关，避免用维度打分的不贴合问题。

        - 通用检查点与能力评估：通用检查点适用于每条 case，包括响应要求、情感表达、推理能力等。通过检查点评估豆包汽车的能力表现，最终汇总为整体能力得分。未来考虑对能力进行二级维度拆解，如情商可拆解为察言观色、同理心等。

        - 场景覆盖与优化：强调场景选取应从典型用户和实际使用场景出发，尽量用少的场景和 case 覆盖核心能力。同时，需对通用检查点进行穷举，将主线检查点与情商、智商等能力相关联。

- **后续工作计划**

    - **优化豆包汽车**：根据会议讨论的优化方向，对豆包汽车在感知、理解和表达执行等方面进行改进，如优化 ASR 后处理模块、建立连续记忆和用户画像、增加生活化经验和态度表达等。

    - **完善评测体系**：进一步完善车载智能助手评测体系 2\.0，包括细化检查点、增加能力维度拆解、进行数据换算和标准化等，确保评测的准确性和全面性。

    - **场景选取与优化**：重新思考场景选取，选择更具代表性的场景，以最小的代价衡量豆包汽车的能力，同时考虑覆盖核心能力。

    - **持续沟通与讨论**：通过飞书等方式，继续就豆包汽车的优化和评测体系的完善进行沟通和讨论，及时解决问题。
