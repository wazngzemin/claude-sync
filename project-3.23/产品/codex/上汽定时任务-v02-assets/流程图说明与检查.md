## 产品口径

- 纯定时由弋途登记和到点唤醒；用户条件任务由动态 Advisor 注册 → 豆包条件触发器命中 → callback 动态 Advisor → advice Planner → 工具 / 客户端执行。
- 后台预置按场景配置的下游处理，不统一经过动态 Advisor。
- “到点”“条件命中”“回调成功”“动作成功”分别说明，不互相替代。
- 一次性与循环在执行结果后的收尾节点分支；一次性完成后的条件清理是建议，持续任务的频控、次数与有效期待确认。
- 旧事件有效性拦截、结果回写、部分创建失败回滚、修改取消顺序均明确标为建议 / 待确认。
- 云端 / 端侧的当前部署、断网能力、跨下电和补发规则均保留待确认，未画成已上线事实。
- 第 3 图虚线表示建议异常闭环 / 结果回写；无法触达和超时的查询、重试、错过判定策略待确认。
- 第 5 图的已经下发车辆动作说明独立成框，避免让用户把取消等同于回滚动作。

## 校正与验证

已查看 6 张本地 PNG，校正了第 2、5 图判断框两侧来回连线共用端口造成的方向歧义，将两路登记回执汇入判断框顶部。第 3 图补齐无法触达和执行结果未知到本轮记录的虚线闭环，第 6 图将一次性结束与用户取消分别显示。标题、节点、注释均没有视觉溢出和裁切。

本地校验不能替代飞书白板回读。发布时仍需查询线上白板并看图；判断菱形的 scale / rotate 变换尤其需要回读确认。
