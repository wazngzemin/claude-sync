## CHAT：aiva-vui-1104.txt 的概念补充

### CHAT-K001｜多屏卡片生命周期（卡片 21 未细分）
- 是什么：按前后屏分别保持和退出卡片的界面规则，与输入管理轮次结束分开。
- 在哪里运行：车机 HMI，赛力斯端侧实现多屏联动，未写独立服务。
- 收到什么：音区、语义相关性、任务类型、交互和 TTS 进度。
- 输出什么：本屏卡片更新/保持/关闭与相关任务跨屏联动。
- 关键数字：无交互在 TTS 后 10 秒退出卡片，这不是输入管理硬超时。
- 来源：chapters/I/raw/aiva-vui-1104.txt:438–451、722–796。

### CHAT-K002｜主交互状态与调度状态映射（扩充卡片 9）
- 是什么：端侧“听/想/说”的表现阶段与云端决定准入的三态，职责不同。
- 在哪里运行：车机状态机和 HMI，云端三态以 input-tech 为准。
- 收到什么：VAD、拒识/采信结果、Planner 工具回复、TTS 事件。
- 输出什么：灯屏、收音与延时聆听状态。
- 关键数字：详细定义延时聆听 30 秒，前文残留 60 秒需列冲突。
- 来源：chapters/I/raw/aiva-vui-1104.txt:167–176、454–478、943–1084。

### PRD-K003｜旧多音区缓存与轮询（演进对照，非候选现行部件）
- 是什么：sound_zone_merge 聚合同会话多音区并检查后来输入；运行位置：AIDV DoPlan 输入预处理、共享 Redis；收到：同 ChatID 四音区 query；输出：合并 query 或 breakChan 中断信号；关键数字：100 ms 轮询、首 token 前可中断；来源：`chapters/I/raw/planner-onepage.txt:25-29,43-47,297-299`；与卡片 13 的统一输入管理区别：旧分散实现。

## TECH-K001｜接入适配层

- 是什么：Planner 前的格式统一逻辑，不调模型、不判意图。
- 在哪里运行：AIDV 服务接入侧。
- 收到什么：各源原内容、来源身份。
- 输出什么：标准 Input 及固定优先级/合并属性。
- 关键数字：4 路业务输入；不另造 Input ID。
- 与部件卡片差额：卡片 13 只提名字，缺独立职责。
- 来源：`chapters/I/raw/input-tech.txt:L271-277,443-481,706-713`。

## TECH-K002｜输入位置 InputState

- 是什么：逐条输入的调度位置，与整个 Chat 状态不同。
- 在哪里运行：AIDV 管理，Redis runtime 中保存。
- 收到什么：新输入、准入动作、执行结束。
- 输出什么：RECEIVED/WAITING/PROCESSING/FINISHED 与结束原因。
- 关键数字：4 种位置；至少 7 类结束原因。
- 与部件卡片差额：卡片 13 未单列。
- 来源：`chapters/I/raw/input-tech.txt:L279-281,369-384,708`。

## TECH-K003｜云端对话运行状态 ChatRuntimeState

- 是什么：云端调度的运行态，不等于车机唤醒/强聆听状态机。
- 在哪里运行：AIDV + 共享 Redis。
- 收到什么：准入、首段展示文字、执行结束、播放终态。
- 输出什么：IDLE/PROCESSING/RESPONDING。
- 关键数字：3 状态；预跑时仍可 RESPONDING。
- 与部件卡片差额：区别卡片 9 的端侧主交互状态。
- 来源：`chapters/I/raw/input-tech.txt:L283-285,378-384,577-584`。

## TECH-K004｜准入规则

- 是什么：按状态、优先级、合并属性和能否重放做规则裁决。
- 在哪里运行：AIDV Input Manager，无模型。
- 收到什么：Input、runtime、可重放标记。
- 输出什么：立即执行/撤销/合并/排队/结束。
- 关键数字：3 状态 × P0/mergeable P1/isolated P1；P1 分歧见 C01。
- 与部件卡片差额：深化卡片 13，补矩阵。
- 来源：`chapters/I/raw/input-tech.txt:L291-297,408-432`。

## TECH-K005｜执行重放边界

- 是什么：工具一旦获准下发，旧输入禁止再以指令重跑。
- 在哪里运行：AIDV 原子许可及工具出口。
- 收到什么：执行身份、许可、tool_call_id、输入集。
- 输出什么：不可重放标记及已许可工具登记。
- 关键数字：新执行初始 true；工具放行前原子 false。
- 与部件卡片差额：卡片 13 未说明工具早于首字的边界。
- 来源：`chapters/I/raw/input-tech.txt:L303-309,391-397,534`。

## TECH-K006｜执行身份与双引用

- 是什么：全局唯一执行字符串，由有效候选和正式输出两个引用分别指向。
- 在哪里运行：服务端发号，Redis 原子登记，贯穿 Planner/TTS。
- 收到什么：来源幂等、新推理/续轮/恢复。
- 输出什么：DirectorExecutionID；同值 TaskRoundID。
- 关键数字：最多 1 候选 + 1 未撤销输出；两者可不同；只比相等。
- 与部件卡片差额：补卡片 13/16 身份规则。
- 来源：`chapters/I/raw/input-tech.txt:L388,531-535,588-646`。

## TECH-K007｜计算许可与输出许可

- 是什么：可提前算不代表可播、可下工具或可写已交付历史。
- 在哪里运行：AIDV runtime 原子许可。
- 收到什么：完整工具批次、有效候选、前序播放依赖。
- 输出什么：ComputePermit 与 OutputPermit、候选 RUNNING/READY 发布。
- 关键数字：同候选转发布不换 ID；预跑无新业务工具。
- 与部件卡片差额：深化卡片 13 的算发分开。
- 来源：`chapters/I/raw/input-tech.txt:L395,605-607,774-796,966-968`。

## TECH-K008｜等待队列

- 是什么：Chat 共享的唯一等待列表，输入内容仍在 runtime。
- 在哪里运行：Redis LIST + HASH。
- 收到什么：等待 Input 的 source_type:source_id。
- 输出什么：可合批一组或 isolated 独立一条。
- 关键数字：每 Chat 2 个主体 Key、1 条 LIST；无业务上限和 TTL。
- 与部件卡片差额：卡片 13 有概要但缺具体归属与清理。
- 来源：`chapters/I/raw/input-tech.txt:L727-757`。

## TECH-K009｜中断上下文

- 是什么：原输入、已播/未播与工具事实，帮助衔接且不是待执行指令。
- 在哪里运行：客户端报进度，AIDV 组装，Planner 使用。
- 收到什么：原执行身份、播放位置、旧回答及原输入。
- 输出什么：随新 Query 传的 last_talk_content 等上下文。
- 关键数字：不入队、不再次发旧工具；未知进度不能填 0。
- 与部件卡片差额：深化卡片 14/16，勿重复恢复入门。
- 来源：`chapters/I/raw/input-tech.txt:L323-325,526,684-720,968`。

## TECH-K010｜客户端播放事件与协调器

- 是什么：车上按真实渲染生命周期上报，由 PlaybackCoordinator 统一协调。
- 在哪里运行：车机播放器/上报器 → AIDV → Redis。
- 收到什么：音频中的不透明 TaskRoundID、真实消费进度及结束边界。
- 输出什么：STARTED/PROGRESS/FINISHED/ABORTED。
- 关键数字：4 事件；TaskRound 多 Provider 共用 ID；0 与缺失有别。
- 与部件卡片差额：深化卡片 14，补终态权威与持久重试。
- 来源：`chapters/I/raw/input-tech.txt:L883-960,1012-1052`。

## TECH-K011｜播放超时兜底

- 是什么：终态缺失时按剩余媒体时长动态限住阻塞。
- 在哪里运行：服务端，deadline 持久在 Redis。
- 收到什么：稳定总长、已播进度、最后进度时间、连接状态。
- 输出什么：软限未确认告警、硬限独立超时结束并解门。
- 关键数字：2 个期限；速率与宽限均未给具体数值。
- 与部件卡片差额：卡片 14 未包含软硬期限。
- 来源：`chapters/I/raw/input-tech.txt:L1053-1156`。

## TECH-K012｜客户端接管

- 是什么：本地已完成指定请求，通知云端终止相应输入与执行。
- 在哪里运行：客户端上报；AIDV 原子结束。
- 收到什么：原 request_id 与本地完成结果。
- 输出什么：目标 FINISHED、关联云执行失效、其他等待保留。
- 关键数字：仅匹配目标请求，重复通知幂等。
- 与部件卡片差额：卡片 8 仲裁已有业务入门，本处补云端调度协议。
- 来源：`chapters/I/raw/input-tech.txt:L331-333,509-513,556-558,754`。

## TECH-K013｜owner 租约与故障关闭

- 是什么：租约发现执行实例失联，恢复不能自动重放已有副作用。
- 在哪里运行：AIDV owner/恢复流程 + Redis。
- 收到什么：续租时间、runtime、可重放标记、播放事实。
- 输出什么：安全新执行或不可重放结束、告警与受控恢复。
- 关键数字：租约不是业务 TTL；无固定租期/重试次数。
- 与部件卡片差额：已有卡片未列。
- 来源：`chapters/I/raw/input-tech.txt:L530,755-756,804-817`。

## TECH-K014｜播放依赖与路由索引

- 是什么：显式关联下一候选在等哪段前序播放，索引只定位。
- 在哪里运行：AIDV + Redis；ID 由客户端原样回传。
- 收到什么：WaitForTaskRoundID、TaskRound 归属、候选许可。
- 输出什么：对合法前序终态解门并发布原候选。
- 关键数字：不使用 ID-1、最近一轮或数值先后。
- 与部件卡片差额：已有卡片未列。
- 来源：`chapters/I/raw/input-tech.txt:L605-607,792-808,964`。

## CHAT：input-async.json 补充概念（早期整理，待设计阶段取舍）

### CHAT-K003｜推荐关联身份（卡片 13 未细分）
- 是什么：把云端任务建议、通知下发和车端回流关联到同次触发的标识，职责不同于 Planner 执行身份。
- 在哪里运行：AIDV 与车端推荐回流链，Extour 托管分支。
- 收到什么：Extour trigger、goal_id、回流 vehicle_recommend_id 与当前账号。
- 输出什么：找到原建议与目标并送输入管理，或拒绝过期/错账号关联。
- 关键数字：该分支早期整理写缓存 10 分钟，同次重试复用幂等键、每次周期触发另起推荐；不等于输入队列过期时间。
- 来源：guide-rewrite-20261030/input-async.json，$.modules[3].nodes[8].detail。

### CHAT-K004｜误打断记录查询与 event 回流（卡片 14 仅有概述的旧链路）
- 是什么：最终拒识后按原请求找未播内容，再借 Frontier 和客户端推荐入口发起恢复判断的临时实现。
- 在哪里运行：客户端打断上报、AIDV 查询/组 event、Frontier 通知、客户端回流、Planner 判断。
- 收到什么：原 request_id、已播与未播内容、最终拒识结论。
- 输出什么：含恢复语义的 event/query，或原记录缺失而无法恢复；不是重新授权旧工具。
- 关键数字：早期整理未给缓存 TTL、查不到时等待时长或重试上限，不能移用其他链路 10 分钟或 1 分钟数字。
- 来源：guide-rewrite-20261030/input-support.json，$.pages[5].sections[5]、$.pages[5].flows[2]；早期临时方案，不能替代 input-tech 统一设计。

### PRD-K004｜DirectorExecutionVersion（历史执行序号；不得照搬为现行唯一身份）
- 是什么：同 Chat 启动一次 Director 就递增的 int64 号，旧设计用作失效拦截凭证；运行位置：云端 ChatRuntime 与各输出/工具出口，车机旧设想原样回传；收到：新执行、续轮、旧输出；输出：递增版本及允许/拒绝；关键数字：每启动加 1，同 Chat 一个当前版本；来源：`lecture-rewrite-20261029/source-补查-input-management.md:122-137,181-188,323-352`；差异：现行应使用全局唯一执行身份，避免状态过期重建或重启后序号复用。
### PRD-K005｜Owner lease（执行归属租约，历史补全候选）
- 是什么：实例定期续期的执行归属凭证，超期只触发恢复检查；运行位置：云端实例与 Redis Runtime；收到：owner 身份、续租/过期信号、重放资格；输出：核验后使旧执行失效并接管，未越工具边界才可能重放；关键数字：文件未给具体时长，不能拿业务 TTL 代替；来源：`lecture-rewrite-20261029/source-补查-input-management.md:248-250,328-329,389-390,415-424`。
