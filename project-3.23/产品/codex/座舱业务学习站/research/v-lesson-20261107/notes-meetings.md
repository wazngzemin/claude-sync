## 3. 让讲解更有深度的点（每主题 2–4 条）

### ASR 与热词
1. **上屏规则背后是“怕偷听”**：全时免唤醒时 ASR 不能流式上屏（M1 00:13:12），因为用户可能在和车里的人说话；唤醒后才流式上屏，给“我被听见了”的安全感。讲 ASR 时可以把“识别准不准”和“什么时候给人看识别结果”拆成两个产品问题。
2. **热词不是万能药**：“智驾→支架”加了热词也不行，根因要提给火山 ASR（M13 00:19:41）；POI 增强识别实测还不如普通识别（M13 00:20:27）。适合讲热词的边界：它只是提高某些词的先验概率，解决不了声学层面混淆。
3. **热词的数据从哪来**：热词用端状态里的导航目的地、在播歌曲生成，但单独存表、走老链路（M32）。讲“热词是动态的，随车上正在发生的事变化”。
4. **识别快慢本身就是时延成本**：ASR 二遍约 800ms（M7），所以才有“流式四合一”。

### 判停（VAD）
1. **固定 600ms 的代价**：上汽只有固定 600ms 的 VAD（M13），口条不顺的用户话说一半被切，还觉得“豆包冷暴力”。这是讲 Soft/Hard VAD 和语义 VAD 的最好开场 case。
2. **VAD 和拒识会“叠加犯错”**：一句话被切成三段，三段都被拒（M10、M13）。嘉锋和左晨的分歧很有讲头：只召回最后一段，DT 也读不懂；要三段都进上下文才算真解决。
3. **端侧能力决定能不能做语义 VAD**：赛力斯把语义判断放端侧，上汽端侧能力有限只能靠云端（M13 00:07:23）。同一个功能在不同车上落地方式不同，原因在硬件。
4. **3～4 秒的停顿谁来判**：左晨认为语义 VAD 也解决不了（M13 00:09:16），这是讲产品取舍的好例子：“等用户说完”和“快速响应”天然冲突。

### 预请求
1. **pre-VAD 一个字段干三件事**（M11 00:46:11）：抢跑预请求、延长 VAD、提前 ASR 二遍。三件事的评测维度不同，所以要分开建测试集。适合讲“一个信号多处复用，验收标准要分开”。
2. **和四合一是互斥的并行方案**（M11 00:45:10–00:45:32）：pre-VAD 有了，就替代了流式拒识那条路。讲“为什么团队同时推两个方案”：在不确定时并行下注，再用数据选。
3. **截至 10/27 还没有数据**，正在定评测集。所以“预请求命中率 12%”这类数字，讲课时要标注来源和口径，不能当作会上结论。

### 拒识与打断
1. **“只采信云端”是一次降级决策**（M1 00:14:20 + 00:11:30）：赛力斯端侧有拒识，但因为 9 月模型准召问题，链路只采信云端，代价是状态机要等云端。可以讲“为什么不把快的那个用起来”。
2. **过拒和过召是两个方向**（M13 00:14:36）：过召多是没上下文的人人单轮（“你吃饭了吗”），过拒多是上下文相关但模型没读懂。打招呼后的回话被拒（M13 00:15:10）是“主动服务和拒识没打通上下文”的真实问题。
3. **“豆包太垃圾了”该不该接**（M6）：一方认为是过召，张航认为换成人被点名也会接。拒识没有标准答案，本质是产品定义问题。
4. **拒识的归属在变**：从独立模型，到要接人数模块（M18），到“DT 后面要承担拒识”（M30）。讲拒识时可以给出这条演进线，提示学员它不是一个固定模块。
5. **打断的“体感”细节**：现在打断直接把音量降到 0（M19），要不要淡出、切在字的中间还是字的边界，是很具体的 PM 决策题。

### 端侧小模型与端云仲裁
1. **完整决策链（可做时间轴）**：8/25 定位 1.7B 身兼离线 FC + 流式拒识（M4）→ 9/1 确定仲裁优先级与 3 秒超时（M3）→ 9/8 预告可能从离线优先改成在线优先（M5）→ 9/15 本地链路测试通过率约 42%（M8）→ 9 月改成兜底（M1 回顾）→ 10/12 日志显示大部分采纳在线（M12）→ 10/19 本地 LM 扩到 140 个 FC（M17）→ 10/20 网络专项想在弱网时提前采纳本地（M19）→ 10/21 新增 30B 需求（M10）→ 11/4 赛力斯想用端侧 VLM 替代 1.7B 做离线（M21）。
2. **“兜底”不等于“只在断网用”**：9/1 的优先级里，本地高频缓存和白名单 FC 排在云端 planner 前面（M3 01:51:22）。讲课时要区分“本地非白名单 FC 只做兜底”和“本地白名单/缓存优先”。
3. **离线要不要让用户知道**（M3 01:49–01:51）：嘉锋 vs 徐洋/雪晴/韩杰，双方理由都很典型：一方怕能力降级用户不知情，另一方坚持别打扰、靠状态栏就够。
4. **硬件和组织约束**：AI Box 灌装要拆车（M16）、纯离线不支持 4 音区同时说话（M2）、离线 ASR 想换供应商就要挪模块（M2）。端侧方案不只是模型问题。

### 记忆
1. **摘要会把“已删除”的事实带回来**（M14）：途经点删了，摘要里还在，豆包用半小时前的信息回答。这是讲“为什么要做摘要、摘要又带来什么风险”的最好 case；之后 9/15 又发现摘要有隐私问题要内审（M8）。
2. **5 轮的硬限制**：DT 只带 5 轮（M31），feedback 干预只在 5 轮内有效（M28）。讲为什么需要摘要来“接住”5 轮之外到短期记忆之间的空白。
3. **人人对话为什么迟迟不上**：技术前提（离线 ASR，M7）、隐私（M7、M3）、合规体验（M3 吴仁杰）、用法没想好（M3）四重原因，所以只在赛力斯实验、上汽不放。
4. **上报的时效性悖论**（M32）：断网要补报，但补报晚了，可能让不该触发的条件任务被触发。

### 豆包记忆与车机记忆打通
1. **“以谁为准”的争论**（M23 00:09:55–00:10:32）：端侧同学认为以地图为准、直接读端状态；云端同学认为语音和车机两条路必然不一致，要做同步。很适合讲“单一事实源”问题。
2. **一个改动引出连锁 bug**：为了让模型不犯错，SP 改成“都走记忆工具”（M23 00:11:55）→ 记忆开关一关就设不了家（M24）→ 系统地图只能按序号选点（M24）→ 选号又被多轮继承带回记忆工具，形成死循环（M24）→ 临时在 feedback 里加干预话术。这条链很能说明 Planner 工具路由、上下文继承、端侧接口约束是怎么纠缠在一起的。
3. **车主/主驾判断**（M26）：只有车主（判断不了就看主驾）说“我家”才同步，防止“记一下我朋友家”把车机的家改掉。
4. **AIVA→豆包同步仍未定**（M25）：倾向单独维护，因为冲突校验逻辑难以直接融合。

### AI Launcher
1. **skill 是“模拟 query”**（M7）：点一下 skill，就等于替用户说一句话，所以带出了“预设 query 要不要上屏”的需求（M18）。
2. **做减法**（M8）：workshop 后砍功能，后排 launcher 的 AI 推荐直接拒了（M3）。可以讲 PM 如何控制范围。

### 端到端时延
1. **口径之争**：3.91s（VAD 结束→TTS 首帧，M10）、2.83/3.01s（sec dev / 生产，M11）、加 VAD 约 3.6s（M11）、“端到端 3 秒”目标（M16）。讲时延一定要先讲清“从哪一刻量到哪一刻”。
2. **速度 vs 质量的真实取舍**：能力边界功能因为影响速度先不上（M11 00:10:20）；DT 去掉 talk 字段换约 200ms（M10、M11）。
3. **上限判断**：不改架构，极限约 3.2～3.3 秒（M11）。这解释了为什么要做四合一、pre-VAD、增量推理，以及为什么赛力斯一直要离线（等 4～5 秒压力大）。
4. **外部依赖也算时延**：高德 agent 首 token 4.6s、全链路 12.3s（M27）；智驾播报绕 planner 会晚 3 秒（M26）。
