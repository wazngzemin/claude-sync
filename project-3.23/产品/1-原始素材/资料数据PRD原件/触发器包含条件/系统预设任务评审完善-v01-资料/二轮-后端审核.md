## P1-01 时序图在“启用失败、条件未通过、卡片展示失败”后仍画出后续动作

- 位置：第 5.1 节，约 452–470 行。
- 原句：`TC-->>U: 已开启或失败；运行同步异常另行提示` 后无分支继续向 Trigger 提供许可并发业务事件；`T->>T: 核对任务、条件、时效、去重、频控` 后无分支直接交事件；`C-->>B: 受理、排队、实际展示或失败` 后仍直接进入用户回答。
- 问题：正文已正确规定“失败不继续”，但可执行顺序图将互斥结果合并在同一箭头里，研发按图讲解时仍会追问失败如何停止。特别是“展示或失败”属于不同状态，不应在同一步之后都等待回答。
- 替换建议：该图保留主流程，不必增加巨量节点；开头改为 `TC-->>U: 许可已保存；运行同步状态另记`，紧接注释 `Note over S,T: 以下仅在保存成功、运行方取得有效许可时继续；失败停在启用阶段`；Trigger 判断后改成 `T->>B: 仅条件通过时交付一次事件及配置版本` 并注释不通过仍等待；卡片段分为 `C-->>B: 请求已受理／排队` 与 `C-->>B: 卡片真正展示`，注明“展示失败、过时或撤回时结束本次；后续回答仅属于展示成功分支”。如需要精确 Mermaid，用 `alt` 包住展示成功与失败即可，优先保障这一处。
- 验证：图上的每条继续箭头都必须有肯定进入条件，不再把“成功或失败”合并后无条件向前。

## P1-02 Trigger 事件待承接没有终止和恢复口径

- 位置：第 5.4 节“事件待承接”；第 5.2 节 Trigger→任务业务；第 5.5 节超时重试。
- 原句：`事件待承接 | 承接业务接收且非重复 | 任务业务 | 进一步判断或跳过到交互策略`。
- 问题：只写已接收后的推进。若接入业务不可用、事件交付超时、已收到但 ACK 丢失，目前不知道谁保留待交付、多久放弃、下一次停车会不会把旧事件重发。现有“失败重试”主要描述模型与车控，无法代替这一阶段。
- 替换建议：将该行补成“承接业务确认接收→后续处理；明确拒绝→结束并记原因；等待超时→按事件有效期和有限重送策略处理，超出有效期则结束，不补发过时事件”。在 5.5 新增一行：`事件交付 | 业务不可用或接收回执丢失 | Trigger及业务接入链路对交付状态负责；重送沿用同一次事件关联。业务已接收时返回既有状态，不重新识别或拉卡。交付时限、重送次数与负责人由接口专项确认；不得无限待承接。`
- 待确认：具体哪一个消息组件实现重送、时限和次数继续技术专项确定，不另造服务。
- 验收新增：业务已接收事件但 ACK 丢失，Trigger 重送后找回同一次处理；业务持续不可用直到场景失效，恢复后不发过时充电询问。

## P1-03 “Planner 入口只处理语音”与兼容模拟 Query 路线冲突

- 位置：第 4.12 节约 427 行，影响第 3.2／5.1 图所对应的配置路线。
- 原句：`如果专项决定用模拟Query兼容，须选择该单一路线、注册目标和上下文，并验证不会直回同时执行。Planner入口仍只处理已展示卡片的有效语音……`
- 问题：第一句允许点击模拟 Query 进入 Planner，第二句又排除所有非语音。读者会误以为点击兼容路线不可能接入，或把点击伪装成用户语音。
- 替换建议：`Planner仅在本任务已经接入且当前询问有效时处理与该卡关联的输入；主方案输入为泛化语音。若专项选定点击模拟Query兼容路线，该Query须标明来自按钮、携带同一询问关联，且不得同时直回业务执行。不因平台选择了Planner就自动具备接入。`
- 验证：全稿都保持“Planner 不拉卡”，同时允许明确标记的非默认兼容输入；不把模拟 Query 当真语音。

## P1-04 充电平台案例漏配运行中实际检查的主动服务总开关

- 位置：第 6.3.2 配置步骤 3／业务摘要；第 6.3.3 步骤 2、3；第 6.3.1 许可行。
- 原句：配置步骤 3 只列 `SOC ≤ 20%`、`口盖关闭`；运行步骤 2 则 `本例总开关开启`、步骤 3 `所需开关有效`。
- 问题：案例已明确采用“两个开关都开启”的演示前提，但平台操作没有说明主动服务开关在哪里选择、是否统一自动门禁，图与运行不能全部映射回填写项。
- 替换建议：配置步骤 3 补一句“本演示按两个开关均开启的假设，在静态条件中加入 AI 主动服务总开关开启；正式会签若定义为统一门禁，平台改为只读展示该门禁来源，禁止重复或相反配置。最终两种方式择一，见 D08。”业务摘要加入“按会签后的主动服务许可关系”，而非把它写为已确定必选条件。
- 验证：运行检查到的总开关能够在配置摘要找到来源；P04 类 OR 用例也不能绕过会签定义的统一许可。
