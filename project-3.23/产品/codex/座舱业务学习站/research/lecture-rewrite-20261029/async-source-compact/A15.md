### 场景失效
触发器回调给任务系统后，任务系统根据任务的执行结果决定是否删除场景，失效or删除场景的接口任务系统已对接过，复用即可
### 频次控制【场景维度】
当前场景执行最小间隔默认30s，场景创建方可重置任意间隔\(单位秒\)，如果在执行间隔内出现了并发推理，处理策略如下：
- 上一轮推理结果首Token正在输出：缓存最新一轮的推理请求，待“判断结果”完全输出后启动下一轮推理
- 上一轮推理结果首Token未出：取消上一次推理，直接进行第二次推理，**被取消轮次推理的vlm识别结果不参与下一轮**
```SQL
请求1  ──[开始]──────● 正在推理(未出首Token) ─ ─ ─ ─ ─ ✕ 被取消
│
请求2  ───────────────● 到达，检测到首Token未出
│
├──→ 标记cancel_requested=true
├──→ 请求1检测到取消，退出推理
└──→ 请求2启动，使用请求2自己的VLM识别结果
```
```SQL
请求1  ──[开始]───[首Token]═══════════[“判断结果”输出完毕]
│                               │
请求2  ──────────● 到达，首Token已出               │
│                               │
└→ 缓存pending=请求2             └→ 启动请求2推理
使用请求2自己的VLM识别结果
```
打断模型推理代码可以参考：[keepCheckShouldBreak](https://code.byted.org/stone_vehicle/aidv/blob/f61ba3cbcdecbab35b29843a4fecea98a17918d9/biz/service/planner/planner.go?ref_type=commits#L81:1-82:1)
#### 20260831评审结果
- 不做模型打断，并发请求时并发推理，推理判定目标达成时标识场景已达成，等待TaskService删除场景
- 需要记录场景目标已达成，每次请求模型进行推理前判断是否已达成，如果达成则不需要请求模型和执行动作，打印日志并返回空即可
- 根据请求参数中的时间戳拒绝3min\(根据联调结果再更改\)前的上报触发
