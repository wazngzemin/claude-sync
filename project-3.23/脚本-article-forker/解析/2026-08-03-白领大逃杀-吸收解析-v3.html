白领大逃杀，比预期的来得更迟

这一版学习黄钊评注文章的手法：不复述、不套用，把文章的论证链一层层剥开。每一层都做三件事：还原原文观点、拆解它的隐含假设、给出我的独立判断（同意什么、反对什么、补什么）。最后把所有争议点摆成一张对账表。文章是纯银的，解读是我的，你来做裁判。

01

先把文章的论证链画出来，再一层层拆

黄钊解读文章的第一步，永远是先把文章的骨架抽出来：结论是什么、用什么支撑、佐证在哪。这篇文章的骨架如下：

02

拆支柱一：「SOP 失灵」论，一半深刻，一半可疑

先拆黑话：SOP 和 harness 到底是什么意思

这句话是全文最难懂的一句，拆成三个词逐个讲：

SOP（标准作业流程）= 普通人干活的方式。一件事做熟了，沉淀成一套固定步骤，以后照着走就行，不用每次重新想。妈妈的拿手菜就是 SOP：红烧肉做了三十年，糖几勺、酱油几圈、火候多大全在肌肉里，做的时候大脑是放空的。

harness = 纯银自己的定义：「任务在 Agent 内的运行规则」。翻译成人话：你给 AI 写的一份「这活怎么干」的说明书，包括用什么工具、按什么步骤、输出什么格式、什么算合格。

为什么每个任务都要单独写：AI 没有「上次学过的体感」。你教它做红烧肉，要写清楚放多少糖、什么酱油、什么锅、煤气还是电磁炉、几个人吃。你以为它换个锅会自己变通，它不会。同一个 AI，每个新任务都是零基础新人，所以每个任务都要单独写一份说明书。

为什么环境一变就改：说明书是写死的文字，不会应变。你说「结尾加祝好」，这个月项目结束、收件人变了，说明书不知道，照旧加祝好，你发现它蠢，回去改说明书，改完再试，这就是「调试」。

用你自己的产品翻译一遍：你的 69 条参考示例，就是把 harness 往 SOP 化的方向压的尝试，常见情况写成标准答案让模型直接命中。但新场景来了示例不管用，要写新示例调 SP，这就是「每个任务单独设计」；上汽把上报格式定成米/秒/hh:mm，之前按别的格式写的规则全部要跟着改，这就是「环境一变就改」；97 条示例被批「死记硬背」推翻重写，那就是一次大调试。

原文观点

普通人把技能沉淀成 SOP 无限复用，Agent 时代没有 SOP，每个任务要单独设计调试 harness，环境一变就改。古法与 Agent 模式，差不多是缓存命中与全新输入+推理的差异。节约脑力是普通人的生物本能，大多数人不具备编辑规则的能力和心力。Agent 工程师的供给以五年十年为时间单位。

拆解一：「缓存命中 vs 全新推理」是全文最好的比喻

这个比喻的妙处在于它同时讲清了两边的成本和收益。SOP 是缓存：命中成本近乎为零，但代价是规则会过期，环境一变，旧 SOP 还在按旧规则跑，照样出事。Agent 模式是每次全新推理：成本持续存在，但永远不过期。所以两边各有代价：SOP 省脑但僵化，Agent 烧脑但永不过期。这是交换，没有免费午餐。纯银把缓存这半边的好处和代价都讲了，但只说了一半，他的结论偏向了「烧脑是负担」，忽略了「僵化是更大的负担」，市场早晚会有一批人因为旧 SOP 纷纷过期而被逼转向 Agent，供给曲线未必像他说的那么平缓。

拆解二：隐含假设值得挑出来

整根支柱建立在一个隐含假设上：Agent 时代，每个人都得变成自己的 harness 工程师。但文章自己在第二节就给出了另一个模型：公司可以「招聘数量更少的 Agent 工程师，由他们来设计和迭代规则，其他人运行规则」。这个中间态说明：并不需要所有人都烧脑，只需要少数人烧脑、多数人运行。大厂里已经有这种分工的雏形（写 SP 的人、维护示例的人、做评测的人）。一旦这个中间态成立，「没有 SOP」的问题就变成了「少数人的供给」问题，规模一下小了两个数量级。纯银把「每个人都要烧脑」当必要条件，这是支柱一最大的可疑点。

拆解三：还有一个他没提的变量，可能绕开整个支柱

他在 2025 年判断供给问题会卡 5-10 年，但他的模型里没有「模型自己会写 harness」这一项。如果模型进步到能自己调试自己的 prompt、自己生成并迭代规则（各家都在往这个方向做），「Agent 工程师供给不足」这个瓶颈可能被技术直接绕过，人只要当验收员。这个变量一旦成立，他的时间判断就要大幅提前。当然，小扎那句「四个月没加速」是反方向的证据，两股力量谁赢，决定了大逃杀到底是 5 年还是 10 年。

我的观点

支柱一方向正确，但被他自己的中间态模型稀释了一半：真正稀缺的不是「会烧脑的大众」，是「能设计 harness 的少数人」，而这类人市场已经开始供给（写 SP 的、维护示例的、做评测的，都是在干这个）。瓶颈真实存在，但没有他说的那么长。后面两节会看到，真正卡住大逃杀的其实不是这一根，是组织那一根。

03

拆支柱二：鸡生蛋死循环，这可能是全文最硬的一根

原文观点

公司不推行 Agent 模式，工作环境就培养不出 Agent 工程师；没有起码数量的 Agent 工程师，公司就没法切换。外招的 AI 信仰者不懂业务，懂 AI 不懂业务驾驶不了 Agent；内部培养的隐藏 bug 是大幅提效必然大幅裁员，谁上谁工贼。

拆解一：这个死循环是真的，而且有历史先例

这不是新现象。工业革命时期的织布机、上世纪的自动化恐慌，都出现过同款结构：技术提效 → 裁员的预期 → 第一批配合者被同事视为叛徒 → 没人愿意先动 → 技术普及被推迟。历史上每一次打破循环，靠的都是外部变量，要么是政策，要么是战争，要么是新市场突然出现把蛋糕做大（提效的增量需求反过来吸纳了被替代的人）。纯银把循环画得很完整，但没有讨论任何打破循环的外部变量，这是他这根支柱的空白，也是文章整体偏悲观的原因之一。

拆解二：「谁上谁工贼」有个他没说的变体

他假设改革者的代价是「同事不配合 + 自己可能被裁」。但现实里还有一个更常见的变体：改革者把提效包装成「增量项目」而不是「存量替代」，不说「我们效率提升可以少招三个人」，说「我们效率提升可以多做三个项目」。同样的提效，包装成裁员就是工贼，包装成扩编就是功臣。这个变体在现实里大量存在（AI 项目本身要人：写 SP 的、做评测的、做数据集的），它不能完全解开工贼死结，但能把死结松一半。纯银的模型里没有这个变量，所以他把话说绝了：99.9% 的公司下不了决心。

拆解三：他把「公司决策」当成了纯理性计算，忽略了决策者个人

他的成本收益模型（收益=裁员省钱，成本=切换风险+社会风险）是理性人的模型。但真实世界里公司切不切换，往往取决于有没有一个「狂热老板」（他自己也承认这是第一种能切的公司）。他把狂热老板当例外，其实在互联网公司里，创始人崇拜型组织占比不低，这类组织的决策就是一个人拍的，理性模型对它们不适用。所以「99.9% 公司切不动」这个数字，是理性模型的产物，真实比例可能比他估计的高，也可能低，但一定不是纯理性分布。

我的观点

这根支柱最硬：组织惯性是真的，工贼困境是真的，外部招聘失灵也是真的。但他在三个地方放了三个空白：打破循环的外部变量、增量包装的变体、狂热老板的真实占比。把这三个空白填进去，死循环不是无解，是被推迟。这也解释了为什么他说「5-10 年」而不是「永远」：循环松动是时间问题，不是结构问题。

04

拆支柱三：「只有两种公司切得动」，这里藏着一个定义问题

原文观点

只有两种公司会切 Agent 模式：第一种，老板狂热拥抱前沿技术宁担风险；第二种，AI native 新项目，没有历史包袱，全员 AI 信仰者，大家真正担心的，是项目挂了全体失业。两种规模都很小，起不到示范效应。

拆解一：「AI native」到底指什么，文章没定义清楚

「AI native」在文章里是「没有历史包袱 + 全员信徒」的近义词，这太宽松了。按这个定义，任何 2024 年后成立的 AI 应用公司都算 AI native。但现实中大量自称 AI native 的公司，只是「用 AI 包装的普通公司」：团队没做过 AI 产品、业务链路还是老一套、只是把 AI 当 API 接进来。真正的 AI native 应该定义为「业务模式建立在 AI 的能力边界上」：AI 不行这业务就不成立，而不是 AI 只是其中一个功能。用这个定义筛，纯银说的「第二种公司」比他想的小得多，但纯度也高得多。这个定义对识别公司很有用。

拆解二：裁员收益论忽略了一个基本经济学效应

他的收益模型只有一侧：提效 3 倍 → 裁员 2/3 → 省钱。但价格弹性的效应他没算：如果 Agent 让产品的边际成本降一个数量级，同样的预算能服务 10 倍的用户，市场规模会扩大，公司可能不裁员反而扩编。软件行业历史上每轮提效（编译优化、云、低代码）都既裁员又扩张，两个方向同时发生。他把收益只算成「省人力」，漏掉了「增市场」这一半，所以他的结论必然偏向悲观。

拆解三：示范效应他说没有，但资本市场会给示范定价

他说两种公司规模小、无示范效应。但 AI native 公司的估值是资本给的，资本会为「Agent 化程度高」支付溢价，这个溢价本身就是示范：它会催生大量模仿者（哪怕模仿者只学了皮毛）。示范效应不止存在于业务层面，还存在于资本层面。他在创业圈里，应该见过不少这种「资本催生范式模仿」的案例。

我的观点

这根支柱方向对，但三个地方都被他收窄了：AI native 的定义收窄成「新公司」、收益模型收窄成「省钱」、示范效应收窄成「业务」。把这三个口子放开，能切的公司比他说的多，但切得动和切得好的差距，比他说的大。这可能才是他真正想说的：能切的公司不多，能切好的更少，中间隔着十年。

05

拆支柱四：「局部提效 ≠ 整体爆兵」，全文最清醒的一段

原文观点

AI 信仰者自己的任务提效 5X 10X，但没权限、不懂业务改不动别人的环节，每一个改不动的协作环节都是绊脚石。个别信仰者什么都推动不了、证明不了，只能匹配自己闭环完成的那一点点。他引用犬校同学：「大公司里最适合上车 AI 的方向，其实是内部工具，而不是任何一个业务部门。」

拆解一：这是全文方法论上最扎实的一段

前几根支柱都有可挑的地方，这根没有。它说的机制在工程上很常见：水桶效应 + 权限边界 + 信息不对称三者叠加，任何局部优化都会在边界处衰减。更关键的是他给出了唯一的例外：「内部工具」，为什么内部工具能上车？因为内部工具的使用者就是开发者自己（懂 AI 的少数人），需求明确、迭代快、不依赖跨部门协作链、出了问题自己就是用户。这其实是一个可推广的判断：凡是「使用者自己就是工程师」的工具领域，都会先被 Agent 化。这个判断可以往前推一步：不只内部工具，任何「专业用户即开发者」的领域（数据分析、运维、量化、设计系统）都会先行。

拆解二：他点破了信仰者的真实处境，但解法只有半句

「什么都推动不了、证明不了，只能匹配自己闭环完成的那一点点」，这句话里藏着文章最有价值的一个洞察：在组织没准备好之前，信仰者的最优策略就是「守住闭环，把闭环做到极致」，然后等组织变或换组织。但他只给了诊断没给策略（除了内部工具这一条），读者容易读成「认命」。

我的观点

这根支柱我完全同意，而且认为它比前面三根都重要：前面三根讲的是「为什么慢」，这根讲的是「个人在慢时代怎么活」。慢时代里，个人能掌控的只有自己的闭环。把闭环做深，等风来或找风去，这就是全文给 Agent 工程师留下的唯一一条个人路径。

06

补拆原文第三节：抄作业、许愿机、和那个 1+2+3 公式

原文第三节里有三个独立观点，前面没拆到，逐个补上。

第一块：「喜欢抄作业的人，抄不到作业了」

原文：Agent 时代没有 SOP，喜欢抄作业的人是抄不到作业的。AI 是千人千面的需求满足，每个人、甚至每个任务，都要定制满足需求的方式。

拆解：这句话真正的意思是「经验没法低成本转让了」。以前的行业，新人抄老手的 SOP 就能上手，老手带新人成本很低。现在老手手里是 harness，harness 绑死在他自己的任务环境上：他的工具、他的数据、他的判断标准。你抄过去，环境不一样，直接跑不动。这就是为什么「培训」和「老带新」在 Agent 时代失灵，也是为什么公司没法批量复制 Agent 工程师，供给瓶颈的根子在这。对你也有一句提醒：这就是你第三件事（盘点规则能不能交付）的意义。你的 57 条示例如果只在你脑子里能跑，那就是抄不了的作业；写到「别人拿去就能跑」，才算把经验从 harness 变回了 SOP。

第二块：「AI 不是许愿机」

原文：即便 Agent 已经大幅度提升了生产力，每个任务适合还是不适合用 Agent 来跑？适合的任务怎样才能跑到更高的效率与质量？古法怎样与 Agent 融合成流畅的工作流？这些都需要长时间的探索。

拆解：这句是给「AI 万能论」泼的冷水。许愿机的意思是：你许愿，它实现，你不用管怎么实现。纯银说现实里根本不成立，因为「选任务」本身就是专业能力：什么任务该给 AI、什么任务别给、给了怎么跑好，这三问比「会不会用 AI」更难。这比 Agent 驾驶技术更稀缺，可以叫它任务判断力。用你自己的产品验证：你们的三层漏斗就是任务判断力的制度化。句法 RAG 接明确指令、情景 RAG 分流、Planner 接复杂任务，整个架构的第一道工序就是判断「什么任务走哪条路」。你 6.12 排查会的分诊法（这个问题归不归 Planner 管）也是同一回事。所以任务判断力你早就在练了，只是没给它起过名字。

第三块：那个 1+2+3 公式，和「挤水分」

原文：理想化的进展是：「1、大量思维活跃并且拥抱 AI 的员工」「2、适合跑在 Agent 上的大量任务」「3、公司提供 1+2 的友好环境」= Agent 协作模式 = 整体效率 3X 向上 = 裁员 2/3。而「最近三年你能看到的裁员，那仅仅是挤出多年积蓄的饱满的水分」。

拆解：公式之外还有那句「挤水分」，这是全文对普通读者最重要的一句安抚：最近三年的裁员，裁的是前些年扩张期多招的人，账上早该挤的水分，跟 AI 效率倒逼没关系。看懂这句，就不会把每次裁员新闻都当成「大逃杀开始了」的证据。媒体每次裁员都挂 AI 的名头，纯银这句话等于把媒体的叙事拆穿了：裁员是真，但因果是假的。

07

补拆第五节：犬校回帖里的「外部性收益」，是全文最该展开的概念

原文的两条发言

犬校同学：每次用公司内部 AI 工具遇到问题，都把完整 session 导出来给 Codex 复盘，只为把 Skill 大锤磨得又快又亮；高频客诉任务 2 个月迭代 200 多个版本，以此为乐。但同事都不在意，他们觉得 AI 出错了骂它、让它记住就好了。他因此发现：「我的内心住着一个提效狂魔，是 AI 激活了他。」

纯银回帖：日常观察到两种人。一种学会一件事就希望无限复用，让他不断学新东西很烦恼；一种愿意把事情做得更好，但必须看到明显的收益。而打磨 harness 往往没有明显的（外部性的）收益，只是自我追求。对任务停留在「能用就行」的人，大概率不会成为 Agent 高手，只是普通的 Agent 操作员。卡点就在这：不能提前证明显著收益，公司就下不了手。

拆解一：「外部性收益」这个词，值得用一整段讲

这是全文唯一一个经济学术语，也是最该展开的一个。收益分两种：内部的，自己感知得到（系统变强了、我用着爽了、我手艺涨了）；外部的，别人感知得到（公司多赚钱了、同事少加班了、老板报表好看了）。职场的定价逻辑只看外部性：你的工资，等于你创造的、能被他人感知的价值。打磨 harness 的问题在于，它的收益几乎全在内部：你把 SP 的 ACC 提了 9 个点，模型变聪明了，你自己知道，但同事的 KPI 没变、老板的报表没变，外人眼里什么都没发生。所以 Agent 高手会被系统性低估：干的活最硬，账面上最看不见。这不是你一个人的委屈，是所有提效狂魔的共同处境。

拆解二：纯银的两种人，其实是三种

纯银分了两种：SOP 型（学会就不想再学）和收益型（没收益就不打磨）。其实还有第三种，就是犬校同学那种：追求型，打磨本身就是乐趣，不需要外部奖励。前两种人是大多数，第三种人稀少。残酷的地方在于：Agent 时代对前两种人都不友好，对第三种人是天堂。更残酷的是：第三种人的回报模式是「延迟的外部化」，手艺先攒着，等环境变了（跳槽、公司转型、行业爆发）一次性兑现。犬校同学的 200 个版本，就是延迟兑现的存款。

拆解三：「能用就行」是一条生死线，也是一个可操作的判据

纯银这句话给出了一个判断「谁是 Agent 高手」的实操标准：看一个人对「能用就行」之后还追不追求。操作员和高手干的是同一个活，差别只在验收标准：操作员的验收是「跑通了」，高手的验收是「还能更好」。这个判据可以用来识人，也可以用来自检。对照你：57 条示例被推翻后全部重写、SP 从 3.3 万往 1.6 万压、每天一篇文章按七段拆，你早过了这条线，而且过线很远。你的问题从来不在「是不是高手」，在前面拆解说的：高手的收益是内部的，你还没把它外部化。

拆解四：这一节其实藏着全文的个人出路

把第五节和前面的公司分析合起来，出路就两条，都在文里：第一条，把内部收益外部化，收益账、提效日志、别人能用的规则、离不开的工具，全是把「自我追求」翻译成「别人看得见」；第二条，去外部性定价更准的地方，AI native 公司里人人都懂 harness 的价值，你的打磨在那里不需要翻译就被认账。这就是第 08 节六件事的底层逻辑：前三件做外部化，后三件找出路。

拆那个 5-10 年：他给自己留了后门，也漏了两个变量

原文观点

「我认为白领大逃杀全面到来，最低最低还需要 5-10 年。推迟到十年以后我也不会太惊奇。」佐证是小扎 7 月内部讲话：「过去四个月，AI Agent 的发展速度并没有像我们预期的那样加速。」

拆解一：这个判断的安全边际很宽，但他知道

「最低最低 5-10 年，十年以后也不惊奇」，这个区间大到没有证伪可能。这与其说是预测，不如说是立场声明：他不是在赌时间点，是在反对「大逃杀马上来」的恐慌叙事。用他的话说，最近三年看到的裁员「仅仅是挤出多年积蓄的饱满的水分，而不是 AI 改变世界」。这个立场的市场价值在于：当所有人都恐慌时，冷静者能便宜地捡到被错杀的资产。

拆解二：他漏的第一个变量，是模型自我改进

他的模型里，Agent 工程师的供给是纯人的问题（5-10 年）。但如果模型能自己写 harness、自己迭代自己的规则，供给瓶颈就被技术绕过了。各家大厂都在做这个方向，小扎那两句「没加速」指的是组织收益没到，不是模型能力没涨。这两个事实指向不同的结论：模型能力在涨，组织吸收能力没跟上，那么时间表由组织决定，5-10 年可能成立；但如果组织吸收能力本身被模型化（AI 帮助 AI 落地），时间表会塌缩。

拆解三：他漏的第二个变量，是政策与劳动力市场

文章讨论公司决策时用的是纯商业模型，但白领大逃杀是劳动力市场事件，政策迟早介入（再培训、补贴、税收调节）。2024-2025 年各国对 AI 的立法速度在加快，政策会推迟大逃杀的钟点，也可能把它拉平。这个变量纯银完全没提。

我的观点

5-10 年是他基于「纯人的供给 + 纯理性的公司 + 纯商业的决策」这三个假设推出来的。三个假设里有一个松动（模型自我改进），时间表就可能塌缩；有一个松动（政策），时间表就可能拉长。所以他的结论我给一半：方向上大逃杀确实比 2025 年的预期慢，但「5-10 年」这个数字的置信度，没有他写的那么高。
