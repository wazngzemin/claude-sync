# 【影视剧搭子】技术方案

# 背景

复用豆包现有的视频通话\&amp;屏幕共享能力实现陪用户聊影视剧内容的功能，且能够通过语音开启屏幕共享功能。

# 概要设计

## 系统交互

- 开启/关闭影视剧搭子功能复用车控Agent链路，由Frontier下发FC车控协议，端侧执行后上报执行结果，云端通过RTC链路下发nlg文案与tts播报。

- 闲聊互动部分复用豆包现有【屏幕共享】功能实现，回复文本由VLM模型生成，TTS由Speech服务通过文本生成，不是v3版本的s2s效果。

- 本期不考虑视频资源下发的功能，通过手动打开各种影视类app播放资源。

## 豆包侧视频交互流程

- 音频上行、ASR过程使用主链路已有的能力。

- 客户端开启视频通话后，每秒会上传6张图片，stream服务每3张图片会传输一张图片给模型。

- 本期先使用豆包的sp体验流程，后续端状态上报后，可以把播放信息补充给到座舱sp中，flow\.agent\.vlm\_real服务通过座舱云获取动态的sp。

# 风险

1. 在手机端测试，开启豆包屏幕共享后打开视频app播放资源，有两种限制的情况（限制逻辑by资源决定）：

    1. 一些资源会提示版权问题，不支持录屏。

    2. 端侧上报的图片帧是全黑的，豆包回复看不到内容。
