四个重点场景，拆开看

① 多群洞察日报 ⚙️ 配置即开

痛点：一睁眼十几个群全是红点。你不是想补完聊天，只是怕错过昨天最有价值的那一句。
机制每天 8:30 自动跑一次（定时管线已存在）
→
范围只看你圈定的群：Bug 攻坚组、体验问题讨论、路测群
→
输出物一份早报：昨天值得看的 3-5 条 + 谁提了什么问题 + 有没有@你的
→
动作你花三分钟看完，再决定点不点进去
现状：定时器和群消息读取都有，SUMMARY_CHAT_IDS 目前是空的——配上群 ID 和日报模板就开播。

② Bug 分诊助手 ✅ 已能用

痛点：路测群甩来一串 bug 清单，每条都要判断归谁、能不能解、走哪条路——纯体力活。
输入把 bug 清单合并转发给它（合并转发读取已修好）
→
动作逐条展开，按你的六大类 A-F 分诊框架归类
→
输出物每条 bug：归类 + 建议归属方 + 排查路径建议
→
边界定级和派单你拍板，它只把证据摆齐
提示：Meego 单据内容它没有接口，涉及单据详情时把文字贴给它。

③ 跨群人物追踪 ✅ 已能用

痛点：评审前想知道"汪帅这周在各个群里对触发器到底表过什么态"，翻聊天记录翻到怀疑人生。
输入"帮我汇总 XX 这周关于 XX 的发言"
→
动作跨群搜索这个人的消息，按时间排
→
输出物表态时间线：哪天、哪个群、说了什么、立场变化
→
边界只摆原话和出处，不给人贴标签
现状：消息搜索通道已实测打通，直接问就行。

④ 吐槽→需求信号日报 ⚙️ 配置即开

痛点：用户在群里抱怨的一个小细节、反复追问的一句话，可能就是最真实的需求信号——但它沉在 500 条消息里。
机制每天定时扫体验问题群/路测群
→
动作把抱怨和追问按主题聚类，标出反复出现的
→
输出物需求线索清单：主题 + 出现次数 + 原话摘录
→
边界它不替你拍板做产品，只让你少靠拍脑袋
现状：读和聚合能力都有，配上定时和聚合模板即开。

要排期开发

写入类（群聊资产化、汇入知识库）需要给应用补文档写权限；监控类（停滞预警、更新提醒）需要加"变化检测"订阅机制。

它可以替你翻、替你整理、替你写第一版；判断、沟通和对外动作，始终在你手里。
