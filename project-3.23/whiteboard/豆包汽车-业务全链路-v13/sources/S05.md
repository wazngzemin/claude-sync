# 动态加载型工具\-技术方案

# 需求简介

需求来源于即时交互卡片场景需要可见即可说的泛化能力。在用户与车机的交互过程中，系统的部分模块（主动服务、外部系统通知等）会拉起即时交互卡片，用户可以通过点击按钮或语音交互的方式来进行二轮交互。语音交互一般依赖端侧可见即可说的能力，但可见即可说只能支持白名单内的文本，没有泛化的能力，因此需要云端来理解用户的query，并定位到卡片中具体的按钮。

动态加载型工具仅在特定场景下出现，因此 DT 也应只在相应场景触发时才感知到对应工具的存在，从而避免普通语音交互对 DT 工具选择造成干扰。系统需抽象出一套通用的工具动态加载机制，以支持不同业务场景下工具的按需注册与动态注入，同时保证场景判定逻辑与工具定义本身解耦 —— 新增工具无需改动 DT 核心调度流程，只需声明其触发场景与生效条件即可接入。

# AgentServer能力

AgentServer需要区分**静态**、**动态**两种类型工具，且支持动态工具的场景判定、工具信息的动态加载。

## 场景判定

动态加载机制的落地依赖一套通用的条件判定引擎。该引擎需要解决三个核心问题：

1. 条件的统一表达，即不同业务场景下的工具生效条件能否用一套通用的声明式结构来描述；

2. 上下文的按需获取，判定所需字段可能来自请求参数、端状态、Context等不同来源，引擎需要具备统一的字段取值能力；

3. 判定的高效执行，在每次 DT 推理前，引擎需快速完成对所有工具条件的批量评估，确保不增加主链路延迟。

### 引擎设计

```JSON
{
        "logic_type": "", // and/or，多组条件时判定且/或逻辑关系
        "conditions": [
            {
                "field_source": "", // 字段来源
                "field_name": "", // 字段名称
                "field_type": "", // 字段类型
                "judgement": "", // 判定方式
                "values": ["",""] // 值列表
            }
        ]
    }
}
```

引擎采用 \&\#34;逻辑组合 \+ 原子条件\&\#34; 的两层结构。`logic\_type` 定义多组原子条件之间的逻辑关系（且/或），`conditions` 数组中的每一项为一个原子条件，由 `field\_source`、`field\_name`、`field\_type、judgement`、`values`五个要素构成。

- `field\_source`：字段来源，引擎根据 `field\_source` 从对应数据源中读取 `field\_name` 指定的字段值。本期只支持`param`。

- `field\_name`：具体的字段名称。

- `field\_type`：字段类型，主要用于判定时的类型转换。

- `judgement`：判定方式，本期支持：`exist\(xx \!= nil\)`，`not\_exist\(xx == nil\)`，`in\(xx in \[\&\#34;a\&\#34;, \&\#34;b\&\#34;\]\)`，`not\_in\(xx not in \[\&\#34;a\&\#34;, \&\#34;b\&\#34;\]\)`。

- `values`：期望的值列表，字符串类型

### 代码设计

抽象出condition模块，负责条件解析、数据获取、规则计算，对外暴露一个判定方法`Judge`，返回判定结果：`true`、`false`，调用模块无需关注具体的规则内容，计算逻辑，只根据结果做后续的业务处理即可。

逻辑判定使用开源项目https://github\.com/expr\-lang/expr。

```Go
type ConditionEngine struct {
    LogicType string
    Conditions []struct{
        FieldSource string
        FieldName string
        FieldType string
        Judgement string
        Values []string
    }
}

func (c *ConditionEngine) Judge(ctx context.Context) bool {
    // 1. 根据FieldSource获取对应数据
    // 2. 根据FieldType转换Values的类型
    // 3. 构造expr表达式
    // 4. 调用expr-lang工具判定逻辑
    
    // 示例
    env := map[string]interface{}{
        "paramA": params.paramA,
    }
    code := `paramA != nil`

    program, err := expr.Compile(code, expr.Env(env))
    if err != nil {
        return false
    }

    output, err := expr.Run(program, env)
    if err != nil {
        return false
    }

    return output
}
```

**后续规划**

条件判定引擎与现有Trigger服务在能力上存在重叠，Trigger服务侧已沉淀端状态信号的解析与判定逻辑。后续若需支持端状态类型的条件，应复用Trigger服务的已有能力，由Trigger服务统一提供端状态条件的判定服务，避免重复建设。AIDV服务可通过`field\_source`字段来选择不同的判定器Adapter。by@张弛@刘杨

### AgentServer应用

每个工具的属性信息都存储在agent\_meta字段中，新增动态加载条件字段。

```JSON
{
    // 已有属性
    "director_invisible": false, // 是否参与dt推理
    "need_user_permission_check": true, // 是否需要用户权限校验
    ...
    // 新增属性
    // 动态加载条件
    "dynamic_condition": {
        "logic_type": "", // and/or，多组条件时判定且/或逻辑关系
        "conditions": [
            {
                "field_source": "", // 字段来源
                "field_type": "", // 字段类型
                "field_name": "", // 字段名称
                "judgement": "", // 判定方式
                "values": [] // 值列表
            }
        ]
    }
}
```

**示例**

在即时交互卡片场景，动态加载的条件为：

```JSON
{    
     "dynamic_condition": {
        "logic_type": "and",
        "conditions": [
            {
                "field_source": "param", // 字段属于参数

                "judgement": "exist", // 当参数中的real_time_card存在时，该工具生效
                "values": []
            }
        ]
    }   
}
```

# 主交互流程

即时交互卡片工具需具备对卡片内容、页面元素及按钮语义的感知能力，一方面用于构造准确的工具描述信息供 DT 推理使用，另一方面用于解析用户语义并匹配至对应卡片按钮，最终通知客户端执行点击操作。

## 卡片信息

本期卡片信息通过参数`real\_time\_card`的方式进行传递，结构如下：

```Go
{
    "title": "", // 卡片标题
    "content": "", // 卡片内容
    "button":["",""], // 按钮名称
    "reason": "" // 卡片触发原因，帮助DT理解上下文
}
```

卡片信息拼接方式如下：

```Go
1.卡片内容
（1）标题：{{title}}
（2）正文：{{content}}
（3）按钮名称：{{button}}
2.卡片触发原因：{{reason}}
```

当出现即时交互卡片时，在query上行请求中的`vehicle\_biz\_params\.ext`中增加`real\_time\_card`参数。

            "real_time_card":{
                "content": "", 
                "button": ["",""]
            }
        }
    }
}
