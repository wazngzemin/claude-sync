## 语气模板

“我们先看一个具体场景。豆包还在播报，副驾开始说话了。这里先别急着说‘应该打断’，要先确认他是在对豆包提需求，还是在跟主驾聊天。前一种需要让新需求进来，后一种如果直接停播，用户就会觉得豆包莫名其妙断了。接下来这一步叫流式拒识，它用当前已经识别出来的文字先做判断。我们在图上把‘判断是不是对车说’和‘端侧真的停播’分开，这样出了问题才知道查哪一段。”

这个模板是按逐字稿方法重写的课堂稿，不是冒充会议原话。保留自然的“我们先看”“这里要区分”“举个例子”“为什么要这样”，删除口语填充、重复、转录错字。英文仍保留在中文术语后的括号，不能照搬会议里的 shorthand 让新人自己猜。

## 已核到的新业务证据，需反馈总图

1. 10/20 00:02:46：当时上下文只在 query 完成时同步，断网/失败没有重新请求。会议提出网络恢复后再同步；南京南站→北进站口是验证场景。应归为“当时现状 + 新需求”，不能写成已完成。
2. 10/19 00:14:20：当时赛力斯对话展示采信云端最终拒识结果，端侧也有拒识但仍等待云端。这能补充“界面最终结果由谁驱动”，不能据此直接消解流式拒识部署矛盾。
3. 10/19 00:15:30、00:58:18：合并描述用“前一个首 token 尚未输出”作时点；与旧多人 PRD“工具下发前”不是完全同一个边界。总图保留版本/模块口径，避免混写。
4. 10/19 00:28:30：主动服务优先级低于用户 query；主动服务即使不要求二次交互，也需拉起对话，避免用户想接话接不上。属于当时主交互讲解口径。
5. 10/19 01:00:56–01:01:26：会上明确长时任务主线仍在做、未准出，不承诺对客；因此会中长时任务的完整理想交互不能当现状。
6. 10/20 00:49:28–00:59:59：按车内有无人做车内外互斥仍在讨论，优先继续向供应商确认可否区分唤醒来源。不能把该互斥直接写成定案。
