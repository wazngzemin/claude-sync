## 1. 背景与需求

### 1.1 为什么要改

系统预设任务需要把业务需求配置为可运行规则。儿童锁需要组合车辆条件、后排儿童或宠物判断、目标锁状态；充电口盖需要先筛出适用停车场景，再交给下游检查设备。平铺条件难以表达这些关系，配置人员也难以判断究竟哪个输入开始检查、哪一步需要模型、为何没有发出建议。

10 月 14 日新增豆包闪念需求。业务希望在感知到乘客睡着或特定车外景象时，在中控屏显示一句静默文字，一期采用固定文案。会议明确了两处开发缺口，预配置场景还未接通视觉描述的监听与判断，Trigger 也尚未接入普通通知下发。动态任务链路已能收到视觉描述，不能据此认定后台预配置规则也能直接使用。

本次在实际平台的场景管理、新建场景和触发记录中增量改造。简单配置继续保留，复杂判断使用 Workflow；两种模式共用范围、动作和策略。命中后按动作分流，询问任务走带卡建议，闪念一期走普通静默通知。

### 1.2 产品定义

四类配置决定场景如何运行，说明**用于哪些车辆、何时开始检查、怎样判断、命中后交给谁、多久允许再次发送**。运行记录由系统生成，解释每次实际发生了什么。

| 部分 | 配置人员需要说清楚 | 平台保存或展示什么 |
| --- | --- | --- |
| 基础与范围 | 这是什么场景，在哪些渠道和车辆使用 | 名称、分类、来源、环境、车型、版本、车辆和泳道 |
| 判断 | 什么更新启动检查，还要满足什么 | 简单条件，或条件／推理节点组成的判断图；对应输入依赖 |
| 动作 | 满足后发送一句通知，还是提出需要确认的建议 | 对应出口及其必需参数 |
| 策略 | 怎样限制重复发送 | 现有次数、最小间隔及其统计口径 |
| 系统生成的记录 | 这次为什么开始，停在哪一步 | 当次定义、输入、判断和实际取得的动作结果；无需人工填写 |

Workflow 是有依赖关系的判断步骤。条件节点比较已有值，推理节点用模型判断已有文字描述是否符合目标。DT 承接下游建议和工具调用；VQA 负责按需获取新的视觉判断。**Trigger 的判断画布不放 VQA、出卡、用户确认或车控节点。**

## 2. 目标与价值

配置人员能够复用既有场景，按页面顺序完成条件、动作和策略，不需要为每个任务另找一条专用配置链路。研发能按明确的输入与输出接入，测试能用同一份场景定义构造正向、不满足和未知案例。

| 要解决的问题 | 本次做法 | 完成标准 |
| --- | --- | --- |
| 复杂条件说不清 | 保留简单模式，新增条件与推理的 Workflow | 儿童／宠物分支关系能够准确保存、回显和运行 |
| 页面可填，真实输入却未接通 | 读取能力目录，展示输入来源、依赖及缺口 | 缺能力的分支不能被标成可正式发布 |
| 不同输出混在一起 | 分开普通通知与主动推荐带卡 | 闪念不进入 DT 或确认；询问任务保持既有确认链路 |
| 不知道失败在哪 | 分开判断、策略、发送和实际回传结果 | 能定位条件未满足、无法判断、策略拦截或下游失败 |

收益以场景能否正确表达、配置错误能否被拦截、联调能否定位问题衡量。配置耗时可在实际使用前后记录，本稿不预设节省比例。

## 3. 本期范围与边界

### 3.1 保留原四项需求

| 原需求 | 本期要求 |
| --- | --- |
| 静态条件非必填 | 存在合法启动和判断语义时允许为空；启动与判断全空仍阻止保存 |
| 场景复制 | 生成独立场景；不复制运行记录、计数、发布状态和单车用户选择 |
| 指定泳道生效 | 运行环境真正受范围限制；空值含义须与运行侧统一 |
| 测试／正式筛选 | 展示实际环境，支持组合筛选；改显示标签不改变部署范围 |

### 3.2 新增内容

| 工作包 | 在哪里做 | 本次交付 |
| --- | --- | --- |
| 场景管理 | 原场景列表 | 模式、分类和范围展示，筛选、复制、只读提示、记录入口 |
| 判断配置 | 原新建场景页面 | 简单配置与 Workflow、元数据级联、输入依赖、结构校验 |
| 视觉输入接入 | Trigger 的预配置规则运行入口 | 匹配指定视觉信号更新，取得本次已有描述，复用目标判断能力 |
| 动作配置 | 原动作区 | 带卡建议信息；新增普通通知的固定正文 |
| 通知下发 | Trigger 动作出口与客户端承接 | 经 Frontier 下发普通通知，复用客户端容器和仲裁 |
| 保存与记录 | 原保存入口、触发记录 | 错误定位、保存摘要、阶段反馈、当次定义及节点结果 |

闪念一期固定的是输出文案。输入为自然语言视觉描述时，仍可能需要模型判断是否达成条件。二期动态生成文字和后续语义匹配、小模型降耗不纳入一期。

### 3.3 不在本期建设什么

不新增端云统一配置、端侧脚本热更新、完整原子能力管理平台或 DT 工具编排画布。天气保护端侧闭环和本地开关保存不在本稿重建。PHUD 图案映射与闪念同属业务整体需求，但当前接入路径未收口，不能把两端同步展示写成已支持。

发布、权限和停用沿现有平台机制。正式草稿、版本替换或回退若无现成能力，需单独评估；本地原型中的草稿和删除恢复不等同于后台正式能力。

### 4.1 平台架构与职责

| 模块 | 本次负责什么 | 交付给下一环什么 |
| --- | --- | --- |
| 配置后台 | 引导填写，展示可选能力，校验和回显 | 完整场景定义及范围 |
| 配置服务 | 校验定义，保存并关联场景，提供查询 | 可查的场景与判断定义；真实保存结果 |
| 端状态／Context | 提供已接入状态和已有视觉描述 | 信号标识、对象、值或文字，及可取得的有效性信息 |
| 开关与单车状态服务 | 提供真实许可和本车任务状态 | 实际值；查询失败须单独表示 |

Context 已收到视觉描述、Trigger 能监听这个更新、后台能配置这个输入，是三个接入环节。闪念需要逐项联通，不能只在页面新增一个视觉下拉框就算完成。

### 4.4 启动检查与条件满足怎样区分

| 配置情况 | 哪个更新启动检查 | 开始后判断什么 |
| --- | --- | --- |
| 简单规则有动态条件 | 动态条件涉及的信号 | 全部动态和附加当前条件 |
| 简单规则无动态条件 | 当前条件涉及的全部信号 | 完整当前条件 |
| 已有描述推理 | 配置指定的视觉输入更新 | 本次描述是否达成目标，及已配置前置 |
| 多分支 Workflow | 全图汇总与唤醒规则待运行侧收口 | 按依赖执行节点，不重复旧判断 |

挡位从非 P 变为 P 是变化事件；当前挡位为 P 是状态条件。车辆一直上报 P 不能被当作不断停车。儿童锁如果只由进入 D 启动，那么进入 D 后才识别到儿童是否补提醒，需要业务明确，不能由后台偷偷扩大启动范围。

输入依赖清单说明这条规则用到了什么。正式启动清单还要说明哪些更新会真正唤醒检查，二者在页面分开标注。输入更新频率、模型调用控制和动作最小间隔也分开，动作频控不能证明上游模型消耗已经降低。

### 4.5 Workflow 怎样得到结果

节点判断使用三态，PASS 表示满足，REJECT 表示明确不满足，UNKNOWN 表示无法判断。缺输入、调用异常、解析失败或超时归入 UNKNOWN，不改成“没有儿童”或“没有下雨”。

| 前驱汇合 | 前驱结果 | 后继节点处理 |
| --- | --- | --- |
| 全部满足 AND | 全部 PASS | 开始判断自身内容 |
| 全部满足 AND | 任一 REJECT | 不运行，按不满足阻断 |
| 全部满足 AND | 前驱全结束，无 REJECT，有 UNKNOWN | 不运行，按无法判断阻断 |
| 任一满足 OR | 任一 PASS | 可开始判断自身内容 |
| 任一满足 OR | 前驱全结束，无 PASS，有 UNKNOWN | 不运行，按无法判断阻断 |
| 任一满足 OR | 全部 REJECT | 不运行，按不满足阻断 |

OR 放行只允许后继开始自己的判断，不取消其他分支。按技术设计，整图等待全部节点终态，再取唯一终点有效结果并进入动作策略。终点满足且另一分支未知，不按节点多数投票改写结果。超时后的迟到返回不得覆盖终态。

运行状态另列等待、运行中、已完成、异常、未运行。SKIPPED 表示受到上游阻断而没运行；它没有自身执行结果，界面展示阻断原因，整图采用继承的阻断结果 REJECT 或 UNKNOWN。

## 5. 原型页面与交互要求

### 5.1 页面怎样搭建

沿实际平台保留左侧菜单、顶部渠道和原有表单。主要页面仍是场景管理、场景配置和触发记录。Workflow 放在场景配置的判断区域，闪念放在共用动作区域，不另建一套独立后台。

场景配置采用五步页内导航，基础与范围 → 判断配置 → 动作 → 执行策略 → 校验与保存。简单和 Workflow 共用外层字段，只替换判断区。已有 Workflow 在同一区域只读查看；需要修改时复制。运行详情从触发记录打开，不在编辑页用最新定义解释历史。

| 页面区域 | 正式页面依赖 | 页面负责的交互 |
| --- | --- | --- |
| 基础／范围 | 场景查询、渠道和适用范围数据 | 填写、回显、切换保护、摘要核对 |
| 简单条件 | 信号元数据及合法值域 | 级联选择、组内关系、参数校验 |
| Workflow | 定义注册／查询、图结构校验 | 节点属性、依赖连线、布局与错误定位 |
| 动作 | 当前渠道的动作目录和真实参数协议 | 按动作显示参数，生成请求预览 |
| 策略 | 现有执行策略及统计语义 | 填次数／间隔，解释范围和单位 |
| 触发记录 | 本次运行、节点、输入及动作记录 | 查询、当次快照、原因和结果分层 |

正式搭建按上述数据接入，不从 HTML 的演示数组生成线上能力。表单上级选择变化时清理不兼容下级值；修改配置后清除旧试跑结果。界面需要区分加载中、无数据、读取失败和实际为空，错误重试保留用户输入。

v08 采用单文件 HTML 和本地存储维护演示草稿、独立场景、判断图与人工记录。正式后台须接服务端保存、权限和发布结果，不能把本地缓存当正式状态。正式草稿和断点恢复是否纳入一期在第 8 章确认。

### 5.2 场景列表

保留渠道、名称／ID、状态、来源、类型和测试／正式筛选，补上配置模式与普通／预设分类。范围通过弹窗查看车型、版本和指定车辆。多个筛选共同生效，刷新／分页保留条件；查询失败保留筛选并允许重试。

| 容易混淆的字段 | 准确定义 |
| --- | --- |
| 来源 source | 通过哪个注册入口创建，由系统提供 |
| 分类 scene_category | 普通或系统预设；后台创建默认普通 |
| 类型 scene_type | 条件、推理、定时或混合的真实能力类型 |
| 简单／Workflow | 如何组织判断，独立于类型和动作 |
| 测试／正式 tag | 实际部署环境标记 |
| 泳道 | 控制隔离运行的范围，不能只改标签 |
| 列表生效状态 | 后台规则是否生效，区别于某车某任务开关 |

新建先选择模式，取消不创建半成品。复制生成独立配置，需重新核对名称、范围和目标渠道能力。原型清空指定演示车辆并默认不启用；正式复制的范围保留和初始发布状态需沿现有机制确定。

| 渠道／车型／版本／车辆／泳道 | 使用实际平台支持的范围格式 | 版本比较方式与版本号成对填写；读取失败不当不限范围 |
| 动态条件 | 配合法变化及相关信号 | 缺旧值无法判断变化时不能当事件已发生 |
| 当前条件 | 类别 → 信号 → 字段 → 比较方式 → 值 | 未选上级禁用下级；改信号清空旧字段、比较方式和值 |
| 数值／枚举 | 数值显示单位，枚举选择合法选项 | 包含可多选；非法值、单位或运算符定位本项 |
| 视觉目标判断 | 选择已有描述来源，写明判断目标 | 不提供“睡着标签已存在”这样的虚假布尔选项 |
| 输入与启动说明 | 随判断配置更新依赖 | 未确认的 Workflow 启动汇总不能标成已生效 |

舱内结构化位置与年龄必须属于同一个乘客对象。年龄使用婴儿、儿童等规范枚举，不能把原始年龄描述当数值阈值。其他自然语言描述按已设计推理入口使用；正式视觉目录未接通时显示缺口，不能用演示字典覆盖真实菜单的“暂无数据”。

### 5.4 Workflow 画布

![P2 Workflow 画布与节点属性](/Users/bytedance/Desktop/3.23/产品/1-原始素材/资料数据PRD原件/触发器包含条件/实际平台原型-v08/02-Workflow-画布与节点属性.png)

图中展示同一判断区域的画布及节点属性入口。展开画布时属性可能位于画布下方；操作讲解按选节点、改属性、接连线、校验顺序进行。

| 操作 | 页面行为与产品规则 |
| --- | --- |
| 加节点 | 只开放条件、推理两种；节点名称可读，标识由系统维护 |
| 填条件 | 复用简单模式字段级联，并配置本节点内部全部／任一条件 |
| 填推理 | 选择已有输入，填写目标与业务判断描述；不让提示词补不存在的数据 |
| 接连线 | 指定起点和终点；防止自连、重复边、循环及无效端点 |
| 配前驱汇合 | 默认 AND；至少两个直接前驱才允许 OR；与节点内部条件关系分开命名 |
| 调整图 | 拖动、缩放、适应和展开；操作不改变业务判断含义 |
| 删除／撤销 | 删节点提示相关边影响；点边可删；删到一个前驱恢复 AND；图结构支持撤销／重做，节点文字及表单输入不承诺由图级撤销恢复 |
| 校验 | 一次展示全部问题，点击定位节点、边或属性；错误保留输入 |
| 查看旧定义 | 已保存 Workflow 判断只读；复制确认后编辑独立新定义 |

每个节点必须且只能包含一种合法判断；所有节点须能到达唯一真实判断终点。空白汇合框、孤立分支、多终点和缺内容节点禁止保存。连线表达判断依赖，不能据此声明支持“事件先发生，再持续若干秒”的时序能力。

简单和 Workflow 保留各自编辑内容，切模式取消保留原输入，不能宣称自动无损转换。切渠道先说明将清理哪些不兼容内容，取消保留；原型确认后清空判断，正式清理策略需评审。换动作同样提示旧参数影响，不隐藏旧参数后继续提交。

### 5.5 动作与执行策略

| 动作 | 配置人员填写 | 系统与下游负责 |
| --- | --- | --- |
| 普通静默通知 | 固定正文；只预览文字 | 按普通通知协议下发，客户端承接仲裁和展示；闪念一期无标题、按钮、TTS |
| 主动推荐带交互卡 | 建议信息，即固定建议 Query | 自动携带本期确认／取消参数；正文和 TTS 沿下游生成、展示 |
| 其他已有动作 | 当前目录声明的必需参数 | 保持原行为，本稿不扩写不存在的参数 |

带卡一期按飞书当前主稿只要求业务填写建议信息，确认／取消自动带上。`advisors_input` 传建议，`real_time_card` 承载带卡参数，页面可只读预览协议，配置人员不手写 JSON。v08 保留带卡参数的演示控件，正式页面应收敛为固定参数说明，按钮自定义和取消带卡不作为本期运营能力。

普通通知一期新增正文控件，通知动作的正式标识与参数沿姜锋提供的协议对齐，本稿不虚构接口字段。所有必需参数校验通过才能提交，带卡建议不能把未知设备写成已识别。

策略保留平台现有次数和最小间隔，显示单位及统计对象。30 秒为原型沿用的页面默认值，尚不能当作闪念正式策略。采样、模型调用控制、动作发送间隔和客户端排队分别处理，具体计数时点、失败计数、周期重置在第 8 章收口。

### 6.2 充电口盖

配置合法进入 P 的启动及任务许可、SOC、口盖状态。技术案例 SOC≤20%，正式阈值以任务需求确认值为准，SOC 代表电量百分比。前置关系简单时可用简单模式，使用 Workflow 也仅放前置判断。

判断通过后提交先检查周边设备、发现后询问开盖的建议。DT 调 VQA，设备未知或未发现不询问开盖；明确发现后沿既有出卡与确认链路继续。SOC 缺失不能当 0，盖已开、许可或任务关闭均不发送。询问期间车况变化由下游执行链路处理，不移回 Trigger 编排。

### 6.3 后视镜加热

采用已确认车况、真实加热状态和已有舱外天气描述。下雨描述由推理节点判断，无需新设备 VQA；通过后提交加热确认建议。无雨明确不满足，天气输入未知则无法判断，加热状态未取得不能当关闭。

技术案例的 P 挡与速度限制业务含义尚需澄清，加热状态来源尚需核对。退出传送带洗车无已确认信号；湿度和温差分支已在技术稿划除，本期不恢复。缺口未补齐的分支不进入正式发布验收。

### 6.4 闪念一期

配置一个已有视觉描述的判断目标，例如是否有乘客睡着；模型只判断达成与否，不要求输出标签。满足且策略允许时，下发业务配置的固定文字，客户端以普通通知静默展示。示例正文“有人睡着了，我会安静陪着”仅用于演示，最终文案由闪念业务确认。

| 步骤 | 谁做什么 | 接入需要核对 |
| --- | --- | --- |
| 获得输入 | VLM 产生描述，Context／上报链路提供给 Trigger | 具体舱内／舱外信号、更新入口和时效 |
| 判定目标 | Trigger 根据本次已有描述判断是否达成 | 预配置监听须新增接入，复用已有推理能力 |
| 检查策略 | Trigger 按已定义频控决定是否发送 | 持续满足是否重复、统计对象和计数时点 |
| 发送通知 | 通知动作通过 Frontier 下发固定正文 | 找姜锋取得协议，刘杨对齐云端下发 |
| 承接展示 | 谢一鸣对接客户端，先验证现有容器 | 无标题、按钮、TTS；能否满足样式和统一仲裁 |
| 记录结果 | 各环按真实支持返回结果 | 受理是否可查、是否回传展示／丢弃 |

会议指出当前卡片仲裁以覆盖为主，排队有后续规划。产品要求闪念低优先级、不打断正常交互，复用统一仲裁；上线前仍要确认本版本能做到哪种避让，不能把规划写成已有保障。

持续睡眠导致重复描述、正常交互占用容器、排队后乘客已醒都是必测反例。队列时效与过期处置尚需业务和卡片侧决定，Trigger 不自行实现第二套排队。PHUD 与通知是否共享触发来源、图案 ID 及同步方式另行对齐，不承诺同一时刻出现。

## 7. 核心异常与完成标准

### 7.1 不同层的成功分别验收

| 阶段 | 什么证据能证明 | 不能据此推断 |
| --- | --- | --- |
| 配置保存 | 正式服务成功返回，按标识回读一致 | 已发布或已运行 |
| 发布生效 | 目标环境实际采用正确规则，非目标不运行 | 已提出建议 |
| 判断完成 | 当次输入、节点与最终结果 | 策略已放行 |
| 动作发送 | 对应出口真实调用结果 | 客户端已收到 |
| 下游接收 | 下游真实受理证据 | 卡片已展示 |
| 展示与后续业务 | 展示、用户选择或车辆状态的真实反馈 | 缺回传时仍判成功 |

正式带卡动作 `simulator_supported=false`，必须真实环境联合联调。记录只展示实际可取得信息；没有客户端展示回传时标未取得反馈，并通过客户端日志补证。

### 7.2 核心验收清单

| 组别 | Case | 预期 |
| --- | --- | --- |
| 管理 | 分类、模式、来源、环境联合筛选和分页 | 含义独立，筛选保留，查询失败区别于零条 |
| 管理 | 指定泳道、车型与版本正反例 | 仅目标范围生效，标签筛选不改变范围 |
| 管理 | 复制已有 Workflow | 独立定义可编辑，原定义不改，不继承计数和用户状态 |
| 填写 | 改信号、渠道、模式或动作并取消 | 不兼容值不残留；取消保留原输入 |
| 填写 | 合法动态启动，静态为空；所有判断为空 | 前者允许，后者阻止；字段错误定位且不丢输入 |
| 结构 | 循环、自连、重复边、多个终点、孤立和空节点 | 一次提示全部问题，不生成可用定义 |
| 结构 | 删边仅剩一个前驱；撤销 | 恢复 AND；结构恢复不偷偷改变节点配置 |
| 运行 | 非启动输入更新；合法启动但附加条件不满足 | 按实际启动清单处理；开始后检查完整条件 |
| 运行 | 缺输入、模型超时、负向或不可解析响应 | UNKNOWN／REJECT 区分，负向文本不误 PASS |
| 运行 | AND 含 REJECT 或 UNKNOWN；OR 含一个 PASS | 按 4.5 放行／阻断；后继仍判断自己 |
| 运行 | OR 一分支慢、迟到回报、重复请求 | 整图按技术调度收敛；重复 Run 不等于重复发送 |
| 策略 | 终点 PASS 但频控拦截或锁未取得 | 无下游发送，不写成模型不满足 |
| 儿童 | 后排儿童／宠物正例，跨乘客拼接、目标锁 ON | 合法对象正确建议；跨对象和已开启不重复 |
| 充电 | 边界电量、SOC 缺失、设备无／未知、取消 | 阈值准确；缺失不当 0；不误询问或执行 |
| 后视镜 | 雨天／无雨／未知，状态缺失，洗车缺口 | 三态正确；缺输入分支不能发布 |
| 闪念 | 睡眠描述达成／未达成／未知 | 达成且策略允许才发固定文字，不生成动态正文 |
| 闪念 | 连续同类输入、正常交互占用、排队后失效 | 按最终频控和仲裁要求处理，不重复刷屏或展示过时文字 |
| 动作 | 普通通知与带卡建议分别检查参数和出口 | 普通通知无 DT、按钮、TTS；带卡保留确认链路 |
| 记录 | 历史定义修改前后、上游失败、未回传结果 | 使用当次快照，保留真实事件，不编造结果；原型重跑不沿用旧演示成功 |
| 状态 | 本车 OFF、读取失败、普通更新或新规则替换 | OFF 保持，读取失败不冒充默认 ON；替换规则须先定案 |

### 7.3 开关边界

后台发布、AI 总开关、某车某任务开关和本次确认分开处理。已有云端设计按车与场景保存单车状态，无记录默认开启；成功确认无记录与读取失败必须区分。更新失败不显示假关闭，普通更新不抹掉用户 OFF。

本稿只要求后台关联和使用真实状态，不替端侧任务指定保存人，也不将徐燃的 AI 设置当单任务状态存储。单次拒绝结束本次建议，不自动关闭长期任务。关闭时的在途展示与已下发动作，按接入业务明确策略，停止新触发不能代替撤卡成功。

## 8. 实施顺序与评审待定项

### 8.1 怎么推进

1. 先把本轮业务范围和真实输入对齐。闪念先补预配置视觉入口与普通通知出口，复用已有判断能力；不等待全部 Workflow 画布交付后才验证最短链路。
2. 用一条真实描述、一条固定通知跑通输入、判断、下发、客户端展示，再检查占用、重复和失效反例。客户端现有容器若满足要求不额外开发；不满足再明确适配项。
3. 并行完善原四项后台需求、简单表单和 Workflow 配置／记录。系统预设任务按各自输入接入情况验收，后视镜缺口分支留在阻塞清单。
4. 最后确认正式发布范围、替换与回退方式，并回读结果。10 月 14 日会上的 10 月 20 日目标与 10 月 26 日提测讨论只作为排期约束，当前优先级和承诺日期须由项目重新确认。

### 8.2 需要收口的具体决定
