# 座舱大模型概述

## 产品简介

<div class="callout">

座舱大模型助手是利用**大模型的推理\+对话能力**，对现有**车内语音助手的重构升级**，从而真正实现对**车内用户需求的理解与满足**。

- **需求理解：**在汽车座舱每一刻场景中，通过上下文对话和场景信号，并结合设定知识和功能定义，识别解读用户的需求是什么，

- **需求满足：**基于对需求的理解，判断合理的解决方式，并提供对话互动和功能调用执行，最终满足用户的需求。

</div>

大模型作为生成式语言模型，自身并不具备连接车内动作、感知环境和主动互动的能力，并且伴随着幻觉多和响应慢等问题。基于此，通过对多个模型组合运用，利用不同参数大模型的特性，让其互相分工明确，打造出成体系可量产的座舱助手。

通过突破这些大模型的局限之处，新一代座舱助手能够深度理解并满足用户需求。

## 联网搜索

### **业务场景介绍**

联网检索是一种整合了豆包大模型能力和联网搜索能力，在通用问答、新闻、知识百科、出行等各类业务场景中，通过图片、文字、语音等多种模态作为信息输入并以图片、音乐、视频等多种模态作为信息输出的端到端联网检索解决方案。

通常形态下，一个优质的联网检索解决方案应该具备海量优质实时内容源和多个垂类领域的专业内容源，除了能够根据问题秒级地呈现高时效性的热点搜索结果之外，还可以将结果整合于卡片、图表、下划线搜索等丰富多样的表现形式。

#### 联网问答智能体方案

##### 名词话术

- 唯一身份相关

    - AccountId：火山引擎主账号ID

    - BotId：智能体ID，火山引擎体系全局唯一，客户私有

    - UtmSource：渠道号，内容定制历史字段，通常访问自建内容时必传且和AccountId一一对应

- 智能体业务相关

    - 智能体/Agent/Bot：由「EPS\-智能内容产品\-内容套件」团队提供的智能问答类产品。

    - BotRuntime：每次请求执行是一个新的Runtime（类似session），集成会话等能力，贯穿于智能体在执行过程中的上下文。

    - Pipeline：业务编排流程（类似workflow），有明确的输入和输出，具体逻辑可由开发者实现。

##### 产品模式

1. 标准模式（lite/pro）：效果最强也最全面，可通过**控制台创建**。

2. 极速模式（一般是座舱）：**通过BotConfig配置开启，目前只能研发配置**，通过对改写搜索等环节做的参数降级来实现，需要兼顾效果，不存在完全追求性能而不顾效果的情况。

## 车控

**业务场景介绍：**

Function calling 是一种将大模型与外部工具和API相连的新功能（充当自然语言和大模型的翻译官），它允许开发者更可靠的从模型中获得结构化数据，无需用户输入复杂的Prompt。对于座舱场景中，可以用于座舱内用户对话的语义理解（**泛化能力**）。相比过去NLU的做法，FC的优势在于无需定义用户的说法，仅通过提示工程（Prompt Engineering，以下简称PE）的方式，让大模型快速理解用户表达。所以除了简单对话，FC可以实现非规则化、口语化表达的语义理解，这是过去NLU做法很难覆盖。

例如：乘客说“车里有点闷”，大模型意图识别**车控场景**，车控插件通过函数选择为**空调开关**后，提槽并下发**打开通风**的空调指令。
