# 事件生产与使用

## 事件的定义

当前的事件日志表

```SQL
CREATE TABLE `event_log` (
  `id` bigint unsigned NOT NULL COMMENT '主键ID',
  `channel` varchar(64) COLLATE utf8mb4_general_ci NOT NULL DEFAULT '' COMMENT '渠道标识',
  `channel_app_id` int NOT NULL DEFAULT '0' COMMENT '标识来源',
  `vehicle_id` varchar(256) COLLATE utf8mb4_general_ci NOT NULL DEFAULT '' COMMENT '车辆ID',
  `account_id` varchar(256) COLLATE utf8mb4_general_ci NOT NULL DEFAULT '' COMMENT '车企oem用户ID',
  `login_doubao_uid` bigint unsigned NOT NULL DEFAULT '0' COMMENT '登录的豆包uid',
  `user_in_car` json DEFAULT NULL COMMENT '车里有哪些人',
  `event_time` datetime(3) NOT NULL COMMENT '事件发生的毫秒时间',
  `event_info` text COLLATE utf8mb4_general_ci COMMENT '事件信息',
  `report_cycle_flag` varchar(256) COLLATE utf8mb4_general_ci NOT NULL DEFAULT '' COMMENT '原始数据上报周期标识',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `resource_id` varchar(64) COLLATE utf8mb4_general_ci NOT NULL DEFAULT '' COMMENT '资源ID',
  `resource_name` varchar(256) COLLATE utf8mb4_general_ci NOT NULL DEFAULT '' COMMENT '资源名称',
  `resource_info` text COLLATE utf8mb4_general_ci COMMENT '资源信息',
  ~~`source` varchar(64) COLLATE utf8mb4_general_ci NOT NULL DEFAULT '' COMMENT '数据来源：client、trigger、cloud',~~
  PRIMARY KEY (`id`),
  KEY `idx_channel_vehicle_id_event_time` (`channel`,`vehicle_id`,`event_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='NDB_SHARE_TABLE;事件日志表'
```

## 生产

1. 端状态满足触发器规则，生产事件日志数据，例如：用户上车事件；

    1. 见刘杨技术方案[【触发器支持生产事件日志\&amp;事件数据同步】服务端技术方案](https://bytedance.larkoffice.com/wiki/Aowjw935OiMyEcki7FFco33QnTh)

        1. 由产品事先定义好事件日志信号（后续有信号管理平台再考虑在配置触发器时生成事件定义），包括自然语音拼接规则；

        2. 触发器配置端状态生成事件时，查询事件服务获取事件定义列表，下拉选择需要生成的事件；

        3. 满足触发规则，触发器生成事件信息，拼接好格式化数据和自然语言描述，将数据传给事件服务；

2. 客户端事件生产上报，例如：用户操作同意喜玛拉雅隐私授权（信号id、定义跟端状态类似）；

    1. 上报方式同端状态，使用数据上报接口，需要产品提前定义事件信号；

    2. 云端按照产品定义的自然语言拼接规则生成事件的自然语言描述；

3. 云端事件生产，例如：人人对话、人车对话、用户打开记忆开关等；

    1. 需要产品提前定义事件信号，云端按信号定义拼接格式化数据和自然语言描述；

## 使用

1. 作为记忆的基础数据（事件服务提供查询接口，支持时间、事件类型、条数等参数）；

2. 将事件数据同步给其他关注的下游业务，按照订阅、通知的方式设计开发：

    1. 用户退登豆包时或者用户点击喜马拉雅的隐私授权，事件服务将该事件同步给弋途；

    2. “tts播报被拒识query打断且需要重播”事件，触发器发起event类型用户query（之前用临时方案支持了该需求：[事件\(event\)触发新一轮query技术方案](https://bytedance.larkoffice.com/wiki/A3jYw2EFtiJSSqkRpJocFPQGnRg)）；

3. “context关注的事件”白名单中的事件，作为context的一种数据源（事件服务提供查询接口，支持时间、事件类型、条数等参数），例如**10分钟内**（暂定）**最多30条**（暂定）的事件流倒序注入DT，如下：

```Markdown
# 事件流（倒序）
1. 9分28秒前，【不含事件发生事件的自然语言描述】
2. 8分00秒前，用户通过按键设置主驾空调为23度。
3. 6分17秒前，小明语音搜索并播放了周杰伦的简单爱。
.
.
.
30. 2秒前，小红在副驾睡着了。
```

4. “up关注的事件”白名单中的事件，作为up的一种数据穿插在user之间展示，如下（条数限制）：


## 内部其他业务

1. 提供查询接口，支持指定时间、事件范围和条数查询事件日志；

    1. 根据channel、channel\_app\_id、vehicle\_id、event\_start\_time、event\_end\_time和resource\_id数组查询日志日志数据，直接返回事件日志数据的model数据；

2. 提供事件上报接口，业务方可以自己上报事件日志数据；

    1. 同触发器调用事件日志生成的接口，可以指定的user\_in\_car，避免多查一次；

3. 业务方在事件日志服务代码中订阅事件，当发生某一事件时，事件日志服务回调注册的接口，将该事件信息作为参数；
