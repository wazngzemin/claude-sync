Planner 任务规划中枢（车载 Agent 大脑）｜产品负责人

背景：把“一句一应”的语音助手升级为能结合车况作判断、跨步骤办事并持续跟进的车载大脑。

  • 决策架构：针对一句话分类无法覆盖车况差异、补样本难以穷举，推动“感知—思考—执行”快慢架构；明确指令保时延，模糊需求结合车况推理，设计 A–D 四组实验比较理解、执行与端到端性能。
  • 任务与对话：定义单步复杂、多步、条件、持续 4 类任务，明确独立动作并行、依赖结果串行；针对任务中改口与打断，设计进度保留和失败重规划，并约束首轮承诺与执行反馈，避免说做不一致。
  • 质量准出：不只评回答，按缺失、冗余、错误操作检验任务质量，纳入车况约束、工具依赖与说做一致；制定推理准确率 ≥ 90%、首 token P90 ≤ 800ms 的版本目标。
  • 决策问题修复：分诊 138 条缺陷，发现工具漏调占 61%；将同类问题的判断方法写成可检索、可注入提示词的动态示例，累计提出 59 条，其中 30 条实车复测通过。
  • 决策经验治理：主导动态示例管理与项目隔离 PRD；选择“先过滤项目、共享内容一次维护”，避免通用示例串用与逐车型复制；配套查重、审核、灰度回滚，要求配置与实际注入共同验收。

舱驾融合司机 Agent 1.0 / 2.0（物理世界具身 Agent）｜产品负责人

背景：让用户像向司机交代行程一样表达需求，把“去哪里、停在哪里、何时执行”转成智驾可承接的任务。

  • 分车型产品规划：主导临停、泊车与抢车位规划，按地图、视觉和智驾能力拆分路径；对接上汽、赛力斯及智驾伙伴，划清座舱理解、任务衔接与智驾执行、安全兜底职责，输出分车型 PRD。
  • 行车视觉临停：围绕“停在拉行李箱的人旁边”，将推理耗时与车辆移动纳入设计；行车多目标就近选取，泊车歧义先确认，分别设计未找到、错过目标和无可用车位的反馈，保留智驾执行拒绝权。
  • 长程泊车：将“去公司，停到负二层充电车位”拆为导航、行车与到达后泊车；按有图、无图和车位信息缺失设计承接方案，明确途中改目标、接管后任务延续与不可执行反馈。
  • 持续车位任务：规划“盯住车位”的持续感知，将空位提醒与自动泊入分阶段设计；纳入电量、遮挡和法规约束，由智驾复核空位及安全条件，定义失败回传、继续监视和退出方案。
  • 数据与评测：设计 113 条用例，逐场景对齐意图、目标、动作与异常反馈；制定视觉语言模型（VLM）参照物采集规范，覆盖 22 个对象、110 条表达，供产品与智驾伙伴验证。

主动服务平台（Always-On + 触发器 + Advisor）｜产品负责人

背景：车应主动照顾天气、儿童与补能需求，但持续感知不应变成频繁打扰或未经确认的车控。

  • 主动服务架构：规划 Always-On 持续感知、触发器与 4 类 Advisor（场景顾问）及长程任务动态顾问；规则承接确定场景、顾问发现开放需求，复用交互执行能力；按弱网可靠性与信息需求划分端云职责。
  • 混合规则编排：旧平台平铺条件无法表达儿童或宠物分支；主导简单配置与 Workflow 可视化编排 PRD，分开车辆规则和视觉推理，设计建议卡与“不播报、不要求回应”的闪念出口，复用同一规则底座。
  • 触发可靠性：推动状态变化触发与频控，避免持续低电量反复提醒；识别信号到达先后带来的漏触风险，对齐 259 条车辆信号口径，并区分条件不满足与输入缺失、模型超时，明确排障要求。
  • 执行与结果闭环：指出用户确认期间挡位变化风险，推动执行前复核与执行后回读；设计触发命中、下游收到、卡片展示和车控结果的分层观测，避免用“触发成功”代替真实完成。

AI 汽车后台平台化与标准化｜产品负责人

背景：多车企后台工具分散，真实车况需手工注入、权限各自维护，产品整合与对外开放缺少统一方案。

  • 整合路线：牵头盘点模拟器、触发器、动态示例与日志回放，核对负责人、现状、客户开放范围及量产需求；据此梳理首批优先级，推动接入火山后台，规划日志直达对话回放的排障路径。
  • 统一授权：针对外部账号授权困难、敏感发布依赖硬编码，主导模块角色与发布工单 PRD；区分管理员直授与敏感操作审核，设计审批结论、真实执行回执及发布审计的关联，统一业务授权。
  • 上下文调试：规划通用提示词与车企定制内容分离，减少重复维护；设计模拟器车况、记忆与动态示例联动调试需求，让同一 Query 在不同条件下可复现，替代手工拼接上下文的调试方式。

多模态语音交互、长期记忆与量产交付｜负责人

背景：多人共用一个车载助手，需在及时接话、任务连续、个性化记忆和共乘隐私之间作出产品取舍。

  • 多人免唤醒：针对乘客通话被误响应、相反指令抢占，协调视觉通话识别与音区抑制；定义工具下发前合并有效输入、冲突先澄清，拒识插话不取消已有请求，形成多人交互方案。
  • 响应与打断：统筹 VAD 语音判停、端云单路采信与播报打断，允许提前理解但不抢跑执行；弱网保留基础车控，简单车控不打断播报；明确唤醒 ≤ 350ms、安静句准 ≥ 95% 的目标。
  • 情境记忆：针对冬夏偏好误用与共乘泄露，负责场景标签召回和记忆控制方案；敏感内容仅在当前在场人员共同经历过时使用，新人上车清敏感摘要，配套关闭冻结、语音删除及画像更新。
  • 量产问题治理：牵头上汽、赛力斯 数千条 badcase 分诊，先排链路、工具描述与车况/记忆缺失，再判断模型推理；按收益和时效拆分快修与中期治理，推动问题定责和实车复测。
  • 车企联调推进：主持赛力斯系统预设任务外审，推动明确触发判定到卡片、车控的承接责任；雨量与车速难以同时实测时，提出先以可控信号验证通用链路，再恢复真实条件，分开联调与业务验收。
