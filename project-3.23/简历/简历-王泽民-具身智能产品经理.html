Planner 任务规划中枢（车载 Agent 大脑）｜产品负责人

背景：面向“去昨天那家游泳馆”等跨步骤请求，负责车载 Agent 的理解、规划与执行反馈。

  • 架构与验证：推动"感知—思考—执行"快慢思考架构：明确指令走快路保时延，"我好热"这类模糊需求结合车况推理后再执行；设计 A–D 四组实验，以意图理解、执行效果和端到端时延作为上线判据。
  • 长程任务：规划单步复杂、多步串行、条件及持续四类任务，围绕“先查地址再导航”等场景，定义动作依赖、失败重规划与打断恢复方案。
  • 评测体系：制定说做一致、动作依赖与参数可执行性标准，明确版本目标：首 token P90 ≤ 800ms、推理准确率 ≥ 90%。
  • Badcase 闭环：分诊 138 条缺陷，识别工具漏调占 61%；沉淀 59 条动态决策示例，其中 30 条实车复测通过。
  • 数据治理平台：针对多车型示例串用风险，设计项目隔离与公共内容复用方案，配套审核、灰度和回滚机制，兼顾车型适配与统一维护。

多模态语音交互、长期记忆与量产交付｜负责人

背景：车内多人共用助手，既要及时接话，也要避免误响应和记忆越权。

  • 免唤醒与多人交互：针对乘客通话误响应、多人指令冲突，统筹多音区免唤醒与交互方案；制定唤醒响应 ≤ 350ms、安静环境句准 ≥ 95%的验收目标。
  • 响应与打断：统筹语音判停、端云仲裁与播报打断设计：话没说完不抢答，断网时基础车控仍可用，有效插话（简单车控除外）即停旧播报，兼顾及时接话与完整理解。
  • 长期记忆：负责场景化记忆召回与共乘隐私方案：按当前场景召回、减少误召，敏感记忆只在当前在场的人都经历过时才使用，新乘客上车即清理敏感对话摘要。
  • 量产问题治理：牵头上汽、赛力斯项目数千条 badcase 分诊，按链路、工具、上下文和模型问题定责，依据收益与时效安排修复优先级。
  • 车企需求交付：主持赛力斯系统预设任务外审，明确端云分工；针对雨量、车速场景难以实测的问题，提出先以可控信号验证链路、再恢复真实条件的方案。
