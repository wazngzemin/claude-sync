版本：v2.0｜状态：需求评审稿｜修订日期：2026-11-05

本期方案以 11 月 4 日晚间会议后段收敛的链路为准：不新增独立的新手引导 Agent。此前生成稿将下午 Agent 方案作为主方案有误，本版已纠正。原始会议文档及既有方案文档保留不变。

本文区分三类内容：「会议结论」用于确定本期方向；「需求补充」用于明确可验收的产品行为；「待联调确认」用于标识输入、接口和执行时序尚未验证的部分。待确认项不再包含是否新增新手引导 Agent。

1. 需求概述

用户尚未了解身份识别、记忆等能力时，豆包需要在相关对话或明确业务节点中介绍能力，并在用户愿意使用时承接后续操作。现有方案的主要缺口是场景判断与条件判断的衔接、引导建议进入当前对话的时机，以及下发后是否被实际处理的反馈。

本期在现有配置、触发器与 DT 链路中补齐这些能力。DT 即 Director，也是 Planner，负责结合用户原始请求和引导建议组织回复、调用工具并处理结果。本期不新增独立的新手引导 Agent，不建立第二套对话推理与执行编排。

对话类场景采用「预设场景描述及示例 → 单模型判断语义相关性 → 触发器判断组合条件 → 向 DT 下发预设引导建议 → DT 沿现有链路执行 → 回传处理状态 → 触发器计次并结束」；明确业务事件直接进入触发器条件判断，不强制经过语义模型。

4. 目标与验收指标

本期目标是在明确场景中完成适时、有限次、可追踪的能力引导。用户原任务应正常承接，系统能够说明某次引导为何触发、DT 是否处理、是否实际播出，以及用户是否进一步完成了功能操作。

目标 统计与验收方法 不得替代的结论
找到相关场景 对场景正例、泛化表达、反例分别评测命中与误触发 不要求枚举全部用户表达；不虚构准确率承诺
条件判断准确 对每个条件记录事实来源与成立／不成立／未知 语义命中不能证明首次使用、已授权或次数剩余
建议进入正确轮次 对关联原请求、DT 接收和开始处理的时间进行联调 请求已发出不能证明 DT 在回复前使用了建议
次数可控 每次对应处理仅计一次；达到配置上限后停止该主动引导 重复反馈、接口重试不得多扣次数
触达可观察 分开统计 DT 处理、播放开始、完成及中断 DT 开始推理不等于用户已经听到或理解

时延验收重点为「引导建议能否进入当前轮回复」。晚间会上提及的 200–300 毫秒及其他时延数字分别涉及已有路径或讨论目标，不能直接作为新链路端到端承诺。需在真实环境测量语义判断、规则判断、建议交接和 DT 处理各阶段耗时，再确定发布门槛。

5. 适用用户与场景范围

沿用按账号管理引导次数的业务方向，车辆用于承载和车型能力判断，当前说话人用于判断是否适合执行身份或记忆操作。登录账号不自动等于当前乘客；无法确认关联时，不将另一人的信息或使用记录写入该账号。

6. 用户价值与交互原则

用户应在当前诉求中理解功能能解决什么问题，并自行决定是否使用。引导介绍与功能执行分开：询问“是否愿意注册”不代表已注册，介绍“可以帮你记住”不代表已写入记忆。

  1. 原请求保留。 触发器向 DT 增加引导建议，不将用户输入替换成引导话术。DT 应结合二者生成自然回复，避免用整段功能介绍掩盖用户当前需求。用户已明确请求功能操作且无需介绍时，DT 不采用该引导建议，只执行原请求，不将该次正常功能推理回传为引导处理成功。
  2. 明确请求直接承接。 用户已主动要求注册、记住或查询时，优先走正常功能流程；必要的身份或授权说明由该流程承接，避免再叠加重复介绍。
  3. 事实判断有来源。 注册、授权、使用、同步及次数分别读取实际状态，缺失不自动等于否或首次。
  4. 处理与触达分开。 本期以 DT 开始对应推理作为处理成功计次依据；实际播放与功能成功另记。此口径用于限制重复处理，不能将账号标记为“已经知晓全部能力”。
  5. 过期建议不补播。 当前轮已回复、账号切换或场景失效后，不将旧建议插入新的无关对话。

其中第 1、3、4 项对应晚间会议链路边界；明确请求优先、未知退出、重复抑制及迟到处理为本稿补充的产品规则，需纳入验收。

配置平台保存场景描述、示例、组合条件和需要 DT 完成的引导目的。语义模型只回答“当前表达是否与某个已配置场景相关”；触发器接收该结果，再检查账号状态、首次或次数、端状态等组合条件。全部满足后，触发器向 DT 提供 advice，即预设的引导建议。DT 负责实际对话及功能操作。

记忆同步完成等明确事件不依赖用户说出某句话，直接作为触发器的输入条件。工具返回前置条件不足时，DT 依据真实 tool_feedback（工具执行反馈）完成必要说明；这条正常执行路径也不要求经过语义模型。

模块 输入 输出与责任边界
场景配置 产品定义的描述、典型示例、条件、引导目的和次数 发布可被识别及执行的场景；语义描述与对应规则保持同一版本
语义匹配模型 当前用户表达、已启用的语义场景候选 返回相关场景或无匹配；不查询记忆、不判断业务首次、不自行发起功能操作
功能与账号模块 实际功能运行及身份信息 提供可关联的状态或事件；不把分析埋点自动视为业务状态接口
触发器 语义结果或事件、真实状态、配置次数 判断组合条件、去重、下发建议、接收处理反馈并计次
DT／Planner 原请求、触发器建议、既有对话及工具结果 组织回复、生成 action_list（下游动作列表）、调用工具、依据结果继续判断
下游工具及端侧 DT 的具体动作或播报内容 执行功能、呈现交互并返回真实结果

不新增“新手引导业务总控”来重复读取上下文、选择工具或追踪全部执行。触发器只管理本场景的条件和计次，复杂对话判断及记忆检索留在 DT 既有链路。

7.2 场景配置与生效

配置对象是产品预设场景，不是用户每说一句话就注册一个新任务。新增语义场景时，将该场景的描述和示例同步到模型候选，同时使对应规则与建议生效；明确事件场景只配置事件及规则。

配置项 业务含义 要求
场景标识及版本 将一次识别、判断、建议和反馈归到同一场景 可追溯配置变更；示例标识不等于已确定接口字段
入口类型 用户表达、业务事件或既有工具反馈 区分适用链路，不强制全部进入模型
语义描述及示例 定义何时适合介绍该功能 提供典型正例、边界反例及明确功能请求；不逐句穷举
组合条件 账号、身份、授权、首次、次数及所需端状态 每项写明事实来源、未知处理和缺失影响
引导建议 希望 DT 达成的目的、可提内容和动作限制 描述如何结合原请求；不只存一段脱离场景的固定 TTS
次数和范围 对哪个账号、哪个场景限制多少次 身份补引导按源表后续一次；其余场景在配置评审中明确
启停及退出条件 场景是否启用、何时结束 停用后不产生新建议；旧建议按有效性处理
处理结果关联 识别本次建议是否进入 DT 对应推理 支持重复反馈去重，避免将其他对话误算为处理成功

“是否首次”必须注明是首次调用、首次成功使用还是首次处理引导，三者不能互换。语义模型不承担这些事实判断。场景表尚未明确的次数、拒绝抑制范围及跨车共享范围列入评审，不借用会上举例的 2 次、3 次作为默认值。

P0：完成端到端联调 下表用例及实际用户可见结果 同时核验输入、判断、交接、反馈与最终表现 产品、测试、相关模块
P1：完善触达和使用统计 播放及业务结果统计 与处理成功次数分开，未知结果可辨认 端侧、数据、功能模块

P1 表示不替代本期处理计次口径，并不允许省略 P0 联调中的用户可见结果检查。具体信号的上线安排根据现有能力确定，不在本稿虚构开发天数。

8.2 关键验收用例

用例 前提与触发 预期链路与结果
身份补引导正常 跳过记录明确、仍未注册、次数剩余，相关表达 语义命中 → 条件成立 → 建议进入 DT → 对应推理计次 → 引导；同意后走注册
身份资格未知 只知道未注册，不知道提车是否跳过 原表补引导不触发；正常功能所需身份说明仍可执行
次数耗尽 同账号场景已达到配置上限，再次相关表达 不再发送主动建议；主动注册请求不被阻断
记忆能力介绍 相关话题、适用条件成立 介绍能力，不为介绍而强制检索旧记忆
明确记忆请求 用户直接要求记住信息 DT 走正常功能流程，按真实反馈回应，避免重复介绍
语义无关 普通问候或其他无关请求 不触发引导，不影响原回复
同步尚未完成 已激活／已授权，但同步未结束 不触发基于记忆的问候
同步完成且可检索 当前账号有效完成事件，工具返回真实记忆 事件直接进入规则，DT 检索后选一到两个点问候
未授权或检索失败 未授权，或授权同步后检索失败 前者不启动该问候；后者不编造个性化事实
建议晚到 DT 已越过当前轮接收窗口 本次结束，不在新话题补播，不误计对应推理
重复与乱序 同一事件或同一处理反馈重复到达 仅一次有效处理及成功计次，不影响其他场景
只发出未处理 advice 发送成功，但 DT 未进入对应推理 不计成功，记录真实状态
已处理但播报中断 DT 对应推理已发生，端侧未播完 处理计次保留；触达记录中断，不能标记完整播报
账号切换 建议待处理或旧反馈返回时切换账号 不向新账号播旧内容，不把次数计到新账号
条件与工具结果不一致 触发后实际注册／记忆操作失败 DT 如实回应；引导计次与业务失败分开记录

8.3 评审仍需落实的具体事项

需要明确：各状态的提供方与粒度；源表未规定场景的次数及有效范围；用户拒绝的抑制范围；同轮多场景冲突规则；DT 的建议接收窗口及反馈关联方式；反馈缺失后的对账方式；本期可提供哪些端侧结果信号。

上述事项属于当前链路的具体实现及产品边界，不再以“先决定是否做新手引导 Agent”作为前置条件。发布应以完整链路联调通过为准，配置保存或模型单项评测通过均不等于场景验收完成。
