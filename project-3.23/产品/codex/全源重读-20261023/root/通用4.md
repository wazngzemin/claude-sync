# AI汽车1\.0端侧架构和需求理解



## **感知\&amp;观察**



### **用户输入**

- **车内语音输入**

    - **语音唤醒**：支持通过豆包唤醒词（如“豆包豆包”）唤醒语音。

        - 端侧方案：集成SDK\+接口引入。

        - 工作量：3人天。

    - **主驾免唤醒（带条件）**：满足特定条件（单人驾驶、特殊指令等）时，主驾无需唤醒词即可交互。

        - 端侧方案：配合实现免唤醒逻辑。

        - 工作量：3人天。

    - **全音区免唤醒**：车内全音区自然对话衔接。

        - 端侧方案：多路音区\+多路拒识设计，需链路改造。

        - 工作量：5人天。

    - **音频降噪**：减少车内噪音干扰。

        - 端侧方案：集成SDK\+接口引入。

        - 工作量：3人天。

    - **音区识别**：识别语音来源座位，实现精准交互。

        - 端侧方案：集成SDK\+接口引入。

        - 工作量：3人天。

    - **离线ASR**：支持离线环境基础识别。

        - 端侧依赖：需豆包后端文字输入接口，可能链路改造。

        - 工作量：10人天。

    - **离在线ASR仲裁**：优选离在线ASR结果，确保最优。

        - 端侧方案：高值需求，断网场景涉及。

        - 工作量：3人天。

    - **声纹识别**：支持区分用户身份。

        - 端侧方案：集成SDK\+接口引入。

        - 工作量：2人天。



- **车外语音输入**

    - **音频降噪**：减少车外噪音干扰。

        - 端侧方案：集成SDK\+接口引入。

        - 工作量：3人天。

    - **离在线ASR**：车外语音输入根据网络状态自动切换。

        - 重复需求。

        - 工作量：0人天。



- **手势输入**

    - **DMS/OMS输入**：通过手势确认或选择。

        - 端侧方案：车端VML转文本query。

        - 依赖：需豆包后端文字输入接口。

        - 工作量：3人天。

    - **豆包IOT输入**：同上，端侧VML转文本query。

        - 工作量：2人天。



- **操作输入**

    - **屏幕输入**：触控操作，AI辅助理解和修正。

        - 端侧方案：端状态上报。

        - 工作量：0人天。

    - **屏幕圈选内容**：理解用户指定信息。

    - **物理操作输入**：点按按钮、旋钮等。

    - **跨端输入**：来自手机或其他IoT输入。



- **车辆输入**

    - **系统端状态采集**：采集电量、导航、媒体播放等状态。

        - 端侧方案：端状态上报。

        - 工作量：0人天。

    - **视觉端状态采集**：采集车内外视觉。

        - 端侧方案：VLM转文本上报。

        - 工作量：1人天。



## **理解\&amp;计划**



### **工具使用**



- **指令解析**

    - **所见即可说**：方案1三方工具，方案2豆包内OCR。

        - 端侧依赖：小模型训练\+数据。

        - 工作量：约20人天。

    - **GUI操作agent解析**：解析用户GUI操作意图。

        - 端侧方案：GUI操作上报。

        - 工作量：0人天。

    - **离线指令解析**：高频简单指令离线解析。

        - 端侧方案：三方方案。



## **执行\&amp;表达**



### **工具执行**



- **控制能力执行**

    - 车辆控制、系统控制、智驾、导航、媒体、应用操作、其他接入控制能力。

        - 端侧方案：车控。

        - 工作量均为0人天。



- **查询能力执行**

    - **视觉查看**：调用视觉模型。

        - 端侧依赖：豆包视觉链路改造。

        - 工作量：7人天。



- **GUI操作执行**

    - 模拟点击、虚拟屏操作

        - 端侧方案：模拟点击。隐藏屏幕需系统支持

        - 工作量：3人天 \+ ?。



- **Agent执行**

    - 由豆包或三方Agent执行任务。

        - 端侧依赖：服务端提供接口和格式。

        - 工作量：5人天。



### **豆包超拟人对话**



- **离线TTS**：支持离线合成豆包音色。

    - 端侧方案：集成SDK。

    - 工作量：5人天。

- **肢体动作**

    - **音画同步**：声音与动作一致。

        - 实现路径多，要求tts工具能回调告知播放进度，工作量约7人天。

    - **特定动作执行**：组件式交互，ASR逐字显示、状态展示。

        - 工作量：3人天。



### **GUI**

- **基础主交互**：生成式非固定交互\+视觉，轻量交互。

- **生成式交互**：展示任务执行、推荐卡片、感知信息等。

    - 无细节无法评估方案和工作量

- **舱外感知可视化**：渲染车外环境。

    - 低价值需求，外包。

    - 工作量：0人天。
