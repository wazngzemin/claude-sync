# 需求概述

## 需求背景

图形用户界面（GUI）是人机交互的核心，用户可通过GUI完成各种事情，如“点外卖”、“发消息”等。传统的GUI自动化多依赖脚本或规则，缺乏适应性（应用页面发生变化）和拓展性（非规则下的交互），难以应对动态工作流。多模态大模型（Vision \- Language Model，VLM）有很强的理解图片内容和推理的能力，这使得通过VLM搭建一个Agent自动去操作图形用户界面，来实现用户的需求，为GUI自动化带来突破性进展。

豆包GUIAgent是一个基于App界面，**一步步自动操作以完成用户需求的Agent**，它的核心是**提升VLM对图形用户界面的理解和规划能力**，并且在此基础上构建一系列的产品服务（Agent）。

## 目标概述

- **用户价值层面：**解决驾驶过程中手动操作手机或车机分散注意力、操作风险高的痛点，实现“一句话完成操作”，保障驾驶安全的同时提升交互效率；

- **产品能力层面****：**能够精准理解用户自然语言指令的核心意图，具备**手车互联（投屏）\&amp;车机小程序**，**和车场景关联度较高应用**的GUI理解，以及完成自动化多步骤操作能力；

### 手车互联（投屏）

手车互联投屏是指将手机屏幕内容通过无线或有线投射至车机系统上，实现手机功能在车机上的共享。市面上主流的投屏协议一共分为两种类型：离屏渲染和镜像投屏。

- 从用户体验角度，优先考虑不影响用户当前操作的 **离屏渲染**

- 从模型通用角度，优先考虑 **能获取到原始手机页面的协议**

### 虚拟屏开发

虚拟屏幕技术（Virtual Display）是一种软件层面的屏幕技术，可在不影响用户当前操作的情况下，为应用程序提供独立的运行环境，常用于后台任务执行、多任务处理等场景。豆包GUIAgent将目标应用的界面分配到虚拟屏进行运行，目标应用在虚拟屏里正常运行并渲染界面。

**默认情况下，用户在车机中控屏上看不到虚拟屏幕**，但是可以通过手动方式看到。用户下发一个GUIAgent指令后，大致流程是：

*前提：除车机屏幕以外，车企提供常驻虚拟屏，供GUIAgent去获取相关截图以及通过无障碍服务控制应用*

- 分配目标应用：Agent将目标应用启动在虚拟屏上

- 应用运行在后台：

    - 目标应用在虚拟屏正常渲染，不干扰用户中控屏的操作

    - 虚拟屏画面通过mirror投屏至主屏任意位置（根据项目设计决定），投屏页面可收起/可展开

    - 当Agent需要用户接管时，支持再次将投屏页面拉起，用户可点击操作

- 释放目标应用：当Agent完成任务时，目标应用在虚拟屏关闭，投屏页面通道关闭



## 智能体能力

GUIAgent本身是个由AI模型驱动，能够 **理解视觉界面**、**推理任务意图**，并**执行类人操作** 的AI Agent系统

### 视觉界面理解（Visual Perception）

```Plain Text
屏幕截图 → 元素识别 → 语义理解
```

- 元素识别：按钮、文本框、下拉菜单、图标等

- 文本识别：OCR 能力，理解界面上的文字

- 布局理解：空间关系、层次结构

- 状态感知：是否可点击、是否已选中、是否加载完成

由于视觉理解完全依赖模型自身能力，我们能做的几个方向：

- 提供正确的截屏（小程序和手机投屏区域只占车机屏幕的一部分，且支持用户来回拖动）

- 平衡上云的图片质量（让图片上传至云端耗时更短，同时保证不影响模型理解）

- 对于核心场景重要页面的解释（有些应用或小程序的交互设计不容易理解，需要辅助一些文字解释）

### 任务规划 \&amp; 思考（Task Planning \&amp; Thinking）

```Plain Text
任务目标 → 子任务分解 → 操作序列
```

- 任务目标（用于持续任务显示）：由planner总结本次GUIAgent目标，如给婉婷发消息、点瑞幸咖啡、预订酒店

- 子任务分解：由Agent将复杂任务拆分为简单步骤

- 操作排序：由Agent确定执行顺序

- 上下文（来自O的分享）：单任务生命周期内，携带全量的思考过程以及最多 5 张图片，作为上下文给模型进行推理



除模型自身能力以外，可增强的方向：

- 补充planner的场景knowhow，在前置环节提前确认清楚需要的信息

- 补充智能体内部的场景knowhow，辅助智能体更高效地进行任务拆解

- 补充异常情况的处理knowhow，如广告弹窗、动作无法执行的备选方案

- 增加重试机制，避免错误动作导致任务死循环或失败的情况

### 动作执行 \&amp; 状态反馈（Action \&amp; Feedback）

```Plain Text
操作意图 → 元素定位 → 动作执行
```

- 坐标计算：确定点击位置

- 操作选择：点击、输入、拖拽、滚动

- 时序控制：等待加载、延迟操作

- 错误检测：验证操作是否成功

- 状态反馈：告知context当前状态，用于advisor对于持续任务的管理

### 安全策略

由于截图以及自动化操作会涉及采集很多用户的个人信息，需要考虑以下用户隐私保护措施：

- **应用使用安全：**应用限制（如截屏黑屏或明文禁止使用应用）直接告知用户限制情况，如“中国银行属于不可自动操作的应用，无法完成相关任务，还是手动操作一下吧”。

    - 明文禁止使用应用：禁止打游戏、薅羊毛、操作银行类

- **截图数据安全：**上云时采用全链路加密方案，推理完成后删除不做存储。

- **隐私红线行为**（可延续O建设）：实行AutoAction行为分类分级管控，高敏感行为必须要求用户确认，或者要求用户直接接管，防止用户过度授权执行。参考文档：[AutoAction隐私安全红线行为](https://bytedance.larkoffice.com/docx/P4t5duZtLozSGHxLYZDcMJWhn6b)[OAuto Agent安全需求汇总](https://bytedance.larkoffice.com/docx/Iq3rdKHNIoeQlWx4jaGc2s7znid)

    - 需要用户确认场景：同意用户隐私协议、登录账号、支付操作

## 准确率需求

测试集/验证集区分简单任务和复杂任务：

- **简单任务：****10步以内**，且 **在单应用内 **完成场景目标，如“帮我去飞书里看下我今天都有哪些会议”

    - 理想步骤：打开飞书\&gt;点击日历\&gt;滑动查看所有日程\&gt;总结回复

- **复杂任务：****10步以上**，或 **需要跨应用** 完成场景目标。如“飞书里帮我创建一个下午3点到4点的guiagent会议，并把会邀发送给我的微信好友廖婉婷”

    - 理想步骤：打开飞书\&gt;点击日历\&gt;创建会议\&gt;添加主题\&gt;选择时间\&gt;保存会议\&gt;点击会议\&gt;点击转发\&gt;点击日程链接\&gt;点击分享\&gt;分享至微信\&gt;查找好友廖婉婷\&gt;粘贴会邀
