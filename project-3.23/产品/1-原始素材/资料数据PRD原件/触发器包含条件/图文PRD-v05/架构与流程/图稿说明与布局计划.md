# 架构与流程图稿说明

图稿配合完整 PRD 使用；Mermaid 供飞书原生画板导入，SVG 与 PNG 供预览和静态交付。蓝色框是配置或运行模块，浅蓝强调关键分流与结果，灰绿为限制或结束分支。正文 22 px，标题 26 px，整图标题 36 px；1700 px 宽，白底，原生可编辑形状。

## A1 总体架构

五层分别回答“后台配置什么、谁保存单车选择、运行侧怎么判断、谁执行下游、在哪里追溯”。配置模式与 DT 分开；简单模式为空 ID，Workflow 为非空 ID。每车开关由云端 Trigger 既有范围表持久维护，不与 AI 设置混成一个开关。架构图不代替端侧保存方案。

## A2 配置发布流程

进入与选择 → 定义判断 → 配置出口 → 校验与验证 → 发布与替换。已有 Workflow 只读，复制后形成独立新定义。替换旧规则的用户选择保持、关联和恢复需要额外确认，不能画成现成的自动无缝切换。非法判断图应返回全部 issues，不生成 Workflow ID。

## A3 运行判定与下游

启动与新旧分流 → 节点调度和三态判断 → 汇合与整图收敛 → 策略/锁/History/Action → 下游卡片和车控边界。AND/OR 配在实际目标节点；允许之后仍需目标自身判断。OR 任一前驱 PASS 即就绪，但不取消其他分支；所有节点終态后才取唯一终点结果。Run 保留每次判断，History 仅在策略允许之后为 Action 创建；两者不是同一种记录。

## 技术方案与本图明确区分的未决项

- 混合判定暂不支持定时；技术文档 Timer 适配代码不能直接推出本期开放。
- 混合判断怎样汇总各节点启动信号、迟到输入如何处理，需确认。
- 复制和替换的切换、用户选择保持、回退方式，是产品建议，需研发确认。
- 下游 Action 回执不代表卡片已经展示或车辆真实成功，必须与卡片/车控联合验收。

## 布局验证

- 三图统一 1700 px 宽；正文不小于 22 px；SVG 使用 rect、polyline、line、text，仅箭头 marker 使用 path。
- 架构图 1660 px 高，流程图 2260 px 高，运行详图 3440 px 高。长图按业务阶段分区，不把所有细节塞入巨型框。
- Mermaid 标签采用 quoted 标签与 `<br/>`，便于飞书原生导入。完整链路节点少于 100 个。
