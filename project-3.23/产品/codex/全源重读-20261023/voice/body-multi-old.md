# 【AI汽车PRD】多音区同时交互需求

<div class="callout">

多音区交互时，系统应该如何反馈，几个关键点

1、用户的query的执行表达方式是什么。语音播报是否是必要的。

2、多个用户的query是否存在冲突。

3、用户的query的是否是涉及驾驶或安全类功能。

# 需求背景

随着智能座舱技术的发展，车内语音交互已从单一用户场景向多用户并发交互演进。现代家庭用车中，平均每车搭载3\-4名乘客的场景（特别是面向家庭的车辆），然而，当前主流车载语音产品仍以单个用户为中心设计，缺乏对多用户同时交互的有效支持。因此这类用户需求需要被满足。

# 决策流程

# 用户体验拆解

1. 类型1：有音区正在语音播报中，其他音区指令「非必要播报TTS」

    1. 场景：主驾驶正在播报天气的内容，副驾驶指令：打开车窗

    2. 体验设计：

        1. 提示音

            1. 成功时：副驾驶用「短促轻响」的正反馈提示音进行提示，并执行开窗动作。（不会打断天气的播报信息）

            2. 失败时：副驾驶用「短促轻响」的负反馈提示音进行提示。

        2. 界面反馈

            1. 成功时：副驾驶语音交互反馈位置弹出「✅」的图标，弹出2秒后消失。

            2. 失败时：副驾驶语音交互反馈位置弹出「❌」的图标，并且以文字的形式，提示副驾驶失败的原因，eg「儿童锁上锁时，无法打开车窗」持续5秒后消失。

2. 类型2：有音区正在语音播报中，其他音区指令一定要播报TTS，但「意图不冲突」且「非安全类」且「非关联补充」

    1. 场景：主驾驶正在播报天气的内容，副驾驶指令：讲个笑话。

    2. 体验设计

        1. 提示音：副驾驶用「短促轻响」的正反馈提示音进行提示。

        2. 语音播报：

            1. 过度话术播报：收到你的需求，等主驾驶的任务结束后，我会给你讲笑话，等一下哈。

            2. 主驾驶的被打断的天气播报，继续按照打断时的位置，延续播报。

            3. 主驾驶播报完增加过度话术，“即将为副驾驶的朋友，讲笑话”

            4. 对副驾驶进行笑话内容的播报“有一只企鹅，不小心把自己的\.\.\.\.\.\.\.\.”

3. 类型3：有音区正在语音播报中，其他音区指令一定要播报TTS，但「意图不冲突」且「安全类功能」

    1. 场景：主驾驶正在播报天气的内容，副驾驶指令：打开雾灯。

    2. 体验设计

        1. 语音播报

            1. 打开雾灯的执行结果，包括成功或者失败的TTS

            2. 打断天气内容的播报

            3. 打开雾灯的结果播报完，，继续按照打断时的天气内容位置，延续播报。

4. 类型4：有音区正在语音播报中，其他音区指令一定要播报TTS，但「意图不冲突」且「非安全类」且「关联补充」

    1. 场景：主驾驶说“温度调到23度”，副驾驶说，再高一点。

    2. 体验设计：

        1. 语音播报：合并两个场景进行播报「空调温度调好了」

        2. 执行：以多意图场景合并执行

5. 类型5:有音区正在播报中，其他音区指令与当前指令存在冲突

    1. 场景：主驾驶说：导航去北京，副驾驶说：导航去海南。

    2. 体验设计

        1. 语音播报：请主驾驶的朋友，帮忙确认下要去的目的地是哪？\-\-》指定主驾驶

        2. 界面反馈：弹出选择框「北京」「海南」
