## NC01：多人输入合并与排队（候选，待输入管理原文补齐）
- 是什么：将不同座位的有效指令拼成一轮、或保存后到任务供当前任务结束后处理的控制逻辑。
- 在哪里运行：本 PRD 未指明独立服务与部署位置，不能直接命名为另一个模型。
- 收到什么：带说话座位、拒识结果和时序的用户 query，以及当前执行/播报状态。
- 输出什么：角色标注的合并请求给 Planner；执行中任务按文本/控制类型作覆盖、打断恢复或排队；排队信息给界面。
- 关键数字：暂定最多合并 4 个；不是已验证上限。
- 来源：multi-prd.txt:5–17、70–83、113–122；卡片 9 只概述合并边界，尚无本部件的完整卡片。

## NC01 补充：输入管理前置模块的正式职责与状态
- 是什么：Planner 前置的工程控制逻辑，组织所有有效输入的打断、排队和合并；不是 Planner 本身，也不是拒识模型。
- 在哪里运行：位于云端 Planner 前置链路；本 PRD 未给服务名/进程部署，待技术方案细化。
- 收到什么：有效用户输入（含多音区及 last_talk_content）、工具反馈、建议、事件，以及推理完整性与 TTS 状态。
- 输出什么：当轮合并后的结构化输入、旧推理终止/重启决策、等待队列；普通反馈等在推理和播报都结束后集中交给 Planner。
- 关键数字：正文无队列容量/时限；高优 advice 分支当前无；v0.5 2026-10-13 加多任务排队/拼接示例；P0/P1、同源保新、过期规则在历史先不看区。
- 来源：input-prd.txt:48–55、90–128、165–169、391–604。

## NC02：播报打断信息注入（候选，区别于 PCM 续播器）
- 是什么：把旧回复实际说到哪里、剩余什么送给 Planner 的信息通道。
- 在哪里运行：车端上报、云端输入管理拼接；本文件未独立定义服务。
- 收到什么：旧播报文本/进度、用户新话及是否拒识、旧动作是否已下发。
- 输出什么：有效输入携带 last_talk_content；拒识输入另发打断 event；整体重推分支无需旧断点。
- 关键数字：无量化阈值；TTS 一字未播仍上报整段未播的能力在文中有追问。
- 来源：input-prd.txt:90–95、123–128、207–209、239–265、311–324。

## M0813 补充证据：恢复价值判断（建议作为恢复调度职责，不另猜一个模型）
- 是什么：按任务类型、被打断节点、核心信息是否已经说完及新任务覆盖/补充关系，判断剩余内容是否值得恢复的业务判断。
- 在哪里运行：文字记录提到 Planner 提示词优化及输入管理架构调整，但未给独立服务或端云位置，不能据此创造独立模型。
- 收到什么：未播完的 NLG、信息查询/控制/多结果搜索分类、新旧任务关系。
- 输出什么：是否恢复以及避免旧新任务交错的处理约束。
- 关键数字：该次会议打断整体通过率约 75%、拒识子集约 53%→约60%，缺样本量和严格分母。
- 来源：m0813.txt:22–23、40–68；现有卡片 5/9 没展开这项职责，需由后续设计者决定并卡或新卡。

## NC01 技术方案补齐：云端输入管理与接入适配
- 运行位置：云端 AIDV 进程内模块，Redis 跨实例保存协调状态；Adapter 把 query/advice/event/feedback 标准化，输入管理本身不调模型。
- 收到什么：来源身份、优先级 P0/P1、mergeable/isolated、聊天/推理/播放状态及能否重放；缺 request_id 走旧链路。
- 输出什么：立即执行、失效旧执行、合并、排队、结束；仅一个有效候选与一个未撤销输出可并存；同 chat 一个 waiting 列表，不是两条物理队列。
- 关键数字：第一阶段无业务 TTL/队列上限；每 Chat 两个 Redis key；旧 4 条缓存、1分钟 TTL、100ms 轮询是迁移前机制。
- 来源：input-tech.txt:194–215、271–321、531–538、570–573、726–757、818–847。

## NC03：执行许可与副作用保护（工程机制，不是模型）
- 是什么：用执行身份和原子许可阻断旧执行的新影响，同时保留已发生工具事实。
- 在哪里运行：AIDV 输入管理、Redis 原子协调及 Planner/TTS/工具/历史出口。
- 收到什么：全局唯一 DirectorExecutionID、当前候选与正式输出引用、许可、前序播放依赖、工具调用身份。
- 输出什么：ComputePermit 允许预跑，OutputPermit 允许正式输出/新工具；工具放行前原子设不可重放；旧候选失效但真实反馈正常回流。
- 关键数字：同 Chat 最多 1 个有效候选和 1 个未撤销输出；TaskRoundID=DirectorExecutionID；ID 只比较相等、不比较大小。
- 来源：input-tech.txt:303–313、388–397、521–536、588–607、780–808、964–968。

## NC04：播放生命周期协调与恢复调度（候选）
- 是什么：将真实启播、进度、完成/永久中止转成调度依据，区别于卡片7的音频合成。
- 在哪里运行：车端 PlaybackCoordinator/播放器采样与持久重报，云端输入管理消费 Redis 播放状态；request级进度另回写历史库。
- 收到什么：TaskRound边界、实际消费时长、STARTED/PROGRESS/FINISHED/ABORTED、断点与新输入；UNKNOWN 与 0 不同。
- 输出什么：暂时暂停可续原对象，永久 ABORTED 不能复活；恢复 event 重推取新身份；合法终态释放 waiting/预跑候选。
- 关键数字：同执行多个 TTS provider 共用 1 个 TaskRound；软截止=末次进度时间+剩余时长/最慢倍速+宽限，硬截止再加最大未确认阻塞时长，各参数未给值；超时不伪造已播完。
- 来源：input-tech.txt:225–237、547–561、848–968、1012–1156。

## NC04 语音链路补充：恢复上下文素材
- 来源侧能力：Sami TTS 打轴提供文本/音频对应关系，端回传播放进度；拒识后 event 与召回后 last_talk_content 两类重新推理路径。
- 关键边界：SingleInterrupt 与离线车控播放表内不恢复，多人流式/豆包开头/云端非拒识可恢复；这是语音表而非通用所有暂停协议。
- 来源：voice-onepager.txt:162–176、461–567。

## NC02 补充：播报进度切分器
- 是什么：buildTTSPlayAndNotPlayedSentence 以真实播报进度恢复已说/未说文本的工程函数，不是语义恢复模型。
- 在哪里运行：云端 Planner 的 TTS 恢复上下文构建链路。
- 收到什么：旧 talk 文本、播放时长、逐字 WordTimestamp；缺打轴时使用估算参数。
- 输出什么：带打断标记的 last_talk_content。
- 关键数字：缺逐字轴默认100ms/字；这会有估算误差，不是统一语速保证。
- 来源：planner-onepage.txt:146–152、293–295。

## NC05：执行与对话历史重建（候选机制，区别于既有回写卡片）
- 是什么：从模型输出与工具执行结果重建多轮 ReAct 时间线的 Planner 工程逻辑。
- 在哪里运行：云端 Planner buildHistoryMessages，读取现有三类历史记录。
- 收到什么：chat_history、planner_histories、planner_task_list 和事件日志。
- 输出什么：按时间稳定排序的 user→assistant observation→user feedback 模型输入；失败降级旧 history。
- 关键数字：并入最近10分钟最多3条白名单事件；100ms/字的恢复估算与历史顺序是不同作用。
- 来源：planner-onepage.txt:104–114、150–152、277–307。

## M1019 新增候选：多轮语义相关判断
- 是什么：判断后一句与上一结果是否同话题、从而决定保留或收起卡片的模型职责。
- 在哪里运行：上汽被明确描述为单独模型，具体端/云位置未给出；不要假定赛力斯也运行同一独立模型。
- 收到什么：前后 query 与上一轮结果的语义关系（字段未给出）。
- 输出什么：相关/不相关，用于保持旧卡或收起。
- 关键数字：无模型参数、准确率或时延数字。
- 来源：m1019.txt:113–114；既有 12 张卡片未覆盖此模型。

## M1019 新增候选：长时目标恢复调度
- 是什么：长时任务被其他任务占用前台后，检查未完成目标并再次推荐继续、恢复界面的任务调度职责。
- 在哪里运行：涉及持续目标与 Planner；文字记录未给独立服务及部署位置。
- 收到什么：长时任务目标、完成情况、新任务前台占用状态。
- 输出什么：继续原话题的推荐及配套界面再次拉起。
- 关键数字：未给出；当时未提测/未准出、主线开发中。
- 来源：m1019.txt:431–477；不能与一句播报的 PCM 续播合成同一个恢复部件。

## NC06：Planner 内的恢复价值判断（职责候选，不新增模型）
- 是什么：既有云端 Planner 根据旧断点、新话、任务与真实结果决定说不说、怎么接的提示词策略；现有卡片5只介绍通用输入输出，缺这项细则。
- 在哪里运行：云端 Planner，不是端侧播放器，也不是独立恢复大模型。
- 收到什么：独立打断 event 或新 query 携带的 last_talk_content、说话人、当前状态和工具事实。
- 输出什么：跳过尾音/用户不想听的内容、相关新旧合答、长内容提炼、称呼原说话人；只有执行成功确认的独立事件可不补说。
- 关键数字：1–3 个无意义剩余字跳过；≥3 句话提炼关键点；未给独立模型参数/耗时/训练集。
- 来源：director-prd.txt:237–251、591–593；voice-onepager.txt:240–242、461–476。

## M1020 新增候选：音频焦点与整车发声控制
- 是什么：车机协调豆包交互、媒体和导航播放通道的控制逻辑，音频焦点决定哪些声音应暂降，发声位置决定从哪些喇叭放声。
- 在哪里运行：车机，依赖上汽音频焦点与喇叭能力。
- 收到什么：豆包被唤醒/用户交互/播报和交互结束事件、系统头枕及前后分区模式。
- 输出什么：申请主驾或整车音频焦点、交互时降低媒体音量、结束后恢复媒体，并保持豆包整车发声。
- 关键数字：未给声压、降音幅度或时延；200 毫秒淡出仅为另一项停声讨论示例。
- 来源：m1020.txt:128–174；m1019.txt:218–219；现有 TTS 卡片只讲合成拉流，未覆盖焦点/播出仲裁。

## NC07：系统通知接入与动态选择工具（候选，与输入管理调度分开）
- 是什么：三方通知直达端侧即时卡，并让确认/取消语音或手动按钮能执行且同步上下文的交互机制。
- 在哪里运行：车端消息盒子/卡片/可见即可说；需语义泛化时云端 Planner 动态注册选择工具。
- 收到什么：通知正文、动态按钮/执行接口、用户语音或按钮点击。
- 输出什么：排队TTS与卡片、语音选中执行项或直接按钮执行结果，手动动作以事件同步云端；卡片消失删除动态工具。
- 关键数字：本原文无容量/超时；SOP 两项系统通知为内部预研，不能将设计当量产。
- 来源：aiva-vui-1104.txt:481–487、584–601、795–796；sop-items.md SOP-A04/SOP-A05。

## NC08：交互卡生命周期与多屏结果接续（候选扩充，避免重复上屏卡片10）
- 是什么：按工具/业务容器管理结果卡保持、替换、折叠和前后排联动的HMI逻辑，区别于只管识别文字的ASR上屏。
- 在哪里运行：车端中控/吸顶屏；云端语义相关判断提供相关性。
- 收到什么：音区、工具结果、卡片类型、相关性、TTS/视频/触摸状态与新query。
- 输出什么：原容器继续交互、相关卡更新、无关前后卡各自保留或新卡覆盖；折叠不停止声音，流式停声不停止出字。
- 关键数字：默认播完10秒退出；长时岛7秒折叠是另一个容器时钟；相关性返回要求在Director首token前，但本文件未给独立模型架构。
- 来源：aiva-vui-1104.txt:323–458、722–807。
