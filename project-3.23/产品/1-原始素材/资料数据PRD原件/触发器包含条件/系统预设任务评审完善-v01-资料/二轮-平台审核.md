# 最终候选 PRD：平台专项第二轮审核

审核范围：第 4 章、第 6.3.2 节、第 7、8 章，并与 `/tmp/prd-build/review-questions.md` 对照。总体已经补齐页面、操作、运行消费、隐藏字段和分层验收；以下只列必须修正的剩余不一致，不再扩张需求。

## 1. 图号引用错误

- 位置：4.2 首段。
- 原句：“页面仍使用一张表单，依次展示图二中的五组配置”。
- 问题：本稿图二是云端全模块接力，五组配置现在是图三。用户按图评审会找错。
- 改为：“页面仍使用一张表单，依次展示图三中的五组配置”。

## 2. ‘只有询问才要求卡片’与仅告知配置矛盾

- 位置：4.1“编辑页需要的三个联动”。
- 原句：“选择‘询问用户’才要求卡片与回答分支”。
- 问题：4.7 已规定仅告知也需要卡片模板和正文。前端可能在仅告知时漏展示卡片配置。
- 改为：“选择‘仅告知’或‘询问用户’均展开卡片与播报配置；只有‘询问用户’要求按钮含义、回答路线和回答分支”。

## 3. 兼容模拟 Query 与‘Planner 只处理语音’再次自相矛盾

- 位置：4.12 倒数第二段。
- 原句：“如果专项决定用模拟Query兼容，须选择该单一路线、注册目标和上下文，并验证不会直回同时执行。Planner入口仍只处理已展示卡片的有效语音”。
- 问题：前句允许按钮模拟 Query 进入 Planner，后句排除了所有非语音输入。问答 Q14 明确有单独兼容路线，正文应一致。
- 改为：“主方案的 Planner 语音入口只处理已展示卡片的有效回答。若专项选定点击模拟 Query 兼容路线，该按钮输入也可按已注册路径交给 Planner，但须标明来自点击、关联当前有效询问；同次点击不能再走直回业务路线。无论哪条路线，Planner 均不注册或拉起卡片。”

## 4. 充电草稿演示缺少 AI 总开关规则的配置落点

- 位置：6.3.1 许可行、6.3.2 步骤 3 及末尾业务摘要；对应 4.4/4.5。
- 原句：6.3.1“总开关与单项任务的关系待会签，本例假设都开启”；6.3.2 只填“SOC ≤ 20%”“口盖关闭”，摘要也只显示任务开启。
- 问题：运行案例检查 AI 总开关，页面却没有任何地方表达它，违反‘案例能映射到配置’要求。不能用“本例假设开启”掩盖遗漏的规则。
- 建议最小修正：在 4.4 或 4.5 补一句：“是否附加主动服务总开关门禁按任务已会签许可策略引用，不由普通条件组 OR 绕过；关系未定显示待确认，不能发布该任务的正式许可规则。”6.3.2 步骤 3 写“本草稿同时展示 AI 总开关为开启这一待会签门禁”；摘要同步写“任务开启，且满足已选许可策略（本例假设 AI 总开关开启）”。不要直接把“总开关必须开”升级为已确认结论。

## 5. 未会签演示草稿被写成可在测试范围发布

- 位置：6.3.2 步骤 9。
- 原句：“先保存草稿，点击‘检查配置’，按提示回填；在测试范围发布”。
- 问题：本段前面说 SOC、设备定义及各时长尚未会签，而 4.9 明确必要参数未定不能发布。‘测试范围’可能包含真实测试车辆，不能用演示参数绕过动作确认；问答 Q28 也要求未决关键参数不发布。
- 改为：“先保存草稿并检查；未会签项保留缺口。仅在隔离模拟环境使用演示值验证页面和分支，不连真实车控；用于测试车辆的发布前，必须完成该范围适用的参数、授权和车控限制会签，再发布受控版本。”

## 6. 7.4 把整车交付误写成‘正式评审后至少能展示’

- 位置：7.4 最后一段。
- 原句：“正式评审后至少能展示：一条完整配置摘要、一张实际卡片及各状态预览、一条对应的运行时间线、正向和关键反向整车验证记录”。
- 问题：本稿定位产品方案评审，评审结束尚未开发；‘实际卡片’‘整车验证记录’只有接入和测试后才能交付。此句易使用户在会上误承诺已有成果，与 8.2 实施顺序矛盾。
- 改为：“本次产品评审应展示配置摘要、卡片及状态设计、预期运行时间线和验收用例；完成接入并进入交付验收时，再展示真实卡片、实际运行记录，以及正向和关键反向整车验证证据。”

## 审核结论

完成以上 6 处后，平台章节与案例、问答、验收在本轮范围内可一致对应。尚未确认的现平台能力、真实研发认领及参数仍需实际专项核对，本审核不能代替他们确认。
