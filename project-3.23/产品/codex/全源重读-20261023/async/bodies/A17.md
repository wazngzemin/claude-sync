定时任务云端触发器需求文档
背景与目标
目前车内有大量需求，用户发出 query（请求）的这一刻不需要执行，而要由系统先记着，到未来某个时间点、或每隔一段时间再执行。
  当前问题：没有统一的定时触发能力，可能会导致边界混乱、下电丢失、重复建设。
  目标：在云端触发器里新增「定时任务」能力，作为与条件触发、语义触发并列的第三种触发方式。

定义与范围
定时任务定义
定时任务 ：用户发起后，不在当前同步会话内立即执行，而是由系统按「时间条件」在未来激活、可能反复执行的任务。它是 Task（任务）的一种，激活方式为时间到达，区别于条件任务（车态满足）和语义任务（画面命中）。

Case
Case 1：十分钟后关座椅加热
用户描述
用户说：“十分钟后帮我关闭座椅加热。”
任务类型
相对延时 · 一次性 在当前会话结束后的未来某个相对时间点执行一次。
触发器
任务系统把「十分钟后」翻译成「当前时间 + 600 秒」，向云端触发器注册一个闹钟。触发器到 14:10:00 响铃并 callback 任务系统。
执行动作
任务系统收到触发器 callback：「任务到点了。」
Guard 检查：车是否在线、座椅加热是否仍开着、是否还有人坐在座椅上。
Guard 通过：下发「关闭座椅加热」指令给车端。
任务系统把任务标记为已完成，卡片进历史记录。
生命周期 / 结束条件
一次性任务，触发一次即结束。如果用户在 14:10 前取消，定时被摘掉。
异常处理 / 冲突策略
到点时用户已下车 → 跳过执行，不算失败。
座椅加热已关 → 跳过执行，不算失败。
车辆下电 → 本趟内任务直接结束，定时摘掉。

Case 2：明天 9 点提醒我出发
用户描述
用户说：“明天 9 点提醒我去万达。”
任务类型
绝对时间 · 一次性 锚定未来某个具体钟点执行一次。
触发器
任务系统根据当前日期和时区，算出目标时间点「2026-07-22 09:00:00」，向云端触发器注册定时。
执行动作
触发器在明天 9:00 响铃，callback 任务系统。
任务系统检查车辆是否在线。
车在线：下发语音提醒「该出发了」。
任务标记为已完成，摘掉闹钟。
生命周期 / 结束条件
一次性任务，响铃即结束。即使到点时车不在线，也只在这次时间点触发一次，不会补发。
异常处理 / 冲突策略
到点时车辆下电 → 本轮跳过，不补。
用户提前取消 → 定时摘掉，明天不再提醒。

Case 3：每小时开一次座椅按摩
用户描述
用户说：“每小时帮我开一次座椅按摩。”
任务类型
固定间隔 · 循环 每隔固定时间反复触发，直到明确结束。
触发器
任务系统设置间隔 3600 秒，向触发器注册第一个定时。触发器每次响铃后，自动计算下一次时间并重新排队。
执行动作
15:00 触发器响铃，callback 任务系统。
Guard 检查：座椅是否有人、按摩功能是否可用。
符合条件：下发「开启座椅按摩」。
触发器把下一次响铃时间设为 16:00，重新进入队列。
生命周期 / 结束条件
满足任一条件结束：用户下车、用户关开关、用户取消、达到最大次数。
异常处理 / 冲突策略
某一轮座椅没人 → 跳过本轮，下个小时继续触发。
用户关开关 → 任务暂停；重新打开开关可恢复。
用户取消 → 任务彻底结束，定时摘掉。


Case 4：每分钟看后排宝宝有没有哭
用户描述
用户说：“每分钟看一下后排宝宝有没有哭，哭了提醒我。”
任务类型
定时采样 + 语义判断 · 循环 以时间为采样时钟，结合视觉语义做边沿判定。
触发器
任务系统同时做两件事：① 向云端触发器注册「每 60 秒响铃」的定时任务；② 订阅端侧 VLM 持续上报的画面描述。
执行动作
云端定时器每 60 秒响铃一次。
任务系统取最新画面描述：「宝宝哭了」/「宝宝没哭」。
只有「上次没哭 变更 这次哭了」才触发提醒。
持续哭不重复提醒；
生命周期 / 结束条件
用户取消或车辆下电（本趟内）时结束。
异常处理 / 冲突策略
连续 3 轮都哭 → 只提醒一次。
连续看不清 → 不更新上次状态，等看清后再判断。
画面流中断 → 按取不到描述处理，不触发提醒。

Case 5：每天早上 9 点提醒我喝水
用户描述
用户说：每天早上 9 点提醒我喝水
任务类型
绝对时间 · 循环 锚定每天固定钟点反复触发。
触发器
任务系统算出「明天 9:00」并创建定时规则。触发器到 9:00 触发通知并回调任务系统。触发通知后，触发器自动计算「后天 9:00」并更新定时规则。
执行动作
触发器在每天 9:00 触发通知，回调任务系统。
任务系统检查车辆是否在线、用户是否在车内。
条件满足：下发语音提醒「该喝水了」。
任务系统不结束任务，等触发器明天再次触发。
生命周期 / 结束条件
循环任务，直到用户取消、车辆下电（本趟内）或达到最大次数才结束。到点时车不在线则本轮跳过，明天继续。
异常处理 / 冲突策略
到点时车辆下电 → 本轮跳过，明天 9 点继续。
用户已手动关闭提醒 → 触发器删除定时规则，任务结束。
连续多天跳过 → 不补发，只按当天时间触发。
