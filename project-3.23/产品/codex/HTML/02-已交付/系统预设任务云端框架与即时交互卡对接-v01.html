CLOUD FRAMEWORK PRD v01

系统预设任务云端框架
与即时交互卡对接

框架宣讲稿：区分云端规则任务与云端推理任务。后视镜是“云端规则判断＋端侧静默执行”；充电口是“Cloud Trigger＋在线编排＋DT/VQA＋即时卡确认＋端侧复核执行”。

一句话边界：Cloud Trigger判断“是否值得启动一次云端任务”；Planner/Advisor/DT完成云端判断和语义；即时卡只在车机展示并收集选择；真实车控永远回到端侧复核。
当前已有结论建议方案待研发确认目标：框架宣讲，不承诺排期Planner = Director，同一职能

00 · READ THIS FIRST

先分清：云端任务不等于都要出卡

部署在云端说明判断或编排发生在云端；是否出卡由交互等级决定。

两类云端任务
① 云端规则任务

规则在云端命中，低风险动作可静默下发端侧复核执行。后视镜自动加热属于此类。

② 云端推理任务

硬条件命中后还需Planner、DT或VQA理解场景。充电设备识别属于此类。

③ 卡片仍在端侧

“云端卡”是云端生成交互请求，不是云端直接在屏幕上画卡。

④ 执行仍回端侧

云端给出建议或授权，不得绕过最新车况复核直接操作车辆。

不要这样讲：“这是云端任务，所以Trigger、卡片、语音和车控都在云端。”卡片与车控仍在车端；只有判断、语义和工具编排在云端。
应该这样讲：“云端负责复杂判断和语义；车机VUI负责呈现；用户选择回云端编排；真正执行前由端侧复核并回读真实状态。”
01 · BACKGROUND / VALUE

为什么需要独立的云端框架

当前资料同时出现“云端Trigger”“主动推荐”“Static Advisor”“Planner”“DT”“端侧VQA”和“即时交互卡”，但没有把每一段输入输出写成同一条合同。

框架宣讲

问题

研发知道各自模块，但不知道一条云端任务由谁创建事件、谁调DT、谁出卡、语音回谁、最后谁收口。

目标

把云端规则任务和云端推理任务分开；把Cloud Trigger、在线编排、VUI与端侧执行的合同说清楚。

价值

复杂判断可利用模型和上下文快速迭代；端侧筛掉无效场景；执行前复核避免旧云结果误控车辆。

任务类型云端做什么是否出卡端侧做什么当前样例
云端确定性规则消费上行状态、匹配规则、生成动作事件按交互Profile；后视镜当前静默检查最新状态、车控、回读后视镜自动加热
云端模型/工具推理硬条件后调用Planner、DT/VQA，获得场景结果并组织交互需要授权时出即时卡呈现卡片、上行选择、复核、车控、回读识别充电设备后开盖

05 · DATA CONTRACT

云端需要给谁什么，谁要返回什么

一条云端交互任务至少包含三份合同：Trigger到在线编排、在线编排到卡片、端侧执行回云端。

产品合同建议

A. Cloud Trigger → 在线编排：CloudAdvice

信息用途充电示例状态
task/instance/run_event/trace贯穿任务、推理、卡片、动作与日志charge_event_3001P0合同
Query/业务目标说明云端要完成什么，不只是传硬条件检查是否存在充电设备；若存在则询问是否开盖业务方向明确
硬条件快照为推理提供车辆上下文并支持审计切P、SOC≤20、口盖关闭、时间戳正式上行协议待定
有效期/幂等/优先级防止旧场景重复调用或晚到执行具体阈值TBD待定

B. 在线编排 → 即时交互卡：InteractionRequest

字段/信息为什么必须有充电示例状态

D. 端侧执行 → 云端/卡片：ActionResult

结果必须包含最终判定展示

06 · FIRST USE CASES

两类云端任务必须分开讲

后视镜验证“规则静默链”；充电口验证“推理＋交互链”。儿童锁不强行归类。

首批样例

样例A｜后视镜自动加热

链路：任务有效与状态上云 → Cloud Trigger命中三个P0规则之一 → 不出询问卡、不播TTS → 端侧复核 → 开启加热 → 真实状态回读。

为什么云端：8月27日会议明确先走云端；便利任务允许弱网时本次漏触发，策略迭代更灵活。

即时卡关系：当前没有授权卡。若需要结果告知，只能作为执行后的展示Profile，不能倒推出需要二次确认。

样例B｜识别充电设备后开盖

链路：端侧状态上行 → Cloud Trigger前置筛选 → 主动推荐Query → DT/VQA识别 → FOUND后即时卡询问 → Planner理解语音/点击事件 → 端侧复核 → 开盖 → 回读。

为什么云端：P档和低电量不能证明用户要充电，需要DT/VQA理解真实环境。

即时卡关系：承载用户授权；它不识别充电桩，也不直接打开口盖。

07 · EXCEPTIONS / ACCEPTANCE

异常与验收：云端失败只能保守结束

当前没有被确认的本地充电设备识别兜底，因此不能画成“云端失败后端侧自动开盖”。

不使用过期结果
编号场景预期结果主要责任证据
CA-01任务关闭但P档/SOC命中不创建云端任务，不调用DT任务状态+Cloud Trigger门禁日志
CA-02上行状态过期或UNKNOWN不命中，不把旧状态当当前状态状态上行+Cloud Trigger时间戳/质量日志
CA-03网络不可用本次不触发；任务开关保持，不自动端侧开盖端云联调断网测试
CA-04DT=NOT_FOUND不出执行确认卡，结束事件DT+在线编排DT结果与卡片日志
CA-05DT=UNKNOWN/ERROR/超时不宣称已识别，不执行DT+在线编排错误码和超时日志
CA-06卡片展示失败不获得用户授权，不执行VUI+在线编排CardAdmissionAck
CA-07用户语音“开吧”但卡片上下文缺失不得猜测；澄清或结束Planner/VUIContext关联
CA-08用户点击确认形成标准事件并让Planner知道卡片已消费VUI/事件上报/Planner点击事件与上下文同步
CA-09确认后驶离P档或口盖已打开端侧复核终止或按已达成收口端侧执行层最新状态
CA-10DT结果或用户授权已过期拒绝执行旧请求端侧执行层frame_time/valid_until
CA-11RPC成功但口盖仍CLOSED最终失败，不展示已打开车控+状态回读+VUIRPC与真实状态对照
CA-12后视镜规则命中后状态已ON不重复执行；记录已达成端侧复核最新目标状态

通过标准

可从Cloud Trigger事件追到Planner/DT、卡片、端侧动作和真实状态。

专项待定

状态上行Schema、确认位置、点击路由、DT/VQA合同、结果有效期、卡片仲裁。

禁止上线

UNKNOWN当FOUND、点击不回云端、云端结果无时效、端侧无复核、无真实状态回读。

“今天只讲云端系统预设任务框架，不直接评排期。云端任务分两种：后视镜是云端规则命中后静默下发端侧；充电口是在硬条件命中后，还要经过Planner和DT/VQA判断，再通过即时卡向用户确认。两种任务最后都必须回到端侧复核和车控。”

讲即时卡：
“云端卡仍在车机显示。云端给VUI的是一次InteractionRequest，里面必须有run_event、卡片内容、Planner上下文、语音和点击路由、DT结果引用与有效期。VUI返回展示ACK、用户选择和生命周期。语音由Planner结合卡片上下文理解；点击不需要模型理解，但必须同步Planner这张卡已经消费。”

讲安全收口：
“用户确认后，云端只下发执行授权，不直接控制车辆。端侧还要重新检查任务、P档、停稳、口盖和DT结果时效；只有真实口盖状态变为OPEN才更新卡片成功。”

现场只问这10个问题

  1. Cloud Trigger消费哪些状态？由谁上行，时间戳、UNKNOWN和重连快照怎么定义？
  2. Cloud Trigger向在线编排发送什么事件和Query？run_event由谁生成？
  3. Static Advisor、Planner和DT谁直接调用谁？请给唯一时序，不保留两套正式方案。
  4. 充电任务是先询问再调DT，还是FOUND后再询问？本稿建议FOUND后询问。
  5. DT/VQA请求、结果、frame_time、confidence、UNKNOWN和超时如何定义？
  6. 云端拉卡如何显式携带CLOUD_ADVISOR、Planner上下文和结果有效期？
  7. 语音如何带当前卡片上下文进入Planner？卡片过期后上下文如何注销？
  8. 点击是直接业务回调、模拟Query还是标准事件？无论选哪条，如何同步Planner已消费？
  9. 端侧执行前复核由哪个模块承接，失败如何回云端和卡片？
  10. 车控结果、真实状态和云端事件如何用同一trace收口？
你会后的交付：把会议选中的唯一链路、废弃链路、正式模块Owner和后续技术专项写回文档。你不需要替Planner、DT、VUI或赛力斯研发设计正式IDL。
