；C10=已在至少一个项目上交付落地。可做标准化交付，交付标准对应该 feature 对外准出测试集。；E10=默认按主线标准交付。项目侧需要提供协议、账号、知识、素材、测试环境和验收样车，按 SOP 完成配置映射、数据联调、准出测试和体验验收；如涉及车型硬件、车企接口、第三方生态或品牌话术差异，作为该功能下的“可配置 / 项目定制”项单独确认范围和排期。。

## 全表审阅后的边界与缺口

- 直接属于 F 的二级功能是 SOP-01～04，共 **4 条**；必要接入依赖与回指项 SOP-05～16，共 **12 条**。二者合计 **16 条**，不把重复出现在身份底座里的同名功能再计一次。
- 工作簿没有单列“Agent 准入”“工具定义管理”“动态工具”“Agent 注册”“指定工具快速测试”“取消协议”“幂等”“工具选择准确率”“灰度上线”这些同名二级功能；这些内容需用 F 原文补齐，不能伪称已在此工作簿逐项可量产。
- `【子功能】座舱工具集合!D61:J64` 的 4 条均标“内部预研”，不能从此前 Agent 管理平台已上线反推这 4 个产品总项都已量产；二级总项状态与具体历史实现状态分别记录。
- 车辆指令执行适配、车控/车设/通讯/媒体/导航等工具的能力边界主归 E；F 只取它们说明新工具定义该怎样写，不把工具家族全量清单重写一次。
- `【子功能】规则、知识与安全干预!D8:J8` 的“主动服务配置项”虽有灰度范围和关闭开关，但对象是主动服务配置，不能当作全部 Agent 通用灰度发布流程的原始依据。
- 模块宣讲计划只有模块、负责人和时间等索引，不构成二级功能状态。说明页区分“可量产=至少一个项目已落地”“可选=本期选配”“定制=一事一议”，三者不可混用。
