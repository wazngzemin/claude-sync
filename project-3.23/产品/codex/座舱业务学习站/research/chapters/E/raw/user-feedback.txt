AIDV 用户反馈技术方案
适用范围：对话卡片点踩、语音 AI 总结反馈。依据 PRD V1.3（2026-09-17）设计，供 AIDV、CDC、ADC/AIBOX、VSHD 联合评审。

核心结论
卡片反馈：全部预设标签（含“其他”）在卡片消失时按端侧最终状态处理；最终未点踩不提交，最终点踩由 AIDV 提交 VSHD。
语音反馈：report_id 生命周期由云端维护；提前下发 start_collect，用户确认后通过 Frontier 下发 submit，由 CDC 补齐日志与附件并提交 VSHD。
职责边界：Planner 只负责路由与最终播报，Issue Report Agent 负责状态和执行，Feedback Model 负责判断与动作决策；执行结果通过 tool feedback 返回 Planner。
范围与目标
目标
支持对话卡片全部预设标签的点踩与取消点踩；卡片消失时仅提交最终有效点踩，点赞由客户端自行处理。
支持用户通过语音主动反馈整车或智驾问题，最多追问 3 轮。
支持 AI 生成不超过 100 字的问题总结，由用户确认后提交。
支持卡片存续期间在端侧维护点踩状态，并在卡片消失时提交最终有效反馈；语音反馈提交幂等，取消时终止上传并删除已采集数据。
非目标
不定义 CDC、ADC、AIBOX 内部的日志采集实现。
不改变 VSHD 的工单处理和用户中心展示逻辑。

总体方案
系统架构：反馈能力由 Planner、Issue Report Agent、Feedback Model、issue_reports、/feedback/dislike、Frontier、CDC 和 VSHD 协同完成。Planner 负责路由与播报，Agent 负责流程编排、状态管理和幂等，Model 负责信息完整性判断与动作决策。
模型职责：Planner 仅向 Issue Report Agent 转发 query。Issue Report Agent 执行模型推理，负责信息完整性判断、澄清、总结分类和动作决策，并生成业务 Function Call；执行结果通过 tool feedback 返回 Planner 播报。
卡片点踩：卡片展示期间的交互仅由端侧维护。卡片消失时，最终未点踩则结束；最终点踩则携带完整 labels 调用一次 AIDV，AIDV 生成 report_id、落库并向 VSHD 提交一次。
语音反馈：“我要反馈问题”“导航有些问题”等输入由 Planner 路由给 Issue Report Agent。Agent 首次确认进入反馈流程后创建 report_id 并下发 start_collect，让 CDC 在澄清期间同步采集日志；描述清楚后由 Agent 生成分类、总结和 review。用户确认提交后才查询历史并组装 conversation_context，随后由端侧、CDC 完成数据汇总并提交 VSHD。
确认与取消：按钮点击、“可见即可说”和泛化语音均进入 Chat/Planner 语音链路。Planner 只转发 query 和请求上下文；Issue Report Agent 结合 input_scene、语义及云端维护的当前反馈任务判断是否生成 submit/cancel Function Call，并统一执行状态与幂等校验。

对话卡片点踩
处理规则
预设标签：支持多选，取有害/不安全、信息虚假、没有帮助、遗忘上下文、记忆使用不当、其他；最终提交时至少选择 1 项。
端侧交互：卡片展示期间，用户可以点踩、取消点踩或调整标签；端侧仅维护当前选择，不调用云端接口。
提交时机：卡片消失时读取端侧最终状态。最终未点踩时直接结束，不提交反馈；最终点踩时调用一次 POST /feedback/dislike，并提交完整 labels 集合。
目标回答：request_id 是端云对话协同标识，用于锚定被评价回答；AIDV 根据 request_id 和当前登录上下文查询目标回答、log_id 与上下文，并校验其属于当前用户和车辆。
幂等：同一 vehicle_id、request_id、source 只创建一条卡片反馈记录。接口重试返回已有结果，不重复落库或提交 VSHD。
VSHD 提交：AIDV 对最终有效反馈生成 report_id、组装完整 labels 与 conversation_context，并向 VSHD 提交一次。

语音 AI 总结反馈
核心流程
启动采集：Planner 将 query 转发给 Issue Report Agent。Agent 首次确认进入反馈流程后创建 report_id 并下发 start_collect；描述不完整时由 Agent 生成澄清 tool feedback，CDC 在此期间持续采集。
生成确认内容：信息完整后，Issue Report Agent 模型生成不超过 100 字的 summary 和 category；Agent 校验、持久化并下发 review，再将执行结果以 tool feedback 返回 Planner。
提交或取消：用户确认后查询反馈触发前最多 20 个已完成轮次，并汇总反馈触发语、Agent 追问和用户补充，组装 history 与 feedback_dialogue，再通过 Frontier 下发 submit；端侧/CDC 补齐用户、车辆、日志和附件后提交 VSHD。取消或超过 3 轮仍无法补齐时，停止采集并清理数据。

确认、取消与模型约束

活动任务定位
端侧后续请求不携带 report_id。Issue Report Agent 在当前 channel、vehicle_id、account_id 范围内，筛选 source=voice_feedback、report_status 为 COLLECTING/REVIEW_READY/CONTEXT_COLLECTING 且未过期的记录，按 created_at 倒序取最近一条；未命中活动任务时不执行反馈操作。
确认与取消：按钮、“可见即可说”和泛化语音统一进入 Chat/Planner，Planner 仅转发 query；按钮入口在 vehicle_biz_params 中携带 input_scene=button，“可见即可说”携带 input_scene=guiding，泛化语音可不传 input_scene。submit 仅允许 REVIEW_READY，cancel 仅允许 COLLECTING 或 REVIEW_READY；Agent 校验归属和状态，并按 report_id + action 幂等处理，终态冲突返回当前状态。
模型约束：Issue Report Agent 最多澄清 3 轮；summary 不超过 100 个汉字，只基于本次反馈描述与澄清内容，不新增用户未表达的事实。

字段承载与赋值链路
上面的 JSON 是 Agent 校验模型输出并执行业务动作后生成的逻辑结果，记为 agent_result。它不是 Feedback Model 的原始输出，也不是 Planner 最终下发给客户端的响应。Agent 将 agent_result 序列化后写入内部 ChatResponse 的 model_content；Go 结构体字段名为 ModelContent，JSON 字段名为 model_content。
Feedback Report Agent 内部 ChatResponse
{
  "content": "",
  "model_content": "{\"success\":true,\"action\":\"review\",\"report_id\":\"rpt_xxx\",\"status\":\"REVIEW_READY\",\"message\":\"反馈内容已整理，请确认是否提交\"}"
}
Planner 汇总工具响应时拼接各响应的 ChatResponse.ModelContent，并包装成 tool_name + tool_feedback 注入 Planner Model 上下文。其中 tool_feedback 的值等于汇总后的 model_content；tool_feedback 是 Planner 上下文字段名，不是 ChatResponse 字段。
注入 Planner Model 的工具结果
{
  "tool_name": "issue_report",
  "tool_feedback": "{\"success\":true,\"action\":\"review\",\"report_id\":\"rpt_xxx\",\"status\":\"REVIEW_READY\",\"message\":\"反馈内容已整理，请确认是否提交\"}"
}
Feedback Model 输出 action、reply、summary、category 等模型决策字段。
Issue Report Agent 解析并校验模型输出，结合服务端状态执行业务 Function Call，生成 agent_result。
Agent 将 agent_result 序列化并赋值给 ChatResponse.ModelContent，对应 JSON 字段 model_content。
Planner 将 ModelContent 汇总为 tool_feedback，并与 Registry 中的 tool_name 一起注入 Planner Model 上下文。
Planner Model 依据实际 tool_feedback 生成最终文本与 TTS，再由外层 ChatResponse 下发客户端。
约束：Feedback Model 输出协议中不定义 model_content；model_content 仅属于 Agent/Planner 框架的 ChatResponse 承载层。Agent 不得把未经校验、未经业务执行的 Feedback Model 原始 JSON 直接写入 model_content 返回 Planner。

Feedback Agent 返回与 Frontier 调用时序
model_content 是 Feedback Agent 每轮结束时返回 Planner 的结果载体；Frontier 仅在动作需要驱动车端业务状态时调用。调用 Frontier 后，Agent 仍须依据实际执行结果生成 model_content，不能在执行前向 Planner 宣称成功。

Agent 动作与业务 Function Call


动作

决策来源

Agent 行为

start_collect

Agent 检测到首次进入且无有效 report_id

创建 report_id 和最小任务并下发 start_collect。该动作不由 Feedback Model 输出。

clarify

Model 判断描述不足或语义不明确

不生成业务 Function Call，直接以 tool feedback 返回具体追问；最多 3 轮。

review

Model 判断描述完整

校验并持久化 summary、category，再下发 review。

submit

Model 识别明确确认

Agent 校验任务处于 REVIEW_READY 后执行 submit，组装 conversation_context 并通过 Frontier 下发 submit 业务指令。

cancel

Model 识别明确取消，或澄清超限/放弃

Agent 校验任务状态后执行 cancel，停止采集并清理任务数据。

校验、状态与幂等
Planner 侧只校验 issue_report 调用 envelope 和 query，不校验 Issue Report 业务 action 参数。
Issue Report Agent 校验模型 JSON、action 与字段组合；非法输出不执行部分字段，也不下发 Function Call。
同一反馈任务仅允许一次有效 start_collect；report_id 由 Issue Report 服务端生成。
review 仅在 summary、category 校验通过后下发；summary 不超过 100 个汉字。
submit/cancel 必须由云端按当前会话定位到有效的非终态 report_id，并校验归属和状态；按钮、“可见即可说”和泛化语音遵守同一规则，均不依赖端侧回传任务 ID。
业务侧按 report_id + action 幂等处理。终态冲突返回当前状态，不重复下发 Frontier、提交 VSHD 或清理 CDC。
Function Call 执行结果以 tool feedback 返回 Planner；Planner 只负责基于结果播报，不提前假定成功。

泛化语音

客户端按 report_id + action 幂等处理。同一 report_id 重复收到 start_collect 时不得重复创建采集任务，重复收到 review 时不得重复创建确认卡片。
Frontier Push 成功只表示消息已被 Frontier 接受，不等同于 CDC 已经开始或完成采集。
conversation_context 字段说明
conversation_context 按反馈来源区分两种结构。预设标签点踩遵循 AIDV 与 VSHD 卡片反馈协议，包含 history 与唯一 target_turn；语音反馈包含反馈触发前的 history，以及记录触发语、Agent 追问和用户补充的 feedback_dialogue。两种场景的 history 均使用相同的 Turn 结构。语音反馈的 conversation_context 不在 start_collect 或 review 中生成、下发，用户确认 submit 后再组装并交由端侧、CDC 提交 VSHD。

history：最多 20 个已完成轮次，按时间升序排列；卡片点踩取 target_turn 之前的轮次，语音反馈取反馈触发之前的轮次。没有历史时传空数组，反馈过程不写入 history。

target_turn：仅用于预设标签点踩，表示被点踩的唯一目标轮次，并与 history 使用相同的 Turn 结构；语音反馈使用 feedback_dialogue 表达多轮澄清，不要求 target_turn。
query / answer：query 与 answer 均为 string，分别保存该轮用户输入和向用户展示的文本回答；纯图片回答允许 answer 为空字符串。
sound_zone：sound_zone 不属于 conversation_context；如其他业务链路需要，应在该链路既有字段中传递。
output_resources：回答产生的图片统一写入 output_resources；Resource 仅包含 resource_type 和 url，当前 resource_type 固定为 image，没有图片时省略 output_resources。
Widget、FunctionCall、Planner observation 和 tool feedback 不纳入反馈历史。
conversation_context 通过 ChatResponse、Frontier 和 ThirdAgent 通道传输；总大小、字段长度和资源数量使用通道配置限制，超限时返回 INVALID_ARGUMENT。
预设标签点踩使用 account_id 作为 AIDV 内部归属键；提交 VSHD 的 userid、PDID、VIN 由 AIDV 从请求上下文补齐。语音反馈同样使用 account_id 定位云端任务，VSHD 所需 userid、PDID、VIN 由语音客户端或 CDC 在提交前补齐。account_id 与 VSHD userid 是不同协议字段，不做直接等值映射。

卡片点踩落库规则
卡片反馈仅在卡片消失且最终状态为点踩时创建记录。AIDV 生成 report_id，保存归一化后的完整 labels 和 conversation_context，并提交 VSHD；卡片展示期间的本地状态不写入 issue_reports。
唯一键：使用 vehicle_id、request_id、source 定位唯一记录；channel 和 account_id 用于归属校验。
创建：首次请求插入完整卡片反馈记录并提交 VSHD。
重试：唯一键冲突时读取并返回已有记录，不更新 labels，不重复提交 VSHD。
关键约束
幂等：语音反馈的 start_collect、review、submit、cancel 以 report_id + action 去重；卡片反馈以 vehicle_id + request_id + source 保证创建幂等，AIDV 与 VSHD 均不得生成重复反馈。
归属校验：request_id、log_id 必须属于当前 channel、vehicle_id、account_id；语音反馈 report_id 由云端按归属、时间和状态查询 issue_reports 取得，并再次校验任务状态。
隐私：日志不打印对话正文、用户身份、PDID 和附件地址。
观测：记录意图识别、Frontier 下发、上下文组装和最终操作结果，使用统一 Trace 与指标基础设施；观测失败不得阻塞反馈主链路。
验收标准
卡片展示期间的点踩、取消点踩和标签调整均只改变端侧本地状态，不调用 AIDV 或 VSHD。
卡片消失时，最终未点踩则不提交；最终点踩则携带 request_id 和 1 至 6 个不重复标签调用一次 /feedback/dislike，AIDV 组装上下文并向 VSHD 提交一次。
同一业务键的接口重试返回已有 report_id 和提交结果，不重复落库或提交 VSHD。
Issue Report Agent 首次确认进入反馈流程后立即生成 report_id 并下发一次 start_collect；信息不足时最多澄清 3 轮，完整后生成并下发 review。
Planner 仅转发 query；Issue Report Agent 执行模型推理，生成 summary/category 和业务 Function Call。
按钮、“可见即可说”和泛化语音统一经 Planner 转发给 Issue Report Agent；端侧不回传 report_id，Agent 按当前用户/车辆、source、非终态、未过期和 created_at 倒序定位最近一条活动任务后判断 submit/cancel，并校验归属、状态和幂等。
语音反馈后续轮次始终复用按时间和状态筛选出的最近一条非终态 report_id；进入 SUBMITTED、CANCELED 或 EXPIRED 后不再命中，下一次反馈生成新的 report_id。
预设标签点踩在卡片消失后通过 /feedback/dislike 提交最终有效状态，AIDV 组装 history 与 target_turn 并提交 VSHD；语音反馈的 review 不收集上下文，确认 submit 后组装 schema_version、history 与完整 feedback_dialogue，并通过 Frontier 下发 submit，端侧/CDC 补齐日志和附件后提交 VSHD；cancel 停止采集并清理。
联调约束

语音端侧或 CDC 在提交 VSHD 前补齐 userid、PDID、VIN，字段类型统一为字符串；日志输出按隐私规范脱敏。
确认与取消统一使用 ChatRequest 进入 Planner；业务执行结果通过 tool feedback 返回，文本与 TTS 必须与实际结果一致。
input_scene 放在 AgentPayload.ext.vehicle_biz_params 对应的 VehicleBizParam JSON 中；端侧不注册或透传 issue_report_id，Issue Report Agent 按当前用户/车辆、时间和状态从 issue_reports 查询最近一条非终态 report_id。
function_code 固定为“问题和建议反馈”；Issue Report Agent 执行 start_collect、review、submit、cancel Function Call。
卡片反馈仅在卡片消失且最终状态为点踩时提交；VSHD 按 report_id 幂等处理重试，不创建重复反馈。
