# 系统预设任务｜产品负责人视角复审与修改记录

> 日期：2026-09-14 · 对应PRD：评审完善V2.0  
> 本记录用于展示独立质疑、修改和剩余证据，不属于正式需求正文，不代表实际产品负责人或各团队已批准。

## 1. 为什么上一版仍不足以过产品负责人评审

上一版侧重“各模块如何交接、怎样不误执行”。这些必要，但不足以证明项目值得做。三名独立审核Agent分别从产品负责人、四项场景体验、平台投入与复用审查V01及上传原稿，均指出：动作成功与用户收益混用，主动服务相较原有操作的新增价值未论证，关键策略缺推荐理由，平台收益没有可验证的边界。

所以本轮不是增加更多状态字段或更复杂的图，而是修改正文的产品判断。已认可的三段Mermaid及原图保留；图下模块交接、四任务案例和原有44条功能验收继续作为实现依据。

## 3. 负责人最可能追问的六个问题

### 3.1 “你说减少操作，用户仍要点确认，真的更省事吗？”

现在不能说已经证明。充电任务想减少的是留意场景和寻找入口，不是声称比所有直接语音都快。需要对照实车原入口，看用户是否少了步骤，还是多等了一次识别和弹卡。若后者成立，就调整候选或交互，不能用开盖成功率替代价值。正文依据：1.2、6.3、B01/B02。

### 3.2 “四个任务都要写业务代码，做平台有什么用？”

第一次接新信号、识别、卡型、车控仍需研发。平台要减少的是接通以后反复改阈值、文案、范围和已支持策略时重接无关模块。R01/R02会验证这一点；如果改文案还要重写回调，就不算完成本次复用要求。天气端侧现有发版不计作云端平台复用成绩。正文依据：4.13、7.5。

### 3.3 “儿童锁这么多待定，你有自己的建议吗？”

有。当前先按变化补查和询问进行走查：补查覆盖切D后才出现的目标，询问让用户纠正对象或侧别，但两者分别增加判断和注意成本。若需求明确要求自动处理，就必须确认预授权、误识别后果和目标侧，而不是研发临时删掉确认。正式选择需D06会签，当前示例不能当批准。正文依据：6.2、8.1。

### 3.4 “为什么充电不直接用低电量和P挡开盖？”

它们只说明值得检查，不能说明用户准备充电。设备观察也不能代替同意。推荐先观察再问，避免无设备时多问一次；但这会增加部分无转化调用，需要用正反停车样本检验筛选范围。已有明确开盖指令走原指令链路，本任务不要并行再问。正文依据：1.4、6.3、B02。

### 3.5 “什么情况下你认为这个项目不该继续放量？”

授权失效仍操作或错误报成功，暂停受影响分支排查；链路正确但长期推荐不相关、用户常纠正或原入口更省事，也不应该只追展示和执行次数，要收窄或修正策略。具体目标和观察窗口应在试用前约定。正文依据：1.5、7.5。

### 3.6 “这版能不能直接排开发、上线？”

产品方案讨论、开发准入、受控发布是不同决定。现在可以讨论固定阶段范围、任务建议和验证计划；各分支开发仍需唯一策略与责任认领；实车发布需参数、许可、执行限制和关键反例验证。不能把Agent审过当成真实团队批准，也不能让未定的高湿窗口阻塞所有独立工作。正文依据：8.1、8.2。

## 4. 修改后的第二轮复核

第二轮由原三名审核Agent直接阅读V02，检查第一轮发现是否解决，以及新增建议是否与已有图、配置、案例和验收冲突。共提出9条意见，合并重复的儿童案例问题后为8项；主稿逐项修复，三名Agent再分别定点回读确认。

| 第二轮发现 | 最终修复位置与内容 | 回读结果 |
|---|---|---|
| 推荐A补查却只详细演示B切D | 6.2.1改为切D时未知、之后有效识别启动补查；新增C04，B仅比较覆盖限制 | 负责人／场景两名审核分别确认对应 |
| 观察许可只停留在论证 | 4.6/4.11接入前提、5.1图前条件、5.2交接、6.3.3步5、D09、V03全部对齐 | 负责人审核确认闭合，不代表实际许可已取得 |
| 加热摘要“用户优先”缺约束 | 8.1明确车辆允许范围、既有安全／热保护及其他有效原因不被覆盖 | 负责人审核确认与6.4一致 |
| 分批UI可能被理解成删需求 | 4.13补首批核验替代、不可延期保护与最终验收；D03补批次会签 | 平台审核确认不是任意延期 |
| R03被误计为复用证据 | 7.5区分R01/R02规则内容复用与R03发布保护；要求真实配置消费模块，模拟仅替换输入／车控 | 平台审核确认，没有用Demo冒充复用 |
| 不重问缺保存与检查 | 4.8抑制项、5.9业务保存和候选前检查、I08区分新编号事件与同持续场景 | 场景审核确认策略有消费方 |
| 询问升级静默沿用旧许可风险 | 5.8范围变化确认、D01/D03、S06规定未确认不启用新增行为 | 场景审核确认，仍须实际接入会签 |
| “业务成功”与用户价值混淆 | 图二说明和7.2统一为车辆动作目标达成，7.5另验价值 | 场景审核确认术语一致 |

本轮保留原有44条功能验收，新增C04、I08、S06、V03共4条，合计48条；另有B01—B06业务验证、R01/R02复用和R03发布保护验证。条数不是质量评分，新增用例仅用于覆盖本轮实际发现。

**最终审核判断：** 原来缺失的产品推荐、取舍、价值验证已进入正文；上述8项文稿一致性问题已闭合。尚不能把真实用户收益、现平台能力和投入说成已验证，也不能保证实际负责人通过。这里的Review结论是“已修正文稿缺陷，剩余问题明确为证据与会签”，不是“项目可以直接上线”。
