# 背景 & 目的

展车模式为独立交互场景。车辆进入展车状态后，豆包汽车交互逻辑区别于日常模式：整体对话风格偏向展厅接待、产品介绍等；本文档定义展车引导 Director 链路的独立场景能力，包括独立系统提示词、独立工具集与独立条件任务体系，和日常用车模式完全隔离，作为产品、研发与测试的协同依据。

# 触发条件

- 收到赛力斯下发的**展车模式开启信号**，切换至展车专属场景；
- 收到**关闭信号**，切回日常模式；
- 展车模式（Showroom Mode）下：车辆前视摄像头持续捕捉车外画面并输入 VLM 大模型分析，车机保持低功耗运行，动力系统锁定；
- 试驾模式联动：进入试乘试驾模式时强制退出展车模式；试驾结束（手动退出或车辆下电自动结束）后按信号切回对应模式。

# 核心配置（全套独立，和日常模式分开）

1. Director 系统提示词（独立一套，控制接待人设、应答策略等）<mention-user id="ou_2b3e6e85766bc9e632c349ec03bdefd5"/>
1. 可用工具集（基于主链路dt工具清单独立裁剪，限制可用工具）
1. 条件任务（独立配置）
	- 独立的欢迎 / 打招呼任务
	- 独立的条件触发任务：所有展车场景需要的自动触发任务，全部条件、触发规则、执行动作单独维护，不复用日常模式条件任务。

# 切换规则

- 进入展车模式：加载整套展车专属配置（提示词 + 工具列表 + 独立条件任务集）
- 退出展车模式：卸载展车全部配置，恢复日常模式的提示词、工具、条件任务
- 两套任务体系互相隔离，参数、触发逻辑互不影响

## Director 系统提示词

展车引导 Director 在展车场景下使用独立sp，控制接待人设与应答策略，人格特性定义参考：<mention-doc token="MCDHwf2YbimWC9kvEPccfT75nPt" type="wiki">AI展车语音Agent人格特性定义</mention-doc>。具体要求：

- **角色设定**：展厅接待顾问人设，对话风格偏向展厅接待、产品介绍，区别于日常用车模式；
- **话术风格**：克制、平实，避免过度推销感；内容有意义、简洁、正确，保持“说做一致”（内容与动作一致、节奏一致）；
- **边界控制**：客观陈述事实，不夸大参数、不贬低竞品；价格、金融政策等敏感商务信息不答复，引导用户咨询现场销售顾问；
- **音色适配**：根据客户画像匹配音色参数（如家庭用户温和语速、年轻用户轻快活泼语调）；
- **语气与表情**：沿用 Director 交互规范，支持语气标签（如[开心地说]）与表情（emoji_id）输出，下游按标签选择播报工具。
- **KnowHow：**由赛力斯负责输入展销领域的“专业经验”，包括：客户诉求识别、竞品对比策略、价值导向推演、试驾路线规划逻辑、促单话术等。

## 条件任务

展车场景加载独立条件任务体系，全部条件、触发规则、执行动作单独维护，与日常模式条件任务完全隔离、互不复用。

### 独立欢迎 / 打招呼任务

- **触发时机**：展车模式下，用户上车稳定后（车辆静止、安全带未系、车门关闭），自动播放迎宾话术；迎宾话术仅在用户首次上车时播放一次；
- **话术生成**：基于客户画像（身份识别结果 + 亮点清单调取结果）生成展销专属语境与音色，进行针对性问候与功能引导；
- **拒绝处理**：用户明确拒绝（如“我自己看”）后，话术调度暂停，界面切换为静态亮点视频介绍，调度在 3 秒内停止；
- **重唤醒逻辑**
	- 指示性意图唤醒（强依赖实时上下文）：如“帮我讲解一下这个功能”，Director 结合静默期隐性上下文（中控停留页面、视线焦点、最近操作）进行实体绑定，输出该功能专属讲解与操作指引；
	- 探索性意图唤醒（全局状态恢复）：如“这车有什么亮点”，执行断点继承策略，优先从会话快照上次中止的亮点节点顺延播报；全新看车周期则结合画像重新抽取核心条目按序播报。
