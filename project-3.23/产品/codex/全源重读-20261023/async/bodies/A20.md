## 需求点提炼

- 支持系统预设场景：

    - 透出给任务中心展示，默认全渠道开启，支持用户按需启用或关闭

- 支持混合判定：预设场景需要通过条件触发\+推理触发，混合判定本期不支持定时

    - 推理触发来源：VLM低频、高频数据上报

    - 条件触发来源：端状态上报、账号配置类开关（AI主动服务开关）

- 接入主服务即时卡片功能：

    - 预设场景的下游主动服务链路，需要复用主服务即时卡片功能由用户确认

### Workflow定义校验

1. 校验 `node\_id` 非空且在 Workflow 内唯一；每个 union（条件触发参数or推理触发参数） 必须且只能设置一个配置字段。

2. 校验 `join\_type` 只能为 `AND` 或 `OR`，未传时补为 `AND`；Source 节点固定按 AND 处理，OR 节点必须至少有两个直接前驱。

3. 校验边两端节点存在、禁止自环和重复边；使用 **Kahn 算法执行拓扑排序，排序数量小于节点数量时判定有环**。

4. 校验 Workflow 只能有一个终点节点；所有节点必须能从至少一个 Source 到达，并且最终能够到达该终点节点。

### DAG 调度逻辑

#### 状态与运行时结构

```go
// ExecutionStatus 描述 NodeRun/WorkflowRun 的执行阶段
// Scheduler 只允许按状态机单向推进，FINISHED、FAILED、SKIPPED 为不可逆终态
type ExecutionStatus string

const (
    StatusPending  ExecutionStatus = "PENDING"
    StatusReady    ExecutionStatus = "READY"
    StatusRunning  ExecutionStatus = "RUNNING"
    StatusFinished ExecutionStatus = "FINISHED"
    StatusFailed   ExecutionStatus = "FAILED"
    StatusSkipped  ExecutionStatus = "SKIPPED"
)

// Result 描述节点判定或 Workflow 聚合后的业务结果
type Result string

const (
    ResultPass    Result = "PASS"
    ResultReject  Result = "REJECT"
    ResultUnknown Result = "UNKNOWN"
)

// NodeRuntimeState 是单个节点在本次 run_id 下的内存状态
// 初始化时由 trigger_workflow_node_run 构建；仅调度协程可以修改，
// 每次修改必须先通过 WorkflowRunStore CAS 落库，再同步到该结构。
type NodeRuntimeState struct {
    NodeID      string
    Status      ExecutionStatus
    Result      Result // FINISHED/FAILED 时有效
    BlockedBy   Result // SKIPPED 时为 REJECT 或 UNKNOWN
    Reason      string
    StartedAt   time.Time
    FinishedAt  time.Time
}

// NodeFinishedEvent 是 worker 返回给调度协程的唯一事件
// worker 不直接推进后继节点；正常返回写入 Output，panic、超时或 基础设施错误写入 Err
// 由调度协程转换为 FINISHED 或 FAILED。
type NodeFinishedEvent struct {
    NodeID string
    Output NodeOutput
    Err    error
}

// DAGRuntime 保存一次 WorkflowRun 的内存调度上下文
// Runner 在 T1 提交后创建该结构；生命周期仅覆盖本次 Run，不能跨 run_id 复用
// EventCh 汇聚所有 worker 的完成事件。
type DAGRuntime struct {
    RunID      string
    Graph      *CompiledWorkflow
    States     map[string]*NodeRuntimeState
    ReadyQueue []string
    Running    int
    EventCh    chan NodeFinishedEvent
}

// Scheduler 是 DAG 调度器
type Scheduler struct {
    Executors  map[NodeType]NodeExecutor // 保存节点类型到执行器的映射
    MaxParallelism int                  // 单次 WorkflowRun 最大并发节点数，默认值设为5
    Store      WorkflowRunStore         //NodeRun/WorkflowRun 的持久化与状态 CAS
}

// NodeTransition 是一次节点状态 CAS 的完整写入参数
type NodeTransition struct {
    RunID      string
    NodeID     string
    From       ExecutionStatus // 数据库更新条件
    To         ExecutionStatus // 目标状态
    Result     Result
    BlockedBy  Result
    Reason     string
}

// WorkflowRunStore 隔离调度逻辑与 GORM/数据库实现
type WorkflowRunStore interface {
    // TransitionNode 仅在当前状态等于 From 时更新并返回 swapped=true
    // err != nil：数据库访问或事务执行失败，需要按数据库错误处理或重试。
    // err == nil && swapped == true：状态转换成功，可以继续后续调度。
    // err == nil && swapped == false：没有数据库错误，但节点当前状态已经不是 From，本次事件已经过期，应直接忽略。
    TransitionNode(ctx context.Context, tx NodeTransition) (swapped bool, err error)
    // FinishWorkflow 在全部节点终态后写入 WorkflowRun 的最终状态和结果
    FinishWorkflow(ctx context.Context, runID string, status ExecutionStatus, result Result, reason string) error
}
```

- 各状态标识

    - `FINISHED` 表示执行器正常返回，结果是： PASS、REJECT、UNKNOWN

    - `FAILED` 表示执行基础设施异常，结果固定为 UNKNOWN

    - `SKIPPED` 表示节点未执行，使用 `BlockedBy` 记录由 REJECT 或者 UNKNOWN 阻断

**前驱汇聚规则**：`join\_type` 配置在目标节点上，默认值为 `AND`。

- AND 节点在全部前驱 PASS 后进入 READY，任一前驱 REJECT 时立即 SKIPPED；全部前驱终态且无 REJECT、存在 UNKNOWN 时按 UNKNOWN 跳过。

- OR 节点在任一前驱 PASS 后立即进入 READY；只有全部前驱终态且没有 PASS 时，才按 UNKNOWN 优先于 REJECT 的顺序进入 SKIPPED。

**Workflow 结果**：Workflow 只能有一个终点节点，最终结果直接取该节点的有效结果。终点 FINISHED 时使用节点结果，FAILED 按 UNKNOWN 处理，SKIPPED 时使用 `BlockedBy`

#### 调度伪代码

```go
// Schedule 驱动一次 WorkflowRun 的节点派发、状态推进和结果收敛。
func (s *Scheduler) Schedule(ctx context.Context, rt *DAGRuntime) (Result, error) {
    // enqueue：将起点节点加入 READY 队列；起点已在 T1 中初始化为 READY。
    enqueue(&rt.ReadyQueue, rt.Graph.Sources...)

    // allTerminal：判断全部 NodeRun 是否都已进入 FINISHED、FAILED 或 SKIPPED。
    for !allTerminal(rt.States) {
        // hasCapacity：判断 Running 数量是否小于 MaxParallelism。
        for hasCapacity(s, rt) && len(rt.ReadyQueue) > 0 {
            // pop：从 READY 队列头部取出一个待执行节点。
            nodeID := pop(&rt.ReadyQueue)

            // transition：通过数据库 CAS 将节点从 READY 原子更新为 RUNNING；
            // 只有抢占成功的调度器才能执行该节点。
            swapped, err := s.transition(ctx, rt, NodeTransition{
                RunID: rt.RunID, NodeID: nodeID,
                From: StatusReady, To: StatusRunning,
            })
            if err != nil {
                return ResultUnknown, err
            }
            if !swapped {
                continue
            }

            rt.Running++
            // executeAndReport：异步调用对应 NodeExecutor，结束后向 EventCh 发送完成事件。
            go s.executeAndReport(ctx, rt, nodeID)
        }

        if rt.Running == 0 && len(rt.ReadyQueue) == 0 {
            // markSchedulingStalled：将无法继续调度的遗留节点按 UNKNOWN 收敛。
            if err := s.markSchedulingStalled(ctx, rt); err != nil {
                return ResultUnknown, err
            }
            continue
        }

        select {
        case event := <-rt.EventCh:
            rt.Running--

            // persistTerminalState：把完成事件持久化为 FINISHED 或 FAILED；
            // 返回 false 表示节点已被超时收敛，本次迟到事件直接忽略。
            applied, err := s.persistTerminalState(ctx, rt, event)
            if err != nil {
                return ResultUnknown, err
            }
            if !applied {
                continue
            }

            // advanceSuccessors：根据后继节点的 JoinType 汇聚其全部直接前驱；
            // AND：任一 REJECT 则 SKIPPED，全部 PASS 则 READY；
            // OR：任一 PASS 则 READY，全部终态且无 PASS 时才按 UNKNOWN/REJECT 收敛。
            if err := s.advanceSuccessors(ctx, rt, event.NodeID); err != nil {
                return ResultUnknown, err
            }

        case <-ctx.Done():
            // markWorkflowTimeout：使用独立短 Context 收敛超时节点；
            // RUNNING→FAILED，PENDING/READY→SKIPPED，结果按 UNKNOWN 聚合。
            if err := s.markWorkflowTimeoutWithDetachedContext(rt); err != nil {
                return ResultUnknown, err
            }
        }
    }

    // aggregateResult：Workflow 只有一个终点节点，直接取该节点的有效结果；
    // FINISHED 使用节点结果，FAILED 按 UNKNOWN，SKIPPED 使用 BlockedBy。
    result := aggregateResult(rt.Graph.Sinks[0], rt.States)

    // retryFinishWorkflow：重试 WorkflowRun 最终状态写入，不重新执行任何节点。
    if err := retryFinishWorkflow(s.Store, rt.RunID, result); err != nil {
        return result, err
    }
    return result, nil
}
```

- 配置复用 `scene\.InferenceParams`，由 `goal` 和 `original\_query` 描述判定目标。

- 模型响应包含“达成”时返回 PASS，明确未达成时返回 REJECT；推理配置或 VLM 输入缺失、`doubao\.Stream` 调用失败、流读取失败、响应无法解析或执行超时返回 UNKNOWN
