# AI汽车自建平台化链路

# 背景

AI汽车业务在产品迭代与技术攻坚的过程中，积累了诸如Planner\-MutiAgent架构、Context管理\&amp;构建、长短期记忆、音频处理等具有使用价值的核心能力，为座舱场景下用户的复杂需求与智能化体验提供了强大的支撑。汽车团队期望能把这些技术积累沉淀出一套平台化的架构，为团队的ToB智能座舱、具身智能等业务提供更好的支撑。

但目前AI汽车业务依托豆包端云链路构建，无法直接应用于其他非豆包IP的业务场景，故而需自建一套端云音视频链路，实现技术能力的平台化应用与跨业务适配。 

# 当前链路介绍

# 为什么要自建链路

豆包车机端与手机端的业务在部分场景下存在差异：

- 功能范围不同，手机端音视频能力与Agent能力相对隔离，车机端需要融合。

    - 在手机的场景中，音视频功能属于相对封闭域的功能，更多的是闲聊、联网等直接对话的场景，不具备很多主Bot可用的Agent能力，如：生图、搜视频等。用户会通过点击按钮的方式明确地打开、关闭该功能。在车机的场景中，用户几乎只有音视频一种使用方式，但系统需要具备车控、POI导航、S2S等不同类型Agent的能力。

- Agent编排方式不同，手机端由意图决定Agent，车机端需要由Planner调度多个Agent并汇总。

    - 在车机的场景中，由Planner对用户的query进行分析与任务拆解，并调度不同的Agent进行处理，再由Planner根据任务执行情况进行总结并反馈给用户。因此需要将语音S2S能力、视频VLM能力都挂载在Planner之后。在当前的链路中，S2S、视频能力与主Bot的Agent能力只能进行二选一的决策，无法承接一些复杂的问题，如【帮我打开空调，并介绍下它的工作原理】（当前通过纯文本接入s2s的方式解决，但存在局限性）。

- RTC通道问题，手机端不存在音区的概念，车机端需要明确区分。

    - 在车机场景中，需要明确地感知Query的来源音区（主驾、副驾、二排左/右等），因此需要开多路RTC通道来实现，就会带来成本高、房间池消耗大等问题。同时用户在开车的过程中，通常并不会长时间地和车机进行对话，会存在连接资源浪费的问题。

**自建链路与当前豆包链路的体验差异主要集中在以下几个方面：**

1. 当前链路下的视频类功能（视频通话、影视剧搭子等）与Planner主链路的体验有以下差异：

    1. 人设与Planner的人设有区别，主要体现在性格情感、回复话术方面。

    2. 无法作为Agent被Planner调度，无法支持复杂任务，比如：【屏幕共享中】帮我找一下这个演员相关的视频、帮我播放剧里的这段BGM。

2. S2S类功能有体验缺陷：

    1. 当前链路不具备唱歌能力（背景是S2S主模型的唱歌能力有退化，S2S团队把模型的唱歌能力独立出了唱歌Tool，暂时只支持音频Input，预计在Q2\~Q3支持文本Input）。

    2. 文本S2S模型存在联网意图的Badcase，S2S团队对音频Input做了优化。

3. 时延方面，豆包RTC链路建联时间长（秒级），在交互过程中首次使用到云端VLM类功能时，会感受到明显的延迟。

**Follow豆包新功能成本对比**：

当前链路与自建链路要Follow豆包新功能都存在成本，差异体现在以下几个方面：

1. 手机豆包迭代了新的Agent能力（天级别）：

    1. Agent对接方面无成本差异，两套链路都需要座舱直接对接Agent系统。

    2. 端云对新Agent数据结构的适配方面，自建链路比当前链路高1\~3PD。

2. 手机豆包升级了架构（周级别）：

    1. 当前链路端云都需要基于豆包的节奏做改造与升级，可能存在跨多版本升级、引入非必要模块等问题。

    2. 自建链路座舱团队可以评估哪些能力是车机需要有的，做选择性升级。

# 模块设计

## vehicle\.model\.gateway

### 模块架构

**各模块职责介绍**

- **WSHandler**：维护端云连接，pb类型数据的解析和转换。

- **EventHandler**：车端上报的事件信息的接收。

- **BizAdapters**：链式结构，负责一些轻量级的必要数据的获取，如：业务会话id的获取，用户登录态token的解析等。通过channel加载对应的Adapter做业务隔离。

- **Invoker**：负责与AIDV服务的实际交互，请求、响应数据的收发。

### 端云连接设计

**方案一：轮次级长链**

每轮对话都由建联开始，断连结束。

**✅方案二：会话级长链**

一次建联过程，多轮对话交互。

**方案对比：**

会话级方案在设计上更适用于连续交互的场景，能充分利用连接，减少建联时端侧的性能、CPU损耗。但相较于轮次级方案，有以下问题需要解决：

- 不同轮会话共用一个连接和logid，需要系统识别轮次信息。

    - 解决方案：

        - 端侧增加requestID标识，同一轮对话的上下行数据使用同一个requestID。

        - 云端基于requestID识别并下发轮次信息，生成轮次级LogID进行日志等数据的上报。

    - 负面影响：

        - 建联时期的日志等信息在默认logID上，上下行交互的日志在轮次级logID上。

- 服务端发版升级时，对于活跃的连接需要做到无损的体验。

    - 解决方案：

        - 云端感知优雅退出信号，在当前轮次回复结束后，主动下发重连信令。

        - 端侧接收到重连信令后，保持音频采集状态，立刻断连并进行重连。

    - 负面影响：

        - 发版期间，其他节点短期内的连接数会上涨，需增加连接数量监控进行监控。

- 端侧需要维护静默断连机制，避免资源浪费。

## vehicle\.model\.aidv\_rpc

- Core是核心能力部分，定义与实现各个模块通用的逻辑，可以定制的部分抽象成接口。

- BizAdapter是业务定制部分，通过参数进行业务区分，差异化地实现Core部分定义的接口。

- BizServer是业务子能力部分，由各个业务系统实现并提供RPC接口供调用。

## 协议内容

```ProtoBuf
// 上行消息体
message UpFrame {
  uint32 event_id = 1;
  string request_id = 2;
  CommonInfo common_info = 3;

  oneof payload {
    SessionConfFrame session_conf = 10; // 会话级别配置
    TextFrame text_data = 11;       // 文本帧
    AudioFrame audio_data = 12;       // 音频帧 
    VideoFrame video_data = 13;       // 视频帧
    CommandFrame command_data = 14;      // 指令帧
  }
}

// 下行消息体
message DownFrame {
  uint32 event_id = 1;
  string session_id = 2; // 仅event_id=SESSION_STARTED时存在
  string request_id = 3;
  string inner_log_id = 4; // 轮次级logId，格式为：logId_roundId
  ContentType content_type = 5; // 下行数据类型


  oneof payload {
    Error error = 10;        // 错误帧
    TextFrame text_data = 11;  // 文本帧
    AudioFrame audio_data = 12;    // 音频帧 
    Observation observation = 13; // 工具/插件内容帧，结构化输出插件调用结果
    WidgetFrame widget_data = 14;  // 桌面卡片 
  }
}

// 通用数据体
message CommonInfo {
  string sound_zone = 1; // 说话人音区，可选值：主驾、副驾、左后、右后
  Location location = 2; // 位置信息
  float car_heading = 3; // 车头朝向，单位是度，定义与正北方向为0度，超过360不处理
}

// 位置信息
message Location {
  float longitude = 1; // 经度
  float latitude = 2; // 纬度
  string province = 3; // 省份
  string city = 4; // 城市
  string district = 5 ; // 区县
  string coordinate_system = 6; // 坐标系标识
}

// 建连配置
message SessionConfFrame {
  string session_id = 1;
  float speech_rate = 2; //TTS 语速，默认1.0，范围[0.5,2.0]
  string speaker = 3; //TTS 发音人，默认"zh_female_vv_uranus_bigtts"
  string format = 4; //音频格式["pcm","opus"]
  string emotion = 5; // TTS 情感
  string character = 6; // 人设名称
  bool is_reconnect = 7; // 是否是重连的StartSession，如果是则不需要传配置信息，云端会使用重连前的配置
  string language = 8; // TTS 语种，映射火山 explicit_language
  string dialect = 9; // TTS 方言，映射火山 explicit_dialect
}

// 文本帧数据
message TextFrame {
  string content = 1;
  bool is_finish = 2;
  string tool_name = 3;
  string extra = 99; // 评估后使用，避免乱用堆积太多内容
}

// 指令帧数据
message CommandFrame {
  string content = 1;
  CommandType command_type = 2; 
  META meta = 3;
  string extra = 99; // 评估后使用，避免乱用堆积太多内容
}

// Command类型
enum CommandType {
    UNKNOWN = 0;
    VEHICLE_CONTROL_EXEC_RESULT = 1;
    CLIENT_INTERRUPT = 2;
    RECOMMEND_EXEC_RESULT = 3;
}
// ContentType类型
enum ContentType {
    CONTENT_TYPE_UNKNOWN = 0;
    TEXT = 1; //文本
    WIDGET = 2; //卡片
}

// Command类型
message META {
  string ip = 1; // aidv实例IP
  string port = 2; // aidv实例IP 对应 端口号
}

// 音频帧数据
message AudioFrame {
    bytes audio_chunk = 1; // 音频内容
    string extra = 99; // 评估后使用，避免乱用堆积太多内容
}

// 视频帧数据
message VideoFrame {
    bytes video_chunk = 1; // 视频帧内容
    VideoFrameMeta video_meta = 2; // meta信息
    string extra = 99; // 评估后使用，避免乱用堆积太多内容
}

// 视频帧meta信息
message VideoFrameMeta {
    int32 width = 1;
    int32 height = 2;
    int64 timestamp = 3;
    VideoFrameFormat format = 4; // 视频帧格式
}

// 视频帧格式信息
enum VideoFrameFormat {
    UNKNOWN = 0;
    PNG = 1;
    JPEG = 2;
}

// 结构化数据
message Observation {
    string tool_name = 1; // 工具名称，根据tool_name选择解析data的结构体
    string data = 2;
    // 拒识
    // tool_name = rejection 
    // data =  "{\"rejection\":true}"; // 拒识标志，true表示拒识，false表示不拒识，并且此时content返回输入文本
    
    // 打断
    // tool_name = interrupt
    // data = "{\"interrupt_scene\": \"xx\"}" // 打断场景
    
    // 简单query仲裁
    // tool_name = arbitration
    // data = "{\"simple\": true}" // true标识简单query
}

// 卡片帧数据
message WidgetFrame {
  WidgetType widget_type = 1;
  string widget_data = 2;
}

// WidgetType 类型
enum WidgetType {
    WIDGET_TYPE_UNKNOWN = 0;
}
```
