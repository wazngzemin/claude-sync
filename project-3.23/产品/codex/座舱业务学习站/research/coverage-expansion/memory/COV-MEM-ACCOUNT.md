# 【PRDv0\.1】AI汽车主线1\.0账号需求梳理

# 产品原则

<div class="callout">

1. **账号关联：**用户在注册/绑定**车企账号**的基础上，可注册、绑定、解绑、换绑豆包账号

2. **账号权限：车辆维度**

    1. **车辆未登录**豆包账号：也可使用基本功能语音功能（具体list待定）

    2. **车辆登录**豆包账号：

        1. 车主/授权用车人：完整使用**AI汽车**千人千面、主动服务等全链路端到端能力

        2. 乘客：仅需录入faceid \&amp; 声纹id，即可让汽车记住你

3. **Faceid、声纹id识别**：千人千面、主动服务等丰富个性化能力，都指向记忆，即**需要能够认出用户是谁**

</div>

## 二、产品逻辑说明

### 1、关联逻辑说明

<div class="callout">

**火山 userid 创建的两种方式：**

- 登录账号，比如：加微信建联   \-\&gt;   有火山userid

- 录入 faceid \&amp; 声纹 id，比如：见过面认识   \-\&gt;   有火山userid



**关键关联逻辑：**

1. **账号映射核心：**火山 userid 与豆包账号严格一一映射，是连接车企体系与生物识别的中间枢纽

2. **车企权限分层：**通过 “主 / 子账号” 区分车企主账号与授权账号的关联关系，实现权限隔离

3. **生物识别绑定：**每个火山 userid 绑定**唯一用户的 faceid / 声纹 id（1 组标识）**，作为身份识别和记忆归属的依据

4. **记忆归属清晰：**所有记忆内容最终绑定到 “火山 userid ”，确保不同用户（主 / 授权 / 乘客）的记忆独立区分

</div>

## 三、场景用户故事

### 1、故事线

明骏买了一辆智能汽车，全家（妻子雨晴、儿子小明）经常用车，偶尔还会让朋友嘉锋临时帮忙接孩子。车辆搭载了火山 userid系统，支持 faceid 和声纹识别，能记录不同人的使用记忆。

<div class="callout">

车主用户故事：

1. **车主注册：主账号链路激活**

- 明骏在车企 APP 注册激活车辆，生成**车企主账号（手机号 138xxxxxxx）**，系统提示 “必须绑定豆包账号”。

- 他绑定了自己的 **主豆包账号（ming123）**，此时车企主账号与主豆包账号形成**强绑定****、一一对应**关系。

- 同步地，主豆包账号 “ming123” 在火山侧自动生成 **主火山userid（HS\-ming123）**，二者**一一映射**。

- 明骏按提示录入 faceid 和声纹 id，系统将这组生物标识与 **HS\-ming123 **绑定（1 个主火山侧账号对应 1 组生物标识）。

- 权限：HS\-ming123 拥有完整权限，可修改 AI 唤醒词、座椅记忆设置等。

</div>

<div class="callout">

2. **家人授权：子账号链路关联**

- 明骏想让妻子雨晴用车，在车企 APP 中添加 “授权用户”，生成**车企授权账号（雨晴手机号 139xxxxxxx）**。

- 雨晴有自己的** 豆包账号（yuqing456）**，绑定到该授权账号后，豆包账号自动映射为**子火山userid（HS\-yuqing456）**。

- HS\-ming123 与 HS\-yuqing456 形成 “1 主对 1 子” 关联（后续明骏还可添加其他子账号，即 “1 主对多子”）。

- 雨晴录入 faceid 和声纹 id，绑定到 HS\-yuqing456，系统提示 “您拥有车辆使用权，无法修改 AI 设置”。

- 记忆关联：雨晴开车时，火山 userid 通过 faceid 识别其身份，将 “偏好空调 24℃” 等记录绑定到 “HS\-yuqing456 \+ 雨晴 faceid” 组合。

</div>

<div class="callout">

3. **未成年人使用：临时子账号场景**

- 儿子小明（10 岁）没有豆包账号，明骏在车企授权列表中添加 “小明”，生成**车企授权账号（无手机号，仅关联身份）**。

- 小明首次上车时，（方式之一）火山 userid通过 faceid 识别到 “新用户”，提示 “是否授权记录身份？”，明骏确认后，系统为小明生成**临时子火山userid（HS\-xiaoming \- 临时）**，并绑定其 faceid 和声纹 id（因无豆包账号，直接关联火山侧临时 userid）。

- 权限：HS\-xiaoming \- 临时仅能使用车辆功能，无法修改任何设置，系统会记录 “儿童模式偏好” 等记忆，绑定到 “HS\-xiaoming \- 临时 \+ 小明 faceid”。

</div>

<div class="callout">

4. **朋友临时用车：无授权账号的临时关联**

- 明骏让朋友嘉锋临时接孩子，嘉锋没有车企授权账号，也没有豆包账号。

- 嘉锋上车后，火山 userid通过 faceid 识别到 “陌生用户”，询问提示 “是否授权记录身份？”，嘉锋同意后，系统生成**临时火山userid（HS\-jiafeng \- 临时）**，绑定其 faceid。

- 过程中，嘉锋说 “打开遮阳帘”，声纹 id 被同步绑定到 HS\-jiafeng \- 临时。

- 记忆内容：本次使用的 “遮阳帘开启记录” 绑定到 “HS\-jiafeng \- 临时 \+ 嘉锋 faceid / 声纹 id”，但车辆下电后，记忆仅作为短期记录，连续 3 个月无记录则清除。

</div>

<div class="callout">

**【核心关联总结】**

- 所有用户的身份识别（faceid / 声纹 id）最终都关联到对应的火山userid（主 / 子 / 临时）。

- 火上 userid （HS\-ming123）是枢纽，关联车企主账号和主豆包账号，控制所有子账号权限；子账号（HS\-yuqing456、HS\-xiaoming \- 临时）依赖主账号授权，仅拥有使用权；临时账号（HS\-jiafeng \- 临时）为一次性关联，权限最低。

- 记忆内容通过 “火山侧账号 \+ 生物标识” 精准归属，确保明骏能看到全家的权限，而嘉锋的临时记忆不会混淆到其他用户中。

</div>
