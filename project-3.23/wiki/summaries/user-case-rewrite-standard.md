# 用户提供的座舱业务案例讲解标准

该材料是学习站改写的深度与表达标准，不单独证明任何功能已经上线。有关参数、版本和执行状态仍要回到相应需求、方案及逐字稿核实。

案例从“带我去昨天那家游泳馆”后补充“附近的餐厅”展开：用户最终要去餐厅，泳馆只是位置参照。正文逐步解释当前文字、预请求、补话、识别收尾和正式提交，让每一步都能对应用户原意的变化。

新术语出现时就在当前场景中解释用途，例如 request_id 关联同一次输入，round_id 区分其中不同版本。字段要回答业务问题，不能用节点编号组成句子来代替说明。

每章需要交代信息从哪里来、谁做判断、为什么等待或重算、结果交给谁，以及失败停在哪里。图下沿同一场景解释真实分叉和回流。没有增加具体机制的概括图应移除，完整业务图保留。

用户要求撤下章节中的术语附录、相关模块清单、额外案例清单、参考资料折叠块与下一模块页尾，避免重复导航打断正文。出处仍可在学习站的全局资料目录中查找。
