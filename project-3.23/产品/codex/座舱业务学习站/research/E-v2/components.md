### A-P001 执行结果语义与替代方案确认（卡片 34 的执行侧展开）
- 是什么：把真实执行的对象、范围、状态和失败原因表达给 Planner 的结果规范。
- 运行处：下游工具/车端执行结果经云端反馈适配；本篇未指定统一模块。
- 收到什么：实际动作、状态、配置或权限限制、实际取值。
- 输出什么：对象明确的成功/失败，或需确认的替代方案，并附简洁回复、勿重复调用等指导。
- 关键数字：设计示例温度 20 度加 15 度，实际上限 30.5 度；不是统一温度范围。
- 来源：chapters/E/raw/tool-return-opt.txt:19–104；6/29 方案。

## [P001] Agent Server（新增，卡片9/13已有主链背景但未定义此管理层）
- 是什么：云端单 Agent 的统一调用和管理模块；运行处：AIDV 云端；输入：agent_id、请求参数及上下文；输出：统一座舱 Agent 响应和历史记录；内部含预处理、按类型选 Executor、通用及业务后处理；关键数字：无模型参数或统一时延指标；IsFinish=true 只结束调用流；来源：chapters/E/raw/agentserver.txt:4–21、71。

## [P002] 工具定义、租户实现与版本环境（新增）
- 是什么：能力定义与具体调用实现分开的注册模型；运行处：云端数据库、管理平台及 Agent Server；输入：工具定义、租户渠道/应用编号、环境和版本；输出：该项目该环境唯一生效实现，供 Planner 加载定义并供执行层找到端点；关键数字：每租户同工具1个发布版本+多个草稿，配置按 channel/channel_app_id/agent_id 唯一，发布列表缓存5分钟，定义2小时刷新/3小时有效；来源：chapters/E/raw/agentserver-opt.txt:27–54、62–104。

### A-P002 车控播报策略（补卡片 7）
- 是什么：按简单、复杂、多意图和实际结果决定在哪生成话术、在哪合成语音的策略。
- 运行处：车端固定 NLG/端侧 TTS 与云端 Planner/NLG/云端 TTS 配合。
- 收到什么：指令类型、所有动作成功/失败明细及原因。
- 输出什么：简单或多意图全成功由端上模板播报；复杂或有失败由云端播报具体结果。
- 关键数字：多意图定义为单次含 2 个及以上独立车控意图；8/24 是方案时点，不是车型全量上线证据。
- 来源：chapters/E/raw/vc-tts.txt:2–33。

## [P003] Agent 管理平台（工具注册与管理平台，新增）
- 是什么：维护工具业务定义与各租户具体实现的可视化配置平台；运行处：云端管理后台，非车机执行器；输入：定义、channel/channel_app_id、参数/notice/tips、端点、版本与启用状态；输出：Planner 可加载工具信息和 Agent Server 可执行配置；关键数字：4种接入方式（http/kitex/mcp/frontier），同定义可有多租户实现，至少启用+发布才可调用；来源：chapters/E/raw/agent-sop.txt:2–8、23–33、195–224、259–264；账号信息不进入研究产出。

### A-P003 不支持指令与车书兜底
- 是什么：车辆控制无法完成时，区分配置缺失与语音控制缺失，并从用户手册查手动替代操作的策略。
- 运行处：云端车控/车书链路，车端播放与展示；本篇未给完整部署图。
- 收到什么：不支持的函数/用户指令、用户手册检索结果。
- 输出什么：明确缺失功能，或解释语音限制并给手动路径；信息不足时说未查询到可用信息。
- 关键数字：两类不支持；配置表暂未纳入早期方案；7/10 方案含更晚 SOP 阶段修正但无修正日期。
- 来源：chapters/E/raw/vc-unsupported.txt:14–39、70–74。

### B-P001｜离线车控干预（云端规则直出）
- 是什么：按规则匹配直接给出预设车控函数，绕过后续模型推理的兜底/修正机制；名称里的“离线”不表示它只跑车机。
- 运行位置：云端 AIDV 编排主链，迁移内部能力平台 DPFM 的干预规则能力。
- 收到什么：用户 query、channel/env/app_id、functionKey；与拒识并行准备的规则结果。
- 输出什么：FunctionResponse（functions、sound_zone、is_simple_vehicle_control=true），交车端执行及端侧播报；命中则取消预启动 Planner，miss/规则异常回原链。
- 关键数字：4 张规则关系表；向量为 1024 维 bge-m3；7/20提测、7/24计划上线；另h2.txt:7417–7428明确预请求漏命中修复7/30已上线，车型开关范围未列。
- 来源：`research/v-lesson-20261107/raw/offline-intervene.txt` 第 9～42、138～142、214～234、449～505 行；与卡片 8 的端云仲裁不同。

### B-P002｜车控 DM 逻辑（执行前提与结果解释）
- 是什么：对函数调用之后的权限、档位、确认、前置条件与执行结果作业务处理；不只是自然语言生成。
- 运行位置：车控执行及端云协作链；11/3 文字记录未明确所有分支统一跑在哪端，不能归为一个独立模型。
- 收到什么：车控函数、当前音区/用户权限、档位等车辆条件与执行状态。
- 输出什么：可以执行/需确认/被限制/未知异常等实际反馈，供 Planner 或本地话术表达。
- 关键数字：11/3 当天20多条原子能力变更；一个原子能力可能新增3个逻辑；非模型参数量。
- 来源：`research/v-lesson-20261105/memory/meeting-1103-transcript.md` 第 771～887、901～947 行（00:23:46～00:28:11）；原发言为业务职责说明，不把全部实现细节推定已完成。
