# 语音课堂风格与教学结构审校

审校对象：已交付培训讲稿 v06、图文课堂 v06、业务全链路 v15；风格依据：training-transcript-0.md、training-transcript-1.md。这里评审的是教学表达，不替代术语事实核实与现状核验。

## 先讲判断

v06 已经有主线场景、中文术语解释、流程图、交互演示和资料边界；不能说它“完全没有图”或“没有解释”。问题是：它仍然要求读者自行完成大量连接。读者刚在学 ASR，马上要处理 partial、热词、上下文、Soft/Hard、预请求、final、二遍、request_id、round_id、缓存复用和历史版本差异。每段本身可能正确，第一次学习的人却无法同时记住这么多新对象。“资料全面”没有自动变成“课程易懂”。

用户要的是讲师带着一个请求走完，并在每个交接点停下来解释“刚才拿到了什么，现在还缺什么，因此接下来交给谁”。应以这条因果链控制正文，依据、版本和接口细节放在对应节点的第二层，而不是把课堂变成按文档来源切割的资料汇编。

## 现稿为什么仍然不连贯

1. **章节标题对了，但每章的教学任务太多。** 第二讲要同时承担识别、停顿、热词、双遍、预请求、请求编号和版本辨析。应拆为“字怎么出来”“为什么停一下不急着执行”“最终文字如何接管前面的准备”三个连续小课。
2. **重要状态被埋在说明段中。** final、Hard、正式请求、工具回执、播放器结束都说到了，但缺少始终可见的状态对照。应让学员看到“音频仍在来 / 文字尚未定稿 / 准备已做 / 动作未发 / 声音未播”。
3. **正文过早引入读者尚未需要的机制。** 初学者还不知道 ASR 输出什么，便介绍热词数量和识别辅助的上下文。数量应进参考层，主课先证明“声音变成文字”。
4. **主线在中段被版本审计打断。** 当前、历史、拟改造必须准确标注，但首次阅读只走一个明确口径。冲突说明进就地展开层，并以“为什么不能直接照搬”解释影响。
5. **图与讲解未形成强指向。** “沿图往下看”不足以指导视线。应写“现在点亮 ② ASR；它交给下一步的是暂时文字。右侧的导航按钮保持灰色，因为还没有最终输入”。每一屏只推进一个知识动作。
6. **动画存在不等于动画解释了机制。** v06 已有交互、计时器及 CSS 动画；v15 是适合检索的可点击总图。但静态大图让新人自己找节点，学习负担仍在读者。课堂需要默认逐步展开、暂停、上一步、重播、反例切换和与当前帧一致的讲解。
7. **产品验收散落各处，没有持续重复的同一问法。** 每节固定回答“用户预期是什么；本节点收到什么；交出什么；谁据此继续；什么证据说明完成；失败往哪回”。这不是机械小卡片罗列，而是正文自然段的写作顺序。

## 两种页面各自负责什么

v15 更像“工作时查地图”：允许自由检索、追箭头和展开证据。v06 应成为“有人带着上课”：默认先走正常路线，逐步亮图，连贯口播，再插入三个必要机制演示。不要试图把大地图里所有证据同时塞进一堂课的第一遍讲解。

## 三个动画必须讲清的机制

### 机制一：ASR 与 VAD 同时工作，Soft 准备、Hard 收尾，最终文字接管

- 第 1 帧：用户发声，声音轨亮起；ASR 轨出现部分文字；VAD 轨显示持续有语音。讲解：边听边认字，同时判断说话边界。
- 第 2 帧：用户短暂停顿，计时从最后一段语音结束处起算；保留“仍可续说”。阈值由事实核实结果填入，不在动画里写死未知值。
- 第 3 帧：达到 Soft 对应条件，准备轨亮起，正式执行闸门保持关闭。讲解：拿现有文字提前准备，不等于已经确定要做。
- 第 4 帧：切换“用户继续说”分支，文字增加，旧准备标注可能失效；不能画成先关麦克风再重新录一遍。
- 第 5 帧：达到当前方案的 Hard 收尾点；二遍轨输出 final；显示临时文字与 final 对照。
- 第 6 帧：按已核验规则比较 final 与预请求，显示复用或重做；此刻才将最终需求交给正式处理。

动画验收：暂停在第 3 帧时，屏上不能出现导航已启动；“二遍”不能表现为用户说第二遍；Soft 与 Hard 不得画成两个相加的固定等待时长。

### 机制二：Planner 思考、行动、观察、再思考

- 第 1 帧：最终文字“去昨天那家游泳馆”，目的地卡显示未知，Planner 发现缺信息。
- 第 2 帧：发出查记忆动作；工具状态变为处理中；Planner 的事实栏不提前填出地址。
- 第 3 帧：工具返回一个候选，回流箭头亮起，事实栏加入地点；再作决定。
- 第 4 帧：切换反馈为两个候选，下一步变为向用户澄清，导航闸门关闭。
- 第 5 帧：恢复唯一候选，发导航动作，依次显示发出、受理、结果反馈；“好的”不能代替这些状态。
- 第 6 帧：用成功或失败反馈生成不同表达，屏幕与播报对齐真实结果。

动画验收：学员能改变 tool_feedback 看见下一步变化，而不是总被带到同一个预设答案。

### 机制三：生成、合成、播放并行；打断后动作不自动撤回

- 第 1 帧：文本分段生成；第一段交给 TTS，第二段仍在生成。
- 第 2 帧：首段音频返回播放器，播放器开始播放，TTS 仍在合成后段；三轨同时有进度。
- 第 3 帧：云端生成结束，播放器仍在播放，显示“生成结束 ≠ 播放结束”。
- 第 4 帧：插入新话“等等，先别去了”，先显示检测、判断、实际停播的独立状态。
- 第 5 帧：声音已停，但导航显示已启动；问学员“这时导航是否已取消”，允许选择并解释。
- 第 6 帧：若场景与能力允许，Planner 发起取消动作，收到取消结果后才更新导航状态；不支持或失败则明确反馈。

动画验收：不能把停音频的按钮连到“全部任务取消成功”；三轨各有自己的完成标记。

## 评审练习：让学员带着证据提问

练习一：“用户说完，屏上字都对，豆包仍迟迟不出声。”先让学员分清 final 返回、正式判断、工具等待、文本生成、首音频和实际播放，再选择需要的时间点。参考提问：“最终识别已经返回，我们能不能把后续各阶段时间拉出来，先确认等待主要发生在工具还是音频播放前？”

练习二：“豆包说导航成功，但车机没有开始导航。”提供 ASR 正确、Planner 动作已发、工具只返回受理三条证据。参考提问：“这条回执只表示接收，还是已经开始导航？当前成功话术依据的是哪个状态？能否补目标端结果做确认？”

练习三：“用户说别去了，声音停了，但导航仍在走。”参考提问：“这轮打断停止的是播放、后续推理还是导航动作？如果导航已执行，有没有单独发起取消并收到结果？我们需要分别验收。”

练习四：“主驾说我冷，后排空调变了。”给出原始音区、Planner 参数、下游执行三个证据入口。先找到错误第一次出现在哪个交接点，再划责任，不能凭最终现象先归因模型。

结课标准：学员能用同一案例讲清输入、输出、条件、反馈、用户结果，并能在图上指出至少三种“上一层成功不代表下一层成功”的位置。
