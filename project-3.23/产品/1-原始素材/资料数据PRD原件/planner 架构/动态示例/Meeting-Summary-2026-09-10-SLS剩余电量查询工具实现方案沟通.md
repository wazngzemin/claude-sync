# SLS 剩余电量查询工具实现方案沟通

## 会议信息

- 时间：2026年9月10日 14:08—14:29（GMT+08）
- 参会人：韩天亮、郝晓伟、韩杰、Jojo（思晴）、王泽民等
- 主题：赛力斯“到达某地点后预计还剩多少电”查询能力的工具承接方案

## 一句话结论

先按“用户询问的地点是否属于当前路线”分流：当前目的地或途经点已有预计剩余电量时，直接用端状态回答；不属于当前路线或当前没有导航时，调用 `poi_search`，保留完整的“地点＋到达后剩余电量”语义，由 POI 返回预计到达剩余电量。该方案先用动态示例试验，韩天亮负责跟进实车验收。

## 会议讨论的问题

用户可能在三种情况下询问预计到达电量：

1. 正在导航，询问到终点或某个途经点时还剩多少电。
2. 正在算路但尚未开始导航，询问到终点或途经点时还剩多少电。
3. 没有导航，或者询问的地点不在当前路线中，询问到该地点时还剩多少电。

现有端状态只能较好地覆盖当前路线中的目的地和途经点。对于路线外地点，端状态没有对应的预计结果；赛力斯提供了一个基于“当前位置＋明确 POI”的预计到达剩余电量接口，可以通过 Navi/POI 链路承接。

## 已达成的方案

### 场景一：询问当前路线内的地点

- 先判断询问对象是否是当前导航的目的地或途经点。
- 如果端状态已经上报该点的预计到达剩余电量，直接依据端状态回答。
- 不重复调用状态查询、POI 搜索或路线规划工具。
- 只能使用端状态真实上报的数值，不自行按距离、当前电量或平均电耗计算。

### 场景二：询问当前路线外的地点，或当前没有导航

- 调用 `poi_search`。
- 入参保留用户完整原话中的两个核心信息：目标地点、到达后预计剩余电量。
- 不要把 query 简化成单纯的“搜索某地点”，否则下游可能只返回 POI 信息，不返回预计电量。
- 不调用 `vehicle_status_search`，因为当前车辆状态不能回答未来到达某个新地点后的电量。
- 不调用 `route_planning`，因为用户是在查询预计电量，并没有要求发起导航。
- 根据 `poi_search` 返回的预计到达剩余电量回答，不自行推算。

### 场景三：POI 不唯一

- 如果 POI 返回多个同名地点，应先给出候选地点并让用户确认。
- 未确认具体地点前，不应把任意一个候选结果的预计剩余电量当成最终答案。
- 用户选定后，再根据选中 POI 对应的预计剩余电量回答。

## 可直接录入的动态示例

**Query：**我现在去漕溪北路400号，到的时候大概还剩多少电？

**决策分析：**

1. 用户询问的是到达指定地点后的预计剩余电量，需要先判断“漕溪北路400号”是否属于当前导航的目的地或途经点。
2. 如果该地点是当前目的地或途经点，并且端状态已经上报对应的预计到达剩余电量，直接依据端状态回答，不调用工具。
3. 如果该地点不在当前目的地和途经点中，或者当前没有导航，调用 `poi_search`，query 保留用户完整语义“我现在去漕溪北路400号，到的时候大概还剩多少电”。
4. 不调用 `vehicle_status_search`，因为它只能查询当前车辆状态，不能得出到达新地点后的预计电量。
5. 不调用 `route_planning`，因为用户只是在询问预计剩余电量，没有要求开始导航或规划路线。
6. 不要把 query 改写成单纯的“搜索漕溪北路400号”，必须保留“到达后预计剩余电量”的查询意图，以便下游返回对应字段。
7. 收到 `poi_search` 返回后，只能根据工具返回的预计剩余电量回答，不自行使用当前电量、距离或平均电耗进行计算。
8. 如果搜索到多个同名地点，先让用户确认具体地点；如果工具没有返回预计剩余电量，如实说明暂时无法估算，不得编造数值。

**其他说明：**本示例只处理预计到达剩余电量的问答，不代表用户要求导航。除非用户同时明确说“导航过去”，否则不得自动发起导航。

## 当前路线内场景的补充示例

**Query：**到下一个途经点时还剩多少电？

**决策分析：**

1. 从当前导航端状态中定位“下一个途经点”。
2. 如果端状态已经上报该途经点的预计到达剩余电量，直接用该数值回答，不调用 `poi_search`。
3. 不得使用整段行程终点的预计电量代替途经点电量，也不得用当前电量代替预计到达电量。
4. 如果端状态没有上报该字段，不得编造；是否降级调用 `poi_search`，需要等接口一致性结论确认后再定。

## 尚未拍板的问题

1. 当前路线端状态中的预计剩余电量，与赛力斯新接口返回的预计剩余电量，是否来自同一个接口、同一种计算口径。
2. 如果两者来自同一接口，是否可以取消分流，统一由 Navi/POI 链路承接。
3. 如果两者不是同一口径，当前路线内是否坚持优先使用更准确的端状态结果。
4. `poi_search` 是否已经能稳定返回每个 POI 对应的预计到达剩余电量字段，包括字段名称、单位、精度及异常码。
5. 正在算路但尚未开始导航时，目的地和途经点是否已进入端状态，以及应按“路线内”还是“路线外”处理。

在上述问题确认前，动态示例适合进入测试或灰度验证，不宜直接作为最终生产规则。

## 验收用例

1. 导航中询问当前目的地：端状态有值时直接回答，不调用工具。
2. 导航中询问当前途经点：准确匹配对应途经点的预计电量，不误用终点电量。
3. 导航中询问路线外地点：调用 `poi_search`，不调用状态查询或路线规划。
4. 非导航态询问明确地点：调用 `poi_search`，保留完整电量查询语义。
5. 同名 POI：先让用户确认，不随意选点并回答电量。
6. POI 接口没有返回预计电量：明确说明无法估算，不编造数值。
7. 用户只问电量：不自动开始导航。
8. 用户同时说“查一下到那里还剩多少电并导航过去”：先获取并确认地点和预计电量，再按依赖关系串行进入路线规划，不能把相互依赖的动作并行下发。
