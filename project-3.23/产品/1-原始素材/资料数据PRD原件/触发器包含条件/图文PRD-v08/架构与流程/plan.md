# v08 图解计划与阅读边界

## D1：视觉来源与使用边界（single structural）

读者需要分清系统预设输入、用户动态观察结果、DT 临时 VQA 三种来源。使用三个上下排列的独立区域，不将它们汇入一个 Context。

- 画布 680 × 700；三个区域 x=40、width=600，y=100/290/480，height=170，间距 20。
- 每区分为来源、接收、用途三个横向文字栏；栏中心 x=140/340/540，字宽预算 180；每行最多 12 个中文字符或等宽混排。
- 区域为灰色，边界提醒使用紫色。仅一类箭头，表示本区内部数据流，不连接三种来源。
- 正文 14/12 px，所有 text 使用 th/ts，标准 style/defs 原样复制；SVG 不含注释，无背景填充。
- 最低文本基线 676，加 4 px 字形下沿及 20 px 留白，H=700。

## D2：配置校验保存流程

五步表单收集一份场景配置，完整校验后区分简单规则保存与 Workflow 定义注册、场景关联。保存、回读、发布和运行分别验收。

## D3：Workflow 三态与汇合

儿童条件与宠物描述是两个并行分支。OR 是真实儿童锁条件节点的前驱关系，不是额外空节点。OR 任一 PASS 可以继续，不取消另一分支；整图终态后才进入图外策略和动作。

## D4：闪念一期运行链路

已有视觉文字更新后做目标判断，三态结果中仅 PASS 进入频控、执行锁、Frontier 和客户端仲裁。回执分层，不将下发等同展示；排队不是已具备能力。

## D5：视觉配置选择逻辑

字段是否可配置以真实渠道目录为准，不把原始数据中的枚举直接当作已开放条件。同一乘员对象内匹配 Position 和 AgeRange；文字来源走已有描述与目标判断，不请求新画面。校验失败只要求保留本次页面编辑内容，不承诺服务端正式草稿能力。
