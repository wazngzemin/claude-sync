按图逐步读懂
G01 · 接收场景与业务关系
来源：任务系统或配置后台；保存条件、动作与生效范围；场景必须能对应到原业务。
云端触发器接收任务系统登记的规则，也接收后台预置的主动服务或系统场景。场景至少要表达什么条件、对哪些车辆生效、命中后通知谁。例如用户任务应回到对应任务系统，静态顾问场景应唤醒对应 Advisor；同样是条件命中，不代表所有场景都调用同一个出口。
G02 · 这辆车能用这个场景吗
核对渠道、车辆、车型和版本；核对平台状态与本车任务开关；能力或范围缺失不默认放行。
开始判断前，系统先核对当前车辆是否在生效范围内、该场景是否启用、相关用户开关是否允许。比如平台规则已开启，但用户在任务中心关闭了本车场景，仍不能触发。10 月平台 PRD 指出视觉能力当前仅赛力斯接入；范围查询失败也不能悄悄解释成全部车辆均可用。
G03 · 哪个信号叫醒这次检查
动态条件关注一次状态变化；静态条件读取当前状态；视觉条件监听指定描述更新。
唤醒信号只决定什么时候开始检查。例如“挡位变更为 D”表示从其他挡切入 D，“挡位等于 D”表示当前状态。10 月方案规定有动态条件时重点由动态信号唤醒，有推理节点时还订阅相应视觉信号。产品要检查车已在 D 挡后儿童才出现的情况，不能把唤醒条件误当全部条件已满足。
G04 · 取本轮真正需要的状态
按业务对象取本轮信号；车况/导航/媒体/座舱/车机五域；位置主键、枚举、数值单位要对齐；缺失、失败、旧值不可当事实。
状态感知 PRD 把信号分为车况、导航、媒体、座舱、车机五域，位置用结构化主键区分座位，数值必须携带单位。例如后排儿童锁不能误读主驾值，也不能把缺失当关闭。信号同时供 Context 注入、状态查询工具、工具拉取或订阅三类消费；三者不等于同一份缓存。标准化及 Trigger 改动仍需方案对齐，500毫秒/1赫兹/30秒是该文当前代码描述，不是所有车型新承诺。
G05 · 逐步判断条件是否达成
结构化字段走规则比较；caption交目标语义判断；Workflow汇合AND / OR分支；PASS / REJECT / UNKNOWN。
结构化状态按合法运算符比较，视觉自然语言则交推理节点判断是否符合目标。例如儿童年龄字段与宠物描述是两条分支，任一成立后再检查儿童锁。10 月 Workflow 方案要求唯一终点，并区分通过、不满足、未知；推理节点只判断已有描述，不负责取新画面、生成文案或直接控车。OR一支通过可继续，但其他分支不取消；缺数据或超时不可算条件不满足。
G06 · 本次允许发出去吗
核对执行次数与最小间隔；处理场景优先级及出口竞争；命中、策略拦截分别留记录。
条件达成后，还要检查这次动作是否受到次数、间隔或并发策略限制。比如乘客持续睡着，视觉描述每次更新都可能符合目标，系统不应因此不断刷屏。平台方案把“条件通过但频控拦截”单独记录。具体间隔与优先级取已发布配置，不把早期文档的示例秒数当作所有项目统一规则。
G07 · 用户任务回调任务系统
通知哪条任务、什么条件已满足；任务系统再生成本次 advice；触发成功不代表已提醒或已控车。
用户创建的定时、条件任务命中后，触发器回调原任务系统，由其检查有效性并继续推进。例如“宝宝哭了告诉我”的条件命中，只能证明观察目标达成；任务系统还要把提醒建议交回 Director，经输入管理安排交互。触发器不直接把整条任务标为完成，也不替代工具实际执行结果。
G08 · 统一派发场景配置的 Action
Advisor / Recommend / 业务事件；闪念 / PHUD 等独立出口；10/21方案：Action Dispatcher；不再固定只回 TaskService。
场景命中可以唤醒 Advisor、直接形成确定建议、记录事件，或只显示闪念和 PHUD，不能全部拐进任务系统。10/21 新技术方案要求推理成功从固定 TaskService 回调改为统一 Action Dispatcher，按配置派发动作。这是改造要求，不是已经全上线。充电等预设的前置通过仍不证明设备已识别；显示出口也只证明一次下发，必须继续核用户真实曝光或工具真实结果。
G09 · 不触发也要知道原因
明确不满足：记录后继续等待；缺数据或推理失败：记录未知；下次有效信号到来再检查。
没有触发可能是条件明确不满足，也可能是数据缺失、模型失败、任务已关闭或频控拦截。比如车内确实没有儿童，与相机结果没上传，是两类问题。产品排障必须看到每步结论及依据，再判断该修规则、补信号还是改模型；不能用一条“未触发”记录覆盖所有失败原因。
G10 · 时间触发：到时回调，不直接控车
一次/周期时间注册到调度；到时只回业务方继续处理；取消需注销后续计划；跨行程恢复不能凭定时器推定。
时间触发把明确时间或周期登记给调度，到期回调任务系统，再按当前车辆与任务状态执行。它不用模型持续循环看时间，也不直接控制车。语义层把“明天早上”或“十分钟后”解释为时间，调度层负责到点，任务层负责执行和结束。周期取消、车辆下电后是否保留必须按 EndPolicy 核对，不能从“支持定时器”推定所有类型都能跨行程长期运行。
G11 · 语义推理只判断目标是否可见
目标+当前caption，核对象位置；达成/未达成/无法判断；无置信度；不负责播报结束；8/31版并发推理，不中断旧请求。
语义模型拿文字观察而非重新取图，判断当前帧是否支持指定对象和位置的目标。证据不足判未达成，本质超出视觉能力判无法判断；规格没有置信度字段，不应添加阈值门禁。8/31 评审覆盖前文打断旧请求的设想，改为并发推理，首条达成后不再新增推理、等待任务删除。此层暂定三分钟过期与 Task 入口二十秒是不同限制，不能相互代替。
G12 · 把有意义的状态变化写业务事件
预置条件用有变更，保留前后值；匹配时刻不等于端采样/上报时刻；模板拼接事件，不必调用大模型；调试client-event不自动进模型。
Trigger 可把空调、媒体或导航等有意义的变化转换为事件，传所需信号的旧值、新值和位置，事件服务按模板拼接；不等于把高频遥测全部写日志。该技术稿的触发时间是规则匹配成功时刻，不是端采样时刻，时延分析要分清。开关和登录态经Trigger同步弋途的旧段落已划掉，不能继续画成职责。业务事件可供记忆、Context或订阅方；调试client-event仅排障，不自动成为模型上下文。
