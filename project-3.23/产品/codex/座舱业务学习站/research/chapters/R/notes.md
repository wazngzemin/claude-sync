## 3. 演进 / 取舍 / badcase / 争议（写进正文的素材）

1. **免唤醒上云方式的演进**：2025-12（上汽时期 PRD）“端侧文字先发云端预判 + 音频上云二次对比”→ 2026-07 AIVA“本地流式拒识判 attend 才上云，未判就等整句”。取舍：流量与误唤醒 vs 首句速度；代价是本地流式拒识要在车上跑，准确率决定体验（10/30 实车误召严重）。
2. **本地结果采信从分流到兜底**（V 章专题一已讲决策链；本章只讲它在入口侧引起的连锁变化）：状态机改为以云端为准；本地 reject 一律不采信；final 上屏文字跟随采纳结果；后处理（函数级白名单）失效；干预黑名单不再需要；上下文同步从“全部同步”改为“只同步被采纳的”。
3. **拒识松紧分工**：本地松（不过拒）、云端严（全时态更严）。代价：上云流量多（“巴拉巴拉”也上云）、全时态隐私顾虑靠“不流式上屏”缓解。
4. **网络判断之争**：用谁的网络判断（豆包 SDK vs 赛力斯 vs 自研）；是否按业务节点定义；是否提示用户离线。
5. **离线体验的边界**：本地 FC 范围一期约 30 余类二级功能；离线车控 88.72%、7 类指令无法调节；赛力斯想用端侧 VLM/30B 做离线（讨论中）。
6. **badcase**：本地模型误唤醒（11/6）；单人在副驾 query 不召回（11/6）；全时态有效 query 没上屏（10/9）；history 只有端侧数据（10/9）；跨音区继承失败；四音区有人时前排丢句（10/21）；开窗唤醒失败率 95%（11/6）；积压消息被合并成闲聊（8/20）；E68 打开 alwayson 开关不切全时免唤醒（10/22）。
