# 触发器 OnePage
# 新人快速了解
**TL;DR**
- **它是什么**：监测事件或时间，条件满足后自动执行预设动作。
- **三类触发**：条件触发、定时触发、推理触发。
- **何时使用**：业务时机明确、动作明确、生效范围可控。
- **关键边界**：混合触发需确认；不做连续趋势与复杂规划指令解析。
---
## 能力描述
**触发来源 → 条件判断 → 动作执行**
触发器服务围绕这条链路组织自动化场景：持续关注车辆端状态、视觉感知结果、云端时间计划或推理结果；命中条件后，自动触发已经定义好的动作。
一个完整场景包含四个要素：
- **条件**：什么情况算命中，例如“主驾上车”或“车速变更为 0”。
- **动作**：命中后做什么，例如给出建议、提醒或发起回调。
- **执行策略**：如何控制执行频率，避免不必要的重复触发。
- **生效范围**：在哪些渠道、车型或车辆 ID 上生效。

## 能力地图
**先按“什么触发、触发后做什么”理解能力。**前三类负责发现时机，动作执行负责把时机转成业务响应。
- **VLM**：视觉语言模型，用图像与文字语义判断画面中的目标情况。
- **Cron**：按固定周期重复执行的时间计划。
- **Advisor**：面向用户主动给出建议或提醒的动作方式。
- **自定义回调**：触发后按照使用方的配置回调指定地址

## 典型使用场景
**场景是否适合接入，先看业务时机能否被明确描述。**
- 主驾上车后，自动触发欢迎或问候。
- 发现后排婴儿哭闹时，主动给出安抚建议。
- 车速变更为 0 且满足位置条件时，触发订单结算回调。

## 什么时候适合用
**触发器适合把清晰的业务规则变成自动响应，未来会承担开放式理解与连续分析。**
**适合**
- 能明确说清“何时触发、触发什么动作”。
- 需要判断当前值或监测状态“变更为”目标值。
- 需要单次时间或 Cron 周期调度。
- 需要按渠道、车型或车辆 ID 控制生效范围。
 | 
**暂不适合或需确认**
- 需要分析温度是否持续上升等连续趋势。
- 希望触发器自行解析复杂规划指令。
- 需要“定时 \+ 条件”混合触发
 |

## 快速开始
**先把业务规则写清，再选择触发方式。**下面是概念步骤，不代表具体管理后台流程。
1. **明确业务时机**：用一句话描述何时需要响应，例如“主驾上车后”或“每天固定时间”。
2. **选择触发方式**：在信号触发、时间触发、推理触发中选择与业务时机匹配的一类。
3. **定义动作与策略**：确定 Advisor 推荐或业务回调，并补充频率限制与生效范围。
4. **小范围验证后放量**：先限定渠道、车型或车辆 ID，确认触发时机与动作符合预期，再扩大范围。

## 常见问题
**静态判断和“变更为”有什么区别？**
静态判断关注信号当前值是否满足条件；“变更为”关注状态是否从其他值切换到目标值。
**能把定时与条件组合使用吗？**
暂不支持“定时 \+ 条件”、“条件\+推理”、“定时\+推理”的混合触发。
**能判断温度是否持续上升吗？**
不能。当前支持当前值判断与“变更为”事件，不支持连续趋势分析。
**触发器会理解复杂规划指令并决定怎么执行吗？**
不会。触发器负责在条件满足时执行预设动作，不负责理解和拆解复杂规划指令。

# 指标一览
- 触发：执行场景匹配的耗时，如端状态上报等
- 触达：执行动作的耗时，如调用Advisor、任务系统、自定义地址、事件服务等

- 推理触发
