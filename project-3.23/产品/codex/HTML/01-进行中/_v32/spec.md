# v32 全站讲义重写规范

## 1. 这次要解决的问题

v31 的正文有两个毛病，用户原话是「硬塞进去」「整得乱七八糟」：

1. 术语解释被塞进句子中间，一句话里套三四个括号，读者断句都断不下来。
2. 每章都用同一套标签段落（`X 是什么：` / `为何需要这一层：` / `不是什么：` / `车内例子：`），像把问答卡片贴进文章，读起来是碎片。

所以这不是「再补一点内容」，而是把每一页的讲义重写成能连续读下去的文章。内容深度参照 `v15/<页面>.md`，那份是用户认可的讲课稿，每章 7000–13000 字。

## 2. 只改 teaching

- 允许改：`teaching.intro`、`teaching.lessons[*].paragraphs`、`teaching.lessons[*].title`、`teaching.guides.base.title`、`teaching.guides.base.paragraphs`、`teaching.closing`。
- 不允许改：`lessons[*].id`（数量与 id 必须和输入文件完全一致）、页面 `summary`、`scenario`、任何节点、边、图、HTML 结构。
- 不要新增 lesson，不要删 lesson。原 lesson 标题如果空泛可以改写，但必须仍然对得上这节课讲的事。

## 3. 每页的结构与篇幅

| 字段 | 段数 | 每段字数 | 写什么 |
| --- | --- | --- | --- |
| intro | 3–5 | 200–350 | 第一段：这一站在整条链的什么位置、接着谁、交给谁，配一个真实场景。后面：用户在这一步感受到什么、系统要做什么决定、这页要回答的问题。 |
| lessons | 与原有一致 | 每课 2–4 段，每段 250–400 | 按业务发生顺序讲：进来时手上有什么、这里判断什么、判断完交出去什么。段与段之间要有因果或转折，不能是并列要点换行。 |
| guides.base | 6–10 | 250–350 | 把这张图当一条路线讲一遍：从哪里进、主线怎么走、哪里分叉、分叉条件是什么、异常从哪里出去、走到哪里算这一站结束、下一张图接哪里。不要逐节点复述。 |
| closing | 2–3 句 | 每句 40–80 | 评审桌上能直接说出口的话：这一章定义什么、不定义什么、验收看哪几条。 |

整页正文（intro+lessons+guides+closing）目标 6000–9000 字。V 页现有 4.4 万字、guides 128 段，属于过度膨胀，必须压回这个量级。

## 4. 语言规则（硬性）

1. **一段一个意思。**后一句解释前一句，段间用「因为/所以/如果/这就是为什么/反过来」这类实词衔接。禁止一段里塞三个并列主题。
2. **术语只在第一次出现时解释一次，写在自然句子里。**例如：
   - 可以：`热词是提前交给识别服务的一份重点词名单，用来提高「游泳馆」这类专有名词被写对的概率。`
   - 不可以：`注入热词（hotword）——热词是提前塞给 ASR（自动语音识别，也就是把说话写成字）的一份重点词名单`
3. **禁止行内括号解释链。**一个括号里最多一个短限定，不超过 12 个字，例如 `（约 300 毫秒）`、`（主驾）`。禁止出现 `Advisor（主动服务顾问）` 这种英文＋中文对照反复刷屏；同一个术语全页只解释一次，之后直接写中文名。
4. **禁止标签式段落。**不许出现 `是什么：`、`为何需要这一层：`、`不是什么：`、`车内例子：`、`用户感知：`、`系统决定：`、`明确不做什么：` 这类开头。这些内容要化成正常句子。
5. **引用节点写「编号（中文名）」。**如 `V5（短停顿 300 毫秒：先做准备）`。同一节点第一次出现给全名，后文可只写编号。每页至少引用 6 个本页相关节点，编号必须能在 `node_titles` 里查到，名称必须与表里一致（可去掉表里的内层括号）。
6. **不写元话语。**不许「本节将」「接下来我们」「下面来看」「值得注意的是」。直接讲事。
7. **状态必须说清。**涉及能力时区分：已落地 / 2.6 目标 / 讨论中 / 待核。没有依据的数字不写；写不出处就写「待核」。
8. **不编事实。**只能用 `v15/<页面>.md`、`inputs/page_<页面>.json` 现有正文、`sources` 列表里的文档标题所支持的内容。新增一个数字或结论，必须能在 v15 原文找到，否则不要写。

## 5. 三条真实反例（现在就在文件里，必须改掉）

- 反例一（括号套括号）：`云端识别建连一接通，就注入热词（hotword）——热词是提前塞给 ASR（自动语音识别，也就是把说话写成字）的一份重点词名单`
- 反例二（标签段落）：`Trigger（触发器）是什么：把已登记的条件与新到信号对上，并在放行后通知原业务。` ／ `不是什么：登记成功 ≠ 本车能跑`
- 反例三（机械三元组）：`用户感知：短停时车没抢跑，还能补话。系统决定：启动允许的准备并继续听。明确不做什么：不创造缺失地址。`

## 6. 好的样子（参照 v15）

> 你说「带我去昨天那家游泳馆」，车要做对四件事：听清你说了什么，判断你是在跟它说话，弄明白「昨天那家」是哪一家，最后真的把导航打开并告诉你结果。读每一站时都问同样四句话：刚才已经拿到什么，现在还缺什么，所以接下来交给谁，拿到什么结果才可以继续。

这段话没有括号、没有标签，先给场景，再给判断标准，读者自然知道往下要看什么。新写的每一页都要达到这个读感。

## 7. 输出格式

写到 `_v32/out/<页面id>.json`，必须严格是这个形状：

```json
{
  "id": "G",
  "intro": ["…", "…"],
  "lessons": [
    {"id": "g-wake", "title": "…", "paragraphs": ["…", "…"]}
  ],
  "guides": {
    "base": {"title": "…", "paragraphs": ["…", "…"]}
  },
  "closing": ["…", "…"]
}
```

- `lessons` 的 id 顺序必须与 `inputs/page_<id>.json` 里的 `lessons` 完全一致。
- 不要输出 JSON 以外的解释文字。
- 写完运行 `python3 _v32/validate.py <页面id>`，把 issues 清零再交。
