禁播 tool feedback 只服务于 Planner 状态同步，不作为用户可感知话术。建议注入自然语言语义：

```JSON
{
  "model_content": "目标创建请求已提交，当前状态：创建中。该工具反馈仅用于系统状态同步，请不要向用户播报创建中或创建成功，也不要总结为创建成功；保留前面已经输出给用户的铺垫话术。",
```

协作边界：

1. 字节客户端关注两类卡片：创建成功卡片 `GoalCreated`、任务执行卡片 `TypeRecommend\.card`。

2. Extour 服务端关注三类接口：`create\_goal`、`lifecycle callback`、`advice\_consumed`。

3. 字节服务端负责 pending、RecommendCache、幂等、Frontier 下发、二次上行恢复和 consumed 通知。

4. 本期不新增多 advice 队列；多 Trigger 仍按现状 latest wins 收敛。

# 多 Trigger / 多 advice 边界（本期暂不处理）

**本期按现状收敛，不承诺多 advice 合并。**现状行为：

5. 如果 Extour 一次传多个 `advisors\_input`，AIDV 会拼成一个 `advisor:` 字符串，Planner 可能理解出多个 action。

6. 如果 Extour 分多次调用 Recommend，`sound\_zone\_merge\.AdvisorQuery` 当前使用 `AdvisorTypeUnknown` 单槽位，后到 advice 可能覆盖先到 advice。

7. 如果前一条 advice 正在等待上一轮 chat/TTS 结束，后一条 advice 更新缓存后，前一条可能被 `ShouldBreak` 判定为过期并放弃。如后续要支持多 advice，需要新增结构化 advice 列表，至少包含 `recommend\_id/goal\_id/advisor\_type/priority/created\_at`，并明确排队、覆盖、合并和展示策略。
