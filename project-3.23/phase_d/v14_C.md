# 04 上下文准备｜v14 全景图 SVG 中的 C 模块（节点 12 个）

框标题：C · 上下文｜多路并行准备背景，缺哪项再查哪项
框说明：按本轮需要准备当前事实、历史和身份信息，缺失与过期状态明确交给决策。

## 节点（编号与文档画板一致；措辞为 10/26 最新版，含每个节点两段讲解）
### C1｜按当前问题准备相关背景（蓝底）
- 要点：接住本轮有效输入身份、状态、历史等按需并行取用已有信息预注入，缺项再查询各来源仍维护自己的原始事实
- 讲解①：Context 把各系统已有信息整理成本轮判断需要的背景。用户说“开主驾车窗”，不一定需要网上天气；说“去昨天那家店”，则可能需要身份、记忆与当前导航状态。相关来源可以并行获取。
- 讲解②：各来源仍负责自己的数据，Context 负责选取和组装，不把所有原始信息都搬成自己的存储。常用背景可以先准备好，Director 发现关键事实仍缺时再显式查询，避免每句简单操作都走最重的一整套检索。

### C2｜确认此刻说话人与被操作对象（蓝底）
- 要点：采用当前可信身份与座位信息人名映射到这次实际座位同名、未知或冲突不能靠猜读取记忆还需独立授权
- 讲解①：Context 提供此刻说话人、音区与在场乘员信息。用户说“给明骏打开加热”，只有确认明骏这次坐在副驾，才有依据把对象改写为副驾座椅；过去坐过哪里不能直接替代当前位置。
- 讲解②：身份识别、座位定位和操作权限分别成立。同名或信息未知时，要保留缺口并走身份或澄清处理，不能猜一个座位。涉及个人记忆，还要先通过相应授权，认识名字本身不会自动允许读取私人信息。

### C3｜把车辆当前状态连同时间交给模型（蓝底）
- 要点：提供本轮需要的车辆状态保留采样或发生时间缺值和旧值不填成关闭或零必要时再查询缺失信息
- 讲解①：车辆当前状态包括空调、车窗、挡位、续航或导航等本轮需要的事实，同时应保留采样时间。用户刚手动调了空调，最新车端上报应优先于历史回答中那句已设为某个温度。
- 讲解②：并非每个信号都每轮齐全。缺值或过期就保持未知，必要时显式查询，不能自动填成关闭或零。可靠状态可以减少无效动作，例如已经最低温度时不再继续降低，也让下一轮知道上一次车控是否真的生效。

### C4｜补充此刻舱内外环境与乘员情景（蓝底）
- 要点：按需取天气、位置和视觉描述保留观察来源与有效时间视觉人物对应可信身份已有背景不必每次重新问图
- 讲解①：持续感知可以给出最近的舱内外描述，其他信息源提供天气、位置与时间。外面下雨、后排宝宝睡着，都会影响“车里有点闷”该怎样处理，帮助 Director 排除不合适的开窗或大风量。
- 讲解②：视觉描述中的人物需要和可信身份对应，不能凭一段画面文字多认出一名乘客。背景已经足够时无需每次主动问图；需要某个方向或细节时，再发起专门查询。观察不清楚或已经过旧，也要保留相应限制。

### C5｜用实际对话与执行事实承接前文（蓝底）
- 要点：保留用户目标和真实候选记清已发动作及工具返回区分已播、未播与被打断内容摘要仍需保留隐私和对象边界
- 讲解①：最近历史要让 Director 知道用户要做什么、上轮调用了什么、结果是什么，以及哪些内容已经说过。用户说“第二家”时，必须保留真实候选与顺序，只有一段简短推荐话术可能不够。
- 讲解②：端侧已经执行的动作和输出结果也会汇到这里，下一轮不能重复当成尚未办理。远处历史可以按配置压缩，但不能丢掉关键对象或把失败写成成功；新乘员加入时，敏感历史还需按隐私规则清理后再供给。

### C6｜告诉模型哪些安排仍在跟进（蓝底）
- 要点：提供当前任务或目标视图创建、等待、执行进度分别保留按当前渠道使用对应托管系统修改取消要定位真实任务
- 讲解①：Context 把当前项目仍在跟进的任务视图交给 Director，让它知道用户是否已经设过同一安排。例如十分钟后关加热已经注册，现在只是等待时间，不能理解成加热已经关闭。
- 讲解②：不同渠道可能使用 Goal 或 Task 托管，同一任务不应把两套系统串着走。需要修改或取消时，要通过真实任务标识找到对象，再交管理能力处理。仅凭标题相同或卡片出现，不能宣布后台任务已经完成相应变化。

### C7｜在推理前预取允许使用的相关记忆（蓝底）
- 要点：先核可信身份与读取授权画像和问题相关记忆可并行取按相关性过滤后注入本轮已有可靠答案就不重复查询
- 讲解①：推理前可以预取常用记忆。当前这套记忆准备方式一边获取画像，一边用用户问题形成检索线索，得到相关记忆与匹配分数，再按规则过滤。能否读取某人的记录，必须先由身份与授权决定。
- 讲解②：如果预取已经给出昨天游泳馆的可靠地址，Director 就可以继续判断导航，无需再查一次。这种标签与分数处理用于相应记忆来源，不能扩大成全部 Context 信息都必须采用同一种检索算法。

### C8｜让模型知道这辆车实际能做什么（蓝底）
- 要点：提供真实车型和设备配置列明参数范围及座位限制按渠道筛选可用工具实现缺能力信息时查证或澄清
- 讲解①：模型需要知道这辆车实际有哪些设备、允许的档位或温度范围，以及哪些座位能够控制。工具表里列有按摩，不意味着低配车型也具备按摩硬件，更不意味着当前渠道已经接入实现。
- 讲解②：能力定义、具体实现和运行条件由准入模块继续核对。车书介绍高配功能时，也不能直接套给当前配置。信息缺失就保留缺口，查询或澄清后再行动，避免模型用通用汽车知识补出车辆没有的能力。

### C9｜选取适用示例帮助判断而不扩大能力（蓝底）
- 要点：按问题寻找相关决策示例同时考虑车型、环境和对象区分召回、注入与模型采用现场事实与能力限制仍须满足
- 讲解①：动态示例把类似问题的决策过程提供给模型，帮助它选择工具或理解场景。例如“有点累”的示例可能包含按摩，但当前车没有这个功能时，不能照着示例发出动作。
- 讲解②：示例需要适合当前渠道、车型和舱内外情景。问题出现时，要分清有没有召回、是否真正放进输入、模型是否正确采用，以及实际工具结果怎样。召回一段文字只完成中间一步，不能由此推定整次行为已经修正。

### C10｜各来源处理质量后汇集并保留未知（蓝底）
- 要点：来源各自核权限、相关性与时效汇集不额外假设统一判真模型冲突信息保留来处和时间缺失值不在整理时擅自补齐
- 讲解①：身份、状态、记忆和知识各自处理相关性与质量后，在这里汇集。当前这条路径没有再安排一个统一模型替所有来源最终判真；相应来源应保留权限、有效时间和仍然未知的信息。
- 讲解②：比如旧偏好写用户不爱开窗，最新明确指令却要求打开，需要 Director 结合当下意图判断。Context 不应在整理时偷偷删除冲突或补出缺失车况。保留这些关系，下一层才能区分历史习惯和当前事实。

### C11｜把本轮输入与准备好的背景交给 Director（绿底）
- 要点：汇合输入、当前事实与项目规则保留工具、记忆和状态的来处信息足够就进入动作判断仍缺关键事实则保留查询出口
- 讲解①：Context 将有效输入与工具、示例、车型规则、记忆、状态和历史组织成这次模型请求。各部分仍应能辨认来处，便于理解某个判断为什么成立，也避免把旧话术当作当前车辆事实。
- 讲解②：到这里交付的是背景，具体动作由同一个 Director 决定。下雨和空调状态已经明确，它可以直接考虑降温方案；餐厅地址仍未知，就继续查证。组装过程不会自己启动导航或车控，也不能把未知自动变成确定答案。

### C12｜预注入不够时由 Director 显式查记忆（蓝底）
- 要点：带明确对象、关键词和时间范围记忆查询重新检查授权范围具体结果作为工具反馈返回经输入管理进入下一轮判断
- 讲解①：预先准备的背景仍无法回答“昨天去过的游泳馆在哪里”时，Director 发起记忆检索。查询要说明关注谁、找什么和什么时间范围，记忆服务再在合法范围内返回相关事实。
- 讲解②：结果以 tool_feedback 回到原调用，经过输入管理和后续背景组织，再由 Director 判断能否导航。记忆服务找到地址不会直接旁路开导航。只有缺关键记忆时才走这条显式查询，避免已经有答案仍重复调用。
