## 关键校正与未闭合问题

1. 事件、当前状态、运行埋点、Director event 输入、情景/语义记忆不是同一对象。
2. Trigger 触发时间是规则匹配时刻；事件字段的时间来源按生产合同解释，不能把落库时间当发生时间。
3. 一个定义对应一个来源是 8 月评审共识，不等于全系统已实现跨源幂等；操作与结果可以是两条不同事实。
4. TTS 恢复在 8 月使用临时 Frontier 链路；事件化与 Input Manager 协同当时待对齐。10 月 PRD 统一目标单独呈现，不拼成假想现网。
5. 入库 → 通知 → 消费 → 实际采用 → 用户结果分别验收；已落库不能证明模型见过。
6. 记忆生产异步：工具受理、pend、success、可召回不是同一状态。
7. 关闭生产/召回不等于删除；删除权限不应凭空要求记忆开关必须开启。语音批量删除需二次确认，10/19 是新增需求，缺上线验收。
8. 语义删除要处理画像；历史/摘要的 chat_id 清空不替代长期库清理；原始事件删除与衍生记忆删除的全链合同未确认。
9. 新乘客摘要隐私和未知乘客换人但人数不变的缺口明确写出；不把“未注册者不参与展示筛选”扩大为隐私无风险。
10. 事件模板全表、原文全部嵌入图像、全部车型配置和实车发布没有在本子任务全量核验，不提供当前可用事件总数。
