# 任务：把上汽会议结论拆成主动服务表格的“需改的触发条件和内容”

## 背景
- 用户是字节豆包上车（Driver Agent 2.0）Planner 模块的 AI 产品经理。字节和上汽 2026-11-11 开了一次“主动推荐双方沟通会议”。
- 字节内部要根据会议内容 + 上汽给的《座舱智能推荐框架》文档，拆出：主动服务表格里每个场景**要改哪些触发条件、推荐内容、端状态依赖**，以及**要新增哪些场景**。
- 主动服务表格 = 飞书多维表格《【DNA】主动服务（系统预设+静态advisor）》，字段：场景 / 需求来源（上汽侧提出|主线能力适配）/ 主线可复用程度 / 触发 / 实现方式（系统预设任务|静态advisor）/ 端状态依赖。
  - 名词：系统预设任务 = 车端/系统按固定规则直接触发的任务；静态advisor = 云端常驻的建议模块（舒适/出行/情感/内容），满足条件时给 Planner 一条建议，Planner 再决定是否说、怎么说。

## 输入（都在 src/ 下，已从飞书拉好，只读）
1. `src/meeting-saic-20261111.md` —— 会议**文字记录（逐字稿）**，取证优先级最高。
2. `src/meeting-ai-minutes.md` —— 同一会议的 AI 智能纪要，只作索引，结论必须回到逐字稿核对。
3. `src/internal-doc.md` —— 《座舱智能推荐框架》文档（保驾护航、情感关怀、兴趣延伸、功能发现、智能场景、智载空间等场景的触发条件、推荐内容、开关、显示规则）。
4. `src/records.json` + `src/fields.json` —— 表格当前 13 行内容（含空行）和字段定义。record_id 在 `record_id_list`，顺序与 `data` 对应。

## 要产出的东西
### A. `plan.md`（给用户看的拆解说明，中文）
对表格里每个非空场景逐条写：
- 现在表里写的是什么（触发 / 端状态依赖 / 主线可复用程度）；
- 会议上关于它说了什么（引用逐字稿时间戳，如 `00:23:15`，原话 ≤30 字）；
- 框架文档里它的触发条件和推荐内容是什么（标章节名）；
- **结论：要改什么 → 改成什么**，并标注属于哪类：「已确认结论」「讨论中观点」「待上汽确认」。会上只是提议或待定的，不能写成已确认。
另起一节写**建议新增的场景**（框架文档里有、表里没有，且会议上提到要做或要评估的），每个给出六个字段的草拟值。
再一节写**待确认问题清单**（谁来确认、问什么）。
开头放一张 mermaid 流程图，画清楚“触发条件满足 → 系统预设任务 / 静态advisor → Planner → 卡片/语音”的链路，以及本次改动落在哪一环。
写法要求：讲清楚，不套模板、不堆限定语、不压缩成一句话结论；不要把你的核验过程写进正文。

### B. `changes.json`（机器可读，供后续写回表格）
```json
{"update":[{"record_id":"rec...","场景":"...","fields":{"触发":"新值", "端状态依赖":"新值"},"basis":"已确认结论|讨论中观点|待上汽确认","evidence":"00:23:15 …"}],
 "create":[{"fields":{"场景":"...","需求来源":["上汽侧提出"],"触发":"...","实现方式":["静态advisor"],"端状态依赖":"...","主线可复用程度":"..."},"basis":"...","evidence":"..."}]}
```
只放有依据的改动；字段值写成可直接填进表格的成品文字。select 字段只能用表里已有选项。
