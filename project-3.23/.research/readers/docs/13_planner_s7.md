# 一、车场景痛点

1. **对于一些复杂、多步任务，需要用户一直给输入，模型缺失需要的上下文，比如：**

   - 口味偏好
   - 冷热偏好
   - 价格偏好
   - ……
2. **很多时候，用户只有一个大目标，没有小目标/明确目标（比如关于具体要做什么的更细化的需求），或者不知道功能怎么用：**

   - 想让座舱更舒适，但具体现在应该怎么操作呢？
   - 想在行程途中找一个充电站，但得考虑到达电量、顺路程度、价格、空闲桩，好头疼，怎么办？
   - 这次OTA更新了全域的领航辅助驾驶、还更新了个什么智能光毯，具体该怎么用呢？
3. **检索到想要的东西很费劲：**

   - 搜一个我想看的电影，很费劲，用户需要花大把的时间在分类搜索上，能不能结合我的偏好和当前的语音指令把这件事搞定？
   - 搜一个车内乘客都想吃的餐厅，很费劲，能不能把我们的需求都告诉豆包，基于位置，来给我一些最优的推荐？
4. **我讲一句，它应一句，一锤子买卖，需求不闭环**
5. **当前的闲聊聊不下去，既割裂，又没内涵：**

   - 不知道舱内外实际发生的情景
   - 不知道车辆实际所处的状态
   - 不知道正在做的事情（任务的进行状态）

……

上面这些痛点，是planner实际要解决的问题，基于此来定planner各迭代的体验目标。



# 二、2.6 整体目标

## 2.6 整体性能目标

- 快速响应：首字响应P50 ≤ 500ms，首字响应P90 ≤ 800ms
- 准确率优：推理ACC ≥ 90%，回复ACC ≥ 93%



## 2.6 细化体验目标

### 复杂车控【s7】

复杂车控对齐0.5---车控对齐路特斯/导航新增/媒体新增：

- ACC ≥ 90%
- 控制完成P90 ≤ 2000ms



### 任务拆解

1. 结合context（情景、状态、记忆）进行思考，提升任务拆解质量，部分case有效缩短复杂任务的轮数：**【s7】**

   1. 结合情景：
   
      1. 简单结合：下大雨不拆解出开窗
      2. 深度结合：推理代替分类，提升思考深度，举个例子——不同的人、在不同的场景中，对于“我饿了”是有不同的响应预期的
      
         1. 下班回家/导航去餐厅/导航去农家乐的路上：可能只是闲聊吐槽
         2. 长途高速出行的路上：可能想让后排帮他找点零食
         3. 真的想找个附近/沿途的吃饭的地方
   2. 结合状态：空调温度已经是最低时，不拆解出调低空调温度
   3. 结合记忆：
   
      1. 偏好记忆：用户不喜欢吹风，尽量避免大风对人吹
      2. 行为记忆：去昨天那个烤鸭店，知道昨天去的烤鸭店是哪里
2. 能够进行不同类型任务的拆解（多步任务、条件任务、持续任务），任务拆解合理（逻辑合理、下游可承接），延时可接受：

### 对话【s7完成对话融合，后续持续优化】

1. planner直接回复普通闲聊；悄悄话、唱歌、语气扮演等调用s2s满足，详细见：<cite doc-id="ApQ1wGDy2iXnLEkBEPhc8vL2nnd" file-type="wiki" title="【AI 汽车】对话需求" type="doc"></cite>
2. 解决当前闲聊的痛点：

   1. 聊天内容和车辆的情景、状态、任务割裂，没内涵
   2. 不能结合情景做动作（真正的闲聊很少，大部分对话还是和车状态/任务相关，比如我准备接朋友去吃个饭，很容易进入闲聊）
3. 做好快速**响应**，任务过渡和任务总结

   1. 快速响应：planner需要快速**响应**用户（响应话术，同时响应话术需要自然），性能参考【1. 整体性能目标】
   2. 任务过渡：任务的打断恢复需要有合理的话术来进行过渡，主观感受不生硬；多步任务之间的衔接需要有过渡话术；
   3. 任务总结：执行成功可以不播报，失败需要播报，介绍失败原因



### 任务和交互管理【s7方案，s8-s10上线+打磨】

1. 有一套鲁棒性高的、融合端云的任务打断恢复策略
2. 解决好 多任务的对话冲突管理
3. 交互内容关注用户当前的话题焦点和情景，有衔接性，以长时任务**功能介绍**为例：

   1. 用户已经触发过的，对于它的开启方式可以不介绍或者简单介绍
   2. 介绍的内容衔接上用户当前的话题，用户的关注重点已经到下一part，就不要在当前part长篇大论了



### 界面【s6-s7工程版】

s6-s7开发工程版界面，s8-s9对界面进行优化。
