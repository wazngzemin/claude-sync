# 原 20 张模块图：节点编号 → 节点名称（取自副本里的原画板，写正文时一律“编号（名称）”）

用法：正文里每次出现节点编号，都要紧跟括号写名称，名称用下表“图上名称”原文；同一段里第二次出现可以用不少于 2 个字的简称。

## 01 声音成为正式请求（V）
| 编号 | 图上名称 | 图上要点 |
|---|---|---|
| V1 | 麦克风收音：保留这一次是谁在说 | 车端持续采集用户原始语音；同步提供车机播放参考音；同一次输入关联音区与编号；OnePager 每 200 ms 分帧上送 |
| V2 | 一遍 ASR：边听边写出文字 | ASR 负责把声音写成文字；一边接收音频，一边返回识别；先追求及时得到过程文字；同时另一支 VAD 在观察停顿 |
| V3 | 过程文字：能准备，还没定稿 | partial 是此刻识别出的文字；后续音频可能修改前面的字；可供流式拒识和预请求准备；不是车控或导航执行授权 |
| V4 | VAD：观察说话和停顿 | VAD 检测人声活动与停顿；它与 ASR 同时工作；停顿达到不同阈值，做不同处理 |
| V5 | 短停顿 300 ms：先做准备 | 停顿到 300 ms：触发 Soft VAD；带当前文字发起一轮预请求；继续收音，不能结束 ASR；再开口再停顿，可再次触发 |
| V6 | 预请求只提前准备，不让车先行动 | 允许拒识、Context 等前置准备；关联 request_id 与 round_id；不执行工具，不播正式答案；不新增正式对话或抢占界面 |
| V7 | 停顿 600 ms：这一段收尾 | OnePager 的 Hard VAD 阈值；通知本段音频结束，等最终文字；600 ms 后还要识别和业务处理 |
| V8 | 二遍 ASR：给出本段最终文字 | 系统重新识别这一段音频；final 是本次识别定稿；用户不需要把同一句话重说一遍 |
| V9 | 正式文字能沿用上一份准备吗 | 必须仍是同一 request_id；final 等于前一轮预请求文字；相同才复用已支持的模块结果；不相同就按最终文字重算 |
| V10 | 语义判停：这句话意思说全了吗 | 停顿不一定意味着意思完整；“我想去……”可能还没说完；OnePager 提到语义 VAD 配合；门控顺序与延长上限仍待核 |
| V11 | 不匹配：按最终文字重新准备 | 文字改变或输入编号不同；重做必要的拒识与 Context；过期准备结果不能继续触发动作 |
| V12 | 把最终输入交给正式业务链路 | 交付最终文字和有效音区；携带同次输入编号及准备结果；接入口采信、拒识与输入管理；工具真实完成仍在后续链路 |
| V13 | 先检查语音能否用，不交给模型猜 | 语音初始化检查麦克风权限；再看 AI 开关和车型互斥状态；不允许时提示或按规则静默；已有交互必要时退出语音 UI |
| V14 | 声学前端：压低噪声和自己的回声 | 各音区原声进入供应商处理；降噪处理风声、胎噪、空调声；参考扬声器信号消除自身回声；输出干净音频供识别和判停 |
| V15 | 确认声音来自哪一座，不等于操控哪一座 | 声源定位给出说话人音区；检查这个音区是否允许交互；音区随 Query 和交互状态传递；设备目标位置由用户意图另定 |
| V16 | 热词增强：把当前人名、地点和按钮交 ASR | 来源含联系人、导航、媒体、车况；当前页面按钮也注册热词；记录字典是否真的进入识别请求；热词增强不保证每次识别正确 |
| V17 | 先约定 ASR 来源和上屏规则 | 离线与在线识别可各自有结果；先上屏的字不一定是最终采信；断网和离线业务按项目选来源；这不同于本地 LLM 的执行采信 |
| V18 | 识别失败：不要把临时文字偷偷当指令 | 无音频、空结果、超时要分开；保留原音与处理后音用于排查；二遍失败是否用一遍兜底待核；不得默认执行残缺高风险指令 |

## 02 有效入口与端云采信（R）
| 编号 | 图上名称 | 图上要点 |
|---|---|---|
| R1 | 识别这次从哪里进入 | 区分唤醒词、按键和已激活续说；区分未激活的全时免唤醒；确认车型与当前开放音区；不是所有输入都先喊唤醒词 |
| R2 | 激活态与免唤醒态使用不同通路 | 激活态允许端云并行准备；未激活先走本地流式召回；采到声音不等于全部直接上云；按项目配置开放可用音区 |
| R3 | 让端云认出这是同一句话 | 同一次输入使用关联 request_id；保留 session、音区与时间；本地云端候选能对到同一句话；不同编号或旧结果不能串单 |
| R4 | 本地 LLM 产生有限范围的候选 | 承接已支持的本地车控等能力；可做轻量位置、对象、功能继承；不能替代联网搜索与复杂规划；候选产生后仍要等采信门槛 |
| R5 | 本地候选是否已获得执行权 | 正常联网：本地模型候选不执行；断网或云端 3 秒超时才启用；分别处理 FC、reject、；unsupported；确定性缓存走独立优先通路 |
| R6 | FC：把操作意图变成执行参数 | 明确设备、目标位置、动作和数值；校验本车型能力及参数范围；适配厂商协议交实际执行方；FC 生成成功不等于车辆已完成 |
| R7 | 正式拒识：是对豆包的诉求吗 | 针对 final 判断是否应该接话；不是简单复杂或车辆能力判断；通过后交输入管理与 Director；端云部署按项目，独立文档缺权 |
| R8 | 交输入管理，准备进入 Director | 有效 Query 保留说话人及音区；交输入管理处理合并和优先级；再以 Context 进入 Director；旧意图/简单复杂并非必经漏斗 |
| R9 | 实际执行后拿到真实结果 | 执行方校验当前状态并操作；分别返回完成、失败或部分成功；有真实反馈才决定怎样答复；已接收或处理中不能报已完成 |
| R10 | 拒识：不接无关对话 | 无关聊天不形成新的用户任务；未上传的免唤醒拒识可静默丢弃；若先停过播报，另看恢复规则；不要取消正在处理的有效请求 |
| R11 | 断网或云端 3秒超时：启用有限兜底 | 按 AIVA 9 月 30 日口径监测；超时才解锁本地候选采信；只使用本车已交付的离线能力；网络恢复和重同步规则仍需验收 |
| R12 | 把本地结果同步进端云上下文 | 同步 Query、回复和真实执行结果；带请求编号、音区、参数和时间；拒识/FC/不支持结果明确区分；下一轮继承不能凭播报猜状态 |
| R13 | 未激活：本地流式判断是否召回 | 边识别边判断是否在叫助手；出现 attend 可提前释放音频；一直未召回则继续等最终结果；最终拒识且未上云时静默结束 |
| R14 | 已放行：补齐音频，交云端最终判断 | attend 后启动云端 ASR 与拒识；final 为 FC 或不支持可补整段音频；已上传不能因本地 reject 撤回；以云端最终召回/拒识决定后续 |
| R15 | 确定性缓存命中：只接唯一明确指令 | 先匹配项目明确配置的正则缓存；单轮、无上下文、意图槽位唯一；命中可跳过本地 LLM 计算；“暂停/继续/就选它”不能泛化缓存 |
| R16 | 本地候选分成三类，不能只写成功/失败 | reject：认为不是对助手说话；FC：已有结构化可执行候选；unsupported：诉求有效但本地不会；分类结果先保存，不等于已执行 |
| R17 | 兜底后云端迟到：不得再次执行 | 记录本次请求已经采信哪一侧；本地兜底后关闭旧云端执行资格；迟到结果只归档，不变成新指令；同时检查重复回复与重复历史 |
| R18 | 本地也不会：限次提示，不谎报完成 | 兜底候选为 unsupported 时失败；按项目说明网络异常或能力边界；同一唤醒周期提示最多一次；不把有效需求伪装成无关聊天 |

## 03 输入管理（M）
| 编号 | 图上名称 | 图上要点 |
|---|---|---|
| M1 | 接住四类输入，保留来处 | 用户 query：这次要做什么；advice：主动服务或任务建议；feedback：真实工具返回；event：打断等已发生事件 |
| M2 | 核对正在算、正在说、已在做 | 模型仍在生成还是已交结果；声音是否真正从车内播出；工具是否已经发出副作用；不要只用“首字到了”判断 |
| M3 | 前台是否空闲，能否直接接入 | 没有候选计算、没有承诺输出；空闲：按队列取下一条输入；后台任务继续不等于前台忙；同车同会话的状态隔离 |
| M4 | 可重算吗：先看工具是否发出 | 未发布动作：可取消旧候选；已发布动作：旧请求不能重放；新旧输入合并须按输入类型；P1 合并边界存在文档冲突 |
| M5 | 谁插入：用户优先，普通消息排队 | 用户新话 P0：打断处理；普通建议、事件 P1：按策略等；同步整批 feedback 单独接入；高优 advice 暂无实际类型 |
| M6 | 取消推理和声音，不抹掉已做的事 | 保留已播、未播、已下发事实；只撤销对应 request 的输入；已执行车控不会自动回滚；旧反馈仍需关联原调用接收 |
| M7 | 组成这一轮输入，生成有效身份 | 保留原 request 与输入来历；新执行生成独立轮次标识；旧轮不能写入新轮输出；依赖工具结果不可凭空补齐 |
| M8 | 普通输入等待，避免重复和串单 | 建议/事件按合并规则等待；完整工具批次不随意混入；TaskRun、tool_call 去重；队列满载和过期规则待核 |
| M9 | 发计算许可，再看输出许可 | 可先算下一轮，不等于可说；前轮播报中可保留候选结果；允许外显后才播报/发新动作；具体能力受新链路开关控制 |
| M10 | 客户端报告真实播放进度 | STARTED：已实际出声；PROGRESS：真实播放位置；FINISHED：轮结束且队列清空；ABORTED：本播放实例已终止 |
| M11 | 等不到终态：解锁但不伪造成功 | 软期限：播放完成未确认；硬期限：播放状态超时；释放队列不等于已经播完；重报幂等，旧轮不可推进新轮 |
| M12 | 故障恢复先防重复副作用 | 持久化/原子写失败不绕过准入；租约过期先恢复合法持有者；已发工具的旧请求不重跑；分别验收文本、工具、无音频轮 |

## 04 上下文准备（C）
| 编号 | 图上名称 | 图上要点 |
|---|---|---|
| C1 | 接本轮输入，按需要并行取背景 | Context 只组装，不包存储；身份、状态、视觉、历史并行供给；常用信息预注入，缺项再查；不是所有 query 固定查全套 |
| C2 | 确认当下说话人与操作对象 | 当前乘客姓名、座位和可信身份；人名→此刻座位，不用旧记忆猜；未知/冲突交 K 身份链处理；给明骏加热→明确副驾加热 |
| C3 | 取车辆此刻的值和时间 | 空调/车窗/挡位/续航/导航等；常用状态固定注入并去重；缺失或过期不当关闭/零值；当前上报优先于旧对话印象 |
| C4 | 取舱内外情景，不把视觉当身份 | 天气、位置、时间及感知描述；乘员动作、外部环境按来源提供；FaceID 与视觉人物要对齐；背景感知≠每次主动拍图问答 |
| C5 | 接最近对话、工具事实和摘要 | 保留用户目标与已完成动作；工具反馈与用户话语分清；摘要隐私清理见 K12；新轮不重复旧轮已下发动作 |
| C6 | 带任务视图，区分旧Goal 与新 Task | 本项目注入 goal_list 或 task_view；只读正在跟进什么及其状态；创建成功不代表条件已触发；具体生命周期转任务系统 |
| C7 | 第一路：推理前预取常用记忆 | 用户画像与相关记忆并行取；query→标签→记忆及匹配分数；记忆来源按分数过滤再注入；隐私与授权先走 K 规则 |
| C8 | 注入本车型可用能力与知识 | 真实车型/配置/功能边界；工具定义和实现按渠道筛选；动态工具准入细节见 F；有工具名≠有设备/已上线 |
| C9 | 选适用示例，不覆盖真实约束 | 静态示例教通用决策方法；动态示例检索低频单点经验；先核渠道/环境/车型/舱内外；召回、注入、采用分别验收 |
| C10 | 各来源各自过滤，保留未知 | V2 已取消统一模型精筛；来源校验范围、时效和相关性；冲突信息保留出处和待确认；不能混成一条万能“真相” |
| C11 | 组装本轮背景给同一个Director | 背景＋输入＋项目提示词；静态规则与动态数据分开放；按目标渠道变量映射注入；信息够则回答，不够再查证 |
| C12 | 第二路：Director缺记忆才显式查 | 携关键词与需要的时间范围；记忆工具重新检索并做权限过滤；结果作为 feedback 进入下一轮；不绕过输入管理直推新动作 |

## 05 Director 理解与规划（D）
| 编号 | 图上名称 | 图上要点 |
|---|---|---|
| D1 | 接本轮输入与多路背景 | 四输入由 M 统一安排进入；Context 提供当前已知事实；按上汽/赛力斯提示词使用；Planner 与 Director 不串联 |
| D2 | 辨认用户目标和本轮对象 | 明确指令：准确执行不加戏；模糊诉求：结合场景补足目标；建议输入：判断是否采纳；反馈输入：判断进展而非新命令 |
| D3 | 信息够吗、功能可用吗、安全吗 | 缺事实：查询；缺选择：澄清；车型能力、参数范围、音区核对；驾驶状态与隐私权限核对；语控不支持≠车辆没有功能 |
| D4 | 缺可查询事实：只发查询这一步 | 状态/记忆/视觉/联网各找其源；先拿真实地址，再规划导航；已有背景够用不重复查；等待结果经 M 回来再推理 |
| D5 | 不能直接做：解释、澄清或拒绝 | 目标歧义先问最少必要问题；不可感知条件不能虚构触发；越界/危险请求不给动作；可替代方案说明限制与原因 |
| D6 | 现在执行，还是交任务系统跟进 | 即时：本轮给工具执行；定时/条件/持续：创建跟进任务；新 Task 与旧 Goal 按渠道选择；注册成功不等于未来动作完成 |
| D7 | 把人话改成明确对象和动作 | 人名→当前座位；序号→真实候选；补全设备、方向、动作与参数；保留用户限制，不擅改目标；调用参数以项目工具定义为准 |
| D8 | 用现场事实排除不合适动作 | 雨天车闷：不要自动开窗；已最低温：不再重复降温；老人宝宝：避免后排大风；偏好影响方案，但不压过安全 |
| D9 | 同轮放独立动作，依赖动作留下一轮 | 单轮 action_list 默认并发；有数据依赖：分轮执行；导航互斥工具不可同轮争抢；同轮顺序写在数组里不算串行 |
| D10 | 决定是否说话，避免空话与预承诺 | 简单查询/车控可不说首轮空话；执行前只说准备，不说已完成；等齐结果后统一说关键结论；续说看信息价值与用户新意图 |
| D11 | 输出一份说做一致的决策 | talk_or_not：这轮是否开口；talk_content：话术与语气标签；emoji_id：表情；action_list：动；作；动作去 E，语音/表情走 |
| D12 | 读真实反馈，决定完成、再查或继续 | 由 E→M 回来，不自建第二回路；部分成功就只确认成功部分；受理/等待仍未完成用户目标；补查/替代/下一步仍经 D11 输出 |

## 06 工具执行与反馈（E）
| 编号 | 图上名称 | 图上要点 |
|---|---|---|
| E1 | 接动作列表，核对调用身份 | 解析 tool_name、action_content；每个动作关联唯一调用标识；保留原用户目标与本轮身份；格式失败不能当执行成功 |
| E2 | 找本项目已发布可用实现 | 定义名→渠道/应用/环境实现；检查启用、版本及权限；未接入与临时失败要分清；工具全集展开见下方40行清单 |
| E3 | 获得发布许可，按同轮规则发出 | 先通过 M 的输出/副作用许可；登记调用后才对外发动作；独立工具并发，互斥工具串行；动态加载与准入条件展开见 F |
| E4 | 交单个 Agent 执行内部业务 | 取依赖→选执行器→调用服务；统一响应，再做业务后处理；UI/模型/语音三路内容分开；具体流程按工具合同，不一刀切 |
| E5 | 返回的是受理、处理中还是完成 | 车控执行、任务注册、订单确认不同；生成中不写成图片/报告已出；Agent is_finish 只表流结束；按业务状态字段继续追踪 |

| K10 | 返回可用记忆，再同步新交互历史 | 预取结果回 C11 背景汇集；显式结果回 E→M→D；事实带对象/时间/范围；交互历史同步支持下一次连续性 |
| K11 | 记忆开关：冻结不是删除 | 关：停止新记录与记忆生成；旧内容保留但不再召回；近轮原始对话仍可能回答；重新授权/开启后恢复合法使用 |
| K12 | 多人隐私：新人上车清摘要敏感信息 | 在场人范围决定共同记忆过滤；新注册人或未知人数增加触发清理；未知换人但人数不变是覆盖缺口；共享身份与共享生成不是同一事 |
| K13 | 删除：先辨范围，批量二次确认 | v1.10新增车主语音删除需求；语义与情景可按范围删除；按人/日期/全部先由 D 确认；旧工具表“不删除”存在版本冲突 |
| K14 | 删除后联动画像、历史和摘要 | 语义删除后更新相关画像；新chat可逻辑清历史与摘要；长期库删除另走管理接口；一键除痕验收多处一致 |
| K15 | 按生产→召回→使用验收，不混责任 | 生成任务 pending/success分别查；验证身份/开关/多人/跨车边界；召回正确还需检查 D 是否采用；记录延迟、错记、漏记和越权 |

## 12 任务生命周期（T）
| 编号 | 图上名称 | 图上要点 |
|---|---|---|
| T01 | 接住未来或持续的诉求 | Director 接到未来/持续诉求；任务类入口透传原话与对象；现在关加热走即时车控；创建受理不等于未来执行 |
| T02 | 弄清要办哪一件事 | Seres：先查询现有 TaskView；Spec Builder 决定增改删查；Task Agent 只做请求入口；修改/取消必须定位原任务 |
| T03 | 条件能看见，动作能执行吗 | 对象、观察条件、动作、结束策略；检查实际信号/工具/开关/配额；不能观察的目标须拒绝或澄清；信息齐备才建立可靠安排 |
| T04 | 登记什么时候再叫醒任务 | 按时间/条件/周期/视觉注册；Trigger Adapter 转换规则；保存任务与回调关联；注册失败不可宣告正常等待 |
| T05 | 先保存 Task，再登记触发 | Task 保存目标与结束策略；Run 保存某次执行；Event 留状态变化事实；保存成功≠规则注册成功 |
| T06 | 等待下一次触发 | Seres Task 等条件，不占 Director；周期任务每次产生新 Run；技术 waiting 指等待激活；UI v0.4 waiting 却指创建中 |
| T07 | 触发来了，任务还有效吗 | 恢复任务，拒绝关闭/重复回调；Trigger 已完成原条件判断；额外执行约束才查 Context；无人等情况可跳过本轮 |
| T08 | 把本次建议交回 Director | 先绑定 Task/Run 与推荐 ID；Recommend→Frontier→客户端；客户端回流→输入管理；Director 再规划本轮动作 |
| T09 | 拿到真实执行结果再记账 | Flow 汇总真实 Agent/Tool 结果；独立 Result Hook 更新 Task/Run；成功/失败/跳过分别记录；TTS播完不等于任务成功 |
| T10 | 继续等，还是结束整条任务 | 单次完成→关闭整条目标；周期/持续→按策略继续等待；失败/跳过是否续跑单独定义；结束同步规则清理与视图 |
| T11 | 用户修改、取消或暂停 | 修改：更新规格与原规则；取消：关目标、清规则、停后续；直接GUI不在普通取消覆盖内；一期删除/预设暂停；周期暂停二期；GUI多用户/重试/用户取消待验 |
| T12 | TaskView查询与任务中心展示 | 语音查询只回状态，不代表执行完成；我的任务 / AI服务 / 场景预设；我的任务46：定时20+条件20+长时6；云更新push；开机/登录拉取；UI状态须与后 |
| T13 | 渠道路由：谁拥有长期任务 | Seres：自建 Task Service；saic-dna：Extour Goal；不是所有渠道都已迁移；同一任务不能双系统同时接管 |
| T14 | 上汽：提交并创建Extour Goal | add_goal 携带目标和上下文；Extour 管目标与触发；creating 只表示请求受理；静态 Advisor 仍另行运行 |
| T15 | 上汽：创建成功直出 Goal 卡 | 创建前铺垫话术可播报；creating/成功禁播，只同步状态；成功Goal卡直达；失败回Planner；创建卡≠触发≠实际执行 |
| T16 | 上汽：触发建议经客户端回流 | 触发先发Recommend执行卡；首跳不播报，二次上行回Director；7/1方案：无操作默认执行；多条建议当时latest wins，不排队 |
| T17 | 上汽：消费、关闭和 done 分开 | consumed设计：进入Planner≠完成；close关闭目标；finish仅同步done；update入口与消费回报路径待补；Goal状态与Task状态需 |
| T18 | 终止后截断迟到回调与旧目标 | 取消/下电/过期按各类策略关闭；停规则、更新有效视觉目标；直接GUI在途停止仍待验证；迟到回调不应再推进旧任务；已执行动作不会因删卡自动撤回 |
