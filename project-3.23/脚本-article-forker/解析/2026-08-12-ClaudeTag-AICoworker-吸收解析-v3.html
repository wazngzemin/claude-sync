01 · 文章开头

作者想让你相信的第一件事

原文说了什么：一个月前，Anthropic 在 Slack 里上线了 Claude Tag，外界当成随手发的小功能。但 Anthropic 内部把它当下一代爆款建设，觉得它可能是 10x Claude Code 的产品形态，对应万亿美元市场。作者借 Karpathy 的话说，AI 产品进入第三阶段：Chat、本地编码 Agent、AI Coworker。背后是三种迁移：单人到多人、被动到主动、同步单次到异步长程。作者还预告：现在产品团队超过 65% 的代码由 Tag 完成，一些员工 90% 的工作已经在用 Tag。
人话：作者在开头就下结论：这东西很大，你们外行没看懂。顺便抛出三个变化方向：AI 从一对一变成一对多，从你问它答变成它自己找活，从马上办完变成慢慢跟进。
对不对

开头这段的 10x、万亿美元，是作者观点，没有数据，信 2 成。但 Karpathy 的三段论值得记，全文都在展开它。

跟你有什么关系

你的产品正好跨在“同步到异步”这条线上：问“开空调”是同步，说“到终点前 1km 提醒我”是异步。这篇文章讲的就是后一半怎么做。

02 · 第一章：产品是什么

它就是拉进群里的一个数字员工

原文说了什么：Claude 以团队成员身份加入 Slack 频道，获得团队全部 context，用户在聊天框、文档里 @claude 就能派活。现在还在 beta，需要同时有 Claude 企业账号和 Slack 企业账号。只在公共频道可用，按 usage 记账，价格和 API 一致；私聊不算 Tag，要绑自己的账号走会员套餐。支持几乎所有 MCP 集成，可接 GitHub、Notion、Google Drive、Snowflake。Runtime 全部由 Anthropic 云端托管，每个 thread 起一个临时 sandbox，跑完整 agent loop。模型可接 Fable 5、Opus 5、Sonnet 5、Opus 4.8、Opus 4.7，管理员后台切换，员工也能直接说“这个用 Opus 5”。
人话：你把它想成拉进飞书群的一个 AI 同事。谁都能 @它派活，它看得到这个群的历史，接了很多外部工具。它所有的运行都在 Anthropic 的服务器上，不在你公司里。注意两个细节：只有公共频道能用，私聊不算；按用多少算多少钱。
难词人话
Slack国外公司用的群聊软件，约等于飞书。
MCP给 AI 接外部工具的统一插座，接上就能用。
sandbox每次任务临时开的一间隔离小房间，干完拆掉。
agent loopAI 自己循环：想一步、做一步、看结果、再想。
usage 记账用了多少量算多少钱，不是包月。
对不对

产品形态描述准确，也能核实：6 月 23 日官方上线，8 月 3 日旧的 Slack 集成切换完成。“只做公共频道”这一点很关键，下面会解释。

跟你有什么关系

你的产品也分公开和私有：车辆状态、事件日志是公开上下文，个人记忆、face_id 是私有上下文。Tag 的频道设计，跟你们 Context 的权限分层是一个道理。

03 · 第二章：三个关键能力

好用不在入口，在三件事

第一件事：Long-horizon autonomy，能自己干多久

原文说了什么：模型只能自主几分钟，适合 chat；能推进约一小时，本地编码 Agent 成立；稳定几小时后，才值得做 async agent，人下班它继续，最后带结果回来。Anthropic 说 Mythos 已经能完成人类专家连续 16 小时的任务。再叠加 Self-schedule：先做完现在能做的，把下一步排到未来，比如下周三回来查实验数据，中间的等待、唤醒、衔接都自己完成。
人话：产品形态跟着“一口气能干多久”走。干得短就做对话框，干得长才配做“没人看着也干活”的同事。Self-schedule 就是它会自己设闹钟。
对不对

“时长决定形态”信 9 成，是全文最有用的判断。16 小时这个数字，我没查到公开的 METR 结果；Mythos 5 只通过受限项目开放，6 月还因出口管制全球暂停过，外部用户未必拿得到这个能力。

跟你有什么关系

你的长时任务就是 async agent。“到终点前 1km 提醒我”，系统要自己等条件、自己醒来、提醒完自己关任务。这就是为什么光靠对话历史记不住，必须有 Task、Trigger、真实状态。

第二件事：Memory，记忆怎么做

原文说了什么：记忆方案试了很多，最好用的是最朴素的文件系统：给模型一块能长期读写的空间，让它自己维护。分三层：Thread context 是当前任务过程；Channel memory 是频道长期规则和决策；Workspace memory 是全公司记忆，别的公共频道能复用。频道之间默认隔离，像一间间办公室，授权才能串门。高阶模型强在“蒸馏”：不只记录事件，还会判断这段经验以后能泛化到哪。
人话：记忆别搞复杂，给块地方让它自己写。但按圈子隔离：当前任务一层、团队一层、全公司一层，没授权不能乱看。
对不对

分层思路对，信 8 成。但“文件系统最好用”是小团队快试的结论，量产座舱要结构化、可追踪、可删改。

跟你有什么关系

Thread 等于任务级 Context；Channel 等于车企车型版本的真值；Workspace 等于通用工具契约和评测。车内还多三道：人物、车辆、驾驶安全。

第三件事：EQ，什么时候主动、什么时候闭嘴

原文说了什么：Anthropic 专门训练了情商和分寸，让 Tag 判断何时主动帮忙、何时退居幕后。作者试用后说它比 Claude Code 情商明显高一档，很有活人感，表情包也用得熟。
人话：主动帮忙也有时机问题。会看脸色的 AI 才不招人烦。
对不对

方向对，但不能只靠模型“有情商”。权限、频控、互斥这些要硬规则兜底。

跟你有什么关系

你们群里正在问的三件事：AI push 展示多久、能不能并行、跟别的卡片谁让谁。这就是 EQ 的产品化，必须有人拍板规则，不能指望模型自己把握。

04 · 第三章：它解锁了什么

两类新工作，加三个内部雏形

原文说了什么：短期它接的是基础执行，像初级运营、行政或工程师。相比 Claude Code 多解锁两类工作。第一类，高协作高 Context 密度：Claude Code 是单人模式，要人先把上下文压缩整理再喂；Tag 常驻群聊，天然知道来龙去脉，谁都能补充纠偏。第二类，主动响应：线上出事，它自己拉监控、定位、写修复、找负责人审批，人只点同意。判断标准：越需要协作、越依赖上下文、越要及时、越碎片越脏没人愿意干，越适合它。
人话：它吃两种饭：一种是“信息散在很多人和很多消息里”，一种是“这事没人盯着，出了事才想起来”。文章给了一个四问判断法：要不要协作、要不要大量背景、要不要马上反应、是不是没人要的脏活。
对不对

这个四问很好用，可以直接拿来筛自己的场景，信 8 成。

跟你有什么关系

“媒体卡片无故弹出”“POI 进四套能力互相不通”，全是高 Context 碎片活。区别是：车上不能让它自动改生产，先做识别和分诊。

内部三个雏形，是全文最惊艳的部分

原文说了什么：一是共享大脑：人只能同时聊一场，Claude 能同时几千场，都跑在共享记忆上。设计负责人 Meaghan 说 Tag 会突然插话：“某某刚就你问的事做了决定，你可能要调整”；“另一边刚把这个改名了，我把文案一起改掉”。为了喂原始上下文，Anthropic 刻意公开文化、减少私聊。二是数字分身：长期参加设计 review，它学会了 Meaghan 的偏好和提问角度，会主动提案，甚至替她找同事讨论。三是端到端负责：让 Tag 为一个渠道的留存率负责，每周读数据、定位、提假设、改代码提 PR、小范围发布、监控、通知负责人。这活平时要好几个人干。
人话：AI 不只干活，还知道全公司在发生什么、学会某个人的风格、为一个业务结果负责。这是三个由浅到深的层次：知道得多、像某个人、背结果。
对不对

要打折扣。文章自己说内部用的是“更先进的模型”，外部用户拿到的可能是降档能力。且“公开文化、减少私聊”是大前提，多数公司做不到。

跟你有什么关系

你的产品群、Bug 群就是公开频道。真正的问题不是 AI 看群，是车上的公开上下文和私有上下文怎么分，以及 AI 主动插话时谁承担责任。

05 · 第四章：它怎么诞生

两个做产品的方法

原文说了什么：Anthropic 做产品有两个偏执。一是 Dogfooding：产品团队分 Product Team 和 Labs；Labs 两条线，Close the Gap 缩小“理论能做”和“实际在用”的差距，Advanced Scout 提前做模型六个月后才会做好的产品。几百个原型大多数死掉，Tag 内部用了几个月，今年 6 月才对外。二是面向未来：找足够宽的容器，吃模型进化的红利。当年 Claude Code 不做自动补全，改做完整编码 Agent，一年后模型追上才爆。今天倒推：“假设 Claude 8 已经存在，人们会怎么用，今天该搭什么”。
人话：他们的办法就两句：自己先天天用；产品留够空间，等模型追上来。不追热点，赌形态。
对不对

Dogfooding 方法好。但“Anthropic 几乎没有失败产品线”是品牌话术，文章没给证据；“OpenAI 烂尾无数”同样是立场，不是事实。

跟你有什么关系

你们的路测、Bug 日清就是 dogfooding。你缺的是固定回流：每次坏 case 修完，把规则写回契约和评测，别只在群里说一句。

文章给 Tag 的三层意义

原文说了什么：第一层，打通 Context 的交互入口：模型继续变强后，限制产品的不是智力，是上下文完整度；与其让人梳理打包，不如让模型住进原始上下文。第二层，真正的数字员工，有记忆、有主动性，为完整项目负责。第三层，AI Firm OS：公司的共享大脑，把组织经验沉淀下来。AI 最深远的影响可能是集体智能：人可以分工，很难合并大脑；会议、文档、周报都是低带宽的合并工具。Tag 可以 Fork 也可以 Merge，副本并行探索，再把经验合并。
人话：未来不只是每个人更快，是“整个公司像一个脑子”。开会、写文档其实是人脑之间传话的低速通道，AI 能把经验直接合并。
对不对

这是全文最有想象力的部分，也是最少证据的部分，信 3 成。

跟你有什么关系

你们的产品文档、会议纪要、Bug 群就是“低带宽合并工具”。你正在做的业务语义表，就是在做车上的“合并接口”。

06 · 第五章：能不能爆发

市场预演过一次，然后卡住了

原文说了什么：先讲 Viktor：同类产品，2 月发布，10 周约 1500 万美元 run-rate，12000 多家下载，2000 多家付费，5 月拿了豪华融资，Slack 两个联创都投了。但它的客户大多是 25 人以内的小公司。两个卡点。一是成本：20 人公司放开用一个月烧几万美金。贵在 cache 命中率低：一对一对话上下文是连续线，容易复用；多人协作异步，今天你发起、半天后别人接上，cache 已失效；几百个 connector 更放大。二是安全权限：像自动驾驶，99% 可靠不够，剩下 1% 决定落地；据说只有 Fable 5 或 Opus 5 级别能可靠隔离。用户评论：“像把整个公司交给 Anthropic，再租回来。”
人话：市场预演过一轮，但只在小公司成立。两大拦路虎：太烧钱、不敢放权。
对不对

Viktor 融资属实，1500 万是年化 run-rate，不是收到的钱，后续订阅 ARR 约 1380 万。成本数字是作者自述，没有独立来源。

跟你有什么关系

“cache 命中率低”翻译成你的语言，就是 SP 固定前缀的 KV 命中、Context 每轮注入什么。端状态筛选加 150 到 250ms、记忆 P90 超 600ms，就是同一个问题的车内版本。

07 · 第六章：五个延伸思考

后半篇从产品转成商业推演

原文说了什么：一是范式：Chat 到 Coding 到 Coworker，每次跃迁大一个数量级，打开数万亿市场；Teams 版本会来，未来和企业版个人 Claude 打通，变成每个人的数字分身。二是数据：Tag 是采集企业长尾数据的载体，轨迹质量高；受条款限制不能直接用原始数据，但可匿名聚合看规律、员工反馈默认可训、Development Partner Program 用折扣换自愿共享；云端 runtime 让开源拿不到完整轨迹，差距拉大。三是护城河：记忆可导出，护城河在运行状态，数百个未完成任务、权限、依赖迁不走。换供应商等于换一批在职员工。四是归谁：国内是字节腾讯阿里的大厂游戏，飞书并入豆包合理，豆包战略指标转向 B 端；海外模型层机会更大，因为 API 毛利假设 80%、成本差 5 倍，加上 Context 碎片化。五是 ARR：扩散更快、自发持续烧 token、从工具预算走向人力预算，三条叠加给 Anthropic 第二条增长曲线，也是 AI CapEx 周期下一个验证题。
人话：后半篇从“产品长什么样”转成“谁会赢、值多少钱”。这些是观点和假设，不是事实。
主张信几成理由
范式跃迁方向5 成方向对，但每次“大一个数量级”没有测算。
数据飞轮让闭源差距拉大4 成机制成立，但企业数据恐惧和监管会反拉。
运行状态是迁移成本8 成全文最硬的判断，与 Palantir 篇结论互相印证。
国内是大厂游戏4 成方向合理，飞书并入豆包没查到独立来源，车企还有自己的入口。
海外归模型层4 成成本差和 Context 碎片化成立，但 API 毛利 80% 是文章自己写的假设。
万亿美元市场2 成估算，无测算过程。
跟你有什么关系

你就在“国内大厂游戏”这局里：字节有豆包（大脑）和飞书（环境），你负责的是车这个新环境。你的上坡路，是把车端做成有语义、可交付、可追踪的环境层。

08 · 黄钊评注

他的拆法，就是你以后读文章的模板

黄钊做了什么：他把长文里跟“产品怎么做”有关的部分拎出来，一条一条加自己的判断。a 产品形态细节；b 自主时长决定产品形态；c 记忆三层，加一句“有时做 A、有时做相反的事，是真正智能和旧规则的分水岭”；d 解锁两类工作；e 三个雏形，加张和老师“一切问题群聊”；f 集体智能；g Dogfooding，他说外界和 Anthropic 的差距至少 3 到 6 个月；h 模型够不够，官方说 Mythos 才解锁，作者说 Opus 4.6 就行，两人都没给公开评测；i 两个卡点；j 为什么对模型公司重要；k 护城河归谁，国内大厂、海外模型层。
人话：黄钊做的事，就是把文章拆成五栏：产品形态、机制、案例、卡点、商业影响，每栏加自己的判断。你以后读文章可以照这个模板。
哪句最值得记

“3 到 6 个月差距”和“有时做 A、有时做相反的事是真智能”。前者提醒你别高估公开产品，后者是判断智能的标尺。

跟你有什么关系

你的车就是 2B 和 2C 连在一起的例子：车企是客户，坐车的是个人。这正是黄钊说“2B 和 2C 是通的”的地方。

10 · 落到你身上

全文就一件事：长时任务要跑通七段

文章讲了那么多，落到你的产品上是一条链：用户说“到终点前 1km 提醒我”，系统要自己接任务、写清目标、记住状态、等条件、醒来、执行、关任务。七段缺一段，就是你们现在看到的“丢三落四、下电后忘记、触发时机错误”。
两句最该带走的话

一，产品形态跟着模型自主时长走，你做的长时任务就是第三段。二，记忆可以导出，运行状态才是迁移成本，你维护的 TaskSpec、Trigger、工具契约就是座舱版运行状态。

11 · 明天做什么

三件事，都带台词

明天 Bug 日清会，把 AI push 三问单独提出来。

展示时长、能否并行、与其他卡片互斥，这三个问题现在没人拍板，下周还会出新票。

会上说：“Bug 之外有一个产品问题需要拍板。AI push 的展示时长、并行上限、卡片互斥，今天不确认，主动服务下周还有新票。请明确 Owner 和时间，我按结论补规则。”
给长时任务做七段证据表。

拿“距终点 1km 提醒”和“歌曲结束后停止”各一条，按七段找日志，缺哪段标哪段。

对研发说：“先不修模型。给我这两条 case 的七段日志，第一次偏离在哪一层，就改哪一层。缺的段我标出来，按段补证据。”
用判断器筛场景，只挑一个进 Task+Trigger。

距终点 1km 提醒最适合先跑通。宝宝哭、媒体卡异常、通勤内容编排按四道硬门降级：事实、动作、权限、可验收，缺一项就不进自动执行。
