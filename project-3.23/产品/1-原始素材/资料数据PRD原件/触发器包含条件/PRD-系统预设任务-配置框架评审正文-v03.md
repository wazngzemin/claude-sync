## 系统预设任务整体配置

### 3.1 建设背景与目标

现有触发器平台支持部分条件与动作配置，但系统预设任务所需的卡片、语音播报、二次确认及后续动作尚未形成完整配置链路。端侧任务仍依赖逐项开发，同类场景的规则和交互难以复用。

本需求扩展现有场景配置平台，统一定义任务关联、触发事件、判断条件、交互方式、执行动作和结果处理。配置人员可通过组合已接入能力创建或调整任务，减少重复开发，降低后续迭代成本。

建设范围覆盖天气路况保护、儿童锁、后视镜加热和充电口盖四项任务所需的公共配置能力。新增信号与动作按统一规格接入能力库；端侧与云端分别管理能力支持范围，未完成接入的能力不可用于任务发布。

### 3.2 基础配置

| 配置模块 | 配置项 | 配置规则 |
| --- | --- | --- |
| 基础信息 | 场景名称；优先级 | 场景名称说明使用场景与目标动作，便于检索和维护。场景优先级与卡片展示优先级分别管理，映射规则由触发器与VUI确认。 |
| 发布范围 | 渠道；指定车辆；适用车型；软件版本及比较方式 | 先选渠道，再展示该渠道可用能力。指定车辆支持多选；车型或版本不限时明确显示“全部”。发布前展示实际生效范围，避免误选范围。 |
| 触发条件 | 动态条件；静态条件；条件组；能力类型、信号、字段、运算符、值 | 动态条件表达变化事件，静态条件判断当前状态。例如档位“变更为P”用于启动检查，“当前为P”用于后续判断。运算符、可选值与单位随能力变化，组合规则见3.3。 |
| 执行动作 | 动作类型；动作参数；下游输入；多个动作及执行关系 | 选择主动推荐时填写“建议信息→下游输入”，提供推荐原因和建议内容。其他动作展示各自参数；动作顺序、等待确认及结果分支按3.3配置。 |
| 执行策略 | 执行总次数；上电周期次数；每日次数；执行最小间隔 | 次数项未填写时表示不限制；最小间隔按分钟、秒填写。次数与间隔分别控制重复触发，保存时展示策略摘要。计数口径与拒绝后的降频策略由场景规则确定。 |

### 3.3 任务编排与交互配置

配置流程：关联任务与适用范围→选择触发事件→配置判断条件→选择处理方式→配置交互与后续动作→设置执行策略→校验并发布。平台根据处理方式展示关联配置项，发布前校验必填内容、能力支持范围和执行分支。

| 配置项 | 配置内容 | 处理规则 |
| --- | --- | --- |
| 任务关联与运行位置 | 关联任务；任务有效状态来源；端侧或云端 | 按渠道、车型、版本及运行位置筛选可用能力。任务关闭后停止新触发，并撤销未执行的询问；运行位置不随网络状态自动切换。 |
| 事件与条件组合 | 触发事件；当前状态；比较方式与值；全部满足或任一满足 | 支持表达“（下雨或湿滑）且车速>30且模式不是湿滑”。根据能力限定运算符、值域和单位，并展示完整规则摘要。 |
| 稳定判断与退出 | 持续时间或连续次数；计算时间窗；退出条件；退出动作 | 稳定判断与执行间隔分别配置。退出动作支持结束本次、再次询问或执行已批准的恢复动作；恢复动作不得默认生成。 |
| 命中后的处理 | 直接执行／仅告知／先询问／发起主动推荐；目标动作及参数 | 直接执行须有任务静默执行策略。主动推荐须配置建议信息及后续承接业务。选择先询问时，必须补充卡片、确认动作和取消处理。 |
| 即时交互卡 | 模板；标题与正文；按钮文案及业务含义；有效时长 | 选择已接入模板，按钮分别绑定确认或取消处理。卡片反馈实际展示、展示失败、关闭及过期状态。未展示或已失效的卡片不接收执行授权。 |
| TTS（语音播报） | 播报开关；固定文案或下游生成；播报内容；播报时机 | 开启播报时，必须填写固定文案或选择内容生成方。询问卡片实际展示后再播报；语音禁用时保留卡片和点击操作，不播TTS。 |
| 二次确认 | 是否需要确认；点击与语音承接方式；等待时长；各类答复后的动作 | 选择需要确认时，必须配置确认动作、取消处理和等待时长。本地语音匹配当前按钮，云端回答交由对应业务处理；仅有效确认进入执行，拒绝、关闭或超时均结束本次。 |
| 动作顺序与结果分支 | 执行顺序；等待结果；成功、失败及未知分支；目标状态 | 支持“出卡→等待确认→复核→执行”和“调用识别→有设备才继续”。需确认的车辆动作不得与询问并行执行。执行后读取目标状态，再更新结果。 |
| 重复处理与频控 | 总次数、上电周期次数、日次数、最小间隔；去重与再次提醒策略 | 同一事件或确认只处理一次，失效询问不得再次执行。次数与间隔按场景统一配置；计数口径及拒绝后降频策略作为待确认项管理。 |

### 3.4 原子能力范围与接入要求

平台统一管理可复用的输入、动作和反馈能力。输入提供车辆状态、感知结果与任务状态；动作提供交互及车辆操作；反馈用于决定后续处理。每项能力标明可用于触发事件、当前条件或执行动作，供不同场景组合复用。

接入要求：能力提供方维护名称、用途、字段、值域、单位、适用车型、端云支持范围及异常结果。平台按场景发布范围筛选能力；未接入、不适配或已停用的能力禁止用于发布，并提示缺失项。

输入能力：同一信号作为“发生变化的事件”和“当前状态条件”分别配置。读取失败、数据过期或识别未知时，不判定为条件满足。

| 输入能力 | 配置方式 | 适用任务与业务规则 |
| --- | --- | --- |
| 任务有效状态；AI主动服务总开关 | 配置开启状态条件；订阅关闭事件 | 任务有效状态用于全部任务，AI总开关按任务策略启用。关闭后停止新触发，未执行的询问失效。 |
| 档位 | 配置变为P/D的事件；配置当前为P/非P的条件 | 用于充电、儿童锁与后视镜加热。变化事件与当前档位判断分开配置；具体目标档位由场景选择。 |
| 车速 | 配置比较符与阈值；单位km/h；配置阈值变化事件 | 天气与加热共用。支持按场景设置不同阈值，例如天气>30、加热<70；触发事件与后续当前值判断保持一致。 |
| 天气识别；路面识别；雨量状态 | 配置目标枚举及变化事件；指定视觉或传感器来源 | 用于天气与加热。天气、路面和雨量分别接入；雨量等级仅开放来源支持的枚举，未知结果不满足触发条件。 |
| 驾驶模式；后雾灯状态 | 配置当前状态条件；选择执行后的回读目标 | 天气保护按雨、雪、雾子场景判断对应模式或雾灯状态；目标状态已达到时，不重复推荐同一动作。 |
| 儿童识别；猫/狗识别；儿童锁状态 | 配置目标成员、座位及对应侧锁状态 | 用于儿童锁。成员类型与普通占座状态区分；识别到目标成员且对应锁未开启时，进入场景规定的处理分支。 |
| 电量；充电口盖状态；充电设备识别结果 | 电量单位%；口盖状态条件；识别结果分支 | 用于充电口盖。电量和口盖用于前置判断；有设备、无设备、无法判断、失败分别处理。识别结果关联本次停车，过期结果不执行。 |
| 传送带洗车退出；环境湿度；温度/温差；后视镜加热状态 | 洗车退出事件；湿度阈值；温差计算窗口；加热状态 | 用于后视镜加热。温差条件必须包含时间窗及数据来源；加热状态用于避免重复执行与确认执行结果。 |

动作与反馈能力：平台根据所选动作展示对应参数，接收交互、识别和执行结果，并按已配置分支继续或结束本次处理。

| 动作与反馈能力 | 配置参数 | 处理规则 |
| --- | --- | --- |
| 主动推荐 | 建议信息、场景内容、后续承接业务 | 沿主动推荐及DT链路完成业务判断；返回结果须关联本次场景处理，明确、有效的结果才可进入后续分支。 |
| 即时交互卡 | 卡片模板、文案、按钮、有效时长、更新与关闭方式 | 业务发起展示请求，VUI反馈实际展示或失败结果。卡片过期、撤销后不再接收确认；业务负责按用户选择继续处理。 |
| TTS（语音播报） | 播报开关、文案或内容来源、播报时机、停止条件 | 随当前交互按配置播报。卡片取消或结束时停止本次播报，不改变系统语音总开关。语音禁用时保留卡片和点击操作。 |
| 用户选择反馈 | 所属询问、确认、拒绝、关闭、超时及对应分支 | 本地语音匹配当前按钮，云端回答由对应业务处理。反馈须关联当前有效询问，仅确认结果进入执行分支。 |
| 驾驶模式切换；后雾灯开关 | 目标模式或灯光状态；适用条件；执行后目标状态 | 雨、雪、雾子场景分别绑定对应动作。执行前复核任务及车况，执行后回读目标状态；不得默认同时执行所有动作。 |
| 儿童锁；后视镜加热；充电口盖 | 目标部位与状态；允许执行条件；结果判定 | 按车型及任务策略开放对应动作。自动执行、询问后执行和恢复动作分别定义，不因能力支持就默认开放全部操作。 |
| 识别与执行结果 | 明确结果、失败或未知原因、车辆实际状态、后续分支 | 识别无结果或过期时不继续执行。调用成功不等于车辆已完成动作，实际状态达到目标后才判定成功。 |

发布校验：所选能力必须支持目标渠道、车型、版本和运行位置；必要参数、结果分支及执行结果判定缺失时禁止发布。新增能力接入后，同类任务可直接引用，无需新增场景专用处理链路。

### 3.5 配置示例：雨天切换湿滑模式

场景目标：天气路况保护启用后，系统在雨天或湿滑路面、车速达标且未处于湿滑模式时询问用户；用户确认并通过执行前检查后，切换湿滑模式。

1. 任务与范围：关联天气路况保护，运行在端侧；选择适用车型及软件版本。任务关闭时，不产生本次建议。

2. 事件与条件：配置天气变为下雨、路面变为湿滑作为检查事件；判断“任务有效且（下雨或路面湿滑）且车速>30km/h且当前不是湿滑模式”。平台展示完整规则摘要。车速后来达标、任务重新开启时是否重新检查，列入场景规则待确认项。

3. 命中后：选择“先询问”，引用即时交互卡模板。正文与TTS为“检测到路面湿滑，要切换到湿滑模式吗？”，按钮为“确认”“取消”。

4. 确认后：绑定“重新检查任务及当前车况→切换湿滑模式”。本地语音命中确认按钮时，与手动点击进入同一处理。仅当前有效询问的确认结果可执行；任务关闭、条件失效或本次已处理时终止执行。

5. 取消、关闭或超时：结束本次卡片与交互，不切换模式。询问排队期间已过时、任务被关闭，也不继续执行。

6. 执行后：读取驾驶模式。确为湿滑才反馈成功；失败或暂无法确认时如实反馈，再按约定结束本次并进入频控。

7. 用例复用：创建浓雾保护场景时，将识别条件改为浓雾，将车辆条件改为后雾灯未开启，目标动作改为开启后雾灯，并修改卡片与TTS文案；复用同一套“出卡→等待确认→复核→执行→结果反馈”配置能力。

场景待确认项：儿童锁采用静默执行还是逐次询问；后视镜加热的档位条件、雨量范围、温差窗口与结束策略；充电任务的确认时机。由触发器产品与赛力斯需求方确认场景规则，相关场景在规则及能力接入完成后发布。

### 3.6 验收标准

1. 配置校验：必填内容缺失、条件表达不完整、参数越界或能力不支持目标发布范围时，禁止发布并定位具体配置项。选择“先询问”但未配置确认动作、取消处理或等待时长时，校验不通过。

2. 规则与分支：按配置组合判断全部或任一条件；不满足时不触发，满足时进入对应处理分支。仅告知不执行车辆动作，需确认的动作必须等待有效确认；拒绝、关闭、超时均结束本次。

3. 交互与执行：卡片未实际展示时不接受授权，语音禁用时不播TTS但保留点击操作。用户确认后再次检查任务与车况；条件失效时不执行。调用返回成功但车辆未达到目标状态时，不展示执行成功。

复用验收：在所需能力已接入、组合方式已支持的前提下，雨天湿滑模式与浓雾后雾灯场景通过修改条件、文案和目标动作完成配置，复用相同的询问、确认、执行及结果处理链路。

异常验收：输入缺失或过期、识别未知或失败、卡片展示失败、用户答复过期时，不继续执行车辆动作，并记录结束原因。同一事件或确认重复到达时只处理一次；任务关闭后，未执行的询问与动作失效。

### 3.7 端侧与云端配置承接边界

云端复用现有场景配置与状态上行链路，扩展交互及结果分支。端侧现阶段按任务需求开发；端云统一配置与下发作为后续建设项，实施前确认能力清单、版本适配和状态同步方案。
