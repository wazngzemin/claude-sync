# 背景
- **模块目标**
    - 定义唤醒、识别、聆听等基础对话状态及流转规则
    - 围绕query和主动服务的生命周期，定义交互结果加载、展示、退出的时机及详细内容
    - 多载体梳理用户交互从头到尾听到、看到、感受到什么
- **赛力斯差异**
    - AI always on：支持全时免唤醒，状态机和上层展示需要重新定义
    - 交互载体差异：
        - 中控屏：临时交互卡展示所有query和主动服务结果，AIbar作信息流转
        - 硬件：存在豆包交互屏、PHUD屏、交互灯等显示，要处理好信息分级和协同关系
    - 新增本地模型对话链路，需要处理端云状态流转

【基础对话状态】
1. 全时免唤醒开关关（同上汽）：
    - 对话策略同上汽，需要明确唤醒或“豆包\+”激活对话，延时聆听中默认计时60s退出对话，恢复静默态
2. 全时免唤醒开关开：
    - 新增“全时态”：四音区持续收音，等待有效指令或唤醒词激活语音
    - 保持“延时聆听态”：TTS播报完后正常进延时聆听，保证研发策略一致性和用户感知连续性，遵循延时聆听的ASR流式上屏和其他HMI策略，计时完毕恢复全时态
3. 端云对话：以实际采纳的端云仲裁结果展示对话状态
    - 本地对话输出reject或functioncall，则驱动状态机流转
        - （0930更新）当前赛力斯定义本地llm输出的拒识和语义结果都不被采纳，需等云，则状态机驱动以云端为准
    - 本地对话输出unsupport，则持续处于思考态，等待云端结果，不视作最终结果

## ASR输入
1. 用户未唤醒，ASR不流式上屏，需判断为有效指令后上屏完整query
    1. 单独喊豆包不上屏
        - \&\#34;豆包\.\.\.“不上屏，“豆包打开车窗”判断非拒识，唤醒对话，上屏完整query
    2. 全时态不流式上屏（全时免唤醒开关开，且对话未激活），最终唤醒后上屏整句有效query
        - \&\#34;打开\.\.\.\&\#34;不上屏，\&\#34;打开车窗”判断非拒识，唤醒对话，上屏完整query
2. 从唤醒到延时聆听状态期间，ASR内容流式上屏，并等待“拒识”模块的结果
    1. 若query为有效，则ASR颜色高亮，保持上屏，对话进入思考态
    2. 若query为拒识，则ASR快速清屏
    > 特殊地，赛力斯端云都有拒识能力，需采纳最终拒识结果用于ASR上屏
    > 
    > - 云端拒识判断有效才刷新asr
    > 
    >

## 思考和播报
1. 思考和执行过程中，为了降低用户等待的焦灼，在ASR区域展示工具调用的过程
    1. 时机：Director输出工具名，直到工具返回结果后清除，恢复显示ASR文本
    2. 基本格式：icon\+工具调用名称，如“联网搜索中”
    3. 展示逻辑：单个工具直接展示，停留x秒，调用多个工具则排序延迟展示，每个工具展示x秒
2. 播报过程中，持续保持收音，允许全车多音区输入
- 播报内容：TTS播报内容和上屏文本可以不一致
- 表现反馈：豆包交互屏和交互灯展示播报动效
- 允许打断：
    - 用户重新唤醒：用户通过唤醒词、硬按键等方式打断播报
    - 用户继续输入query，流式拒识模块输出要打断（满足ASR连续字数或流式模型判断有效），则打断播报，在ASR区域、豆包交互屏、光灯作出打断动效
    - 新的NLG下发：允许语音、导航、系统等多通道的播报下发作TTS打断
3. 无论免唤醒开关，TTS播报完毕，进入延时聆听态
## 即时交互卡
### 是否出卡
对话交互存在3种结果呈现类型
1. 仅播报：简单控制类
2. 即时交互卡：
    - 用于VUI产生的结果临时展示、主动服务的结果承载
    - AIVA分大中小三种卡片形态
3. 跳转应用/界面：直接跳转到app进行展示
详细工具范围见附录更新[【AIVA】主交互\&即时交互卡需求汇总](https://bytedance.larkoffice.com/wiki/CNCBwbMcmiPOq7kNYRAcHRz8nCf?from=from_parent_docx)
### **生成**
1. 卡片出现时机：工具返回feedback，且定义需要展示卡片
2. 自然过渡：ASR文字保持上屏，ASR胶囊自然过渡变宽，向下加载出结果卡
3. 最大高度及滚动：
    1. 内容滚动：超过卡片不再增长，内容区域匀速自然往下滚动，直到流式输出停止
    2. 此时内容区域可通过VUI指令和手势上下滑动，右侧并带有对应的滚动条
### **内容元素**（详细见UE）
1. 下线总结文字：对query和advisor的精要总结
2. 当前交互定义了大中小三种卡片样式，展示不同信息
    1. 小卡：固定单组件场景
    2. 中卡：多组件或多工具场景
    3. 大卡：存在任一【生图、导航、游戏】等大容量信息
3. 内容要素区：
    1. 原子形态：覆盖纯文本、文本\+图片、多图片、widget展示（车控、POI、媒体组件）等基本范式
    2. 可组合：多业务功能可根据原子形态自由组合

    4. 可放大：图片和视频等特殊内容，可点击放大展示

### 消失
以下条件任一满足，则卡片经过收起状态（ASR条），卡片消失
1. 无交互倒计时退出：在TTS播报完毕，卡片默认延迟10s后退出，
    - 有以下交互暂停计时，交互完成后10s重新计时
        - TTS正在播报
        - 卡片中存在视频正在播放
        - 卡片中图片正在加载
        - 手动点击或滑动卡片
2. 触发新页面跳转：
    - 用户VUI触发新页面或应用拉起（任务打断）
    - 点击卡片内的按钮发生页面跳转
3. 语音对话退出
4. 语音通道挤占
5. 用户手动关闭：上滑ASR胶囊
用户上滑ASR胶囊，卡片关闭消失（上滑时胶囊跟随手指移动，达到触发距离后松手执行，未达距离松手回弹原位）
## 聆听及对话退出
1. 对话进入延时聆听的时机
    1. TTS播报完毕（query或主动服务）
    2. 点击卡片内按钮，页面跳转打断TTS
2. 延时聆听默认计时30秒，不允许用户自定义时长
    1. 延时聆听的计时重新刷新条件
        - 触发唤醒
        - 任一音区触发有效指令
        - 触发advisor主动服务
    2. 在特殊场景下，延时聆听计时暂停
    - 拒识/本地LLM/云端Director结果未返回
    - TTS播报中
    - 末尾说话：计时将结束时，用户正在输入但vad并未结束，此时延长收音直到用户说完
        - 如果是有效语义，则刷新计时
        - 如果被拒识，则直接退出延时聆听
3. 全时免唤醒开启，也在TTS结束后进入延时聆听态。此时用户有较强的交互倾向，HMI及链路遵循激活态定义，开启30秒计时，影响范围包括：
    - ASR流式上屏
    - 豆包表情及其他HMI动效
    - 端云链路遵循激活态双跑
    - 拒识逻辑更宽松
4. 满足以下条件后，语音对话退出，助手恢复静默态/全时态
    1. 倒计时结束
    2. “退出”类VUI指令
    3. 方控键退出
    4. 满足语音禁用条件
# 特殊交互策略
## 卡片链路（0818）
- **① Planner 链路推出的卡片**：Query → Planner 推理并调用工具（字节自闭环工具 / 三方工具如预约充电）→ 结果经 Planner 汇总下发拉起卡片。语音可由 Planner 自闭环；手动点击直接执行，执行结果作为特殊事件日志上报云端。此场景不注册卡片\&\#34;可见即可说\&\#34;词条。
- **② 豆包主动服务（静态 Advisor）**：Advisor 输出建议 → Planner 接收并继续下发拉起卡片。语音由 Planner 闭环，输出执行工具并展现结果；手动点击因无直接执行接口，需模拟一个 Query 走到云端，完成\&\#34;Advisor 建议 → 工具\&\#34;的推理转换。
- **③ 系统通知拉起的卡片**：三方直接触达端侧，端侧出即时交互卡片（文本 \+ 动态按钮）。语音为\&\#34;可见即可说\&\#34;增强版——Planner 动态插入选择工具（生命周期与卡片绑定），用户说\&\#34;确认/取消\&\#34;后透传匹配并下发端侧执行指令、更新卡片状态；手动点击有执行接口可直接完成操作，同时通过事件日志上报云端完成 API 与 UI 同步。
- **④ 端侧自闭环的服务通知**：不经过 Planner，端侧直接出卡（文本 \+ 动态按钮，离线直接执行）。语音靠\&\#34;可见即可说\&\#34;实现；手动点击后续进入上下文即可。

        - 规则配置：触发器判断条件满足后，直接拉起卡片，不经过director，通过可见即可说闭环
    - 优先级：
        - 所有advice优先级一致，整体低于用户Query，采用排队无丢弃策略【from任务管理需求定义】

            - 单个advice被处理
            - 多个advice同时处理
            - advice和用户Query合并处理

        - 当前语音处于未激活状态，先激活语音，再下发Director结果

            - Director正在处理任务，但未输出首Token，取消本次任务，和advice合并，重新给到Director处理

## 卡片三方调用（0818）
1. 定义：即时交互卡提供被外部调用的通用能力，外部业务直接触达端侧拉起的交互卡，且提供二次交互能力
2. 范围：
    1. 赛力斯的卡片调用都通过消息盒子拉起[中控屏消息盒子（系统消息）需求汇总](https://sai-seres.feishu.cn/sheets/RYvYsWF5HhbekCtb8jmc77UOnde?sheet=zUJ6FR)
    2. 字节也存在不经planner直接调用端侧卡片的业务，例如规则配置的主动服务
3. 响应预期
    1. 排队进行TTS播报，并展示即时交互卡片
    2. 拉起所有音区收音，进入播报态，播报完毕后进入强聆听态
4. 二次交互
    1. 对速度、本地有强要求的业务，不经过planner，走可见即可说，直接进行按钮模拟点击命中
        - 例如：天气保护路况
    2. **对泛化有诉求的业务，planner新增动态选择工具，实现增强版可见即可说**
        - 触达端侧展示交互卡后，将卡片信息及按钮上报到云端，注册一个新的选择工具
        - Director选中工具后将用户泛化的query与按钮文案进行匹配，下发执行项
        - 生命周期和卡片的存活绑定，卡片消失则动态工具删除
    3. VGUI交互同步：用户手动点击的卡片行为，需要同步至planner上下文

## 多屏交互（0915）
1. 吸顶屏介绍
    1. 可以在全车多位置移动，可能位于前排
    2. 打开观影模式会自动打开吸顶屏，且此时中控屏会休眠
**界面适配规则****：高度复用、宽度重配**。卡片高度、字体规格、间距体系可以共用一套设计 token，但宽度布局、列数、边距需要分别出两套规范。建议设计侧先定义一套基础组件（高度固定），再分别做 16:10 和 16:9 的布局适配。（**差距不大简单适配，可考虑同一套尺寸，可和设计中心沟通后确认）**
2. 判断吸顶屏状态，决定进入交互模式
    1. 吸顶屏关闭，全车交互呈现在中控屏
    2. 吸顶屏打开且特殊处于观影模式，全车交互呈现在吸顶屏
    3. 吸顶屏打开处于前排，未处于观影模式，全车交互呈现在中控屏
    4. 吸顶屏打开处于后排位置，采用后排交互模式
3. 后排交互模式下，
    1. ASR音区分前后排展示
        - 前排ASR输入展示在中控屏，后排ASR输入展示在吸顶屏
        - 各屏幕遵循各自的asr流式上屏、跨音区有效上屏、工具展示、打断和保持策略，不发生跨屏幕关联
    2. 前后排光效独立展示
        1. 单人说话：从唤醒到TTS播报结束，光效都在唤醒音区位置，进入延时聆听后光效回到中间
        2. 多人场景：
        - 和asr上屏逻辑一致，流式上屏和有效指令都需要在对应音区展示光效
        - 如果存在合并场景两个asr共存，光效回到中间

# HAI联动
HAI联动用于将豆包的对话状态、感知结果及车辆场景，通过豆包交互屏、AI交互灯和PHUD协同呈现，让用户直观感知豆包当前“在听、在想、在说、看到了什么”，以及车辆正在执行或提醒什么。
系统统一接收语音对话、Planner及端侧状态，并按照安全优先、状态连续的原则，决定各载体的呈现内容及切换方式。
1. **载体分工**
- 豆包交互屏：呈现豆包形象、表情及场景状态。
- AI交互灯：提供空间指引、氛围表达和功能反馈。
- PHUD：呈现豆包感知到的舱内外人或物。
2. **范围及优先级**
    - 包含安全警示、对话状态、功能反馈及情绪范围等场景
    - 安全警示优先级最高，不允许被其他场景打断。
    - 同类优先级默认后打断前
    - 特殊地，AI交互灯存在多个灯位，对话状态与场景氛围可同时呈现。

# 需求优化
## 多工具展示
1. 问题现状：一句话触发多个工具时，展示效果无分割，且和query关联关系关系弱
    - 一句话多意图：打开座椅按摩导航去南京南站
    - 推理出多工具：我好冷啊
2. 期望优化：工具结果分区
    1. 采用 DT 拆分的单工具改写 query 作为每个结果区块的标题
    2. 同一工具拆分后如存在多指令，则将多query合并展示
        - 现状：工具feedback返回后流式展示卡片组件，哪个快展示哪个
        - 可能导致以下问题，体验可接受
            - 同工具拆分的query顺序和组件顺序不一致
            - 在车控内，实际展示结果组件比query标题数量少
    3. UI增加工具间空行或分割符
