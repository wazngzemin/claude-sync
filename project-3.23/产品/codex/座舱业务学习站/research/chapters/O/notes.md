3. 打断：2 月以前简单车控“叮”一声不打断、非简单车控等新回复才打断 → 二月底实验版本：几个字就停、拒识从前一标点续播 → 现行：流式拒识判召回就停，拒识走 event、召回走 last_talk_content，由 DT 决定补不补 → 新输入管理：暂停与永久停止分开、四种播放事件（开发中）。
4. 播放完成：临时事件键 + 进度数据库两条线 → 结构化播放事件（开发中）。
5. 卡片：上汽 AI 画布（多轮相关模型决定保持/收起）→ 赛力斯即时交互卡（工具返回后出卡、10 秒退出）→ 赛力斯内容完成后才倒计时（10/23 技术评审）。

取舍
- 播报统一由 DT 出：换来人设统一、上下文完整；代价是慢（智驾“过 planner 晚 3 秒”）和幻觉（没变道说变道）。8/20 未定。
- 首轮话术：有它，等待不空白；但说多了易过度承诺、易与次轮重复，所以 PRD 要求“首轮不说清楚全部、不预设结果”。
- 通话链路：首帧快 200–300ms；代价没有打轴，打断恢复只能按“1s 5 字”估已播到哪，还可能卡顿，所以先在赛力斯测试环境试。
- 音频焦点（上汽）：申请主驾焦点 → 头枕模式下媒体不降音；改整车焦点、整车发声，放弃“哪个音区说就哪个音区喇叭”。
- 卡片在工具返回后才出：慢一点，但避免车控失败时卡片上出现一个“已开”的开关。
- TTS 播报内容与上屏文字允许不一致：屏幕可展示结构化结果，声音讲重点；代价是 10/27 赛力斯导航“播报与列表不一致”成头部问题。

## 四、与旧版内容的冲突/修正
1. 旧版写“tts_audio_id 让客户端找回这次应播的声音，request_id 让端云双方认出这是哪一次请求”——方向对；但旧版说 O13/O14 等节点编号、“离线白名单与云端仲裁是两套条件：无网时……由端侧白名单直接执行和应答”属于 R 章内容，且上汽/赛力斯规则不同，本章不再讲。
2. 旧版把 STARTED/FINISHED/ABORTED 四态写在“实际起播、播完和中止由播放器确认”里，像现状；核对后是 10/23 输入管理技术方案的开发中设计，现状是临时事件键 + 进度数据库。
3. 旧版“选路口径是文本链路指定情绪时统一走 Sami，未指定情绪时由文本 S2S 自己合成”——原文是“文本链路+未指定情绪：文本S2S链路使用文本S2S自己合成的音频；其他链路统一使用Sami”，旧版漏了“其他链路”。现行 OnePager 写的是无标签时用用户 query 作情绪信息、走 Sami。
4. 旧版“弱网或断连导致播报终态没回传时……新技术方案允许先标完成未确认，再按动态截止和受控超时推进”——原文是“不按文本长度猜测完成……仍无法恢复时触发告警，由受控的‘确认输出已结束’运维操作推进”，没有“动态截止”的说法，按原文改写。
5. 旧版“表情：Lotus 2025 历史方案……按 token 阈值请求提取”——属于 2025 历史方案，现行是 DT 直接输出 emoji_id；本章只一句带过“历史方案”。
6. 旧版“声音合成日志给过约五百五十二毫秒”——日志排查文档原文手算是“约 600ms”（20:54:07.983 → 08.535，差 552ms，文档写约 600ms）。正文用“约 0.55 秒（文档记为约 600 毫秒）”避免误差，或直接用 H2 的 P50 465ms。正文采用后者。
7. 旧版 P0–P5、预置 500/动态 1500、方言强制在线等与 PRD 一致，保留并标“需求，上线待确认”。
