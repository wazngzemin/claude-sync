03先完整跟纯银走：他为什么断言产品经理的老路正在变窄

这一篇不能只记“PM 要贬值”。作者先选了一把估值尺子，再用这把尺子量需求、AI 和职业。你要先看尺子，再看结论。

3.1 第一块地基：PM 的价值等于他能满足多少人的共同需求

原文锚点：“最大公约数需求覆盖的用户规模越大，创造的价值与收益也就越多。”

原文意思古典互联网里，一个产品功能能覆盖一亿人，通常比覆盖一万人创造更多收入。能找到大规模共同需求的 PM，也就拥有更高的组织地位。

大白话以前的产品经理像找矿的人。找到一座大矿，所有人的工资都跟着涨；只找到一小块矿，哪怕挖得很专业，老板也不会按大矿定价。

这段在论证里干什么：它规定了后面所有判断的计分板。只要接受“用户人数决定 PM 价值”，后面的悲观结论就很顺。
作者没说出的前提：用户规模和商业价值大体同向；单个用户的价值差异不大；安全、交付风险、企业采购和平台复用都可以忽略。

我怎么看这把尺子量 C 端增长很有用，量 B 端和物理 Agent 会失真。一个场景只影响一款车型，也可能决定一笔车企合同能不能验收；一个低频安全场景的价值，也不能按点击人数算。

跟你啥关系你不能用“这个场景有多少车主天天点”给自己的工作定价。你要补三项：客户合同影响、错误代价、能否变成其他车型复用的底座能力。

3.2 第二步：大需求被摘完，能力更强的 PM 也可能没仗打

原文锚点：“严格来说需求不是枯竭，枯竭的是高增长高价值的需求。”

原文意思打车、外卖、短视频这类亿级需求已经有人占住。剩下的新需求越来越小，做产品和获客的成本却没有同比下降。

大白话以前地上有西瓜，现在只剩芝麻。你捡芝麻的手法比过去熟练很多，收成仍然更少。

论证推进：作者把“个人能力”与“时代给出的题目”分开。一个人越来越强，不保证市场还能给他同样大的题目。
边界：这个判断适合存量互联网产品。如果技术创造了新的交互形态、新的生产资料或新的交易方式，需求池会重新变大。AI 是否正在创造这种新池子，正是他与 Jeff Dean 分歧的起点。

跟你啥关系你在大公司里争资源时感到“项目明明复杂，却很难得到增长业务同等重视”，这不一定说明项目没价值。它可能只是不符合流量增长的旧计分板。你需要换成客户交付和系统能力的计分板。

3.3 第三步：AI 把需求撕成两个极端，头部进不去，尾部养不活人

原文意思一端是服务十几亿人的基座和少数头部应用，岗位极少；另一端是为几个人即时生成的小工具，单个软件的商业价值很低。

大白话他说未来只剩五星酒店和家庭厨房。五星酒店岗位太少，家庭厨房又不卖票，普通 PM 被夹在中间。

全篇最大的漏项：企业软件、行业系统和物理世界没有进入这张两极图。这里的客户数量可能少，单客价值、流程深度和错误代价却很高。FDE 五篇全部发生在这个中间地带。

别误读看到漏项，不代表“做 B 端一定高价值”。客户愿不愿付钱、方案能否复用、交付成本会不会吞掉利润，仍要逐项验证。

跟你啥关系豆包上车不靠一个车主为一次对话付费。它服务车企的车型竞争、交付和持续软件能力。你的位置恰好在纯银两极图漏掉的那一层，但要靠复用证明价值，不能只靠“B 端”这个标签。

3.4 第四步：“效率不等于胜率”到底是什么意思

原文锚点：“少数个体和个别任务的大幅度提效，对于整体效率并没有多少改变。”

大白话你把写 PRD 从两天缩到两小时，只说明你写得快。系统能不能更准、项目能不能更早验收、客户会不会多买一款车，这些才影响输赢。

为什么行业一起坐电梯大家都能用同一批模型生成文案、代码和图片。这类能力会迅速变成平均线。只有私有 Context、独有流程和长期反馈形成的质量差，才可能留下。

放进你的工作：SP 从 32,806 tokens 降到更短、首包 P50 从 2309ms 降到 998ms，属于效率和体验；同一批场景知识从 88.3% 做到 95% 以上、已删除场景不再误召回，才开始接近胜率。两类指标都重要，含义不同。

边界在高频、规模大的链路里，效率本身也可能变成胜率。延迟降低会改变用户是否愿意使用；成本降低会决定功能能否量产。纯银把效率与胜率切得稍微过开了。

3.5 第五步：AI 新事物可能很粗糙，照样有价值

原文意思AI 视频、旅行攻略、个人纪念页面等产物未必达到传统专业标准，却能快速接住热点或满足一个人的特殊需要。

大白话以前做一件产品，要先赢过市场上其他产品；现在 AI 可以临时给一个人做一件“只属于他”的东西，它不用参加大众比赛。

这段很关键：作者自己已经看见新需求的萌芽。后面他仍然悲观，原因在于这些新事物当前占注意力和交易的比例很低。

跟你啥关系车里“根据这次行程临时生成一段沿途讲解”“记住这家人对温度和音乐的偏好”“在孩子哭时按当下状态处理”，都属于按现场生成。它们的评价标准不能只照搬传统固定功能。

3.6 第六步：为什么他判断商业大潮还要五到十年

原文意思AI 用户很多，但大量活动仍是用新工具重做旧任务。当前真正由 AI 创造的新事物，在人的注意力和交易中占比仍低。

大白话会用聊天框不等于新产业已经成熟。要等人的时间和钱大量花在以前根本不存在的产品上，商业机会才算全面展开。

这个时间判断靠什么：作者用的是注意力占比，不是模型基准分数。黄钊保留意见，理由是模型进步曲线和全社会投入可能加速。两边都没有足够证据给出精确年份，所以“五到十年”应当看作情景判断。

对你的操作含义行业成熟慢，不等于个人应该等待。越早进入真实现场，越有机会在标准固化前积累失败样本、接口经验和评测方法。等待行业宣布成熟，通常只剩成熟岗位的竞争。

3.7 最后一段是作者的位置声明，别把情绪当事实

原文意思纯银已经接受退休，他承认自己可以悲观，仍在职的人承担不起完全放弃行动的代价。

大白话他在岸上描述海况，海况可能说得准；他不再需要亲自游到对岸，所以文章不会给出细致游法。

你该拿走什么拿走三条事实判断：大众需求缩小、局部提效难变整体胜率、新产业全面成熟需要时间。把“拔剑四顾心茫然”留给作者，不要当成你的职业结论。

04Jeff Dean 逐段接住：旧路变窄以后，1% 问题为什么可能是新路

Jeff Dean 给出的重点不止“做难题”。他讲了一套完整链路：怎样选题、怎样给 Agent 材料、为什么长任务会脱轨、怎样用评估器纠错、最后人还剩下什么能力。

4.1 1% 法则：模型已经会 20%，为什么反倒危险

原文锚点：“去找模型成功率 0% 或 1% 的问题，不要找 20%。”

原文意思如果通用模型已经偶尔能做对，说明相关能力已经存在。未来模型升级后，你今天包在外面的功能可能直接消失。

大白话模型今天像一个会做两道题的学生。你创业去教它剩下八道，它明年可能自己学会。模型连题目在问什么都不知道，通常意味着缺了专有数据、工具或新的系统，这才给外部产品留下空间。

1% 不等于好机会：有些问题成功率 0%，原因是没人需要、没有可获得数据、结果无法判断、成本高过收益。机会必须同时满足四项：客户真痛、模型单独做不了、你能拿到关键材料、结果能被评估。

跟你啥关系“写一份普通 PRD”已经远高于 20%，会越来越便宜；“在实时车况、乘员、VLM、记忆和任务约束下做可靠决策”，模型离开私有 Context 后接近 0%。你的职业要逐步从前者移到后者。

4.2 两条具体路径：私有数据与专用系统

路径一通用模型接触不到的数据，例如公司内部规则、实时设备状态和个人历史。你把这些材料以可靠方式提供给模型，系统能力会立刻不同。

路径二围绕一个窄问题做专用模型或专用求解系统。AlphaFold 的启发不在“所有人都去训练模型”，在于极难窄题可以有完全不同的系统设计。

你的对应关系：实时车况、FaceID、用户记忆、路线和 Task 进度属于路径一；场景知识、Trigger 条件、动态示例、车载能力边界和专门 Eval 属于路径二。你当前工作已经同时踩中两条。

范围提醒你参与这些链路，不等于你独自拥有记忆、VLM 或 Task 服务。职业叙事应该写“我把它们组织进可验证闭环”，不要写“我负责整个系统”。

4.3 Agent 可以跑几天几周，为什么这不等于可以完全放手

原文意思强模型配合合适环境，可以连续做大型软件重写等长任务。很多人仍用“一两个小时”的旧印象理解 Agent。

大白话Agent 的耐力变长了。耐力长不代表方向永远正确。一个人可以连续开十小时车，也可能第二个路口就走错。

真正变化：当任务能连续运行很久，人类工作从“亲手完成每一步”转成“定义目标、分阶段验收、设置失败恢复”。Task、checkpoint 和 Eval 会比单轮 Prompt 更重要。

放到车里“沿途有风景就介绍”“宝宝哭了告诉我”“到家前提醒别落东西”都跨时间。它们必须定义开始、等待、触发、成功、无法判断、取消、下电和超时。只有一句目标，没有生命周期，Agent 跑得越久，错误积累越大。

4.4 搬数据比算数据贵很多，跟产品经理有什么关系

原文意思一次简单计算耗能很低，把数据从高带宽内存搬到处理器可能贵三个数量级。很多系统瓶颈发生在数据移动和 IO，不只发生在模型算法。

大白话厨师切一刀很便宜，食材每切一刀都要从十公里外运来，运输才是大头。批处理的作用，就是一次多运一些，把运费摊薄。

跟你啥关系你每轮给 Planner 塞进大量无关示例、历史和状态，问题可能不在模型“不会想”，在材料搬得太多、太乱。SP 示例动态加载、远区对话精简、公共 Context 前置筛选，本质上都在减少无效搬运。

边界：少给 Context 也会伤质量。正确目标不是 token 越少越好，是每个 token 对当前决策有用。删减以后必须用同一批 Eval 验证。

4.5 上下文工程：普通团队怎样和大厂坐到同一张桌上

原文锚点：“把你作为人类会用的方法，写成模型能用的形式。”

原文意思训练基础模型需要天量资源。普通团队可以通过 Context、工具和方法说明，快速改变模型在一个具体问题上的表现。

大白话你造不起一个新大脑，但可以把正确卷宗、操作手册、工具和检查表放在它桌上。

放到你的 SP：角色和输出格式决定工作身份；工具描述告诉它能找谁干活；车辆知识限制幻觉；动态示例给相似 case 的推理路径；{{memory}}、{{env_info}}、视觉和任务变量提供本轮材料。它们共同构成上下文工程，不等于“写 Prompt 文案”。

最重要的工作方式先让模型真做题，看失败发生在哪；再把人类专家当时用的判断方法写成知识、Skill、示例、工具约束或评测。你不是先凭想象写一套完美 SP。

4.6 Agent 第 30 步脱轨：为什么越走越错

原文意思长任务逐渐走出模型熟悉的训练分布。开环状态下，一次错误会改变后续输入，后面的判断在错误基础上继续叠加。

大白话第一步把浦东机场认成虹桥机场，后面查天气、规划路线、找停车场都可能做得很认真，整条链仍然错。

解法一用 Skill、提示和结构化状态，把 Agent 留在已知路径。解法二是多条路径并行尝试，再由评估器保留更好的。

你的“删除途经点”实测就是一个完整例子：唯一加油站时直接删除；两个同类站点时列名澄清；候选尚未加入路线时只取消待选；当前无导航时不能调用工具；route_planning 返回新路线后再播报。环境只变一点，正确 Harness 就要多一个分支和验收。

这也回答了 SOP 疑问可复用的是“先判断当前状态、再行动、拿反馈、继续”的骨架。每个任务仍要补自己的状态、工具和边界。Agent 时代并非完全没有 SOP，固定答案型 SOP 变少，元流程型 SOP 更重要。

4.7 自动化科学方法：最难的常常是评估器

原文意思Agent 可以自动分解问题、跑实验和搜索候选。只要目标能被度量，推理时计算就可以换来更多发现。瓶颈经常落在结果评估。

大白话一百万个 AI 同时交卷并不稀奇。难的是有一位足够快、足够准的老师批完一百万份卷子。

跟你啥关系动态示例库继续变大很容易。你真正要回答：哪条示例被命中、改完后哪类错误下降、有没有伤到主路径、什么时候应该删除旧例。没有这套评估，示例越多可能互相干扰。

评估器也会错：如果标准只看最终话术，它会把下游执行失败算到 Planner；如果缺日志，它会强行猜原因。6 月 12 日的 A 到 F 分诊说明，判卷之前先确认问题属于哪一层。

4.8 品味：代码能自动写以后，人为什么还值钱

原文意思工具和技术越来越普及，稀缺能力转向“把时间押在哪个问题”。Jeff Dean 建议写下未来十二个月重要的事，一年后逐条对账。

大白话AI 可以帮你把十个方向都做出第一版。你仍要决定哪一个值得团队花三个月做到量产。

跟你啥关系你的风险不是做不出来，是可做事项太多。不断多做一份材料能延迟押注，却不会训练品味。品味需要留下预测、选择和复盘记录，允许自己有一条明确没押的路。

与纯银拼起来：纯银说大需求稀缺，Jeff Dean 说挑题能力更稀缺。市场题目变少时，选择错误的代价会更大。

05FDE 五篇逐篇读：它为什么像你的下一站，又为什么很容易退化成外包

Jeff Dean 找到了“通用模型接近 0%，加上私有材料才可能做成”的题。FDE 五篇接着回答：谁进入企业，把这些私有材料、规则和工具接进 Agent？答案是 FDE。这里先不急着说你要不要转岗，先把五篇各自解决的问题拆开。

5.1 第一篇讲红利：企业知道 AI 很重要，却不知道第一铲挖在哪里

原文主张：AI coding 与 token 成本下降后，企业存在三层机会，重做旧软件、软件化长尾流程、创造新的收入路径。

第一层把现有软件做得更好用。例如旧配置台要研发手写脚本，新平台让产品直接配置规则。这一层主要省时间、降门槛。

第二层把以前不值得开发的碎流程做成系统。它们用户少、变化多，以前请一支研发队不划算；AI 降低实现成本后，这些小需求第一次有机会被服务。

第三层让企业长出新的收入或竞争方式。例如一辆车交付以后，Agent 还能通过持续服务提升车型差异、订阅和用户关系。这层价值最大，证明最难。

大白话前两层像修店、补货架，第三层像开出一家过去不存在的新店。文章说“低枝果实很多”，意思是大量公司连前两层都没做好，懂 AI 又懂业务的人可以先摘。

文章暗藏的门槛：果子低，不等于任何人伸手就能摘。文中的强案例同时具备战略访谈、销售、产品、评测、coding 和现场交付能力。它证明顶尖复合型人才有机会，不能证明 FDE 是低门槛退路。
放到你身上：你把 20 条 Trigger 条件写清、把动态示例做成回归资产，主要处于第一层和第二层。只有当这些能力支撑第二款车型、更高验收率或新的可收费服务，才进入第三层。评审时要把“功能看起来新”与“产生新业务价值”分开。

5.2 第二篇讲“一百万个烂员工”：模型很强，管理模型的方法很弱

原文比喻每个员工都能调用大量 Agent，像公司一夜雇了一百万名便宜员工。若任务、材料和评价不清楚，百万员工只会把错误放大。

Token-maxxing 是什么把 token 消耗量当工作量。模型读了三万字、循环二十轮、调用十个 Agent，看起来很勤奋。结果若没有改善，这些只是更贵的忙碌。

Loop 为什么会浪费需求没说清，模型反复猜同一件事。每轮没有新工具结果、新状态或新证据，重复思考只是原地转圈。有新证据进入的 Replan 则有必要。

100X token 是什么一段高杠杆 Context 可以让后续大量任务少走弯路。例如一句准确的工具边界、一个反例、一个安全规则，可能比几十条泛泛正例更值钱。“100X”表达杠杆，不是固定倍数。

Eval 是新 OKR 是什么过去公司先定目标，再看员工有没有做到。Agent 也需要明确试卷、答案、扣分点和发布门槛。不先定义什么叫做对，调用更多模型只是在扩大抽奖次数。

放进你的 Planner：32K tokens 的 SP、69 条示例、26 个工具并不会自动形成能力。应该做组件消融：移除一组示例或一类历史，用同一批 case 比较工具选择、参数、安全、延迟和成本。你的目标是找出哪一小块 Context 真正在改变结果。
别照抄“80% token 都浪费”：这是观点文章里的修辞，没有你的系统数据支持。关键安全状态即使低频，也不能因为节省 token 被删除。先测，再减。

5.3 第三篇讲中国现场：一个 Agent 项目为什么有钱、有合同、仍然做不成

国企案例的表面老板签下大合同，要求六个月做十个 Agent。执行层拿不到真实业务数据，也没人愿意承担需求和验收责任，内部还出现竞争部门。

大白话出钱的人、知道问题的人、提供数据的人、做系统的人和签字的人分成五拨。五拨人都在场，项目仍然没有一个真正的主人。

校长三天手搓案例专业团队用了三个月重做完整流程，却要求老师改变录音、填表、上传习惯。老校长只改一个局部步骤，三天做出大家愿意用的工具。赢点不在技术高，在行为改变成本更低。

“AI 替代 task，不替代 job”AI 可以完成岗位中的某几个步骤，例如查资料、起草、分类。完整岗位还含异常处理、责任、协作和判断。自动完成 30% 的任务，不能直接写成裁掉 30% 的人。

放到座舱：“做动态 Advisor，让车更主动”只是合同语言。你还要补：谁定义用户价值，谁提供信号，谁定安全边界，谁负责端侧实现，谁签体验验收，badcase 出现后谁跨模块推进。缺一项，项目可能有方案、没有责任链。
这篇最值得你记住：先做一个用户无需学习新操作的闭环，往往比一次重构全链路更容易证明价值。例如“到家前提醒别落东西”若能用现有导航、档位和播报链路跑通，比先造一套宏大主动服务平台更容易拿到真实反馈。

5.4 第四篇回答你的疑问：FDE 与咨询、外包到底差在哪

角色客户一开始知道什么你承诺什么项目结束后留下什么
咨询知道有问题，不知道方向帮他想清路线认知、报告、方案
外包已经知道要做什么，缺人实现按要求交出系统一个客户专属交付物
FDE连真实问题也说不清共同发现、实现、上线和验证客户结果 + 回流自家主产品的共性能力

最强判断题客户 A 做完以后，客户 B 会不会直接更容易？如果答案长期是否定，职位叫 FDE 也可能是外包。写了一份复盘不算回流，通用能力真正进入产品、被下一项目复用才算。

为什么 FDE 也要把产品搭出来因为 AI 需求在项目开始时往往说不清。只交 PPT 无法产生新知识，必须通过原型、真实数据和失败找出需求。搭出来是发现问题的手段，也是承担结果的方式。

为什么仍然不等于外包外包的终点是客户验收当前项目。真 FDE 还有第二个终点：把现场共性沉淀回后方平台，使下一次不从零开始。两者都写代码、都可能驻场，反馈去向才是分水岭。

你的例子：上汽提出一个途经点删除 case。只为这一款车补一段专属 Prompt，接近定制交付；提炼成“当前导航状态、候选状态、同类多候选、工具结果、无导航”五类通用分支，再进入动态示例、工具边界和回归集，开始形成产品回流。

5.5 第五篇给了最实用的方法：明线、暗线、五问与四次翻译

明线客户直接说出的方案，例如“做一个知识库”“做动态 Advisor”“再加二十个主动场景”。这通常已经是他脑中的答案，不一定是真问题。

暗线方案下面没说出口的担忧和目标。例如怕误打扰、怕验收失败、想让车型显得更智能、想减少端侧开发、想证明项目有价值。不同角色的暗线还可能冲突。

五问，先找完整责任链 ① 现在谁在完成这项工作？
② 哪一步最耗时、最容易错？
③ 不解决，业务最担心什么？
④ 老员工靠什么判断对错？
⑤ AI 做完以后，谁按什么标准验收？

车载还要补三问什么状态下绝不能执行？用户怎样撤销？多个模块意见冲突时谁拥有最终决策权？这三问决定安全与责任。

四次翻译，决定项目能否落地 ① 客户表达 → 业务目标
② 业务目标 → 判断规则
③ 判断规则 → 工作流程
④ 工作流程 → 验收结果

用主动服务跑一遍“让座舱更主动”先翻译为“在明确情境中发现帮助机会，同时降低无价值打扰”；再写信号新鲜度、置信度、组合条件、冷却、拒绝后沉默期；再分配 VLM、Trigger、Advisor、Planner、Tool 职责；最后测该触发、不该触发、时机、执行成功、可撤销和可追溯。

边界：四次翻译不是一次写完的瀑布流程。真实 case 会反过来修改目标和规则。FDE 的价值恰恰在于允许这条链小步往返。

06《需求爆兵》完整拆开：代码快了，为什么需求上线没有快十倍

这篇文章的“爆兵”来自游戏，意思是短时间造出大量可投入战斗的单位。放到产品里，一个需求只有写出代码还不算兵。接通真实数据、通过测试、能发布、能监控、能回滚，才算真正上场。

6.1 作者最初的梦：以前烂在抽屉里的方案，现在都能上线

原文意思传统互联网进入深水区，增长方向不明确。AI 让代码便宜后，可以同时尝试多个不确定方向，用更多小实验提高撞中机会的概率。

大白话以前你只有一张彩票，必须开很多会决定买哪一注；现在打印彩票很便宜，理论上可以买十注。

第一处隐藏前提：做实验最贵的环节真的是写代码。车载 Agent 里，信号开放、工具能力、车端版本、数据合规、安全验证、测试车辆和跨公司决策都可能比代码更慢。

跟你啥关系AI 能在一天内帮你写十份 PRD、十套 Prompt 和十个 HTML 原型。仁杰的端上报格式、刘杨的 Trigger 能力、丁彬与西钺的 VLM 链路没有同步变成十倍，真正上线数不会跟着翻十倍。

6.2 为什么程序员说 3X、5X，产品发版仍然没变化

原文观察个人编码速度上涨，需求从提出到上线的总周期没有明显缩短。

大白话高速公路中间一段从 80 提到 240 公里，收费站、事故检查和出口仍堵着，总行程不会变成三分之一。

一条需求经过的站点AI 能直接加速什么仍可能卡在哪里
问题定义整理材料、生成候选方案客户目标和优先级没有共识
交互与规则原型、文案、分支草稿异常、安全和模块边界仍需确认
开发写代码、测试样例、查旧代码旧接口、权限和历史债
联调日志摘要、错误聚类端云版本、车辆、多人时间窗口
验收发布自动回归、报告生成责任、风险和签字不会自动消失

结论AI 提效以后，瓶颈会移动。你若只盯原来的编码瓶颈，就会误以为团队不愿变快；真正该做的是重新测每个站点耗时和失败率。

6.3 发电机悖论：为什么把 AI 塞进旧流程，三十年都可能没有生产率

历史类比早期工厂只把中央蒸汽机换成电动机，旧皮带、旧厂房布局和集中传动没变，生产率提升很小。后来每台机器安装独立电机，工厂按物料流重新布局，效率才大幅提升。

大白话你买了洗碗机，却规定每只碗仍要先手洗三遍、填表、排队签字。新机器再快，也被旧规矩吃掉。

作者的组织设想设计师变组件设计师，程序员变全栈和基础设施支持者，产品经理变需求工程师，简单功能自己实现，复杂功能交给工程兜底。

不能照搬“三个人留一个”：这只是作者推演，不是发电机历史自动证明的结论。车控、安全和生产系统需要职责分离。PM 能做原型、配置和 Eval，不代表应该绕过工程审查修改生产车控。
你更适合的版本：你直接把 Trigger 条件、动态示例、Eval case、接口草案和可运行沙箱做出来；研发把时间集中在运行时、并发、可靠性和生产门禁。两边缩短的是重复翻译，不是互相取代。

6.4 真阻力在利益：为什么“谁爆兵，谁工贼”

原文意思产品经理天然欢迎更多需求上线。研发和设计若把提效理解为岗位减少，就缺乏主动改变的理由。先行动的人还可能被同事视为帮公司裁员。

大白话你说“我们一起把效率提高三倍”，对方听见的可能是“请帮我证明三个人只需要一个”。

真正需要对齐的账：谁获得收益、谁承担线上风险、谁因贡献被认可、节省的时间用来做什么。把这些问题藏在“拥抱 AI”口号下面，协作一定消极。

你开会可以这样说“我想先减少重复澄清和错误归因，不改生产责任。产品把分支、测试集和接口样例准备好，研发把时间留给稳定性。我们先看返工和联调时长有没有下降。”

6.5 为什么爆兵既推不动上面，也推不动下面

自下而上失败产品想试的深水区项目收益不确定，他没有权力要求多团队为实验承担风险。

自上而下也弱老板若真正重视一个项目，可以用旧管理方式催上线；若收益不确定，他也不急着大改组织。

三种能力分散技术主管懂代码，产品主管懂业务，老板有权力；很少有人同时拥有三者。所以“只要有强人操盘”通常找不到那个人。

7 月 24 日会议就是缩影：韩杰负责提出 Trigger、Condition、Action 的原子抽象；仁杰关注平台怎样形成事件处理工厂；你追问“新脚本是否就是新场景”。每个人掌握一块真相。有效推进依赖共享契约和验收，不靠某个人假装全懂。

6.6 这篇文章对你的真正要求：少造文档兵，多造闭环兵

文档兵PRD、流程图、Prompt、示例、会议纪要都做了，链路仍没有真实执行证据。它们有准备价值，还没形成产品吞吐。

闭环兵同一真实 case 从输入、Context、决策、工具、端侧执行、反馈到 Eval 都可复现，并且失败能定位、版本能回滚。

你的优先级未来一个月不追求同时铺十个新场景。先选一个条件任务、一个导航多步任务、一个 VLM 任务，做成三条端到端黄金链，再看哪些积木可以复用。

07《白领大逃杀》逐句拆：Agent 时代真的“没有 SOP”吗

这是用户最容易被一句黑话卡住的文章。作者说“每个任务要单独设计 harness，环境一变就改”。这句话一半很重要，一半说得过头。

7.1 先用“十分钟后关闭座椅加热”讲清 SOP 与 Harness

SOP像固定菜谱：识别定时任务、登记、到点执行、通知。只要任务结构稳定，大家重复照做。

Harness像整间厨房：输入格式、可用工具、权限、Task 状态、Trigger、失败重试、停止条件、人工确认、日志和 Eval。Prompt 只是墙上的一张操作提示。

为什么环境一变就要改同一句话在不同状态下结果不同：座位没人、车辆下电、座椅加热已经关闭、任务被用户取消、车控失败。固定回答覆盖不了这些变化，Harness 必须知道如何观察和处理。

为什么作者说无法复用开放任务的对象、数据和异常经常变化。今天分析客诉，明天写销售方案，后天查代码，工具和判断标准都不同。普通人过去靠背熟一套步骤省脑力，现在要频繁重建工作台。

这里说过头了：自然语言千变万化，底层任务仍可归类。定时任务可以抽成相对延时、绝对时间、固定间隔和周期日历；条件任务可以抽成事件、状态、运算符、冷却和动作。变化的是参数和场景边界，元流程可以复用。

7.2 “缓存命中”和“全新推理”只是人脑比喻，不是技术定义

作者想说普通人遇到熟悉任务会直接调用旧经验，节省脑力；Agent 驾驶者需要重新看环境、编辑规则和判断结果，持续耗费注意力。

大白话一个人喜欢每天按同一份表格办事。让他每次先判断表格是不是还适用，再重写一份，他会觉得累。

技术上的 KV Cache它指输入前缀相同时复用已计算的中间向量，节省模型计算。它不等于人类复用旧答案。你读文章时要把两层意思分开。

放到 SP：角色、工具定义和输出格式保持稳定前缀，有利于 KV Cache；{{memory}}、{{env_info}} 和视觉等动态信息放在后部。这个技术设计与“同事不想重新思考规则”的组织问题有关联，但不是同一件事。

7.3 谁是 Agent 操作员，谁是 Agent 工程师

操作员会输入一句话，结果错了就骂模型、重说一次，能用就停。价值来自使用工具。

熟练驾驶者知道怎样拆任务、选工具、补 Context、检查中间结果，能让自己的任务稳定很多。

工程化负责人把个人经验做成团队可复用的模板、Skill、规则、Eval、日志与版本治理，让别人也稳定获得结果。

你职业上的生死线：会用 Codex 帮你写更多材料，只证明个人提效。能把失败变成动态示例、工具边界、分诊规则和回归集，才开始产生组织能力。

7.4 双重死循环为什么让白领替代变慢

第一圈公司不切 Agent 模式，就培养不出懂业务的 Agent 人才；没有这样的人，又不敢把业务切过去。外招的人懂 AI，却不懂业务暗线。

第二圈内部先行者一边承担交付风险，一边担心自己帮助公司裁人；同事也可能不配合。提效带来的收益没有回到贡献者，动力很快耗尽。

第三个隐藏阻力单个人只改得动自己闭环的任务。一个跨部门流程里，任何没改造的环节都会成为新的瓶颈，所以个人 10X 很难变成公司 10X。

你的位置：你可以让动态示例写得更快，却无法单独开放 `chargePortCoverState`，也无法替仁杰决定上报格式，更不能替车控团队承担误执行风险。你的提效必须转成一份多人认可的契约，才能跨过组织边界。

7.5 “打磨 Harness 没有外部性收益”到底在说什么

外部性收益你做了一件事，别人也因此受益。原文的意思是：一个人花两个月调了 200 版，若没有共享、指标和认可，他只得到自我满足，同事感受不到价值。

黄钊的反方持续运营恰好可以变成壁垒。先运行的人更早获得失败样本，更早更新规则，下一版继续领先。

两人其实没完全冲突纯银讲员工为何不愿投入，黄钊讲公司若能保存成果会得到什么。中间缺的是版本库、复用统计、效果指标和贡献归属。

你的做法：每次 SP 或动态示例变更必须记录：修复哪些 case、影响哪些场景、指标变化、谁提供了关键规则、怎样回滚。这样“我调了一百版”会变成团队可见的资产。

7.6 五到十年预测能不能信

能信的部分组织替换比模型升级慢；成熟业务有历史债、责任和社会成本；局部提效不会自动变整体产能。

不能当事实的部分五到十年是作者明确承认的主观估计。模型能力、工具自动化、FDE 人才培养和企业压力都可能改变速度。

你的正确读法全面裁员可能慢，岗位内部的低价值任务迁移已经开始。你没有五年时间继续只做材料转述，同时也无需恐慌到立刻改行。

08“复杂、边界清晰、端到端”逐词拆：这三个词怎样变成你的产品筛选器

这篇短文的方向很有价值，表达过于压缩。它想说：简单且公开的任务容易被底模吸收；真正能留下产品价值的任务，通常有很多现场变量，同时有清楚的成功和失败边界，最后让 Agent 自主处理长尾。

8.1 “复杂”不是流程图节点多，是情况多、关系多、失败方式多

错误理解把一个简单审批画成五十个节点，看起来很复杂。节点多可能只是旧流程啰嗦，不代表值得用 Agent。

真正复杂输入来源多、状态会变化、多模块互相依赖、规则有冲突、异常无法提前穷举、执行后还要根据结果修正。

座舱例子复杂来自哪里简单脚本为何不够
“我好热”说话人位置、当前温度、风量、窗户、偏好、其他乘员直接把全车空调调低可能让别人不舒服
“去昨天那个游泳馆”记忆召回、地点消歧、当前位置、路线、工具反馈名称不是显式地址，前一步结果决定后一步
“宝宝哭了告诉我”VLM 周期观察、语义判断、误报、冷却、任务生命周期一帧画面不能稳定代表持续哭泣
“沿途有风景就介绍”路线、位置、视觉、内容价值、打扰时机和去重开放环境的长尾无法靠几条 if 完整覆盖
复杂本身没有价值：有些流程复杂，是因为组织低效或接口破碎。先删掉不必要的复杂度，再判断剩余部分是否需要智能。把混乱原样交给 Agent，只会让错误更难追踪。

8.2 “边界清晰”不是写一个数字，是把要、不要、灰区和禁区都说清

文章说的画面感只有真正懂业务的人，脑中才有“什么结果一眼就对，什么结果一眼就别扭”的具体画面。这就是 know-how 和 taste。

产品化要求只存在你心里的画面还不够。它必须外化成正例、反例、灰区、禁止项、状态依赖和验收标准，团队和模型才能复用。

动态示例的真实边界：车速大于 80 km/h 时开窗只开 10%；空调温度范围 15.5 到 30.5℃；风量 1 到 11 档；按摩 8 种且仅主副驾；巡航 30 到 130 km/h 且为 5 的倍数。这些数值是硬边界。另一些边界来自画面：有两个同类途经点时应该先澄清，不应猜一个删除。

“不是什么”为什么重要正例只告诉模型一条亮路，反例标出悬崖。比如“到家前提醒”不等于一进入导航就播报，也不等于车辆已到 P 档后还说“快到了”。

你要写的金线：场景触发的最小充分证据是什么；证据缺失时怎样降级；什么情况下宁可不做；做错的代价是什么。边界清晰以后，模型才有自主空间。

8.3 “把所有 Context 扔进去会激发智能”为什么不能照字面执行

作者真正想表达复杂现场不能被几十个固定节点穷举。给模型足够相关材料和工具，它可以在长尾条件下自主推理。

字面风险所有材料一起塞入会带来冲突、过期、注意力稀释、成本和隐私风险。模型也可能被无关信息带偏。

你应该怎么改写把“所有 Context”改成“当前决策所需的最小充分 Context”。公共 Context 服务先维护 13 类信息，再由知识筛选、人物身份、任务和时效选择本轮需要的部分。

例子：删除途经点需要当前导航状态、已加途经点与候选，不需要用户长期食物偏好；宝宝哭任务需要 VLM 描述、座位信息、任务状态和冷却，不需要完整导航历史。按决策点装材料，比永久全量注入更稳。

8.4 “端到端”至少有三种意思，混用会让评审吵偏

模型端到端尽量由一个模型从原始输入直接生成输出，中间少用人工规则。这是算法架构含义。

任务端到端从用户提出目标，到真实结果完成并被确认，整个任务闭环。这是产品含义。

系统链路端到端每个模块仍清晰分工，但数据、状态、错误和责任能贯穿全链路。这是工程与交付含义。

你的项目应优先争后二者：车载系统需要可解释的权限、车态、工具和回滚。没有必要为了“模型端到端”取消确定性保护。真正目标是用户任务走完、系统责任不丢。

Planner 与 Director它们是同一决策职能的内外名称，不应在图中画成两个连续大脑。VLM 观察；Trigger 匹配、防抖和回调；Advisor 提供建议；Planner/Director 做面向用户的统一决策；Tool 执行并返回 feedback。

8.5 Workflow 与 Harness 谁更稳定，这个二选一也说过头了

Workflow把确定步骤明确连起来，适合合规、审批、固定接口和安全动作。

Harness给 Agent 自主空间，同时规定工具、状态、检查点、退出和评测，适合开放式判断。

车载最佳组合模型负责理解模糊意图和选择策略；Task/Trigger 保存确定状态；车控工具执行受权限保护的动作；Eval 和日志负责追踪。开放判断与确定执行长期共存。

效果不好不一定是 Prompt 或 Skill 没调好：也可能缺信号、工具不支持、下游失败、数据过期、模型能力不足、UI 误导或无日志。6 月 12 日分诊会已经证明，导航约 40 条问题里真正属于 Planner 的只有 2 到 3 条。

09四篇物理世界文章合读：从 AI 硬件、眼镜、机器人到汽车，真正难在哪

这四篇表面分别谈硬件创业、机器人融资、AI 眼镜和车企上新，底层是同一个矛盾：模型按天进步，物理产品按月和年交付。最后赢的公司必须让前端形态快速变化，后端能力持续复用。

9.1 AI 硬件指南：硬件为什么是不可逆的决定

原文链路先选品类和用户场景，再选择供应链伙伴、做原型、走量产、控制良率与交期、做营销和团队。任何前期错误都会在开模、备料、认证和售后阶段被放大。

大白话软件按钮做错可以明天改，硬件尺寸做错可能已经生产十万套。每一次“先试试”背后都绑着物料、工厂和库存。

“硬件获客，软件服务”用户先被外形、佩戴、价格和用途吸引，买回去后才会长期感受 AI。硬件是进入生活的门票，软件决定留存和关系。

边界：工业和车载硬件很多时候已经存在，不需要靠“性感外观”重新获客。汽车本身就是已售出的高价值平台，座舱 AI 的核心任务更接近提升持续软件价值。
跟你啥关系：你做的 Driver Agent 运行在一辆已定义好的车上，不能为模型随意增加传感器、改变算力或改车身。你必须在既有硬件约束下，把状态、工具、端云延迟和权限组织好。这是物理产品经理与纯软件 PM 的第一处分界。

9.2 猎头看具身：机器人 Scaling 为什么还是一张没有画出来的曲线

融资故事LLM 用数据和算力规模化后出现智能，所以机器人积累更多真实数据也会出现通用能力。前半句有现实成绩，后半句仍是推论。

数据差在哪文本由人类多年免费积累，抓下来就能用。机器人轨迹要在物理世界采集，贵、慢、分散；仓库抓包数据未必教会叠衣服；操作员水平会影响质量；换一双手或身体，数据可能难迁移。

为什么公开共识会失真融资市场更愿意听“通用人形智能”。一个扎实但窄的跨本体数据项目，可能被要求换成人形渲染图才能融资。公开声音的大小反映融资难度，不等于事实概率。

终局正确为何挡不住泡沫人形机器人可能是终局，今天的价格仍可能过高。互联网长期正确，不妨碍 2000 年许多公司估值崩塌。终局和当前价格是两道题。

最诚实的观察口：看招聘和预算。公司若大量招聘数据引擎、遥操作、仿真到真机迁移、部署与硬件可靠性，说明它在为 Scaling 铺路；若主要招三个月做融资 demo 的人，长期故事可能还没落到组织投入。
你转具身时可直接问：上个月采了多少小时真机数据？多少进入训练？成功率按什么任务和环境统计？失败怎样回流？数据能否跨本体复用？这五问比“我们是不是做世界模型”更有价值。

9.3 夏勇峰暂停 AI 眼镜：产品成功，为什么战略仍可能错过时代

他的决定眼镜业务已有市场份额和增长，大厂订单也在手，却暂停新品。理由不是眼镜没有需求，是眼镜要先解决舒适、外观、适配和线下体验，AI 很难成为当下第一购买理由。

大白话继续做眼镜，团队每天会优化镜腿轻两克、款式更好看。这些工作能赚钱，也可能让团队错过定义 AI 原生产品的窗口。

“为 AI 造硬件”从 LLM 需要什么出发，寻找最小可成立的物理载体。身体先保持轻，借手机、云、IoT、位置、触摸和声音进入一个高频场景，再逐步长出能力。

关系为何成为核心高频交互带来信任；信任让用户分享更多真实信息；连续记忆让 AI 越来越懂用户；稳定人格和关系在设备更换后仍能继承。作者把这一层称为 Soul。

这里有三道没回答的题：关系是否真的提高长期留存；用户是否愿意把敏感记忆交给系统；多人共享设备时人格、身份和权限怎样分开。Soul 是产品假设，还不是已经证明的护城河。
放到车里：FaceID、search_user_memory、operate_user_memory、目标列表和情感 Advisor 是 Soul 的基础积木。车属于多人共享空间，所以必须先解决“这条记忆属于谁、谁能看到、何时失效、换车能否继承”，再谈关系资产。

9.4 车圈疯狂星期四：车型越多，为什么反而更考验一套底座

第一阶段像福特一样把生产规模做大，让更多人买得起车。

第二阶段像通用汽车一样，为不同人群铺满产品矩阵。家庭、驾驶、智能、性价比等需求分化，车企用更多车型占住细分位置。

产品矩阵是什么像超市货架，同时摆出不同尺寸、价位和用途的商品。货架丰富不代表仓库高效；每款车背后若是不同软件和数据系统，车型越多，维护越乱。

价值迁移是什么钱和竞争优势逐步从“多发布一款车”流向三处：统一智能化底座、供应链组织、交付后的持续服务。

放到你的产品：一套 Planner/Director 核心、统一工具语义、Trigger 原子能力、Task 状态和 Eval，外加车型配置与信号映射。新车型只改配置和能力差异，比每款车重新写 SP、规则和场景更接近真正底座。
出行服务终局仍是推论：自动驾驶成熟、监管允许、车企掌握用户关系、服务收入足够高，这些条件都没在文章里证明。你可以用它看长期方向，不能拿它给当前每个座舱功能立项。

9.5 四篇拼起来，你从座舱转具身时真正可迁移的能力

你现在的积累在具身里的对应物还缺的实证
车辆状态、事件和 Trigger机器人环境状态、事件检测与触发传感器噪声、实时性和安全闭环
Planner、Task、tool_feedback任务规划、执行状态和失败恢复真实动作反馈与长时任务可靠性
动态示例与能力边界策略案例、动作限制和 Eval跨环境与跨本体泛化
OEM 多方协作客户现场、硬件团队、算法和部署协作生产线或真实客户的交付结果
用户记忆与多人身份家庭机器人长期关系与权限隐私、迁移和连续学习机制

所以你未来不只能进车企，也不只能做车载 FDE。仓储、制造、零售、医疗设备、家庭服务等行业都需要这套“现场状态 → 任务 → 工具 → 反馈 → Eval”的能力。跨行业时，你要重新学习物理流程与风险，通用骨架可以带走。

10梁文锋的“克制”与《认知只是心之奴》：你怎样避免懂很多、仍然押不下一条路

前面九节解决外部问题：市场、Agent、组织和物理世界。最后两篇转向个人取舍。一篇讲公司怎样用克制集中资源，一篇讲人为什么知道道理却不行动。两篇有启发，也最容易被写成不可验证的精神判断。

10.1 先说明来源：52 条是媒体收集材料，不是可核验的逐字会议实录

材料自己的说明内容来自多方收集，部分词句在保留原意的基础上可能与原文略有出入。因此页面里只能写“整理材料称”，不应把每句话当梁文锋逐字原话。

为什么这个边界重要人物语录容易被后人拼成完整哲学。来源本身有编辑选择，哪些话被留下、怎样分组，都影响你看到的形象。

10.2 梁文锋的主线不是“什么都不做”，是先确定终点，再砍掉不增加成功概率的支线

终点AGI。产品、API、Agent、持续学习和具身都按“是否增加做成 AGI 的概率”排序。

阶段材料把路线描述为 CoT、Agent、持续学习、AI 自迭代、具身。每个阶段解决下一类能力缺口。

为什么不追产品规模产品被看作技术能力在现实中的副产物。团队不想把主要精力投入 C 端、B 端运营、3D、视频和超级 App 竞争。

为什么重成本低成本既能让更多人使用，也能在算力有限时训练更大模型。成本是技术路线的一部分，不只是价格策略。

为什么开源和低价材料认为让利能提高员工成就感、组织凝聚力和社会支持，减少竞争敌意，从长期提高成功概率。

为什么团队稳定是底线技术路线可以试错，核心研究团队一旦瓦解，长期积累会中断。融资的重要作用之一是解除团队不稳定风险。

完整逻辑：终点清楚 → 选择当前台阶 → 把成本与组织围绕台阶优化 → 主动放弃会分散资源的机会 → 用让利换环境与团队稳定。
最大风险：“提高 AGI 成功概率”难被外部观察，也可能为任何取舍辩护。有效克制必须配一张可检查的路线图：当前能力缺口是什么、这个项目如何填补、多久看不到证据就停止。
放到你身上：你的克制不应是少写材料，也不应是拒绝小需求。它是确定一个季度的唯一结果，例如“把三类长任务做成可测闭环”，然后让场景知识、动态示例、Trigger 和评审材料都服务这个结果。与结果无关的新图、新模板和新概念暂缓。

10.3 “心力先于认知”有一块真问题：知道方法不等于愿意承担后果

文章的有效核心人可以理解很多道理，仍不采取行动。启动一件困难的事需要欲望、勇气、责任感和承受不确定性的能力。认知只告诉你可能怎么做。
