# R7 跨模块 impact（触发器×记忆 / 知识检索 / 自进化）

来源：r7 补读 13 篇（5 篇无内容或无权限）。每条带链接、状态、车型。资料有、副本缺的产品事实。

## 11 K｜身份与记忆

- **身份五层字段**：OEM 账号 → 座舱豆包账号 → 火山 user ID → Occupant ID（舱内占位）→ 生物身份（faceid+声纹）。生物信息不出车，识别结果出车、仅当前车内生效。【已落地·终版共识】《身份识别、记忆隐私原则》https://bytedance.larkoffice.com/docx/SbZvdWu4ToVAQIxcUd7ciTYGn9b
- **记忆开通门槛**：车主必选绑定豆包账号（车辆激活不可跳过）；上汽已确认授权用户也必须绑定；未录入生物信息可用豆包大部分功能，但**无 Always On、无记忆**。【已落地·上汽 D6X 已确认】同上。
- **记忆隐私操作**：记忆设置页可见范围「查」、增删改需 faceid 或手机扫码校验；乘客上限 25、孩子上限 5。【已落地】同上。
- **记忆服务七类产物**：短期情景（20min/20 条合并，1 天有效）、短期历史、长期情景（按天合并短期）、长期语义（偏好，只从用户说的话提取、不扩展）、记忆打标、结构化记忆标签、记忆打分、记忆画像推理。【已落地】《记忆 OnePage》https://bytedance.larkoffice.com/docx/CH1rduG07oRsooxHD2UcXPL4nIc
- **抽取时机（与触发器强相关）**：偏好抽取**每天凌晨定时离线触发**，只有用户明确表达记忆增删改时才实时触发——这是算资综合考虑，不是每轮对话后都抽。【已落地】《MOA vs Mem0》https://bytedance.larkoffice.com/docx/GGwedUKlJoGNcixLsOucAv9znQd
- **取舍对比**：我们比豆包 MOA 多一个**记忆删除能力**；豆包 MOA 是每轮后异步抽取、全量注入零延迟，我们是离线批量+按需实时。【已落地】同上。

## N9｜事件日志

- **任务历史记忆**：完整任务 trace 按 1200 字符/chunk、180 字符 overlap 切片存向量库；任务摘要每条单独成一条记忆（描述+总结）。事件日志是「发生过什么」，任务摘要回答「这趟办成了什么」。【已落地】《MOA vs Mem0》同上。

## N6｜知识 & 状态检索 / 动态知识对 Context 的影响

- **动态示例 scenario_sample**：把海量「用户输入→处理逻辑」存向量库，请求时按 query 语义 Top3 最相似 SFT Case 注入系统提示词；在 pre-query 阶段并行检索，不拖主链路；解决长尾 badcase、省静态示例 token。【已落地】《动态示例与动态知识 OnePage》https://bytedance.larkoffice.com/docx/JNySd1dhUoUVT3xilTGcIoeAnlg
- **动态知识 knowledge**：不走向量，用一个小模型根据近两轮对话选场景 ID，把对应 SOP 长文（儿童安抚、车内观影、急速调温等 8 大场景）拼进提示词；边界条件写死（如行驶中禁止前排观影）。【已落地】同上。
- **两者分工**：动态示例教模型「这个工具具体怎么调」（原子案例）；动态知识给「多步骤高阶业务流程怎么走」（场景 SOP）。一个管动作，一个管流程。【已落地】同上。

## N5 / N19｜自进化、反思、个性化规则

- **记忆画像推理（点状→面状）**：「我喜欢麦当劳/肯德基/必胜客」→ 推理出「喜欢西式快餐」，后续推荐汉堡王。这是点状记忆到面状偏好的聚合，是自学习个性化规则的雏形。【已落地】《记忆 OnePage》同上。
- **打标标签化**：记忆→打标签（音乐偏好/通勤/饮食）→ 结构化标签（喜欢歌手：周杰伦）→ 打分，供业务方排序过滤。【已落地】同上。
- **降本方向**：用新的用户记忆标签模型对记忆打标签，替代对全量记忆合并，减少 token 销量、提速、降低无关记忆干扰。【讨论中·工程设想】《记忆发展愿景》https://bytedance.larkoffice.com/docx/EdoXdyTGSoFXqrxPnZVcCniRnWd
- **空/无权限**：「反思」「动态知识体系」正文仅标题；「离线反思需求沟通」「豆包自我探索需求说明」打不开。自学习闭环细节（用户能不能看/改/删、优先级排序）本轮未取得一手材料，建议标【待核】。

## 13 G｜触发器怎么用记忆和事件（重点）

- **记忆生成是定时任务，不是对话实时**：语义记忆长记忆生成从 http 触发改成脚本+定时任务，可按日期、按用户（master:5371）重跑。【已落地·运维】《aidv 触发语义记忆调整》https://bytedance.larkoffice.com/docx/VenXdiHDSo1aDPxaKbqczqRInhc
- **干预与拒识并行**：车控干预在主链路与拒识并行执行，拒识未命中且干预命中时直接返回车控协议给客户端，不进大模型。【已落地】《aidv 接入离线车控干预》https://bytedance.larkoffice.com/docx/HbFjdX4SWoCpzsx60Zvc7iPdndg
- **缺口（资料有、副本缺）**：「事件/记忆怎么变成新一轮 query」这一环本轮补读的多是抽取侧（定时离线）和干预侧（并行兜底），**记忆事件主动触发新一轮对话**的产品链路没有一手 PRD，建议【待核】，不要写成已上线。
