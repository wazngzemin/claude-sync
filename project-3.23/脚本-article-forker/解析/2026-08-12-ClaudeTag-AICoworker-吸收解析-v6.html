01 · 开头六段

先看作者想让你相信什么

原文第 9-11 行

原文一个月前，Anthropic 在 Slack 里上线了 Claude Tag，这个产品并没有引起太多讨论和关注，外界只是把它当成 Anthropic 随手发的小功能。

人话一个多月前，做 Claude 的 Anthropic（公司名）在 Slack（企业聊天软件）里放了一个新东西，叫 Claude Tag（可以理解成“Claude 数字员工”）。没人热烈讨论，大家都觉得是个小功能。

原文第 12 行

原文但实际上，Anthropic 内部对这个产品的期待远远超过外界感知，他们正在明确地把它当作下一代爆款产品来建设。在他们看来，Tag 可能是一种 10x Claude Code 的产品形态，对应万亿美元级别的市场空间。

人话公司内部把它当大事。10x Claude Code，意思是价值可能比 Claude Code 大十倍；万亿美元，是说这类产品的市场总量。

原文第 15 行

原文借用 Andrej Karpathy 的判断，Claude Tag 意味着 AI 产品的交互方式会真正开始迈入第三个阶段: Chat → Local Coding Agent → AI Coworker。

人话AI 产品的样子分三步走：第一步，聊天机器人，你问它答；第二步，本地编码助手，帮你写代码；第三步，AI 同事，长期待在团队里干活。作者说现在进入第三步。

原文第 18 行

原文这背后是三种工作模式同时发生迁移：从单人到多人，从被动到主动，从同步单次到异步长程。

人话三对变化一起发生。单人到多人：AI 从服务一个人变成服务一群人。被动到主动：从你问它，变成它自己找活。同步单次到异步长程：从当场办完，变成任务跨几天甚至几周。

你身上你的产品正好踩在第二和第三对变化上：主动 Advisor 是“被动到主动”，长时任务是“异步长程”。这篇文章讲的就是你正在踩的那条线。

原文第 21 行

原文Coding 只是 AI 进入生产力场景的第一步，Claude Tag 以及它所代表的 AI Coworker 类产品形态可能会让 AI 真正走入“替代白领”的阶段。

人话帮程序员写代码只是第一站。下一步是替普通坐办公室的人干活。

原文第 24 行

原文团队的工作正在快速从 Claude Code 向 Claude Tag 迁移：目前产品团队超过 65% 的代码已经由 Tag 完成，一些员工甚至 90% 的工作都已经在使用 Tag 而非 Claude Code。

人话Anthropic 自己的团队已经重度用上 Tag：产品团队写的代码里，超过一半是它写的；有的员工九成工作靠它。

02 · 第一章：产品是什么

七个细节，把产品边界画出来

原文第 36 行

原文Claude 可以以团队成员的身份直接加入公司的 Slack 频道，获得团队全部 context，用户只需在聊天框、文档等地方 @claude，就能直接调用它来处理任务。

人话就像把一个人拉进公司群：它能看这个群的历史消息和文件，谁都可以@它派活，聊天框和文档里都能叫它。

你身上你们的公共 Context 也是这个思路：给模型当前场景的事实，而不是把全部历史塞进去。“常驻”对应你们的 Always On 和事件时间线。

原文第 38 行

原文目前整个产品仍在 beta 测试阶段，需要同时拥有 Claude 企业账号和 Slack 企业账号才能试用。

人话还没正式卖。要试用，公司得先同时买了 Claude 企业版和 Slack（企业聊天软件）企业版。

原文第 44 行

原文除此之外，也支持配置 skills，支持设置长期目标，定时任务等。

人话除了聊天，还能干三件事：装技能包，让它按固定方法办事；记长期目标，一直挂在心上；设定时任务，到点自己干。

你身上skills 对应你们的 SP 静态规则，长期目标对应 goal list 和 Task，定时任务对应定时 Trigger。文章的机制和你的模块是一套词表的两面。

原文第 46 行

原文模型方面，目前可以接入 Fable 5、Opus 5、Sonnet 5、Opus 4.8 和 Opus 4.7，只有企业管理员可以在后台切换模型，普通员工则可以直接对 Claude 说“这个用 Opus 5”，为具体任务临时切换模型。

人话底层的大脑可以换，有好几款。公司管理员定默认款，普通员工也能口头指定“这一件事用更强的那个”。

你身上对应你们 PE 和 SFT 两套方案的切换，你正处在“给谁用、哪个版本用”的口径治理里。

原文第 48-52 行

原文Tag 只支持在 Slack 的公共频道里面使用，以 usage-based 方式记账，记在企业账上，和 API 价格一致。如果要在 Slack 内跟 Claude 私聊，则不属于 Tag 的使用范围，需要绑定自己的 Claude 账号，走自己的会员套餐。

人话只在公共群里能@它，按用量算钱，单价和直接调 API（程序接口）一样，公司付账。私聊它是另一回事，走个人套餐。

你身上你们“公开上下文”和“私有上下文”的边界，就是这类产品的核心决定。车上的公开信息是车辆状态和事件，私有信息是记忆和 face_id，边界不能混。

原文第 54 行

原文支持几乎所有 MCP 集成，可以自由接入 GitHub、Notion、Google Drive、Snowflake 等。

人话通过一个标准插座接外部软件：代码库、笔记、网盘、数据库，接上就能读能写。

你身上你们正在做的工具契约表，就是座舱版 MCP：意图边界、参数、前置状态、失败返回。方向一样。

原文第 56 行

原文Runtime 全部由 Anthropic 云端托管，每个 thread 起一个临时 sandbox 跑完整 agent loop，底层复用的是 claude managed agent 的 tech stack。

人话每次任务都在 Anthropic 的服务器上开一间隔离小房间，AI 在里面自己循环干活：想一步、做一步、看结果、再想，干完拆掉。

03 · 第二章：三个关键能力

入口不重要，三件事才是真功夫

原文第 80-86 行

原文Claude Tag 并不是一个多新的产品形态。过去半年多，市面上已经出现了非常多把 AI 放进协作场景的产品。最早的是 Devin，最火的可能是 OpenClaw。但这些产品最终没有大规模铺开……背后的核心原因是模型能力还不成熟，Anthropic 的团队认为，其实模型只有到了 Mythos 级别，才算真正解锁了 AI Coworker 的产品形态。

人话作者先自认这不是新点子：把 AI 拉进群，前两年就有人做。没做起来，是因为当时的模型不够强。Anthropic 自己说，要到 Mythos（Anthropic 的高端模型）这个级别才算够。

第一件事：Long-horizon autonomy，能自己干多久

原文第 97 行

原文模型能自主工作的时间，最大程度上决定了 AI 最合适的产品形态。

人话AI 一口气能干多久，决定了它该长成什么样。

原文第 103-107 行

原文当模型只能连续自主工作几分钟时，最合适的是 chat 或 autocomplete……当它能推进约 1 小时的任务时，local coding agent 开始成立……只有稳定工作数小时之后，才值得做 async agent：用户下班了，Agent 仍在云端自主推进，最后带着结果回来。

人话三档对应三形态：只能干几分钟，就做对话框，人全程盯着；能干一小时，做本地编码助手，人在旁边随时接手；能干几小时，才做异步同事，人下班它继续，完事带结果回来。

你身上“到终点前 1km 提醒我”就是 async agent 的最小样本。它要求系统自己等条件、自己醒来、提醒完自己关任务。

原文第 111-117 行

原文按照最新的 METR 评测，Mythos 已经能完成大约相当于人类专家连续工作 16 小时的任务。Claude Tag 又在此基础上增加了 Self-schedule……比如，下周三回来检查实验数据。于是，单次 16 小时的执行能力可以被连续串联起来，变成持续几个月的长期任务。中间的等待、唤醒和衔接，都由模型自己完成。

人话作者说 Mythos 一口气能干人类专家 16 小时的活。Self-schedule 是“自己给自己设闹钟”：今天干不完，把下一步排到下周三，到点自己醒，接着干。16 小时一段一段串起来，就成了几个月的大任务。

你身上文章叫 Self-schedule，你们叫定时 Trigger 加条件 Trigger 加 Task 生命周期。名字不同，干的是一件事。

第二件事：Memory，记忆怎么做

原文第 124-127 行

原文记忆对 Tag 很重要，模型需要能真正记住人类交代的 to-do、方法和风格偏好，并把单次经验迁移到未来的任务中。Anthropic 尝试过很多记忆方案，最后发现，最好用的就是最朴素的文件系统，给模型一块可以长期读写的空间，放手让它自己维护。

人话记忆要记住三样：你交代的待办、做事的固定方法、你喜欢什么风格。他们试了很多花哨方案，最好用的是最土的办法：给模型一个文件夹，让它自己写、自己改、自己删。

原文第 129-137 行

原文这并不意味着每只 Claude 都可以随意翻看全公司的信息。Tag 的记忆会按照权限分层……每只 Claude 只能看到自己所属频道里的 Context，只有获得授权后，它才能走出房间，去其他频道浏览信息。最终，Tag 的整套记忆库分成三层……Thread context：当前任务相关的对话和工作过程；Channel memory：这个频道长期稳定的规则、决策、项目背景；Workspace memory：整个公司的记忆，可以被同一 workspace 的其他公共 channel 复用。

人话记忆分三层，权限像办公室。第一层 Thread（当前任务），这一件任务的过程，干完就归档；第二层 Channel（当前群），这个群的长期规则和决定；第三层 Workspace（全公司），全公司公共知识，别的群也能用。没授权不能串门。

你身上Thread 等于任务级 Context；Channel 等于车企、车型、版本的真值；Workspace 等于通用工具契约和评测。车内还多三层：人物、车辆、驾驶安全。

原文第 143-149 行

原文“我发现的一些最有意思的东西是：低阶模型和高阶模型之间的主要区别，就在于蒸馏（distillation）能力。高阶模型更能判断出怎么对记忆进行高维抽象，它们不光记录具体事件，还会真正思考，这段经验以后还能泛化到什么地方。”

人话这段话是引用 Anthropic 内部人的话。蒸馏在这里是比喻：把经历“熬浓”成经验。低阶模型只会记流水账；高阶模型会想：这件事说明了什么规律，以后哪种情况还用得上。

你身上你们的动态示例就是这个道理：好例子是抽出来的规则，坏例子是堆上去的个案。这也解释了为什么动态示例要按车企、车型、版本治理，而不是越多越好。

第三件事：EQ，什么时候主动、什么时候闭嘴

原文第 156-159 行

原文Anthropic 还专门训练了 Claude Tag 的情商和分寸感，让它能判断出来什么时候该主动帮忙，什么时候该退居幕后。(我们自己试用完也觉得 Tag 比 Claude Code 情商明显高一个 level，沟通起来非常舒服，很有活人感，表情包也用得相当熟练。)

人话专门训练它看时机：什么时候插话帮忙，什么时候别出声。作者自己用下来觉得它比 Claude Code 会做人，表情包都发得顺。

你身上你们群里正在问的三件事：AI push 展示多久、能不能并行、跟别的卡片谁让谁。这就是 EQ 的产品化，必须有人拍板规则。

04 · 第三章：它解锁了什么

两类新工作，加一个四问筛法

原文3. Tag 类产品可能让大模型公司开始形成一些护城河。这种护城河不一定来自模型记住了多少公司信息，因为记忆是可以被完整导出的，更关键的是，Claude Tag 会逐渐持有公司的一部分“运行状态”。比如……Boris 一个人现在就在同时运行数百个 Tag 任务，其中很多是长程任务，每个都有不同的权限、数据源、与其他任务的依赖关系……如果后面要更换模型供应商，相当于替换一大批正在工作的员工……现在模型层的竞争越发胶着……开源模型可能也只有三个月左右的身位差。一代模型即使短暂领先，真正有效的变现窗口可能也只有两个月。

人话第三个延伸：护城河。记忆可以导出，所以记住多少信息不算壁垒。真正的壁垒是“运行状态”：几百个没跑完的任务、各自的权限、数据源、任务之间的依赖关系，这些导不走。换供应商等于换掉一批正在上班的员工。背景是模型竞争胶着，开源只落后三个月，一代模型领先窗口可能只有两个月，所以要把短暂优势固化成迁移成本。

你身上你维护的 TaskSpec、Trigger 订阅、工具契约、事件定义，就是座舱版“运行状态”。这些做得越标准，模型换哪家都能跑，你的价值越稳。

原文第 489-516 行

你身上你就在“国内大厂游戏”这局里：字节有豆包当大脑、飞书当环境，你负责车这个新环境。你的上坡路，是把车端做成有语义、可交付、可追踪的环境层。

原文第 518-550 行

原文5. 08 · 黄钊评注

他的 11 段评注，一段一段看

黄钊把这篇评为“今年年度最有价值”，并把它拆成 11 段。他的手法值得你学：不重述原文，只挑产品视角的关键点做评注。下面逐段看他到底在说什么。

评注 a

黄钊产品形态细节：Slack 公共频道、按量记账、私聊不算、MCP 全接、五模型切换、云端沙箱。他的评注是：Agent 在“群”里中转加工各种信息，会是 AI-native 组织的核心特征；2B 和 2C 在这个模式上是相通的。

人话他挑出的重点不是功能列表，是“在群里中转加工信息”这个位置。他的判断：未来公司会围着“AI 在群里”长出新组织方式，而且这个模式和做消费者产品是同一条逻辑。

你身上你的车就是 2B 和 2C 连在一起的样本：车企是客户，坐车的是个人。这是黄钊说“通”的真实例子。

评注 b

黄钊“模型能自主工作的时间，决定 AI 最合适的产品形态”，他说能尽早洞察这一点非常难。

人话他把原文第 97 行那句单独拎出来表扬，因为大部分人只会看“强不强”，不会看“一口气能干多久”。

评注 c

黄钊记忆三层，加上他本人最爱的一句：“能有时做 A，但有时又需要做 B（A 的反面），这个 feature，是真正的 AI（智能）跟旧规则模式的核心分水岭。”

人话他的判断标准：同一个东西，有时该主动、有时该闭嘴；有时该坚持、有时该退让。旧规则只能定死一条，真智能能看情况选。会用“有时这样、有时相反”来做事，就是智能和规则的差别。

你身上你们的 Advisor 就是同时要“有时主动、有时沉默”，模型给判断，频控和互斥守底线。

评注 d

黄钊相比 Claude Code，Tag 解锁两类工作：高协作高 context 密度、主动响应。他把原文的“四问”原样保留。

人话他没加新观点，只是标记这两类工作是 Tag 相对旧工具的真正增量。

评注 e

黄钊三个雏形，加一个他自己的补刀：一年前张和老师就说过，团队协作就该“一切问题群聊、几乎不私聊”，因为要对齐大家的认知。

人话他借张和老师的观点补上共享大脑的组织前提：公开讨论不光是给 AI 看，更是团队对齐认知的方式。

你身上你们的公开群聊文化已经具备，缺的是把群里的结论沉淀成可复用文档，这正好是你的收口工作。

评注 f

黄钊“集体智能”，他只保留一个词：Fork 和 Merge。

人话他用最短的方式复述：AI 的经验可以像代码一样复制、并行、合并。这就是集体智能的机制基础。

评注 g

黄钊Dogfooding 一节，他的评注是：“仅仅在这个层面，外界跟 Anthropic 的差距，就至少 3 到 6 个月了。”

人话他说别的公司差的不是技术，是“自己先真用几个月”这个动作。光这一点，就落后半年。

你身上你们有路测和 Bug 日清，但日常办公里用自己产品的深度，值得自己打个分。

评注 h

黄钊模型够不够：官方说 Mythos 级，作者说 Opus 4.6 就够。他把两边的分歧并列放出来，没有替谁选边。

人话他在教你怎么读分歧：作者和官方口径冲突时，先把两句话并排摆，再各自找证据，别急着信任何一边。

评注 i

黄钊两个卡点：成本、安全。他把 cache 命中率、connector、自动驾驶比喻全部保留，并强调“99% 可靠不够，1% 决定落地”。

人话他给这两节最高保留度，因为这是唯一同时有机制解释和用户差评支撑的部分。

评注 j

黄钊为什么对模型公司格外重要：护城河不在记忆，在运行状态；换供应商等于换一批在职员工。

人话他把全文第二硬判断也完整保留：记忆可导出，运行状态导不走。

评注 k

黄钊护城河归谁：国内大厂游戏、海外模型层。他保留了“飞书并入豆包很合理”和“B 端比 C 端重要”的判断。

人话他接受文章的地域划分，但重点是提醒国内读者：这局里你站哪一层。

11 · 明天做什么

明天 Bug 日清会，把 AI push 三问单独提出来，当场要拍板人。

完成证据：会后有一句话的结论加一个 Owner 名字，写进产品群。
