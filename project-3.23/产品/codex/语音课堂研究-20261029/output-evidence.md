## 可落到课堂的证据

### 文本、音频与播放是不同交付

OUT-07 明确区分用户音频、ASR 文本、待播报文本、TTS 音频四种形态。AIDV 对接 Speech 云合成并缓存音频，回复文字和音频关联信息经豆包返回客户端；客户端再经独立音频通道获取和播放。`tts_audio_id` 关联云端音频流，不能解释为车辆动作或播放完成标识。云端缓存支持流式消费，不要求先有整段文件。

OUT-04 的优化目标是在文本返回时提前合成，减少客户端收到文字后再次触发合成的等待。约 100 ms 是设计预计，不是本轮或全量实测。OUT-05 明确生成音频可能未被端侧拉取使用；`TaskStarted` 可以携带零音频长度，不能用这类信令充当首个可听声音。

### 话术所有权先于声音服务

OUT-08 将简单指令固定 NLG 与复杂指令动态 NLG 分开。复杂指令等待时可先给进度；实际状态须由车端各模块回报，云端据此说明结果与失败原因。多意图含任意失败时应保留成功项、失败项和失败原因，不能仅播一句“全都完成”。这描述需求分工，不等于所有项目都按该例实现。

OUT-08 的“全部成功”结果 NLG 示例误重复了过渡句；课堂采用状态闭环的正文规则，不把示例当成允许未完成就说成功。简单指令“调用端侧 TTS 服务”与 OUT-01 的引擎选路是不同层：服务入口在端侧不自动代表声音一定由离线引擎合成。

### 选路及两个缓存层级

OUT-01：网络正常且无大波动用在线；无网、弱网/波动大、在线 ASR 本次异常或未登录豆包账号选离线；系统警告与提示强制离线，历史上下文的特殊风格要求强制在线。若特殊在线风格与无网/未登录相撞，原文未给完整优先规则，不能自行承诺某种自动兜底。范围明确不包含“在线合成中断后的离线断点续播”。

OUT-01 的“离线缓存策略”实际只缓存在线合成音频，离线合成本身不缓存；预置不超过 500、动态不超过 1500 都标暂定。动态缓存描述为首次合成并播放完成后入本地池；这不是云端每次请求的流缓存，也不是 Planner 的 KV 缓存或预请求结果。匹配正文只写待合成文本与音频文件名完全一致，未给音色、情绪、方言变化的完整复合键和失效规则；课堂把这些列为应核对的体验约束，不伪装现有实现。

### 顺序、抢占及恢复

OUT-02：解析 talk_content 中的情绪段，普通说话使用 Sami；包含“唱”的标记时聚合唱歌文本调用 S2S。OUT-04 的老技术稿提测分路是：指定情绪统一 Sami；未指定情绪时文本 S2S 用自己的音频，其他链路使用 Sami。二者属于不同层次/时期的协议描述，具体项目需确认生效版本，不合成一条所有流量都走同一供应方的规则。

OUT-05 记载同请求多模块产音频导致顺序难辨，方案包括统一生成入口或分模块编号队列。正文没有证明两套同时在线。历史空帧、标点或 FinishTask 晚发，会造成首声慢；Sami 生命周期提前关闭共用通道还可能导致 S2S 音频缺段。不能把这类故障都归成模型推理慢，也不将历史缺陷视为当前必现。

OUT-01 的 P0～P5 是提供的优先级范围，具体各业务等级由车企音频管理定义；高优可打断低优，低优在高优播报中会被拒绝，文中没有统一排队与恢复承诺。OUT-02/06 中 ComeNewPlay（不低于当前优先级的新播报）、服务挂起、第三方停止、离线车控反馈、静默和 SingleInterrupt 标不恢复；NotRejectQuery、StreamNotRefusal、MultiPersonSayStartWithDoubao 标为可恢复。可恢复不代表必须重放整段，也不是所有音频焦点丢失都能续播。

### 播放状态回流与版本冲突

OUT-09 的角色与事件定义章节要求：STARTED 在首个非空样本实际进入播放器渲染时上报；PROGRESS 记录真实播放位置；FINISHED 要已见 TaskRoundEnd 且所有声音来源的解码队列及渲染尾部耗尽；ABORTED 表示本播放实例永久结束、队列已清理。SubTTSEnd 仅结束一个声音来源，TaskRoundEnd 只证明云端边界发完，网络断开与最后网络包均不能替客户端生成 FINISHED。

技术稿明确两条回流：TaskRound 级事件维护 Input Manager 的播放运行状态；request 级进度和中断原因写历史，供打断恢复。播放事件不是新的业务诉求；模型推理结束也可能仍在播。临时人声可先暂停，最终拒识且允许时继续同一未结束对象；永久终止后再经 Event 生成回复，应登记新的播放对象。

重要冲突：OUT-09 的 `event_type` 字段表把 PROGRESS/ABORTED 划线，但职责、事件定义、兼容与实施章节仍完整要求二者。课堂写成“新方案的完整语义，字段范围仍需定版”，不声称当前接口已经支持四种。旧端旧服务、旧端新服务、新端旧服务和新端新服务行为不同；其中新端旧服务不兼容，原文要求先升级服务端。

OUT-09 设计了终态丢失后的动态超时路径，先标未确认，必要时超时推进，但不能伪装正常完成；后到事件仅补审计，不重复出队。总音频时长和已播时长能帮助防止调度卡死，仍不能证明乘客已经听完。具体超时配置及部署需确认，不能沿用一个通用固定分钟数。
