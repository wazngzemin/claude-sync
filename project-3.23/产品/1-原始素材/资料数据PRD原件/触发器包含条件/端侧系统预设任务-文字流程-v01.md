# 端侧系统预设任务：文字版业务流程

本文依据两次评审记录及上一轮审图修正整理，可作为 PRD 的流程说明。新版流程图尚未收到，本文未宣称已与新图逐节点复核。任务初始值、关闭在途卡片、恢复失败等策略的状态见配套 PRD，不将建议写成已上线能力。

## 核心边界

**任务中心负责展示任务、提交开关操作和回显结果；端侧 Trigger 侧负责本车任务启停状态的维护与运行生效。Trigger 命中条件后只发出业务事件；天气任务业务负责注册、发起并维护卡片，接收用户选择并衔接执行。DT 不参与本次端侧拉卡或本地确认。**

这里“端侧维护”说明谁对实际运行结果负责，不限定状态必须物理存储在 Trigger 进程中。“天气任务业务”是这项场景的接入与处理逻辑，不是要求新建服务，也不代表必须由另一支团队开发。

## 完整流程

1. **任务接入与列表展示：**天气任务提供方给出任务名称、说明、适用车辆及版本、对应的端侧任务和规则范围。任务中心按既有任务列表接入方式展示本车适用任务。列表说明“本车有哪些任务”，不以列表默认值替代用户已保存的开关。任务服务是否参与列表、查询和操作转发，分别确认。

2. **启动恢复与读取状态：**车辆上电或端侧服务重启后，端侧恢复本车天气任务已保存的开启／关闭选择；任务中心打开页面时查询当前状态。首次没有设置记录，按确认后的初始策略处理；读取失败不能当作“首次未设置”。原会产品口径为首次默认开启，本次还需确认迁移和异常处理。用户曾主动关闭的同一任务，不因重启、列表刷新或规则升级重新开启。

3. **用户提交开关：**用户在任务中心设置开启或关闭。任务中心将“本车哪项任务、希望开启还是关闭”交给端侧操作接收方，并进入处理中。具体通道及接收人由双方确定，不能假设已有车辆状态信号会自动传递这次操作。操作需要能与返回结果对应，避免旧结果覆盖更新的状态。

4. **端侧保存并实际生效：**端侧状态维护能力找到该任务及其关联规则，保存用户选择，并使运行采用新状态。开启表示允许该任务按原规则产生新的事件；关闭表示停止该任务的新事件，不修改全量车辆共用的场景配置，也不影响其他任务。只保存值、规则仍按旧状态运行，不能视为操作完整成功。

5. **结果回显：**端侧向任务中心返回本次处理结果及当前状态。成功后，页面显示已生效的开关；明确失败时提示原因并以重新确认的实际状态为准；未取得结果时查询确认，不把“暂时没返回”当作“肯定失败”。若用户选择为开启、但任务能力暂不可用，应明确说明暂不可用，不能把它伪装成用户主动关闭。端侧实际运行不等待页面收到回执才开始或停止。

6. **Trigger 判断并发出事件：**本车任务开启且运行条件就绪时，端侧 Trigger 读取本地车辆状态及已接入的天气、路况识别结果，按原天气规则判断条件、数据有效性、优先级和防重复。规则满足后输出本次天气任务事件，供原业务识别是哪项任务、哪次提醒、哪种场景。Trigger 不在此创建卡片、接收卡片确认或调用车辆工具。关闭或状态尚未恢复时如何阻止新事件，按本次评审确认的策略执行。

7. **天气业务注册并发起卡片：**天气任务业务接收事件，按已有场景定义确定本次建议，例如“当前路面湿滑，是否切换湿滑模式？”。业务提供既有卡片能力要求的正文、确认／取消按钮、播报内容、按钮回调和本地语音按钮绑定；如采用模板则引用已有模板，不因此新增模板平台。等待、过期和撤销规则沿用已确认的卡片规范；本次尚未确认的字段和能力不能凭文稿认定已支持。

8. **卡片展示并承接交互：**即时交互卡按现有规范排队、展示和播报。排队中不视为用户已看见；展示成功后承接手动点击及该任务已接入的本地“可见即可说”。“可见即可说”在此指把用户说出的受支持按钮表达匹配到当前卡片按钮，由接入方调用同一个原业务处理入口，不经 DT。展示失败、关闭、超时或失效时，业务按对应结果结束本次，不启动车辆动作。

9. **原业务处理本次选择：**天气业务核对选择是否属于当前有效询问、是否已经处理。有效确认进入既有执行业务；取消结束这一次建议，不关闭长期任务。重复回应只忽略，不重复提交动作，也不终止第一次已经开始的执行。任务关闭使旧卡失效的范围，按本次会签策略落实；用户确认不返回 Trigger 重跑整套天气条件。

10. **执行、结果与本次结束：**有效确认后，原执行业务按已确认的车辆执行限制请求车控，并使用现有能力确认结果。请求已收到不等于目标车辆状态已经达到；有依据才展示成功，明确失败时展示失败，尚无法确认时不伪报成功。业务按既有交互方案更新卡片或反馈结果，清理本次卡片关联；长期任务仍开启时，Trigger 继续按原规则等待，不因确认或取消而修改任务中心开关。

## 横跨流程的关闭处理

用户在任一阶段关闭长期任务，端侧首先停止新事件。已经发出的事件、排队卡和展示卡不会因此自然消失，需要原业务接收关闭通知并按评审确定的范围处理。

本次建议：尚未提交车辆动作的旧提醒取消或失效；若已注册本地语音按钮，随卡片生命周期处理；已经提交的车辆动作不承诺撤回、不自动反向车控，继续处理真实结果。确认与关闭同时发生时，以什么完成点决定是否继续执行，须由状态维护、卡片业务与执行方共同约定。此处不是新增“回 Trigger 二次判断”的流程。

## 用一个例子核对整体逻辑

用户上次关闭天气任务 → 本次上电恢复关闭 → 即使湿滑条件满足也不发新提醒 → 用户在任务中心开启 → 端侧保存并生效、页面显示开启 → 到约定检查时机，天气条件满足 → 天气业务出询问卡 → 用户取消 → 本次不切换模式，任务仍开启 → 用户回任务中心关闭 → 后续不发新提醒 → 再次重启仍保留关闭。

如果用户在卡上确认，则沿原执行业务处理动作和结果；不能把长期任务开启当作本次确认，也不能把取消一次建议当作关闭长期任务。
