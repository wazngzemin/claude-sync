# V02 平台产品与复用价值复审

审核对象：实际《PRD-系统预设任务配置平台与端云交互框架-评审完善-v02.md》，重点 1.3、4 章开头、4.2、4.13、7.5、8.1。结论：平台建设理由已明显改善，不再仅凭“四个任务”承诺节省；四任务没有被删除，端侧也没有被写成已支持云端配置发布。未发现需要推倒结构的问题。下面仅有 2 处应立即收紧正文。

## 一、应立即修正的两处

### 1. 分批实现缺少统一的首批验收边界，容易被理解为页面要求可任意延期

**原句：** 4.13：“摘要、卡片预览、缺项定位和可读详情仍在本期需求，排期可分批，但发布前必须能核对实际生效规则、文案和执行分支。”

**对照：** 4.2 写页面底部实时更新业务摘要；4.9 要求问题点击定位字段；4.10 要求完整可读详情；4.12 要求实时卡片与 TTS 预览；7.1 把这些全部列为平台交付。逻辑上可以同属本期而分批，但现在没有说明第一批少了某个 UI 功能时，究竟用什么代替，谁接受，什么时候补齐。研发有可能把结果关联也当成可后补，或测试坚持所有 UI 都完成才允许一项任务试用。

**建议仅在 4.13 补一段，不改四任务范围：**

> 本章描述本期完整交付，不等于首批必须同时上线所有展示增强。分批项须在排期会签时逐项列明完成批次和临时核验方式：完整业务摘要与文案可先由只读配置预览核验，可读时间线可先沿用能关联各阶段的现有记录入口；问题定位的交互可以分批优化，但具体错误字段与原因首批必须可见。任何一批用于真实任务运行前，许可、当前启用分支、配置一致性、可控发布、回退及真实结果关联必须可验证，不能以“详情后补”为由缺少数据。分批不取消 4.2、4.9、4.10、4.12 的本期最终验收项。

**同时在 D03 增加：** “首批最小交付、分批 UI 项的批次和临时核验方式”。这比继续笼统写“研发确认排期”更能形成范围结论。

### 2. R03 被错误归入‘证明参数复用’，会把发布保护当成效率证据

**原句：** 7.5 末段：“R01—R03只能证明同一已接入案例的参数复用，不能证明跨云端任务复用已实现。”

**问题：** R01 是规则参数复用，R02 是内容复用；R03 验证不兼容能力无法绕过校验，不证明参数变更免开发。现稿做了有价值的验收，但最后归因不准确。

**改为：**

> R01、R02 验证同一已接入案例的规则与内容变更能否复用现有运行链路；R03 验证能力边界与发布校验，不能作为节省开发的证据。上述验证均不能证明跨云端任务复用已经实现。复用用例应通过读取真实配置的运行模块完成；隔离模拟只替换环境输入和车辆动作，不得以另写演示分支替代配置消费。后续真实云端任务明确后，再比较可复用阶段与新增专属工作，决定是否继续扩充平台。

这不会增加新业务 Case，也不会要求先做完实车才能验证参数消费，但能排除“前端改文案 Demo”被当成平台价值验收。

## 三、外部核验缺口，不应再靠扩写正文‘解决’

1. **现平台能力证据。** 韩杰与平台研发需要给出当前入口或能力引用、实际支持版本、已有框架但场景未注册/确需新能力/专属开发分类；本轮文字审核不能把类别填成事实。
2. **最小接入投入。** 系统预设任务业务、Trigger、卡片、DT/VQA 和执行方需按两份工作包估算首次接入，确认哪些修改只变配置。没有估算前不能推算节省，也不能将大量业务实现归到“前端表单”一个工作包。
3. **已有能力的参数范围。** 哪些时效、频控、文案与车型范围能开放，哪些只能引用批准策略，需要能力方给出依据；PRD 的三层分类不是已经具备权限控制的证据。
4. **复用及价值判据。** R01/R02 应留配置版本、运行样本和必要代码差异说明；B类业务验证的样本和判据要在试用前约定。第二个真实云端任务未明确前，不承诺跨任务效果。

完成两处正文修正后，可以拿去进行平台范围和产品方案会签；这不等于真实平台接入、人员认领和投入回报已经被验证。
