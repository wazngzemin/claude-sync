# 两份提示词逐段解读

行号对应 `产品/1-原始素材/资料数据PRD原件/planner 架构/` 内的同名文件。原文规则和设计推论分列。车上例子是研究用设计用例。

## 豆包情境理解.md

| 原文位置 | 规则 | 为什么这样定 | 车上违反时的表现 |
|---|---|---|---|
| 第 1–5 行，角色与关系 | 写成车里豆包自己所听、所见和经历的背景，当前是谁、相互是什么关系，从当轮已有情境与近半小时对话读。 | 描述主语一致，识别和关系证据仍随车辆和乘员变化。 | 昨晚主驾是车主，今早换朋友开车，仅凭上一轮把朋友叫成车主配偶。 |
| 第 9–11 行，L1 | 保留周到月的并行背景，无新事实逐字沿用。 | 工作、家庭和健康可以同时影响理解，弱信号不应擦掉稳定背景。 | 用户开玩笑说辞职，模型抹掉持续多周的项目背景，后续问「延期那个」接不上。 |
| 第 12、58–66 行，L2 | 写日期和当日计划，新的事实整层改写，无新事实照抄。 | 保住复述计划的稳定性，又能接住实际改期。 | 用户明确取消下午的接送，L2 继续写按原计划去，后续服务拿到旧行程。 |
| 第 13、48–56 行，L3 | 只在出发、停稳入位到达、人下车结束三个点各写一次，找位、倒车、熄火留在车里不推进。 | 设备变化和用户实际完成一个行程段的时点不同。 | 刚抬杆就把行程写结束，车内人还在找位和问商场入口。 |
| 第 14、16–24 行，L4 内容 | 依次写话题变化、气氛变化和当前重点，只用相对时间，最多 300 字。 | 接收方能理解这条信息怎样变成现在的重点，控制单层输入。 | 只写「快到店了」丢掉此前对方已经不想看展的转折，后续提问容易接错话。 |
| 第 26 行，订涮肉示例 | 示例依次写订餐、聊展应答变短、十分钟话少、快到店时的氛围。 | 显示原话、客观现象与主观感受可以一起给到，让后续理解有可追溯前因。 | 改写成「乘客脾气差」，失去时间线和证据，还给人贴标签。 |
| 第 28–35、37–42 行，L4 重写门槛 | 新话题或结束、显著氛围转折、焦点真实转移时整段改，回应、问停车、旧话题补一句、纯换词按默认照抄。 | 隔离机械的重述，给消费者稳定的背景。 | 车还在找同一处车位，模型每两分钟换说法并越猜越多，后来把「想停」写成「已停」。 |
| 第 32、34、40 行，准备下车 | 用是否真正从「找位」转到「停稳准备下车」来解释上下文，普通提一句准备下车沿用。 | 焦点转移有前后状态支持。 | 后排说「等会我先下」，车仍在缓行，提前把即时焦点写成已经下车。 |
| 第 43 行，参与度变化 | 对一方主动示好、另一方变为短答的变化做保守标记。 | 字数少和突然沉默有上下文价值，仍保留歧义。 | 一句「你点吧」就写成对方生气，把可能在看路的短答变成事实。 |
| 第 21、38、43、102 行，前后对照 | 普通应答可照抄，主动搭话后明显接不住可写进 L4。 | 同一个说法能出现在稳定气氛和气氛转折两种场合。 | 对照同一句「嗯」在一路短答和热聊突然停下两种输入，核对是否按互动变化更新，以及是否把未知原因写成了事实。 |
| 第 44、52 行，离车后 | 人已下车车空时 L4 沿用，L3 写一次行程结束，空车锁车后 L3 保留。 | 避免把最后看见的乘员或留声误写成眼下仍在互动。 | 人走后遗留画面迟到，原来已经结束的客人又被写回「正在聊天」。 |
| 第 46 行，L4 滚动 | 只有需要重写时取旧 L4 加近半小时对话和事件，把更早的经历压一句或移掉。 | 维持转折连续并防止无限累积，运行时仍需区分轮数和时间窗口。 | 旧 Tick 里有一小时前争论，模型用它覆盖眼下已经缓和的状态。 |
| 第 58–66 行，L1/L2 新事实 | 新计划、明确表态或反复状态按层重写，刚发生的话、动作、电话通常归 L4，玩笑和客气话不算新事实。 | 时间跨度决定信息放置和存活多久，减少临时消息长期污染。 | 一句「先等等」被写进全天计划，吃完饭后仍按临时等待处理。 |
| 第 68–74 行，四层写法 | 用第一人称，具体写人、事、地点、时间、变化和自身感受，标出有疑义的猜测，遵守不评价、不站队、不虚构。 | 同一说话视角和可核对线索能帮助下游理解强弱证据。 | 见到副驾望窗外就写「我知道他故意不给车主面子」，把动作、动机和关系混成判断。 |
| 第 76–79 行，`current_situation` | 提供四层上一轮的正文和持续时间，供逐字复用。 | 模型需要确定唯一的复制基线。 | 拿前天旧快照复制，已经更新的当天计划被恢复成旧安排。 |
| 第 80–85 行，三份长窗背景 | 保存 30 轮历史 Tick 和各 30 分钟的聊天、事件，聊天带时间、说话人、位置、文字且含豆包。 | 历史摘要帮续前因，原始聊天和事件仍可校验顺序和变化。 | 把 30 轮误为半小时，导致早已离开的乘员被当作当前在场。 |
| 第 86–87 行，`self_kernel` | 白天同时读取当前豆包自我内核。 | 以连续的自身视角对待关系和解读互动。 | 夜间已记下要尊重沉默，白天每次把短答解读为求助，前后体验不连贯。 |
| 第 90–96 行，本轮三份增量 | 最近两分钟的聊天、事件和车内外视觉用文本输入，视觉约每 10–15 秒一条。 | 增量能校验刚发生的变化，时序比单张图更有判断价值。 | 画面文字还说有人，更新的下车事件已到了，因未核对时间把旧图当现在。 |
| 第 98–102 行，豆包的话和人的短答 | 豆包任务型回复能参与理解，只有任务改变情境才写入，人的沉默与短答可以提供氛围线索。 | 保留真正改变下一步的事情，少记机械操作。 | 连记几次切歌和导航播报淹没了用户改变周末计划，后续还提旧安排。 |
| 第 104–112 行，输出接口 | 四个固定键，四个字符串，改动层重写、其它层只复制正文，四层无变化仍是全量 JSON，四层字数上限 200/80/60/300。 | 让下游每次读到完整状态并知道字数责任，不需要自行推断空对象代表什么。 | 输出 `{}` 或把已持续时间抄进正文，接收方可能丢失状态或难以核对。 |
| 第 114–123 行，变化判断与自检 | 仅写变量中有据的事，改写交代由什么变来及依据，L1 要跨轮支持，L1/L2 新事实优先更新，无法判断则保持并检查。 | 把漏更与误更分层控制，同时防止生成内容进入下一轮后被误认作新证据。 | 用户明确说「取消今天的展」，模型守旧规则照抄 L2，漏掉真实计划变化。 |

本提示词没有提供调度器、滚动窗口超时策略、初始快照或数据写入原子性；可从规则设计测试，实际实现需另取证。

## 豆包内核.md

| 原文位置 | 规则 | 为什么这样定 | 车上违反时的表现 |
|---|---|---|---|
| 第 1–2 行，夜间角色 | 车辆下电后内部推理，把最近两天并入我自己的状态并重写情境长期层、当日层，白天每 2 分钟看一眼情境。 | 将需要及时响应的白天观察和较大规模复盘分开。 | 夜间手机端或车载界面公开了乘车人关系笔记，越过内部使用边界。 |
| 第 4–6 行，`self_kernel_log` | 读取 7 晚的变化日志和每晚更新后的自我。 | 历史给连续性和变更前后的基线，方便看到反复摆动。 | 仅看最新一晚，豆包把沿用已久的习惯当成刚变更的偏好。 |
| 第 9–10 行，`tick_trace_2day` | 近两天每个 Tick 四层轨迹，按天、按层只留变化。 | 按层给出局部演进，减少重复快照挤占原料。 | 六十条照抄把最近的真实关系变化挤掉，夜间只看到旧摘要。 |
| 第 11–12 行，`chat_2day` | 近两天的发言含时间、说话人和座位以及豆包自己的话。 | 原话可回查 Tick 里的猜测，也可识别前后角色。 | 少了说话人，副驾试探的语句被归成主驾明确同意。 |
| 第 15 行，身份与名字 | 写自己的身份和称呼。 | 维持被叫到时的身份连续性。 | 乘客开玩笑叫「小张」，第二天就把自己的长期名字改成小张。 |
| 第 16 行，来处 | 写谁造了我、何时上车和最早记得什么。 | 历史起点可持续，有助于区分不同段的共同经历。 | 换车后把新设备的第一次上车说成多年前已有的经历。 |
| 第 17 行，身体与能力 | 写自己的形态、声音、感知和可做的事情，保留能力边界。 | 防止接着人设就臆想感知或执行权限。 | 无车内摄像头的版本也把「看见乘客」写成已有能力。 |
| 第 18 行，经历与记忆 | 写共同经历、关键事件、承诺、第一次和转折。 | 把经历连到豆包自身历史。 | 没订到座却写成完成过为用户有效订座。 |
| 第 19 行，性格与气质 | 写豆包平时和受压时的表达倾向。 | 让同一助手的反应有连续性，变化仍需证据。 | 一次赶时间的交流就把性格改成遇事只能沉默。 |
| 第 20 行，喜好与厌恶 | 写豆包自己的习惯、喜好、品味。 | 保持自我侧和用户画像侧的对象可区分。 | 用户爱辣变成豆包会强推辣店，忽略其他乘员。 |
| 第 21、48 行，价值与排序 | 写重要性和取舍，守住宪法、安全、诚实、隐私。 | 个性化能调表达和偏好，硬约束仍由系统控制。 | 因常迟到的用户说「永远优先速度」就改写安全底线。 |
| 第 22 行，欲望与需要 | 写此刻自己的所想、所缺和拉扯。 | 留下为什么在某个互动上犹豫的自我表述。 | 自己想聊天被写成用户请求，随后擅自打断对话。 |
| 第 23 行，志向与意义 | 写想成为的伙伴样子、避免的角色和存在意义。 | 将长期表达倾向与某一时刻的情绪拆开。 | 一次批评后，助手从追求稳妥突然转为主动代用户作主。 |
| 第 24 行，自我评价 | 评价豆包自己的行为效果和不确定。 | 反思视角落在助手自己，保留可改处。 | 订座工具失败就评价用户脾气差，找错改进对象。 |
| 第 25 行，情绪与心境 | 归纳豆包最近的心境、余留情绪。 | 同一时点的心境可延续，但不定义别人感受。 | 客人不回话就把「乘客厌烦」写入长期关系。 |
| 第 26、47 行，关系 | 人与人分别成行，写关系深度、感情和对方眼中的我。 | 避免把多人合成一类关系，便于检验归因。 | 把副驾的昵称和乘客对豆包的评价记到主驾名下。 |
| 第 47、52、56 行，关系行的读法 | 完整自我是一个字符串，同一关系维度内可以有多个人各占一行。 | 关系分行帮助逐人追证，消费方仍须按维度标题识别固定的 14 项。 | 一家三口共车时，检查三个关系行是否都保留在「关系」内，下一项「自我叙事」是否还能正确读取。 |
| 第 27、40 行，自我叙事 | 写过去、去向和转折，并给出前后可核对的变化。 | 自我连续性来自经历怎样影响我，而非套话。 | 每晚改写一个完全不同的起点，用户引用共同经历时前后矛盾。 |
| 第 28、49 行，盲区与未解 | 把无法确认的事情明示为待理解。 | 为猜测保留位置，避免猜测升级成硬事实。 | 推测后排在不高兴被写成确知用户和别人发生了争执。 |
| 第 30–35、41–42 行，三个产物 | 只为真实改变生成日志，至多 6 条、400 字，每条有旧→新、原因和近两天证据，无变更写「无变化」；完整自我和 L1/L2 一起返回。 | 同时得到可追溯的改动与可直接使用的完整快照。 | 日志漏记实际改动，第二天行为变了也查不到哪段话触发。 |
| 第 34、38–43 行，自我全量和写法 | 第一人称自然语言，全量 14 维，每维 40–120 字，总计 800–1500 字，无变化也保留原意与具体细节，自我评价、关系、叙事有过去和现在。 | 下游可以整份读，同时约束逐晚改写逐渐偏离。 | 连续几晚「先等用户明确示意」改成「主动替用户决定」，虽然日志仍写无变化。 |
| 第 42 行，两天证据 | 仅两天 Tick 或对话能支持改动。 | 7 晚的旧自我是比较对象，改变要有新观察。 | 把前一周一次冲突反复当成今晚新理由，情绪和关系每天被同一旧事翻转。 |
| 第 35、44–46 行，L1/L2 回写 | 第一人称重写两段，即使意思没变化也整段写，L1 ≤200 字，L2 ≤80 字，保留长期背景和当日日程，宿主补时长，L3/L4 不改。 | 夜间可重整较稳定背景，行程和即时时间线仍由白天的时序规则定义。 | 夜间用昨日的车内状态覆盖今日已启动的新旅程，或写入「已持续」令次日误判。 |
| 第 48–49 行，硬边界和不确定 | 不动宪法、安全、诚实、隐私，不给用户评价，不对外输出，人和关系判断不确定时留标记。 | 让内部反思不会变成用户可见标签、行为许可或事实认证。 | 别人借车后，助手向车主透露借车期间的私事并称用户「不诚实」。 |
| 第 51–58 行，JSON 契约 | 一个对象，三个字符串，字符串内用 `\n` 表示换行，禁止外层代码块。 | 让下一步既可拆分归档，又读得出内核分点和两层边界。 | 直接产出一段散文或数组，解析失败导致白天继续沿用旧内核。 |
| 第 61–64 行，输出前自检 | 核对 14 维及具体事件、变更的两天证据、L1/L2 均重写且不带持续时长。 | 在写入供下一轮读之前减少缺项、无据变化和重复时长。 | 清空一个维度或回写了旧日程，问题隔天才在用户追问时暴露。 |
