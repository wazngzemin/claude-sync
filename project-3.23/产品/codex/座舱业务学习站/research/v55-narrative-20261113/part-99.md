## 收尾　三分钟讲给别人听

我会用主驾的一段话解释这条链路。他先叫“豆包豆包”，再说“带我去昨天那家游泳馆”，停一下，补上“附近的餐厅”。唤醒让助手进入交互，免唤醒则让用户省去喊名字。接下来，声学前端减轻噪声和车机自身播报回声的影响，并给出声音来自哪个座位。说话位置帮助理解“我的座椅”，身份信息负责区分是谁，两者各有用途。

声音随后交给 ASR，也就是自动语音识别，逐步变成文字。在线识别在云端，离线识别在车上；过程文字还会更新，最终文字才是这段声音的定稿。热词把场景里的人名、地名提供给识别，帮助写准名字；“昨天那家”没有说出名字，还得继续查经历。VAD，也就是语音活动检测，观察发声和停顿。短暂停顿先发预请求，准备判断和背景，继续收音；正式收尾后再提交完整请求。主驾补了“附近的餐厅”，目标就从泳馆变成餐厅，前半句的准备不能直接拿来执行。

完整请求交给 Planner，也叫 Director，负责理解需求、安排动作。它收到的 Context，也就是上下文，是这次实际带来的背景。“昨天那家”缺具体地点，我会先看有没有相关经历，再查用户记忆；查清泳馆，才以它为中心搜餐厅，查不清就追问。Planner 交出动作清单，工具办完交回真实结果，它再决定下一步。搜到餐厅后，要保留用户实际看到的候选和顺序。

这里我会把记忆分开讲：近期历史保留刚才的原话和列表，摘要保住较早的任务约束，短期情景整理当天经历，长期情景承接跨天经历，长期语义保存稳定事实和偏好；瞬时记忆强调最近事件的原始细节。它们负责提供背景，Planner 负责用背景办事。乘员之间的人人对话也属于背景来源：助手保持安静，记录链路按权限保存并供给后续理解，聊天本身不触发操作，一次表达也不能直接变成长期偏好。

豆包开始介绍餐厅，主驾插话“帮我把副驾座椅加热打开”。流式拒识先根据过程文字和背景判断要不要停播，让他说完；最终拒识再用完整文字判断是不是在请豆包办事。前者解决让出说话机会，后者解决接不接这条请求。接住以后，固定说法和本地模型提供简单操作候选，复杂查询交云端；仲裁决定本次采用哪份结果，避免两边重复执行。本地办不了，要与不该接话分开处理。

座椅控制要把对象明确为副驾，交给车辆执行，再核对真实结果。采用本地结果时，还要把请求、回答和执行观察回写给云端，让下一轮知道插进来的事怎样结束。回答内容交给 TTS，也就是文本转语音，云端合成音频，车端拉取并播放；组织后续回答还要知道餐厅介绍实际播到了哪里。

最后主驾说“第二个”，我会让它接回刚才展示的餐厅列表，取出原来第二家的地点，再交给导航，继续核对执行结果。中间开过座椅加热，不能把“第二个”理解成加热第二档，也不能重搜一份列表再取第二家。用户看到选对了餐厅、导航真正启动，这段请求才算办成；出错时，我就沿着声音、文字、判断、背景、工具和实际结果，找到最早交错的那一步。

### 最容易讲错的地方

- 唤醒打开交互入口，ASR 写出文字，最终接话判断接受请求，车辆或业务工具才真正执行。
- 在线与离线说明识别在哪里运行，过程与最终说明这次识别走到哪里，离线识别也能连续返回过程文字。
- 热词帮助写准用户说出的名字，“昨天那家”缺的是经历和具体地点，要靠记忆查询补齐。
- 软判停后的预请求只做准备，文字补全后要重新核对复用条件，不能拿半句话的准备结果直接办事。
- 流式停播、最终接话和端云采纳是三项决定，本地不支持也不能直接当成人人对话丢掉。
- 历史、摘要和各层记忆提供的细节不同，回写执行结果也不会自动生成长期偏好。
- 接住“第二个”需要用户实际看到的原列表及顺序，座椅插话和重新搜索都不能替换它的指代对象。
- 回答已经生成、音频已经合成和用户已经听到是三个进展，导航与车控成功还要核对真实执行结果。

| AI Launcher／车机智能桌面入口 | 展示引导、任务、推荐场景和技能，让用户发现能力并选择操作入口。 | 第十二段 |
| 入口协议 | 约定用户点击后交给谁、携带什么，以及打开页面、调用接口或提交请求的规则。 | 第十二段 |
| 模拟请求 | 将点击选择表达成供云端理解的一次用户请求，不需要用户再念出卡片文字。 | 第十二段 |
| VUI／Voice User Interface／语音用户界面 | 用户通过语音与系统交互的界面，相关需求规定卡片、上屏表现及操作。 | 第十二、十三段 |
| HMI／Human-Machine Interface／人机界面 | 用户在车机上查看内容、完成操作的界面。 | 第十二段 |
| NLG／Natural Language Generation／自然语言生成 | 将需要表达的内容组织成用户能理解的话。 | 第十三段 |
| TTS／Text-to-Speech／文本转语音 | 接收可播文字并合成音频，再交给车端播放。 | 第十三段 |
| talk_content | 提供给云端语音合成的待播文字。 | 第十三段 |
| 音频流标识 | 帮助车端找到本次合成音频流的标识。 | 第十三段 |
| 流式播放 | 车端陆续取得声音、陆续播放的方式。 | 第十三段 |
| last_talk_content | 带入上一条被打断播报的内容和位置，帮助重新组织后续回答。 | 第十三段 |
| SingleInterrupt | 单人且识别文字字数大于 2 时直接停播的一项特定停止原因。 | 第十三段 |
| 播报恢复 | 停止原因允许且新话最终拒识时，通过事件发起新请求，处理上一条未播完内容。 | 第十三段 |
| 回答融合 | 一起考虑有效新请求、未播完内容和实际结果，组织自然且不重复的新回答。 | 第十三段 |
