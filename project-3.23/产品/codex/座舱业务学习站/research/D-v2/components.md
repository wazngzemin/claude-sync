## [P-D001] Planner 输出结构（卡片5的协议深化）

- 是什么：DT一次决策给出的机器可读JSON，分别表达要不要说、说什么、表情及动作列表。
- 在哪里运行：由云端DT生成，由服务端解析后交TTS/机器人/工具；执行细节留E。
- 收到什么：四类输入及背景；输出什么：talk_or_not/talk_content/emoji_id/action_list，动作包括编号、工具、参数，PRD示例action_content与实际提示词可不同。
- 关键数字：4类输出；同轮多工具同时下发，需等反馈齐再统一说。
- 来源：raw/director-prd.txt:L147-L176、L590-L603。

补证（原研究记录 P-X001，合并到同一概念）：
- 是什么：云端 Planner 服务解析的一次模型输出对象；工程定义有五字段，产品常用四字段另需对齐。
- 在哪里运行：云端 AIDV Planner 服务；严格 JSON 由方舟模型服务约束，流式字段由服务端提取。
- 收到什么：方舟豆包模型生成的结构化字符流。
- 输出什么：talk_content 进入 TTS，emoji_id 进入表情，action_list 进入工具；另有 goal_list_update；talk_or_not 云端注释为不使用。
- 关键数字：5 字段；ActionItem 含 action_id / tool_name / params；单模型调用 60 秒超时。
- 来源：`座舱业务学习站/research/chapters/C/raw/planner-onepage.txt:L122–L144、L205–L217、L285–L291`。

## [P-X002] ReAct 图与循环分支（补证）

- 是什么：让模型每次依据新结果再决策的编排图，非独立推理模型。
- 在哪里运行：云端 AIDV，基于 cloudwego/eino。
- 收到什么：模型 JSON、动作列表、工具 observation、图状态 Round / Step。
- 输出什么：进 tools、回 llm 或 direct_return 收口；直返工具可直接结束。
- 关键数字：action_list 非空且 Step≤20 才进 tools；本轮发 TTS 最多等端侧播完 1 分钟；模型单次超时 60 秒。
- 来源：`座舱业务学习站/research/chapters/C/raw/planner-onepage.txt:L48–L87、L122–L144、L305–L307`。

## [P-D002] 任务分流与合理性判断

- 是什么：DT识别即时、多步依赖、定时、条件、持续目标，并在登记前审查可行性。
- 在哪里运行：云端DT；长期等待/触发归task_agent与任务系统。
- 收到什么：目标、时间/条件、车能力与背景；输出什么：立即动作、补事实查询、任务登记/修改/取消或解释拒绝。
- 关键数字：条件合理性5查；定时/条件均有单次和循环。多步不是独立于即时的唯一分类轴。
- 来源：raw/director-prd.txt:L682-L903。

补证（原研究记录 P-X005，合并到同一概念）：
- 是什么：Planner 判断能否即时闭环、是否要分轮、是否交任务工具的决策；“即时 / 定时 / 条件 / 持续”与“单步 / 多步 / 并行 / 串行”不是完全互斥的同一层分类。
- 在哪里运行：云端 Planner；任务登记与后续触发在任务系统。
- 收到什么：用户最终目标、先后顺序要求、当前已知事实、车况与工具能力。
- 输出什么：当前动作列表，或 task_agent 创建 / 更新任务请求；反馈回来后续轮。
- 关键数字：用户“依次开四窗”示例是四次反馈驱动的动作；宣讲没有在此给“每个动作列表最多 20 个动作”规则。
- 来源：`座舱业务学习站/research/v-lesson-20261105/director-talk.md:L186–L207`，00:28:59–00:33:38。

## [P-D003] 说话与动作协调

- 是什么：DT在同一决策中同时组织话术与动作，并在真实反馈后校正。
- 在哪里运行：云端DT；语气交TTS，表情交机器人。
- 收到什么：行动计划和反馈；输出什么：简短过渡、真实完成确认、必要失败说明。
- 关键数字：PRD表情48个；首个标点尽量早；同轮多工具齐后统一播报。
- 来源：raw/director-prd.txt:L253-L284、L286-L603；具体车型表情范围需另核。

补证（原研究记录 P-X007，合并到同一概念）：

- 在哪里运行：云端Planner生成；TTS / 机器人驱动在呈现链。
- 收到什么：用户话、办理阶段、工具结果、当前人和场景。
- 输出什么：可为空的talk_content、必要时的语气标签、可为空的emoji_id。
- 关键数字：SP列15种表情但示例出现未列ID；4个产品输出字段、25段完整示例、6条注意事项；这些是7/31快照。

## [P-X006] 车型能力边界的结构（上汽SP实物补证）

- 是什么：给Planner同时约束功能有无、语控是否支持、角色权限、车辆状态、安全条件、参数范围的规则集。
- 在哪里运行：作为云端Planner系统提示词一部分；最终车辆执行仍属下游工具。
- 收到什么：本车型配置、当前车况与音区、用户目标。
- 输出什么：可执行动作 / 合法参数，或解释限制、手动指引、部分执行、先确认。
- 关键数字：上汽快照空调15.5–30.5℃步长0.5℃、风量1–11；音量>21档或单次跨度>5先确认；主驾座椅非P禁动。

## [P-D004] 能力边界检查与工具 knowhow

- 是什么：在DT前用小模型判断这辆车能否做、需要哪些工具，knowhow是选中工具的原子能力与调用限制说明，不是动态示例。
- 在哪里运行：云端DT前的实验模块，8月产品方案未证明已上线。
- 收到什么：最近两轮非拒识问答、音区和当前请求；输出什么：reason提示拼query、req_cap选工具知识、result分类当时未用。
- 关键数字：豆包2.0 mini；70条初试；不伤DT准出98%、分类90%；10/24因性能未准出；不能按局部初试宣布普遍上线。
- 来源：raw/capability-product.txt:L54-L146。

补证（原研究记录 P-X003，合并到同一概念）：
- 是什么：Planner 前置的能力可实现性检查模型和能力说明注入，技术验证方案，并非可直接宣布上线的固定模块。
- 在哪里运行：云端 Flow / query 模块发起，Planner 等结果并填提示词。
- 收到什么：当前请求、检查提示词；原子能力 map。
- 输出什么：can_implement、reason、required_capabilities；不能实现时的系统补充提醒与 capability 背景。
- 关键数字：2.0 lite / mini 曾先后比较；9/8 lite 模型单元速度基本满足只是自测补充；检查 FunctionKey 为 aicar.ability.check。

## [P-D005] 假成功防护（目标与实际结果核对）

- 是什么：将用户目标、DT下发指令和工具真实结果对齐，防止只看到“成功”就宣称原任务完成。
- 在哪里运行：DT云端读回执决策；工具侧提供具体事实，执行验收归E。
- 收到什么：执行指令、实际结果及warning；输出什么：真实确认、纠正/替代动作或澄清。
- 关键数字：假成功分析23个case、36个多标签；8月方案每条回执附一次核对提醒。
- 来源：raw/fake-success.txt:L4-L79、L438-L758；raw/fake-success-fix.txt:L25-L47。

## [P-D007] JSON输出保障

- 是什么：模型服务生成时的严格结构约束加服务端字段顺序/历史写入处理，不是只在SP里说“输出JSON”。
- 在哪里运行：云端方舟模型调用与Planner服务。
- 收到什么：schema、模型输出流；输出什么：字段/层级正确且按指定顺序的JSON，供TTS和工具解析。
- 关键数字：strict=true，顶层4字段必填，动作3字段必填；38/4000异常促成修复；示例单调用60秒。
- 来源：raw/json-guard.txt:L5-L147；schema允许params附加字段，不能因此保证动作正确。

## [P-TE004] DT 基础评测与准出体系

- 是什么：从任务理解、上下文推理、话术、风险和性能共同检查 Planner 是否达到可交付标准的评测流程。
- 在哪里运行：离线模型评测、人工校准及实车测试侧，非 Planner 在线决策模块。
- 收到什么：用户/建议、背景、动作、工具反馈与完整话术；性能还要真实调用和音频时间。
- 输出什么：0—4 分及错误/冗余/缺失分类，首 token、首工具、闭环耗时和 token 消耗；已补读11月16日飞书现行v0.2原表，14项阈值见facts F-TE092—105。
- 关键数字：4超预期、3符合、2勉强、1极差、0失败/风险；现表功能6项阈值95/92/90/90/92/90%，安全4项95%且无0/1分，交互4项92/92/95/85%。
- 来源：`chapters/D/raw/eval-guide.txt:4-331`。
- 原表补证：eval-dimensions-live-20261116.json，sheet YWVS0m!C2:F15；原始指南和现表分开，0—4分的3/4分占比才是准出可用率。
