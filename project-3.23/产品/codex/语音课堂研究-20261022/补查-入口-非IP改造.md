二、域名拆分考虑
当前 wss.volcvehicle.com 同时承载三类服务：
DPFM：车载客户端直接调用，我们仅提供云服务接口。
AIDV：智能座舱 2.0 豆包链路的语音服务。
Gateway：智能座舱 2.0 自建链路的语音服务。
三类服务的形态和可控程度不同，共用同一域名会产生耦合。尤其在 DNS 调度时，针对其中一个场景的调整会同步影响另外两个场景。因此，除非存在必须共用域名的约束，建议按场景拆分域名。

网关同学建议拆分新申请域名

文本链路保留：端侧文本 → Gateway →  请求 AIDV (预请求) -> 正式请求aidv

TTS 接口
目前 TTS 接口仅承载翻译客户端的文本转语音请求，无其他业务。
当前主线方案：端侧文本 → AIDV TTS 接口 → SAMI → 合成音频 → 下发端侧
改造方案：将 TTS 能力迁移至 Gateway，由 Gateway 调用火山引擎 TTS。Gateway 提供 WebSocket 接口并接入 Frontier，与主链路共用域名，通过独立流下发音频。


待确认事项
当前主链路的 TTS 音频由服务端直接下发；AIDV 通过 ID 拉取音频，因此存在 cancel 操作。需确认自建链路是否也需要支持 cancelTTS。

账号同步
车辆上电或用户注册声纹后，通过同步接口将账号信息同步至云端，该请求走 TLB。
改造方案：Gateway 接口已就绪，仅需将原有接口适配至 Gateway。

主动推荐
豆包链路：触发器 → AIDV 推送接口 → 端侧 → 豆包 → AIDV。

方案一 （推荐）
触发器通过 RPC 调用 AIDV；AIDV 使用 Frontier Broker 模式向客户端下发主动推荐触发消息。客户端收到后，通过主链路将请求回传 Gateway；Gateway 调用 AIDV，并通过主链路向客户端下发处理结果。


方案二
触发器通过 RPC 调用 Gateway。Gateway 定位客户端对应的主链路连接；如连接位于其他实例，则先跨实例转发。连接实例构造用户请求并调用 AIDV，结果再通过主链路下发客户端。
