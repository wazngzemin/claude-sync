# 途经点删除动态示例｜Fornax 0.0.276 实测

- 测试平台：Fornax `Planner-上汽dna版本`
- 版本：`0.0.276`
- 测试日期：2026-08-06
- Badcase：导航途中说“把加油站删了吧，不去了”后，没有重新算路，画布消失且地图仍显示旧路线。

## 结论

图中原示例能够让唯一途经点场景正确调用 `route_planning`，但在路线中存在两个加油站时只回复“两个都删吗”，没有逐个播报候选名称，属于部分通过。

收紧歧义分支后复测通过：

- 唯一匹配：调用 `route_planning`，参数为“删除途经点中国石化龙吴路加油站”。
- 多个匹配：播报“中国石化龙吴路加油站、中国石油龙华加油站”，询问用户删哪一个，`action_list=[]`。
- 候选尚未加入路线：只取消待选，不调用 `route_planning`。
- 用户澄清“龙吴路那个”：调用 `route_planning` 删除对应途经点。
- 当前无导航：不调用工具，说明没有可删除的途经点。
- `route_planning` 返回新路线成功：播报剩余途经点、剩余距离和预计到达时间，不重复发起导航。

当前版本在“明确给出已生效途经点”的环境下，即使不注入动态示例，原话也能正确调用 `route_planning`。因此本次结果证明的是示例没有破坏主路径，并补强了歧义、待选候选和工具回传闭环；不能仅凭 Fornax 判定端侧画布和地图路线已经真正更新。

## 建议最终动态示例

**Query**

`把加油站删了吧，不去了`

**决策分析**

导航途中删除途经点：先结合当前已生效途经点判断。只有一个匹配项时，改写为“删除途经点XX”调用route_planning重新算路，不能只口头说已删除；有多个同类途经点或工具返回多个子poi时，必须逐个播报候选的完整名称和可区分信息，再问用户具体删哪一个，action_list保持为空，禁止只问“两个都删吗”或笼统问“删哪个”；用户选定后再调用route_planning删除所选途经点并重新算路。子poi未澄清、新路线未算出前，不调用navi_basic_control、不下发开始导航或导航意图；route_planning返回新路线成功后，再播报剩余途经点、预计时间等关键信息。若加油站仍是待选候选、尚未加入路线，则只取消待选，不调用route_planning。

## 验证边界

Fornax 本次验证的是 Planner 是否生成正确动作和话术。原 Badcase 中“画布是否消失、系统地图是否真的换成新路线”属于 `route_planning` 下游及端侧地图执行结果，还需在真实工具链或车端环境补一次端到端验证。
