P0-7 需求明细（v3 细化版，逐条可开发可验收）

1）数据模型：新增「车企」字段

项明细
字段定义字段名 oem（车企），枚举值：saic（上汽）/ seres（赛力斯）；枚举在后台可配置扩展（后续新车型项目接入时加值，不改代码）
必填与默认必填、不允许为空。新增弹窗中默认值 = 当前列表页筛选的车企（用户在上汽视图点新增，默认就是上汽，减少手选错误）
唯一性约束由「环境 + query」升级为「车企 + 环境 + query」联合唯一。这是防重复的最后一道兜底：即使查重被"仍要新增"放过，同车企同环境下 query 完全相同的第二条在数据库层直接拒绝
ID 规则ID 保持全局唯一递增，不按车企分段。跨车企复制产生新 ID（见第 5 条），原 ID 不变——Meego 单上已贴的 ID 全部不受影响
举例现网 ID 1024（query=打开天窗，上汽）与复制后的 ID 2001（query=打开天窗，赛力斯）可以同时存在；但在上汽池再建一条 query=打开天窗 会被唯一键拒绝

2）存量迁移：1250+ 条回填「车企=上汽」

项明细
迁移范围现网全部存量（列表最大 ID 1250，全部为上汽 D6X/家越07 项目产出，创建人均为 wangzemin.cxz 等上汽项目成员），无例外
迁移方式低峰期执行（建议晚上 21 点后），执行期间平台锁写（新增/编辑/删除暂不可用，页面挂提示条）；执行前整表备份，失败可整体回滚
迁移后校验跑校验脚本：count(oem 为空) 必须 = 0；count(总数) 与迁移前一致；抽 20 条人工核对字段值正确。校验通过才放开写入
迁移后默认视图所有现有用户进入列表页默认带「车企=上汽」筛选（当前全部用户都属于上汽项目），视觉上看不到任何变化，无感知迁移

3）平台 UI：三处加车企维度

位置明细
列表页筛选区筛选顺序固定为：车企 → 环境 → Query 关键词（车企是最外层维度，先看哪家的车，再看哪个环境）。车企下拉选项：上汽 / 赛力斯 / 全部；「全部」视图主要给审核和管理用，普通添加默认不带全部
列表列新增「车企」列，放在 ID 列之后；列宽要窄（就两三个字），别把决策分析列挤得更窄
新增/编辑弹窗在现网三字段（Query/决策分析/环境）基础上，「车企」下拉加在环境之前；默认值取当前列表筛选车企；用户手动切换车企时，弹 toast 提示"切换后查重范围随之切换为该车企"
编辑限制已上线条目的车企字段不允许直接改（改车企=搬到另一个池，必须走"复制到 XX"流程重新过审，防止有人手滑把上汽示例挪进赛力斯池直接生效）；草稿态条目可改车企

4）检索注入侧过滤（关键依赖，不做 = 平台侧白做）

项明细
接口改造召回服务接口增加必填参数 oem；Planner SP 组装侧把「当前车型 → 车企」的映射结果传入。车型→车企映射：D6X、家越07 → saic；赛力斯车型 → seres。映射表建议放配置平台维护，新增车型不改代码
过滤逻辑召回时先硬过滤 where oem = 当前车企 and env = prod and status = 已上线，再在过滤后的集合内做语义相似度排序取 top3。过滤必须发生在相似度计算之前，不能先召回 top3 再过滤（池子小的情况下会召回不足 3 条）
空池行为某车企池为空或无召回时，{{scenario_sample}} 注入为空串，明确禁止 fallback 到其他车企的池——fallback 就是污染源，宁可没有示例，不能注错示例
配合方与排期需要检索侧配合改召回服务。两侧解耦：平台侧先落字段和回填（对线上零影响，因为现网全是上汽，过滤条件加上后结果不变）；检索侧后接过滤参数。时间窗内赛力斯池为空，无风险
验收方式用赛力斯车型标识构造请求，断言召回结果中不含任何 oem=saic 的条目；再用上汽标识回归，确认现有 top3 召回结果与改造前完全一致（零回归）

5）跨车企复制

项明细
入口列表页勾选（支持多选）→ 顶部「复制到赛力斯」按钮（目标车企按当前枚举动态生成）；复制是批量操作
复制规则生成新条目：新车企、新 ID、初始状态=草稿（不直接上线！复制过来的内容必须按目标车企能力边界核对后走审核流生效）；决策分析/其他说明原样带过去，编辑页顶部挂醒目提示"本条复制自上汽 ID xxxx，请按本车企能力边界核对后再提交"
两类示例区别对待①通用类（可直接复制）：与车型能力无关的决策模式，如"导航去XX地方必须保留导航动作词""导航静音不改写成音量=0""地点搜索 poi_search/info_search 工具选择"；②能力边界类（复制后必须改写）：写死车型能力的，如"本车为实体天窗不支持语音""尾门高度最低 40%""车速>80 开窗只开 10%"——80 这个阈值、40% 这个下限在赛力斯车型上是否成立必须逐条确认，不能带过去就用
复制后独立两个池的条目完全独立：改上汽的不影响赛力斯的，反之亦然；不做"联动同步"（联动=把错误传播自动化）
日志与追溯复制动作记操作日志（谁、何时、从哪些 ID 复制到哪些新 ID）；新条目的其他说明里自动追加来源 ID，双向可追溯

6）查重范围收窄到「同车企同环境」

项明细
查重 keyP0-1 的相似度查重只在「同车企 + 同环境」范围内执行。举例：上汽池已有"打开天窗"，在赛力斯池新建"打开天窗"不弹相似拦截——两个车企本来就允许同 query 不同答案
跨车企参考（加分项）查重不拦，但可以弱提示：在新增页异步展示"其他车企存在相似 query"的信息区（仅展示、可点开抄内容、不强制三选一）。赛力斯建库初期大量条目可以从上汽抄思路，这个提示能省一半时间
批量导入同理Excel 里每一行按行内的车企值确定该行的查重范围；一份 Excel 允许混合两个车企的行，一次导入分头查重

7）批量导入 / 导出联动

项明细
标准模板「车企」加为模板第一列，必填；列值必须在枚举内（填"长安"等未注册值 → 该行报错并列出当前可用枚举值）
导入校验顺序格式校验（列全不全）→ 车企枚举校验 → 逐行按（车企+环境）查重 → 出校验报告。每行报告里带该行车企值，方便混合导入时对数
导出导出弹窗支持按车企筛选（上汽/赛力斯/全部）；导全量时文件内带车企列——红涛做全量回归时可按车企拆分测试集，上汽的回归集和赛力斯的回归集互不污染
验收标准：①同一 query（如"打开天窗"）可在上汽、赛力斯各建一条不同决策分析，互不判重；同车企下同 query 第二条被唯一键拒绝；②用赛力斯车型标识请求检索，召回结果不含车企=上汽的示例；用上汽标识回归，top3 与改造前完全一致；③存量 1250+ 条全部带「车企=上汽」，count(空值)=0；④从上汽复制 10 条到赛力斯：全部进草稿区、带来源 ID 提示、上线前必须过审核；⑤已上线条目修改车企字段被禁止并给出提示。

八、边界场景与异常处理

  1. 一条新 query 同时相似多条旧条目 → 全部列出，逐条三选一；
  2. 批量导入含相似/报错行 → 该行拦截或跳过，不阻塞其余行；
  3. 更新操作改完 query 后与其他条目撞了 → 同样触发查重；
  4. 删除线上生效中条目 → 校验报告标红，审核时重点确认；
  5. 审核期间条目被他人修改 → 提示审核人"内容已变更，请刷新再审"；
  6. 草稿超 7 天未审 → 列表标黄提醒；
  7. 回滚时条目在导入后被人工单独改过 → 跳过该条目并在结果中提示；
  8. 模板列顺序错/列缺失 → 整单报错并指明问题列，不静默容错；
  9. 两个车企存在同 query 不同决策分析的条目 → 正常共存，查重不跨车企；
  10. 批量导入的车企列填了未注册的枚举值（如"长安"） → 该行报错并提示可用枚举；
  11. 车企字段回填迁移期间有人正在添加 → 迁移脚本先锁写或低峰执行，迁移后校验无空值再放开。

九、验收标准汇总

#验收用例预期
1添加与库内语义相近的 query（"打开天窗" vs "帮我开一下天窗"）检出相似并强制三选一
2批量导入 10 条（含 3 条重复、1 条 ID 报错）报告准确标出，6 条正常进草稿
3批量导入后未经审核线上检索不到，不生效
4审核批量通过 / 单条驳回带理由通过后生效；驳回理由导入人可见
5模板批量更新 5 条、删除 5 条结果正确，ID 错误行有明确报错
6导出全量条数与列表一致，字段完整无乱码
7批次回滚（含 1 条导入后被人工修改）新增删除、覆盖还原；人工改过的跳过并提示
8批量导入条目添加人字段显示真实操作人，无 system
9同 query（"打开天窗"）分别建于上汽、赛力斯，决策分析不同两条共存，互不判重，切换车企筛选互不可见
10以赛力斯车型标识请求检索注入召回结果不含车企=上汽的示例（检索侧过滤生效）
11存量数据迁移完成后全量校验1250+ 条车企字段=上汽，无空值

十、配合 SOP（非平台功能，8.5 会上已定）

  1. 单条 Meego bug：平台直接添加 → Meego 单贴动态示例 ID + 自测结果 → 测试复测关单前核查，缺信息打回；
  2. 批量修复：Excel 标准模板集中维护 → 群内过一遍 → 泽民/晓朝审核 → 批量导入；
  3. 分工原则：按问题分类/功能模块认领（不按 query 均分），避免同类问题多人重复添加。
