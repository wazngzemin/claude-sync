# Review 共识材料 \- 身份识别、记忆隐私原则（终版）

<div class="callout">

**使用 豆包 AI 能力的前提：**

1. **OEM 账号已绑定豆包账号**

2. **车辆已完成豆包账号登录**

</div>



### 1、背景及目标

长期记忆是AI汽车构建像人，懂人，实现个性化服务的最关键模块，但相对于其他终端单人使用场景，座舱的空间属性带来的多人场景让构建实际乘车人身份极为重要。

所以身份 \&amp; 记忆模块的目标是构建 实际乘车人身份、相关人员关系，以及做好相应的记忆隐私权限。



### 2、身份识别

<div class="callout">

**核心原则：**

1. **使用 豆包 AI 能力的前提：AI汽车 绑定并登录豆包账号**

    - **车主：****必选 **绑定豆包账号，**可选**** **生物信息录入，时机：车辆激活流程（不可跳过）

    - **授权用户：****可选**** **绑定豆包账号，**可选**** **生物信息录入，时机：车辆绑定流程（可跳过），后续可在车机/手机设置页面绑定

        - **产品建议：授权用户必选绑定，强化豆包IP，是否为其他合作方提供****可选方案****可内部进一步讨论**

            - 上汽侧：已确认将要求 授权用户也必须绑定豆包账号

    - **其他用户：**根据车企设计进行调整（游客账户可不绑定豆包账号，限制使用，参考2\.4）



2. **车辆豆包账号登录态：**

    1. **车上无豆包账号登录时：无法使用豆包AI功能、无法录入生物信息**

    2. **车上有豆包账号登录时：**

        1. **step1：车辆有豆包账号登录**

            1. 即车上用户可以使用 豆包AI 功能（记忆除外）

        2. **step2：用户通过设置页面录入对应生物信息（faceid等）**

            1. 即生成 Occupant ID（即占位人的 ID）

            2. 车上用户可以使用豆包 AI 功能（记忆包含在内，记忆范围可进一步根据车企需求设置）

</div>



会议纪要：

车主可选录入生物信息，通过showcase的形式：吸引用户完成录入，并充分告知隐私保护

#### 3\.1 单人场景：基础场景

- 说明：**有且仅 **有 **账号实际使用者（通过faceid校验）**在车上，记忆生成、检索、使用等均不受任何限制

- **举例：同时满足如下条件**

    1. 车机上登录**白宇的车企账号**（对应白宇的豆包账号）

    2. 此账号已录入 faceid，用户上车时通过了 faceid 校验，此时**白宇本人在车上**

    3. **车上无其他人**（通过端状态感知）

- 记忆生成：（用户授权后）无限制

- 记忆使用：（用户授权后）可使用豆包APP、电脑端生成的记忆信息

    - todo：豆包APP侧明确输出的记忆维度、清单



#### 3\.2 多人场景：复杂场景

<div class="callout">

- **记忆生效前提**：

    1. 身份识别：

        1. **已登录豆包账号的****本人在场****（即通过 faceid 校验），不区分位置，记忆模块****工作**

        2. **如已登录豆包账号的****本人不在场****，不区分位置，则记忆模块****不工作**

    2. 确认位置：通过 Face ID 与声纹 ID 校验，确认不同位置对应的人是谁（Occupant ID）

        1. 举例：

            1. 主驾明骏（Occupant ID 1），副驾嘉锋（Occupant ID 2）

            2. 主驾明骏（Occupant ID 1），副驾嘉锋（Occupant ID 2），后排左仁杰（Occupant ID 3）

            3. 主驾明骏（Occupant ID 1），副驾嘉锋（Occupant ID 2），后排左仁杰（Occupant ID 3），后排右**未知用户**

    3. 记忆生成：与 Occupant ID 对应关联，并进一步与登录的豆包账号关联

    4. 记忆使用：

        1. 单人：生成、输出均无限制，输出可使用豆包APP、电脑端记忆

        2. 多人：生成无限制，输出不可使用豆包APP、电脑端记忆

        3. 其他：根据车企需求确定

            1. 举例1：车企如希望孩子记忆能够跨登录账号共享，可在设置中增加选择

            2. 举例2：车企如希望增加家庭模式等，可在设置中增加选择（参考上方示例如）

</div>

- **记忆生成示例：**

    1. 车辆已登录「张航」的OEM账号；

    2. 车辆已登录「张航」的OEM账号绑定的豆包账号；

    3. 已校验完成「张航」的faceid，确认张航本人在车上（不论是否在主驾）；

    **此时，记忆模块即可工作**

    <div class="callout">

    - 场景1：车上有张航、明骏、嘉锋三个人：

        - 此时因为**张航本人在场**，记忆模块工作，示例如下：

            - 记忆生成：根据每个Occupant ID进行生成，如：

                - 明骏：有一只5岁的博美犬

                - 嘉锋：有一只3岁的布偶猫

                - 张航：张航的同事明骏有一只5岁的博美犬，朋友嘉锋有一只3岁的布偶猫

            - 记忆使用：**仅使用车端生成记忆，不包含豆包APP、电脑端输入记忆**

                - 原因：手机端、电脑端用户信息较车端较为私密，多人场景不可提及

                - 如：用户可能在手机端询问过自己家庭关系怎么处理、得了腮腺炎等病该怎么治，在多人场景不因提及，暂定一刀切方案，降低用户理解成本及隐私泄漏风险

    </div>

    

    <div class="callout">

    - 场景2：**张航下车了**，主驾上来一个「新用户」，车上有「新用户」、明骏、嘉锋三个人：

        - 此时因为车辆登录「张航的」豆包账号，但是**张航本人不在场**：

            - 记忆生成、使用均不工作

    </div>

**登录账号非首次切换，为faceid 无感切换**

<table><tbody>
<tr>
<td>

**对比维度**

</td>
<td>

**以账号为维度管理**

**（乘客从属于账号，换账号需重新录入 FaceID）**

</td>
<td>

**以车辆为维度管理**

**（所有人可见，FaceID 共享）**



</td>
</tr>
<tr>
<td>

**隐私安全**

</td>
<td>

1. FaceID 与账号强绑定，仅账号持有者可查看、管理自身生物信息

2. 切换账号需重新录入 / 验证，避免临时访客生物信息被车主或其他账号获取

3. 个人关联数据（导航地址、座椅偏好等）随账号隔离，无泄露风险

</td>
<td>

1. 违背数据最小化原则

2. FaceID 及所有乘客数据全车可见，无隐私隔离

3. 临时访客录入的 FaceID 会被**其他使用者**看到，存在生物信息泄露隐患



例：

临时用车 或 租车场景，如用车人最后一次离开车辆时未删除 **FaceID，其他人均可见则存在隐私问题**

</td>
</tr>
<tr>
<td>

**个性化体验**

</td>
<td>

1. 每个账号下的 FaceID 对应其专属记忆

2. 切换账号后配置完全独立，不会因他人数据残留导致体验混乱

3. 结合 AI 记忆能力，可基于账号长期习惯持续优化交互策略



例：

白宇在张航开车时候喜欢听民谣，在左晨开车时喜欢听汪苏泷，更加细致颗粒度的画像

</td>
<td>

1. 系统无法精准匹配个人习惯，交互准确率低（相当于一个人在一辆车上，只有一种记忆）

</td>
