# 模拟触发器配置平台产品经理评审

审阅范围：已读 `source.txt` 全文 0001—0652 行及原稿图 3（`white-3.png`）。本评审只代表模拟平台产品经理视角；外链 Demo 已在正文 0133—0134 行提供，本次未审，以下不足指当前已读正文和图 3 的规格，不断言 Demo 中没有对应设计。

总体判断：图 3 已明确在现有场景管理和同一个新建/编辑页上做五组扩展，也明确发布、消费者和运行记录，方向足以开展方案讨论。进入开发评审前，还需要把四个 Case 翻译为这些配置的实际填写方式，并明确哪些是能力接入、哪些可由产品编辑。优先讨论以下 4 项。

## 1. 五组配置已经有，但四个 Case 尚未形成可直接验收的映射，天气动作还存在冲突

- 原文位置：0126—0134、图 3 五组配置；天气 0163—0170、0246—0266；儿童锁 0368—0385；充电口盖 0473—0490；后视镜 0633—0647。
- 已有内容：基本信息、条件、业务处理、交互与后续动作、运行策略均已列明；四个 Case 有进入/退出规则；天气已按雨、雪、雾拆分建议。
- 不足：没有展示每个子场景如何落入五组字段，以及一个任务关联几个场景、进入与退出是否各建一条规则。天气旧表仍写“切雪地模式 + 开后雾灯”，与分场景动作冲突；儿童锁的静默/询问分支和后视镜的定时关闭，要求交互区可跳过、进入与退出动作可分别配置，图中尚未明确这些表达方式。
- 评审提问：“能否拿雨天、儿童锁静默、充电识别、洗车后加热各填一条完整配置，说明五个区分别填什么、哪些区可空？天气三个子场景和后视镜三个子场景，是同一任务下多条配置，还是一条配置里多分支？发布时以哪一版天气动作表为准？”
- 业务影响：不同开发人员可能把同一需求实现成多套配置结构；误将雨雾雪动作合并执行，或让静默任务被强制绑定确认卡片。
- 可粘贴补文：
  > 四项任务在发布前均提供“任务—子场景—五组配置”的完整填写样例。每条配置明确任务关联、进入事件及条件、判断能力及结果分支、交互方式与执行/回读动作、退出和频控策略。静默执行允许跳过卡片确认，但仍必须配置执行前复核和结果回读。天气任务按雨、雪、雾分别绑定目标动作，不配置“雪地模式与后雾灯统一执行”；进入和退出动作分别定义。子场景使用多条场景配置或单条多分支，由平台数据结构确认后统一落表。
- 需实证确认：现平台是否支持同一任务关联多场景、动作分支、跳过交互、延时/退出动作；外链 Demo 是否已有完整样例。不能仅凭本稿确认这些能力现已具备。

## 2. 能力库方向明确，但“研发接入什么”和“产品能改什么”还需拆开

- 原文位置：0008—0027、0128—0130；图 3 的条件区和业务处理区；天气 0143—0174；儿童锁 0327—0330；后视镜 0517—0548、0607—0618。
- 已有内容：已说明组合已接入能力、端云分别管理支持范围、未接入能力不可发布；后视镜信号和动作明确标注待确认。
- 不足：原子能力表把信号、变化事件、判断、卡片和动作并列，但没有统一说明每类能力必须接入的内容及可编辑参数。例如“连续 3 次”“温差窗口”“VLM 猫狗字段”“DT 判断”分别由谁计算、是否已有实现，不能仅靠填一个字段得到能力。已列 ID 不等于对应车型/版本已可用。
- 评审提问：“产品在条件区选一个能力后，能改阈值、连续次数和时间窗口中的哪些项？新增温差窗口或宠物识别，是接入新能力，还是已有算子组合？能力库如何展示车型、端云、版本和支持状态？”
- 业务影响：配置人员可能把尚需研发实现的判断当作已可配置；支持范围不匹配的配置即使字段齐全，也无法在目标车辆运行。
- 可粘贴补文：
  > 能力接入与任务配置分开管理。研发接入时提供能力 ID、类别、端云位置、适用车型/版本、输入输出及未知值、时效规则、支持的运算方式或动作、参数类型与可填范围、承接方和验证状态；配置页只展示已接入能力允许编辑的参数。新增信号、识别结果、计算方式或车控动作若不在已接入范围内，先完成能力接入与验证，再开放任务配置。待确认字段可保存为草稿，不可据此发布。
- 需实证确认：原子能力表/现平台真实注册规格；已列 ID 的有效性和支持范围；持续时间、次数防抖、时间窗口、端侧计时分别在哪个模块实现。

## 3. 发布检查已有原则，需要落实到能阻断错误发布的规则和生效回执

- 原文位置：0130“未完成接入…不可…发布”；图 3 右侧“检查字段、能力支持和业务承接”“发布版本并确认生效”；充电 0479—0481；后视镜 0636—0647；天气 0267—0278。
- 已有内容：已有配置检查、缺项定位回填、版本发布和确认生效，不能评价为没有发布机制。
- 不足：尚未明确哪些错误阻断发布、如何检查跨字段关系，以及“确认生效”来自哪些消费者。充电确认时机和部分退出策略仍待定，天气存在联调替代信号，这些都不能仅以字段非空校验通过。端侧现阶段需研发实现，也需要说明云端配置发布是否依赖相应端版本。
- 评审提问：“发布校验会不会拦住未定的确认时机、未接入的回读、联调替代信号以及不支持该动作的端版本？Trigger 已加载而承接业务还没加载时，列表展示什么状态，是否允许接收新触发？”
- 业务影响：后台显示发布成功但链路只生效一半；联调条件或未确定策略进入正式任务，导致误触发、无动作或无法结束。
- 可粘贴补文：
  > 发布前阻断以下配置：必填项或业务决策未定；能力在目标车型/版本未接入；判断结果缺少处理分支；需确认的动作未配置有效确认及过期处理；执行动作缺少复核或回读；正式配置仍引用联调替代信号。发布记录区分“配置已发布”和“所需消费者已生效”，展示各消费者版本、加载结果与失败原因；所需消费者未全部就绪时，不标记为全部生效。端侧能力依赖对应端版本时，同时校验版本兼容范围。
- 需实证确认：现发布/灰度/回滚机制、消费者回执、配置版本传递机制；哪些规则可自动校验、哪些需业务会签。以上是建议校验规格，不是已验证能力。

## 4. 图中已区分 Trigger 与业务消费，但现有字段基线和分工仍需一张对照表固化

- 原文位置：0008—0009、0057—0063、0084—0089、0128—0134；图 3 中“保留车型版本”“保留条件组及与或关系”“保留次数间隔”和“Trigger 读规则，业务读后续处理”。
- 已有内容：已明示复用场景列表/编辑入口、部分现有字段和 Trigger/原业务边界；原业务负责卡片注册与回调，端侧暂按任务开发。
- 不足：图把保留、新增和扩展写得清楚，但本次材料尚未提供现平台字段截图或字段结构来证明基线；五组配置具体由谁读取执行也没有逐组落表。“交互与后续动作可配置”究竟是原业务读取参数、调用预注册能力，还是配置可以直接下发端侧，需要与“端云统一配置与下发作为后续建设项”对齐。
- 评审提问：“能否对着现有编辑页逐项标注原字段、新字段和暂不支持项，再标明保存后谁读取？卡片/车控配置是传给已有业务实现的参数，还是本期要增加解释执行配置的能力？端侧配置本期怎样落地？”
- 业务影响：容易把编辑页设计误当成运行能力已完成，前后端做出字段却无人消费；也可能意外扩大成端云统一配置下发项目。
- 可粘贴补文：
  > 本期以现有场景编辑页为基线，附字段改造表，逐项标注“保留/修改/新增”、字段含义、编辑约束、保存位置、消费模块及生效方式。Trigger 消费任务许可与触发规则；承接业务消费进一步判断、交互与结果策略，并调用已接入能力；卡片组件按原业务提供的参数展示并回传生命周期。端侧动作及复核本期仍由对应业务实现，平台仅引用已接入且可承接的能力，不将端云统一配置下发默认为本期完成项。
- 需实证确认：真实平台当前字段、动作配置能力及 API/配置结构；原业务是否能读取新增参数；Demo 是否已覆盖对应设计。本次未审外链 Demo，因此不能断言字段改造表或交互设计在全部材料中缺失。
