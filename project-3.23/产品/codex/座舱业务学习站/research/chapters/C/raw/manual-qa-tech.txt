现有方案中，查询车书知识作为一个独立的工具，被 director 作为下游工具调用。
本期目标是把常用的车书知识从原先的独立车书工具，前置到 director 之前的 context 初筛步骤。如果车书工具是唯一一个工具调用，RPC 请求的耗时就会被拿掉；而如果车书知识没有成为 Context 最慢的粗筛，那这段成本会被并发隐藏。

执行器获取车书 Agent 配置，然后调用 rewrite_query 插件。插件返回改写 query，用于后续 VikingDB 检索。
检索
使用改写的 query 作为检索 query。
检索时根据需求带上租户/车辆过滤条件：channel+channel_app_id或vehicle_id。
如果车书存在车型或版本差异，则追加过滤条件vehicle_type。
召回
利用 query 和过滤条件进行向量检索，召回 TOP3。
对召回结果使用 score_threshold 做低置信过滤，低于阈值的结果不注入 Director。
如果过滤后无结果，则 knowledge 变量为空，Director 不使用车书知识进行推理。
