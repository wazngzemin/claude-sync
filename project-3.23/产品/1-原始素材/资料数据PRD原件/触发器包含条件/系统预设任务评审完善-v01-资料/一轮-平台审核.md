# 配置平台与前端产品审核

审核范围：用户上传 PRD 的“系统预设任务整体配置”、四个案例中对配置表达的要求；参考 v07 第 4 章的细化写法。v07 仅作为建议方案，不是现平台已实现的证据。本轮不访问、不修改真实平台。

## 一、12 项需要补入正式 PRD 的关键问题

| 序号 | 原稿依据与问题 | 研发会问什么 | 建议写入正文的具体要求 | 确认属性 |
|---|---|---|---|---|
| 1 | 原稿“配置平台改造范围与页面落位”只有图，缺逐页操作；“本期覆盖四项”又与“端侧当前按需求开发”并列 | 四个任务都要在这次平台上配置运行吗？前端要做几个页面？ | 本期在现有云端场景管理的列表、新建/编辑、触发记录和详情页扩展；端侧案例用于核对公共任务规格和能力缺口，不因此承诺端侧配置发布。端侧不可执行项显示“仅规格/待接入”，禁止伪装成可发布任务。明确本轮端云发布范围的待决项。 | 页面扩展是本次需求；最终端侧平台范围待确认 |
| 2 | 原稿把“用户开启一次”与“平台配置任务许可”写在同一段，未说明哪个界面改什么状态 | 配置页上的“开启”是发布场景还是替用户打开任务？ | 场景列表展示配置状态；任务实际开启状态另设只读诊断入口，查询前必须选择车辆及需要的账号。保存/发布不会替用户开启任务；用户关闭不会删除任务配置。状态未知显示“未取得”，不显示“关闭”。 | 产品必须明确的对象边界 |
| 3 | 原稿提出可配置原子能力，但缺能力在哪选、缺什么不能发 | 给产品一个输入框就算支持新信号吗？谁把参数变成可运行内容？ | 在信号、识别、卡片、动作、回读选择项旁提供能力说明。研发预先接入能力并提供名称、来源、字段、单位、值域、车型版本、端云范围、输入输出及可编辑参数；产品只组合已接入能力。范围变化后重新校验已选能力；不可用可存草稿，不可发布。 | 本次需求；能力实际接入状态待各团队确认 |
| 4 | 四案例同时含“变为”、当前值、穿越阈值、连续次数、温差窗口、计时完成，原稿只泛称触发事件/判断条件 | 进入 P 与一直是 P 有什么区别？车速/开关变了会不会再判断？ | 条件区分为“启动检查的事件”和“检查时必须满足的状态”。每一任务列清启动事件列表；静态值变化不自动被认作新启动事件。连续次数必须连续、不能累计不相邻结果；温差要有时间窗和基准；15 分钟到时是已接入定时事件，不可仅写备注。未支持的计算方式显示缺口。 | 区分是产品要求；具体补判/窗口/端云支持待确认 |
| 5 | 天气任务有雨/雾/雪不同动作，后视镜有三个入口，但平台配置未说明不同分支怎样避免串动作 | 同时满足雨和雾，是开灯、换模式还是全做？ | 支持按业务子场景配置条件→建议→动作对应关系；每条分支独立呈现内容与目标。对同时命中明示合并、排序或互斥策略，未确认时不默认全量执行。条件摘要加括号显示 AND/OR 作用范围，任务实际有效状态是所有组共同门禁，不可被 OR 绕过。 | 分支表达为本次要求；冲突策略待产品会签 |
| 6 | 原稿把“主动推荐/识别 Query”“交互等级”“后续动作”罗列，未定义可串联关系 | 选主动推荐后就不能选询问了吗？识别成功能不能直接执行？ | 在命中处理区先选承接业务，再选是否需要进一步判断；识别结果按找到/未找到/无法判断/失败（另含超时策略）分别选择下一步。之后独立配置无需交互/仅告知/询问，再配置允许的执行动作。充电示例必须表达“识别→询问→执行”，不是三选一。 | 结构化配置方案；是否询问按案例确认状态 |
| 7 | 原稿云端总述允许直接回业务或显式模拟 Query，行为表却默认静态 Advisor 模拟 Query | 前端点击到底调业务还是发 Query？会不会发两遍？ | 在“回答路线”明确当前选中一种点击路径；本次目标为直接回系统预设任务业务，尚未接通则列依赖；兼容模拟 Query 只在明确选用且能力支持时启用。不得同时调用两条链路。语音路线独立配置，Planner 不创建卡片；仅当前卡实际展示后注册当前语境。 | 当前路径必须会签；不可把目标路径写成已实现 |
| 8 | 原稿“卡片、TTS、按钮、有效期”未交代修改时页面联动及草稿隐藏值 | 从询问改成仅告知，原开盖动作还会下发吗？ | 交互方式切换后，不适用项收起并从当前运行定义移除；可保留草稿供恢复，但明确“未启用”。仅告知不能因存在旧确认配置进入车控；关闭识别后旧 Query 和结果分支不运行。再次启用需重新确认依赖与参数。 | 本次前端/配置生成要求 |
| 9 | 口盖/天气需询问，儿童与加热有静默策略；各类卡未区分文本、语音输入、TTS 播放和界面状态 | 不说话是否还能播报？排队多久算超时？开关被关闭时卡片怎么办？ | TTS 开关/内容、语音输入路线、手动点击分别配置与验收。区分受理、排队、实际展示、用户结果、结束；回答计时自实际展示起算，识别时效不会因排队刷新。拒绝/关闭/超时结束本次，不关闭长期任务。任务关闭或场景失效时业务撤卡并注销关联。 | 生命周期为需求；时长及语音禁用降级待会签 |
| 10 | 原稿“结束/退出”混合终止卡片和反向车控；镜热又有停止计时动作 | 关闭任务等于关掉儿童锁/口盖/加热吗？ | 在运行策略区分“终止本次处理”和“退出时车辆动作”。前者停止后续申请和清理卡片；后者必须独立引用已批准车控及条件。儿童锁、口盖原稿已说不自动关闭，应显示无反向动作。镜热 15 分钟关闭是否跨任务关闭继续、手动操作后如何处理需要独立会签，不能统一“退出=恢复原状”。 | 保留原稿明确策略，其余待确认 |
| 11 | 原稿缺保存草稿、校验、发布及版本处理中描述 | 前端保存成功后谁使用新版本？下游失败算生效吗？ | 底部提供保存草稿、检查配置、发布。缺项清单可定位字段；草稿不影响旧有效版本。发布区分处理中、有效范围内生效、失败，展示运行接收结果；相关运行方未取得一致配置时不得显示完整生效。回退保留操作记录，不撤销已发生车控。在途单次处理采用哪版应作为版本策略会签。 | 本次需求；发布承接实现待研发确认 |
| 12 | 原稿“原业务回传结果”缺记录页可见效果 | Trigger成功之后没结果，到底是未执行还是回传丢了？ | 记录列表分别显示 Trigger 交接状态、最后阶段、业务最终结果；详情展示各阶段输入/判断/输出/时间/停止原因。未进入、等待结果、处理失败、未取得回传分开显示。真实口盖未读取时不能绿标成功；已成功但卡片更新失败要保留“车辆成功、展示更新失败”两个事实。 | 本次数据回传及前端需求 |

## 二、可直接放入正文的五组页面操作说明

配置者从“场景管理”进入新建或编辑。在同一页完成以下五组内容；本期云端配置使用，端侧实例仍按需求与版本开发。下面是需要交付的页面行为，不代表当前后台已具备。

| 页面区域 | 配置者怎样操作 | 页面应呈现的结果 | 运行时谁使用 |
|---|---|---|---|
| 任务关联与适用范围 | 选系统预设任务→选具体任务定义→选车型/版本→选系统预设任务业务 | 展示任务状态能力是否已接入及业务承接是否可用；不让产品手填用户真实开关 | Trigger 读取任务许可和范围；原业务接收事件 |
| 触发规则 | 分别选启动事件、当前条件→选择全部/任一满足→填写受支持的稳定判断、数据时效、同次场景去重 | 生成可读的完整条件句；不可用能力标红并解释；OR 不绕过任务状态 | Cloud Trigger |
| 命中后业务处理 | 选是否进一步判断→需要时选能力/问题/上下文来源→填写每类结果走向 | 各分支清楚显示继续、结束或已支持重试，不把识别接口受理当业务成功 | 系统预设任务业务调用主动推荐/DT/VQA |
| 用户交互与动作 | 选无需交互、仅告知或询问→需要时填模板/文案/TTS/按钮/回答路线→配允许执行的动作、复核和回读 | 预览用户最终看到和听到的内容；显示每种回答下一步；不把识别结果等同授权 | 原业务注册卡片；VUI 展示；必要时 Planner 理解；端侧执行及回读 |
| 运行与结束策略 | 填次数/间隔/起算点→设置失效与退出→设置允许的重试→检查并发布 | 展示停止原因、清理行为和独立反向动作；摘要只包含启用分支 | Trigger 消费频控；业务消费等待/结束；端侧执行复核 |

## 三、前端与平台操作验收

| 用例 | 操作 | 可观察预期 |
|---|---|---|
| F01 普通场景兼容 | 打开已有普通 Trigger 场景并保存无关信息 | 不被强制关联预设任务；旧路径不改变 |
| F02 系统任务必填 | 新建系统任务，未关联任务直接检查 | 显示缺少任务关联，跳到第一组；已填条件不丢失 |
| F03 实际状态查询 | 列表点击查看任务状态，未选车辆；选车辆后来源返回未知 | 先要求选车辆/账号范围；查询结果为未知及原因，不显示全局开启或关闭 |
| F04 适用范围改变 | 已选口盖动作后扩大到不支持车型 | 保留选项并指出不兼容范围，允许改范围或换能力；不得静默删条件或继续发布 |
| F05 AND/OR 门禁 | 添加两组 OR，其中一组条件成立但任务关闭 | 规则摘要仍包含任务许可；运行预期无事件 |
| F06 事件与状态 | 配置进入 P，车辆一直为 P；再从 D 变 P | 前者不凭静态 P 反复产生进入事件；后者按规则检查；初始化补判若未确认应明确不算本用例已通过 |
| F07 无效输入 | 数值字段填文本、负时长、空条件组或枚举外值 | 即时指出位置/范围；可保留草稿但不允许该路径发布 |
| F08 模式切换 | 完成识别+询问+开盖后改为仅告知 | 预览和高级输出不包含旧确认授权与开盖；恢复询问提示复核保留值 |
| F09 点击单路 | 选择业务回调路线并点击确认 | 仅向已选业务交付一次，不同时再发送模拟 Query；传输重送不得重复执行 |
| F10 识别四分支 | 分别模拟找到、未找到、未知、失败 | 仅已配置的有效找到路径进入卡片，其他停止并有可读原因；不是统一“调用成功” |
| F11 播放与输入 | 禁用语音输入但手动点击可用 | 页面不把 TTS、语音输入、手动点击揉成一个开关；按已选降级策略展示并可点击 |
| F12 展示计时 | 卡片排队后实际展示；排队中识别先过期 | 回答计时从展示起；识别过期卡不得因排队轮到而继续询问 |
| F13 状态隔离 | 编辑草稿→保存→发布失败 | 原有效配置继续明确展示；没有改变用户实际开关；失败原因可查 |
| F14 记录分层 | 事件发出但 VQA 未返回；车控成功但回读未知；车辆成功但更新卡失败 | 三种分别显示当前等待/真实结果未知/车辆成功而卡更新失败，不合并成“执行成功” |
| F15 任务终止 | 用户确认前关闭任务；车控已经发出后关闭任务 | 前者撤卡不执行；后者不谎称撤销动作，继续确认真实结果；记录保留终止时点 |

## 四、主要呈现建议

1. 现有“平台改造范围与页面落位”必须补真实页面落点图或表；运行时序图不能代替配置流程图。
2. 主图继续只表达五个区域及联动，字段和规则放图下表格；把“填写了什么→哪个模块读取→产生什么效果”对应起来。
3. 配置产物预览包含一条可读业务句、卡片/TTS 示例、结果分支和退出行为，不展示大段未经确认 JSON。
4. 原稿两处需要主 Agent 处理的内容一致性问题：儿童锁前文主动语音卡与后文静默策略冲突；云端点击段落对直接业务回调和模拟 Query 的默认性不一致。不能由前端 Agent 擅自拍板。
