## 会议案例：m0813.txt

### MT-C001｜真实 badcase：BAB / BABA 交错
- 用户看到了什么：新问题与旧结果来回切换，路测还观察到 BABA。
- 系统里发生了什么：新 query 先回应、旧 feedback 插入、新 feedback 再到是会上对 BAB 的解释。
- 根因：BAB 指向输入管理架构与策略；BABA 是否额外工程 bug 未定。
- 怎么改：当时短期建议压缩提示词响应，根治需改输入管理；未证明已修复。
- 来源：chapters/I/raw/m0813.txt:14-35（2026-08-13 文字记录）。

### MT-C002｜真实 badcase：被打断任务没回来
- 用户看到了什么：旧任务被打断后没回传、没完成。
- 系统里发生了什么：恢复链路没有完成旧任务，未提供具体 request_id。
- 根因：仅确认恢复损点，不能确定是队列、许可还是恢复价值判断。
- 怎么改：另开专项重看恢复资格与反馈，演示前不改。
- 来源：chapters/I/raw/m0813.txt:19-20、40-47、73-74（2026-08-13 文字记录）。

### MT-C003｜真实 badcase：已经问饭店，旧幼儿园仍恢复
- 用户看到了什么：从搜幼儿园改问饭店或自己打断自己后仍听旧回答。
- 系统里发生了什么：旧任务继续当成待恢复内容。
- 根因：恢复价值与新旧覆盖关系判断不足，未给唯一工程根因。
- 怎么改：按任务类型、核心内容是否播完及覆盖/补充关系评测；覆盖旧目标时不恢复。
- 来源：chapters/I/raw/m0813.txt:37-38、61-74（2026-08-13 文字记录）。

### MT-C004｜真实 badcase：已删途经点半小时后复活
- 用户看到了什么：问当前途经点却听到半小时前已删地点。

- 根因：陈旧记忆与真实状态不一致是怀疑方向，未唯一确认。
- 怎么改：建议重要状态以事件上报、穿插对话替代摘要，未证明已完成。
- 来源：chapters/I/raw/m0813.txt:97-116、148-152（2026-08-13 文字记录）。

### MT-C005｜真实 badcase：只问时长却改导航
- 用户看到了什么：问国贸到辰山植物园多久，途经点却被添加。
- 系统里发生了什么：Planner 调 Route planning，feedback 返回更新路线成功，现场确认动了系统导航。
- 根因：怀疑后台查询与前台算路工具未拆清和确认未生效，仍让思晴查。

- 来源：chapters/I/raw/m0813.txt:128-239（2026-08-13 文字记录）。

### MT-C007｜真实 badcase：话术与任务/车控事实相反

## CHAT：aiva-vui-1104.txt

### CHAT-C001｜真实现状：一句话多工具结果挤在一起
- 用户看到了什么：“打开座椅按摩导航去南京南站”或“我好冷啊”触发多个工具，结果缺少分割、与 query 对应弱。
- 系统里发生了什么：feedback 到达即展示组件，多个结果缺少清楚分组。
- 根因：明确的是界面分组问题，不能推定调度或模型故障。
- 怎么改：提出按 DT 拆分的单工具改写 query 分区、同工具多指令合标题、工具间加分隔；未见验收。
- 来源：chapters/I/raw/aiva-vui-1104.txt:926–941。

### CHAT-C002｜设计场景：前后排两句并成一轮
- 用户看到了什么：前排“打开座椅按摩”，后排在首 token 前说“空调调高点”，前后屏一起出多控件。
- 系统里发生了什么：旧规则以首 token 前为合并条件，两个音区合进一轮。
- 根因：设计示例，无真实故障。
- 怎么改：用于历史边界对比，现行设计须补执行重放边界。
- 来源：chapters/I/raw/aiva-vui-1104.txt:765–772。

### CHAT-C003｜设计场景：新闻中插话“导航去”
- 用户看到了什么：新闻正在播或卡片出字，Q2“导航去”停 TTS，但旧卡片继续出字，最终有效才覆盖。
- 系统里发生了什么：播放停止与上屏生成分开控制。
- 根因：设计场景，无事故归因。
- 怎么改：解释停播不等于取消所有计算/上屏，也不代表副作用回滚。
- 来源：chapters/I/raw/aiva-vui-1104.txt:798–807。

### CHAT-C004｜设计场景：跨音区接续导航
- 用户看到了什么：主驾“导航去南京南站”，后排“第一个”或“添加途经点”，仍在前排卡片刷新。
- 系统里发生了什么：出行类用首个交互音区卡片作容器，跨音区接续同一任务。
- 根因：设计是为了避免 VGUI 同步混乱。
- 怎么改：保留输入音区来源，同时单独确定任务接续和展示容器。
- 来源：chapters/I/raw/aiva-vui-1104.txt:783–787。

### CHAT-C005｜设计场景：后排无关请求不延长前排卡片
- 用户看到了什么：前排新闻卡片在，后排新指令引起 TTS，前排卡片仍独立到时退出。
- 系统里发生了什么：前后屏卡片各自计时，无关 query 不互相清卡或续期。
- 根因：设计场景，卡片生命周期不能只跟全车 TTS 走。
- 怎么改：区分卡片存在、执行有效与播放结束。
- 来源：chapters/I/raw/aiva-vui-1104.txt:788–793。

## 会议案例：m1019.txt

### MT-C008｜真实 badcase：主动打招呼后接不上话
- 用户看到了什么：上汽主动服务向用户打招呼，用户回应却接不上。
- 系统里发生了什么：主动服务没有完整拉起可二次交互的语音状态。
- 根因：主交互激活与主动服务链路未拉齐，会议未展开具体代码根因。
- 怎么改：无论是否需要二次确认，主动服务均拉起全车音区进入播报并支持接话。
- 来源：chapters/I/raw/m1019.txt:158-159（2026-10-19，00:28:30）。

### MT-C009｜真实 badcase：副驾说了却未上屏
- 用户看到了什么：赛力斯实测视频中副驾说话没上屏，难以判断豆包是否响应。
- 系统里发生了什么：多音区的输入/结果呈现没有完整生效；记录未证明 Planner 是否收到。
- 根因：主交互多音区呈现损点，唯一根因未定。
- 怎么改：按有效 query 与左右胶囊的展示规则排查；不要把上屏故障直接等同输入丢失。
- 来源：chapters/I/raw/m1019.txt:29-42、86-90。

### MT-C010｜设计场景：未完成的长时导览被新任务插入
- 用户看到了什么：沿途导览中插入调座椅或联网查询，前台换成新任务，之后可继续导览。
- 系统里发生了什么：新 query 打断前台，未完成的长时目标被 review 后再推荐 Planner 继续并重拉界面。
- 根因：这是目标恢复设计说明，不是真实事故；当时主线还在做。
- 怎么改：把长时任务目标恢复与单轮输入调度分开验收，不能承诺当时已上线。
- 来源：chapters/I/raw/m1019.txt:422-477。

### MT-C011｜设计场景：前后排无关任务各自保持
- 用户看到了什么：前排搜餐厅、后排搜周杰伦，分别展示结果；后排开窗不清空前排导航卡。
- 系统里发生了什么：卡片按前后排独立保持，只有语义相关或音区合并才联动刷新。
- 根因：用于解释一条统一交互流与多个显示区域并不冲突的设计例子。
- 怎么改：排查时区分输入合并规则与显示容器保持规则。
- 来源：chapters/I/raw/m1019.txt:212-216。

## 会议案例：m1020.txt

### MT-C012｜设计风险：到号提醒和用户结果卡同时出来
- 用户看到了什么：评审假设用户正在 query 链路时又来美团到号提醒，可能两张卡同时出现。
- 系统里发生了什么：业务提醒与主交互卡片未统一定义时序与合并。

- 系统里发生了什么：A 尚无工具副作用时，新 B 使 A 原执行失效并合并重推；已放行工具则只执行 B。
- 根因或设计边界：待重放输入必须仍可重放，不能用“没听见回复”代替判断。

## TECH-C002｜设计场景二：播报中有效插话

## 案例使用边界

- 技术方案场景一至八完整保留为TECH-C001–008；较早副本的同组场景为PRD-C031–038，属于版本对照，不重复算真实事故。
- 无线充电后补西餐厅、制冷后补停车场、空调串约会等已有原始路测行号；BAB/BABA的会议解释是当场分析，未证明新模块已修复。
- 导航报告及其他周报症状用于排除“都怪输入管理”的错误归因，除非原材料给出链路证据，否则根因明确留空或标未定位。
- 设计场景中“怎么改”是应有规则；真实症状中只有原材料明确的修复才能称已改，其他记录为排查/防范方向。
