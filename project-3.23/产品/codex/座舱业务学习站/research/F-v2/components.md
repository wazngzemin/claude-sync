# F 章部件与概念候选

供下一步设计部件卡使用，不改全站卡片；已有部件只登记F需深化层。部署和数字未知时明确留缺口。

### [P01] Agent 接入协议字段（卡片37/38深化）
- 是什么：座舱云与单个Agent的请求、响应、身份归属和鉴权约定。
- 在哪里运行：座舱云调用方与第三方HTTPS服务，车机承接卡片/透传。
- 收到什么：话题/会话/单轮编号、Agent编号与协议版本、query、上下文、渠道/车辆/车型、选填账号与位置、trace。
- 输出什么：按内容用途、结束状态和错误信息分层的SSE帧。
- 关键数字：v1.4=2026-08-13；账号自2026-05-13选填；两类鉴权，签名有效时差30秒不是工具超时。
- 来源：chapters/F/raw/agent-protocol.txt:2–49、69–319、449–603、1021–1075。

### [P02] 流式返回分层（卡片41传输侧深化）
- 是什么：将屏幕、语音和模型判断内容分开传递的协议。
- 在哪里运行：下游Agent→云端适配→Planner/车机展示播报。
- 收到什么：逐帧输出、chunk_type、content_type。
- 输出什么：content、tts_content、model_content、reasoning_content和is_finish末帧，支持卡片与透传。
- 关键数字：chunk_type回答/命令=1/2；content_type文本/卡片/透传=1/6/9；末帧必须true。
- 来源：chapters/F/raw/agent-protocol.txt:189–281、381–448、968–1013；默认TTS路由存在文内冲突。

### [P03] 取消协议（卡片37/42接入边界深化）
- 是什么：通知下游终止当前对话请求的协议意图，不能据此声称撤回已执行动作。
- 在哪里运行：座舱云到第三方Agent；精确状态机未给。
- 收到什么：query_type=3及公共请求身份。
- 输出什么：没有专用取消ACK、最大生效时间、重复取消约定。
- 关键数字：查询1、预查询2默认关闭、取消3。
- 来源：chapters/F/raw/agent-protocol.txt:928–945。
### [P04] 工具定义与调用说明（卡片38深化，不重复建平台卡）
- 是什么：让Planner知道何时选它、填什么、有哪些限制的能力契约。
- 在哪里运行：云端平台存储，动态组装入Planner系统提示词，产品在Fornax或副本调试。
- 收到什么：中英文名、UI名、能力描述与项目覆盖说明、参数描述、notice、tips。
- 输出什么：模型可读工具信息；正式Prompt用{{tool_info}}加载。
- 关键数字：定义/实现两层，租户键2项；无统一描述字数或最佳工具数量。
- 来源：chapters/F/raw/agent-sop.txt:19–29、81–93、191–202、255–272。

### [P05] 接入与发布流程（卡片38的操作侧深化）
- 是什么：把能力定义、可调用实现、测试环境版本与正式发布串起来的工作流。
- 在哪里运行：云端管理平台与研发测试发版流程，实车另验。
- 收到什么：接入点/鉴权、租户/环境、实现代码及测试证据。
- 输出什么：测试通过的已发布且启用实现；禁用保留配置，删定义前禁用关联实现。
- 关键数字：4种接入类型；快速测试两种入口路径，指定Agent跳过Planner且暂限部分纯文本。
- 来源：chapters/F/raw/agent-sop.txt:98–102、203–245、247–272。

### [P06] Context取消信号与取消投递（P03补证）
- 是什么：调用链内通知终止在途下游请求的操作，不等同于用户一句“取消”必然撤销全部业务。
- 在哪里运行：调用方→云端Agent Server→对应下游Executor/服务。
- 收到什么：Context cancel，再断开连接。
- 输出什么：通知下游结束、记录已生成内容；无专用成功ACK与时限。
- 关键数字：未给取消超时及全Executor覆盖率；与对外query_type=3是两层表达，不可声称映射实现已全覆盖。
- 来源：chapters/F/raw/agentserver.txt:71；agent-protocol.txt:928–945。

### [P07] 工具能力Knowhow（补卡片34能力检查）
- 是什么：每个工具所含原子能力、前提、特殊说明和例句的知识；与工具是否暴露列表不同。
- 在哪里运行：当时临时存云端代码map，能力检查后拼入Planner的capability变量，平台管理是产品化方向。
- 收到什么：required_capabilities能力key、原子能力知识。
- 输出什么：按能力key顺序拼接编号知识，必要时附无法执行原因改写query。
- 关键数字：2.0lite主选、mini备选；9/8单元加白后只报告速度基本满足，无具体性能和准确率数字。
- 来源：chapters/F/raw/capability.txt:37–74、94–112。

### [P08] 动态工具列表与条件引擎（已有卡片20，F补配置与适用边界）
- 是什么：只把本轮场景可用的工具说明交给Planner的规则机制，不是按模型猜测生成新能力。
- 在哪里运行：云端AgentServer，每次Planner推理前。
- 收到什么：租户/环境候选工具、agent_meta.dynamic_condition、请求param和开关。
- 输出什么：判定true/false后的工具列表与页面限定说明，执行权限检查仍另处理。
- 关键数字：本期1类字段源param、4种判断、2种组合；端状态适配Trigger为后续方向。
- 来源：chapters/F/raw/dynamic-tools.txt:3–36、74–130、173–185；不重复W章按钮语义内部机制。

### [P09] 工具选择与参数准确率（补卡片36，评测体系留EV）
- 是什么：分别检查是否选对工具、调用参数是否保留用户目标与限制的接入质量指标。
- 在哪里运行：算法直请模型或PPE链路测试，不是实车结果本身。
- 收到什么：query、该环境实际工具列表/定义、预期工具与参数、真实输出。
- 输出什么：选择与填参问题归因，接入前后回归结果；本报告未提供独立参数指标数值。
- 关键数字：12/25意图322/337=95.54%；5/28表86.97%与计数不闭合；没有工具数-准确率曲线或统一工具上限。
- 来源：chapters/F/raw/planner-tool-accuracy.txt:1–7；指标拆分为研究定义，非已测出参数准确率。

### [P10] 请求身份、调用身份与业务幂等（补卡片24/25/45）
- 是什么：将同一次网络重传、一次推理执行、一次工具调用和一项业务任务分开识别，避免重复副作用。
- 在哪里运行：车云请求层、云端编排/Agent、下游持久存储与业务端。
- 收到什么：端云request_id/round_id、Agent话题/会话/单轮编号、工具调用身份，或反馈report_id/action。
- 输出什么：原调用关联、重复回读与状态条件更新；不能说所有工具已统一持久幂等。
- 关键数字：反馈创建键3项vehicle_id/request_id/source，业务键2项report_id/action；TTL建议10分钟仅为反馈任务。
- 来源：chapters/F/raw/proto.txt:28–72；agent-protocol.txt:88–188、449–505；chapters/E/raw/user-feedback.txt:1394–1478；通用工具调用身份详见overlap.md的M02/M03/M08。

### [P11] 错误码分层与可恢复条件
- 是什么：分清网络/协议失败、Agent参数/权限错误、业务未完成、设备回执与物理目标结果的证据层，不是已有全工具统一错误码字典。
- 在哪里运行：调用网关/Agent/下游服务/车端执行与Planner反馈适配。
- 收到什么：HTTP结果、error_code/error_message、业务状态及实际执行结果。
- 输出什么：具体失败层、下一步补信息/授权/换方法/允许重试与否；用户表达仍由Planner负责。
- 关键数字：通用协议0表示成功；反馈应用6类不可重试+1类内部错误可重试；设备码30000/30001与车控ACK状态0是另层，回指E。
- 来源：chapters/F/raw/agent-protocol.txt:271–301；tools-io-excerpt.txt:28、33、37、42；chapters/E/raw/user-feedback.txt:1099–1155；完整设备证据见overlap.md E23。

### [P12] 工具准入标准（研究综合候选，非已发布统一评分规则）
- 是什么：把拟接能力的业务价值、职责边界、可执行输入、真实输出与模型可选性放到接入评审中核对。
- 在哪里运行：产品/项目/Agent提供方评审，平台注册、联调和整体SP评测。
- 收到什么：能力形态、中英文名、功能/Query描述、相邻工具区别、协议端点与认证、正常异常反馈、示例。
- 输出什么：走纯车端FunctionCalling或座舱Agent的接入选择，以及需补边界/字段/测试的事项；不凭平台能建定义就判可上线。
- 关键数字：无统一价值评分、数量上限或通用准入分数；10/22高德两工具因边界重叠仍未达上线标准。
- 来源：chapters/F/raw/agent-protocol.txt:52–68；tools-io-excerpt.txt:27；v-lesson-20261105/director-talk.md:358–377、423–436。

### [P13] 能力开关与车型配置（补卡片34/38，F配置分层）
- 是什么：分别管理项目有无实现、某场景是否暴露、该车原子能力、调用时权限与业务条件的信息，不是单一万能开关。
- 在哪里运行：工具平台/云端条件引擎/Planner能力注入/车端与下游业务校验。
- 收到什么：channel/app_id/env、启用发布/参与推理、dynamic_condition、开关param、车型配置、账号权限。
- 输出什么：项目候选与本轮可见工具、模型能力说明、执行许可或拒绝结果；各层不能互相替代。
- 关键数字：渠道示例1000/99210/99220；本期动态源只param；座椅动态能力曾因上报bug待重测。
- 来源：chapters/F/raw/agent-sop.txt:191–220；dynamic-tools.txt:30–36、77–130；h2-excerpt.txt:218–224；proto.txt:2–27。

### [P14] 单工具流与整批工具反馈（补卡片42，避免两个同步概念混淆）
- 是什么：单次Agent可逐帧产生输出，而本期Planner同轮工具结果按批收齐；流式传输与多工具异步调度是两个维度。
- 在哪里运行：Agent SSE服务、AgentServer后处理、云端编排和输入管理。
- 收到什么：单Agent多帧is_finish、同批各项真实结果与失败占位。
- 输出什么：末帧结束单工具，完整批tool_feedback进入下一轮；普通HTTP同步单JSON接口在本次原文中缺契约。
- 关键数字：无所有工具统一等待秒数；不能把首包500/800ms、端云3秒、排查10秒当Agent超时。
- 来源：chapters/F/raw/agent-protocol.txt:189–281、1010–1013；agentserver.txt:18–21；overlap.md E26、C04及其原文指针。

## 后续设计必须保留的五个难点

1. 工具被注册、本轮可见、允许执行、最终做成分别需要什么证据；账号/档位限制不能一律写成动态过滤。
2. 平台按项目动态加载、特定SFT工具块改造、按场景临时暴露、按车动态参数与能力知识注入是不同机制。
3. 用户请求、ASR轮次、Planner执行、单工具调用、业务任务、Trace分别属于哪一层；同名字段不能未经映射直接套用。
4. 单Agent流式content/tts_content/model_content、Planner上下文tool_feedback和最终响应同名model_content之间怎样交接，末帧与业务完成如何区分。
5. Context取消、对外取消类型、停止TTS和取消业务任务分别停什么，何种重发沿用身份，哪些幂等与取消保证尚无确证。
