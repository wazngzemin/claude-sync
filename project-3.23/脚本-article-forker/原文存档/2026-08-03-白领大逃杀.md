白领大逃杀，可能比我之前的预期更迟……得多
我从 2025 年开始预测 AI 推动的白领大逃杀的未来。有意思的是，时间进入到 2026 年我拥抱 Agent 之后，体验过 Agent 带来的生产力提升，对大逃杀的进度反而比以前乐观非常，非常，非常多。

简单来说，我认为 5 年内白领大逃杀不会到来。

一、

按目前的技术潮流，只有 Agent 才能提高任务复杂度和输出稳定性，拥抱 Agent 的人往往会惊叹于 AI 对白领工作的替代。

我同时留意到了另外一件事。

harness，我理解为任务在 Agent 内的运行规则。每一个任务都要写对应的 harness，当任务环境发生变化的时候调试对应的 harness，对于 Agent 玩家来说都是常识。

但不匹配大多数人的工作方式。

我再重复一次：第一批拥抱 Agent 的人可能没有意识到，这不匹配大多数人的工作方式。

什么是大多数人的工作方式？花时间学习一些技术和方法，沉淀成自己的 SOP，无限次地重复 SOP。在无限次重复的过程之中，根据 SOP 运行时细小的差异来进行优化。白领也好，蓝领也好，这就是普通人的工作方式。

这套方式在 Agent 时代彻底失灵了，因为根本就没有 SOP。

每一个由 Agent 执行的任务，都要根据任务环境单独设计和调试 harness，无法复用同一套规则来节约大脑运算的能量。因此，第一批拥抱 Agent 的人同时也是思维活跃，不吝惜脑力，甚至乐意于支付脑力的人。这不仅仅是世俗意义上的聪明，还包括大脑的活力旺盛。

犬校里有着大量活力旺盛的同学，花钱花时间加入这么一个毫无收益的小社区，本身就是活力的证明。但我们看看身边的人……他们活力旺盛吗？他们愿意为每一个任务去设计和调试规则吗？他们愿意在任务「稍有变更」的时候同步修改规则吗？

太多太多的人能够学习方法，但不知道如何编辑规则。方法是可以用体感和死记硬背来学习的，规则是抽象的，抽象是大量消耗脑能量的。我观察到的许多样本，至少在目前并不具备编辑规则的能力，更不具备跟随环境变化反反复复迭代规则的能力和心力。“太累了”，他们会摇着头告诉你，大脑频繁进入思考模式太累了。

古法与 Agent 模式，差不多是缓存命中与全新输入与推理的差异。节约脑力是普通人的生物本能。

如果我们把未来被 AI 高度赋能的职业视为 Agent 工程师，或者犬校同学命名的「Agent 驾驶员」，就要面对这么一个现实：当前大部分白领一招鲜吃遍天的工作模式，跟持续支付脑力的 Agent 工作模式是不兼容的。市场在很长的时间里边都不可能供给大量的 Agent 工程师。

这个 “很长的时间” 跨度是以五年十年为时间单位的。

二、

如果第一小节有一定的道理，我们很容易预测另一种可能性，如果 Agent 模式能够提效（平均）3 倍以上，那么公司可以裁员到原来的 1/3，仅保留熟练的 Agent 工程师。

或者公司可以招聘数量更少的 Agent 工程师，由他们来设计和迭代规则，其他人运行规则。毕竟 Agent 在运行中也是需要人类监督的，大多数任务环境下并不能完全放手。

这个未来有可能发生，同样是以五年十年为时间单位的。

首先，市场得供应起码数量的 Agent 工程师，让他们来接管公司业务。这批人必须同时掌握 Agent 驾驶技术与公司业务，缺哪一样都不行。

其次，Agent 协作模式与传统协作模式，作为两大流派是不兼容的，或者倒向 Agent 协作模式，或者保留传统协作模式。公司在什么情况下会把（一部分）工作切换到 Agent 模式？如果仅仅是为了减少人力支出，相对收益来说，新范式带来的业务风险可能会醒目得多。

那什么情况下收益大于风险呢？

从我的行业观察来看，有两种公司会向着 Agent 模式大步迈进。第一种是老板对于前沿技术相当着迷，宁肯承担业务风险也要狂热地拥抱前沿技术。（此处应艾特犬校同学甲）

第二种是 AI native 新项目，没有历史包袱，由狂热的 AI 信仰者组成。此外还有一个隐藏彩蛋是，新项目根本不在乎提效之后裁员，大家真正担心的是项目挂了全体失业……必然全力拥抱在 AI 赋能下效率最高的协作模式。（此处应艾特犬校同学乙）

无论哪一种情况，规模都很小，对不对？这点点规模起不到任何的示范效应。

于是行业陷入了鸡生蛋、蛋生鸡的困境。如果公司没有推行 Agent 模式，工作环境就培养不出来多少 Agent 工程师。没有起码数量的 Agent 工程师，公司就没法切换到 Agent 模式下工作。

死循环了不是。

对 Agent 工程师的人力需求很难通过外部招聘满足。外招 AI 信仰者中的大多数人不熟悉业务，懂 AI 不懂业务是驾驶不了 Agent 的。而内部培养的隐藏 bug 是，如此大幅度提效必然带来大幅度裁员，谁上谁工贼。第一批积极配合的人既要面对交付稳定性的风险，也要面对来自同事明里暗里的不配合。他甚至不知道同事都走了之后，下一个被裁的是不是自己。

三、

之前说过，Agent 时代没有 SOP，喜欢抄作业的人是抄不到作业的。AI 是千人千面的需求满足，每一个人，甚至细到了每一个任务，都要去定制满足需求的方式。

与此同时，AI 不是许愿机。即便 Agent 已经大幅度提升了生产力，每一个任务适合还是不适合用 Agent 来跑？适合的任务怎样才能跑到更高的效率与质量？古法怎样与 Agent 融合成流畅的工作流？走向多人 Agent 协作的新范式需要长时间的探索，而探索本身意味着公司层面的决心。

到目前为止，大多数公司下不了这个决心。基础要素包括：

乐意于用 Agent 去实现一切任务的员工。

该员工有权限的任务中，一部分适合跑在 Agent 上。

在此基础上，Agent 必须从单人任务走到多人协作任务，才能真正发挥 Agent 模式的能力。

而现实中我们最容易看到的情况是：

一个部门内有少量的 AI 信仰者，自己的日常任务尽可能多地用 Agent 去实现。

其他人的任务，他没有权限干预，同时因为对别人的业务陌生，他也不知道怎样改造。

能够带来整体效率提升的任务，往必然需要改造大量的多人协作环节，每一个无法改造的协作环节都会成为整体效率的绊脚石。

（此处应艾特犬校同学丙/丁/戊/己/庚/辛）

不然还能怎么办呢？大多数公司在长时间的探索中收益模糊且无从下手。既不知道从哪里啃，啃也啃不动。

你让一些根本不合适的人切换到 Agent 模式上，这肯定不行。

你在新的协作模式探索成功之前，把不合适的人开掉换血，这更加不行。

你招聘足够多的 Agent 工程师来适配新范式，你招不到。

你在现有的团队中给 Agent 工程师提要求，他们手一摊跟你表示：如果整个协作链条不改造，自己单打独斗也改变不了什么。

死循环了不是。

个别信仰者的提效被老旧的协作链条死死扯住后腿，个别信仰者在公司内部什么都推动不了，什么都改变不了，什么都证明不了，他只能匹配自己闭环完成的那一点点，看不到像样的收益。

而公司既没有新范式下的人才储备，也没有增加人才储备的有效方法（内部培养的苗子有限，外部招聘又不懂业务），还看不到如此折腾之后会带来怎样的收益，怎么可能承受切换到新范式的高昂成本呢？

因此正如第二小节所述，只有 “下黑手的老板和全员信徒” 才能把业务切换到 Agent 模式。市场上 99.9% 的公司只能喊着号子让员工多用 AI，但完全不知道怎样做到业务和 Agent 模式有效匹配……整个尴尬住了。

理想化的进展是：「1、大量思维活跃并且拥抱 AI 的员工」「2、适合跑在 Agent 上的大量任务」「3、公司提供 1+2 的友好环境」= Agent 协作模式 = 整体效率 3X 向上 = 裁员 2/3（没活干了，不得不裁员）。

我终于 callback 绕回到了这篇文章的主题：白领大逃杀，可能比我之前的预期来得更迟……得多。

一个人也好，一家公司也好，在自己身边找到 “AI 擅长的任务” 这个千人千面的结合点，把自己的专长和 AI 的长板结合在一起，对于个人具备相当程度的随机性（身边恰好有 AI 擅长的高价值任务），公司则面对业务流程和组织结构颠覆性重构的巨大障碍。尤其公司改革如此剧烈，最终收益是什么呢？仅仅是裁掉 2/3 的员工吗……

节约成本的收益，切换新范式过程中的系统风险，大裁员带来的社会风险，以上收益与风险完全不匹配，大多数公司并没有快步走向新范式的动力。AI 带来的局部效率提升不能转换为整体效率爆兵，在因循守旧的协作模式下，个别任务 5X 也好 10X 也好，对整体生产效率并没有多大改变。

如果你让我一拍脑袋说个数，我认为白领大逃杀全面到来，最低最低还需要 5-10 年。推迟到十年以后我也不会太惊奇。

至于最近三年你能看到的裁员，那仅仅是挤出多年积蓄的饱满的水分，而不是 AI 改变世界，效率高到了非裁员不可的地步。

四、

外媒报道，扎克伯格今年 7 月的在内部讲话中表示：

“AI agent development over the last four months has not accelerated in the way we expected.” 

“The upside that we were hoping to get from the new structure hasn’t come to fruition yet.”

我让 GPT 翻译过来的结果是：

“过去四个月，AI Agent 的发展速度并没有像我们预期的那样加速。”

“我们希望从新的组织结构中获得的收益，目前还没有实现。”

Meta 是这个行业最强大的公司之一，同时存在巨量历史债和复杂协作链。单凭小扎这两句话得不出什么定论，只能说：

市场上 99.9% 的（老）公司完全不知道怎样做到业务和 Agent 模式有效匹配……整个尴尬住了。

如果不是 AI native，老业务切换新范式就这么难。看不清收益，但是高昂的切换成本就摆在眼前。每一个任务适合还是不适合用 Agent 来跑？适合的任务怎样才能跑到更高的效率与质量？古法怎样与 Agent 融合成流畅的工作流？关键是改革的最终收益是什么——那个终点的圣杯到底是什么？

五、
犬校同学回帖：
和我最近的感受完全一样。

我每次用公司内部的 AI 工具遇到问题，都会把完整 session 导出来给 Codex 让它复盘。我的目的只有一个，就是要把这把 Skill 大锤磨得又快又亮，所有重复性任务都必须在最快的时间内以最高的质量完成。

另外我还有一些高频的每日任务，需要处理大量客诉数据，我每天都在迭代和扩展，2 个月迭代了 200 多个版本，以此为乐。

但我最近意识到，我的同事都不在意这些，他们觉得 AI 出错了骂他、让他记住就好了嘛。实在不行就放过彼此。

这让我意识到，我的内心住着一个提效狂魔，是 AI 激活了他。

成熟业务需要的 AI 驾驶员，首先需要懂业务本身。

在我自己负责的方向上，能 AI 化的早就 AI 化了，不能 AI 化的大部分卡在上下游流程里，超出当下的组织能力。

当我去看别的方向，虽然他们大部分还在和 AI 幻觉对骂，不知如何 harness，但真的让我去搞，（因为不懂他们的业务）我大概率也搞不出啥，只能作为一个门外汉表演 AI 杂技，对真正关键的问题没有判断力。

恍惚的时候我会想，大公司里最适合上车 AI 的方向，其实是内部工具，而不是任何一个业务部门。

我的回帖：
日常观察到两种情况，一种是普通人花心思学会了一件事情之后，希望能无限复用，让他们不断学习新东西是一件很烦恼的事情。
第二种情况是，他愿意花心思把一件事情做得更好，但必须能看到明显的收益。这其实是我们身边大多数同事的情况。
Agent 时代并不是这样的。把一套 harness 打磨得更好，往往并没有明显的（外部性的）收益，只是自我追求。如果一个人对任务停留在「能用就行」的地步，那么大概率是不会成为一个 Agent 高手的，甚至无法成为熟手，他只是一个普通的 Agent 操作员。这样的员工没有资格作为 Agent 工程师推动业务进入 Agent 模式。
于是这又回到了关键的卡点，卡点不就是打磨 harness 没有明显的外部性收益吗？如果不能提前证明显著的收益，支付如此多的成本（员工学习 Agent 的成本，业务切换 Agent 的成本与风险，公司换血的成本与风险），在方方面面都是下不去手的。
