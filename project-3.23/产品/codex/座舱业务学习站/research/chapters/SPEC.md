# 豆包汽车业务学习站：章节写作规范（以 V 章 v41 为最低标准）

读者：入职约 8 个月的初级 AI 产品经理（懂产品，不懂语音/模型细节），负责 Planner 相关工作，需要靠这份材料把整条业务链路讲给别人听并用于晋升。
标杆：`/Users/bytedance/Desktop/3.23/产品/codex/HTML/01-进行中/豆包汽车-业务学习站-v41.html` 的 V 章，源码 `research/v-lesson-20261106/content_v39.py`（正文）、`diagrams.py`（图）、`svgkit.py`（画图工具）。写之前必须先通读 V 章源码。每一章都必须达到或超过它。

## 一、用户明确提出过的要求（违反任何一条都不合格）
1. **讲链路、讲方案，不能散。** 全章沿一条主线讲：一个真实业务例子从进入本模块到离开本模块，每一步讲清“拿到什么 → 方案怎么做 → 为什么这样设计 → 交出什么给下一步”。段与段之间用“交给下一步：……”接上。不要把一节拆成七八个并列小块。
2. **讲给产品经理听。** 先讲用户会碰到什么、再讲机制；正文用产品语言，研发字段名（request_id、functioncall 等）只在附录对照表出现，正文需要时用“研发叫 xx”一句带过。第一次出现的术语立刻用中文说清是什么、在哪一步、干什么用。
3. **要有深度，但深度只服务于“为什么这样设计”。** 演进（原方案 → 问题 → 改造）、取舍（比过哪些方案、代价是什么）、真实 badcase（日期、现象、根因）、仍在争议的点，要写进讲述里，不要另起散落的小块。
4. **端和云必须分清。** 每个模型、模块、判断写清在车上（端侧）还是云端，以及不同项目（上汽 / 赛力斯 / 其他）的差异。例：1.7B 是端侧模型，赛力斯装车跑，上汽把同一端侧模型部署在云端服务器跑；30B 视觉与 30B 离线 DT 都在端侧。拿不准就去原文核实，核实不了就写“待确认”。
5. **事实必须有出处、状态必须准确。** 每个数字、日期、人名、引语都能在原文找到；区分：已上线 / 已定方案 / 开发中 / 讨论中 / 评估中 / 待确认 / 历史方案。讨论中、个人意见不能写成结论；会上提出的设想不能写成已上线；AI 纪要不算最终证据，必须追读文字记录。引号里只能放原话。
6. **不要废话。** 不写空泛价值句、写作过程旁白（“我的账号”“本章将”）、给作者看的说明。
7. **图要能看懂。** 每张图下面写“怎么看这张图”：从哪开始、沿哪条线走、每个分叉代表什么。图上不出现研发字段。图和正文的数字、状态必须一致。

## 二、章节结构（按 V 章 v41）
1. 开头 2–3 段：一个贯穿全章的真实例子 + 这一章讲哪一段链路 + 为什么产品经理要懂。
2. 「先看整条链路」：一张本模块的链路图（步骤编号），加一张“分几段、每段解决什么、交出什么”的表；说明本模块在全站主链路中的位置（上游是哪一章、下游是哪一章）。
3. 「第一段……第 N 段」：沿链路讲，每段结尾“交给下一步”。段的顺序和图上的步骤编号一致。
4. 「回头看：整条链路一张表」：步骤｜谁做（车上/云端）｜拿到什么｜方案｜交给下一步。
5. 「方案专题」2–4 个：每个讲清 要解决什么 → 怎么做 → 为什么这样设计（演进与取舍）→ 代价与边界 → 还在争的点。
6. 「产品经理工具箱」：出了问题先查哪一步/找谁；每一步看什么指标（区分现状数据与建议新增）；还没定、需要盯的事；5W2H 速记表。
7. 「讲给别人听：三分钟版本」+ 易错对照表（容易说成 → 应该是）。
8. 「附录：和研发对齐时会听到的词」。
9. 「对照：原始节点全图」（保留原章节的原图入口，若该章有原图）。

## 四、产出文件（每章一个目录 `research/chapters/<ID>/`）
1. `notes.md`：读取清单（标题｜链接｜编辑时间｜读到哪）+ 按链路步骤整理的事实笔记（事实｜出处+位置｜状态）+ 演进/取舍/badcase/争议 + 与旧版内容的冲突 + 缺口。
2. `content.py`：定义 `INTRO`（HTML 字符串）和 `SECTIONS`（列表，每项 `dict(id, title, html)`），id 用 `<章ID小写>-xxx`。可 `import sys; sys.path.insert(0, '<v-lesson-20261106 目录>')` 后复用 `content.py` 里的 `p, ul, table, fold, say` 等 helper 和 `content_v39.py` 里的 `h3, hand, note`。图用占位 `<!--fig:<key>|<标题>-->`，紧跟 `<div class="v34-howto"><div class="v34-howto-h">怎么看这张图</div>…</div>`；原图用 `<!--original-->`。依据链接用 `<p class="v34-src">依据：<a href=…>…</a> · …</p>`。
3. `diagrams.py`：用 `svgkit.py` 画本章的图，key 用 `<章ID小写>-xxx`，运行后输出 `diagrams.json`（key → SVG 字符串）和 `svg/*.svg`；用 `rsvg-convert` 渲染 PNG 自查压字、穿线、文字溢出。
4. `selfcheck.md`：逐条对照本规范第一节 7 条和第二节结构自查的结果。
