按图逐步读懂
B01 · 车辆与设备状态持续变化
车门、空调、座椅等状态；行驶、充电、导航等状态；车型支持范围与单位要一致。
车辆设备、导航和应用不断产生状态。业务首先确认每个项目实际支持哪些字段、单位和有效取值，不能用另一个车型的能力表填空。例如车窗百分比与开关量不是同一种精度；导航第几个途经点也不等于稳定的某个地点。信号缺失要标为未知，而非默认安全或默认关闭。
B02 · 乘员与手机／应用等信息
座位、已识别身份与权限；应用当前使用和播放信息；按授权与实际接入范围读取。
乘员信息让指令落实到具体对象，应用与手机信息让系统知道播放、行程等背景。已识别人脸、识别到有人、确定用户身份是不同能力。正文列出的潜在数据类型不代表所有项目均已接入或可任意使用；读取权限、账号归属与当前车型支持情况必须独立核对。同车多人也应分别确认信息归属。
B03 · 视觉观察是推断，不是设备值
摄像头画面进入感知模型；记录位置、可见性和观察时间；看不见不等于事情没发生。
视觉语言模型把画面描述成可供业务使用的信息，比如后排是否有人抱着宝宝。这与车门开关这类设备值不同：可能受光照、遮挡、视角影响。画面无法支持结论时应保留未知，不能当成确定未发生。模型还不负责替业务决定“满足条件多久才触发”“播完是否重置”。验收时应加入看不清与看错两类案例。
B04 · 把各种输入对齐成可用状态
字段、位置、时间统一表达；区分当前值与变化事件；保留数据来源和失败状态。
信号管理把不同来源的数据整理成下游可识别的表达。当前车门关闭是一种状态，刚刚关闭是一条变化事件；规则可能需要两者不同组合。字段映射、采样时间、音区与单位一旦错了，即使模型输出正确，也可能控制错误对象或在错误时间触发。具体数据契约要由项目接口确认。
B05 · 判断这份信息还可不可信
有效、缺失、过期分别处理；权限撤回与设备断连可区分；不拿旧状态补成当前事实。
状态有采样与更新周期，不能永久有效。用户换座或路线改变后，旧位置关系与地点序号可能失效。产品需要明确每类状态缺失和过期时是暂停、澄清还是降级，而不是统一默认值。本图不编造通用有效秒数；车型、设备和场景需要分别确认，验收也要刻意模拟断连与恢复。
B06 · 供给 Context 作为本轮背景
按本次请求选相关事实；例如空调已开、外面下雨；Director 据此决定还要做什么。
Context 从已有状态中选出当前请求相关的内容。用户说车里闷，空调已开、正在下雨、后排有宝宝，会改变合适的动作组合。数据中心提供事实，Director 作本轮业务决策，两者不要合并成同一职责。若关键事实没进上下文，应先排查供给与选择，不要直接归咎模型能力。
B07 · 供给端云 Trigger 判断条件
只唤醒相关规则与任务；同一来源可被多种场景消费；唤醒不等于条件成立。
触发器监听与自身场景相关的信号变化。新信号到达可以让它重新检查条件，但不代表已满足整个条件组。例如导航距离更新只负责唤醒检查，还要确认对应任务未过期、目标未漂移、阈值及频控满足。条件组中的且／或只表达组合，不能自动代表先后顺序或持续时间窗。
B08 · 供给静态 Advisor 做建议
按预设服务领域理解情景；判断是否值得提出服务建议；建议还要回 Director 仲裁。
舒适、出行等静态 Advisor 基于相关变化思考服务机会，不直接抢占播报或控制车辆。比如观察到充电等待，可以提出内容服务建议；当前用户正在处理更重要的对话时，应由输入管理和 Director 协同决定何时处理。相关信号、背景与任务目的要一起看，不能每个变化都主动打扰。
B09 · 执行后的真实状态再回流
动作回包之外继续看状态；设备变化写回可用背景；支持后续判断与问题追溯。
工具执行会改变车辆或应用状态，这些变化再通过状态通道回流。如此下一轮知道空调已经开了、歌曲正在播放，而不是从一句“好的”推测结果。回包与状态采样可能有先后差异，验收要检查两者时间线，区分真实失败、状态尚未刷新和错误关联，不能机械把短暂不一致都判为模型错误。
B10 · 先分清状态、事件和意图
状态：当前温度/开关值；事件：某时发生开门/点击/停播；query：用户希望系统做什么。
状态是当前事实，事件是某时发生的变化，用户 query 是希望达到的目标。它们可以一起进入下一轮背景，但不能互相替代。端云协议允许 event 作为一次交互输入，并不代表 event 就是用户说的话。例如播报被打断是系统事实，新的“先导航”才是用户请求；把事件当命令可能误触发车辆动作。
B11 · 记录请求、轮次和结果关联
request_id：关联端云采信请求；round_id：端云协议中的轮次；工具调用/任务运行/音频另有标识。
一个用户目标可能跨多个推理轮次和工具调用；一个周期任务还可能有多次运行。端云协议只把 round_id 写为轮次信息，不能未经接口核实就等同于大模型的每次推理编号。产品应沿同一案例对齐请求、语音轮次、工具调用、任务运行和音频，确认迟到反馈属于谁、何时作废，防止旧结果进入新请求。
B12 · 通知通道送到不等于显示
Frontier 推送事件/动作/任务状态；车端按消息类型分发所属业务；受理、展示和真实执行分层回执。
Frontier 是云端向车端发送消息的通道，不是一个替代业务判断的“大脑”。一条任务建议可能先推送提示，再由车端携标识回调主链；一条 PHUD 消息则去显示系统。要在同一消息或任务上区分云端已发、车端已收、业务已受理、界面已显示、动作已执行，不能用 RPC 成功证明用户已经看到。
