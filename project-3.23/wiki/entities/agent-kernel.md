# 豆包内核

11 月 4 日会议中的设计概念：后台维护对当前情境、人物关系、记忆、自我与内驱需求的持续理解，选择相关背景供后续交互使用。

| 内容 | 会议所谈职责 |
|------|------|
| 世界／情境账 | 理解当下、行程与近期发生的事情 |
| 自我账 | 记录情绪与较稳定的自我认识，更新速度不同 |
| 关系账 | 维护人物关系、对人的认识和偏好 |
| 记忆账 | 筛选整理值得保留的经历 |
| 内驱欲望账 | 描述主动了解用户、做好任务等关注动机 |

五本账是内容组织方式，不据此推断已建成五个数据库、五个服务或五个模型。

实时推理倾向更新当下场面和情绪；后台整理需要反复分析证据、历史矛盾和长期变化。两类输出及与既有记忆的最终边界待确认。

Planner／Director 仍负责当前交互中的决策与执行调度。快频率上下文提前准备在 01:01:14 被明确讨论为不在内核，不应直接合为一个已定模块。

身份连续不等于所有用户能读取全部经历；借车、换人和卖车的范围与迁移规则待确认。完整最终 owner 未由来源确认。
