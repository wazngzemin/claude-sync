### 存在的问题
**从记忆内容的角度：**
1. 短期记忆\&amp;长期记忆的更新存在空白期（更新有延迟）。
影响：容易失忆，前面跟他聊过的事情，后面就忘了（超过历史对话记忆轮次后丢失），又得再来一遍
2. 缺乏对于用户的整体建模——用户画像，对于人的记忆碎片化
影响：生疏感，无法构建持续进步的人和豆包之间的关系
3. 缺乏对于当前情境的整体建模——情境感知（连续时空建模）
影响：
1. 对当前的情境没有追踪，没眼力见
    - 在AI汽车演示场景中，AI需要保持对当前情境的理解和设定，在场景中主动协助用户和推销自己
    - 在周末出游场景中（用户整体情绪轻松愉悦），AI需要保持对当前情境的理解和设定，从而影响处理决策，比如更倾向从游玩、舒适导向解决问题，适时整点乐子，主动提供一些娱乐内容和情绪价值
    - 在通勤上班场景中（用户整体情绪属于平静且效率导向），AI更倾向从效率导向解决问题
    - 用户最近在控制热量，推荐吃的时可以多一些轻食
    - 用户最近在备孕，推荐餐厅时尽量避免酒精、高油、高糖、生冷
2. 影响记忆生成准确性
    - 我们现在来玩反话挑战，真的喜欢时我会说不喜欢，不喜欢时我会说喜欢
3. 记忆无法和情境关联，影响记忆使用
    - 用户喜欢听周杰伦、用户喜欢听英文歌曲 \-\-\-\&gt; 用户单人通勤的时候喜欢听周杰伦、和女友一起出行的时候倾向听英文歌
    - 用户上车后喜欢开座椅通风两档 \-\-\-\&gt; 用户夏天上车时喜欢开座椅通风两档
    - 用户经常把空调温度设置为26度 \-\-\-\&gt; 用户冬天上车时喜欢把空调设置为26度
    - 用户导航时经常选择避开高速 → 用户市区短途出行时导航经常选择避开高速
    - 用户经常开启后视镜加热 \-\-\-\&gt; 雨天且户外上车时，用户都要开启后视镜加热
**从记忆召回及使用角度：**
向量\+关键词检索的弊端：仅匹配表层相似，无法理解深层语义，做不到真正的理解，造成漏召或误召。

## 人类记忆系统
### 人类记忆的科学分类
人类记忆并非单一的存储单元，而是一个由多个子系统协同工作的复杂结构。
从信息处理的流程来看，记忆被经典地分为三个阶段：
- **感官记忆 \(Sensory Memory\)**：这是记忆的入口，信息在这里仅被短暂保留（通常少于1秒），如视觉的“图像记忆”和听觉的“声像记忆”。它为大脑提供了极短的时间窗口来决定哪些信息值得被进一步处理。** **
    **\-\-\-\&gt; 对应我们的数据流**；
- **短时/工作记忆 \(Short\-Term / Working Memory\)**：经过“注意”筛选的信息进入此阶段。**短时记忆**容量有限（乔治·米勒提出的“7±2”魔法数字），信息若不经复述，会在15\-30秒内消失。而**工作记忆**是其动态升级版，不仅临时存储信息，更对其进行主动加工、操控和整合，是推理、理解和决策的核心中枢。** **
    **\-\-\-\&gt; 对应我们的短期记忆**；
- **长时记忆 \(Long\-Term Memory\)**：信息通过深度加工（如精细化复述、构建联系、赋予意义）从短时记忆转入长时记忆，其容量和保存时间几乎是无限的。** **
    长时记忆内部也存在精细分工，主要分为两大类：
    **记忆类型**
    **核心特征**
    **大脑关联区域**
    **陈述性记忆
    ****\(Declarative / Explicit\)**
    **“知道是什么”**
    **\-\-****\-****\&gt; 对应我们的长期情景记忆和长期语义记忆**
    - **可被有意识回忆和言语表达**
    - **语义记忆 \(Semantic\)**：关于世界的事实、概念和常识。例如，“特斯拉是一家电动汽车公司”。
    - **情景记忆 \(Episodic\)**：关于个人亲身经历的事件，包含时间、地点、情感等上下文。例如，“上周日，我和家人开车去了海边，路上听了周杰伦的歌”。
    主要依赖**海马体 \(Hippocampus\)** 和内侧颞叶进行编码和巩固。
    **非陈述性记忆
    ****\(Non\-Declarative / Implicit\)**
    **“知道怎么做”**
    **\-\-****\-****\&gt; 一些“肌肉记忆”**
    - **无意识形成，难以言表，通过行为展现**
    - **程序性记忆 \(Procedural\)**：技能、习惯和运动学习。例如，熟练地调节空调温度、驾驶时的肌肉记忆（老司机可以快速精准地驾车转过每一个不同的弯，但你要问他具体要怎么打方向盘，他也答不上来）。
    - **启动效应 \(Priming\)**：先前接触的刺激会无意识地影响后续反应。
    - **经典条件反射 \(Classical Conditioning\)**：学习到的情绪或生理反应。
    主要与**基底神经节 \(Basal Ganglia\)、小脑 \(Cerebellum\)** 等区域相关。
    **\-\-\-\&gt; 对应我们的长期记忆。**
### **人的记忆有哪些特征**
1. 人的视觉、听觉、触觉、味觉、嗅觉……都在为大脑的记忆系统提供素材，人脑对这些内容加工后，形成记忆，**记忆产生于感知**；
2. 最近发生的事情，记忆会比较清晰，很早前发生的事情，记忆会比较模糊，**记忆会随着时间衰减**。
    > 人类的遗忘并非缺陷，而是一种重要的自适应机制，防止大脑被海量无用信息淹没。艾宾浩斯遗忘曲线揭示了“先快后慢”的遗忘规律，而记忆间的相互干扰（前摄/后摄）也是导致回忆失败的重要原因。
    > 
    > 
3. 人的记忆是**连续**的，包括：
    1. 人对于人的记忆是连续的：
        - 比如对于一个朋友的记忆，这些内容不是碎片化的，而是从过去到现在**一连串共同经历**串起来的：一起吃饭、上学、出游、吵架、和好……经历过的点点滴滴，最终形成一个完整连续的形象，下次跟他对话的时候带着对他的整体认知，而不是只带着他的一些属性片段；
    2. 人对于情境的记忆是连续的：
        - 比如老师教学生一个知识点，第一次教的时候会比较有耐心，第二次的时候可能略微有点不耐烦，第三次的时候老师开始破口大骂你怎么这么不用心……后续想起来时，会记得这个人怎么教都教不会，而不是只召回：第一次教他的时候比较有耐心。
        - 再比如一个开场就非常严肃的会议，严肃的环境会影响会议始终。
4. 一件令人开心、悲伤、心跳加速、意义重大的事情，会被打上“高亮标签”，从而强化这部分的记忆，在后续的场景中更容易被回忆起，影响用户的行为表现，**人的记忆被****情绪****强化**；
    > 情绪会强化人类记忆的存储。情绪并非记忆的干扰项，而是其编码和提取的“强化剂”。高唤醒度的情绪事件（如一次惊喜的旅程、一次烦躁的堵车）会被打上“高亮标签”，形成类似“闪光灯记忆”的深刻印象。
    > 
    > 
### **人的记忆被怎样使用以及对AI记忆系统的启发**
基于几个情境分析：
1. 你叫什么：**脱口而出，肌肉记忆、思想钢印 **\-\-\-\&gt; 对应固定给AI的那些内容；
2. 你过去最难忘的一件事情是什么：**情绪增强，高优召回 **\-\-\-\&gt; 对应情绪强化的记忆内容；
3. 双周会要到了，写一下你的周报吧：**回忆事件，提炼总结 **\-\-\-\&gt; 对应从常规记忆/事件日志中总结出的记忆内容。

整体召回策略上：
1. 第一步：LLM场景标签推理
    - 人类在回忆时，大脑首先会进行一个“剪枝”过程。比如提到“充电”，大脑会自动关闭关于“社会关系”的搜索域。好处是：
        - 减少干扰：向量检索容易产生“语义漂移”。通过LLM先进行标签匹配（\#出行偏好、\#补能偏好、\#美食偏好），可以将检索范围限制在相关领域。
        - 可以改善用户记忆模糊的场景：上次吃过的那个，什么什么酸酸辣辣的特色菜那家
        - 性能优化：在数万条记忆日志中做全量向量匹配比较慢。通过标签做元数据过滤，可以将检索范围瞬间缩小到几百条，提升响应速度。
2. 第二步：基于语义相似度、信息重要性、时效性、情感显著性及情感极性，标签内rerank
3. 第三步：取topn，得到最终结果
**核心收益：**
优化了向量检索的过召和漏召问题。
- 过召：标签提取会更加贴合场景
- 漏召：标签提取能够在记忆召回时就融入场景知识，比如长途出行场景把补能相关的内容也召回，让整个场景不单薄；结合情绪等因子排序，也可以优化漏召问题。

**用户**：“又得去充电了，上次那地方排队太久，烦死了。”

**第二步**：向量\+关键词混合检索：寻找语义上与“排队、充电、体验差”相似的片段

- 有一条记忆是“一年前在某地充电很快”，虽然相似度比较高，但时效性和情感共鸣都比较低
- 另一条记忆是“上周在A站排队50多分钟”，相似度高、时效性高、情感显著和情感共鸣都比较高
**最终表现**：豆包：“是啊，上次在A站等了快一个小时，确实糟心，我来帮你找个附近更快、空闲桩更多的。”

> **新的人上车**的判断方式：
> 
> 基于face id来判断（a or b）：a、车内未注册用户人数有新增；b、有新的已注册用户上车

> 
> face id A、face id B、未注册乘客 ===变为===\&gt; face id A、face id B、未注册乘客、未注册乘客
> 
> face id A、face id B、未注册乘客 ===变为===\&gt; face id A、face id B、face id C、未注册乘客
> 
> 
> 
> 不清敏感信息的场景举例：
> 
> face id A、face id B、未注册乘客 ===变为===\&gt; face id A、face id B
> 
> face id A、face id B、未注册乘客 ===变为===\&gt; face id A、未注册乘客
> 
>

> 敏感信息包含范围：
> 
> 1. 用户表达的情感偏好：
> 
>     1. **判定**：用户主动流露的情绪倾向、关系态度、情绪触发点，或对他人 / 事物的主观好恶。
> 
>     2. **示例**：\&\#34;我不喜欢坐我旁边那个人\&\#34;、\&\#34;今天心情很差\&\#34;、\&\#34;我跟我爸关系不太好\&\#34;。
> 
>     3. **边界**：功能性偏好（\&\#34;我喜欢冷空调\&\#34;）不算；一旦涉及人、关系、情绪状态即归入此类。
> 
> 2. 用户表达的重要地点：
> 
>     1. **判定**：被赋予私人身份标签的地点，而非单纯导航目的地。
> 
>     2. **示例**：\&\#34;我家\&\#34;、\&\#34;公司\&\#34;、\&\#34;我妈家\&\#34;、\&\#34;孩子学校\&\#34;、\&\#34;我常去那家肿瘤医院\&\#34;。
> 
>     3. **边界**：一次性导航 \&\#34;去机场\&\#34; 不算；当地点被命名为 \&\#34;家 / 某人住处 / 某机构\&\#34; 等身份锚点时归入此类。
> 
> 3. 用户表达的重要日期：
> 
>     1. **判定**：带个人身份或家庭关系属性的纪念日、周期性安排、医疗 / 财务节点。
> 
>     2. **示例**：\&\#34;我生日下周五\&\#34;、\&\#34;结婚纪念日\&\#34;、\&\#34;我妈每月 15 号要透析\&\#34;、\&\#34;每月 20 号还车贷\&\#34;。

> 
>     1. **判定**：可直接识别个人身份或关联账户的号码、证件、凭证。

>     3. **边界**：作为文本出现即触发，不论用户是否 \&\#34;主动提供\&\#34;。
>

> 
>     1. **判定**：疾病、症状、用药、过敏、生理状态、就医行为等。
> 
>     2. **示例**：\&\#34;我高血压\&\#34;、\&\#34;最近在吃安眠药\&\#34;、\&\#34;怀孕三个月\&\#34;、\&\#34;腰椎间盘突出坐不了硬座椅\&\#34;。

**共享乘客与记忆生成（SLS）：**
在SLS的定义中，共享乘客当前有两个维度的概念：
- face id维度：一个乘客被车主设置为共享乘客后，该车后续登录其他任何账号时都认识该乘客
- 记忆维度：一个乘客被车主设置为共享乘客后，如果主账号登录期间共享乘客也在车内，记忆会同步地在共享乘客的豆包账号中生成
举例：
假设当前在Car A上登录了豆包账号A，且共享乘客（豆包账号B）也在车内，则后续的用车过程中，除了会生成/补充Car A\&amp;豆包账号A的记忆单位，也会生成/补充Car A\&amp;豆包账号B的记忆单位。

信息的有用性固然重要，比如用户家的地址、上周去过的地方、美食偏好等等。但情感才是构建更好用的记忆系统乃至AI人格的关键（为gpt\-4o献一束电子鲜花），下面这些都是记忆有用性不高，但重要性高的例子：
- 很多年前的一个下午，你和儿时伙伴一起，在门口的那堆沙子当中打滚、挖洞，从下午到天黑，脏到都快认不出来，最后依依不舍地互相道别各回各家，当时只道是寻常，如今忆起只剩恍惚；
- 去年3月8号那天，你开着自己的车，缓缓打开敞篷，晚风轻轻吹进来，小美头发飘在脸上，一边害羞挡着，一边偷偷看着你笑，你们沿着江边慢慢地兜风，这一刻你觉得甜甜的恋爱或许就是这样吧；
- 今年1月23日那天，你开车去了一趟安吉，其实路上的风景平平无常，但因为此行的目的是去策划自己的求婚仪式，所以至今都对路上的花草树木记忆犹深；
- 今年8月19日那天下午，你没有去上班，自己一个人独自驾车在日落大道浪漫出逃，除了风没有别人知道，逃离社会的框架，那天下午你找回了最真实的自己。
- ……
如果将mem0记忆遗忘机制抽象成简单的公式：
```Plain Text
最终得分 = α*语义相似度 + β*信息重要性 + γ*时效性
```
新方案期望在此基础上能够更多的考虑情感因素（即上面提到的情感显著性），在检索时，将情感显著性作为检索后的rerank因子：
```Plain Text
最终得分 = α*语义相似度 + β*信息重要性 + γ*时效性 + δ*情感显著性
```
情感显著性的定义和计算逻辑：
- 定义：记忆存入时，对记忆进行的情感评估并打上的分值
- 计算逻辑：
    - 情绪强度：强烈的快乐、愤怒、悲伤、恐惧（如：用户失业、亲人过世、获得大奖）；
    - 冲突/独特性：与常态不符的事情（如：平时打车下班，今天北京下雪了，选择步行5公里，边回家边感受自然）。
    - 核心用户画像：涉及用户核心偏好或价值观的事情（如用户偏爱二次元、用户提到自己坚决不吃香菜）
- 效果：即使这个记忆是半年前的，且语义匹配度和信息重要性都不是很高，但因为情感显著性比较高，它依然会被顶到模型前面。
上面几个参数决定了AI的性格：
- 工具人模式：α和β比较大，更偏理智，只回答你问的问题，不翻旧账；
- 感性模式：δ比较大，会记着那些让你情绪深刻的事，能更好地照顾用户的情绪；
- 活在当下模式：γ比较大，更关注近期发生的事情。
但只靠上面的公式还是不能全面地评估记忆是否应该被召回。情感包括正向情感和负向情感，二者在召回中不能仅通过显著性来一概而论，应该由时下的情感共鸣决定。
```Plain Text
最终得分 = α*语义相似度 + β*信息重要性 + γ*时效性 + δ*情感显著性 + ε*情感共鸣
```
参考心理学对于情感维度的定义，情感共鸣由记忆的极性以及当前对话的情绪极性决定：
```Plain Text
最终得分 = α*语义相似度 + β*信息重要性 + γ*时效性 + δ*情感显著性 + ε*（Pmem*Pnow）
```
其中Pmem为记忆的极性，\[\-1,1\]；Pnow为当前对话的情绪极性，\[\-1,1\]。新增项提供了同频共振的能力：
- 当 Pmem和Pnow 同号（同为正或同为负）：乘积为正，得分增加。
    - 场景：用户现在很高兴（Pnow＞0\)，模型更容易检索出以前开心的记忆（Pmem\&gt;0）来助兴，“锦上添花”。
    - 场景：用户现在很沮丧（Pnow\&lt;0），模型更容易检索出以前悲伤的经历（Pmem\&lt;0）来共情，“感同身受”，同时做到不戳伤疤。
- 当二者异号：乘积为负，得分减少。这可以防止在用户难过时，模型提起一件大喜事，显得缺乏情商（除非你的策略是“转化”情绪）。
实际使用时：
- 如果Pnom（当前情绪）判断不准，情感共鸣项可能会起反作用。可以给Pnow设定一个置信度阈值。如果模型不确定用户现在是什么心情，就把ε设为0，退回到不带情感共鸣的检索；
- 解决“情感显著性”与“情感共鸣因子”的冗余：在数学建模上，通常会有“情感显著性”≈\|“情感共鸣因子”\|的倾向。
    - 如果一个记忆的极性是0\.9（大喜）或\-0\.9（大悲），它的显著性一定很高。
    - 如果极性是0\.1（平淡），显著性通常很低。
    - 因此，在存储时，可以只计算一个极性值\[\-1,1\]，“情感显著性”自动定义为情感共鸣因子的绝对值，这样可以简化标注工作。
- 在有些情况下，比如悲伤的时刻，模型做不好在检索出悲伤经历时感同身受、不戳伤疤（表现为哪壶不开提哪壶），或者希望能够检索出一些开心的时刻来激励用户，可以动态调整ε，直接将ε置为负，检索出想要的记忆，情绪策略可以是模型来决定的：
    - 模式A：共情验证\(Validation Mode\)\-\-\-“我懂你”
        - 适用场景：用户刚开始表达负面情绪，需要被听见和理解。
        - 逻辑：ε为正，检索相似的负面记忆，但侧重于“感受”而非“事件”。
        - 效果：“我记得上次你加班到深夜时也是这种感觉，那种努力没被看到到的心情真的很糟糕。”（这能建立深度的信任感）。
    - 模式B：情绪修复\(Mood Repair Mode\)\-\-\-“拉你一把”
        - 适用场景：用户深陷负面情绪一段时间，或者明确表现出想要摆脱现状
        - 逻辑：强制将ε设为负值，专门检索Pmem\&gt;0的记忆
        - 效果：“我知道你现在很累。但你还记得去年那个夏天，你最后通过难关时的兴奋劲吗，我们要不要换个思路，找找那次解决问题的感觉?”
- 并不是所有的负面记忆都能拿出来聊。针对一些特殊的记忆，可以在记忆库中增加\*\*敏感\*\*标签，来在检索或使用时区分轻度负面或重度负面（如“亲人离去”、“重大的失败”等），作为一种安全过滤措施。
综上，希望在记忆的rerank机制中，除了考虑语义相似度、信息重要性以及时效性，能够**考虑记忆的情感显著性以及和当前情绪的情感共鸣**，提升结果质量。
