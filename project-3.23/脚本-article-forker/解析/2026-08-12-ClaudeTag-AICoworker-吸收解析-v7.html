人话一个多月前，做 Claude（克劳德） 的 Anthropic 公司在 Slack 里放了一个新东西，叫 Claude Tag。没人热烈讨论，大家都觉得是个小功能。

原文第 12 行

人话公司内部把它当大事。10x Claude Code，意思是价值可能比 Claude Code 大十倍；万亿美元，是说这类产品的市场总量。

原文第 18 行

原文这背后是三种工作模式同时发生迁移：从单人到多人，从被动到主动，从同步单次到异步长程。

人话三对变化一起发生。单人到多人：AI 从服务一个人变成服务一群人。被动到主动：从你问它，变成它自己找活。同步单次到异步长程：从当场办完，变成任务跨几天甚至几周。

你身上你的产品正好踩在第二和第三对变化上：主动 Advisor（主动建议模块） 是“被动到主动”，长时任务是“异步长程”。这篇文章讲的就是你正在踩的那条线。

原文第 21 行

原文Coding（编码） 只是 AI 进入生产力场景的第一步，Claude Tag 以及它所代表的 AI Coworker 类产品形态可能会让 AI 真正走入“替代白领”的阶段。

人话帮程序员写代码只是第一站。下一步是替普通坐办公室的人干活。

原文第 24 行

人话Anthropic 自己的团队已经重度用上 Tag：产品团队写的代码里，超过一半是它写的；有的员工九成工作靠它。

七个细节，把产品边界画出来

人话就像把一个人拉进公司群：它能看这个群的历史消息和文件，谁都可以@它派活，聊天框和文档里都能叫它。

你身上skills 对应你们的 SP（系统提示词） 静态规则，长期目标对应 goal list（目标列表） 和 Task（任务），定时任务对应定时 Trigger（触发器）。文章的机制和你的模块是一套词表的两面。

人话底层的大脑可以换，有好几款。公司管理员定默认款，普通员工也能口头指定“这一件事用更强的那个”。

你身上对应你们 PE（效果评估方案） 和 SFT（监督微调） 两套方案的切换，你正处在“给谁用、哪个版本用”的口径治理里。

人话只在公共群里能@它，按用量算钱，单价和直接调 API 一样，公司付账。私聊它是另一回事，走个人套餐。

你身上你们“公开上下文”和“私有上下文”的边界，就是这类产品的核心决定。车上的公开信息是车辆状态和事件，私有信息是记忆和 face_id（人脸识别号），边界不能混。

原文第 54 行

人话通过一个标准插座接外部软件：代码库、笔记、网盘、数据库，接上就能读能写。

你身上你们正在做的工具契约表，就是座舱版 MCP：意图边界、参数、前置状态、失败返回。方向一样。

原文第 56 行

原文Runtime（运行环境） 全部由 Anthropic（做 Claude 的公司） 云端托管，每个 thread（会话线） 起一个临时 sandbox（隔离小房间） 跑完整 agent loop（智能体循环），底层复用的是 claude managed agent（Claude 托管智能体） 的 tech stack（技术栈）。

人话每次任务都在 Anthropic 的服务器上开一间隔离小房间，AI（人工智能） 在里面自己循环干活：想一步、做一步、看结果、再想，干完拆掉。

03 · 第二章：三个关键能力

入口不重要，三件事才是真功夫

原文第 80-86 行

原文Claude Tag（克劳德团队版） 并不是一个多新的产品形态。过去半年多，市面上已经出现了非常多把 AI（人工智能） 放进协作场景的产品。最早的是 Devin（同类产品），最火的可能是 OpenClaw（同类产品）。但这些产品最终没有大规模铺开……背后的核心原因是模型能力还不成熟，Anthropic（做 Claude 的公司） 的团队认为，其实模型只有到了 Mythos（高端模型名） 级别，才算真正解锁了 AI Coworker（AI 同事） 的产品形态。

人话作者先自认这不是新点子：把 AI 拉进群，前两年就有人做。没做起来，是因为当时的模型不够强。Anthropic 自己说，要到 Mythos 这个级别才算够。

第一件事：Long-horizon autonomy（长时间自主能力），能自己干多久

原文第 97 行

原文模型能自主工作的时间，最大程度上决定了 AI 最合适的产品形态。

人话AI 一口气能干多久，决定了它该长成什么样。

原文第 103-107 行

原文当模型只能连续自主工作几分钟时，最合适的是 chat（聊天） 或 autocomplete……当它能推进约 1 小时的任务时，local coding agent（本地编码智能体） 开始成立……只有稳定工作数小时之后，才值得做 async agent（异步智能体）：用户下班了，Agent（智能体） 仍在云端自主推进，最后带着结果回来。

人话三档对应三形态：只能干几分钟，就做对话框，人全程盯着；能干一小时，做本地编码助手，人在旁边随时接手；能干几小时，才做异步同事，人下班它继续，完事带结果回来。

你身上“到终点前 1km 提醒我”就是 async agent 的最小样本。它要求系统自己等条件、自己醒来、提醒完自己关任务。

原文第 111-117 行

原文按照最新的 METR（AI 评测机构） 评测，Mythos 已经能完成大约相当于人类专家连续工作 16 小时的任务。Claude Tag 又在此基础上增加了 Self-schedule（自我排程）……比如，下周三回来检查实验数据。于是，单次 16 小时的执行能力可以被连续串联起来，变成持续几个月的长期任务。中间的等待、唤醒和衔接，都由模型自己完成。

人话作者说 Mythos 一口气能干人类专家 16 小时的活。Self-schedule 是“自己给自己设闹钟”：今天干不完，把下一步排到下周三，到点自己醒，接着干。16 小时一段一段串起来，就成了几个月的大任务。

你身上文章叫 Self-schedule，你们叫定时 Trigger（触发器） 加条件 Trigger 加 Task（任务） 生命周期。名字不同，干的是一件事。

第二件事：Memory（记忆），记忆怎么做

原文第 124-127 行

原文记忆对 Tag（团队版数字员工） 很重要，模型需要能真正记住人类交代的 to-do（待办）、方法和风格偏好，并把单次经验迁移到未来的任务中。Anthropic 尝试过很多记忆方案，最后发现，最好用的就是最朴素的文件系统，给模型一块可以长期读写的空间，放手让它自己维护。

人话记忆要记住三样：你交代的待办、做事的固定方法、你喜欢什么风格。他们试了很多花哨方案，最好用的是最土的办法：给模型一个文件夹，让它自己写、自己改、自己删。

原文第 129-137 行

原文这并不意味着每只 Claude（克劳德） 都可以随意翻看全公司的信息。Tag 的记忆会按照权限分层……每只 Claude 只能看到自己所属频道里的 Context（上下文），只有获得授权后，它才能走出房间，去其他频道浏览信息。最终，Tag 的整套记忆库分成三层……Thread context（任务级上下文）：当前任务相关的对话和工作过程；Channel memory（群级记忆）：这个频道长期稳定的规则、决策、项目背景；Workspace memory（公司级记忆）：整个公司的记忆，可以被同一 workspace（工作区） 的其他公共 channel（频道） 复用。

人话记忆分三层，权限像办公室。第一层 Thread，当前这一件任务的过程，干完就归档；第二层 Channel，这个群的长期规则和决定；第三层 Workspace，全公司公共知识，别的群也能用。没授权不能串门。

你身上Thread 等于任务级 Context；Channel 等于车企、车型、版本的真值；Workspace 等于通用工具契约和评测。车内还多三层：人物、车辆、驾驶安全。

原文第 143-149 行

原文“我发现的一些最有意思的东西是：低阶模型和高阶模型之间的主要区别，就在于蒸馏（distillation（蒸馏，提炼规律））能力。高阶模型更能判断出怎么对记忆进行高维抽象，它们不光记录具体事件，还会真正思考，这段经验以后还能泛化到什么地方。”

人话这段话是引用 Anthropic 内部人的话。蒸馏在这里是比喻：把经历“熬浓”成经验。低阶模型只会记流水账；高阶模型会想：这件事说明了什么规律，以后哪种情况还用得上。

你身上你们的动态示例就是这个道理：好例子是抽出来的规则，坏例子是堆上去的个案。这也解释了为什么动态示例要按车企、车型、版本治理，而不是越多越好。

第三件事：EQ（情商），什么时候主动、什么时候闭嘴

原文第 156-159 行

原文Anthropic 还专门训练了 Claude Tag 的情商和分寸感，让它能判断出来什么时候该主动帮忙，什么时候该退居幕后。(我们自己试用完也觉得 Tag 比 Claude Code（克劳德编码助手） 情商明显高一个 level（档位），沟通起来非常舒服，很有活人感，表情包也用得相当熟练。)

人话专门训练它看时机：什么时候插话帮忙，什么时候别出声。作者自己用下来觉得它比 Claude Code 会做人，表情包都发得顺。

你身上你们群里正在问的三件事：AI push（推送） 展示多久、能不能并行、跟别的卡片谁让谁。这就是 EQ 的产品化，必须有人拍板规则。

04 · 第三章：它解锁了什么

两类新工作，加一个四问筛法

原文第 167 行

原文短期来看，Claude Tag（克劳德团队版） 主要接手的还是基础执行工作，角色更像一个初级运营、行政或工程师。

人话先别想太远。现在它能接的是入门级执行活：初级运营、初级行政、初级工程师的日常。

原文第 173-179 行

原文1.高协作密度、高 context（上下文） 密度类工作。Claude Code（克劳德编码助手） 本质上还是单人模式……需要人类先把 Context（上下文） 压缩、整理，再喂给模型。Claude Tag 则常驻在公司群聊里，天然了解一件事情的来龙去脉，所有人也都可以直接跟它协作，随时补充和纠偏。

人话第一类活：事情的前因后果散在很多人和很多消息里。老工具 Claude Code 是一个人用，得你先整理背景再喂给它。Tag（团队版数字员工） 常驻群里，自己看着事情发生，谁都能插话补充、纠正它。

你身上你们的 Context 服务就是“人打包喂”的高配版：13 类信息提前过滤。Tag 的模式提醒你，过滤之外还要保证信息是“当场的”，别用旧版本替现场。

原文第 182-190 行

原文2.主动响应类工作。Chat/Code/Cowork（聊天/编码/同事） 都是人类主动发起的……Tag 则可以主动发现问题并揽下工作。比如下面这个 demo（演示），线上突然出事了，它可以自己拉取监控、定位问题、编写修复，然后找相关负责人审批，人只需要点个最终同意。

人话第二类活：没人喊它，它自己发现有事。例子是线上系统挂了，它自己一步步来：拉监控数据、找到问题、写修复代码、找负责人审批，人最后点一下同意就行。

你身上你们的“媒体卡片无故弹出”，就属于这类主动响应。但车上的修复动作风险更高，先做到“识别和分诊”，自动修复必须等权限、回滚、审批齐了再说。

原文第 193-196 行

原文很多时候组织内存在盲区……比如有人提了个 edge case（边界情况） 没人跟进、客户反馈里藏着一个重复 pattern（规律）。很多事情没人觉得这是自己的职责，Claude Tag 有能力自行提出来，自行包揽。总体来看，(1) 越需要协作的、(2) 越依赖 context 的、(3) 越需要及时响应的、(4) 越碎片越 dirty（脏活） 没人愿意做的，越适合交给 Claude Tag。

人话公司里总有没人管的边角：有人提了个特殊情况没人跟，客户反馈里同一个问题反复出现但没人统计。这些事没人当自己的活，Tag 能自己认领。文章给了四问筛法：要不要多人配合、要不要大量背景、要不要马上反应、是不是没人要的脏活。四个都沾，就适合它。

原文第 202-207 行

原文产品团队约 65% 的代码都由它生成；新人遇到法务、HR（人事） 等 onboarding（入职流程） 问题会直接 @Tag；客户反馈频道里的 bug（缺陷） 和数据频道里的所有查数问题，也普遍先交给它处理。不少员工还会把它当成一个贴身秘书，让它在几十上百个 Slack（企业聊天软件） 频道中筛选重要信息、跟进多个 feature（功能），并自动生成总结。

人话内部用法举例：新人办入职问法务 HR 找它；群里报的 bug 和查数据找它；还有人把它当秘书，让它在一百个群里筛重点、跟进多个功能、自动出周报。

原文第 208 行

原文长期来看，如果模型质量提高，Claude Tag 则可以完整替代一个人类员工，甚至成为整个公司的 OS（操作系统） 系统。

人话远期想象：模型再强一点，它能顶一个正式员工，甚至当整个公司的操作系统。

内部三个雏形，是全文最惊艳的部分

08 · 黄钊评注

他的 11 段评注，一段一段看

黄钊把这篇评为“今年年度最有价值”，并把它拆成 11 段。他的手法值得你学：不重述原文，只挑产品视角的关键点做评注。下面逐段看他到底在说什么。

评注 a

黄钊产品形态细节：Slack（企业聊天软件） 公共频道、按量记账、私聊不算、MCP（工具接入协议） 全接、五模型切换、云端沙箱。他的评注是：Agent（智能体） 在“群”里中转加工各种信息，会是 AI（人工智能）-native 组织的核心特征；2B 和 2C 在这个模式上是相通的。

人话他挑出的重点不是功能列表，是“在群里中转加工信息”这个位置。他的判断：未来公司会围着“AI 在群里”长出新组织方式，而且这个模式和做消费者产品是同一条逻辑。

你身上你的车就是 2B 和 2C 连在一起的样本：车企是客户，坐车的是个人。这是黄钊说“通”的真实例子。

评注 b

黄钊“模型能自主工作的时间，决定 AI 最合适的产品形态”，他说能尽早洞察这一点非常难。

人话他把原文第 97 行那句单独拎出来表扬，因为大部分人只会看“强不强”，不会看“一口气能干多久”。

评注 c

黄钊记忆三层，加上他本人最爱的一句：“能有时做 A，但有时又需要做 B（A 的反面），这个 feature（功能），是真正的 AI（智能）跟旧规则模式的核心分水岭。”

人话他的判断标准：同一个东西，有时该主动、有时该闭嘴；有时该坚持、有时该退让。旧规则只能定死一条，真智能能看情况选。会用“有时这样、有时相反”来做事，就是智能和规则的差别。

你身上你们的 Advisor（主动建议模块） 就是同时要“有时主动、有时沉默”，模型给判断，频控和互斥守底线。

评注 d

黄钊相比 Claude Code（克劳德编码助手），Tag（团队版数字员工） 解锁两类工作：高协作高 context（上下文） 密度、主动响应。他把原文的“四问”原样保留。

11 · 明天做什么

三件事，每件拆到能直接照做

明天 Bug（缺陷） 日清会，把 AI（人工智能） push（推送） 三问单独提出来，当场要拍板人。

你今天读到的群里已明确三个未决点：展示时长、多个 push 能否并行、与其他卡片互斥。会前先在群里把这三个问题复制成一行待办，会上直接念。

会上说：“Bug 之外有一个产品问题需要拍板。AI push 的展示时长、并行上限、卡片互斥，这三点今天不确认，主动服务下周还有新票。请明确 Owner（负责人） 和时间，我按结论补规则。”

完成证据：会后有一句话的结论加一个 Owner 名字，写进产品群。
给长时任务做七段证据表，先只做两个 case（案例）。

“距终点 1km 提醒”和“歌曲结束后停止”。每条填七格：用户原话、TaskSpec（任务规格）、任务状态、订阅事件、回调、执行、关闭。缺哪格标哪格，再找对应 Owner 要日志。

对研发说：“先不修模型。给我这两条 case 的七段日志，第一次偏离在哪一层，就改哪一层。缺的段我标出来，我们按段补证据。”

完成证据：一张表，两个 case，每格要么有日志出处，要么标了缺。
用判断器筛场景，只挑一个进 Task（任务）+Trigger（触发器）。

距终点 1km 提醒最适合先跑通。宝宝哭、媒体卡异常、通勤内容编排按四道硬门降级：事实、动作、权限、可验收，缺一项就不进自动执行。
