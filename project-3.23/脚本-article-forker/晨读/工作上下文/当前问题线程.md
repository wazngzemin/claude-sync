### 我的判断

这条线已经不再是一个“触发器功能需求”。它正在变成 Driver Agent 的运行时底座。你需要守住的核心契约是：

## 线程 2：动态示例、动态知识与评测

### 当前已经暴露出的三个层次

1. **内容层**：示例本身有没有错、是否冲突、是否重复。
2. **检索层**：目标 Query 是否命中正确示例。
3. **使用层**：命中后，DT 是否真正参考；最后通过是否真由这条例子造成。

你过去的工作主要在内容层补例子，现在最应该补的是后两层的可观测性。否则“实测通过”只能说明这一次成功，不能证明动态示例机制已经可靠。

### 当前最需要的验收指标

- 示例召回率：目标 Query 是否检索到目标示例。
- 示例采用率：输出是否遵循示例里的关键决策。
- 修复通过率：目标 badcase 是否通过。
- 负向影响率：其他原本正确的 case 是否被带坏。
- 版本正确率：当前车企/车型/PE 是否拿到属于自己的示例。

## 线程 3：导航、POI 与高德 Agent
