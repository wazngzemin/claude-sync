>

>
> 本文区分三类内容：「会议结论」用于确定本期方向；「需求补充」用于明确可验收的产品行为；「待联调确认」用于标识输入、接口和执行时序尚未验证的部分。待确认项不再包含是否新增新手引导 Agent。

## 1. 需求概述

用户尚未了解身份识别、记忆等能力时，豆包需要在相关对话或明确业务节点中介绍能力，并在用户愿意使用时承接后续操作。现有方案的主要缺口是场景判断与条件判断的衔接、引导建议进入当前对话的时机，以及下发后是否被实际处理的反馈。

本期在现有配置、触发器与 DT 链路中补齐这些能力。DT 即 Director，也是 Planner，负责结合用户原始请求和引导建议组织回复、调用工具并处理结果。**本期不新增独立的新手引导 Agent，不建立第二套对话推理与执行编排。**

对话类场景采用「预设场景描述及示例 → 单模型判断语义相关性 → 触发器判断组合条件 → 向 DT 下发预设引导建议 → DT 沿现有链路执行 → 回传处理状态 → 触发器计次并结束」；明确业务事件直接进入触发器条件判断，不强制经过语义模型。

## 4. 目标与验收指标

本期目标是在明确场景中完成适时、有限次、可追踪的能力引导。用户原任务应正常承接，系统能够说明某次引导为何触发、DT 是否处理、是否实际播出，以及用户是否进一步完成了功能操作。

| 目标 | 统计与验收方法 | 不得替代的结论 |
| --- | --- | --- |
| 找到相关场景 | 对场景正例、泛化表达、反例分别评测命中与误触发 | 不要求枚举全部用户表达；不虚构准确率承诺 |
| 条件判断准确 | 对每个条件记录事实来源与成立／不成立／未知 | 语义命中不能证明首次使用、已授权或次数剩余 |
| 建议进入正确轮次 | 对关联原请求、DT 接收和开始处理的时间进行联调 | 请求已发出不能证明 DT 在回复前使用了建议 |
| 次数可控 | 每次对应处理仅计一次；达到配置上限后停止该主动引导 | 重复反馈、接口重试不得多扣次数 |
| 触达可观察 | 分开统计 DT 处理、播放开始、完成及中断 | DT 开始推理不等于用户已经听到或理解 |
| 功能结果真实 | 身份注册、记忆读写以工具业务结果为准 | 能力介绍或工具调用发出不等于功能使用成功 |

时延验收重点为「引导建议能否进入当前轮回复」。晚间会上提及的 200–300 毫秒及其他时延数字分别涉及已有路径或讨论目标，不能直接作为新链路端到端承诺。需在真实环境测量语义判断、规则判断、建议交接和 DT 处理各阶段耗时，再确定发布门槛。

## 5. 适用用户与场景范围

沿用按账号管理引导次数的业务方向，车辆用于承载和车型能力判断，当前说话人用于判断是否适合执行身份或记忆操作。登录账号不自动等于当前乘客；无法确认关联时，不将另一人的信息或使用记录写入该账号。

## 6. 用户价值与交互原则

用户应在当前诉求中理解功能能解决什么问题，并自行决定是否使用。引导介绍与功能执行分开：询问“是否愿意注册”不代表已注册，介绍“可以帮你记住”不代表已写入记忆。

1. **原请求保留。** 触发器向 DT 增加引导建议，不将用户输入替换成引导话术。DT 应结合二者生成自然回复，避免用整段功能介绍掩盖用户当前需求。用户已明确请求功能操作且无需介绍时，DT 不采用该引导建议，只执行原请求，不将该次正常功能推理回传为引导处理成功。
2. **明确请求直接承接。** 用户已主动要求注册、记住或查询时，优先走正常功能流程；必要的身份或授权说明由该流程承接，避免再叠加重复介绍。
3. **事实判断有来源。** 注册、授权、使用、同步及次数分别读取实际状态，缺失不自动等于否或首次。
4. **处理与触达分开。** 本期以 DT 开始对应推理作为处理成功计次依据；实际播放与功能成功另记。此口径用于限制重复处理，不能将账号标记为“已经知晓全部能力”。
5. **过期建议不补播。** 当前轮已回复、账号切换或场景失效后，不将旧建议插入新的无关对话。

其中第 1、3、4 项对应晚间会议链路边界；明确请求优先、未知退出、重复抑制及迟到处理为本稿补充的产品规则，需纳入验收。

### 7.1 总体链路及模块边界

**图 1：新手引导现有模块协作链路**

<whiteboard type="blank"></whiteboard>

配置平台保存场景描述、示例、组合条件和需要 DT 完成的引导目的。语义模型只回答“当前表达是否与某个已配置场景相关”；触发器接收该结果，再检查账号状态、首次或次数、端状态等组合条件。全部满足后，触发器向 DT 提供 advice，即预设的引导建议。DT 负责实际对话及功能操作。

记忆同步完成等明确事件不依赖用户说出某句话，直接作为触发器的输入条件。工具返回前置条件不足时，DT 依据真实 tool_feedback（工具执行反馈）完成必要说明；这条正常执行路径也不要求经过语义模型。

| 模块 | 输入 | 输出与责任边界 |
| --- | --- | --- |
| 场景配置 | 产品定义的描述、典型示例、条件、引导目的和次数 | 发布可被识别及执行的场景；语义描述与对应规则保持同一版本 |
| 语义匹配模型 | 当前用户表达、已启用的语义场景候选 | 返回相关场景或无匹配；不查询记忆、不判断业务首次、不自行发起功能操作 |
| 功能与账号模块 | 实际功能运行及身份信息 | 提供可关联的状态或事件；不把分析埋点自动视为业务状态接口 |
| 触发器 | 语义结果或事件、真实状态、配置次数 | 判断组合条件、去重、下发建议、接收处理反馈并计次 |
| DT／Planner | 原请求、触发器建议、既有对话及工具结果 | 组织回复、生成 action_list（下游动作列表）、调用工具、依据结果继续判断 |
| 下游工具及端侧 | DT 的具体动作或播报内容 | 执行功能、呈现交互并返回真实结果 |

不新增“新手引导业务总控”来重复读取上下文、选择工具或追踪全部执行。触发器只管理本场景的条件和计次，复杂对话判断及记忆检索留在 DT 既有链路。

### 7.2 场景配置与生效

配置对象是产品预设场景，不是用户每说一句话就注册一个新任务。新增语义场景时，将该场景的描述和示例同步到模型候选，同时使对应规则与建议生效；明确事件场景只配置事件及规则。

| 配置项 | 业务含义 | 要求 |
| --- | --- | --- |
| 场景标识及版本 | 将一次识别、判断、建议和反馈归到同一场景 | 可追溯配置变更；示例标识不等于已确定接口字段 |
| 入口类型 | 用户表达、业务事件或既有工具反馈 | 区分适用链路，不强制全部进入模型 |
| 语义描述及示例 | 定义何时适合介绍该功能 | 提供典型正例、边界反例及明确功能请求；不逐句穷举 |
| 组合条件 | 账号、身份、授权、首次、次数及所需端状态 | 每项写明事实来源、未知处理和缺失影响 |
| 引导建议 | 希望 DT 达成的目的、可提内容和动作限制 | 描述如何结合原请求；不只存一段脱离场景的固定 TTS |
| 次数和范围 | 对哪个账号、哪个场景限制多少次 | 身份补引导按源表后续一次；其余场景在配置评审中明确 |
| 启停及退出条件 | 场景是否启用、何时结束 | 停用后不产生新建议；旧建议按有效性处理 |
| 处理结果关联 | 识别本次建议是否进入 DT 对应推理 | 支持重复反馈去重，避免将其他对话误算为处理成功 |

“是否首次”必须注明是首次调用、首次成功使用还是首次处理引导，三者不能互换。语义模型不承担这些事实判断。场景表尚未明确的次数、拒绝抑制范围及跨车共享范围列入评审，不借用会上举例的 2 次、3 次作为默认值。

### 7.3 对话类场景运行流程

**图 2：语义匹配至处理反馈的主流程**

<whiteboard type="blank"></whiteboard>

| 步骤 | 谁做什么 | 交给下一步的信息 | 退出与异常 |
| --- | --- | --- | --- |
| 1 | 对话入口提供本轮用户表达 | 当前请求及必要的账号关联信息 | 原对话继续按现有流程处理 |
| 2 | 语义模型对已配置候选做相关性匹配 | 命中的场景或无匹配 | 无匹配、结果异常时结束本次引导机会 |
| 3 | 触发器定位场景并读取组合条件 | 状态事实、次数及当前适用性 | 未知或条件不成立，不下发建议 |
| 4 | 触发器对本轮候选进行去重与冲突处理 | 最终待下发场景和预设建议 | 不叠加多段重复能力介绍 |
| 5 | 触发器在当前轮接收窗口内向 DT 交接 | 原请求关联、引导目的和限制 | 已错过窗口则结束当前机会，不跨话题补播 |
| 6 | DT 判断建议是否需要采用，再结合原请求进入对应处理 | 本条建议的处理开始状态，或未采用及原因 | 若用户已明确请求功能操作、无需介绍，DT 不采用该引导建议，仅执行原请求；不回传本条引导处理成功，不扣引导次数 |
| 7 | DT 组织回复或调用工具 | talk_content 或 action_list，随后接收 tool_feedback | 工具失败按真实结果回应；不得虚构成功 |
| 8 | 触发器依据对应处理反馈计次 | 本次处理结果及剩余次数 | 达上限停止主动引导；重复反馈不重复计次 |
| 9 | 端侧及功能模块提供后续结果 | 播放开始／完成／中断，注册或记忆业务结果 | 结果缺失保留未知，不反推用户已听到或功能已成功 |

第 8 步的计次依据是第 6 步的 DT 对应处理反馈，可在工具执行或播报完成前发生，不要求等待第 7 步全部执行结束。流程表按业务信息展开，计次与执行结果统计分别进行。

一轮同时命中身份与记忆介绍时，本稿建议优先解决当前功能必需的身份前置问题，避免双重介绍。语义模型是否输出多个候选、冲突优先级如何配置需要在接口与产品评审中确认，不能把会上“输出 1 或 2”的举例视为固定协议。

### 7.4 场景一：身份感知补引导

**场景描述。** 提车当天跳过 FaceID 注册的乘客，后续在个人称呼、个人偏好、希望被记住或认识新朋友等相关对话中，获得一次注册能力提示。呈现采用 TTS 及适用的轻量卡片，内容说明注册作用及“看哪里、说什么”，操作沿用车型已有注册流程。

**图 3：身份感知补引导链路**

<whiteboard type="blank"></whiteboard>

| 项目 | 产品规则 |
| --- | --- |
| 示例输入 | “以后叫我小王，我喜欢吃川菜。”这是相关性示例，不单独构成注册授权 |
| 语义条件 | 表达与认识用户、称呼、个人偏好或记住用户相关 |
| 身份资格 | 能确认提车时跳过注册，且当前相关对象仍未注册；未注册不能代替“提车时跳过” |
| 组合条件 | 账号及对象关联明确、场景启用、补引导次数未耗尽、当前注册能力可用；必要状态均有真实来源 |
| 触发动作 | 触发器向 DT 提供身份引导建议，DT 结合当前诉求说明注册价值并询问是否愿意注册 |
| 功能执行 | 用户同意后，DT 调用既有身份注册工具并处理返回结果；不因语义命中直接注册 |
| 结束规则 | 对应引导处理成功达到配置的一次上限，停止该项主动补引导；后续主动注册请求照常执行 |
| 资格缺失 | 不能确认跳过记录或对象关联时，原表主动补引导不触发；不影响正常工具流程中的必要说明 |

**建议配置示例（需求示例，非固定话术）：** 结合用户希望被识别或被记住的诉求，简短说明注册身份后可以更好地区分使用者，询问是否愿意注册；用户同意前不要启动注册操作，不替用户承诺已经完成。

**一次完整执行。** 用户提出称呼与偏好 → 模型匹配身份场景 → 触发器确认提车跳过记录、仍未注册及次数剩余 → 向 DT 提供建议 → DT 进入对应推理并回传 → 触发器计一次处理 → DT 解释注册价值并询问 → 用户同意 → DT 调用身份注册工具 → tool_feedback 返回成功或失败 → DT 如实回应。引导处理计次和注册是否成功保持分离。

**工具反馈入口。** 若用户主动使用某功能，工具返回缺少身份前置条件，DT 可以基于反馈说明如何补齐身份。这是当前任务的必要处理，不能仅凭该反馈认定用户属于“提车跳过注册”的人群。若同轮已做必要身份说明，不再叠加一段主动补引导；该说明是否消费主动引导次数需要定义对应场景关联与回传，不能由调用次数推断。

### 7.5 场景二：记忆能力引导

**场景描述。** 用户在对话中表达个人偏好或信息，且仍符合引导资格时，介绍豆包可以帮助记住信息的能力。该场景旨在让用户理解如何使用记忆，不要求先查询一条历史记忆。

**图 4：记忆能力引导链路**

<whiteboard type="blank"></whiteboard>

| 项目 | 产品规则 |
| --- | --- |
| 示例输入 | “我平时比较喜欢吃川菜。”可作为介绍记忆能力的语义候选 |
| 明确请求分支 | “记住我喜欢吃川菜。”应由 DT 优先承接正常记忆操作，避免先播一段重复功能介绍 |
| 组合条件 | 当前对象与账号关联可确认，场景处于启用状态，相关次数和适用条件满足；使用状态需由功能模块提供 |
| 触发动作 | 触发器提供“结合当前话题介绍记忆作用”的建议，DT 自然承接原请求 |
| 操作边界 | 按记忆模块既有身份和授权要求执行。用户随口表达不自动作为本场景额外记忆写入的许可 |
| 用户同意后 | DT 调用既有记忆操作工具，根据 tool_feedback 说明是否成功保存 |
| 无需介绍 | 明确请求已被正常承接、功能使用事实表明无需引导、次数已达上限或用户明确拒绝当轮操作 |
| 特殊边界 | 记忆检索为空不等于从未使用；转述他人偏好不等于当前用户偏好 |

**建议配置示例：** 在当前话题中简短介绍记忆能力能帮助持续记住用户希望保留的信息，给出与本次表达相关的使用方式。涉及实际记忆操作时，遵循功能自身的身份、授权及执行规则，并以真实结果回应。

**一次完整执行。** 模型判断当前表达与记忆能力相关 → 触发器检查真实条件与次数 → 下发建议 → DT 进入对应推理，触发器计次 → DT 介绍能力并承接用户选择 → 用户进一步要求记住 → DT 调用记忆工具 → 工具返回结果 → DT 告知保存成功或失败。模型不查询旧记忆，触发器不代替 DT 写入记忆。

### 7.6 场景三：记忆同步完成后问候

**场景描述。** 用户在开箱流程中选择记忆授权并完成同步后，豆包结合一到两个真实记忆点进行问候，让用户感受到历史信息已被承接。这是明确事件驱动场景，不经过语义相关性模型。

**图 5：记忆同步完成后的问候链路**

<whiteboard type="blank"></whiteboard>

| 项目 | 产品规则 |
| --- | --- |
| 启动条件 | 用户选择授权及同步；未授权时不启动这项记忆问候 |
| 准确事件 | 记忆同步完成。激活完成、授权完成、开始同步均不能替代 |
| 身份限制 | 开箱 FaceID 可以跳过，不额外将注册完成设为此问候的必备条件；检索仍遵循记忆工具已有权限规则 |
| 组合条件 | 完成事件属于当前账号和本次有效同步，场景可用且未重复处理，当前仍处于合适的开箱交互阶段 |
| 触发器动作 | 下发预设 advice，要求 DT 查询可用记忆并选取一到两个合适信息进行问候 |
| DT 动作 | 调用记忆检索工具 → 接收真实 tool_feedback → 按结果选择内容 → 沿现有语音链路输出 |
| 结果处理 | 触发器按 DT 对应处理反馈计次；记忆检索、播放结果单独记录 |
| 空或失败结果 | 不编造记忆点。可按开箱既有流程继续普通问候，但不能记为已完成个性化记忆问候 |
| 结束与失效 | 重复事件不重复播报；账号切换、旧批次或交互时机已过时结束旧机会 |

**建议配置示例：** 本次账号的记忆同步已完成，请检索当前可使用的记忆，选择一到两个适合在当前场合提及的信息组织简短问候；检索无结果时不要编造用户经历或偏好。

**一次完整执行。** 记忆模块发出同步完成事件 → 触发器核对账号、批次、次数与交互条件 → 向 DT 下发建议 → DT 进入对应推理并反馈 → 触发器计次 → DT 调用记忆检索 → 工具返回真实信息 → DT 选取一到两个点生成问候 → 端侧播放并返回实际状态。

本链路无需把记忆正文塞进触发条件，也无需由新 Agent 先读取记忆。晚间 26:31 明确触发时点，28:40–28:54 明确由 DT 接收配置文字后检索并问候。[晚间文字记录](https://bytedance.larkoffice.com/docx/Vz57dXaeYoHHECxEuytcsDROn9b)

### 7.7 成功反馈、计次及结束规则

**图 6：DT 处理反馈与触发器计次**

<whiteboard type="blank"></whiteboard>

**本期处理成功口径：DT 已针对本条引导建议开始对应推理。** 晚间会末明确将成功判断从触发器“任务触发／advice 下发”向下推进至 DT。因此本版不再把播报开始、播报完成与 DT 推理列作平行待选计次方案。具体如何证明 DT 处理了本条建议，需要 DT 与触发器完成回传协议和联调。

| 阶段 | 能证明什么 | 是否增加本期处理成功次数 |
| --- | --- | --- |
| 语义匹配命中 | 表达与场景相关 | 否 |
| 组合条件成立 | 本次满足触发规则 | 否 |
| 建议发出 | 触发器尝试交接引导建议 | 否 |
| DT 开始对应推理 | DT 已处理本条建议，而非只在处理其他对话 | 是，同一关联记录仅一次 |
| 端侧开始或完成播放 | 用户端实际出现播放行为 | 不再重复计次，单独统计触达 |
| 用户拒绝或中断 | 本次操作意愿或播放结局 | 不回写成业务成功；不因已计次而自动重播 |
| 功能执行成功 | 注册或记忆操作实际成功 | 不重复计引导处理次数；更新该功能真实状态 |

触发器维护按账号、场景及适用版本可追溯的处理记录。下发重试与回传重试必须关联同一条建议，不能产生多次成功计数。反馈属于哪个账号、场景、请求或业务事件，需要接口携带足够关联信息；本文不将这些业务要求写成已经上线的字段名。

处理反馈缺失时，状态为待确认或未知，不凭建议发出扣成功次数，也不立即再次下发。应先通过对账或有效期处理完成收尾，避免在无法确认 DT 是否已处理时反复触达。具体超时与对账方式由接口设计补齐，不预填无依据的秒数。

达到配置上限后，停止该账号对应场景的主动引导。停止引导不阻断用户主动使用功能。不同场景分别计次；一次身份引导不能同时扣除未实际处理的记忆引导次数。实际功能使用、用户停止意愿是否提前结束引导及其作用范围，由场景配置定义并使用真实状态。

### 8.2 关键验收用例

| 用例 | 前提与触发 | 预期链路与结果 |
| --- | --- | --- |
| 身份补引导正常 | 跳过记录明确、仍未注册、次数剩余，相关表达 | 语义命中 → 条件成立 → 建议进入 DT → 对应推理计次 → 引导；同意后走注册 |
| 身份资格未知 | 只知道未注册，不知道提车是否跳过 | 原表补引导不触发；正常功能所需身份说明仍可执行 |
| 次数耗尽 | 同账号场景已达到配置上限，再次相关表达 | 不再发送主动建议；主动注册请求不被阻断 |
| 记忆能力介绍 | 相关话题、适用条件成立 | 介绍能力，不为介绍而强制检索旧记忆 |
| 明确记忆请求 | 用户直接要求记住信息 | DT 走正常功能流程，按真实反馈回应，避免重复介绍 |
| 语义无关 | 普通问候或其他无关请求 | 不触发引导，不影响原回复 |
| 同步尚未完成 | 已激活／已授权，但同步未结束 | 不触发基于记忆的问候 |
| 同步完成且可检索 | 当前账号有效完成事件，工具返回真实记忆 | 事件直接进入规则，DT 检索后选一到两个点问候 |
| 未授权或检索失败 | 未授权，或授权同步后检索失败 | 前者不启动该问候；后者不编造个性化事实 |
| 建议晚到 | DT 已越过当前轮接收窗口 | 本次结束，不在新话题补播，不误计对应推理 |
| 重复与乱序 | 同一事件或同一处理反馈重复到达 | 仅一次有效处理及成功计次，不影响其他场景 |
| 只发出未处理 | advice 发送成功，但 DT 未进入对应推理 | 不计成功，记录真实状态 |
| 已处理但播报中断 | DT 对应推理已发生，端侧未播完 | 处理计次保留；触达记录中断，不能标记完整播报 |
| 账号切换 | 建议待处理或旧反馈返回时切换账号 | 不向新账号播旧内容，不把次数计到新账号 |
| 条件与工具结果不一致 | 触发后实际注册／记忆操作失败 | DT 如实回应；引导计次与业务失败分开记录 |
