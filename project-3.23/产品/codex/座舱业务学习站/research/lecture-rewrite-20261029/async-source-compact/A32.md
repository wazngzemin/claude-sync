一、需求
静态 Advisor 是一套「持续运行、主动挖掘」的车载主动服务：云端观察人/车/环境，主动产出目标、建议与 UI 描述（覆盖舒适 / 出行 / 情感 / 内容四类）。端侧目标是把这些主动服务落地到赛力斯原生界面——AI bar、舒适空间、AI 电台等，并在用户确认后驱动执行。字节负责产出与下发数据、赛力斯负责界面渲染与交互，一期聚焦舒适/出行/情感的 P00 场景。

三、协议 A：云端 → 客户端
在现有 FrontierMessage 的内层 message JSON 上扩充字段，向后兼容（原 {recommend_id, query} 豆包唤醒分支不受影响）。ui_control 承载 UI 控制：ui_payload 下发赛力斯渲染。

四、协议 B：豆包 → 车控进程（AiCar SDK）
nova 把 UI 消息发给车控进程，走 AiCar SDK 新增的一套 AIDL：register 监听（下行）+ notify 回传（上行）。车控进程作为 AiCar SDK 的客户端接收，再转调赛力斯原子能力 SDK（协议 C）。
AiCarSpeechClient 新增接口（车控进程集成）
fun registerUiControlListener(listener: IUiControlListener)
fun unregisterUiControlListener(listener: IUiControlListener)
fun notifyUiEvent(uiEventJson: String)         // 车控进程回传点击/确认等
interface IUiControlListener {
fun onUiControl(uiControlJson: String)      // 下行：信封 + 不透明 payload
}
下行 uiControlJson 信封：biz_type、event_id（映射自 recommend_id）、action（show/update/remove）、payload（不透明；不含 reply）。
上行 uiEventJson：biz_type/event_id（关联）、ui_event（click/confirm/expose/dismiss）、event_data（不透明）。车控进程/赛力斯不需要知道确认后 nova 做什么。
五、协议 C：车控进程 → 赛力斯原子能力 SDK
车控进程集成赛力斯 SeresPlatformSDK（com.seres.common:PlatformLib），收到协议 B 的 UI 消息后，通过原子能力的UI渲染接口下发；SDK 内部路由到 AI bar / 舒适空间 / AI 电台等模块渲染。
