# 三张业务流程图

本次只重画三张图，不改旧 PRD。用户指定三张详细流程图，因此不用时序图，也不按图解技能的简图节点上限拆成更多图。

## 01 总业务框架

- 类型：业务流程图。
- 目的：把产品定义、能力接入、用户管理、端云判断、静默/询问、执行与真实结果接成一条完整业务链路。
- 阅读结果：知道系统预设任务不是开关页面，也不是只有触发条件；每项交接都需要有人承接。
- 命名对象：需求方、配置/开发、任务中心、任务接入方、端云触发器、主动推荐、即时卡、执行与车控。

## 02 端侧天气

- 类型：业务流程图。
- 目的：以切换湿滑模式为例，区分触发器判断、天气业务填卡、本地语音模拟按钮、业务执行、真实模式回读。
- 阅读结果：知道交互卡不判断天气，不把按钮点击直接当成车控成功。
- 命名对象：任务中心、天气任务接入方、端侧触发器、车辆/VLM数据、天气业务、即时交互卡、可见即可说、端侧执行、赛力斯车控。

## 03 云端充电

- 类型：业务流程图。
- 目的：把值得检查、识别设备、用户同意、当前允许、真实开盖五件事分别画清。
- 阅读结果：知道取到 DT 结果后还缺哪一段询问交接，不能把系统 Query 当用户同意。
- 命名对象：任务中心、充电业务、云端触发器、主动推荐、DT、端侧视觉及结果接入、Planner、即时卡、端侧执行、赛力斯车控。

## 表达与证据边界

既有 PRD V11 已核对任务全集、VUI、可见即可说、任务中心和评审逐字稿；本次是图形重制，不新增会议结论。每张图均标明是评审流程方案，不代表全部上线。保护规则与未认领交接在图中标识。静态 Advisor 点击模拟 Query，不混成另一类系统通知卡的直接业务回调。

## 布局

固定 680 宽 SVG，自上而下，主流程居中偏左，退出分支在右侧；端云和点击/语音分支分列。业务动作使用方框，判断使用菱形，箭头表示下一步。详细交接优先于简图节点上限。SVG 用显式坐标绘制；同一节点/连接数据另存 Mermaid 源码。
