Planner 任务规划中枢（车载 Agent 大脑）｜产品负责人

背景：传统语音只能一句一应，负责结合车况、记忆与执行反馈，把用户目标转为可持续推进的任务。

  • 架构与实验：针对“我好热”在不同车况下需不同响应，推动“感知—思考—执行”快慢思考架构，保留明确指令快路；设计 A–D 四组实验，以理解效果、执行合理性和端到端时延共同判断可用性。
  • 长程任务规划：定义单步复杂、多步串行、条件、持续 4 类任务及分期路线；以“去昨天的游泳馆”为例，明确先查记忆再导航的动作依赖，配套失败重规划、任务修改与打断恢复方案。
  • 质量与性能评测：将缺失、冗余、错误操作及说做不一致纳入任务评测，校验依赖关系与参数可执行性；制定推理准确率 ≥ 90%、首 token P90 ≤ 800ms 的版本目标。
  • 问题修复闭环：分诊 138 条缺陷，识别工具漏调占 61%，将同类决策问题沉淀为可检索的动态示例；累计提出 59 条示例，其中 30 条实车复测通过。
  • 动态示例治理：针对跨车型示例串用与逐车型复制的维护负担，选择“项目范围先过滤、共享内容只维护一次”，主导管理平台与项目隔离 PRD，配套查重、审核、灰度及回滚规范。

舱驾融合司机 Agent 1.0 / 2.0（物理世界具身 Agent）｜产品负责人

背景：用户用人、车、店招等参照物表达停车意图，负责将语言和视觉结果转成智驾可承接的目标。

  • 产品与场景定义：负责临停、泊车、抢车位的产品规划与舱驾融合 PRD；围绕“停在拉行李箱的人旁边”，明确参照物识别、目标定位与驾驶执行的衔接要求。
  • 视觉交互取舍：针对同色同款车辆等目标歧义，设计候选澄清与车位确认；将“识别到参照物”与“存在可用停车位”分开判断，避免看懂画面就默认可以执行。
  • 安全与异常设计：明确紧急制动优先、智驾保留执行拒绝权；为感知不确定、智驾拒绝和操作超时定义解释、可行替代与安全退出方案，避免用含糊话术掩盖能力边界。
  • 评测与采集规范：围绕视觉理解、目标定位、执行与拒绝设计 113 条评测用例；制定 VLM 人车参照物采集规范，覆盖 22 个对象、110 条用户表达。
  • 跨团队交付：对接上汽、赛力斯与智驾方案商，划清座舱意图与视觉理解、智驾可执行性与安全兜底、车企接口与法规要求的分工，形成分车型产品需求。

多模态语音交互、长期记忆与量产交付｜负责人

背景：多人共车需要及时接话而不误响应、个性化而不越权，负责语音、记忆体验及车企交付治理。

  • 免唤醒与多人交互：围绕乘客通话误响应、多人相反指令，统筹音区抑制、有效输入合并与冲突澄清方案；制定唤醒响应 ≤ 350ms、安静环境句准 ≥ 95% 的验收目标。
  • 响应与打断：统筹语音判停、端云仲裁与播报打断设计，采用可作废的提前理解而不抢先执行；断网保留基础车控，有效插话先让声（简单车控除外），兼顾速度与语义完整。
  • 长期记忆与隐私：针对无关旧事误召与共乘泄露风险，负责场景标签召回和敏感记忆使用方案；敏感内容仅在当前在场人员共同经历过时使用，识别新乘客上车后清理敏感对话摘要。
  • 量产问题治理：牵头上汽、赛力斯项目 数千条 badcase 分诊，先排工程链路、工具描述与上下文缺失，再判断模型能力；按收益和修复时效划分快速修复与中期治理，避免问题一律归因模型。
  • 车企需求推进：主持赛力斯系统预设任务外审，明确端云分工；针对雨量、车速依赖真实环境而难以联测，提出先用可控信号验证通用链路、再恢复真实业务条件的分步验证方案。
