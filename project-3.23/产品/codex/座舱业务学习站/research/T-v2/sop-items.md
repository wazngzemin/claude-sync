## 清单内部与其他证据的冲突提示

- C-SOP-01：`全量功能清单!H27` 与 `【子功能】座舱工具集合!C3` 仍写“最多 6 个定时 / 条件任务、1 个持续目标”；旧网页又写 20 定时＋20 条件＋6 长时，新产品介绍也需另核对。保留旧工具边界数字，T 新正文不能把它与任务中心总量合成一个上限。
- C-SOP-02：`【子功能】对话推理!D16:J16` 和 `【子功能】账号、记忆与任务底座!D14:J14` 将 Script 动态调整标为可量产；技术设计对通用 Script、独立 Task Agent 的二期规划需要逐项比较，不能以功能清单标签替代代码/项目交付现状。
- C-SOP-03：持续目标管理工具 / 任务管理工具标必选，基础底座的任务管理工具标可选，异步任务推理二级能力标必选；这是不同表层的选配标记，当前清单没有说明如何统一，需原样保留。
- C-SOP-04：一级“任务交互卡片”标内部预研，但其二级“即时任务卡片”标可量产；任务中心界面、长时任务卡片、任务岛状态展示与操作仍标内部预研，T 后端可量产不能推出 U 所有界面可交付。
- C-SOP-05：旧架构表保留“动态目标”（可量产），新版汇总将用户动态目标收进持续目标管理 / 任务管理入口；“主动目标推理”（静态 Advisor）仍内部预研，二者不得混用成熟度。
- C-SOP-06：旧架构表异步任务描述包含长程、持续，新版一级汇总改成定时、条件“等任务”，但底座完整版仍含持续和 GUI；文字缩短不是取消能力的直接证据。
- C-SOP-07：`【必读】清单说明&change log!B10:E11` 将可量产定义为至少一项目已落地、可标准交付，内部预研定义为不可对外宣传/透露；不能把“可量产”改写成全车型均已上线。
