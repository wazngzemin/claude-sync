## 本版结构

以 8 个业务阶段形成横向主链，各阶段内部用单列向下的 4 个步骤展开。模块之间保留 480 个逻辑像素的走线通道，内部步骤保留 170 个逻辑像素的间距。正文、例子、异常/交接、产品追问放在同一个节点内，避免仅看标题。

结果再判断、用户选择、端侧快路、纯交互、Task 通用执行与主动建议分别有具名连接。虚线只表示机制/目录展开，不表示额外运行步骤。工具目录为可选能力，不把 27 项串成必经流水线。

HTML 默认聚焦第一框；提供逐框前后、5 条阅读路线、连线起终点检查、节点/工具搜索、完整自测指标、个人笔记和 Markdown 导出。讲解路线不是一条真实运行 Trace。

页面优化沿用用户已选择的「结构重塑」，采用 qiaomu-design-advisor 的阅读层级/留白原则；beautiful-feishu-whiteboard 用于蓝白配色和原生可编辑导入。不是生成一张扁平图片替代画板。

## 来源与事实边界

本轮用飞书搜索查找 Director PRD，再读取 Director 原文和 Task 技术设计相关段落；重新解析本地 SP，得到 27 个唯一工具定义。此前已核对的 VLM/可见即可说原文作为原有证据延续，来源链接保留在 HTML 中。

旧 Goal/动态 Advisor 与新 Task 设计分开。实际车型注入数、内部模型与 SDK、统一门禁落地、完整幂等/取消协议和实测性能并未获得全量运行证据，不宣称这些均已上线。
