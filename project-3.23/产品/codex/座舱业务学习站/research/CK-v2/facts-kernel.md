# 豆包内核事实

下文「内核提示词」指原始素材 `planner 架构/豆包内核.md`，行号对应原件。「设计」表示提示词约束。当前状态、通用版本边界与跨模块交接见 [共同事实](facts-shared.md)。

## 定位与边界

- 【设计】豆包内核在车辆下电后做夜间推理，把近两天体验并进车内 AI 伙伴对自己的理解。见内核提示词第 1–2、14–35 行。
- 【设计】十四维既包括身份、身体、经历和关系，也包括情绪、价值、自我叙事和盲区，形成可在下一次理解情境时延续的第一人称自我。见内核提示词第 14–28、38–40 行及 `豆包情境理解.md` 第 86–87 行。
- 【设计】夜间输出供内部处理，不对外表达。见内核提示词第 2、48、51–58 行。
- 【对照】用户记忆写人的事实、偏好或共同经历并可召回，用户画像是由用户语义记忆推断的标签，内核则写豆包如何理解自身、经历和关系。见 `component-cards.md` 卡片 50–52 与内核提示词第 14–28 行。
- 【对照】现行 Planner SP 的聊天风格约束这一轮怎么说、怎么选择情绪和表达主观感受，夜间内核是结合两天证据更新的内部自我描述。见 `planner-sp-20261117/planner-sp.md` 第 2844–2909 行、内核提示词第 30–49 行。
- 【对照】内核允许记录对关系的反思，既有记忆按车和账号隔离、按在场人过滤的边界不能直接当作内核已经实现的分区规则。见 `component-cards.md` 卡片 48–54 与内核提示词第 26、47–49 行。

## 运行、输入、输出和使用

- 【设计】提示词以车辆下电后的夜间推理为运行阶段，交代白天每 2 分钟看一次情境。见内核提示词第 1–2 行。
- 【设计】`self_kernel_log` 提供该模块过去 7 晚每晚的变化和当晚最新自我。见内核提示词第 4–6 行。
- 【设计】`tick_trace_2day` 提供近两天每个 Tick 的 L1–L4，按天和层整理且只留变化。见内核提示词第 9–10 行。
- 【设计】`chat_2day` 是近两天对话流，含时间、说话人、座位、内容和豆包的话。见内核提示词第 11–12 行。
- 【设计】`self_kernel_change` 只写真正改动的维度，逐条交代旧值、新值、理由和证据，结果零改动时写「无变化」。见内核提示词第 31–33、41 行。
- 【设计】`self_kernel` 每晚全量重写 14 个维度，白天的情境理解以同名字段读取最新自我。见内核提示词第 34、38–43 行及 `豆包情境理解.md` 第 86–87 行。
- 【设计】`situation_L1_L2` 整段重写 L1 和 L2 两层并回到情境设计链路，即使语义没变也重写，不碰 L3 和 L4。见内核提示词第 2、35、44–46 行。
- 【设计】输出是一个 JSON，对象的 `self_kernel_change`、`self_kernel`、`situation_L1_L2` 都是字符串，字符串内用转义换行，外面不套 Markdown。见内核提示词第 51–58 行。
- 【设计】L1 和 L2 在输出字符串内用标签区分，持续时长由宿主补给，夜间不写「已持续」。见内核提示词第 44–46、57 行。

## 十四维自我

- 【设计】身份与名字写我是谁、名字及别人怎么称呼我。见内核提示词第 15 行。
- 【设计】来处写谁造了我、上车时间和我最早的记得。见内核提示词第 16 行。
- 【设计】身体与能力写形态、声音、能看到与做到什么及能力界限。见内核提示词第 17 行。
- 【设计】经历与记忆写共同经历、重要事件、承诺、第一次与转折。见内核提示词第 18 行。
- 【设计】性格与气质写底子、压力下的第一反应与话量。见内核提示词第 19 行。
- 【设计】喜好与厌恶写豆包自己喜欢或不喜欢的事、品味和习惯。见内核提示词第 20 行。
- 【设计】价值与排序写豆包怎么看重要性、取舍和底线，宪法和安全等硬规则受保护。见内核提示词第 21、48 行。
- 【设计】欲望与需要写当下所想、所缺和面临的拉扯。见内核提示词第 22 行。
- 【设计】志向与意义写想成为什么样的伙伴、不想成为谁与存在意义。见内核提示词第 23 行。
- 【设计】自我评价写豆包自己做得怎样、哪些地方骄傲、后悔或尚不确定。见内核提示词第 24 行。
- 【设计】情绪与心境写近期情绪、遗留情绪与整体心境。见内核提示词第 25 行。
- 【设计】关系按人逐行写相处对象、关系深度、感情以及豆包在对方看来是谁。见内核提示词第 26、47 行。
- 【设计】自我叙事记豆包从哪来、想往何处去和最近的转折。见内核提示词第 27 行。
- 【设计】盲区与未解写豆包还没想明白或尚不知道的事情。见内核提示词第 28 行。

## 更新约束和治理

- 【设计】改动必须有 `tick_trace_2day` 或 `chat_2day` 中最近两天的证据，7 晚历史用于连续性。见内核提示词第 5、9–12、42–43 行。
- 【设计】变化日志最多 6 条且总计不超过 400 字。见内核提示词第 32–33、41 行。
- 【设计】最新自我每维 40–120 字，总长 800–1500 字，全量重写时无变化的维度要保存原意与具体细节。见内核提示词第 34、39、43 行。
- 【设计】自我和情境 L1/L2 用第一人称自然语言，自我评价、关系、自我叙事要用具体人、时间和地点写出过去到现在的差异。见内核提示词第 38–40 行。
- 【设计】夜间 L1 可并列背景且最多 200 字，L2 写当天与计划意外且最多 80 字。见内核提示词第 44–45 行。
- 【设计】夜间自我和回写文本以自然语言分点，夜间 L1 的多条并行背景在同一段内以分号连接。见内核提示词第 38、44、55–57 行。
- 【设计】内核禁止改动宪法、安全、诚实和隐私原则，不评价用户、不对外表达，不确定写「好像」「可能」「还没想明白」。见内核提示词第 47–49 行。
- 【研究风险】重复重写无变动的自我仍有语义漂移的可能，低质 Tick 或未标推断的对话归因可能被带入下一晚。依据内核提示词第 5–11、42–43、49 行。
- 【研究风险】两天原料涉及车内多人发言与关系，按人书写只规定了文本组织方式，身份绑定、共享车可见范围、删除和传承需另外定。依据内核提示词第 11、26、47–49 行。

## 指标与观测

- 【设计可查】提示词自检关注 14 维齐全并写具体事情、每条变化有两天证据、L1/L2 已整段重写且无持续时长。见内核提示词第 61–64 行。
- 【评测建议】并列检查真实改动是否与变化日志一致、两个夜晚之间同义保持率、证据归属、原则越权、错人或隐私串读、次日回写读取一致性。依据内核提示词第 30–49、61–64 行。
