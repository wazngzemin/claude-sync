最值得先做的补齐项目是：**机器人同时执行两个任务时，如何按资源预算调度，并根据事件先后决定继续、暂停或取消。** 例如整理物品期间收到新任务，系统需处理相机观察占用、任务优先级、过期观察和执行反馈；在同一测试集下比较有无时序与资源调度机制的结果。它可以衔接下文项目 A，再按目标岗位扩展为现场验收。此处是研究者设计的练习，不是宣称用户或某家公司已经实现。

场景交付是值得发展的方向，但目前“创建 PRD”仍不足以证明已经具备完整交付经验；数据平台方向也仍需独立的数据生产证据。

## 1. 先给职业判断

**建议优先验证“机器人任务与交互产品”或“机器人应用方案产品”的匹配度；有完整数据生产经验时，再重点考虑数据与评测平台。整机、本体与运动控制产品需要单独补硬件及实机证据。** 这是基于下列少量岗位样本的研究判断，不是行业岗位数量排名，也不是录用概率预测。

车载 Planner（理解诉求、拆解任务并跟踪执行的规划模块）和 Trigger（满足条件后启动或调整任务的触发模块）有可迁移价值：它们都涉及目标、状态、条件、动作、反馈和异常。但机器人会追问：物体究竟在哪里、当前能不能抓、动作失败后场景变成什么、谁接管、如何验收。只展示语言理解和接口调用，无法回答这些问题。

本次读到 **5 份官方 JD（岗位说明），中国 2 份、美国 3 份**。它们显示门槛差异很大：有岗位接受 AI 产品背景，也有岗位明确要求机器人行业、训练数据链路或仓储机器人年限。不能把“转具身产品”视为一个统一职位。下文将招聘原文要求与研究者建议分开。

**来源与状态：**[公司官网 JD](https://www.bingorobotics.cn/join/embodied-product-manager)，正文可读；招聘主体北京缤果万境科技有限公司，工作地点深圳，全职。页面标注发布于 2026-07-01，截止于 2026-12-31。

**JD 明确要求：**统筹 BingoMate、场景大脑和机器人联合方案，调研场景、制定需求与路线图，协调研发、销售、交付。要求本科及以上、3 年以上 AI 或机器人产品经验；行业客户经验优先，具身/世界模型背景及招投标、市场进入经验属于加分项。[岗位原文](https://www.bingorobotics.cn/join/embodied-product-manager)

### 3.2 中国｜越伴动力：产品经理

**来源与状态：**[公司官网 JD](https://luvbotics.com/careers/product-manager/)，正文可读，有投递方式；地点北京，未标发布日期。产品对象为双足家庭陪伴机器人。

## 4. 四条方向分别需要什么

下表是研究者对工作内容的归纳，不是五家公司统一的组织分工。

| 方向 | PM 主要解决的问题 | 车载经验可以迁移什么 | 关键迁移限制 | 本次直接证据 |
|---|---|---|---|---|
| 任务规划与交互 | 用户说的目标如何变成机器人可执行任务；何时追问、停下、恢复或求助 | 意图澄清、多步依赖、条件触发、任务状态、失败反馈 | 要处理物体身份、空间关系、可达性和技能限制；任务规划不等于运动路径规划 | Standard Bots 交互岗位；SayCan、Spot 文档提供技术补证 |
| 数据与评测平台 | 哪些过程值得采集；数据能否用于训练；效果是否真的改善 | badcase 归因、标签体系、回放、回归、版本对比 | 多相机、机器人状态和动作需要时间对齐；要理解示教、接管、数据分布与泄漏 | Dyna JD |
| 场景交付 | 一个客户现场能否稳定运行，并复制到下一个现场 | 跨软硬件团队评审、接口协同、验收和问题闭环 | 新增布局、现场节拍、维护、培训、客户系统集成和商业收益责任 | 缤果万境、Ambi JD |
| 本体与运控产品 | 机器人形态、传感、负载、续航和运动能力是否满足任务 | 性能取舍、软硬件依赖管理，前提是本人做过 | 整机定义与运控能力是两个子方向；需要对应硬件或运动能力实测，不能只改产品术语 | 越伴动力支持整机方向；纯运控 PM JD 证据不足 |

本体指机器人身体及其硬件，例如底盘、机械臂、关节、传感器。运动控制指让身体按目标稳定运动的能力。产品岗位可以定义能力边界与验收指标，而由算法和控制工程师实现；是否需要亲自写控制算法必须看具体 JD。

## 5. 核验“具身”、API 编排、SayCan 与 VLA

### 5.1 本研究采用的工作定义

具身智能关注智能体通过身体和传感器与环境交互：观察影响决策，动作改变环境，后续观察又改变行动。机器人和车辆都可能成为载体，研究也使用有身体与环境交互的仿真。不能只凭“装在车上”判定某个功能具备这类闭环，也不能把具身缩成“人形机器人的连续关节控制”。这是一种工作定义；不同论文的边界并不完全一致。[arXiv 综述：引言、表 I 与任务分类](https://arxiv.org/html/2407.06886v8)

**系统是否具身、某个模块是否参与具身闭环、PM 是否具备特定岗位资历，是三个不同问题。** 例如负责机器人任务界面的人属于具身产品团队，不必因此声称自己做过运动控制研究。

### 5.2 三种技术路线解决的不是同一层问题

| 路线 | 论文实际做什么 | 与 API 编排的关系 | 不能据此声称什么 |
|---|---|---|---|
| SayCan | 结合语言模型对下一技能的任务相关性判断，以及技能在当前状态下成功的可行性估计，选择并执行技能 | 和高层技能调用有相似结构，但增加了基于机器人和环境的能力约束 | 把工具列表交给 LLM 就已经复现 SayCan |
| Code as Policies | 生成程序，读取感知输出，组合控制 API，并表达条件、循环和空间计算 | 直接证明 API 调用与具身控制可以共存；重点是调用内容和反馈如何关联物理环境 | 任何网页工具调用都等同于机器人能力 |
| RT-2 / VLA | 将视觉与语言输入映射为机器人动作；RT-2 用机器人轨迹和视觉语言数据共同微调 | 动作可经软件接口下发，但学习目标不同于仅选 API 名称 | 输出动作合法就保证安全、任务成功或掌握新运动技能 |

来源：[SayCan 原论文，第 3 节](https://arxiv.org/html/2204.01691v2#S3)、[Code as Policies 原论文](https://arxiv.org/pdf/2209.07753)、[RT-2 原论文](https://arxiv.org/html/2307.15818v1)。

VLA 即视觉—语言—动作模型。RT-2 的动作包含机械臂末端的位置/旋转变化、夹爪开合和终止标志；它把连续量离散化成 token（模型处理的符号单元）。因此，“模型输出离散符号”不代表没有控制物理运动。论文也明确指出，网络预训练不会凭空带来机器人训练数据中没有的新运动技能，高频运行还受计算开销约束。[RT-2，第 3.2 节与第 5 节](https://arxiv.org/html/2307.15818v1)

OpenVLA 则提供开放的模型与微调路线，是理解“观察和动作数据如何进入学习过程”的实践入口；不能把成功运行一次推理等同于完成机器人部署。[OpenVLA 原论文](https://arxiv.org/abs/2406.09246)

### 5.3 连续控制不是所有岗位的唯一门槛；世界模型也不是必需组件

**连续控制是许多机器人执行系统的重要能力，但高层规划、交互、数据平台与部署 PM 不必亲自实现整个控制系统。** SayCan 的高层规划与底层技能分工、Code as Policies 的感知和控制 API，都提供了可核验的架构例子。岗位上则应分别考察本节的实际资历要求，而不是自设一条所有人都要过的算法门槛。[SayCan](https://arxiv.org/abs/2204.01691)、[Code as Policies](https://arxiv.org/abs/2209.07753)

**不能宣称世界模型必需。** 若世界模型指显式学习“执行某动作后环境如何演变”的预测模型，SayCan 的技能价值评估与 RT-2 的直接动作策略并未把这种模型列为必要组件。这支持“存在不依赖该组件的具身方案”，不支持“世界模型没有价值”。读取当前状态、做地图、预测一个技能能否成功，也不能一概改称已具备通用世界模型。此处是基于论文结构的推论。[SayCan 方法](https://arxiv.org/html/2204.01691v2#S3)、[RT-2 方法](https://arxiv.org/html/2307.15818v1)

### 5.4 一个最贴近 Trigger 的官方机器人例子

Spot 官方文档讨论：机器人经过叉车通道时，如果“先检查再通行”只写在某条任务序列中，绕路或低电回充经过同一区域时可能漏掉检查。因此它提供区域回调，将动作绑定到地图区域，并定义等待、继续和控制权转移。[Boston Dynamics：GraphNav Area Callbacks](https://dev.bostondynamics.com/docs/concepts/autonomy/graphnav_area_callbacks.html)

这说明 Trigger 经验的迁移问题很具体：**条件应绑定某条任务，还是绑定所有会经过该区域的行为？任务取消、换路、接管后，条件是否仍有效？** 这里不是把原来的事件名换成机器人事件名，而是重新确认规则覆盖的物理路径与执行责任。

Agility 的 Arc 官方产品页则提供另一类证据：机器人车队需要工作流、运行指标及现有仓储系统集成。这说明机器人行业存在上层平台工作，不代表 Arc 使用某种特定 LLM 技术，也不构成 PM 招聘证据。[Agility：Solutions / Arc](https://www.agilityrobotics.com/solutions)

## 6. 车载经验怎样迁移，怎样避免夸大

以下均为条件式映射：只有本人实际负责并有结果证据的部分，才适合写入简历。本文没有审阅用户项目，不能确认用户已具备这些经验。

| 假设已有车载工作 | 可对应的机器人工作 | 面试仍需证明的内容 |
|---|---|---|
| 拆分多步任务、跟踪下游反馈 | 技能调度、任务恢复与重规划 | 每个技能的前提、失败后真实状态、能否取消；不能只展示正确的调用顺序 |
| 按车况/时间/事件触发服务 | 场景事件、区域规则与任务中断 | 感知误判、定位误差、状态过期、重复事件和并发任务下是否仍可靠 |
| 多模态交互与主动服务 | 目标物澄清、进度解释、人机协作 | 指向和空间指代、遮挡、用户打断、多人接近、接管时机 |
| 端云链路与异常兜底 | 网络不稳定时任务降级与本地执行 | 分清云端任务判断与本地停机/避障；不能把所有安全反应交给云端生成 |
| badcase 分类与版本回归 | 机器人数据质检及分层评测 | 观察/动作时序、机器人型号和标定、跨场景分布、训练测试隔离 |
| 跨团队评审与验收 | 客户场景上线 | 从一次演示扩展到稳定班次、维护负担、人工干预、成本和客户签收 |

例如用户说“把杯子拿给我”：系统要先确定哪个杯子和交付位置，再判断是否够得着、是否被挡住；调用抓取后要区分“命令收到”和“杯子已抓住”。抓空后重新观察，杯子被人挪走后改变计划，交付条件不满足时求助。这个产品例子展示的是应补齐的设计判断，不是某公司已实现的能力。

更可信的转岗表述是：“我做过复杂任务、条件触发和执行反馈的产品设计，正在通过机器人项目证明物理状态判断、失败恢复和实测评估能力。”不要将座舱服务规划改写为自动驾驶路径规划，也不要将规则配置写成学习型机器人策略训练。

## 7. 具体补齐项目：用一个场景串起作品集

建议选“桌面物品整理”作为主项目：把指定物品移到指定区域，支持遮挡、抓取失败、任务取消与人工协助。前三个项目可共用场景和日志，避免重复造演示。下列周数、样本量均为建议的个人学习范围，不是行业标准，也不是已完成结果。

### 项目 A：有状态回查的机器人任务产品，约 2–3 周

**对应方向：**任务规划与交互；对照 Standard Bots 的原型和功能行为要求。

**做什么：**先用仿真或可接入的实验机器人，只开放观察、移动、抓取、放置、停止、求助等有限技能。明确技能前提和结果判据；界面能够解释正在执行什么、为何不能继续、何时等待人。底层已有控制能力可以复用，不以从零写控制器为目标。

**比较方法：**使用同一批至少 30 个场景，覆盖正常任务、物体缺失、抓空、目标变化和中途取消，分别运行“仅按文本编排”与“加入状态检查和失败恢复”的版本，每个场景重复 3 次。保存全部试验，不只保留成功视频。

**验收产物：**可运行原型、技能前后条件表、状态转换图、过程日志、未剪辑案例、结果表。统计任务成功率、错误报告成功次数、重试次数和人工介入率，并分失败类别报告。若规则估计技能可行性，标为“受 SayCan 启发”，不要声称完整复现其学习型价值函数。[技术参考：SayCan](https://arxiv.org/html/2204.01691v2)、[Code as Policies](https://arxiv.org/pdf/2209.07753)

**迁移限制：**仿真结果证明系统设计与实验能力，不等于实机可靠性或客户部署。

### 项目 B：机器人失败数据与评测工作台，约 2 周

**对应方向：**数据与评测；对照 Dyna 的采集、标注、评测和工具体验要求。

**做什么：**用公开机器人数据或项目 A 的记录组织 episode（一整次任务过程）：将视频、机器人状态、动作、时间、任务及版本放到同一时间线上，支持跳转到失败位置、标记原因、复核标签和导出数据集。LeRobot 的官方格式与可视化工具可作为数据基础。[数据格式](https://huggingface.co/docs/lerobot/lerobot-dataset-v3)、[可视化文档](https://huggingface.co/docs/lerobot/using_dataset_tools)

**最低范围：**整理至少 100 个过程；建立意图错误、目标识别错误、技能不可执行、执行失败、状态不同步、取消/接管错误等标签。没有真实失败的数据不可硬标失败；可另建明确标记的故障注入集。让另一名标注者独立复标至少 20 个过程，分析分歧并修订定义。

**验收产物：**字段定义、数据质量规则、标注手册、回放原型、复标报告、版本和来源记录。对比工具前后的故障定位时间；若有对应策略模型，再用固定留出集验证改善。没有训练与复测，就只报告数据工具成果，不能写“已形成模型提升闭环”。

### 项目 C：一个小场景的实机交付与验收包，约 2–4 周，取决于设备与场地

**对应方向：**场景交付；对照缤果万境和 Ambi。应安排实际机器人实验或与有设备的实验室合作，而不是默认购买昂贵本体。

**做什么：**限制物品、布局和工作区域，测量现有人工流程，再做机器人试验。写清接入什么任务系统、谁补充物品、谁处理异常、多久需要维护。将同一方案在两个布局下测试，并分别保留配置差异。

**验收产物：**部署检查表、操作手册、异常升级流程、现场试验记录、客户式验收表及成本模型。指标至少包含合格任务完成数、有效工作时间、每百次任务人工介入、故障恢复时间和损坏/碰撞事件。成本模型应包含设备、维护、操作员接管、现场改造和停机成本；实测值与假设值分列。

**完成边界：**个人试验可作为部署准备证据；没有真实客户、连续运营和签收记录时，不写“商业化落地”。这类工作与官方 JD 的场地布局、系统集成及持续性能责任相对应。[Ambi JD](https://jobs.lever.co/ambirobotics/b9c943c3-212a-4d5a-9680-d04b1f9097e7)

### 项目 D：仅在瞄准本体/运控方向时补做能力边界实验

**做什么：**联合硬件或控制工程师，在设备规定的工作范围内测试负载、可达位置、定位误差、连续工作时长及异常停止行为。若对象是移动机器人，再按场景定义通道、地面和定位条件；不把机械臂与双足本体混成一套测试。

**验收产物：**“哪些条件能做、哪些不能做”的能力表，需求到实测结果的对应关系，以及功能、成本和可靠性取舍。该项目提供对话基础，但不能替代越伴动力所要求的机器人全流程工作年限。[越伴动力 JD](https://luvbotics.com/careers/product-manager/)

### 可选 VLA 实验，不作为全员前置门槛

如果目标岗位直接涉及机器人模型产品，可在前三个项目后增加一次现有策略的仿真评测：使用与环境匹配的公开检查点，锁定模型、任务集、初始条件和动作格式；比较一个基线与一个改动，报告成功率、运行时延及失败分布。LeRobot 提供 LIBERO 仿真评测入口，OpenVLA 提供开放模型研究路线；二者不代表任意检查点都能直接互换。[LIBERO 官方集成文档](https://huggingface.co/docs/lerobot/libero)、[OpenVLA 原论文](https://arxiv.org/abs/2406.09246)

离线动作预测误差低、仿真成功和实机成功是不同证据。不要用“能加载模型”和一段演示视频替代完整评估。

## 8. 用什么标准筛岗位与准备面试

先检查四件事：岗位对 AI 背景是否开放；是否明确要求机器人细分行业年限；是否要求现场、出差和硬件责任；最终指标是用户体验、模型数据、客户运营，还是整机能力。再选择作品集重点。本文国际样本均为美国岗位，地理与工作资格需另核实，不能当成中国岗位要求的无差别替代。

可直接用于了解岗位范围的问题：

1. “这个岗位负责用户目标到任务执行的哪一段？底层技能由谁提供，失败恢复由谁决定？”
2. “最近一次演示成功但现场不能交付的问题是什么？产品经理要推动哪项改变？”
3. “模型升级用什么固定评测集验收？如何区分规划错误、感知错误和执行错误？”
4. “客户的完成标准是单次任务成功，还是吞吐、稳定性、接管成本和连续运行？”
5. “如果我已有车载复杂任务和事件触发经验，贵团队最希望我提供哪类机器人项目证据？”

当前更值得补的第一项证据，是**一个受环境状态约束、能处理失败并留下完整试验记录的机器人任务产品**。若目标是数据岗，将它扩成数据工作台；若目标是交付岗，将它扩成现场验收；若目标是整机/运控岗，再加入对应硬件实测。这一顺序是作品集建议，不是替代正式工作经历的承诺。
