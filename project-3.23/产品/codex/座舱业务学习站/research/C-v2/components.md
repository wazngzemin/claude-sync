# C 章新增部件与概念候选

研究范围：只取证，不写章节正文，不改网页。

统计：26 个候选部件/概念登记，另有“终态事件”1项概念缺口；这里是供下一步设计者补卡的研究草案，没有修改全站部件卡片。已并入同一候选的来源补充不再重复计数。来源路径以 `座舱业务学习站/research/` 为基准；原文行号指本地文件的物理行。设计、测试、讨论、周报状态分开记录。


## B-COMP-01｜动态示例
- 是什么：按当前用户问题取出的少量“用户输入—处理逻辑”教学案例，指导 Planner 调用具体工具。
- 运行位置：云端检索与 Planner SP 组装；VikingDB 在线检索，MySQL 管理台账。
- 收到什么：当前 query、env、channel。
- 输出什么：Top 3 格式化案例，写入 scenario_sample。
- 关键数字：Top 3；外部示例库 1000+ 为方案预期收益规模；pre-query 并行，后台热更新。
- 来源：`chapters/C/raw/dyn-example-onepage.txt:3-23,91-94`。

## B-COMP-02｜动态知识与场景路由模型
- 是什么：小模型选择当前任务适用的场景 SOP，教 Planner 遵守边界并安排多步骤。
- 运行位置：云端 director.prompt.select_skill；知识在 Go 代码 skillConfig 及缓存中。
- 收到什么：近两轮对话历史和场景选择提示词。
- 输出什么：场景 ID 列表；据此取得正文并拼进 SP 的 knowledge。
- 关键数字：Seed-2.0-mini；8 大核心场景；更新需代码发版；无原文实测耗时。
- 来源：`chapters/C/raw/dyn-example-onepage.txt:25-35,59-89`。

## F-COMP-01｜Context 上下文组装服务
- 是什么：为 Planner 等调用方获取本轮有关背景的公共服务，V2 是常用预注入加按需检索；不是 Planner 推理，也不等于输入管理。
- 运行位置：云端 AIDV 服务；OnePage给出 aidv 的 retrieval.go 代码入口，具体子进程边界未给。
- 输入：当前请求及各源数据；输出：筛选后的背景供 Planner 提示词组装。
- 关键数字：9 类源；V1 统一精筛最多5项；V1 P90 1.2s、V2表中564ms；80/20为方案声称。
- 来源：`chapters/C/raw/context-onepage.txt:13-106,146-171`。
- 待补：完整链路图在txt中空缺，不能从空白重建图。

## F-COMP-02｜预注入与动态检索
- 是什么：预注入在Planner首次推理前送常用背景；动态检索由Planner发现缺信息后调用工具补查。
- 运行位置：云端Context负责前置，Planner及下游查询工具负责后置。
- 输入/输出：当前query→常用背景；Planner查询请求→工具反馈供下一次推理。
- 关键数字：OnePage80%/20%，技术评审五期另有90%预估；不是两套已经核验的线上覆盖率。
- 来源：`chapters/C/raw/context-onepage.txt:101-106,167`。



### 来源补充（原取证编号 A-COMP-07，并入同一候选）

- 输出什么：首轮可用的基础背景，或后续轮检索补充结果；画像在五期拟全量提供。

## F-COMP-03｜环境信息 env_info 与当前目标 goal_list
- 是什么：env_info 是这次决策需要的车辆最新状态，goal_list 是持续追踪目标及进展；区别于status视觉描述。
- 运行位置：云端组装进Planner输入；端状态来自车辆上报，具体数据链见端状态方案。
- 输入/输出：车辆状态及目标队列→提示词背景；4月方案放本轮UP并声明最新优先，转历史后删除。
- 关键数字：本文件未规定字段token上限和固定刷新秒数；按请求提供最新快照，不等于每信号实时无延迟。
- 来源：`chapters/C/raw/dt-context-adjust.txt:5-22,42-79`；和7月SLS注入SP有冲突。

## B-COMP-03｜能力边界检查与 capability 注入
- 是什么：检查系统能否实现当前请求，并将相关工具的原子能力、前置条件和示例作为补充背景交给 Planner。
- 运行位置：云端 Flow 的 runPrepare 启动 aicar.ability.check；Planner 消费通知和拼装 SP。
- 收到什么：当前 ChatRequest；模型返回能否执行、原因、所需能力列表。
- 输出什么：不支持时给 query 追加系统提示，并按能力 key 拼接说明到 capability；完整输出用于观测。
- 关键数字：原文比较 2.0 lite 与 mini，9/8 白名单 lite 单元速度基本满足，未给可读取的毫秒数；属于大规模评测临时方案。
- 来源：`chapters/C/raw/capability-boundary.txt:8-14,37-74,94-112`。

## F-COMP-04｜屏幕上下文
- 是什么：当前或近期屏幕内容进入模型背景，使“这个/第二个”等指代有对象；与W章页面词注册和卡片信息上报需区分。
- 运行位置：1.0由端侧屏幕采集模块产出，云端Context消费；现有专门技术方案正文无权限。
- 输入/输出：屏幕图像及时间戳→可供模型参考的屏幕背景，具体当前结构未有可读原文。
- 关键数字：1.0设计记录5分钟截图；不能当作当前每车型已上云能力。
- 来源：`chapters/C/raw/public-context-prd.txt:85-100`；上线状态见周报。

## F-COMP-06｜情景描述 status 与世界信息

## F-COMP-07｜风险上下文与历史终态过滤
- 是什么：把模型内容风控与正常成功、拒识、错误分开标记，并在下一轮排除风控输入，保留审计事实。
- 运行位置：云端Planner流处理、Flow收尾、Redis/MySQL历史读取与消息重建。
- 输入：finish_reason、原始模型输出与会话记录；输出：安全兜底JSON（条件成立时）、debug_info、finish_type及过滤后的历史。

## F-COMP-08｜事件日志与业务事件
- 是什么：事件日志记录某时刻发生的状态变化或用户/系统行为；它不同于当前设备状态，也不同于会话结束标记。
- 运行位置：端侧/云端/触发器生产，云端事件服务存储和订阅分发，Context或Planner消费。
- 输入：信号ID、格式化事件、event_time、来源；输出：结构化事件及自然语言、查询结果或事件通知。
- 关键数字：Context方案10分钟30条暂定，Planner实现10分钟3条另有依据；Advisor20分钟n条。
- 来源：`chapters/C/raw/event-iter-tech.txt:30-68,86-128,152-179`；该文件没有定义“终态事件”类别。
