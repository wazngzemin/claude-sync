# 【触发器后台】全渠道生效场景创建权限细分

# 背景与目标

配置人员在触发器后台创建场景时，可以设置场景全渠道生效。根据本次沟通截图，现有管理员、运营相关权限没有把这项能力单独限制，测试场景也存在同样的问题，可能让本来只用于局部验证的配置扩大到全部渠道。

**本期目标：把“可创建场景”和“可创建全渠道生效场景”分开。运营人员和未单独授权的管理员不能创建全渠道生效场景；只有被指定的管理员可以。**测试和正式场景均执行这条权限规则，不以场景标签作为豁免条件。

# 用户场景

- 运营人员创建测试或正式场景时，仅能沿用账号原有授权范围，不能把生效范围设为全渠道。

- 普通管理员即使具有场景创建权限，也不能自动获得全渠道生效场景创建权限。

- 指定管理员需要配置面向全部渠道的场景时，可以直接创建并选择全渠道生效，不必每次替其他人员创建场景或代点生效按钮。

# 需求内容

## 细分创建权限

- 在现有账号／角色权限体系中，增加独立的“全渠道生效场景创建权限”。取得该权限的前提是管理员身份，并被明确指定授权；普通管理员身份本身不构成授权。

- 运营人员不具备该权限；未指定授权的管理员同样不具备该权限。

- 该权限同时约束测试场景和正式场景。普通场景创建、账号原有渠道权限及已有发布流程保持不变，不因本需求扩大授权。

## 创建页控制与服务端校验

有权限的管理员可以选择“全渠道生效”。无权限人员不能选择或提交该范围；页面应明确提示“无全渠道生效场景创建权限”。具体采用隐藏、禁用还是现有权限组件，由前后端在评审中确定。

为保证上述限制真实生效，提交创建请求时由服务端校验操作者权限，不能只控制前端按钮。无权限请求即使携带全渠道范围也应被拒绝，不生成全渠道生效场景；返回明确的权限错误。

## 不增加逐次审批

**本期限制的是谁能创建全渠道生效场景，不是改成“所有场景必须由管理员点生效”。**不新增逐次审批或管理员代操作流程，不改变已获授权人员的既有生效操作。

# 验收标准

1. 运营账号分别创建测试和正式场景，均无法选择全渠道范围；直接提交全渠道创建请求同样被拒绝。

2. 未指定授权的管理员分别创建测试和正式场景，均不能创建全渠道生效场景，不因管理员身份绕过限制。

3. 指定授权的管理员分别创建测试和正式场景，可以成功保存全渠道范围；回读结果与页面选择一致。

4. 无该专项权限的账号仍可在原有授权渠道内创建场景；新增权限不影响普通创建能力，也不扩大其原有范围。

5. 无权限创建请求不产生全渠道生效场景，不返回成功假象；前端错误提示与服务端拒绝原因一致。

6. 本需求不引入逐次审批，不把所有生效操作改为管理员代点。
