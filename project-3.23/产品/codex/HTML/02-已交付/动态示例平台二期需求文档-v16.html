01

摘要与本次评审结论

先看最终要解决什么，以及最容易混淆的两条规则。

核心结论：赛力斯渠道下的“舱内”和“舱外”是两套独立动态示例库。运行时请求必须携带舱域，先按车企/渠道、环境、舱域过滤，再做 Query 语义召回；舱内空池不得去舱外兜底，反之亦然。
另一条独立规则：维护人员新增或导入时的“重复检查”不按车企、环境、舱域或车型缩小范围，而是跨全量动态示例做相似检索并展示来源范围。结果只做软提醒，用户仍可继续提交；提交时必须再次检查，避免编辑期间出现新重复项。

减少错误新增

单条与批量新增都进入查重流程，展示相似记录及其适用范围，帮助维护者判断是复用、编辑旧记录，还是保留一条范围不同的新记录。

降低批量维护成本

用固定模板完成新增、修改、删除；先校验、再确认写入，报告可下载，错误在本地 Excel 修复后重新上传。

保证生效范围准确

本期按车企/渠道、环境和舱域隔离，赛力斯舱内/舱外参与运行时检索；车型只保留需求预览，参数、字典和运行时能力尚未交付。

03

背景与一期现状

为什么需要二期，以及一期已经具备哪些能力。

3.1 动态示例是什么

动态示例是一组 Query → 决策分析 的示例数据。运行时会把符合范围且语义相关的示例注入 Planner 的 {{scenario_sample}}，帮助模型生成更符合预期的决策。平台一期替代了人工维护 Excel 的方式。

3.2 一期已有能力

列表与检索

  • 展示 Query、决策分析、操作人、更新时间。
  • 支持 Query 模糊搜索、更新时间排序。
  • 支持 20 / 50 / 100 条分页。

基础维护

  • 新增、编辑、删除动态示例。
  • 编辑 Query 后重建对应检索索引。
  • 支持环境选择，并保留方案类型等一期字段。

3.3 已暴露问题

  1. 重复内容难发现：多人维护时，需要人工逐条搜索；历史库已存在相似甚至相反决策。
  2. 批量处理链路缺失：测试一次可产生上百条 Case，逐条录入效率低，且缺少统一校验报告。
  3. 单条提交缺少质量门禁：缺少审核、驳回原因、个人处理结果和关键动作留痕。
  4. 生效范围不够细：不同车企、舱内/舱外乃至车型可能需要不同动态示例。若运行时不隔离，可能召回与当前车辆能力冲突的示例。
04

目标与成功标准

本期目标用可验收结果描述，不以“页面上多了字段”作为完成标准。

P0 质量与隔离

  • 100% 的单条新增与批量新增进入查重流程。
  • 100% 的单条提交动作执行服务端二次查重。
  • 赛力斯舱内/舱外互不召回；空池不跨域兜底。
  • 单条新增/编辑在审核通过前不影响已上线数据。

P1 效率与治理

  • 批量导入可完成模板下载、校验、报告导出、确认导入。
  • 管理员可按当前数据空间导出全量数据与全字段。
  • 关键动作可追溯到人、时间、批次和处理结果。
  • 独立操作记录页、版本快照和回滚作为 P1 方案预览，具体粒度与规则待确认。

说明：原 PRD 中“重复示例新增率 0、相似度检查 100%”理解为所有新增都经过检查并被提醒；会议已确认不做硬拦截，因此不能把“库里永远没有相似记录”作为验收指标。

数据空间的页面口径

用户进入列表后，先明确当前查看的数据空间。已确认的范围由 车企/渠道 × 环境 × 舱域 组成；车型在研发确认参数与字典接入后加入。赛力斯选择后必须进一步选择“舱内”或“舱外”，页面标题和列表范围需持续显示当前空间，避免用户误以为两者共用一套数据。

详细需求一：单条新增 / 编辑查重

查重是帮助用户判断的建议，不是硬性拦截；运行时隔离规则不用于缩小维护查重范围。

8.1 触发与范围

  1. 用户填写完整 Query 后，可主动执行“检查相似示例”；具体用按钮或自动触发可由交互实现决定，但必须呈现明确状态。
  2. 检索范围为当前可检索的全量动态示例，不受当前车企/渠道、环境、舱域、车型筛选限制。
  3. 结果按相关性返回 Top N，不向用户开放阈值配置，也不在页面展示相似度分数。N=3 或 5 待确认
  4. 每条结果必须显示：ID、Query、决策分析摘要、车企/渠道、环境、舱域、车型（如有）、创建/更新人、更新时间。
  5. 用户可打开原记录详情；如只是历史记录内容有误，应优先编辑原记录。
  6. 即使存在相似项，用户仍可继续提交。适用范围不同、决策不同的记录可以同时存在。

8.2 六种页面状态

S0未检查

Query 为空或尚未触发检查。点击提交时先进入服务端二查，不能绕过查重。

S1检查中

展示加载状态并阻止重复触发；不清空用户已填写的其他字段。

S2未发现相似项

显示“暂未发现相似示例”；用户可继续提交审核。

S3发现相似项

展示相似列表和来源范围；提示用户先判断是否应维护旧记录，但保留“仍要提交”。

S4检查失败

保留表单并说明失败，可重试。提交时仍须二查；二查不可用时不得假装检查通过。

S5结果已过期

用户在检查后又修改 Query，旧结果失效，页面恢复待检查提示；提交触发新 Query 的二查。

8.3 提交时二次检查

填写并检查维护者查看相似项
→
点击提交将当前完整表单送审
→

若二查发现页面首次检查后新出现的相似项，弹出二次确认：展示新增相似项；用户可返回修改，也可确认“仍要提交”。二次确认仅对当前内容有效；再次修改 Query 后须重新确认。

禁止做法：发现相似项后自动覆盖某条旧记录、让用户在多条相似记录上逐条点“覆盖更新”、或把软提醒改成禁止提交。编辑旧记录必须进入对应 ID 的编辑流程。

详细需求四：单条提交与审批

审批只覆盖单条新增/编辑；审批中心独立于线上动态示例列表，普通用户看自己的提交结果，审核人看全量。

11.1 提交人流程

  1. 点击“提交审核”时完成必填校验和提交二查，生成待审记录。
  2. 普通用户进入“审批中心 → 我的提交”，查看待审核、已通过、已驳回状态。
  3. 被驳回后展示驳回原因；用户编辑后重新提交，形成新一轮审批记录，旧结论不可被覆盖。

11.2 审核人流程

  1. 审核人进入“全部待审”，可按提交人、时间、操作类型、车企/渠道、环境、舱域筛选。
  2. 审批详情同时展示本次内容、变更前后差异、适用范围、相似示例与关联信息。
  3. 支持逐条通过/驳回；也可勾选多条单条申请统一通过。统一处理前必须显示本次条数与操作摘要。
  4. 驳回必须填写原因；通过后新版本生效，并记录审核人和生效时间。

11.3 关键生效规则

  • 单条新增记录：审核通过前不进入运行时检索。
  • 编辑已上线记录：审核期间旧版本继续生效；通过后原子切换到新版本。
  • 扩大适用范围：例如给已上线记录新增车企标签、舱域或车型范围，必须重新审核。
  • 单条停用或删除是否纳入同一审批流尚未确认；未拍板前不得写成既定能力。
  • 白名单管理员完成批量校验并确认后直接写入，操作记录按批次留痕，不生成审核任务。
  • 首版不做 IM 通知；用户通过审批中心查看结果。
首版权限方案：后台现有权限按模块划分，没有审核员角色。本期由服务端配置审核人/管理员白名单，当前业务口径为王泽民、赵晓朝；长期角色权限系统不在本期。

AC-05提交二查命中新记录首次检查后库中新出现相似项，再提交展示新增相似项并要求确认，不能静默提交
AC-06导入错误阻断ADD 行缺 Query 或 UPDATE 的 ID 不存在报告定位具体行列；确认导入不可用；正式库无变化
AC-07导入重复仅提醒上传包含相似 Query、其余字段合法的文件行状态为警告并显示 Top N 相似项；仍可确认
AC-08报告离线闭环下载报告、修复 Excel、重新上传新文件重新校验；错误为 0 后可确认导入
AC-09批量删除二次确认与直接导入合法批次含 DELETE，白名单管理员确认弹窗显示删除数量和目标；取消则不写入，确认后直接执行新增/修改/删除并生成批次记录，不产生审批单
AC-10普通用户审批可见性普通用户打开审批中心只看到本人提交，无法审批他人记录
AC-11驳回与重提审核人填写原因并驳回提交人可见原因并重提；旧审批记录保留
AC-12编辑上线隔离修改已上线记录并等待审批旧版本继续生效；新版本通过后才切换
AC-13导出固定按当前范围全量列表设置 Query、车型筛选并停留在任意页，管理员确认全量导出文件包含当前车企 × 环境 × 舱域的全部记录与全部字段，不受 Query、车型或页码影响
AC-14导出权限普通用户直接调用导出接口服务端拒绝并给出权限提示；产生安全日志
AC-15赛力斯舱内命中舱内、舱外配置相同 Query 但不同决策；运行时请求为舱内只返回舱内决策，舱外决策不进入候选
AC-16赛力斯舱外命中同上，运行时请求改为舱外只返回舱外决策
AC-17舱域空池赛力斯舱内目标池为空，舱外存在强相似项返回空动态示例并记录监控；绝不返回舱外内容
AC-18跨车企隔离赛力斯目标池为空，上汽 PROD 有强相似项运行时不跨车企召回
AC-19UI 与检索同步后台把记录标为赛力斯舱外并审核上线只有舱外请求可召回；若舱内也能召回则整项不通过
AC-20车型隔离请求参数与字典接入完成后，用两个车型配置冲突决策各车型只召回自身适用记录；在前置条件未完成前，此项状态保持“未交付”

发布建议与依赖

用能力依赖分阶段，不在需求尚未评估时写死日期。

第一阶段 · P0 主链路

单条查重六状态与二查、单条审批中心、白名单批量导入闭环，以及车企 × 环境 × 舱域字段和运行时隔离。

第二阶段 · P1 治理

全量导出与关键动作留痕；独立操作记录页、版本快照和回滚仅作方案预览，评审确认后再进入实现。

需求预览 · 车型

当前只展示车型字段需求。车型请求参数、权威字典与运行时过滤尚未交付，前置条件确认后另行排期和验收。

关键依赖

  • 相似检索服务可返回稳定 Top N 及记录信息。
  • 运行时调用链路提供 channel、env、scene_domain。
  • 平台字段与 SP/Planner 检索过滤同一版本联调上线。
  • 审批人/管理员白名单有可配置入口并在服务端校验。
  • 车型隔离依赖车型参数与字典来源确认。
