AI汽车语音基础体验链路OnePager
AI汽车语音基础体验链路OnePager
## 简要介绍
这条链路解决四个基础体验问题：
听得准：
- 用户开始说话后，端侧持续采集音频，以200ms一帧发送云端。
- 端侧仅上送音频并控制 VAD，端侧收到流式ASR结果，以 Soft VAD 触发本轮预请求、以 Hard VAD 600 ms 结束 ASR 并发起正式请求。
- 热词与对话上下文由云端维护，云端在 ASR 请求建联时以及 ASR 链路上行信息中读取并注入ASR热词提高识别准确率。
- 端侧上传流式ASR请求云端基于流式文本先做拒识判断，确认用户在和车机交互时可立即打断正在播放的 TTS。

回得快：
- 通过 Soft VAD 判断用户是否可能说完话，来用已经生成的Query文本预跑部分模块，正式链路时若能命中缓存数据，则可以缩短正式链路耗时。
- 云端TTS提前合成，端侧通过TTS标识来拉取音频。

端云上下文一致：
- 端侧召回的处理，需要将执行结果、回复话术等信息回传同步给云端，以保证端云对话历史一致性。

打断恢复
- 当TTS正在语音播报时，用户开始说话，部分场景下触发了TTS打断，当前Query上云后云端考虑是否需要恢复被打断的TTS。

    C->>A: 建立通道并持续上送音频分片

    par 流式一遍识别
        loop 每次 partial
            A-->>C: 一遍 partial 文本
            C->>G: 流式拒识判断
            alt 判定为人机交互
                G-->>C: 下发打断通知
                C->>C: 停止当前 TTS
            else 非人机交互或证据不足
                G-->>C: 继续收音
            end
        end
    and Soft VAD 抢跑
        C->>G: 300 ms 阈值触发 pre_query
        Note over C,G: 携带 request_id + round_id
        G->>G: 预跑拒识与前置无状态任务
        G->>H: 预跑 Context
        H-->>G: 返回预跑结果
        G->>G: 保存前一轮预请求 Query 与结果
    end

    A-->>C: 二遍 final 文本
    C->>C: Hard VAD 600 ms 确认结束
    C->>G: 正式请求最终 Query
    Note over C,G: 正式请求携带 request_id + round_id
    G->>G: 校验 requestID 相同且正式 Query 与前一轮预请求 Query 完全相同
    alt 两个条件同时满足

    else 任一条件不满足

    end

    G->>H: 组装正式 Context
    H-->>G: 返回云端上下文

    P-->>G: 生成 Answer 文本

    T-->>G: 音频就绪并返回 TTS 标识
    G-->>C: 下发 TTS 标识
    C->>T: 通过 TTS WSS 拉流
    loop 音频 chunk
        T-->>C: 返回音频分片
        C-->>U: 流式播放
    end

    alt 可见即可说或简单车控本地命中
        U->>C: 本地可处理指令
        C->>C: 召回、执行并生成 Answer
        C->>H: context/sync 上报 Query、Answer、Observation
        H->>H: 按 requestID 写入历史
    else 端侧未命中
        C->>G: 进入云端正式链路
    end云端处理：
- 请求准备：AIDV 前置链路在 ASR 建联前，先从云端热词库读取候选热词，再读取最近对话上下文，并把热词与 Context 一并注入云端 ASR。
- 语音采集：用户开始说话，端侧与 ASR 建立通道、持续上送音频分片。端侧负责采音、VAD、音频上送、打断 / 播放控制、TTS WSS 拉流。
- TTS打断与预请求处理： - 流式一遍识别：ASR 每次返回 partial 文本，端侧做流式拒识判断 —— 若判定为人机交互，则下发打断通知、停止当前 TTS。
- Soft VAD 抢跑：达到 300ms 阈值即触发 pre_query（携带 request_id + round_id），预跑拒识与前置无状态任务、预跑 Context，并保存前一轮预请求的 Query 与结果。

- 正式请求：端侧以 Hard VAD 600ms 确认说话结束，ASR 返回二遍 final 文本，发送正式最终 Query。云端校验「requestID 相同」且「正式 Query 与前一轮预请求 Query 完全一致」—— 两个条件同时满足则直接复用预请求结果，否则正式重算拒识与 Context；随后做最终拒识与多音区合并、组装正式 Context。
- 生成与播报：最终 Query + Context 交给 Planner 生成 Answer 文本与工具调用，云端以桃子音色请求 TTS 合成，下发 TTS 标识，端侧经 TTS WSS 拉流、流式播放音频分片。

端侧处理：
若为「可见即可说」或简单车控且本地命中，端侧直接召回、执行并生成 Answer，并将 Query、Answer、Observation 经 context/sync 上报写入历史；端侧未命中则进入云端正式链路。

### 打断恢复链路
sequenceDiagram
    participant U as 用户
    participant C as 端侧
    participant A as ASR / 流式语义
    participant R as 打断恢复服务
    participant P as Planner
    participant T as Sami TTS

    Note over C,T: 打断判断何时停播；恢复判断未播内容是否仍有价值
    T-->>C: 上一条 TTS 经 WSS 拉流播放
    U->>C: 上一条未播完时发起新 Query
    C->>A: 持续上送音频流
    alt 单人模式
        A->>R: ASR 字数达到阈值（待确认）
    else 多人模式
        A->>R: 流式语义判定为人机指令
    end
    R-->>C: 触发打断并停止当前 TTS
    C->>R: 上报已播放秒数与打断原因
    R->>T: 结合 TTS 打轴定位已播与未播内容
    R->>R: 判断是否播完、打断类型、是否需要恢复
    A->>R: 当前 Query 最终拒识结果
    alt 当前 Query 最终 Reject
        R->>R: 通过 Event 请求恢复上一条未播内容
        R->>T: 生成恢复播报
    else 当前 Query 不 Reject
        R->>P: 新 Query + 上一条未播内容
        P->>P: 按信息价值保留核心并去重
        P->>T: 合成自然衔接的新 NLG
    end
    T-->>C: 下发 TTS 标识并通过 WSS 播放恢复分流：当前 Query 最终 Reject 时通过 Event 触发新 Query恢复上一条；Recall 时由 Planner 融合新 Query 与未播内容，生成自然且不重复的新 NLG。

### 预请求介绍
通过Soft VAD + 语义VAD 标识多次预请求前置模型请求来换取正式请求耗时

步骤一：基于的 Soft VAD + 语义 VAD 得到的预请求 Query 做一些前置无状态任务处理。比如：拒识、Context
步骤二：当 Hard VAD + 语义 VAD 确认最终 Query 时，若与预请求query完全相同，通过直接获取前置已经处理的预请求任务结果来加速当前正式请求的速度，从而降低链路耗时。
