00 / VERDICT

先给结论：不该“换成 OpenClaw”，应该把现有系统升级成车规 Harness

OpenClaw/Hermes 是通用个人 Agent 运行时；汽车行业真正有竞争力的不是原版框架，而是把它们重做成端云 AIOS、车载 Skill 平台和安全执行系统。

近期
我们更好

面向 D6X 和近期车型量产：保留豆包上车当前路线更合理。它已经拥有车载快慢分流、权威车辆 Context、固定工具边界、tool_feedback 闭环和真实车型集成；通用 OpenClaw/Hermes 直接替换会丢失车规能力。

面向未来三年平台竞争：Auto Claw、KaKaClaw、AquaClaw 展现出的端侧运行、任务池、Skill 包、沙箱和可扩展生态，确实比“继续把规则和示例塞进一个大 SP”更可持续。

最佳解：快慢路 + Director 中心仲裁 + 车规 Skill Registry + Task/Run/Event + Trigger + 端云混合运行时 + LLM 外确定性策略引擎。

真正的相同点

两者都有“理解目标 → 规划 → 调工具 → 看结果 → 再规划”的 Agent 循环。我们的 Planner/Director 本质上已经是车载 Agent Harness，而不是传统 NLU 指令树。

真正的差异点

我们偏封闭域、中心仲裁、模型云端、工具固定；Claw 类偏技能化、运行时化、端侧化、生态开放。差异不在有没有大模型，而在能力如何装载、任务如何持久、权限如何治理。

当前最大误区

“开源免费”不等于“车载方案便宜”。MIT License 只免框架授权；车端硬件、OS 适配、车型接口、功能安全、网络安全、OTA、数据闭环才是整车成本主体。

03 / OUR SYSTEM

我们的当前架构：车载闭环很强，但 Harness 仍主要压在大 SP 里

当前本地 SP 为 2026-07-31 版本：127,789 字符、2,186 行；4 类输入、27 个明确工具、4 个输出字段、25 个示例块（24 个不同编号）。S1

当前同步链持续任务域触发/事件必须确定性治理

已有优势

  • 简单指令有快路，不必每次进入大模型。
  • 车辆、乘员、导航、记忆是业务 Context，不是普通聊天历史。
  • action_list 与 tool_feedback 形成可反复 Replan 的闭环。
  • 工具定义包含车型边界、前置条件和串行约束。

当前结构债务

  • 27 工具、规则、车型边界和示例大量压在 12.8 万字符 SP 中。
  • SP 当前仍有编号重复、旧工具名和未定义工具引用。
  • Goal、动态 Advisor、Task Service 处在演进期，不能假定已经统一。
  • “Prompt 写了不允许”不能代替执行层安全策略。

与 Claw 的关键差距

  • 缺统一、版本化、可签名的 Vehicle Skill 包。
  • 缺标准 Runtime 生命周期和 Skill 装载/卸载协议。
  • 端侧 Agent/本地模型承担比例有限。
  • 任务池和跨会话恢复仍在 Task WIP 中完善。
04 / CLAW

OpenClaw/Hermes 强在哪里：不是“更聪明”，而是 Harness 工程更完整

它们把模型外的会话、上下文、工具、Skill、插件、持久化、定时任务、安全和可观测做成独立运行时，而不是全部写进 Prompt。

OpenClaw 的工程亮点

  • Gateway 是会话、工具、事件和渠道的本地控制平面。
  • 每个 Session 的 Agent run 串行化，支持超时、压缩、重试和流式事件。
  • Skills / Plugins / MCP 独立于模型，能力可组合扩展。
  • Prompt caching、compaction、tool-loop detection 已运行时化。

S4 S5 S6

Hermes 的工程亮点

  • Prompt 分 stable / context / volatile 三层，天然利于缓存与动态上下文。
  • 18+ Provider 路由、70+ 工具、SQLite Session、插件和轨迹数据。
  • Cron、Delegation 和 Gateway 是一等能力。
  • 但官方安全文档也明确：文件写保护并不能约束同权限 Terminal，仍需真正沙箱。

S7 S8

为什么不能直接装上车：通用沙箱解决“Agent 不要删宿主文件/偷密钥”，车规安全还要解决“谁能在什么车速、挡位、座位、车辆状态下调用哪个 ECU 能力；失败如何回滚；跨域动作怎样事务化”。这是完全不同的信任边界。

06 / SCENARIO

同一真实需求跑完两套链路

场景：“明早 8 点如果下雨，提前开空调除雾，导航去公司，顺路帮我买杯冰美式。”它同时包含时间、条件、车控、导航、第三方服务、支付和跨会话恢复。

豆包上车：业务 Task + Trigger 驱动

Director 判断任务类型
不是当前轮能完成的一次 Action；拆出“明早 8 点”“如果下雨”“除雾”“导航”“下单”与授权缺口。
创建持续任务
当前链路调用持续管理入口；目标链创建 Goal + Trigger Scene。WIP 目标态写入 Task、Run 策略、结束条件和用户管理信息。
Trigger 持续监听
Timer 到 8 点；再获取天气事件/状态。未下雨则按策略 skipped 或询问是否仍导航，不直接执行除雾。
回调并读取最新 Context
重新读取车辆是否在线、挡位、车窗/空调、用户是否上车、公司地址、支付授权、当前天气与路况。
Director 再规划
可并行的除雾与天气确认并行；导航与沿途咖啡搜索按依赖串行；支付需要用户确认或预授权。
执行回执与任务收口
每个工具返回 tool_feedback；失败时重试/降级/询问。Task 记录 finished / partial / skipped，并可查询、修改、取消。
优势：车辆条件、任务状态和用户安全语义明确。
当前缺口：Task 统一化仍是 WIP；第三方下单/支付工具是否真实可用需车型项目确认。

通用 OpenClaw/Hermes：Cron + Agent Loop 驱动

Agent 解析并创建 Cron
把 8 点任务写入 Cron；可能将天气、导航、咖啡流程保存为 Skill 或 Prompt。
到点创建一次 Agent Run
Hermes Cron 官方语义是新鲜 Session、默认不继承当前聊天；必须把公司地址、授权边界等写进任务或持久记忆。
调用天气与服务插件
Web/API 工具判断天气，再调用导航、外卖/咖啡插件。通用框架不知道哪个工具是车辆安全域。
缺车辆 Trigger 语义
Cron 能表达“8 点”，不能天然表达挡位边沿、用户是否入座、信号 TTL、VLM 连续 K 帧去抖，需要 OEM 自建事件总线。
缺整车事务边界
“除雾成功但导航失败”“咖啡下单成功但用户没上车”的补偿策略，需在 Skill 和策略引擎里额外实现。
汽车版 Claw 的补丁
Aqua/KaKa/Auto Claw 正是通过 AIOS、车辆 ontology、Skill library、Policy/Sandbox 和端侧模型把这些缺口补齐。
优势：流程可快速 Skill 化，生态接入灵活。
风险：若只把通用 Agent 装上车，而没有车辆事件、权限和事务层，Demo 很快，量产很危险。

08 / SAFETY

安全差异：沙箱不是车规安全，Prompt 也不是权限系统

真正量产必须把“模型建议”与“动作授权”分开。无论我们还是 Claw，都不能让模型自己决定自己的权限。

① 身份域

谁说的、坐哪里、是否注册、是否主驾、是否具有付款/通讯/车控权限。

② 车辆状态域

车速、挡位、车门、动力状态、驾驶模式、当前执行任务与信号新鲜度。

③ 动作风险域

信息查询、舒适控制、付费交易、驾驶相关动作应有不同确认、审计和回滚策略。

④ 运行时域

工具 allowlist、参数 schema、幂等键、超时、重试、补偿、沙箱、网络出口与供应链签名。

安全问题仅靠 Prompt 的结果通用 Claw 沙箱的结果车规正确做法
高速行驶时“帮我打开车门”模型可能拒绝，但存在提示漂移和绕过沙箱允许它正常调用一个已暴露的 vehicle toolECU/Vehicle Policy 根据车速与挡位硬拒绝，模型只负责解释
重复 tool_feedback 导致二次支付靠上下文记忆“不再调用”，不可靠Tool loop detection 可能发现重复，但不理解交易幂等订单 idempotency_key + 事务状态机 + 二次确认
Skill 被恶意更新SP 无法治理外部代码ClawHub 扫描/插件策略能降低风险OEM 签名、版本锁、灰度、SBOM、权限声明、回滚和隔离执行
旧车态误触发历史对话可能压过实时事实通用 Memory 不知道车态 TTL每个 Signal 带 source / capture_ts / TTL；过期不得参与条件判断
座舱 Agent 影响智驾Prompt 不构成隔离Docker/OpenShell 只隔离计算环境座舱/智驾物理或强隔离，跨域接口最小化；KaKaClaw 官方明确提出 Fortress 隔离
对我们的直接建议：把 SP 中的“注意事项、工具 tips、车型能力边界”迁移成机器可执行的 Policy Registry；Director 输出的是 intent/action proposal，Policy Engine 输出的才是 executable action。

Auto Claw、KaKaClaw、AquaClaw 和豆包上车均未公开单车软件授权/NRE/云包价。下面只呈现可核验的公开价格和计算模型。

开源框架费

¥0

OpenClaw 与 Hermes Agent 均为 MIT License。它只意味着框架代码无需许可证费，不包含模型、算力、车载适配、认证和运营。S6 S7

商业车载方案费

未公开

三家供应商官网没有公开按车/按年授权价。任何“几十到几百元/车”都不是当前可核验的官方报价，本报告不采用。

¥1,500–4,000

真正应向供应商索取的报价拆分

成本项豆包上车云优先汽车版 Claw 端云方案采购必须问清
软件许可模型/平台/功能包商务AIOS/Runtime/Skill Platform 商务按车型、按车、按年还是买断；最低量和升级权
NRE 集成车型工具、Context、车企生态对接OS/芯片/车辆 ontology/Skill 适配平台复用率、二车型增量、验收边界
云资源复杂任务模型调用占比较高端侧为主时较低，但仍需云协同Tokens、并发、缓存、峰值 SLA、超额单价
端侧硬件可复用既有座舱算力，增量视车型可能需要大内存/NPU/AIBOX；舱驾融合也可能节省双芯BOM、功耗、散热、内存、芯片锁定、供货周期
安全与认证现有车企流程可复用开放 Skill 与端侧 Runtime 增加供应链治理ASPICE、ISO 26262/21434 范围，谁承担测试与整改
长期运营云侧模型迭代、Badcase、提示词/工具发布端云版本矩阵、Skill 商店、签名、沙箱、模型更新3–5 年 OTA、SLA、回滚、数据归属、停服兜底
成本结论：低频复杂任务时，云优先通常避免增加硬件 BOM；高频、长上下文、弱网和隐私场景多时，端侧模型可能在三年 TCO 上更有优势。真正的分界点取决于“端侧增量硬件成本”是否低于“3 年复杂任务云成本 + 网络/SLA 成本”，而不是开源 License 是否免费。
10 / DECISION

哪个更好：要分“现在量产”和“未来平台”两张卷子

评分是透明权重下的产品判断，不是厂商官方 Benchmark；未知能力不会按宣传满分处理。

下一代大算力/舱驾融合平台混合车规 Harness端侧模型 + 云端强推理 + Task/Trigger + Skill/Policy，兼顾性能与安全
低配车型/成本敏感快路端侧 + 复杂任务云端避免为了低频 Agent 任务增加高额 NPU/内存 BOM
高端车型/强主动服务端云 Agent OS + 开放服务生态长期记忆、Always On、跨服务执行和弱网体验需要端侧运行时
POC 快速验证可用 OpenClaw/Hermes验证 Skill 和工具闭环速度快，但必须隔离在非安全域，不能直接成为量产安全边界

P0 · 0–3 个月

  • 把 27 工具收敛到唯一 Tool/Skill Registry。
  • 从 SP 移出互斥、权限、车型能力与安全规则。
  • 落实 Task/Run/Event 与幂等、恢复、取消。
  • 统一 tool_feedback 为标准 Execution Receipt。

P1 · 3–6 个月

  • Prompt 分 stable/context/volatile，支持动态工具披露。
  • 建立端侧 Router + 轻量模型 + 弱网 Skill。
  • 上线 OEM 签名 Skill 包、沙箱与灰度。
  • 补齐 Context source/timestamp/TTL。

P2 · 6–12 个月

  • 开放受控服务 Agent SDK，而非开放任意代码。
  • 端云模型按风险、时延、成本动态路由。
  • 跨车型 Skill 复用与自动兼容性检查。
  • 用真实任务完成率和三年 TCO 驱动架构选型。
