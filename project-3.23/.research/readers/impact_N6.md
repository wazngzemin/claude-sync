# impact_N6（事件日志）——资料有、副本缺

来源：事件日志产品需求文档 v1.2（全文+2画板已看）、公共Context管理（事件日志类 P0）。

## 缺：事件的定义与正反例
事件=所有发生的、能被车内人类感知到的、非规律的人/车/豆包行为或变化。
- 不属于事件：车内空气轻微流动、常规转动方向盘、眨眼、情感 agent 联网搜索但没给建议、内容 agent 给建议但主 agent 没采纳。
- 属于事件：猛打方向盘超180度、突然下暴雨/雨停、开始/停止抖腿、内容 agent 给建议主 agent 采纳并行动。
- 分类一：人际及人宠互动事件 / 人员行为动态事件 / 人车交互事件 / 状况与任务执行事件。分类二：简单事件（原子不可拆）/复杂事件（上车=迈步×N+开车门+坐下；超车=打灯+加速+打方向）。
- 链接：https://bytedance.larkoffice.com/wiki/Gt9qwfzlHiIKLgkWKCfcqYsYngg ｜ 状态：全文 ｜ 车型：通用。

## 缺：事件日志表的字段结构
时间戳（毫秒）、事件ID（系统生成）、Face ID（车端识别，可多人如 ID001:明骏 ID002:雨晴）、交互形式（手动/语音）、事件（自然语言拼接，**不涉及大模型**，11.18 改为固定格式【主体】（谁）+【做了什么/说了什么】+【客体】）、触发任务ID（从 planner 获取，可一对多 T11105-T11111）、所属任务ID、端状态（从端状态取）、情景描述（从 watcher 取）、1-4级分类/信号ID/信号名称。
- 链接同上。

## 缺：事件与任务的双向关系
事件是外在表征、任务是内在规划；事件触发任务产生，任务执行也产生事件。关联好处：①通过任务把多事件串起来（一问一答/互为因果/一对多/多对多）②关联本身记录"在什么场景下系统产生了这个任务"。
- 任务列表示例：内容 agent 负责财经新闻/AI进展/汽车界/社会热点/展览演出/天气/黄历（定时播报）；主 agent 负责强劲制冷上车调风量、闪光提示+挪车+开后备箱、座椅按摩按人分配、i8询问、空调20→23度自动。探索任务和普通任务不在一个队列但编号唯一可追溯。
